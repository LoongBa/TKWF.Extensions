## 二、批次设计（顺序 + 分组 + 理由）

### 批次顺序原则

1. **风险优先**：IDomainUser 注入 = 生产必失败 → 先改；最大违规面先拆
2. **主题聚类**：同域扩展一批（一次掌握模式，多扩展套用）→ skill 心得一次沉淀多次复用
3. **契约边界**：Abstractions 契约（Account→SecurityLog.Abstractions 等）**只改实现不碰契约**，无批次间阻塞
4. **依赖亲和**：Account（含 PasswordResetFlow 依赖 IAccountPasswordManager）先于 Identity 先于 Authentication——小面先改、大面后改（Oracle 建议）
5. **验收门禁**：每批结束 = 该批扩展 slnx 0 错误 + 测试全绿 + skill 心得已入库（任务 2）+ 故障已转达（任务 3）

## 四、铁律速记（委派 prompt 必含附录——对齐交接文档 §五）

1. **IDomainUser 永不注册 DI**——经基类 `DomainServiceBase.User` 取上下文；禁构造注入
2. **领域服务必须继承 `DomainServiceBase`**；接口标 `: IDomainService`（DI005）
3. **禁 Store 伪 DataService 层**——CRUD 归 SG1 DataService，组合归门面
4. **DataService 禁构造注入**（DI004 默认 Error **零豁免**）——`User.Use<具体类>()` 懒加载
5. **禁裸 ORM / 禁直接 IEntityDAC**（数据访问红线）——经 SG1 DataService
6. **注册形态**：门面 `AddConstructibleService`；接线型/纯内存型普通 DI；DataService 零手动注册
7. **`InitializeAsync` 启动加载/种子**经 `BeginSystemScopeAsync` + `scope.System.Use<T>()`
8. **过滤器解析域服务**经 `context.DomainUser.Use<T>()`（不读 ambient）
9. `[DiContractIgnore]` 仅用于运行时手写注册的服务（豁免 DI001 误报）——**不豁免 DI004**
10. 框架调整需求 → **及时反馈**（任务 3 模板），不自行绕开
