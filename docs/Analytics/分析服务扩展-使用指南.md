> **扩展**: `TKWF.Ext.Analytics`（分析服务——AnalysisSpec 读取/校验/透传）| **核心**: `TKW.Framework.Utility.Analytics`（主框架 Utility，v4.10.27+）| **版本**: V0.1.0（骨架）
> **关联设计**: [D20-TKWF 分析服务设计方案](../../../_TKWF/docs/D20-TKWF-分析服务设计方案.md)（v1.1，主框架私有）、[D20B 分析服务开源对标与语义层定位](../../../_TKWF/docs/D20B-分析服务开源对标与语义层定位.md)、[D20 附 flint 模板注册表快照](../../../_TKWF/docs/D20-附-flint模板注册表快照.md)
> **架构**: 两层——核心加载校验（`TKWF.Utility` 零依赖）+ 本包集成门面（DI/Options/API 接线），对齐 Metrics 完整先例（`Utility.Metrics` + `TKWF.Ext.Metrics`）

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj（NuGet 模式——v4.10.27+，Analytics 依赖主框架 Utility.Analytics） -->
<PackageReference Include="TKWF.Ext.Analytics" Version="0.1.0" />
<!-- 传递依赖：TKWF.Domain 4.10.27+ / TKWF.Utility 4.10.27+（含 Utility.Analytics） -->
```

**双模式引用（扩展仓库开发，2026-09-16 方案 B）**：

| 模式 | 开关 | 引用方式 | 用途 |
|------|------|---------|------|
| 本地联调 | `UseLocalFw=true`（默认） | **DLL 模式**：`$(TKWFDeployPath)\build\refs\` 预编译框架 DLL（对齐消费项目；替代早期 ProjectReference 跨仓库耦合） | 本地开发/调试 |
| NuGet 发布 | `UseLocalFw=false` | PackageReference（CPM 集中版本） | CI/发布，验证真实消费方视角 |

> ⚠️ `UseLocalFw=true` 的 DLL 模式需要 `TKWFDeployPath` 环境变量指向主框架部署根（`build\refs\` 含 4.10.27 框架 DLL）；未设置时回退本仓库 `build\refs\`。

### 2. 白名单声明（v4.9.85+ 必需）

```csharp
using TKWF.Ext.Analytics;

[TKWFEnabledExtension(typeof(AnalyticsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后扩展三钩子自动接线：`AnalyticsSpecLoader`（Singleton）+ `IAnalyticsQueryService` 门面（Singleton）。

### 3. 注入 + 使用

```csharp
public class SalesAnalyticsService(IAnalyticsQueryService analytics)
{
    public async Task<JsonDocument> GetTrendSpecAsync(CancellationToken ct)
        => await analytics.GetSemanticTypesAsync("merchant", "PaymentLogStatView--daily-sales-trend", ct);
}
```

**门面 4 方法**（`domain` + `specKey` 双参；返回 `JsonDocument` 原样透传，不镜像强类型——flint 单一真相）：

| 方法 | 职责 |
|------|------|
| `GetSemanticTypesAsync(domain, specKey)` | 读取 semantic_types.json（flint flat map）；stale → `SpecStaleException` |
| `GetChartSpecAsync(domain, specKey, chartType)` | 读取 chart_spec/{chartType}.json；chartType 缺失/非法 → 主图兜底（primaryChartSpecFile） |
| `ListPivotChartTypesAsync(domain, specKey)` | 读 pivot-hint.json allowedTransitions（可选文件，缺失 → 空列表；实际切换由 flint 前端门控） |
| `GetManifestAsync(domain, specKey)` | 读 manifest.json（**不校验 status**——前端读 status 展示 stale/deprecated） |

## 二、AnalysisSpec 产物规范（Spec Files）

### 目录与命名

```
docs/analytics-specs/{Domain}/{specKey}/
├── README.md              # spec 概述：意图、数据形态、主图、维护者
├── view-sql.sql           # ①-1 DDL（方言中立规范 DDL，供 tkwf-entity 生成 VEntity）
├── data-contract.md       # ①-2 数据契约（字段角色/类型/口径/二级聚合）
├── pivot-hint.json        # ①-3 可切换图型提示（可选；实际切换由 flint pivot 门控裁决）
├── semantic_types.json    # ①-4a flint flat map（spec 内唯一）
├── chart_spec/            # ①-4b 视觉模板（主图 + 可切换）
│   └── {chartType}.json   #   chartType 用 flint 模板注册表名（见 §六）
└── manifest.json          # spec 元数据：specKey/version/sourceVEntity/sourceViewSqlHash/status/primaryChartSpecFile/fields
```

- **specKey 命名**：`{VEntityName}--{intent}`（PascalCase--kebab-case，如 `PaymentLogStatView--daily-sales-trend`）。
- **domain 命名**：kebab-case 小写（如 `merchant`）。
- **生成工具**：`tkwf-analytics-view` skill（产物契约见主框架 `docs/AC-Kit/skills/tkwf-analytics-view/SKILL.md`）——人工/Agent 手工产出，不做 AI 意图分解（D20 §9.1 边界）。

### 格式示例（`PaymentLogStatView--daily-sales-trend`）

**semantic_types.json**（flint flat map，**不含自造 `$schema`**——D20B §4.3 单一真相归 flint）：

```json
{
  "semantic_types": {
    "BizDate":     { "semanticType": "Date",  "unit": "day" },
    "TotalAmount": { "semanticType": "Price", "unit": "CNY" },
    "PaidCount":   { "semanticType": "Count" }
  },
  "field_display_names": {
    "BizDate": "营业日",
    "TotalAmount": "销售总额",
    "PaidCount": "已付笔数"
  }
}
```

**chart_spec/line.json**（chartType 用 flint 模板注册表名；聚合语义在 encoding 层）：

```json
{
  "chartType": "Line Chart",
  "title": "每日销售趋势",
  "subtitle": "销售总额与已付订单数，按营业日",
  "encodings": {
    "x": { "field": "BizDate" },
    "y": [
      { "field": "TotalAmount", "aggregate": "sum" },
      { "field": "PaidCount", "aggregate": "count" }
    ]
  },
  "baseSize": { "width": 960, "height": 400 }
}
```

**manifest.json**（含 `sourceViewSqlHash`——VEntity ViewSql 的 SHA-256，供 stale 检测）：

```json
{
  "specKey": "PaymentLogStatView--daily-sales-trend",
  "version": "1.0.0",
  "sourceVEntity": "PaymentLogStatView",
  "sourceViewSqlHash": "sha256:9f4a2b7c...",
  "generatedAt": "2026-09-16T10:00:00Z",
  "generatedBy": "tkwf-analytics-view@0.1.0",
  "status": "active",
  "primaryChartSpecFile": "line.json",
  "fields": ["BizDate", "TotalAmount", "PaidCount"]
}
```

### 校验规则（核心层 `AnalyticsSpecValidator`）

- `status == "stale"` → `SpecStaleException`（强制重生，不静默渲染）。
- `status == "deprecated"` → 放行（消费方读 manifest.status 展示警告）。
- 文件缺失/JSON 损坏 → `ChartSpecLoadException`。
- `domain`/`specKey` 命名非法（正则）→ `ChartSpecLoadException`（**防路径遍历**）。

## 三、消费端渲染接线（flint-chart）

### 数据流

```
消费端（浏览器/Blazor）
  GET /api/analytics/{domain}/{specKey}/...（经 [GenerateController] 暴露的消费方 Domain Service）
    → { spec JSON + data.values }（spec 由 IAnalyticsQueryService 透传，data 由 tkwf-service 查询）
  → assembleECharts(input)（flint-chart 薄包装）
  → ECharts option → render
```

### flintBridge 薄包装（TypeScript）

```ts
import { assembleECharts } from 'flint-chart';  // 版本 0.5.1，package.json 钉锁

const input = { semantic_types, chart_spec, data: { values } };
const option = assembleECharts(input);           // → ECharts/Vega-Lite/Chart.js/Plotly/Excel spec
```

- **ECharts 按需导入**（D20 §6.2 P3）：`import * as echarts from 'echarts/core'` + 选择性注册（LineChart/BarChart + GridComponent/TooltipComponent/LegendComponent）——全量 >500KB gzip，按需 ~100KB。
- **失败模式**（D20 §10.4）：
  - `SpecStaleException` → UI 提示"spec 已 stale，需重跑 tkwf-analytics-view"。
  - 数据空 → "暂无数据"占位。
  - 渲染失败 → catch + "图表渲染失败"占位。
- **许可红线**：ECharts/Chart.js/Recharts 均 MIT/Apache 可商用；**避开 ApexCharts**（年营收 ≥$2M 需付费）、Highcharts（商业付费）。

## 四、配置选项

```json
{
  "TKWF": {
    "Analytics": {
      "SpecRoot": "docs/analytics-specs"
    }
  }
}
```

- `SpecRoot`：spec 根目录（默认 `docs/analytics-specs`，相对消费方仓库根；继承自核心 `AnalyticsSpecOptions`）。
- SG1 `[Options]` 自动绑定 + 扩展 Initializer `AddOptions` 兜底默认值。

## 五、异常处理

| 异常 | 触发 | 消费方建议 |
|------|------|-----------|
| `SpecStaleException` | manifest.status == stale / 缺失 | 提示重跑 tkwf-analytics-view |
| `ChartSpecLoadException` | 文件缺失 / JSON 损坏 / 命名非法（含路径遍历） | 提示重生 spec；检查 domain/specKey 命名 |
| `DataShapeMismatchException` | **消费方数据层**校验 semantic_types 字段 vs data 行不匹配（核心仅定义不抛出） | 提示"VEntity 字段变更，spec 需重生" |

> 三个异常均含结构化属性（`SpecKey`/`ChartType?`/`LoadTarget?`/`Reason`）——程序化处理，勿 parse 消息字符串。

## 六、flint 模板注册表速查（0.5.1 锁定）

> 完整清单 + 5 后端支持矩阵见主框架 `docs/D20-附-flint模板注册表快照.md`。**chartType 用模板注册表名**（非短码），如 `"Line Chart"`/`"Bar Chart"`/`"Scatter Plot"`。

**常用主图 chartType**（47 个并集，主后端 ECharts 全支持）：

| 数据形态 | chartType | 说明 |
|---------|-----------|------|
| 时间序列 | `Line Chart` / `Area Chart` | 趋势 |
| 分类对比 | `Bar Chart` / `Grouped Bar Chart` / `Stacked Bar Chart` | 排行/分布 |
| 构成分布 | `Pie Chart` / `Donut Chart` | 占比 |
| 关联分析 | `Scatter Plot` / `Regression` | 相关性 |
| 分布形态 | `Histogram` / `Boxplot` / `Density Plot` | 统计 |
| 地理 | `Map` / `Choropleth`（ECharts 仅 Map） | 地理分布 |

> ⚠️ **拼写陷阱**：Chart.js 用 `Doughnut Chart`（英式），其余后端用 `Donut Chart`（美式）——两个不同字符串，非别名。

**一数多图（pivot）**：flint 原生 `PivotTransition` 门控（Grouped↔Stacked、bar→line/area、Scatter↔Regression 等）——spec 只声明主图 + 可选 pivot-hint，可切换图型由 flint 前端按数据形态门控裁决，**服务端不做候选推导**（D20B §5.2 删除）。

## 七、常见问题（FAQ）

### Q1: `SpecStaleException` 何时触发？
manifest.status == "stale"（VEntity ViewSql 变更但未重跑 tkwf-analytics-view）或 manifest 缺失 status。修复：重跑 skill 重生 spec。

### Q2: chartType 传错会怎样？
文件不存在 → 静默回退主图（`primaryChartSpecFile`）；`chartType ∉ flint 注册表` → 前端 flint assemble 抛错（核心不硬编码模板名——避免第三真相源 D20B §4.3）。

### Q3: 为什么 `GetManifestAsync` 对 stale spec 不抛异常？
manifest 是状态展示载体（P1-4）——前端需读 status 字段展示 stale/deprecated 警告。`GetSemanticTypesAsync`/`GetChartSpecAsync` 才抛 stale。

### Q4: 与 Metrics（`TKWF.Ext.Metrics`）关系？
两者职责正交（D20B §2.2）：Metrics 算指标（复购率/留存 → `MetricResult`），Analytics 管图表（spec → flint 渲染）。可共存于同一 specKey 目录（`metric-definitions.json` + `chart_spec/` 不同文件互不解析）。

### Q5: spec 目录与 Metrics `SpecRoot` 默认值相同？
两者默认都是 `docs/analytics-specs`（Metrics 也用它）——消费方可统一配置指向同目录，无需拆分。
