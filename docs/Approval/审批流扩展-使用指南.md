# Approval 轻量审批引擎-使用指南

> 扩展：`TKWF.Ext.Approval`（v0.2.0）——内置轻量审批引擎（不依赖外部工作流引擎；P1 差异化模块）。
> 本指南公开；迭代开发方案/ADR/审核报告见主框架私有 `_TKWF/docs/03_扩展模块/Approval/`。

---

## 1. 本扩展解决什么

企业应用普遍需要审批流（报销/请假/采购/发布），但主框架无工作流基座（差异化确认）。本扩展提供**内置轻量审批引擎**：
- **审批流定义**（`ApprovalFlow`）：顺序步骤链 + 审批人规则 + 或签（Any）/会签（All）模式；
- **审批实例**（`ApprovalInstance`）：业务实体弱关联（`BusinessType`+`BusinessId`）+ 状态机 + 活动唯一约束；
- **审批任务**（`ApprovalTask`）：步骤级待办（审批/驳回/转交载体）；
- **完成事件**（`ApprovalCompletedEvent`）：审批通过/驳回后经事件总线触发业务动作（解耦）；
- **v0.2.0 深化**：委派（Flowable 两阶段）+ 加签（运行时追加审批人）+ 抄送（仅通知）+ 超时自动处理（5 动作）。

**边界**：v0.2.0 支持**顺序步骤链 + 或签/会签 + 委派/加签/抄送/超时**；并行分支/条件网关/设计器 UI/审批历史统计 归 v0.3.0。

## 4. 快速开始

```csharp
// ① 定义审批流（提交后一次性）
var approval = ...;   // 注入 IApprovalService
await approval.CreateFlowAsync("expense", "报销审批",
    [new(0, "部门经理", ApprovalApproverType.User, "u_manager", ApprovalMode.Any),
     new(1, "财务",     ApprovalApproverType.User, "u_finance", ApprovalMode.Any)],
    description: "部门经理审核后财务打款");

// ② 业务提交审批
var instanceId = await approval.StartAsync("Expense", "exp-001", "expense", currentUser.UserIdString);
await approval.SubmitAsync(instanceId);

// ③ 审批（消费方待办页触发）
var tasks = await query.GetPendingTasksAsync(new ApprovalTaskQueryInput(ApproverUserId: currentUser.UserIdString));
await approval.ApproveAsync(tasks.Items[0].Id, currentUser.UserIdString, "同意");

// ④ 完成事件回调（业务动作解耦）
[DomainEventHandler]
public class ExpenseApprovedHandler(IMoneyTransferService money) : ILocalEventHandler<ApprovalCompletedEvent>
{
    public async Task HandleEventAsync(ApprovalCompletedEvent e, CancellationToken ct)
    {
        if (e.BusinessType == "Expense" && e.Result == ApprovalInstanceStatus.Approved)
            await money.PayAsync(e.BusinessId, ct);   // 审批通过 → 打款
    }
}
```

## 5. 状态机

```
实例 Instance：
  Draft ──Submit──▶ Pending ──全步骤通过──▶ Approved（终态，IsActive=false）
    │                  │
    └──Withdraw──▶ Withdrawn（终态）  └──任一步驳回──▶ Rejected（终态，IsActive=false）
                                          （终态后业务可重新 Start 新实例——IsActive 释放约束）

任务 Task：
  Pending ──Approve──▶ Approved（本任务通过）
     │       └──Reject──▶ Rejected（实例 Rejected）
     │       └──Transfer──▶ Transferred（新任务 Pending 给 toUserId）
     └──会签（All）：本步骤全部 Approved 后，其余 Pending 任务→Completed
```

## 6. 审批动作与权限

| 动作 | 方法 | 权限（身份硬校验） |
|------|------|------|
| 提交 | `SubmitAsync` | Draft→Pending，建首步任务 |
| 审批 | `ApproveAsync(taskId, approverUserId)` | **仅任务审批人**（`approverUserId == task.ApproverUserId`）可操作，非审批人抛异常；**委派中（Pending）不可 Complete**（须先 Resolve） |
| 驳回 | `RejectAsync(taskId, approverUserId, reason)` | 同上 |
| 转交 | `TransferAsync(taskId, fromUserId, toUserId)` | 仅任务审批人可转交；转交后原任务终态 |
| 撤回 | `WithdrawAsync(instanceId, userId)` | **仅提交人**（Draft/Pending） |
| 委派 | `DelegateTaskAsync(taskId, fromUserId, toUserId)` | 仅任务审批人（不可委派给自己/委派中不可再委派）——委派人成为处理人，原审批人保留 |
| 解决 | `ResolveTaskAsync(taskId, delegateUserId)` | 仅委派人可 Resolve——任务回到原审批人 |
| 加签 | `AppendApproverAsync(taskId, operatedByUserId, appenderUserIds, mode, remark)` | 仅当前审批人；去重（已是本步骤审批人拒绝）；加签人走既有审批流 |
| 抄送 | `AddCCAsync(instanceId, userIds)` | 实例非终态可追加；抄送人仅通知不审批 |

## 7. 审批人解析（角色→用户）

- `ApproverType.User`：内置直接解析（`ApproverValue` = 用户 ID）；
- `ApproverType.Role`：需注册自定义 `IApprovalAssigneeResolver`（角色→用户反查属消费方业务——扩展不跨模块引用 Identity 实体）。示例（经 Identity 查询）：

```csharp
public class MyAssigneeResolver(/* 注入查询服务 */) : IApprovalAssigneeResolver
{
    public async Task<IReadOnlyList<string>> ResolveUserIdsAsync(ApprovalStepDefinition step, CancellationToken ct)
        => step.ApproverType == ApprovalApproverType.User
            ? [step.ApproverValue]
            : await _userRoleQuery.GetUserIdsByRoleAsync(step.ApproverValue, ct);  // 消费方实现
}
```

## 8. 防重复与重新提交

- **防重复**：同业务（BusinessType+BusinessId）**活动实例**（Draft/Pending）唯一（`UX_ApprovalInstance_Active` 唯一约束 + StartAsync 前置检查）——二次 Start 抛 `InvalidApprovalOperationException`；
- **重新提交**：实例终态（Approved/Rejected/Withdrawn）时 `IsActive=false` 释放约束——消费方可直接 `StartAsync` 新实例（如驳回修改后重提）。

## 9. 查询

- `GetInstancesAsync(input)`：实例分页（BusinessType/BusinessId/Status/Submitter/时间）；
- `GetPendingTasksAsync(input)`：待办分页（按审批人 + Pending）；
- `GetInstanceDetailAsync(instanceId)`：详情含任务链 + BusinessDataJson（列表 DTO 不含大字段）。

## 10. v0.2.0 深化能力

### 10.1 委派（Flowable 两阶段——临时代办）

```csharp
// ① 审批人出差，委派给同事（ApproverUserId 切换为委派人，原审批人保留）
await approval.DelegateTaskAsync(taskId, fromUserId: "u_manager", toUserId: "u_deputy");

// ② 委派人处理完，提交给原审批人复核（Resolve——回到原审批人，任何人不可代审）
await approval.ResolveTaskAsync(taskId, delegateUserId: "u_deputy", "已核对，请复核");

// ③ 原审批人复核后 Complete（委派中 Pending 状态委派人不可直接 Complete——须先 Resolve）
await approval.ApproveAsync(taskId, approverUserId: "u_manager", "同意");
```

- **委派 = 临时**（同任务状态切换，原审批人保留可追溯）；**转交 = 永久**（TransferAsync 创建新任务，原任务终态）——两模型并存，按场景选用。
- 委派单层不嵌套（委派中不可再委派）；Resolve 后不可再次委派同任务（须用 Transfer）。
- 审计：委派时间（`DelegatedAt`）/委派人（`DelegatedToUserId`）/原审批人（`OriginalAssigneeId`）全记录。

### 10.2 加签（运行时追加审批人——步骤内并行）

```csharp
// 参与审批：法务加入当前步骤（与财务并行——Any/All 判定复用当前步骤模式）
await approval.AppendApproverAsync(taskId, operatedByUserId: "u_finance",
    appenderUserIds: ["u_legal"], remark: "需法务确认");

// 仅通知：专家知情（不建任务，发布 ApprovalAppendNotifyEvent 供消费方通知）
await approval.AppendApproverAsync(taskId, operatedByUserId: "u_finance",
    appenderUserIds: ["u_expert"], mode: ApprovalAppendMode.Notify);
```

- **加签 ≠ 会签**：会签（`ApprovalMode.All`）= 流程定义时步骤级全部通过；加签 = 运行时动态追加审批人（追加后按当前步骤 Any/All 判定）。
- 去重：已是本步骤审批人/同批重复 → 拒绝（抛 `InvalidApprovalOperationException`）。
- 加签任务继承步骤超时配置（`TimeoutAt` 同规则）。

### 10.3 抄送（仅通知不审批——组装 Notifications 投递）

```csharp
// 发起时抄送（StartAsync 追加可选参数 ccUserIds——命名参数调用）
var instanceId = await approval.StartAsync("Expense", "exp-002", "expense", "u_submitter",
    ccUserIds: ["u_finance", "u_manager"]);   // ⚠️ 位于 ct 之后，须命名参数

// 运行中追加抄送
await approval.AddCCAsync(instanceId, ["u_legal"]);
```

- 抄送位置：`Start`（发起时）/`Finish`（完成时）/`StartFinish`（两者）——`ApprovalCCPosition`。
- **投递边界**：本扩展只发布 `ApprovalCcNotifiedEvent`（含 InstanceId/BusinessType/BusinessId/Result/Position/CcUserIds）**不投递**——消费方 `[DomainEventHandler]` 订阅后组装 Notifications（邮件/短信/站内信）。Withdrawn 不触发 Finish 事件（撤回非审批结果）。

### 10.4 超时自动处理（5 动作——后台任务触发）

```csharp
// 流程定义步骤配置超时（步骤级）：
await approval.CreateFlowAsync("expense", "报销审批",
    [new(0, "部门经理", ApprovalApproverType.User, "u_manager", ApprovalMode.Any)
     { TimeoutMinutes = 48, TimeoutAction = ApprovalTimeoutAction.Remind },
     new(1, "财务", ApprovalApproverType.User, "u_finance", ApprovalMode.Any)
     { TimeoutMinutes = 72, TimeoutAction = ApprovalTimeoutAction.Transfer,
       TimeoutTransferToUserId = "u_finance2" }],
    description: "48h 提醒 / 72h 转交");
```

- **超时动作**：`Remind`（催办事件）/`Transfer`（转交） /`Jump`（跳转步骤）/`Approve`（自动通过）/`Reject`（自动拒绝）。
- **触发**：`IApprovalTimeoutService.ProcessTimeoutTasksAsync()` 由消费方经框架 `IBackgroundJob`/`ITimerService` **周期调用**（扩展不内建调度器）——BackgroundJobs 扩展可观察执行历史；返回本次处理数。
- **系统身份**：超时动作由系统触发（跳过 C1 用户身份校验），审计字段写 `ApprovedBy="system:timeout"`（不冒充审批人）；状态机合法迁移校验保留。
- **防重**：扫描即占位（条件取行 `TimeoutProcessed=false`）——重复调度不重复执行。

## 11. 安全与边界

- **身份硬校验**：审批/驳回/转交/委派/加签仅当前处理人可操作（任何人持有 taskId 不可代审）；超时/系统动作经 internal 方法（不可从消费方调用）；
- **事务原子**：状态变更经 `ITransactionManager` 原子提交（含 v0.2.0 补齐的 WithdrawAsync）；完成事件在提交后派发（非强一致——handler 失败不回滚审批，消费方重试/补偿）；
- **零外部依赖**：无工作流引擎/状态机库（AOT 友好）；
- **不实现**（v0.3.0）：并行分支/条件网关/循环/子流程/审批历史统计/任务清理。
