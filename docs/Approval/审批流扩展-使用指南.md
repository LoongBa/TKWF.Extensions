# Approval 轻量审批引擎-使用指南

> 扩展：`TKWF.Ext.Approval`（v0.1.0）——内置轻量审批引擎（不依赖外部工作流引擎；P1 差异化模块）。
> 本指南公开；迭代开发方案/ADR/审核报告见主框架私有 `_TKWF/docs/03_扩展模块/Approval/`。

---

## 1. 本扩展解决什么

企业应用普遍需要审批流（报销/请假/采购/发布），但主框架无工作流基座（差异化确认）。本扩展提供**内置轻量审批引擎**：
- **审批流定义**（`ApprovalFlow`）：顺序步骤链 + 审批人规则 + 或签（Any）/会签（All）模式；
- **审批实例**（`ApprovalInstance`）：业务实体弱关联（`BusinessType`+`BusinessId`）+ 状态机 + 活动唯一约束；
- **审批任务**（`ApprovalTask`）：步骤级待办（审批/驳回/转交载体）；
- **完成事件**（`ApprovalCompletedEvent`）：审批通过/驳回后经事件总线触发业务动作（解耦）。

**边界**：v0.1.0 支持**顺序步骤链 + 或签/会签**；并行分支/条件网关/设计器 UI/委托/超时 归 v0.2.0。

## 4. 快速开始

```csharp
// ① 定义审批流（提交后一次性）
var approval = ...;   // 注入 IApprovalService
await approval.CreateFlowAsync("expense", "报销审批",
    [new(0, "部门经理", ApprovalApproverType.User, "u_manager", ApprovalMode.Any),
     new(1, "财务",     ApprovalApproverType.User, "u_finance", ApprovalMode.Any)],
    description: "部门经理审核后财务打款");

// ② 业务提交审批
var instanceId = await approval.StartAsync("Expense", "exp-001", "expense", currentUser.UserIdString);
await approval.SubmitAsync(instanceId);

// ③ 审批（消费方待办页触发）
var tasks = await query.GetPendingTasksAsync(new ApprovalTaskQueryInput(ApproverUserId: currentUser.UserIdString));
await approval.ApproveAsync(tasks.Items[0].Id, currentUser.UserIdString, "同意");

// ④ 完成事件回调（业务动作解耦）
[DomainEventHandler]
public class ExpenseApprovedHandler(IMoneyTransferService money) : ILocalEventHandler<ApprovalCompletedEvent>
{
    public async Task HandleEventAsync(ApprovalCompletedEvent e, CancellationToken ct)
    {
        if (e.BusinessType == "Expense" && e.Result == ApprovalInstanceStatus.Approved)
            await money.PayAsync(e.BusinessId, ct);   // 审批通过 → 打款
    }
}
```

## 5. 状态机

```
实例 Instance：
  Draft ──Submit──▶ Pending ──全步骤通过──▶ Approved（终态，IsActive=false）
    │                  │
    └──Withdraw──▶ Withdrawn（终态）  └──任一步驳回──▶ Rejected（终态，IsActive=false）
                                          （终态后业务可重新 Start 新实例——IsActive 释放约束）

任务 Task：
  Pending ──Approve──▶ Approved（本任务通过）
     │       └──Reject──▶ Rejected（实例 Rejected）
     │       └──Transfer──▶ Transferred（新任务 Pending 给 toUserId）
     └──会签（All）：本步骤全部 Approved 后，其余 Pending 任务→Completed
```

## 6. 审批动作与权限

| 动作 | 方法 | 权限（身份硬校验） |
|------|------|------|
| 提交 | `SubmitAsync` | Draft→Pending，建首步任务 |
| 审批 | `ApproveAsync(taskId, approverUserId)` | **仅任务审批人**（`approverUserId == task.ApproverUserId`）可操作，非审批人抛异常 |
| 驳回 | `RejectAsync(taskId, approverUserId, reason)` | 同上 |
| 转交 | `TransferAsync(taskId, fromUserId, toUserId)` | 仅任务审批人可转交；转交后原任务终态 |
| 撤回 | `WithdrawAsync(instanceId, userId)` | **仅提交人**（Draft/Pending） |

## 7. 审批人解析（角色→用户）

- `ApproverType.User`：内置直接解析（`ApproverValue` = 用户 ID）；
- `ApproverType.Role`：需注册自定义 `IApprovalAssigneeResolver`（角色→用户反查属消费方业务——扩展不跨模块引用 Identity 实体）。示例（经 Identity 查询）：

```csharp
public class MyAssigneeResolver(/* 注入查询服务 */) : IApprovalAssigneeResolver
{
    public async Task<IReadOnlyList<string>> ResolveUserIdsAsync(ApprovalStepDefinition step, CancellationToken ct)
        => step.ApproverType == ApprovalApproverType.User
            ? [step.ApproverValue]
            : await _userRoleQuery.GetUserIdsByRoleAsync(step.ApproverValue, ct);  // 消费方实现
}
```

## 8. 防重复与重新提交

- **防重复**：同业务（BusinessType+BusinessId）**活动实例**（Draft/Pending）唯一（`UX_ApprovalInstance_Active` 唯一约束 + StartAsync 前置检查）——二次 Start 抛 `InvalidApprovalOperationException`；
- **重新提交**：实例终态（Approved/Rejected/Withdrawn）时 `IsActive=false` 释放约束——消费方可直接 `StartAsync` 新实例（如驳回修改后重提）。

## 9. 查询

- `GetInstancesAsync(input)`：实例分页（BusinessType/BusinessId/Status/Submitter/时间）；
- `GetPendingTasksAsync(input)`：待办分页（按审批人 + Pending）；
- `GetInstanceDetailAsync(instanceId)`：详情含任务链 + BusinessDataJson（列表 DTO 不含大字段）。

## 10. 安全与边界

- **身份硬校验**：审批/驳回/转交仅任务审批人可操作（任何人持有 taskId 不可代审）；
- **事务原子**：状态变更经 `ITransactionManager` 原子提交；完成事件在提交后派发（非强一致——handler 失败不回滚审批，消费方重试/补偿）；
- **零外部依赖**：无工作流引擎/状态机库（AOT 友好）；
- **不实现**（v0.2.0）：并行分支/条件网关/委托/超时自动处理/审批历史统计/任务清理。
