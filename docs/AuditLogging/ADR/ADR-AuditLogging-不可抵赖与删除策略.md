# ADR-AuditLogging-不可抵赖与删除策略

> **版本**：v0.2
> **状态**：**已通过 Oracle5 评审（PASS WITH CONDITIONS，E1–E10 已闭环）**；待实施
> **关联**：`docs/AuditLogging/审计三面分层与业务审计-开发方案.md` §五（G4）/§七；需求来源 DMP-Lite《审计能力装配分析》§4 G4/§3.2；《设计原则手册》P3/P7/P14
> **日期**：2026-11-27

## 目的与目标

把审计记录确立为**默认不可变（append-only）**：审计事实一经落库不可单条删除，仅保留"保留期清理"这一有界、可审计的回收能力；任何删除动作本身必须留痕且限特权。目标是满足"审计日志不可删除/不可篡改"的合规语义，同时不引入 `AllowDelete` 之类的运行期能力开关。读者 3 句话内明白：当前 V0.4.0 管理 API 带单条物理删除；本 ADR 把"删除"从默认能力降级为**独立的、特权的、必留痕**的能力；不可变是默认，而非开关。

## 问题

### 问题现象

1. `AuditLogging` V0.4.0 管理 API 含 `DeleteAsync(id)` 单条物理删除（证据：`_Framework/AuditLogging/DataServices/AuditLogEntityDataService.cs:239`；README §196 明示推翻 V0.3.0"无单条删除"限定）。
2. 删除动作**本身不产生审计留痕**——删除审计记录无法被反查，形成"审计可被静默抹除"的合规漏洞。
3. 双清理路径语义分裂（G12 关联）：门面 `CleanupExpiredAsync()` 无限轮+静默 vs 端点 `CleanupAsync()` 100 轮+抛。

### 触发场景

- 合规审计要求"审计日志不可篡改/不可删除"。
- 误删/恶意删除审计记录的风险场景。
- 需要区分"正常工作负载回收（保留期清理）"与"针对特定记录的删除"。

### 现有方案的不足

- **默认可删**：单条删除默认开放，违背"缺省=守卫硬失败"（P7）。
- **删除无痕**：删除不写审计/安全事件，无法追责。
- **开关思路诱人**：加 `AllowDelete=false` 布尔开关看似灵活，但把"安全性"降级为可运行时翻转的能力矩阵（P3 反模式）。

## 使用场景

| 场景 | 使用方式 |
|---|---|
| 默认部署 | 不注册单条删除能力 → **端点/方法不存在（404/无方法）**（能力=注册，E3）；非"存在但抛错" |
| 保留期回收 | `PurgeAsync(cutoff, batch, maxRounds, ct)`：有界、可取消、失败可见，产出 `AuditCleanupCompleted` |
| 合规"法务保留解除"（罕见） | 显式启用特权删除能力 + `IAuditAccessPolicy` 强校验 + 删除动作写业务审计留痕；**结构化错误仅在此已注册特权路径 + 策略拒绝时** |
| 防篡改增强（可选） | 启用 `IAuditIntegrityProvider`（哈希链/签名），默认关 |

**不适用边界**：不定义法务保留（Legal Hold）的完整模型（本期仅"默认不可删 + 特权删留痕"）；不改变 SecurityLog（本就无单条删除）；不实现签名审计的密钥管理（若启用完整性，密钥归消费方）。

---

## 决策

1. **默认 append-only（E3）**：单条删除能力**不注册即不存在**（P3 能力=注册），默认部署无删除入口（端点 404/无方法）；结构化错误仅存在于"已注册特权路径 + 策略拒绝"。
2. **保留清理为独立有界能力**：`PurgeAsync` 单一入口（有界轮次 + 取消 + 失败可见），替换旧"无限循环静默"路径（G12 收敛）。
3. **特权删除 = 独立注册 + 强校验 + 必留痕**：仅显式启用时存在；经 `IAuditAccessPolicy` fail-closed 校验；删除前写 `BusinessAuditEntry`（Action=`Purged`/`Deleted`，Target=目标记录）。
4. **不用 `AllowDelete` 开关**：以"注册/未注册"表达能力，避免运行期布尔矩阵。
5. **可选完整性（P2 延后）**：`IAuditIntegrityProvider` 抽象就位，默认不启用；启用时前条 hash→本条 hash，篡改可检测。

## 备选方案

| 方案 | 放弃原因 |
|---|---|
| A. `AuditImmutabilityOptions.AllowDelete=false` 开关 | P3 反模式；默认可翻转不安全 |
| B. 保留单条删除但强制写日志 | 默认仍可删；"可删"本身违背不可抵赖 |
| C. 完全不实现删除（含保留清理） | 日志无限膨胀；合规留存窗口无法回收 |
| D. 软删除（IsDeleted） | 审计"不可变"语义被软删绕过；且需改查询谓词 |

## 后果

- **正面**：默认满足"不可删除"；删除可追责；清理有界可观测。
- **负面/缓解**：误录纠错需走"特权删除 + 留痕"（可接受，合规优先）；`PurgeAsync` 替换旧语义 → 0.x 内破坏 + 适配说明；完整性启用有额外计算成本 → 默认关。
