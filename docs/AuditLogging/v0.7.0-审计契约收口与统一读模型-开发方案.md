## 一、背景与目标

v0.6.0 完成"三面分层 + 业务事实审计 + 同步优先信号层"，BLOCKER 清零、120+61 测试全绿。v0.7 的目标不是"逐条补洞"，而是**把审计能力从"能写能查"升级为"统一读模型 + 可集成 + 可扩展 + 可治理"**，并为 v0.8 的导出/水位/Web/完整性打好单一底座。

**定位（3 句话）**：① 以**统一读模型（`IAuditQueryService` + `IAuditFacetReader`）**作为读侧唯一骨架，业务审计读面与未来导出/水位都构建其上（避免"先三面各做一遍再重构"）；② 补齐**业务审计读面暴露（REST/GraphQL + 受控详情 DTO）**与**权限/数据域治理**（含 Permissions 集成）；③ 提供**业务自定义维度扩展点（Attributes）**与 **Actor 自动派生**，让"业务可能需要扩展审计信息"不靠改表实现。

## 二、范围与切片

### 2.1 v0.7.0（本迭代）

1. **E9 契约随迁**：`IAuditLogQueryService`/`IAuditLogAnalyticsService`/`AuditLoggingOptions` → `AuditLogging.Abstractions`（namespace 不变，零代码改动，SecurityLog V0.3.0 先例）。
2. **统一读模型**：`IAuditQueryService`（统一门面）+ `IAuditFacetReader`（分面读取契约）+ `AuditRecordView` 及三子类型（`InvocationAuditView`/`SecurityAuditView`/`BusinessAuditView`）。
3. **业务审计读面暴露**：`IBusinessAuditQueryService` 生成 REST/GraphQL（`[GenerateController]` + `[ApiExpose]`）；新增受控详情 DTO（含 `Before/After`/`Attributes`），`Detail` 操作经 `IAuditAccessPolicy` 门控。
4. **访问策略组合 + Permissions 集成**：`DefaultAuditAccessPolicy` 可选依赖 `IPermissionChecker`（Permissions.Abstractions），按 `AuditPermissionNames` 判定；未启用 Permissions 回退 `AllowWithoutPermissions`；`QueryOwn` 绑定调用方租户。
5. **`IAuditActorProvider` 接线**：`BusinessAuditWriter` 在 `Actor` 为空时由 provider 派生；仍为空则抛（fail-closed）。
6. **`Attributes` 扩展点**：`BusinessAuditEntry.Attributes` → `BusinessAuditEntity.AttributesJson`（`[MaxLength(-1)]`，同 `IAuditMaskingPolicy` 脱敏）；详情透出、列表裁剪。
7. **`AuditImmutabilityOptions` 落地**：特权删除 = 独立门面 `IAuditPrivilegedDeleteService`（**默认不注册**，能力=注册）+ `AuditOperation.Delete` 强校验 + 写 `BusinessAudit` 留痕。

### 2.2 v0.8.0（延后，基于 v0.7 底座）

G6 导出（`IAuditExportService` + CSV/Excel formatter + 上限 + 留痕 + E6 `AuditExportCompleted`，消费 `IAuditQueryService`）；G8 统一水位编排/Outbox（基于 `IAuditFacetReader.GetIncrementalAsync`）；G9 Web ambient（独立 `TKWF.Ext.AuditLogging.Web`）；`IAuditIntegrityProvider`（哈希链）；TenantId 存量迁移 DDL。

## 三、统一读模型（v0.7 核心）

### 3.1 契约（Abstractions）

```csharp
// 统一记录视图（跨面可比）
public abstract record AuditRecordView(
    AuditFacet Facet, long Id, AuditActor? Actor, AuditTarget? Target,
    string? ActionType, string? Summary, string? CorrelationId,
    DateTimeOffset ExecutionTime, IReadOnlyDictionary<string, object?>? Attributes);

public sealed record InvocationAuditView(... ServiceName, MethodName, DurationMs, Success, ...) : AuditRecordView;
public sealed record SecurityAuditView(... EventType, Result, IpAddress, UserName, ...) : AuditRecordView;
public sealed record BusinessAuditView(... BeforeJson, AfterJson, ...) : AuditRecordView;

// 分面读取契约（每面一实现，集合注册）
public interface IAuditFacetReader : IDomainService
{
    AuditFacet Facet { get; }
    Task<AuditFacetPageResult> QueryAsync(AuditFacetQuery query, CancellationToken ct = default);
    Task<AuditRecordView?> GetDetailAsync(long id, CancellationToken ct = default);
    Task<long> CountAsync(AuditFacetQuery query, CancellationToken ct = default);
    Task<IReadOnlyList<AuditRecordView>> GetIncrementalAsync(long afterId, int batch, CancellationToken ct = default);
}

// 统一门面（facet 定向查询 + CorrelationId 跨面聚合；不提供跨面统一分页）
public interface IAuditQueryService : IDomainService
{
    Task<AuditFacetPageResult> QueryAsync(AuditFacet facet, AuditFacetQuery query, CancellationToken ct = default);
    Task<AuditRecordView?> GetDetailAsync(AuditFacet facet, long id, CancellationToken ct = default);
    Task<long> CountAsync(AuditFacet facet, AuditFacetQuery query, CancellationToken ct = default);
    Task<IReadOnlyList<AuditRecordView>> GetByCorrelationAsync(string correlationId, CancellationToken ct = default);
    Task<IReadOnlyList<AuditRecordView>> GetIncrementalAsync(AuditFacet facet, long afterId, int batch, CancellationToken ct = default);
}
```

- **注册**：`IAuditFacetReader` 用 `TryAddEnumerableConstructible`（ADR92 集合，写门槛面自行注册实现）；`IAuditQueryService` 用 `AddConstructibleService`。
- **实现**：三面各一 Reader（Invocation→`AuditLogEntityDataService`；Security→`SecurityLogEntityDataService`；Business→`BusinessAuditEntityDataService`）；`AuditQueryService` 遍历 Reader 集合按 `Facet` 定向委托。
- **跨面聚合**：仅支持 `GetByCorrelationAsync`（按 CorrelationId 分别查三面后合并，小集合）；**不支持跨面统一分页**（各表无统一排序键/索引，合并分页成本高且语义不一致）。

### 3.2 关键前瞻性裁定（写入 ADR）

- **统一的是"读契约与视图"，不是"写表"**（写仍三面分立，P2 单一事实源）。
- **跨面不做统一分页**，只做 `CorrelationId` 聚合；需要全量跨面检索/导出的场景（如 SIEM、平台总览）走 v0.8 的"逐面水位 + 平台编排"，不把三表并成大表。
- **`AuditRecordView` 用子类型而非大字典**（强类型、可演进；`Attributes` 承载业务自定义维度）。

## 四、业务审计读面暴露

- `IBusinessAuditQueryService` 实现类加 `[GenerateController]` + `[ApiExpose]`（REST + GraphQL，方法级 `ExposeRest/ExposeGraphQL` 可收窄）。
- **受控详情 DTO**：`BusinessAuditDetailDto`（含 `BeforeJson/AfterJson/AttributesJson`，脱敏后）——仅 `Detail` 操作经 `IAuditAccessPolicy` 放行时返回；列表 DTO 不含 Before/After/Attributes 全文。
- **端点**：list / detail / count / incremental（facet 定向）。权限键：`AuditLogging.Query/QueryAll/Detail`。
- **数据域**：`QueryOwn`（绑定调用方租户）vs `QueryAll`（跨租户，需权限）；见 §五。

---

## 五、访问策略组合 + Permissions 集成

- `IAuditAccessPolicy` 保持唯一策略契约；`DefaultAuditAccessPolicy` 依赖可选 `IPermissionChecker?`（Permissions.Abstractions，`GetService` 解析，未启用为 null）。
- 判定顺序：`QueryOwn` → 已认证且绑定调用方租户（空租户拒绝）；`QueryAll/Detail/Export/Delete/Purge` → ① `IPermissionChecker` 可用则按 `AuditPermissionNames.*` 判定；② 否则 `AllowWithoutPermissions`（默认 false → 拒绝）。
- **fail-closed** 默认；策略可被消费方 `Replace`。
- `AuditAccessRequest` 增 `TenantId`（已有）、`IsAuthenticated`（已有）；补 `requiredPermissions` 可选。

## 六、`IAuditActorProvider` 与 `Attributes` 扩展点

### 6.1 Actor 自动派生（接线）

`BusinessAuditWriter.SaveAsync`：`entry.Actor` 为空时调用 `IAuditActorProvider.ResolveActor()`；仍为空则抛 `ArgumentNullException`（fail-closed）。默认 provider 返回 null（保持"显式优先"）。系统帧/后台任务可注册派生实现（返回 `AuditActor.Job/System`）。

### 6.2 Attributes 扩展点

- 契约：`BusinessAuditEntry.Attributes`（`IReadOnlyDictionary<string, object?>?`）。
- 实体：`BusinessAuditEntity.AttributesJson`（`[MaxLength(-1)]`）。
- 写入：`IAuditMaskingPolicy.Mask(attributes)` 后序列化。
- 读出：详情 DTO 透出；列表裁剪。
- **边界**：JSON 列仅"携带上下文"，**非主查询维度**；需要强检索时提升为类型化列（ADR 写明升级路径）。

---

## 七、`AuditImmutabilityOptions` 落地（特权删除）

- 新增独立门面 `IAuditPrivilegedDeleteService`（`[ApiExpose]`，方法级可关）：`DeleteAsync(facet, id, reason)`。
- **默认不注册**（能力=注册，ADR 决策）；启用时：`IAuditAccessPolicy.EvaluateAsync(Delete)` 强校验 → 删除前写 `BusinessAuditEntry`（Action=`Deleted`，Target=目标记录，Reason）留痕 → 执行删除。
- 删除留痕通过 `IBusinessAuditWriter`（同一脱敏/失败信号管线）。

## 八、E9 契约随迁

`IAuditLogQueryService`/`IAuditLogAnalyticsService`/`AuditLoggingOptions` + 相关 DTO 自主包迁 `AuditLogging.Abstractions`（namespace 不变）。主包 `ProjectReference` 契约包；消费方零 using 迁移。对齐 `SecurityLog.Abstractions` V0.3.0 先例。

## 九、实施计划与测试

### 9.1 顺序

Abstractions（新契约 + E9 随迁）→ 三面 `IAuditFacetReader` 实现 + `IAuditQueryService` → 业务审计读面端点/详情 DTO → Access 策略组合/Permissions → ActorProvider 接线 → Attributes 扩展点 → 特权删除 → 测试 → 文档 → 本地部署 → tag。

### 9.2 测试矩阵（P11/P12）

| 面 | 用例 |
|---|---|
| 统一读模型 | 三面 reader 定向查询/详情/计数/增量；`GetByCorrelationAsync` 跨面聚合；跨面分页"不支持"边界断言 |
| 业务审计暴露 | 端点 list/detail/count/incremental；详情含 Before/After/Attributes 仅 Detail 放行时返回 |
| 访问策略 | Permissions 启用→按 AuditPermissionNames；未启用→AllowWithoutPermissions；QueryOwn 租户绑定/空租户拒绝 |
| ActorProvider | 空 Actor + provider 派生；provider 返回 null → 抛 |
| Attributes | 脱敏生效、`[MaxLength(-1)]`、读写往返、列表裁剪 |
| 特权删除 | 默认未注册（能力不存在）；启用后策略强校验 + 留痕 |
| 变异实弹 | 各守卫回退→失败→恢复（P11） |

### 9.3 门控/诊断

无新增 SG 管线；`IAuditFacetReader` 集合注册用 ADR92 `TryAddEnumerableConstructible`；生成物走既有 xCodeGen。
