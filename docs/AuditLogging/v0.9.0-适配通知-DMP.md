# AuditLogging v0.9.0 适配通知（致项目组 / DMP-Lite）

> 适用：已接入 `TKWF.Ext.AuditLogging` / `TKWF.Ext.SecurityLog` 的消费方项目。
> 版本：`AuditLogging/v0.9.0` + `AuditLogging.Abstractions/v0.2.2` + `SecurityLog/v0.5.2` + `AuditLogging.Web/v0.1.0`（已打 tag、已本地部署至 `%TKWFDeployPath%\build\refs\` 与 `build\extensions\refs\`）。
> 结论：**需适配**（1 项 DDL + 3 项契约/行为变更）；其余为可选增强。

---

## 一、必改项（Breaking / 运维必做）

### 1. 数据库加列（生产必做）

`AuditLogEntity` 与 `SecurityLogEntity` 新增可空列 `TenantId`（C11）。

- **开发环境**：`UseAutoSyncStructure=true` 自动加列，无需操作。
- **生产环境**：`UseAutoSyncStructure` 只建新表/加新列（不 ALTER 已有列类型），但**新增可空列**可由 SyncStructure 自动补；若生产关闭自动同步，请手动执行：

```sql
-- PostgreSQL
ALTER TABLE "TKWF_AuditLog"       ADD COLUMN "TenantId" BIGINT NULL;
ALTER TABLE "TKWF_SecurityLog"    ADD COLUMN "TenantId" BIGINT NULL;
ALTER TABLE "TKWF_BusinessAudit"  ADD COLUMN "AttributesJson" TEXT NULL;

-- SQL Server
ALTER TABLE [TKWF_AuditLog]       ADD [TenantId] BIGINT NULL;
ALTER TABLE [TKWF_SecurityLog]    ADD [TenantId] BIGINT NULL;
ALTER TABLE [TKWF_BusinessAudit]  ADD [AttributesJson] NVARCHAR(MAX) NULL;

-- SQLite
ALTER TABLE TKWF_AuditLog       ADD COLUMN TenantId BIGINT NULL;
ALTER TABLE TKWF_SecurityLog    ADD COLUMN TenantId BIGINT NULL;
ALTER TABLE TKWF_BusinessAudit  ADD COLUMN AttributesJson TEXT NULL;
```

> **可执行脚本**：`docs/AuditLogging/v0.9.0-DDL-生产加列.sql`（Pg/SqlServer/SQLite 三方言 + 校验查询，可直接交 DBA 执行）。
> 可空单义：存量行为 `NULL`，不影响既有查询；租户过滤仅在传入 `TenantId` 时生效。

### 2. `AuditImmutabilityOptions` 已删除（如引用需移除）

`AuditLogging.Abstractions` 中 `AuditImmutabilityOptions.AllowPrivilegedDelete` **已移除**（C3：特权删除改为"能力注册即存在"）。
- 若 `appsettings.json` 配置了 `TKWF:AuditLogging:AllowPrivilegedDelete` → 可直接删除该键（不再被读取）。
- 若代码 `services.Configure<AuditImmutabilityOptions>(...)` → 删除该行（类型已不存在，编译失败）。
- 未引用该类型 → **零改动**。

### 3. `IAuditAccessPolicy` 升级为领域服务（自定义实现需适配）

`IAuditAccessPolicy` 现继承 `IDomainService`，默认实现改为 `DomainServiceBase` + `AddConstructibleService`（C9）。

- **未自定义策略**（使用默认 fail-closed）→ **零改动**。
- **自定义了 `IAuditAccessPolicy` 实现** → 需改为：
  1. 继承 `DomainServiceBase`，ctor 增加 `IDomainUser user` 并 `: base(user)`；
  2. 注册改用 `services.AddConstructibleService<IAuditAccessPolicy, 你的实现>()`；
  3. 解析改 `User.Use<IAuditAccessPolicy>()`（不再 `GetService`）。

### 4. 业务审计查询"拒绝"语义变更（调用方需处理）

`IBusinessAuditQueryService.GetListAsync / CountAsync / GetDetailAsync` 在访问被拒绝时**不再返回空结果 / null**，改为抛 `AuditAccessDeniedException`（`ErrorCode = "AUDIT_ACCESS_DENIED"`）（C2）。

- 调用方若依赖"拒绝即空"语义 → 需 `try/catch (AuditAccessDeniedException)` 或改为保证放行。
- 放行方式（任选）：
  - 配置 `TKWF:AuditLogging:AccessPolicy:AllowWithoutPermissions = true`（无 Permissions 的独立部署，需自担风险）；或
  - 自定义 `IAuditAccessPolicy` 实现（可基于 Permissions 判定，注册为域服务）替代默认策略。

---

### 5. Web 端点迁移（若已用 v0.8.x in-package Web）

v0.9.0 起业务审计 Web 端点**移出主包**，改由独立包 `TKWF.Ext.AuditLogging.Web` 承载（主包已移除 `FrameworkReference Microsoft.AspNetCore.App`）。

- 若你在 v0.8.x 已装配 in-package `AuditLoggingWebExtension`：
  1. 引用 `TKWF.Ext.AuditLogging.Web`；
  2. 增 `[TKWFEnabledExtension(typeof(AuditLoggingWebExtensionInitializer<>))]`；
  3. `UseWebExtensions(e => e.Add<TKWF.Ext.AuditLogging.Web.AuditLoggingWebExtension>())`（命名空间改为 `.Web`）；
  4. 移除对主包 `AuditLoggingWebExtension` 的引用。
- 未用 Web 端点 → **零改动**（只要不依赖主包传递的 AspNetCore 共享框架）。

## 二、可选增强（非必改，建议采用）

| 能力 | 用法 |
|------|------|
| 统一读模型 | `User.Use<IAuditQueryService>()` → `QueryAsync(facet, query)` / `GetDetailAsync` / `CountAsync` / `GetByCorrelationAsync` / `GetIncrementalAsync`；缺面抛 `AuditFacetUnavailableException` |
| 导出（G6） | `User.Use<IAuditExportService>().ExportAsync(facet, query, AuditExportFormat.Csv\|JsonLines, stream)` |
| 完整性校验 | `IAuditIntegrityProvider.ComputeHashAsync / VerifyAsync`（默认 SHA-256，可 Replace） |
| 水位（G8） | `IAuditWatermarkStore.GetAsync / SetAsync`（默认内存，生产建议 Replace 为持久化） |
| 业务审计扩展 | `BusinessAuditEntry.Attributes`（脱敏后落 `AttributesJson`）；`BusinessAuditQueryInput.AfterId`（keyset 深分页/导出） |
| 特权删除（C4，opt-in） | `services.AddAuditPrivilegedDelete()` → `User.Use<IAuditPrivilegedDeleteService>().DeleteAsync(facet, id, reason)`（先写脱敏快照留痕后删；Security 面 append-only 不支持） |
| 业务审计 Web 端点（C6/G9，opt-in） | 引用 `TKWF.Ext.AuditLogging.Web`；`[TKWFEnabledExtension(typeof(AuditLoggingWebExtensionInitializer<>))]` + `UseWebExtensions(e => e.Add<AuditLoggingWebExtension>())` → `POST /api/audit-logging/business-audit/query` + `GET /api/audit-logging/business-audit/{id}`（安全 DTO）+ `GET /api/audit-logging/business-audit/{id}/detail`（**受控详情**，需 `AuditOperation.Detail` 放行）；均 `RequireAuthorization`。**主包 v0.9.0 已移除 `FrameworkReference Microsoft.AspNetCore.App`**（Web 依赖仅在 Web 包，非 Web 消费方不再被动引用 AspNetCore）。 |

## 三、兼容性确认（零影响清单）

- `IAuditLogStore` 契约不变（实现类 `AuditLogStore` → `AuditLogWriter` 仅内部改名，DI 解析 `IAuditLogStore` 不受影响）。
- `IAuditLogQueryService` / `IAuditLogAnalyticsService` 签名不变（E9 仅程序集随迁，`namespace` 不变）。
- **`IBusinessAuditWriter` 新增 `SaveStrictAsync`**（自定义实现方需补该方法；仅用默认实现者零改动）。
- **导出默认拒绝**：`IAuditExportService.ExportAsync` 需 `AuditOperation.Export` 放行（配置 `TKWF:AuditLogging:AccessPolicy:AllowWithoutPermissions=true` 或自定义 `IAuditAccessPolicy`）；系统帧（后台作业）需 `AllowWithoutPermissions=true` 才放行。
- 新增配置键：`TKWF:AuditLogging:FailurePolicy:FailOpen`、`TKWF:AuditLogging:EventPublishing:PublishEvents`、`TKWF:AuditLogging:AccessPolicy:AllowWithoutPermissions`（宿主须注册 `IConfiguration`；非 Web 宿主未注册时审计组件解析失败）。
- `AuditLoggingOptions` 位置随迁（namespace 不变），配置节 `TKWF:AuditLogging` 不变。
- SecurityLog 除新增 `TenantId` 列外无其他契约变更。
