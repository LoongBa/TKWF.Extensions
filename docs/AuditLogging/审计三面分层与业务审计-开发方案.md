## 一、背景与目标

### 1.1 触发

DMP-Lite 转达《审计能力装配分析》，请求裁定 12 项通用能力缺口（G1–G12）与 6 个审计生命周期事件（E1–E6），并明确"业务特殊需求（§3，15 类业务事件）≠ 通用能力缺口（§4）"。

### 1.2 定位与目标

> **审计三面分层（写模型分立，P2 每面单一事实源）+ 统一只读门面（读模型单源）+ 同步优先的信号层（审计不能丢）。**

| 面 | 语义 | 载体 | 现状 |
|---|---|---|---|
| 调用审计 | 方法调用事实 | `AuditLogging` | 已有 |
| 安全事件审计 | 认证/授权事件 | `SecurityLog` | 已有 |
| **业务事实审计** | 实体/对象生命周期（Target+Action+Before/After+Actor） | **`AuditLogging.Business`（新增面）** | **缺（G1/G2）** |

目标状态（3 句话内）：补齐"业务事实审计"面，使消费方以统一形状记录业务对象变更；把脱敏/失败/不可抵赖/清理收敛为单一策略/单一入口（消除空转与静默）；审计信号**同步回调为主、本地事件为辅（默认关）**，杜绝"写失败 + 未启用派发 = 双丢"。

### 1.3 与 DMP 诉求的分界（不可互替）

- **通用能力（扩展提供）**：三面模型、统一读模型（v0.7）、Actor、脱敏、失败信号、不可变、权限、清理、事件、导出/水位（分批）。
- **业务语义（消费方声明）**：DMP 15 类业务事件经 `IBusinessAuditWriter` 门面自建，扩展不硬编码、不改表结构。

## 三、总体架构

### 3.1 三面分层（写分立）

```
写模型：AuditLogEntity（调用） / SecurityLogEntity（安全事件） / BusinessAuditEntity（业务事实）
读模型：v0.6 IBusinessAuditQueryService（单面，诚实）；v0.7 IAuditQueryService（统一，additive）
```

### 3.2 Actor 模型（★E1 闭环）

`AuditActor(ActorType, Id, DisplayName)`，`ActorType ∈ {User, System, Job, Service, Anonymous}`。

- **Actor 必填显式传入**（P5 显式优于自动）——`BusinessAuditEntry.Actor` 非空；系统帧 `AuditActor.System("job:{name}")`。
- 可选扩展点 `IAuditActorProvider`（Abstractions）：消费方可注册从环境自动派生；**默认实现返回 null → 强制显式**（不依赖 `IDomainUser`/框架内部环境访问器，可判定）。

### 3.3 信号层（同步优先）

```
落库成功 →（可选，默认关）本地事件 Persisted
落库失败 → ① 同步 IAuditFailureHook.OnPersistFailed（恒触发，不静默）
           ② IAuditDiagnostics 计数
           ③ AuditFailurePolicy（FailOpen 默认 / FailClosed）
           ④（可选，默认关）本地事件 PersistFailed
```

依据：`横切设计域.md:32`「审计类需求不能丢→同步回调」；事务时序安全实证：`ILocalEventBus` Pre-commit 收集 → PostProceed 派发、永不重抛（框架 CHANGELOG v4.9.99:769）。

| `AuditLoggingOptions`（随迁） | `[Options("TKWF:AuditLogging")]` |

### 4.4 ★E1 `IBusinessAuditWriter` 注册与消费形态（决定性）

| 项 | 规格 |
|---|---|
| 注册形态 | **接线型** `TryAddScoped<IBusinessAuditWriter, BusinessAuditWriter>`（ctor `IServiceProvider`+`ILogger`+`IOptions<…>`；无 `IDomainUser`）。先例 `AuditLogStore.cs:22-34` |
| 域帧消费 | `User.GetService<IBusinessAuditWriter>()`（`Use<T>()` 约束 `: IDomainService`，接线型门面不适用——已按 Oracle E1 落定写法）。**先行验证用例**入 §9.3 |
| 系统帧消费 | `provider.GetRequiredService<IBusinessAuditWriter>()`（BackgroundJob/System scope） |
| DataService | 懒解析 `_sp.GetRequiredService<BusinessAuditEntityDataService>()`（C1 延迟，不触 DI004） |

### 4.5 ★E2 `IAuditAccessPolicy` 默认规则（决定性）

默认实现 `DefaultAuditAccessPolicy`：

| Operation | 默认判定 |
|---|---|
| `QueryOwn` | 已认证即放行 |
| `QueryAll` / `Detail` / `Export` / `Delete` / `Purge` | `IPermissionChecker` 可用（Permissions 启用）→ 按 `AuditPermissionNames.*` 判定，缺权限拒绝；否则仅当 `AuditAccessPolicyOptions.AllowWithoutPermissions=true` 放行，**默认 false → 拒绝** |

- 与 `[RequirePermission]` 叠加：特性在 Permissions 启用时做编译期权限名校验；策略是扩展级守卫，**Permissions 未启用时仍生效**（fail-closed）。
- **out-of-box 适配通知**：敏感端点默认拒绝，消费方须启用 Permissions 或显式 `AllowWithoutPermissions`。

## 六、事件契约（E1–E6）

| 事件 | 裁定 | 传输 | 默认 | 依据 |
|---|---|---|---|---|
| E1 `AuditLogPersisted` | 接受（便利扇出） | 本地事件 | 关 | 权威在库 |
| E2 `AuditLogPersistFailed` | **主通道同步 hook**；事件仅副本 | 同步回调（主）+ 本地事件（次） | hook 恒开 | 审计不丢；纯 async 双丢 |
| E3 `SecurityLogPersisted` | 同 E1 | 本地事件 | 关 | 风控便利 |
| E4 `SecurityLogPersistFailed` | 同 E2 | 同步 hook 主 | hook 恒开 | 同上 |
| E5 `AuditCleanupCompleted` | 接受 | 同步返回值（权威）+ 事件 | 事件关 | 运维观测 |
| E6 `AuditExportCompleted` | **延后 v0.7**（v0.6 无发布点） | — | — | ★E8，避免"声称未实现" |

**契约约束**：① 提交后发布，失败事件永不抛；② 载荷最小化（禁 `ArgumentsJson`/`Detail` 原文）；③ 失败隔离；④ 本地事件走 `ILocalEventBus`，消费方须 `AddEventDispatch()`；⑤ **启动守卫（★E4：统一为复用框架门控，不做扩展自造 fail-fast）**——`PublishEvents=true` → 一次性醒目启动提示 + 复用框架 `EventDispatchFilter` 门控（V4.9.102/ADR35 #6）；文档列为硬前置；⑥ 可关闭/零订阅零开销；⑦ 契约在 Abstractions。

**发布点**：扩展 store 实现内、落库成功后同栈（先例 `ChannelConfigChanged.cs:8-9`、`FeatureManager.cs:349-351`）。
**时序归属（§7.7）**：扩展保证"提交后发布"；消费方保证 `AddEventDispatch()`；扩展以醒目提示 + 框架门控暴露前置缺失。

| 列 | 类型 | 说明 |

### 7.2 CorrelationId 单源

统一 `NVARCHAR(128)`（AuditLog 现 128、SecurityLog 现 64→加宽 128），单一常量 `AuditCorrelationId.MaxLength=128` 于 Abstractions。

### 7.3 迁移

- 新表 `TKWF_BusinessAudit`：开发自动建，**生产 DBA 执行 DDL**（写入使用指南）。
- SecurityLog `CorrelationId` 64→128：存量库 `ALTER TABLE`（SQLite 忽略；Pg/SqlServer 显式加宽）。
