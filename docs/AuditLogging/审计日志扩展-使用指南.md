# 审计日志扩展使用指南

**扩展**: `TKWF.Ext.AuditLogging` | **版本**: V0.5.1 | **框架**: .NET 10

---

## §1 概述

`TKWF.Ext.AuditLogging` 是 TKWF 框架的审计日志扩展，提供方法级调用事件的数据库存储与查询。

**核心能力**：
- 记录调用者、目标方法、参数（脱敏 JSON）、耗时、成功/异常、关联 ID
- FreeSql 持久化（异常静默处理，不阻塞业务）
- SG1 声明式实体（自动建表）
- **查询 API**（V0.2.0）：按时间范围/用户/服务名/方法名等条件分页查询审计日志
- **统计聚合 API**（V0.3.0 + V0.4.2）：调用次数 TopN（按服务名/用户名，**V0.4.2 起经 `GroupCountAsync` SQL 下推**）+ SQL 级统计（成功/失败/平均/最大耗时）
- **保留天数清理**（V0.3.0）：按 `RetentionDays` 分批物理删除过期审计日志（合规留存窗口回收）
- **管理 API**（V0.4.0）：5 REST 端点（列表/详情/清理/统计/单条删除）——`[GenerateController]` 由消费方 SG1 生成
- 消费方 opt-in 启用（不强制）

**与主框架的关系**：
- `IAuditLogStore` + `AuditLogEntry` + `AuditLogFilterAttribute` 由主框架定义
- 本扩展提供 `AuditLogStore` 实现 + `IAuditLogQueryService` 查询服务 + `IAuditLogAnalyticsService` 分析服务 + 自动注册

## §2 快速开始

### 1. 添加引用

```xml
<!-- 消费方 .csproj：源码模式（本仓库联调） -->
<ProjectReference Include="..\..\_Framework\AuditLogging\TKWF.Ext.AuditLogging.csproj" />

<!-- NuGet 包模式（推荐，已发布 TKWF.Ext.AuditLogging） -->
<PackageReference Include="TKWF.Ext.AuditLogging" Version="0.5.1" />
```

> **依赖条件（V4.10.39 聚合 SQL 下推）**：
> - **主项目数据访问管线须为 FreeSql**（框架默认）——扩展存储实现为 FreeSql 特定；TopN 聚合（`GetTopServicesAsync`/`GetTopUsersAsync`）经框架 `FreeSqlQueryableExtensions.GroupCountAsync` 下推 SQL（GROUP BY + COUNT + ORDER BY COUNT DESC + LIMIT，替代既有 `Take(100_000)` + 内存 GroupBy），**仅认 FreeSql 支撑的 IQueryable**（非 FreeSql 管线调用会抛"仅支持 FreeSql 支撑的 IQueryable"）。
> - **不构成 ORM 锁定**（ADR15 按 ORM 分层）：换 ORM 影响面仅聚合调用点——EF Core 原生 GroupBy 可替代（翻译成熟），主体存储/查询代码 ORM 无关。

### 2. 启用扩展（v4.9.85+ 必需）

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.AuditLogging;

[TKWFEnabledExtension(typeof(AuditLoggingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

### 3. 启用审计日志过滤器

白名单声明后，在消费方 `ConfigureGlobalFilters` 中启用过滤器：

```csharp
protected override void ConfigureGlobalFilters(FilterBuilder<MyUserInfo> builder)
{
    // 启用审计日志（opt-in）
    builder.AddAuditLog();
}
```

### 4. 自定义过滤器参数（可选）

```csharp
builder.AddAuditLog(filter =>
{
    // 为匿名调用记录审计日志（默认 false）
    filter.IsEnabledForAnonymous = true;
    // 序列化返回值到审计记录（默认 false，慎用）
    filter.SaveReturnValues = false;
});
```

### 5. 运行

应用启动后，所有启用了 `AddAuditLog()` 过滤器的服务方法调用会被自动记录到 `TKWF_AuditLog` 表。

## §3 配置

通过 `appsettings.json` 配置审计日志选项（仅 `RetentionDays`/`CleanupBatchSize` 为当前生效项）：

```json
{
  "TKWF": {
    "AuditLogging": {
      "RetentionDays": 90,
      "CleanupBatchSize": 500
    }
  }
}
```

### 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `IsEnabled` | bool | true | ⚠️ **预留未消费**（当前版本未使用，勿依赖） |
| `LogAnonymous` | bool | false | ⚠️ **预留未消费**（匿名过滤由主框架过滤器 `IsEnabledForAnonymous` 决定，勿依赖） |
| `SaveReturnValues` | bool | false | ⚠️ **预留未消费**（返回值记录由主框架过滤器属性控制，勿依赖） |
| `AdditionalSensitiveFields` | HashSet&lt;string&gt; | 空 | ⚠️ **预留未消费**（敏感字段脱敏由主框架过滤器私有 SensitiveFields 处理，勿依赖） |
| `RetentionDays` | int | 90 | 审计日志保留天数（`ExecutionTime` 早于 `UtcNow - RetentionDays` 的记录在清理时被物理删除）——**生效项** |
| `CleanupBatchSize` | int | 500 | 保留清理单批删除条数（分批循环，防长事务/大锁）——**生效项** |

### Options 绑定

扩展在 `ConfigureServices` 中注册 `AuditLoggingOptions` 默认值。消费方如需从 `appsettings.json` 绑定配置，在自身 `ConfigureServices` 中调用：

```csharp
services.Configure<AuditLoggingOptions>(configuration.GetSection("TKWF:AuditLogging"));
```

## §4 实体表结构

`AuditLogEntity` 映射到 `TKWF_AuditLog` 表（v4.10.66 起 `TKWF_` 前缀）：

```sql
CREATE TABLE [TKWF_AuditLog] (
    [Id] BIGINT IDENTITY(1,1) PRIMARY KEY,
    [UserName] NVARCHAR(128),
    [UserId] NVARCHAR(128),
    [ServiceName] NVARCHAR(200) NOT NULL,
    [MethodName] NVARCHAR(200) NOT NULL,
    [ArgumentsJson] NVARCHAR(MAX),
    [ExecutionTime] DATETIME NOT NULL,
    [DurationMs] INT NOT NULL,
    [Success] BIT NOT NULL,
    [Exception] NVARCHAR(MAX),
    [CorrelationId] NVARCHAR(128),
    [CreateTime] DATETIMEOFFSET NOT NULL
);
```

**索引**（`TKWFIX_` 前缀）：

| 索引名 | 列 | 类型 | 用途 |
|--------|-----|------|------|
| `TKWFIX_AuditLog_ExecutionTime` | ExecutionTime | 非唯一 | 时间范围查询/保留清理锚点 |
| `TKWFIX_AuditLog_UserName` | UserName | 非唯一 | 按用户查询 |
| `TKWFIX_AuditLog_CorrelationId` | CorrelationId | 非唯一 | 链路追踪查询 |
| `TKWFIX_AuditLog_ServiceName` | ServiceName | 非唯一 | 按服务名查询/统计聚合（V0.3.0 补建） |

**字段说明**：
- `ArgumentsJson`：参数 JSON 序列化（已脱敏，敏感字段值替换为 "***"）
- `DurationMs`：方法执行耗时（毫秒）
- `CorrelationId`：分布式链路追踪 ID（可选）
- `CreateTime`：记录创建时间（自动填充）

> 建表由框架 `SyncTables` 统一托管（ADR49），无手工 DDL 前置；上表供 DBA 参考。

## §5 自定义 IAuditLogStore

若需替换默认的 `AuditLogStore`（如写文件、发送到 SIEM），可自定义 `IAuditLogStore`：

```csharp
public class SiemAuditLogStore : IAuditLogStore
{
    public async Task SaveAsync(AuditLogEntry entry, CancellationToken ct = default)
    {
        // 发送到 SIEM 系统
        await _siemClient.SendAsync(entry, ct);
    }
}

// 消费方 ConfigureServices 中注册（覆盖默认实现——IAuditLogStore 为 TryAddScoped 接线型，AddScoped 后注册覆盖默认）
services.AddScoped<IAuditLogStore, SiemAuditLogStore>();
```

> **注册形态注记（V0.4.3 领域自治根治 ADR90）**：`IAuditLogStore` 是主框架契约（非 `IDomainService`），实现为**接线型**（ctor `(IServiceProvider, ILogger)`——DataService 经 `IServiceProvider.GetRequiredService<AuditLogEntityDataService>()` C1 延迟解析），主框架过滤器经普通 DI 解析。自定义实现同样不继承 `DomainServiceBase`、不注入 `IDomainUser`。

**TryAdd 语义**：消费方实现优先，扩展默认实现不覆盖。

## §6 查询 API（V0.2.0）

通过 `IAuditLogQueryService` 按条件分页查询审计日志，返回 DTO 列表（不暴露实体）。

### 1. 解析查询服务

`IAuditLogQueryService`（接口已标 `: IDomainService`）V0.4.3 起经 **`AddConstructibleService`** 注册（接口守卫工厂 + 实现 throw-factory）——**在领域服务内经 `User.Use<IAuditLogQueryService>()` 解析，禁构造注入（DI004 零豁免）**：

```csharp
public class AuditLogQueries : DomainServiceBase
{
    public AuditLogQueries(IDomainUser user) : base(user) { }

    public async Task ShowAsync()
    {
        var queryService = User.Use<IAuditLogQueryService>();
        // ↓ 下列示例均基于 queryService 调用
    }
}
```

### 2. 基本查询

```csharp
// 全量分页（默认 Take=50）
var result = await queryService.GetListAsync(new AuditLogQueryInput());

foreach (var item in result.Items)
{
    Console.WriteLine($"[{item.ExecutionTime}] {item.UserName} → {item.ServiceName}.{item.MethodName} ({item.DurationMs}ms)");
}

Console.WriteLine($"Total: {result.Total}");
```

### 3. 按时间范围查询

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    StartTime = DateTime.Today.AddDays(-7),  // 最近 7 天
    EndTime = DateTime.Today.AddDays(1),
    Success = false  // 仅失败记录
});
```

### 4. 按用户查询（模糊匹配）

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    UserName = "alice"  // LIKE '%alice%' 模糊匹配
});
```

### 5. 组合条件 + 分页

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    ServiceName = "OrderService",
    MinDurationMs = 100,       // 耗时 ≥ 100ms
    Skip = 0,
    Take = 20                  // 每页 20 条（最大 200）
});
```

### 6. 统计总数

```csharp
var total = await queryService.CountAsync(new AuditLogQueryInput
{
    Success = false,
    StartTime = DateTime.Today.AddDays(-30)
});
Console.WriteLine($"最近 30 天失败调用: {total}");
```

### 7. 自定义查询服务

若需替换默认查询实现（如加缓存、加权限控制）：

```csharp
public class CachedAuditLogQueryService : IAuditLogQueryService
{
    private readonly IAuditLogQueryService _inner;
    // ... 缓存逻辑

    public async Task<AuditLogPagedResult> GetListAsync(AuditLogQueryInput query, CancellationToken ct = default)
    {
        // 缓存命中 → 直接返回
        // 缓存未命中 → 调用 _inner.GetListAsync
    }

    public Task<long> CountAsync(AuditLogQueryInput query, CancellationToken ct = default)
        => _inner.CountAsync(query, ct);
}

// 消费方注册（后注册覆盖 AddConstructibleService 默认——查询/分析门面为 IDomainService 契约）
services.AddScoped<IAuditLogQueryService, CachedAuditLogQueryService>();
```

### 8. 查询参数说明

| 参数 | 类型 | 匹配方式 | 说明 |
|------|------|---------|------|
| `StartTime` | DateTime? | 范围（≥） | 执行时间起始 |
| `EndTime` | DateTime? | 范围（≤） | 执行时间结束 |
| `UserName` | string? | LIKE '%value%' | 用户名模糊匹配 |
| `UserId` | string? | 精确匹配 | 用户 ID |
| `ServiceName` | string? | 精确匹配 | 服务名（类名） |
| `MethodName` | string? | 精确匹配 | 方法名 |
| `Success` | bool? | 精确匹配 | 是否成功 |
| `CorrelationId` | string? | 精确匹配 | 链路追踪 ID |
| `MinDurationMs` | int? | 范围（≥） | 最小耗时（毫秒） |
| `MaxDurationMs` | int? | 范围（≤） | 最大耗时（毫秒） |
| `Skip` | int | 偏移量 | 跳过前 N 条（默认 0） |
| `Take` | int | 截取量 | 返回记录数（默认 50，最大 200） |

### 9. 返回类型

`AuditLogPagedResult(Total, Items)`：
- `Total`：符合条件的总记录数（用于前端分页控件）
- `Items`：当前页 `AuditLogListItemDto` 列表

`AuditLogListItemDto` 字段：Id / UserName / UserId / ServiceName / MethodName / ExecutionTime / DurationMs / Success / Exception / CorrelationId / CreateTime

> **安全决策（D5）**：DTO 不含 `ArgumentsJson`——防止脱敏前的参数结构泄露。消费方如需查看参数详情，走管理 API `GetDetailAsync`（含 ArgumentsJson，见 §8）。

## §7 统计聚合与保留天数清理（V0.3.0）

通过 `IAuditLogAnalyticsService` 提供聚合分析与保留清理——**同样经 `User.Use<IAuditLogAnalyticsService>()` 解析（AddConstructibleService 注册，禁构造注入）**：

```csharp
public class AuditDashboardService : DomainServiceBase
{
    public AuditDashboardService(IDomainUser user) : base(user) { }

    public async Task ShowAsync()
    {
        var analytics = User.Use<IAuditLogAnalyticsService>();

        // 1. 调用次数 TopN（按服务名/用户名）——window 相对 UtcNow，null = 全量；V0.4.2 起 SQL 下推
        var topServices = await analytics.GetTopServicesAsync(topN: 10, window: TimeSpan.FromDays(7));
        var topUsers = await analytics.GetTopUsersAsync(topN: 10);

        foreach (var s in topServices)
            Console.WriteLine($"{s.Dimension}: {s.Count} 次");

        // 2. SQL 级统计——Total / Succeeded / Failed / AvgDurationMs / MaxDurationMs
        var stats = await analytics.GetStatsAsync(window: TimeSpan.FromHours(24));
        var failureRate = stats.Total > 0 ? stats.Failed / (double)stats.Total : 0;
        Console.WriteLine($"24h: {stats.Total} 次, 成功 {stats.Succeeded}, 失败 {stats.Failed},"
            + $" 平均耗时 {stats.AvgDurationMs:F0}ms, 最大 {stats.MaxDurationMs}ms, 失败率 {failureRate:P1}");
    }
}
```

**聚合边界**：
- `GetTopServicesAsync` / `GetTopUsersAsync`：**V0.4.2 起 GroupCountAsync SQL 全下推**（`GROUP BY + COUNT + ORDER BY COUNT DESC + LIMIT`——替代既有 `Take(100_000)` + 内存 GroupBy，消除全量拉取）；空白键 `!string.IsNullOrWhiteSpace` 过滤一并下推 SQL；`topN` 上限 100。
- `GetStatsAsync`：SQL 级聚合（COUNT/AVG/MAX 下推），空窗口返回全零。

**保留天数清理（两条路径）**：

```csharp
// 门面路径（供后台任务每日调度）：
// 删除 ExecutionTime < UtcNow - RetentionDays（默认 90 天）的过期记录，分批循环清完
var deleted = await User.Use<IAuditLogAnalyticsService>().CleanupExpiredAsync();
Console.WriteLine($"清理审计日志 {deleted} 条");
```

- 分批大小 `CleanupBatchSize`（默认 500）——每批最多删除条数，循环至清完，防大表一次性删爆事务
- 时间锚点 `ExecutionTime`（有 `TKWFIX_AuditLog_ExecutionTime` 索引）
- **物理删除**（`hasSoftDelete:false` 实体）——仅 `AuditLogEntityDataService.DeleteExpiredAsync` 单点路径，聚合仍只读
- 扩展**不内建调度器**——由消费方经 BackgroundJob/Quartz/Hangfire 每日定时调用，示例（作业内经 `DomainServiceBase` 子类 + `User.Use`，锚定域作用域）：

```csharp
public class AuditLogCleanupTask : DomainServiceBase, IBackgroundJob
{
    public AuditLogCleanupTask(IDomainUser user) : base(user) { }

    public async Task ExecuteAsync(IDictionary<string, string> args, CancellationToken ct)
        => await User.Use<IAuditLogAnalyticsService>().CleanupExpiredAsync(ct);
}
```

> **双清理路径差异**：管理 API `CleanupAsync`（§8）为 `maxRounds = 100` 死循环保护 + 循环内取消检查、失败自然传播；门面 `CleanupExpiredAsync` 为 `while(true)` 无轮次上限、异常静默（失败记 Warning 返回 0）。两者共享 `DeleteExpiredAsync` 单点删除，仅循环策略与异常语义不同。

## §8 管理 API（V0.4.0）

`AuditLogEntityDataService` 标记 `[GenerateController(FromDataService = true, ExcludeMethods = ...)]`——消费方 SG1 自动生成 REST 管理控制器（SubDomain `/AuditLogging` → 路由前缀 `/api/auditlogging`）。标准 CRUD（GetById/Select/SelectPage/Create/Update）经 `ExcludeMethods` 排除（防 ArgumentsJson 泄露 + 防伪造审计），仅暴露 5 个受控自定义端点：

| 端点（方法） | HTTP 形态 | 语义 |
|------------|----------|------|
| `SearchLogsAsync(AuditLogQueryInput)` | 列表查询 | 同 `IAuditLogQueryService.GetListAsync`（列表裁剪 DTO，不含 ArgumentsJson） |
| `GetDetailAsync(long id)` | 详情 | **含 `ArgumentsJson`**（详情显式暴露——敏感参数，调用方须有权限门） |
| `CleanupAsync()` | 清理 | 保留天数清理（`maxRounds = 100` 死循环保护 + 分批删除，不委托 AnalyticsService 避循环依赖） |
| `GetStatsAsync()` | 统计 | SQL 级聚合统计（Total/Succeeded/Failed/AvgDurationMs/MaxDurationMs） |
| `DeleteAsync(long id)` | 单条删除 | 单条物理删除（推翻 v0.3.0 "无单条删除"限定） |

**权限责任传达（⚠️ 安全）**：
- **`GetDetailAsync` 返回含脱敏前参数结构（ArgumentsJson）**——敏感数据面；`DeleteAsync` 为**物理删除**（不可恢复）——两者均为高风险端点，**消费方必须在生成控制器上补权限门控**（如 `[RequirePermission]` 或装配层过滤），否则任何已登录用户可读参数详情/删除审计记录，审计完整性主张失效。
- 扩展侧未内建权限标注（DataService 为 SG1 生成控制器的数据源，不可直接标注）——按仓库惯例管理写端点应随版本补 `[RequirePermission]`（对齐 WeChatOperations 门面方法直接标注先例），当前以文档传达 + 消费方装配层门控。

## §9 与 EntityHistoryFilter 的区别

| 维度 | AuditLogFilter | EntityHistoryFilter |
|------|---------------|-------------------|
| **跟踪对象** | 方法调用事件 | 实体字段变更 |
| **记录内容** | 调用者、方法、参数、耗时、异常 | 实体字段 OldValue/NewValue |
| **持久化** | 需 `IAuditLogStore` 实现 | 需 `IEntityHistoryStore` 实现 |
| **查询** | `IAuditLogQueryService`（V0.2.0） | 待实现 |
| **脱敏** | 内置（SensitiveFields） | 无 |
| **适用场景** | 安全合规审计 | 业务数据变更追踪 |

**使用建议**：
- 安全合规审计 → `AuditLogFilter` + `IAuditLogStore` + `IAuditLogQueryService`
- 业务数据变更追踪 → `EntityHistoryFilter` + `IEntityHistoryStore`
- 两者可同时启用，互不冲突
