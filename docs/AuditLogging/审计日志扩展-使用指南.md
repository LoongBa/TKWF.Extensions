# 审计日志扩展使用指南

**扩展**: `TKWF.Ext.AuditLogging` | **版本**: V0.3.0 | **框架**: .NET 10

---

## §1 概述

`TKWF.Ext.AuditLogging` 是 TKWF 框架的审计日志扩展，提供方法级调用事件的数据库存储与查询。

**核心能力**：
- 记录调用者、目标方法、参数（脱敏 JSON）、耗时、成功/异常、关联 ID
- FreeSql 持久化（异常静默处理，不阻塞业务）
- SG1 声明式实体（自动建表）
- **查询 API**（V0.2.0）：按时间范围/用户/服务名/方法名等条件分页查询审计日志
- **统计聚合 API**（V0.3.0）：调用次数 TopN（按服务名/用户名）+ SQL 级统计（成功/失败/平均/最大耗时）
- **保留天数清理**（V0.3.0）：按 `RetentionDays` 分批物理删除过期审计日志（合规留存窗口回收）
- 消费方 opt-in 启用（不强制）

**与主框架的关系**：
- `IAuditLogStore` + `AuditLogEntry` + `AuditLogFilterAttribute` 由主框架定义
- 本扩展提供 `FreeSqlAuditLogStore` 实现 + `IAuditLogQueryService` 查询服务 + 自动注册

## §2 快速开始

### 1. 添加引用

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\Framework\AuditLogging\TKWF.Ext.AuditLogging.csproj" />
```

### 2. 启用扩展（v4.9.85+ 必需）

> **V4.9.85 (ADR47) 起**：扩展不再"发现即启用"。消费方需在领域初始化器上显式声明 `[TKWFEnabledExtension]`，扩展才进入白名单（三钩子执行）。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.AuditLogging;

[TKWFEnabledExtension(typeof(AuditLoggingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

若不声明 `[TKWFEnabledExtension]`，扩展的三钩子（ConfigureServices / ConfigureFilters / InitializeAsync）不会执行，DI 注册不会生效。

### 3. 启用审计日志过滤器

白名单声明后，在消费方 `ConfigureGlobalFilters` 中启用过滤器：

```csharp
protected override void ConfigureGlobalFilters(FilterBuilder<MyUserInfo> builder)
{
    // 启用审计日志（opt-in）
    builder.AddAuditLog();
}
```

### 4. 自定义过滤器参数（可选）

```csharp
builder.AddAuditLog(filter =>
{
    // 为匿名调用记录审计日志（默认 false）
    filter.IsEnabledForAnonymous = true;
    // 序列化返回值到审计记录（默认 false，慎用）
    filter.SaveReturnValues = false;
});
```

### 5. 运行

应用启动后，所有标记了 `AddAuditLog()` 的方法调用会被自动记录到 `AuditLog` 表。

## §3 配置

通过 `appsettings.json` 配置审计日志选项：

```json
{
  "TKWF": {
    "AuditLogging": {
      "IsEnabled": true,
      "LogAnonymous": false,
      "SaveReturnValues": false,
      "AdditionalSensitiveFields": ["creditCard", "ssn"],
      "RetentionDays": 90,
      "CleanupBatchSize": 500
    }
  }
}
```

### 配置项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `IsEnabled` | bool | true | 是否启用审计日志 |
| `LogAnonymous` | bool | false | 是否为匿名调用记录审计日志 |
| `SaveReturnValues` | bool | false | 是否序列化返回值到审计记录 |
| `AdditionalSensitiveFields` | HashSet&lt;string&gt; | 空 | 附加敏感字段名（值替换为 "***"） |
| `RetentionDays` | int | 90 | 审计日志保留天数（`ExecutionTime` 早于 `UtcNow - RetentionDays` 的记录在清理时被物理删除） |
| `CleanupBatchSize` | int | 500 | 保留清理单批删除条数（分批循环，防长事务/大锁） |

### Options 绑定（V0.2.0）

扩展在 `ConfigureServices` 中注册 `AuditLoggingOptions` 默认值。消费方如需从 `appsettings.json` 绑定配置，在自身 `ConfigureServices` 中调用：

```csharp
services.Configure<AuditLoggingOptions>(configuration.GetSection("TKWF:AuditLogging"));
```

## §4 实体表结构

`AuditLogEntity` 映射到 `AuditLog` 表：

```sql
CREATE TABLE [AuditLog] (
    [Id] BIGINT IDENTITY(1,1) PRIMARY KEY,
    [UserName] NVARCHAR(128),
    [UserId] NVARCHAR(128),
    [ServiceName] NVARCHAR(200) NOT NULL,
    [MethodName] NVARCHAR(200) NOT NULL,
    [ArgumentsJson] NVARCHAR(MAX),
    [ExecutionTime] DATETIME NOT NULL,
    [DurationMs] INT NOT NULL,
    [Success] BIT NOT NULL,
    [Exception] NVARCHAR(MAX),
    [CorrelationId] NVARCHAR(128),
    [CreateTime] DATETIMEOFFSET NOT NULL
);
```

**索引**：

| 索引名 | 列 | 类型 | 用途 |
|--------|-----|------|------|
| `IX_AuditLog_ExecutionTime` | ExecutionTime | 非唯一 | 时间范围查询/保留清理锚点 |
| `IX_AuditLog_UserName` | UserName | 非唯一 | 按用户查询 |
| `IX_AuditLog_CorrelationId` | CorrelationId | 非唯一 | 链路追踪查询 |
| `IX_AuditLog_ServiceName` | ServiceName | 非唯一 | 按服务名查询/统计聚合（V0.3.0 补建） |

**字段说明**：
- `ArgumentsJson`：参数 JSON 序列化（已脱敏，敏感字段值替换为 "***"）
- `DurationMs`：方法执行耗时（毫秒）
- `CorrelationId`：分布式链路追踪 ID（可选）
- `CreateTime`：记录创建时间（自动填充）

## §5 自定义 IAuditLogStore

若需替换默认的 FreeSql 存储（如写文件、发送到 SIEM），可自定义 `IAuditLogStore`：

```csharp
public class SiemAuditLogStore : IAuditLogStore
{
    public async Task SaveAsync(AuditLogEntry entry, CancellationToken ct = default)
    {
        // 发送到 SIEM 系统
        await _siemClient.SendAsync(entry, ct);
    }
}

// 消费方 ConfigureServices 中注册（覆盖默认实现）
services.AddScoped<IAuditLogStore, SiemAuditLogStore>();
```

**TryAdd 语义**：消费方实现优先，扩展默认实现不覆盖。

## §6 查询 API（V0.2.0）

通过 `IAuditLogQueryService` 按条件分页查询审计日志，返回 DTO 列表（不暴露实体）。

### 1. 注入查询服务

扩展自动注册 `IAuditLogQueryService`（默认 `AuditLogQueryService`，TryAddScoped）：

```csharp
public class AuditQueryService(IAuditLogQueryService queryService)
{
    // 注入即用
}
```

### 2. 基本查询

```csharp
// 全量分页（默认 Take=50）
var result = await queryService.GetListAsync(new AuditLogQueryInput());

foreach (var item in result.Items)
{
    Console.WriteLine($"[{item.ExecutionTime}] {item.UserName} → {item.ServiceName}.{item.MethodName} ({item.DurationMs}ms)");
}

Console.WriteLine($"Total: {result.Total}");
```

### 3. 按时间范围查询

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    StartTime = DateTime.Today.AddDays(-7),  // 最近 7 天
    EndTime = DateTime.Today.AddDays(1),
    Success = false  // 仅失败记录
});
```

### 4. 按用户查询（模糊匹配）

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    UserName = "alice"  // LIKE '%alice%' 模糊匹配
});
```

### 5. 组合条件 + 分页

```csharp
var result = await queryService.GetListAsync(new AuditLogQueryInput
{
    ServiceName = "OrderService",
    MinDurationMs = 100,       // 耗时 ≥ 100ms
    Skip = 0,
    Take = 20                  // 每页 20 条（最大 200）
});
```

### 6. 统计总数

```csharp
var total = await queryService.CountAsync(new AuditLogQueryInput
{
    Success = false,
    StartTime = DateTime.Today.AddDays(-30)
});
Console.WriteLine($"最近 30 天失败调用: {total}");
```

### 7. 自定义查询服务

若需替换默认查询实现（如加缓存、加权限控制）：

```csharp
public class CachedAuditLogQueryService : IAuditLogQueryService
{
    private readonly IAuditLogQueryService _inner;
    // ... 缓存逻辑

    public async Task<AuditLogPagedResult> GetListAsync(AuditLogQueryInput query, CancellationToken ct = default)
    {
        // 缓存命中 → 直接返回
        // 缓存未命中 → 调用 _inner.GetListAsync
    }

    public Task<long> CountAsync(AuditLogQueryInput query, CancellationToken ct = default)
        => _inner.CountAsync(query, ct);
}

// 消费方注册（覆盖默认实现）
services.AddScoped<IAuditLogQueryService, CachedAuditLogQueryService>();
```

### 8. 查询参数说明

| 参数 | 类型 | 匹配方式 | 说明 |
|------|------|---------|------|
| `StartTime` | DateTime? | 范围（≥） | 执行时间起始 |
| `EndTime` | DateTime? | 范围（≤） | 执行时间结束 |
| `UserName` | string? | LIKE '%value%' | 用户名模糊匹配 |
| `UserId` | string? | 精确匹配 | 用户 ID |
| `ServiceName` | string? | 精确匹配 | 服务名（类名） |
| `MethodName` | string? | 精确匹配 | 方法名 |
| `Success` | bool? | 精确匹配 | 是否成功 |
| `CorrelationId` | string? | 精确匹配 | 链路追踪 ID |
| `MinDurationMs` | int? | 范围（≥） | 最小耗时（毫秒） |
| `MaxDurationMs` | int? | 范围（≤） | 最大耗时（毫秒） |
| `Skip` | int | 偏移量 | 跳过前 N 条（默认 0） |
| `Take` | int | 截取量 | 返回记录数（默认 50，最大 200） |

### 9. 返回类型

`AuditLogPagedResult(Total, Items)`：
- `Total`：符合条件的总记录数（用于前端分页控件）
- `Items`：当前页 `AuditLogListItemDto` 列表

`AuditLogListItemDto` 字段：Id / UserName / UserId / ServiceName / MethodName / ExecutionTime / DurationMs / Success / Exception / CorrelationId / CreateTime

> **安全决策（D5）**：DTO 不含 `ArgumentsJson`——防止脱敏前的参数结构泄露。消费方如需查看参数详情，应通过安全渠道（管理后台 + 权限控制）访问实体层。

## §7 统计聚合与保留天数清理（V0.3.0）

通过 `IAuditLogAnalyticsService` 提供聚合分析与保留清理（扩展自动注册，TryAddScoped）：

```csharp
public class AuditDashboardService(IAuditLogAnalyticsService analytics)
{
    // 1. 调用次数 TopN（按服务名/用户名）——window 相对 UtcNow 闭区间，null = 全量
    var topServices = await analytics.GetTopServicesAsync(topN: 10, window: TimeSpan.FromDays(7));
    var topUsers = await analytics.GetTopUsersAsync(topN: 10);

    foreach (var s in topServices)
        Console.WriteLine($"{s.Dimension}: {s.Count} 次");

    // 2. SQL 级统计——Total / Succeeded / Failed / AvgDurationMs / MaxDurationMs
    var stats = await analytics.GetStatsAsync(window: TimeSpan.FromHours(24));
    var failureRate = stats.Total > 0 ? stats.Failed / (double)stats.Total : 0;
    Console.WriteLine($"24h: {stats.Total} 次, 成功 {stats.Succeeded}, 失败 {stats.Failed},"
        + $" 平均耗时 {stats.AvgDurationMs:F0}ms, 最大 {stats.MaxDurationMs}ms, 失败率 {failureRate:P1}");

    // 3. 保留天数清理——删除 ExecutionTime < UtcNow - RetentionDays（默认 90 天），分批循环清完
    var deleted = await analytics.CleanupExpiredAsync();
}
```

**聚合边界**：
- `GetTopServicesAsync` / `GetTopUsersAsync`：内存 GroupBy 聚合（SQL WHERE 下推时间窗口 + 10 万条安全上限），`Dimension` 空白（空服务名/匿名无用户名）记录跳过；`topN` 上限 100。
- `GetStatsAsync`：SQL 级聚合（COUNT/AVG/MAX 下推），空窗口返回全零。

**保留清理说明**：
- 时间锚点 `ExecutionTime`（有 `IX_AuditLog_ExecutionTime` 索引）；分批大小 `CleanupBatchSize`（默认 500）。
- **物理删除**（`hasSoftDelete:false` 实体）——仅 `AuditLogEntityDataService.DeleteExpiredAsync` 单点路径，无管理端点；匿名/用户维度聚合仍只读。
- 扩展**不内建调度器**——由消费方经 BackgroundJob/Quartz/Hangfire 每日定时调用，示例：

```csharp
public class AuditLogCleanupTask : IBackgroundJob
{
    private readonly IAuditLogAnalyticsService _analytics;
    public AuditLogCleanupTask(IAuditLogAnalyticsService analytics) => _analytics = analytics;

    public async Task ExecuteAsync(IDictionary<string, string> args, CancellationToken ct)
        => await _analytics.CleanupExpiredAsync(ct);
}
```

## §8 与 EntityHistoryFilter 的区别

| 维度 | AuditLogFilter | EntityHistoryFilter |
|------|---------------|-------------------|
| **跟踪对象** | 方法调用事件 | 实体字段变更 |
| **记录内容** | 调用者、方法、参数、耗时、异常 | 实体字段 OldValue/NewValue |
| **持久化** | 需 `IAuditLogStore` 实现 | 需 `IEntityHistoryStore` 实现 |
| **查询** | `IAuditLogQueryService`（V0.2.0） | 待实现 |
| **脱敏** | 内置（SensitiveFields） | 无 |
| **适用场景** | 安全合规审计 | 业务数据变更追踪 |

**使用建议**：
- 安全合规审计 → `AuditLogFilter` + `IAuditLogStore` + `IAuditLogQueryService`
- 业务数据变更追踪 → `EntityHistoryFilter` + `IEntityHistoryStore`
- 两者可同时启用，互不冲突
