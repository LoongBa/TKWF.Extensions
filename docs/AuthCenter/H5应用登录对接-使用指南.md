# H5 应用登录对接-使用指南

> **版本**：v2（2026-11-15；v1 自 DMP-Lite 迁入本仓库并按扩展模块视角修订）
> **状态**：已实施且持续维护
> **适用对象**：对接 **TKWF 认证体系**（AuthCenter + Federation 系扩展，见 §0）的会员营销类 H5 应用（如 UserH5 / 小书童 / 数独思维 / 数学巧算天天练 / 英语天天练）
> **参考实现（唯一先例）**：`DMP-Lite.UserH5/`——多租户（`/m/{mid}/...`）会员 H5，登录形态在本指南全部落地并有实测；DMP-Lite 是认证体系的**首个完整参考实现**，非指南主体
> **来源**：本文档原为 DMP-Lite 仓库 docs/H5应用登录与会员体系对接指南.md（2026-11-15 迁入 docs/AuthCenter/ 修订）——参考实现落地细节与 BR 编号保留原口径，扩展能力状态以本仓库为准。
> **范围**：认证体系定位、登录通道、统一会话契约、前端接入骨架、后端对接面、安全底线、踩坑清单

> ⚠️ **阅读前提**：本指南面向"对接同一套 TKWF 认证体系的 H5 应用"，不假设读者熟悉 DMP-Lite 内部。参考实现的背景只此一条：DMP-Lite 是**多租户 B2B2C 平台**——每个租户（mid）一个库，H5 页面路径前缀 `/m/{mid}/`，租户上下文由中间件从 URL 装填，所有登录端点均为**匿名访问 + 多租户路径**形态。
>
> 本文「出处」中的「方案」「D02A」「D03」「BR-xx」及 scenario.ts 等源文件均属 DMP-Lite 仓库（不在本仓库）；扩展能力事实源以本仓库 docs/ 与 _Framework/ 为准。

## 0. 认证体系定位（先读——本指南对接的是哪套认证）

本指南的一切登录通道、会话契约、安全边界，都建立在一套 **TKWF 生态认证体系**之上。接入方对接的是这套体系本身，而不是 DMP-Lite 项目；参考实现（DMP 商户域）只是最早走通全部环节的示例。

| 层 | 扩展 / 实现 | 职责（一句话） | 状态（2026-11） |
|----|------------|---------------|----------------|
| 认证中心 | `TKWF.Ext.AuthCenter`（含 `AuthCenter.Abstractions`） | 统一账号/凭证体系；密码登录（`/login/password`，SecurePassword 协议）与短信验证码登录（`/sms/send-code` + `/login/sms`，V0.6.0 起内建）；令牌体系与票据兑现（`/login/ticket`、`/login/ticket/redeem`）；外部 IdP 登录桥接（`/login/external/{channelType}`，借道 Federation）；平台账号映射（PlatformAccountMap） | **V0.14.0 已发布**（2026-11-11：`POST /login/ticket/redeem` 业务兑票端点已上线——详见本仓库 `docs/AuthCenter/认证中心-使用指南.md` §6-e） |
| 联邦互联 | `TKWF.Ext.Federation` 系（`Federation.Abstractions` + `Federation.WeChat/QQ/Alipay/Google/Microsoft/Oidc/DingTalk/WeCom` 等平台适配器） | 多端 OAuth 通道注册（`IChannelRegistry`）与对外授权端点（子应用委托：`authorize/start`、oauth callback、`trust/issue`、`identity/claim`）；微信关注域（`IFollowStateService`）；事件链签票（`EventReplyHandlerBase`，`FederatedTicketPayload` 契约在此） | 已交付（多平台适配器齐备） |
| 应用间信任 | `TKWF.Ext.TrustCenter`（含 `TrustCenter.Abstractions`） | 应用注册（SsoClient origin 白名单/credential）、token2 签发与 JWKS、accesscode 联邦流与密封票据实现（`ISealedTicketService` 契约为框架 Domain.Ticket） | 已交付（认证体系三层架构的信任中枢） |
| 短信 + Captcha | `TKWF.Ext.SmsCode` + `TKWF.Ext.Captcha`（+Captcha.Abstractions） | 短信验证码发送/校验（频控）；Captcha 人机验证（v1：自建图形 Provider + IChaptchaProvider SPI；滑块/点选/行为/第三方接入 LATER） | **已立项 2026-11**：`TKWF.Ext.SmsCode` + `TKWF.Ext.Captcha`（+Captcha.Abstractions）拆分立项；设计梳理双 Oracle 评审通过，M0 开发方案 Oracle 评审闭环（2026-11-15，见 `docs/SmsCode/`——状态以该目录为准） |
| **参考实现** | DMP-Lite 商户域（Merchant.Domain + Merchant.WebApi + UserH5） | 认证体系的**首个完整消费实现**：多租户分库、租户会话（IdentitySession 契约）、四通道登录 | 已实施（2026-11） |

**两种消费模式**（接入方先选定其一）：

- **A. 经接入主体域中转**（参考实现采用的模式）：H5 → 接入主体 WebApi（多租户路由 `/m/{mid}/api/...`）→ 内部调 AuthCenter/Federation 完成认证 → 返回**接入主体定义的会话契约**（参考实现即 IdentitySession）。适用：拥有独立租户域、需要会员业务上下文（领卡/积分/券包）的 H5。
- **B. 直连平台认证**：H5 直接消费 AuthCenter 平台端点（`POST {prefix}/login/password`、`/sms/send-code` + `/login/sms`、ticket 兑付——端点全集见本仓库 `docs/AuthCenter/认证中心-使用指南.md` 端点表，{prefix} 默认 `/api/auth`）与平台会话契约。⚠️ **密码交互走 SecurePassword 协议**（请求体 `{ identifier, clientHash, salt }`，服务端零明文）——与参考实现 A 模式的 `{ mobile, password }` 明文体不同，直连消费方勿照抄；命中平台侧频控（V0.13.1：密码 `login-ip:{ip}` 20/h、短信 `sms-ip:{ip}` 20/h，反代须配 ForwardedHeaders）。适用：无接入主体域、仅需平台登录的轻量 H5。

> ⚠️ **契约归属**：本指南 B 章 `IdentitySession` 契约由**参考实现（DMP 商户域）定义**并与其后端强绑定；选择 B 模式（直连平台）的接入方，以 AuthCenter 会话契约为准（D02A §4），本指南 B 章仅作对照参考。

出处：`docs/D02A-AuthCenter统一认证系统设计方案.md`（DMP-Lite 仓库内部文档）§1.1/§4；本仓库 `_Framework/` 目录（AuthCenter/Federation 系）；扩展侧文档 `docs/AuthCenter/认证中心-使用指南.md`（端点表/契约权威）。

## A. 登录通道全景（4 通道矩阵）

> 端点路径为**参考实现形态**（`{base}/m/{mid}/api` 前缀）——接入主体按自身路由约定改写；直连平台模式走 AuthCenter 平台端点（§0 B）。

| # | 通道 | 端点（参考实现形态） | 状态（参考实现，2026-11） | 适用场景 |
|---|------|------|------|---------|
| ① | 微信 ticket 免登 | `POST /auth/ticket-login`，body `{ ticket }` | **已上线**（v0.10.0） | 公众号图文链接/菜单下发 ticket → AuthCenter 兑票 → 免登（参考实现 BR-34/BR-38） |
| ② | 手机号+密码 | `POST /auth/password-login`，body `{ mobile, password }` | **已上线**（v0.10.8），IP 频控 10 次/分/端点 | 无微信环境（PC 浏览器 / 非公众号）；凭据 localStorage 免登 |
| ③ | 手机号+验证码 | `POST /auth/sms/send-code`（body `{ mobile }`）+ `POST /auth/sms/login`（body `{ mobile, code }`） | **扩展模块立项中**（`TKWF.Ext.SmsCode` + `TKWF.Ext.Captcha`，见 §0 表；前端已按契约预留 sms-login-sim.ts） | 无密码便捷登录（服务端能力落地后启用） |
| ④ | 扫码（PC） | 无后端端点（前端模拟） | **仅 mock 模式渲染**；真实微信网页扫码权限未具备 | PC 浏览器快捷登录（生产可用前必须接入真实通道） |

出处：方案 §1、§3.4；sms-login-sim.ts 契约头注释；.env.example。

### A.1 请求/响应形态（② 为例，各通道同构）

```
POST {base}/m/{mid}/api/auth/password-login
Body: { "mobile": "13800138000", "password": "***" }
→ 200 IdentitySession（结构同 ticket-login，前端零适配）
→ 400 { error, message }   invalid_credentials / invalid_merchant
→ 403 { error, message }   member_disabled（禁用/冻结）
→ 429 { error = "rate_limited", message = "请求过于频繁，请稍后重试" }
→ 500 { error, message }   session_create_failed / internal_error
```
出处：方案 §3.2、§4 错误码表；MemberLoginEndpoints.cs。

### A.2 错误形状与 SDK 透传规则（前端消费方必读）

- 业务错误体统一 `{ error: errorCode, message: 用户文案 }`（MemberLoginEndpoints.cs）。
- SDK（@tkwf/tsclient 1.0.5+）透传：**仅 4xx 开放 `body.error` 业务码进 `err.code`**；其余按传输层码：
  | `err.code` | 前端处理 |
  |---|---|
  | 4xx 业务码（`invalid_credentials` / `invalid_merchant` / `ticket_rejected` 等） | 直查业务码→文案表 |
  | `FORBIDDEN`（403 传输层） | 会员禁用/冻结文案 |
  | `AUTH_EXPIRED` / `AUTH_REQUIRED` / `AUTH_FAILED` | 会话失效 → 重新验证引导 |
  | `RATE_LIMITED` | "请求过于频繁，请稍后重试" |
  | `NETWORK_ERROR` / `TIMEOUT` | 平台不可达/超时文案 |
  | `SERVER_ERROR`（500） | "服务暂时不可用，请稍后重试" |
出处：auth.tsx `sdkErrorToMessage()`（SDK v1.0.15+ 透传注释）。

## B. IdentitySession 契约（统一响应体——四通道同构）

> **契约归属**：本契约为**参考实现（DMP 商户域）定义**的接入主体会话契约（后端 ⑦ 组装；前端 identity-session.ts 同形声明）；直连平台模式（§0 B）以 AuthCenter 会话契约为准。四通道同构是"新通道前端零适配"的根基（参考实现 ADR12 决策 2）。

```typescript
interface IdentitySession {
  sessionKey: string | null;          // 会话键：随 storage { sessionKey } 形态落 sessionStorage，后续业务 API 凭此（BR-36）
  tenant:     { alias; name; status };  // 商户展示信息：alias=商户简称，name=商户名称，status=商户状态（MemberLoginService.GetTenantInfoAsync，缺省回退 UId）
  identity:   {
    platformUid: string;              // 平台账号映射键（BR-33）；空串 = 平台账号未绑定 → 建档入口禁用（BR-44）
    assurance: string;                // 通道保证级别：微信 snsapi_base / 密码 password / 验证码 phone_sms / 模拟 qr_scan（BR-46）
    channelType: string;              // wechat_oauth | password | sms | qr
    channelId: string | null;         // 无微信通道时恒 null（BR-47：密码登录无关注域查询对象）
  };
  membership: { status: 'member'|'not_member'|'frozen'; memberUId: string|null; level: string|null; frozenReasons?: string[]|null };
  nextAction: 'open_vip'|'register'|'follow_guide'|'unfollow_notice';  // 服务端裁决（BR-41）
  capabilities: string[];             // 本期固定集 ['browse','member_card','points','coupons']（D03 §17.6）
  registerToken: string | null;       // 领卡建档一次性凭证（仅 register 分流 + platformUid 非空签发；10 分钟过期、单次消费，BR-44）
}
```
出处：identity-session.ts；MemberLoginService.cs ⑦；BR-41/BR-44。

### B.1 关键语义（四条铁律）

1. **nextAction 仅登录后首次跳转**；此后路由守卫**以 capabilities 为准**（`hasMemberCard` 判据 = `membership.status==='member' && capabilities.includes('member_card')`）——nextAction 不得作为持久授权依据（BR-41 B5 定稿；auth.tsx 注释；identity-session.ts `hasMemberCard`）。
2. **openid/unionId 不出响应**——IdentitySession 只含展示级字段（platformUid），微信标识属 R5 PII 闭合（BR-41）；前端任何需求/调试都不得要求后端下发 openid。
3. **assurance ≠ channelType**：assurance 表达"认证保证等级"（微信授权仅 snsapi_base 静默级别；密码为强凭证），channelType 表达"通道来源"；前者用于等级判定，后者用于渠道分析/null 语义（BR-47）。
4. **registerToken 语义**：仅 `nextAction==='register'` 且 `platformUid` 非空时由服务端签发；`canEnroll()` 守卫 = 三者同时满足才允许建档（identity-session.ts）。

## C. 前端接入骨架（复制清单——新 H5 如何最快接上）

参考实现的登录侧由 6 个文件构成可整体复制的"登录套件"。**新 H5 直接复制这 6 个文件、改 3 个点**即可获得四通道登录 + 多租户会话 + 免登全套能力（以 `@tkwf/tsclient` 门面 + codegen 产物为前置，见 C.3）。

### C.1 逐文件说明

| 文件 | 职责 | 复制时注意事项 |
|------|------|------|
| `src/lib/scenario.ts` | **多租户 scenario 收敛层**：每 mid 一个 scenario（storageKey=`m:{mid}`，sessionStorage 隔离）；`restPathPrefix=/m/{mid}/api` 是唯一实质变化点；`ensureScenario` **幂等守卫**（同 mid 只 configure 一次——重复 configure 会静默覆盖并泄漏旧 host 心跳定时器）；`onUnauthorized/onPong` 过期 → 引导回 `/m/{mid}/auth?reason=...`（不静默重建会话） | 依赖 codegen 产物 `ts-client.g.ts` 的 `operationSelection/Query/Mutation`（operationKinds 权威映射，替代前缀启发式）；需按自己后端 schema 重生成 |
| `src/lib/identity-session.ts` | IdentitySession 类型（与服务端契约对齐）+ sessionStorage 缓存（`m:{mid}:identity`）+ `canEnroll`/`hasMemberCard` 守卫 | 缓存键命名空间 `m:{mid}:*` 与 scenario 同前缀，防跨租户串读 |
| `src/lib/credential-store.ts` | 密码凭据 localStorage（`m:{mid}:credential` → `{mobile,password}`）；save/load/clear | **仅自动重登消费；凭据类失败才清除**（瞬态网络失败保留——评审 P2） |
| `src/lib/sms-login-sim.ts` | 验证码模拟层：mock 模式返回固定码 888888；真实模式走契约端点（`auth/sms/send-code`、`auth/sms/login`），**端点未落地 → 优雅降级提示**（"短信服务暂未开通，请使用密码登录"），不阻塞其他通道；`buildMockSession` 供 sms/qr/pwd 三模拟通道共用 | 契约占位注释已含扩展模块接入点（Captcha 参数位 `chaptcha` 预留——wire 层拼写约定，见 `docs/SmsCode/v0.1.0-SmsCode-Captcha-开发方案.md` M4） |
| `src/routes/m.$mid/auth.tsx` | **三入口登录页**：ticket 分支**零改动原则**（v0.10.8 不碰已验证链路）；入口状态机 `pending/success/error/ready`；`commitSession` 统一写盘+跳转（三通道共用同一写盘格式）；错误码→文案表随业务码扩展 | 标签/UI 可按应用定制；`nextActionRoute` 映射表需对齐自己页面路由 |
| `src/main.tsx` + `.env` | 入口配置：`ensureDefaultScenario()` 与 mock 数据集注入（严格模式）；环境变量 `VITE_USE_MOCK` / `VITE_API_BASE_URL` / `VITE_QR_LOGIN` | **`.env` 不会被平台自动生成**——缺 `.env` 时 `VITE_USE_MOCK` 为空 → MockTransport 不启用 → 请求直打真实地址报 Network error（AGENTS.md 实证）；环境变量只在 dev server 启动时读取，改动后必须重启 |

出处：scenario.ts；identity-session.ts；credential-store.ts；sms-login-sim.ts；auth.tsx；main.tsx；.env.example；AGENTS.md。

### C.2 最小改动点（3 个）

| # | 改动点 | 位置 | 说明 |
|---|--------|------|------|
| 1 | 路由前缀 | scenario.ts `restPathPrefix` | 已内建 `/m/{mid}/api`；非 `/m/{mid}/` 形态的应用改这里+authRedirect 目标 |
| 2 | 租户 mid 来源 | 路由参数与 URL | UserH5 从路由 `useParams({from:"/m/$mid/auth"})` 取 mid；自行决定来源但必须与 `ensureScenario(mid)` 一致 |
| 3 | 页面跳转目标 | auth.tsx `nextActionRoute()` / `commitSession` | 映射到自己应用的会员页路由；`onUnauthorized/onPong` 引导路径同步改 |

### C.3 复制前的前置依赖（不满足则编译失败）

- `@tkwf/tsclient` 门面（`Tkwf.configure` 集中配置一次；页面经 `Tkwf.GetUser/GetGuest(scenarioOf(mid))` 调）
- codegen 产物：`src/gql/ts-client.g.ts`（operationSelection/Query/Mutation）+ `ts-client.mock.g.ts`（handlers）+ `mock/data.ts`（initialData）——scenario.ts/main.tsx 直接 import
- `qrcode.react`（扫码模拟弹层）
- 复制改造成本经验值：**6 个套件文件整体复制 + 3 个改动点 + codegen 重生成**，全量约 1 个前端人日（不含 UI 定制）。

## D. 后端对接面（接入主体域中转模式的参考范式——照此新增登录端点）

> 参考实现的密码登录后端是"登录编排服务新范式"的范本——**省掉 Controller 生成链的写法**。新登录端点照此办理。直连平台模式（§0 B）不需要本层的租户路由/中间件链，直接消费 AuthCenter 平台端点。

> **V0.14.0 直连兑票补充**：若 H5 选择直连平台模式（§0 B），微信免登的 ticket 兑票端点已由 AuthCenter V0.14.0 上线提供：`POST {prefix}/login/ticket/redeem`（仅兑票不建会话、不发 token——会员会话由业务方自建，`IExternalTicketRedeemService` 独立门面，11 字段 + extensions 明文 payload）。参考实现（DMP 商户域）的 `/auth/ticket-login` 属接入主体域自定义编排端点，二者并存不冲突：前者服务端到服务端兑票，后者直建会员会话。详见本仓库 `docs/AuthCenter/认证中心-使用指南.md` §6-e。

### D.1 中间件顺序红线（Program.cs 实名注释，违反即 404/会话越权）

`BeforeRouting` 内三个中间件**顺序固定**（须在 UseRouting 之前——端点匹配若先于重写/装填执行，`/m/{mid}/api/...` 请求将 404，v0.10.1 审核 P0 实证）：

| 顺序 | 中间件 | 职责 |
|------|--------|------|
| 1 | `MerchantFrameBindingMiddleware` | 商户帧装填：游客帧 `OwnerId ← AmbientContext.MerchantId`（闭合匿名端点商户上下文缺口）——**须最先**：在 PathRewrite 前读取原始 `/m/{mid}/` 路径 |
| 2 | `TenantSessionGuardMiddleware` | 会话越租户校验：URL.mid 与 session.tenant 不一致 → 403 `tenant_mismatch`（BR-43）——须在 PathRewrite **前**（读原始路径） |
| 3 | `MerchantIdPathRewriteMiddleware` | 移除 `/m/{mid}/` 前缀（提取由框架 ContextExtractionMiddleware 完成） |

新端点关联的频控中间件用 `IWebExtension + MiddlewareAnchor.AfterRouting`（RateLimitWebExtension 先例）——AfterRouting = UseRouting 之后按端点 metadata 生效。

### D.2 登录编排服务形态（MemberLoginService 范本）

| 要素 | 做法 | 出处 |
|------|------|------|
| 基类 | `DomainServiceBase<DmpUserInfo>` | MemberLoginService.cs |
| 控制器 | **不标 `[GenerateController]`**——登录编排服务仅 WebApi 层直建，不暴露框架会话鉴权面 | 方案 §3.1 |
| 数据访问 | `User.Use<T>()` 懒加载（零 DI 注册；DI004 零豁免） | 同上 |
| 商户帧 | `User.UserInfo?.OwnerId ?? ""`（缺省 → `invalid_merchant`，不泄露内部错误） | 同上 |
| WebApi 直建 | 手写 `MapPost` 匿名端点内 `user.Use<MemberLoginService>()`（域用户帧自 `ContextExtractionMiddleware.DomainUserKey` 取） | MemberLoginEndpoints.cs |
| 会话 | 校验通过 → `LoginAsUserAsync(..., EnumLoginFrom.MobileWeb)`（BR-36 与其它登录方式等价；BR-43 租户绑定 `OwnerId=当前商户`） | 同上 / BR-46 |

### D.3 错误映射表（password-login 全集，新端点照抄形态）

| errorCode | HTTP | 场景 | 前端文案 |
|-----------|------|------|---------|
| `invalid_credentials` | 400 | 手机号未注册 / 密码错误 / 未设密码（统一，防枚举） | 手机号或密码错误 |
| `invalid_merchant` | 400 | 缺商户帧 / 伪造 mid（Npgsql 连接类异常 catch 后转此码） | 无效的商户入口 |
| `member_disabled` | 403 | 会员禁用 / 冻结 | 会员已禁用/已冻结，请联系商家 |
| `session_create_failed` | 500 | 会话创建失败 | 会话创建失败，请稍后重试 |
| `internal_error` | 500 | 兜底（不泄露堆栈） | 服务暂时不可用，请稍后重试 |
| `rate_limited` | 429 | 频控命中 | 请求过于频繁，请稍后重试 |

出处：方案 §4 错误码表；MemberLoginEndpoints.cs `MapMemberLoginError`。

### D.4 频控（password-login 已挂——新端点照抄模式）

- `Program.cs RegisterServices`：`AddRateLimiter` + `AddPolicy("password-login", ...)` 固定窗口 `PermitLimit=10 / Window=1min`，`partitionKey = context.Connection.RemoteIpAddress`；`OnRejected` 写 429 `{error:"rate_limited",...}`（**委托返回 `ValueTask`**）
- 端点侧：`.RequireRateLimiting("password-login")` 元数据（方案期"本期不做"按评审 P1-1 补挂——**登录类匿名端点必须默认挂频控**）
- ⚠️ **.NET 10 API 名是 `RequireRateLimiting`（带 ing），不是 `RequireRateLimiter`**（旧名不存在）
- 遗留注：验证码/Captcha 频控由扩展模块统一收口（方案 §7）

出处：Program.cs；MemberLoginEndpoints.cs；ADR12 安全边界。

### D.5 会员状态机（密码登录视角）

- `Normal`：放行建会话。
- `Frozen`：**403 一律拒绝**——密码登录不属微信关注链，**不区分 unfollow 冻结原因**（BR-46 简化决策，文档留痕）；冻结原因多值 JSON 数组（`FreezeReasons`: unfollow/business/admin，BR-40）
- `Disabled`：403 拒绝，文案"会员已禁用，无法登录"
- 密码登录**无软拒绝分支**：密码仅于 AdminResetPassword/ChangePassword/ResetPasswordBySms 落库 → 持密码者必然已建档 → nextAction 恒 `open_vip`（MemberLoginService.cs 注记）

出处：BR-40/BR-45/BR-46；MemberLoginService.cs ⑤。

## F. 踩坑清单（参考实现实证——按高频价值排序）

> 「适用」列：**通用** = 对接 TKWF 认证体系的任何项目都适用；**参考实现特有** = 仅 DMP-Lite 形态（Dll/源码双模式、.TKWF 活文档等）下需注意。

| # | 坑 | 解法 | 适用 |
|---|-----|------|------|
| 1 | **直接 `dotnet build <csproj>` = DLL 模式缺扩展类型**（WeChat/Federation 扩展类型编译不过） | 必须 `/p:SolutionFileName=DMP-Lite.Dev.slnx`（Project 源码模式）构建后端 | 参考实现特有 |
| 2 | **`[GenerateController]` 服务多行 XML 注释被 ControllerGenerator 复制进 .g.cs 导致 CS1519** | public 方法 `<summary>` 保持单行；多行说明移入类级注释或私有成员（MemberLoginService 不标 GenerateController 无此问题——适用于同域 [GenerateController] 服务） | 通用（TKWF 生成链） |
| 3 | **.NET 10 NamedRateLimiter API 更名**：`RequireRateLimiter` 不存在 | 用 `RequireRateLimiting`；`OnRejected` 委托返回 `ValueTask` | 通用（.NET 10） |
| 4 | **AfterRouting 闭包参数类型**：`AfterRouting((app, _) => ...)` 的 `app` 是 `IEndpointRouteBuilder` 不是 `IApplicationBuilder` | 中间件（如频控）用 `IWebExtension + MiddlewareAnchor.AfterRouting` 装配，不入 BeforeRouting 管道 | 通用（TKWF Hosting） |
| 5 | **PowerShell 路径含 `$mid` 被变量展开** | 含 `$` 的路径参数用单引号包裹 | 参考实现特有（开发便利） |
| 6 | **Business.md 是活文档且命中 `.TKWF` gitignore**——git 校验无效 | 更新后做**内容级验证**（读回渲染确认），不依赖 git diff；提交纪律：push 不打 tag（tag 必须征求同意） | 参考实现特有 |
| 7 | **`.env` 不随平台生成**：缺 `.env` → `VITE_USE_MOCK` 为空 → MockTransport 不启用 → 直打真实地址报 Network error | 复制 `.env.example` 建立 `.env`；环境变量改动必须重启 dev server 才生效（AGENTS.md） | 通用（Vite 项目） |
| 8 | **架构评审闭环流程**：编码 → 代码审核 → 架构评审；P0 修复闭环后才能提交 | 评审发现的安全问题（如频控缺失 P1-1、mock 退役 P0-1）在同迭代闭环后再提交，不留跨提交债务 | 通用（质量标准） |

## G. 扩展边界与演进

### G.1 验证码 + Captcha 为什么归扩展模块（不落接入主体域）

- 短信验证码登录（发送/校验/频控）与 Captcha 人机验证（v1：自建图形 Provider + SPI，滑块/点选/行为/评分与第三方适配 LATER，门禁归属消费方场景注册表）是**基础设施能力**，非接入主体域业务——与微信联邦（TKWF.Ext.Federation）、微信运营（TKWF.Ext.WeChatOperations）同类的扩展边界（方案 §3.4）。
- 形态：**`TKWF.Ext.SmsCode`（短信验证码引擎）+ `TKWF.Ext.Captcha`（人机验证，+Captcha.Abstractions 契约包）拆分立项**（2026-11——独立立项裁定 C1：不并入 AuthCenter，「商户会员域 vs 全局账号域」；引擎按未来统一核心的胚胎写：场景注册表驱动、零 DMP 逻辑）：领域服务 + REST 端点 + 消费方（UserH5）契约冻结为 `{base}/m/{mid}/api/auth/sms/*`；前端已按契约预留接入点（sms-login-sim.ts TODO 注释）。登录编排归消费方（DMP MemberLoginService 形态）。详见 `docs/SmsCode/验证能力谱系与模块架构-设计梳理.md` + `docs/SmsCode/v0.1.0-SmsCode-Captcha-开发方案.md`
- 期间策略：前端真实模式请求端点 → 404 → 优雅降级"短信服务暂未开通"（不阻塞其他通道）。

### G.2 与 D02A 认证目标态的偏差（ADR12——中间态非目标态）

- D02A 目标态：会员**不设密码**，认证归平台库 `MemberUser`（认证矩阵中会员密码登录 ❌）。
- 现实：`MemberUser` 当前代码不存在、无落地排期；`MemberInfo.PasswordHashed` 已被既有密码管理（ChangePassword/ResetPasswordBySms/AdminResetPassword）写入——v0.10.8 决策：**激活为活登录凭证**（ADR12 决策 1，已实施）。
- **归并路径已就位**：`MemberInfo.PlatformUId` 外键映射（BR-33 及 `idx_memberinfo_merchant_platform` 索引）——`MemberUser` 落地时密码登录可平滑迁移至平台认证，本决策仅影响中间期凭证存储位置（ADR12 后果/缓解）。
- 技术债登记（ADR12 负面后果）：`DmpPasswordHasher` 为 **SHA256 单迭代**（无 KDF 拉伸）——升级到 PBKDF2/Argon2 列入目标态要求。
