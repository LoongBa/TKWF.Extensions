## ⚡ 一句话摘要

**AuthCenter V0.12.0 把 11 个手写 minimal API 端点迁移为 MapGenerated 生成化**（`[ApiExpose]` + `DeclareEndpoints`，框架 B4 生成器 v4.10.82/83/84）——**路径/方法/成功状态码零变化**，但三处**破坏性变更**需适配：① 错误体信封 `ErrorResponse{code,message}` → RFC 9457 `ProblemDetails`（**`errorCode` 值存活**）；② `POST /logout` 204 → 200；③ `GET /grants` 查询键 `?app_id=` → `?appId=`。另门面签名变更（`LoginResult` 删除 + DTO 首参）仅影响**直接消费门面**的业务代码。

## 一、变更总览

| 对象 | 变更前 | 变更后 | 影响 |
|------|--------|--------|------|
| **错误响应信封** | `ErrorResponse{ code, message }` | RFC 9457 `ProblemDetails{ type, title, status, detail, instance, errorCode, translationKey, messageArgs }`——**`errorCode` 扩展字段值存活**（既有业务码 `SMS_SENDER_NOT_CONFIGURED`/`TICKET_INVALID`/`ACCOUNT_FROZEN` 等全部保留） | HTTP 消费方错误解析逻辑 |
| **`POST {prefix}/logout`** | 204 No Content | **200 OK**（生成端点 Task 默认 200） | 前端/客户端状态码判断 |
| **`GET {prefix}/grants`** | 查询键 `?app_id=` | **`?appId=`**（生成器不透传 `[FromQuery]`，Oracle1 D4 裁定回退） | 前端查询参数 |
| **门面签名**（直接消费方） | `LoginAsync(phone, code)` 等简单参数 + 返回 `LoginResult` | **请求 DTO 首参**（`LoginAsync(SmsLoginRequest)`）+ 返回 `Task<TokenResponse>`（`LoginResult` 删除）+ 失败**抛类型化异常** | 后端代码门面调用 |
| **`RoutePrefix` Options** | 生效（默认 `/api/auth`） | **`[Obsolete]`**（组路径由 `TKWF:Api:RestBasePath` + 模块前缀控制） | 显式配置 RoutePrefix 的消费方 |

## 二、逐项适配指引

### ① 错误解析（HTTP 消费方——前端/网关）

错误响应体从 `{code, message}` 改为 ProblemDetails 信封：

```jsonc
// 变更前：{ "code": "SMS_SENDER_NOT_CONFIGURED", "message": "..." }
// 变更后：{ "type": "https://httpstatuses.io/503", "title": "...", "status": 503,
//           "detail": "...", "instance": "...",
//           "errorCode": "SMS_SENDER_NOT_CONFIGURED",   // ✅ 业务码存活——读 errorCode 而非 code
//           "translationKey": "...", "messageArgs": [...] }
```

- **适配动作**：错误解析改读 **`errorCode`** 扩展字段（原 `code` 字段已不存在）；HTTP 状态码语义不变（400/429/503/401）。
- **不破坏**：`errorCode` 值与既有业务码**逐一对应**（9 个既有码全保活——Oracle1 D2 覆写机制），业务判断逻辑仅改字段名。
- 实测字段名：系统字段 PascalCase（`Type`/`Title`/`Status`/`Detail`/`Instance`）+ 扩展字段 camelCase（`errorCode`）——**解析用大小写不敏感或直接读 camelCase**。

### ② logout 状态码（前端/客户端）

- `POST {prefix}/logout` 从 **204 → 200**（body 为空或空对象）。
- 适配动作：成功判断改 `200 OK`；依赖 204 的代码（如 fetch 无 body 分支）检查 2xx 即可。

### ③ grants 查询键（前端）

- `GET {prefix}/grants?app_id=xxx` → **`GET {prefix}/grants?appId=xxx`**。
- 适配动作：查询参数名改 `appId`（camelCase）。

### ④ 门面调用（后端代码——仅直接 `User.Use<IXxx>()` 的消费方）

| 门面方法 | 变更前 | 变更后 |
|----------|--------|--------|
| `ISmsLoginService.LoginAsync` | `(string phone, string code)` → `LoginResult` | `(SmsLoginRequest request, ct)` → `Task<TokenResponse>` |
| `IPasswordLoginService.LoginAsync` | `(string identifier, string clientHash, string salt)` → `LoginResult` | `(PasswordLoginRequest request, ct)` → `Task<TokenResponse>` |
| `IExternalIdpLoginService.LoginAsync` | `(string channelType, params)` → `LoginResult` | `(string channelType, IReadOnlyDictionary<string,string?> parameters, ct)` → `Task<TokenResponse>`（保持原形态） |
| `IExternalTicketLoginService.LoginAsync` | `(ticket, channelId, ipAddress, ct)` → `LoginResult` | `(ExternalTicketLoginRequest request, ct)` → `Task<TokenResponse>`（**`ipAddress` 参数删除**——门面内 `IHttpContextAccessor` 取服务端 IP，防伪造） |
| `ISmsVerificationService.VerifyCodeAsync` | `(phone, code, scene)` → `bool` | `(SmsVerifyRequest request, ct)` → `Task<SmsVerifyResponse>` |
| `ITokenService.RefreshTokenAsync` | 返回 `TokenRefreshResult` | `(RefreshRequest request, ct)` → `Task<TokenResponse>` |
| `ITokenService.GetCurrentTokenInfoAsync` | 返回 `TokenVerificationArtifact` | `(ct)` → `Task<VerifyResponse>`（读 ambient） |
| `ITokenService.RevokeCurrentSessionAsync` | 返回 `bool` | `(ct)` → `Task`（void） |
| `IAuthGrantQueryService.GetGrantsAsync` | `(userId, appId?)` | `(string? appId, ct)`（**userId 参数删除**——门面内读 ambient） |
| `IOAuthTicketService.ExchangeAsync` | 简单参数 | `(TicketExchangeRequest request, ct)` → `Task<TokenResponse>` |

**失败语义**：变更前返回 `LoginResult.FailReason`（值语义）；变更后**抛类型化异常**——调用方需 catch：

| 异常 | HTTP | 典型场景 |
|------|------|---------|
| `DomainException`（基类） | 400 | 校验失败 / 业务拒绝（`ACCOUNT_FROZEN`/`SMS_CODE_MISMATCH` 等）——`ErrorCode` 属性 = 业务码 |
| `RateLimitedException` | 429 | 频控（`SMS_RESEND_TOO_FREQUENT`/`TICKET_RATE_LIMITED`） |
| `ServiceNotConfiguredException` | 503 | 服务未装配（`SMS_SENDER_NOT_CONFIGURED`/`TICKET_SERVICE_NOT_CONFIGURED`） |
| `AuthenticationException` | 401 | 非匿名端点无有效凭据（门面防御兜底；框架 HttpAuth gate 已先拦） |

```csharp
try
{
    var resp = await user.Use<ISmsLoginService>().LoginAsync(new SmsLoginRequest(phone, code), ct);
    // resp.AccessToken / resp.RefreshToken / resp.TokenType / resp.ExpiresIn（+ snake_case 双发别名）
}
catch (DomainException ex) when (ex.ErrorCode == "ACCOUNT_FROZEN") { /* 400 业务码判断 */ }
catch (RateLimitedException) { /* 429 频控 */ }
```

### ⑤ RoutePrefix 配置（显式配置的消费方）

- `AuthCenterEndpointOptions.RoutePrefix` 标 `[Obsolete]`——**不再生效**。
- 组路径现由 `TKWF:Api:RestBasePath`（缺省 `/api`）+ `TKWF:Api:Modules:AuthCenter:Prefix`（缺省 `auth`）控制。
- 适配动作：显式配置了 `TKWF:AuthCenter:Web:RoutePrefix` 的消费方**迁移到 `TKWF:Api` 配置节**（或接受默认 `/api/auth`）。

### ⑥ 端点开关（配置消费方）

- 11 个 `*EndpointEnabled` 开关**塌缩为门面级门控**（`MapGenerated<TFacade>` 挂载门面全部 `[ApiExpose]` 方法）——如 `RefreshEndpointEnabled`/`LogoutEndpointEnabled`/`TokenVerifyEndpointEnabled` 任一开即挂 `ITokenService`（其暴露 refresh+logout+verify 全部）。
- 适配动作：依赖"单端点精确开关"的消费方改在**网关层**做细粒度禁用（框架层已塌缩）；默认全开消费方零改动。

## 三、不破坏项（无需适配）

- **路径/方法**：11 端点路径、HTTP 方法、成功状态码（除 logout）**零变化**。
- **匿名/非匿名语义**：8 匿名端点（`.AllowAnonymous()`）+ 3 非匿名端点（框架 401 gate）与变更前一致。
- **业务错误码值**：9 个既有码（`SMS_SENDER_NOT_CONFIGURED`/`EXTERNAL_IDP_NOT_CONFIGURED`/`TICKET_SERVICE_NOT_CONFIGURED`/`SMS_*_LIMIT`/`TICKET_RATE_LIMITED`/`INVALID_ARGUMENT`/`INVALID_SCENE` 等）**全部保活**——仅信封字段名变。
- **成功响应 body**：`TokenResponse`（access_token/refresh_token/token_type/expires_in 双键并存）零变化。
- **`/login/ticket` 频控**：429 Retry-After 语义不变。

## 四、升级顺序建议

1. **后端先**：门面调用方适配（④）——catch 类型化异常 + DTO 首参 + `TokenResponse` 返回值（编译期强制，缺失即 CS 错误可提前发现）。
2. **前端随后**：错误解析改 `errorCode`（①）+ logout 200（②）+ grants appId（③）——三处均可在升级窗口内灰度。
3. **配置最后**：RoutePrefix 迁移（⑤）+ 开关语义确认（⑥）——影响面最小。

> ⚠️ **破坏性版本**：V0.12.0 为破坏性发布（与 V0.10.x 不兼容）——升级需按上述适配完成后切换；AuthCenter tag 发布后消费方 CPM 升版本时同步适配。

## 五、⚠️ 连带破坏性变更：Federation 端点路径下移（装配 Federation 的消费方必读）

框架 B1-c 端点契约化（v4.10.82/83/84）同步影响 Federation 扩展：
- **端点组路径从旧默认 `/feberation/*` 变为 `/api/feberation/*`**（组 = `TKWF:Api:RestBasePath` 缺省 /api + `[assembly: ExtensionModule("Federation","feberation")]` 前缀）
- 这是**破坏性路径变化**（旧默认为 `/feberation` 无 /api 段），并非"消费方零迁移"
- 受影响消费方须迁移三处：
  1. **微信后台服务器 URL**（公众平台「服务器配置」）：`https://{域名}/feberation/wechat/event/{channelId}` → `https://{域名}/api/feberation/wechat/event/{channelId}`（人工重配）
  2. **跨服务代理调用**：任何硬编码 `/feberation/...` 的出站 URL 改 `/api/feberation/...`
  3. **图文落地链接**：`FederationEventReplyOptions.RoutePrefix`（缺省 `/feberation`）显式配 `/api/feberation`（EventReply 节）——否则拼接出站图文 URL 404
- 前缀覆盖：`TKWF:Api:Modules:Federation:Prefix` 可覆盖模块前缀段（改不了 /api basePath）
- 无配置逃逸口：`TKWF:Api:RestBasePath=""` 回退 /api；设 "/" 全局影响所有扩展（不可行）
