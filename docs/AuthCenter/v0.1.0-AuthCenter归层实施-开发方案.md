# AuthCenter 归层实施 — 命名归层与平台网关库 开发方案（skill 正确路线）

> **范围**: 认证体系四层归层模型（ADR-AuthCenter-归层与命名，Oracle PASS）的**代码落地**——SSO→Federation 命名归层（代码零移动）+ `TKWF.Federation.WeChat` 平台网关库 + 测试路径对齐
> **版本**: v0.1.0 ｜ **日期**: 2026-10-05
> **状态**: 📋 提议（待 Oracle 评审）
> **关键约束**: **tkwf-extension skill §5 铁律——不手写 Store**（SG1 DataService 已提供全部 CRUD 原子方法，门面直接 `User.Use<DataService>()` 组合）；扩展 = TKWF 消费方（强制 Skill 路由）

## 一、背景与目标

### 问题

- **归层模型已定（ADR-AuthCenter-归层与命名）但代码未落地**：认证体系应收敛为 AuthCenter（对内）/ Federation（对外接口）/ `TKWF.Federation.{平台}`（平台网关库）/ `TKWF.Utility.OAuthClient`（引擎）四层；当前代码仍是 SSO 独立包（名称/命名空间与归层模型不一致）。
- **阶段 1 失败教训**：曾试建 `ISsoClientStore`/`ISsoAccessCodeStore`（DataService 薄包装）+ 实体迁回 AuthCenter——被 tkwf-extension skill §5 铁律否决（Store 伪层），已回退（763e614）。
- **平台适配仍是扩展形态**：SSO.WeChat 规划为含 Initializer 的 `TKWF.Ext.SSO.{平台}` 卫星扩展——按归层应为**纯库**（无 Initializer 无 `[TKWFExtension]`）。

### 目标

1. **SSO → Federation 命名归层，代码零移动**：`TKWF.Ext.SSO` → `TKWF.Ext.Federation`（项目名/命名空间/MinVerTagPrefix）；实体 `SsoClientEntity`/`SsoAccessCodeEntity` 保留在本包（不迁 AuthCenter——已裁定 Federation 自含实体）；数据访问保持直接 `User.Use<SsoClientEntityDataService>()`（不建 Store）。
2. **`TKWF.Federation.WeChat` 平台网关库**：微信公众平台双向网关（OAuth 身份获取 + 事件推送接收验签），**纯库无装配**——被 `TKWF.Ext.Federation` 经 `ISsoChannel` 窄适配编排。
3. **测试路径对齐 skill §4.5**：生产路径集成 + 分层单测，宿主不手写 Store、不掩盖守卫。

## 五、技术方案

### 5.1 命名归层（T1——代码零移动）

```
_Framework/SSO/  →  _Framework/Federation/          # 目录改名（git mv）
TKWF.Ext.SSO    →  TKWF.Ext.Federation              # 包名 + 命名空间（全局替换）
MinVerTagPrefix SSO/v → Federation/v                # tag 前缀（SSO 未发布无破坏）
SsoExtensionInitializer → FederationExtensionInitializer  # Initializer 类名/Name/Description
  ⚠️ 消费方白名单 [TKWFEnabledExtension(typeof(SsoExtensionInitializer<>))] 同步改 FederationExtensionInitializer<>（SSO 未发布应无外部消费方——实施前 grep EduPlatform 等确认）
SsoOptions      →  FederationOptions                # Options 类名 + 配置节 TKWF:SSO → TKWF:Federation
SsoSigningKeyConfig → FederationSigningKeyConfig    # Options 子配置类
SsoSecretKeyStore → FederationSecretKeyStore          # internal 静态类（非契约，归层一致）
ISsoChannel / IToken2Service / ISsoAccessCodeService / ISsoClientService / ISsoProfileService
                  # 接口名保留（V0.1.0 契约——语义不变，重命名=破坏性留阶段 2）
Ss* 实体/DataService/内部逻辑类名保留               # 代码零移动铁律 + DB 表名同步（重命名=数据库迁移得不偿失）
.xCodeGen/extensions/sso.xCodeGen.json → federation.xCodeGen.json  # 配置文件改名
_Tests/Extension.SSO.Tests/ → _Tests/Extension.Federation.Tests/   # 测试项目目录+csproj+InternalsVisibleTo+命名空间
```

**原则**：命名归层只调整"包名/命名空间/类归属层次/配置节名"，**不重构代码逻辑**（实体/DataService/门面组合方式保持现状——现状已符合 skill 正确路线）。

**xCodeGen 重生成纪律（Oracle P1-3）**：命名归层后实体命名空间 `TKWF.Ext.SSO` → `TKWF.Ext.Federation`——**必须重跑 `pwsh .xCodeGen/run-xcodegen.ps1 -Ext Federation`**（.g.cs 内命名空间随包迁移需重生成入库，AGENTS §8 重生成纪律）。

### 5.2 数据访问（T1 验证——符合 skill）

```
Federation 门面（ISsoClientService/SsoAccessCodeService 等 : IDomainService）
  └─ 继承 DomainServiceBase（ctor (IDomainUser user,...) : base(user)）
  └─ 数据访问：private XxxDataService? _ds; XxxDataService Ds => _ds ??= User.Use<XxxDataService>();
  └─ 零 Store、零构造注入、零裸 ORM（红线合规）
```

**已满足**（SSO V0.1.0 现状）——命名归层不改变此形态。

### 5.3 `TKWF.Federation.WeChat` 库（T3-T5——纯库无装配）

```
TKWF.Federation（单库包多命名空间）
  └── TKWF.Federation.WeChat
        ├── WeChatOauthChannel（ISsoChannel: wechat_oauth——snsapi_base 静默 OAuth 身份获取）
        ├── WeChatEventChannel（ISsoChannel: wechat_event——事件推送验签 + AES 解密入站）
        ├── WeChatApiClient（出站：access_token L1 缓存 + 并发锁 + code→openid + sns/userinfo）
        ├── WeChatOptions/ChannelConfig（TKWF:Federation:WeChat 节——AppId/AppSecret/Token/EncodingAESKey）
        └── 零 Initializer 零 [TKWFExtension]（纯库——被 Federation 扩展/消费方引用）
```

- **方向（对外/上游）**：认证中心作为 RP 经 WeChatConnector 消费微信 IdP——OAuth 授权码（wechat_oauth）/ 事件推送（wechat_event）两种身份获取流程归一 `(channel_id, openid) → uid` → Federation 签 token2。
- **与既有 `WeChatAuthenticationProvider` 边界**（Oracle P2-3）：内部 Provider（认证中心 token1 签发）vs 联邦库（token2 联邦流身份源）——两会话永不交叉。
- **信任根（一票否决）**：事件推送验签（msg_signature = SHA1(sort(token,timestamp,nonce,msg_encrypt)) + AES 解密）——漏验 = 可伪造任意 openid = 体系崩溃（设计文档 §8.1）。
- **命名空间表归属、程序集保独立**：可独立包发布不引 Federation 扩展（Oracle P2-1 语义）。

### 5.4 Federation 窄适配编排（T6——Oracle P1-1 裁定）

```
TKWF.Ext.Federation（**联邦互联**外交部扩展——ISsoChannel 契约定义在此，随包命名归层）
  ├── ISsoChannel（身份获取窄抽象）——: IDomainService（ADR92 守卫工厂约束）
  ├── `TKWF.Federation.WeChat` 库实现 ISsoChannel（WeChatOauthChannel/WeChatEventChannel）
  │     └─ 库引 Federation 扩展（依赖方向 库→扩展→Abstractions+Domain，单向无循环）
  ├── 注册责任（库无 Initializer——Oracle P1-4/评审点 7）：库提供
  │     `services.AddWeChatFederationChannels()` 扩展方法（内部 TryAddEnumerableConstructible<ISsoChannel, WeChatOauthChannel/WeChatEventChannel>）
  │     消费方 ConfigureServices 调用；Federation 扩展可选按需引库注册
  └── 编排：/sso/login 按 channel 路由（wechat_oauth → 302 OAuth / wechat_event → 引导页）
```

**ISsoChannel 契约归属（Oracle P1-1 定案）**：**保留在 Federation 扩展内**（现状 `ISsoChannel.cs` 仅随命名空间迁移，代码零移动）——理由：① 迁 Abstractions 需引 `TKWF.Domain`（破坏纯 BCL 先例）；② 新建 Federation.Abstractions 增包违反少包原则；③ 库引扩展单向依赖无循环（扩展不引库），是合理依赖方向。ADR §五.3 已同步修订。

**注册责任（Oracle 评审点 7）**：库无 `[TKWFExtension]` Initializer——由**库提供 `AddWeChatFederationChannels()` 扩展方法**（`Microsoft.Extensions.DependencyInjection` 命名空间），消费方/装配层调用；Federation 扩展**不强制引库**（保持扩展核心轻量，平台网关按需加装）。

```xml

<!-- TKWF.Federation.WeChat 库 csproj（Oracle P1-1：引 Federation 扩展实现 ISsoChannel） -->

     入站端点（/sso/wechat/event）归 Federation 扩展/消费方装配层，库只提供验签逻辑类 -->
```

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 命名归层破坏 SSO V0.1.0 已实施代码 | 高 | 代码零移动铁律——只改命名空间/包名/目录（git mv + 全局替换），不重组逻辑；全量回归兜底（F1） |
