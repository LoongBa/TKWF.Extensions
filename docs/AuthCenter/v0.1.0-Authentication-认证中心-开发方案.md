## 一、本版目标

- **核心交付**：`TKWF.Ext.Authentication` v0.1.0——认证中心**通用内核**，覆盖：
  1. **令牌体系**：`TokenService`（RSA RS256 签发/验证/撤销/kid 轮换 + Refresh Token rotation 落库 + 黑名单持久化）
  2. **登录保护**：`AuthLoginAttemptEntity`（限流/审计）+ 防暴力策略
  3. **票据换令牌**：`OAuthTicketEntity`（一次性票据 TTL 5min 单次 + PKCE 支持 + redirect_uri 白名单）
  4. **认证矩阵框架**：Provider 模式 + 配置化启用（短信验证码流程内置 + 微信 OAuth 双形态内置；密码/抖音为扩展点）
  5. **身份适配层**：`JwtDomainUserParser.ParseAndVerify`（验签+令牌→DomainUser，内部强制验签）+ `ITokenVerifier` + `IAuthorizationMapper<TUserInfo>` + `AuthenticationUserHelperBase<TUserInfo>`——**AuthorityFilter 零改动**
  6. **跨系统映射**：`PlatformAccountMapEntity`（平台内部 id ↔ 业务 app + 业务本地 id + UnionId——统一 DMP 双机制）
  7. **平台凭证**：`PlatformCredentialEntity`（AES-GCM 加密）+ `WeChatApiClient`（token 缓存/并发锁）
  8. **平台账号**：`AuthAccountEntity`（手机号主键 + 微信绑定 + 认证声明，不含业务角色）
- **完成定义（DoD）**：8 组件全部落地 + SG1 实体/DataService 委托红线合规（零 IEntityDAC/IFreeSql 直注入）+ xCodeGen `.g.cs` 入库 + 测试（含消费方白名单装配）+ README + 使用指南 + slnx 接线 + 全量回归不破坏。

## 四、命名与边界裁定（ADR-Authentication-认证中心命名与边界 同步落档）

> 详见 [ADR-Authentication-认证中心命名与边界](./ADR/ADR-Authentication-认证中心命名与边界.md)（三问必填）。核心裁定：

| # | 决策点 | 裁定 | 理由 |
|---|--------|------|------|
| 1 | **扩展命名** | `TKWF.Ext.Authentication`（命名空间 `TKWF.Ext.Authentication`） | 既有 `TKWF.Ext.Identity`（V0.3.3 用户/角色管理）已占用 Identity 名——需求文档建议的"身份适配层命名 Identity"**冲突**（Oracle I1 是教育线方案语境，落 TKWF 生态须规避撞名）；`Authentication` 语义准确（认证中心 = 认证面 + 身份适配层 + 映射）且与对标清单 OpenIddict 条目标签一致 |
| 2 | **包形态** | 单包，不拆 `.Abstractions`（本期） | 消费方是业务系统（应用层）而非其他扩展；身份适配层契约（`ITokenVerifier`/`IAuthorizationMapper`）随主包发布即可；未来 Profile/口令体系若需消费再按 ADR48 D7 拆 |
| 2b | **Domain/Web 拆分裁定（Oracle C6 吸收——T1 前落档）** | v0.1.0 单包含 `FrameworkReference Microsoft.AspNetCore.App`（RateLimiting 先例），**暂不拆 `.Web` 独立包**；显式记录触发条件 | 评估：v0.1.0 目标消费方（DMP 装配实例 / 教育线 auth.loongba.cn / 业务系统 Web API）**均 Web 宿主**——单包可行且简单；但 **standalone/非 Web 消费方出现时须拆 `TKWF.Ext.Authentication.Web`**（对齐 Notifications.SignalR 先例）——使用指南注明该触发条件 |
| 3 | **账号边界** | `AuthAccountEntity` 只承载「你是谁」：平台内部 id + 手机号 + 微信绑定 + 认证声明（teacher_verified/auth_level）——**不含业务角色/商户模型** | 令牌最小化（Oracle N1）+ 业务角色本地映射（Oracle I4）；DMP 的 PlatformAdmin/Merchant/Member 多态账号在装配层经 `IAuthorizationMapper` 本地化，Ext 不感知角色模型 |
| 4 | **与既有 Identity 划界** | Identity（用户/角色管理 + PasswordHasher）**保持不动**，认证中心**不复用其 UserEntity/RoleEntity**——认证中心账号表独立（手机号主键 + 微信绑定，模型根本不同） | Identity 面向用户名/密码 + 角色持久化；认证中心面向手机号主键 + OAuth 便捷登录 + 令牌签发；两模型不兼容，强行复用反而耦合（需求文档 §6 约束 1 同向） |
| 5 | **与 Account/SecurityLog/RateLimiting 划界** | 认证中心登录保护 = `AuthLoginAttemptEntity`（限流/审计）**独立实现**；SecurityLog（安全事件日志）/Account（锁定/重置）/RateLimiting（Web 层限流）保持现状 | AuthLoginAttempt 是认证中心实例自身库的登录尝试计数（含 authType/商户维度），语义与 SecurityLog 事件日志、Account 锁定、RateLimiting 中间件互补不重叠；装配实例可按需叠加启用 |
| 6 | **ISessionExchangeService** | **自建** `ITokenVerifier`（主框架无该接口——探索确认零匹配） | 需求文档 §2.1 引用的 DMP `ISessionExchangeService` 在主框架/扩展生态均不存在（DMP 仅接口无实现）——以 `ITokenVerifier` + `JwtDomainUserParser.ParseAndVerify` 替代语义（令牌验证 + DomainUser 恢复） |

### 5.2 令牌契约（冻结，需求文档 §三 + Oracle 确认）

```json
{
  "iss": "<auth-instance-id>",
  "sub": "user:<平台内部id>",
  "userId": "u_xxxx（string32 内部 id）",
  "authType": "sms | wechat | password | redeem",
  "auth_level": 1,
  "teacher_verified": false,
  "exp": 1722243600,
  "iat": 1722240000,
  "jti": "unique-token-id",
  "kid": "rsa-key-2026-07"
}
```

- **不含业务角色**：令牌只回答「你是谁」——`teacher_verified` 是身份声明（类比 OIDC `email_verified`），**不参与 AuthorityFilter 的 IsInRole**；业务角色由各业务系统 `IAuthorizationMapper.MapRoles(sub, claims)` 本地映射（Oracle I4）。
- **签名**：RS256（RSA PKCS#1 v1.5 SHA-256）；`kid` 标识密钥版本（JWK RFC 7517 语义），支持轮换。
- **令牌生命周期**（需求文档 §3.3）：

| 类型 | 有效期 | 用途 |
|---|---|---|
| Access Token | 2h（在线） | 调用 API / 换 DomainUser |
| Long-lived Token | 7d（壳端/低敏） | 凭 refresh 续 |
| Refresh Token | 30d rotation | 换新 Access（SHA256 落库，新旧不可复用） |
| 一次性票据 | 5min 单次 | URL 回调承载，换令牌用 |

- **回调承载铁律（用户裁定 + Oracle B1）**：URL 只带一次性票据 + `redirect_uri`，绝不带敏感信息；纯前端静态站走公网 `/oauth/exchange` + **PKCE code_verifier** + 票据绑 `app_id` + `redirect_uri` 白名单。

### 5.4 TokenService（业界成熟重写）

> **摒弃 DMP 三缺陷**：①内存 `Lazy<RSA>` 密钥（重启丢失/多实例不一致）→ **持久化密钥**（`AuthCenterOptions.SigningKeyPath` PEM 文件，启动加载，kid 轮换）；②内存 `ConcurrentDictionary` 黑名单（重启丢失）→ **`AuthTokenBlacklistEntity` 落库**（验签时查 jti）；③直注入 `IEntityDAC<AuthRefreshToken>`（红线违规）→ **委托 `AuthRefreshTokenEntityDataService`**。

```csharp
public interface ITokenService
{
    Task<TokenIssueResult> IssueTokenAsync(TokenIssueRequest request, CancellationToken ct = default);
    Task<TokenValidationResult> ValidateTokenAsync(string accessToken, CancellationToken ct = default);   // 验签 + kid + exp + 黑名单 → 载荷
    Task<TokenRefreshResult> RefreshTokenAsync(string refreshToken, CancellationToken ct = default);      // rotation：SHA256 查旧 → TokenVersion 校验 → 置 revoked → 签发新对
    Task RevokeTokenAsync(string jti, string reason, CancellationToken ct = default);                     // 撤销 → 黑名单落库
}
public record TokenIssueRequest(string UserId, string AuthType, int AuthLevel, bool TeacherVerified, string? DeviceInfo = null);
public record TokenIssueResult(string AccessToken, string RefreshToken, int ExpiresIn);
public record TokenRefreshResult(string AccessToken, string RefreshToken, int ExpiresIn);
public record TokenValidationResult(string UserId, string AuthType, int AuthLevel, bool TeacherVerified, string Jti, DateTime ExpiresAtUtc, IReadOnlyDictionary<string, string> Claims);
```

- **JWT 编解码**：手写（Base64Url + RS256 签名），对齐 DMP 新版手写 RSA 语义但**零第三方 JWT 库依赖**（与扩展仓库"零新增依赖优先"一致——仅 BCL `System.Security.Cryptography`）；`kid` 从签名密钥版本注入。
- **🔒 JWT 验签安全加固清单（Oracle C1 吸收——T2 编码前落档）**：
  1. **`header.alg` 强制 == `"RS256"`**（拒绝 `none`/`HS256` 等——防 `alg=none` 伪造令牌攻击）；
  2. **签名比对用 `CryptographicOperations.FixedTimeEquals`**（防时序攻击）；
  3. **RSA 密钥长度校验 ≥ 2048-bit**（启动 fail-fast）；
  4. **`exp`/`iat` 校验**（`iat` 不得未来；`exp` 不得过去）；
  5. **`kid` 不匹配 → 拒绝**（防 kid 注入——验证遍历 `SigningKeys` 白名单）；
  6. **`iss` 校验**（`Options.Issuer` 匹配——多 auth 实例隔离，Oracle 8.4）；
  7. **Base64Url 边界**：padding 去除/补齐、多段拼接签名范围 `base64url(header).base64url(payload)` 精确实现 + 测试覆盖（含 `+`/`/`/`=`/unicode）。
- **密码修改/绑定变更处置策略（Oracle C2 吸收——T2 编码前落档）**：`AuthAccount.TokenVersion++` 后，**存量 2h access token 靠短 TTL 自然失效**（业界主流——Access 验签保持无状态，Refresh 是收权点；不做 access 级主动撤销）。使用指南须告知消费方"密码修改后 2h 内旧 access token 仍有效"；高安全场景可后续加"按 UserId 批量黑名单撤销"（v0.2.0 候选）。
- **黑名单查询缓存策略（Oracle C3 吸收——T2 实现时落实）**：`ValidateTokenAsync` 查 `AuthTokenBlacklist` 前经 **`IMemoryCache` 短 TTL 缓存（30~60s）** 前置过滤（黑名单条目量小 + TTL=token 自然过期；对齐 WeChatApiClient L1 缓存先例）——避免每请求 1 次 DB lookup；使用指南说明高流量场景可配 Redis 分布式缓存（v0.2.0）。
- **密钥管理**：`AuthCenterOptions.SigningKeyPath`（PEM 私钥）+ `PublicKeyPath`（可选，默认从私钥推导）；**fail-fast**：生产（`IsProduction`）缺密钥/默认值 → 拒绝启动（对齐 DMP fail-fast + 需求 §8）；开发自动生成临时密钥 + Warning。
- **kid 轮换**：Options 支持 `SigningKeys`（多个 `{Kid, Path}`），`CurrentKid` 指定签发；验证遍历所有 kid 匹配（JWK RFC 7517 语义——旧密钥签名可验证直到过期）。
- **Refresh rotation 流程**：`RefreshTokenAsync` → SHA256(refreshToken) 查记录 → 校验 `IsRevoked=false && ExpiresAt>now && TokenVersion==account.TokenVersion` → 置旧 `IsRevoked=true/RevokedAt=now` → 按原 UserId/AuthType 重新 `IssueTokenAsync` → 新 refresh 落库。**重用检测**（业界 BCP）：已撤销 TokenHash 再次出现 → 判定泄露 → 撤销该用户全部 refresh + Warning（DataService 批量更新 `RevokeAllByUserIdAsync`——Oracle 2.3 确认 `.g.cs` 基座含批量转发或手写分部补）。
- **撤销**：`RevokeTokenAsync` → 黑名单落库（jti/ExpiresAt=token 过期时间）→ 验签时查 `AuthTokenBlacklist`（命中 → 拒绝）。

|---|---|---|
| null（服务端/trust 签发） | null | **放行**（信任服务端路径，须配合 AppId 白名单 + 内网 IP 信任） |

- 端点映射（`/oauth/exchange` 等）归**装配实例**（DMP 应用层/教育线认证中心实例重写 `AuthEndpoints`——需求 §2.3 明确端点按业务线重写，Ext 提供 Service 层）。

### 5.8 身份适配层（AuthorityFilter 零改动）

> **探索确认主框架事实（2026-09-30 源码核实）**：
> ① `AuthorityFilterAttribute<TUserInfo>.PreProceedAsync` 只消费 `DomainUser<TUserInfo>` 的 `IsAuthenticated` + `IsInRole(string)` + `UserInfo.UserName`——**不关心 DomainUser 来源**（Oracle N3）。
> ② **主框架 HTTP 认证 = SessionKey 会话恢复**（`ContextExtractionMiddleware` 阶段 2 + `UseWebSession<TUserInfo>()` 注册的会话解析委托 → 从 SessionKey 恢复 DomainUser 放入 `HttpContext.Items[DomainUserKey]`）——**无内置 Bearer JWT handler**（`HttpAuthenticationMiddleware` 只消费已恢复的 DomainUser，不解析令牌）→ **认证中心必须自建「JWT→DomainUser」恢复路径**。
> ③ **`DomainUser.LoginAsUserAsync(TUserInfo authenticatedUserInfo, EnumLoginFrom loginFrom)` 为 public**（DomainUser.cs L451，注释明示"适用于 OAuth、扫码等外部认证流程，由外部认证方保证用户身份"——内部 `UserInfo=...; IsAuthenticated=true; UpdateAndActiveSessionAsync()`）——**扩展可经此路径构建已认证 DomainUser**，但需已 Attach Host 的实例 → `DomainUserHelperBase.CreateUserInstance()`（protected internal）——**必须走 UserHelper 子类路径**。
> ④ `DomainUserHelperBase` 已有 `OnLoginBySmsCodeAsync`/`OnLoginByWeChatScanAsync`/`OnLoginByWeChatAppletAsync`/`OnLoginByOAuthAsync` 子虚方法（默认 NotSupportedException）——**认证中心可预实现**（对齐 IdentityV0.3.0 `IdentityUserHelperBase` 先例，该先例生产验证）。

**双路径设计**（对应两种消费场景）：

```
路径 A · 登录钩子（业务系统自己触发登录：短信/微信/OAuth）
  AuthenticationUserHelperBase<TUserInfo>（消费方继承）
    └─ 预实现 OnLoginBySmsCodeAsync / OnLoginByWeChatScanAsync / OnLoginByWeChatAppletAsync / OnLoginByOAuthAsync
         └─ ISmsVerificationService 校验 or ITokenVerifier 验签
         └─ IAuthorizationMapper<TUserInfo>.MapRoles(sub, claims)   // 本地业务角色（Oracle I4）
         └─ CreateUserInfoFromToken 工厂 → CreateUserInstance()（已 Attach Host）→ user.LoginAsUserAsync(userInfo, loginFrom) → 已认证 DomainUser
         └─ AuthorityFilter 零改动消费

路径 B · 令牌恢复（业务系统每次请求带 Bearer JWT——API 消费场景）
  JwtAuthenticationMiddleware<TUserInfo>（认证中心自建 Web 中间件，装配方 opt-in AddJwtAuthentication）
    ├─ 读 Authorization: Bearer <jwt>
    ├─ JwtDomainUserParser.ParseAndVerify(token)（验签 + 令牌→TokenValidationResult，Parse 内部强制 Verify——Oracle I5）
    ├─ IAuthorizationMapper<TUserInfo>.MapRoles(sub, claims) → 本地角色
    ├─ 构建 TUserInfo → user.LoginAsUserAsync(userInfo, loginFrom)（经 UserHelper 子类 CreateUserInstance——需要 Host 上下文）
    ├─ 放入 HttpContext.Items[ContextExtractionMiddleware.DomainUserKey]
    └─ 后续 HttpAuthenticationMiddleware 读已认证 DomainUser → HttpAuthCheckPerformed=true → AuthorityFilter 跳过重复认证检查

**管线顺序（Oracle C5 吸收——T6 编码前落档）**：
  `JwtAuthenticationMiddleware` → `ContextExtractionMiddleware`（SessionKey 会话恢复）→ `HttpAuthenticationMiddleware` → `AuthorityFilter`
  - JwtAuthenticationMiddleware 在 ContextExtraction **之前**：先尝试 Bearer JWT（无 Bearer 则透传），已恢复则**短路**——检测 `HttpContext.Items[DomainUserKey]` 已有值即跳过（防 SessionKey 覆盖 JWT 结果 / 双向覆盖竞态）。
  - 有 Bearer 走 JWT；无 Bearer 走 SessionKey 会话恢复——两路径互斥不叠加，先到先得。
```

- `PlatformCredentialService`：`GetEnabledByPlatformAsync`/`GetAsync(platform, appType)`/`CreateAsync`/`UpdateAsync`/`SetEnabledAsync`——**加密在 DataService 边界**（`PlatformCredentialEntityDataService` 写路径 AES-GCM 加密 `AppSecretEncrypted`，读路径解密；Service 层只见明文）。
- `WeChatApiClient`（对齐 DMP 语义重写，解耦商户模型）：`GetAccessTokenAsync(appId, appType)`（L1 缓存 `ConcurrentDictionary` + `SemaphoreSlim` 并发锁 + 提前 5 分钟过期刷新）+ `GetOpenIdAsync(appId, code)`（`sns/oauth2/access_token`）+ `GetUserInfoAsync(accessToken, openid)`（`sns/userinfo`）——凭证经 `IPlatformCredentialService` 解析（不再直注入裸 DB）。

## 九、DMP-Lite 迁移路径（用户裁定：完成后改用本扩展）

> 迁移 = 用 `TKWF.Ext.Authentication` 替换 DMP-Lite 既有 AuthCenter 实现（参考重写，不复用代码——Oracle I2），DMP 会员卡 AuthCenter **保留原址运行过渡**，按需迁移不强制（用户裁定）；**本扩展完成后 DMP 切换**。

| DMP 组件 | 处置 |
|---------|------|
| `Platform.Domain\Services\AuthCenter\ITokenService/TokenService`（async + RSA + 内存黑名单） | **替换**为 Ext `TokenService`（持久化密钥/黑名单 + DataService 委托——消除 IEntityDAC 直注入 + 内存态两缺陷） |
| `DMP-Lite.AuthCenter\Services\ITokenService/JwtTokenService`（同步旧版） | **废弃**（需求 §2.3：统一用 Ext Platform.Domain 语义版） |
| `AuthLoginAttempt` + `IAuthLoginAttemptService` | 替换为 Ext（DTO/API 对齐，字段兼容） |
| `AuthRefreshToken` | 替换为 Ext（+ TokenVersion 闭环） |
| `ISessionExchangeService`（仅接口无实现） | 替换为 Ext `ITokenVerifier` + `JwtDomainUserParser` |
| `GlobalUserMap` | 替换为 `PlatformAccountMap`（统一映射表承载；DMP 会员外键机制迁入映射表——需求 §6 约束 1） |
| `PlatformCredential` + `WeChatApiClient` | 替换为 Ext（SG1 化 + DataService 委托——消除裸 FreeSql） |
| `PlatformAdmin`（管理员 + 角色） | DMP 应用层装配：经 `IAuthorizationMapper.MapRoles(sub, claims)` 本地映射 SuperAdmin/Operator（Ext 不感知管理员角色） |
| `PlatformSettings` | 复用既有 `TKWF.Ext.Settings`（Ext 认证中心不新建 KV 服务——探索确认既有 Settings 已覆盖） |
| `AuthCenterModule/AuthEndpoints/UserEndpoints`（端点装配） | DMP 应用层重写为消费 Ext Service（`/auth/*` 端点调用 Ext `ITokenService`/`ISmsVerificationService`/`IOAuthTicketService`） |
| `DmpPlatformUserInfo` | 替换为 `AuthenticationUserHelperBase<DmpPlatformUserInfo>` + `IAuthorizationMapper<DmpPlatformUserInfo>` |
| `PlatformDb` | DMP 应用层数据库包装保留（多商户分库），Ext 实体表建在平台库 |

> **⚠️ 迁移破坏性影响声明（Oracle C7 吸收——迁移方案评审前落档）**：
> 1. **密钥交接不可行 → 全部存量 access token 失效**：DMP 密钥是启动时内存生成（`Lazy<RSA>`）**无 PEM 可导出**——迁移切到 Ext 持久化密钥后，DMP 存量 access token 验签全部失败 → **所有在线用户被迫重新登录**。须选低峰窗口迁移 + 提前公告；refresh token 可保留（SHA256 hash 迁移 + TokenVersion 初始化对齐则可续，见下）。
> 2. **`PlatformAdmin` 处置单一路径（Oracle 10.2 定案）**：PlatformAdmin **表保留为 DMP 本地表**（AuthAccount 只承载"你是谁"，管理员角色是业务角色不进 AuthAccount）——`IAuthorizationMapper.MapRoles(sub)` 查 PlatformAdmin 映射 SuperAdmin/Operator。不迁入 AuthAccount。
> 3. **DMP 会员外键拆除影响评估（Oracle 10.3）**：`GlobalUserMap → PlatformAccountMap` 迁移须**拆除会员外键**（`MemberUser.UId ↔ MemberInfo.MemberUId` JOIN 改经 `PlatformAccountMap` 查询）——列出受影响查询清单 + 改造量评估后再动；迁移脚本须含外键拆除步骤。
> 4. **TokenVersion 初始化对齐（Oracle 10.5）**：DMP `PlatformAdmin.TokenVersion` 从未自增（未消费字段）——迁移时 `AuthAccount.TokenVersion = 0` + `AuthRefreshToken.TokenVersion = 0` 对齐，否则迁移后所有 refresh 立即失效。

**迁移顺序**（建议）：①DMP 平台库建 Ext **8 实体表** → ②存量数据迁移（GlobalUserMap → PlatformAccountMap、AuthRefreshToken 字段对齐、PlatformAdmin 迁入 AuthAccount 或本地映射）→ ③端点改造（AuthEndpoints 消费 Ext Service）→ ④验证（登录/刷新/撤销/票据闭环回归）→ ⑤观察期后废弃旧实现。

## 十、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| **DomainUser 构建路径**（`IsAuthenticated`/`AttachedHost` setter internal）——认证中心无法直接 `new` 已认证 DomainUser | 身份适配层不可用 | **探索已确认主框架路径**：`DomainUserHelperBase` 子类（`CreateUserInstance` protected internal + `OnLoginBy*Async` 钩子）+ **`LoginAsUserAsync(TUserInfo, loginFrom)` public**（DomainUser.cs L451，明示适用于 OAuth/扫码外部认证）——`AuthenticationUserHelperBase` 走该路径（对齐 IdentityV0.3.0 `IdentityUserHelperBase` 先例，该先例已生产验证）；路径 B 中间件经消费方恢复委托（不触碰 internal Host）；D9/D9b/D10 测试前置验证 |
| 持久化密钥安全（PEM 文件泄露 → 伪造令牌） | 全系统伪造风险 | PEM 文件权限（chmod 600）+ 使用指南安全说明 + 生产 fail-fast 缺密钥拒绝启动；kid 轮换支持紧急换钥；密钥不进代码库 |
| 黑名单表膨胀（每撤销一条） | 存储增长 | `AuthTokenBlacklistEntity` 条目 TTL=token 自然过期 → 定期清理任务（v0.2.0 对齐 BackgroundJobs 清理范式）；本期索引 + 使用指南说明 |
| 短信 Provider 第三方依赖 | Ext 引入外部 SDK | **Ext 零依赖**：`ISmsSender` 抽象 + 装配层实现（腾讯云等）——参考 Emailing `IEmailSender` 先例；生产 Mock → 503 语义测试 |
| 微信资质未就绪（教育线个人订阅号阶段） | 微信便捷登录不可用 | 认证降级路径（需求 §1.3）：手机号短信 = 唯一在线认证，微信 openid 菜单/聊天被动采集；微信 Provider 代码就绪但 `EnabledAuthTypes` 未启用即不接线 |
| 与既有 Identity 命名/职责混淆 | 消费方误用两扩展 | ADR 命名与边界裁定 + 使用指南划界章节（Identity=用户/角色管理，Authentication=令牌/认证，可共存） |
| 手机号唯一 + 微信绑定并发（同手机号两单） | 账号分裂 | `UX_AuthAccount_Phone` 唯一约束 + 绑定流程事务包裹 + 短信验证防劫持（对齐需求 §8 账号合并防劫持） |
| RSA 签名/验证性能（手写 RSA vs 库） | 高并发压力 | 签名在签发/验签路径各一次（2h token 生命周期内有限调用）；RS256 2048-bit 单次 < 1ms（BCL 优化）；JWT 解码零依赖无反射 |
| xCodeGen 生成物陈旧 | 源码/生成物漂移 | AGENTS §8 纪律：实体变更重跑 `run-xcodegen.ps1 -Ext Authentication` + `.g.cs` 提交 + D1 验收断言 |
| 消费方未实现 `ISmsSender`/`IAuthorizationMapper` | 运行时解析失败 | `TryAddScoped` 语义（消费方优先）+ 未实现时 fail-fast（`ISmsVerificationService` 首次调用抛清晰异常）；使用指南接线示例 |
