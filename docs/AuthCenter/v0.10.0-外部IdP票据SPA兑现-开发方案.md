## 一、背景与目标

### 问题

扩展组已完成的微信联邦认证覆盖**两种 OpenId 获取方式**，服务端链路已闭环：

| 方式 | 通道 | 服务端链路（已就绪） | 身份流出形态 |
|------|------|----------------------|-------------|
| **静默认证**（snsapi_base） | `wechat_oauth` | `WeChatOauthChannel`（302 微信 authorize）→ 回调 code → `GET {prefix}/{platformId}/oauth[/{channelId}]/callback` 落地 → `IExternalIdpLoginService.LoginAsync` → 签 token1 | 前端经 `POST {prefix}/login/external/wechat_oauth`（body=`{code, channel_id}`）→ `TokenResponse` **（前端对接面已就绪，SDK 侧补齐 API 即可）** |
| **事件取 OpenId** | `wechat_event` | `POST {prefix}/{platformId}/event[/{channelId}]` 验签一票否决 + AES 解密 → openid → `EventReplyHandlerBase` 签 `ISealedTicketService<FederatedIdentity>` → **被动回复图文链接** | 图文链接落地页凭 **ticket** 获得身份——**前端兑换面缺失（本方案补齐 `POST {prefix}/login/ticket`）** |

**缺口根因**（已逐条核实）：

| # | 断言 | 核实结果 | 证据 |
|---|------|---------|------|
| 1 | 事件链签发的 `SealedTicket`（`FederatedIdentity`）**没有生产可用的 SPA 兑现端点** | ✅ | 图文链接默认指向 `{prefix}/{platformId}/test/{channelId}/{ticket}`——`TestTicketEndpointEnabled` **默认 false（联调验证用，README 明示生产必须关闭）**（`FederationEndpointOptions.cs:50-54`）；且 test 端点返回**身份载荷 JSON（uid/channel_id/openid）非 token1**，不建会话 |
| 2 | 现有票据消费通道**不适配浏览器 SPA** | ✅ | 子应用委托面 `POST {prefix}/identity/claim` 是 **server-to-server**（app_id + credential 鉴权，`SsoSubAppBridge.ClaimAsync`）——SPA 无法持有 credential；`ExpectedClaimant` 原子 CAS 面向 app_id 语义 |
| 3 | 事件链图文链接的落地页**无 token1 会话建立面** | ⚠️ 推论 | 用户在微信内触发事件 → 点击图文 → 落地页（H5/SPA）持 ticket——需"票 → 登录态"端点；当前零生产端点可兑（test 关、claim 需 credential） |

### 目标

1. **新增生产可用的 SPA 票据兑现端点**：`POST {prefix}/login/ticket`（body=`{ticket}`，可选 `{channel_id}`）——验 `ISealedTicketService<FederatedIdentity>` → `IFederatedLoginOrchestrator` 建号/复用编排 → 签 token1 → `TokenResponse`；
2. **与既有 code 通道同族但独立路由**：独立 `login/ticket`（不挂 `external` 前缀——`channelType` 是平台通道语义槽，ticket 是兑现方式）；前端 SDK 侧 `redeemTicket(ticket)` 直接对接（配套 SDK 方案已按此设计）；
3. **安全边界显式化**：票高熵 + 单次 CAS + 短 TTL + 频控（对齐 `ISealedTicketService` 既有语义），不引入新信任根；
4. **编排收敛**：抽取共享 orchestrator（`IFederatedLoginOrchestrator`）——code 通道与票据通道共用"identity → 账号 → 签发"子编排，消除复制编排（P2-2 全局最优）。

> **不属于本方案**（明示边界）：静默认证前端对接面（服务端已闭环——评估结论"静默 = 纯扩展侧可实现，零框架缺口"）；ticket 签发侧（事件链已就绪）；test 端点保留（联调用途）。

## 五、技术方案

### 5.1 端点形态（P2-1 全局最优——独立路由，不挂 `external` 前缀）

```
POST {prefix}/login/ticket              # 独立路由——与 login/external/{channelType}（code 通道）并列
body: { "ticket": "<32B base64url>", "channel_id": "<可选——多通道消歧>" }
→ 200 { access_token, refresh_token, token_type: "Bearer", expires_in }
→ 400 { error: "INVALID_ARGUMENT" | "TICKET_INVALID" | "ACCOUNT_FROZEN", message: <FailReason> }
→ 429 { error: "TICKET_RATE_LIMITED" }
```

- **路由语义**：`login/external/*` 表"外部 IdP 认证通道"（code 通道，需与 IdP 交互）；`login/ticket` 表"票据 SPA 兑现"（已签发的票换 token，无需再与 IdP 交互）——**兑现方式与平台通道解耦**。未来 accesscode SPA 兑现/其他票据形态归 `login/ticket/*` 路由族。
- **路由冲突核实**：`login/ticket` 与 `login/external/{channelType}` 前缀不同，天然无冲突（无 ASP.NET Core 匹配优先级依赖）。
- **游客帧**：`GetGuest(ctx).Use<IExternalTicketLoginService>()`（须 `UseWebSession` 同装配，对齐既有 `HandleExternalLogin`）。

### 5.2 门面编排（P2-2 共享 orchestrator——code 通道与票据通道统一委托）

```
IExternalTicketLoginService.LoginAsync(ticket, channelId?, ip)
  → 频控：IRateLimitCheck.TryAcquire($"ext:ticket:{ip}", TicketRedeemPerMinutePerIp, 1min)   // P2-4 强制
  → RedeemAsync(ticket, context: null)   ← ExpectedClaimant=null：匿名浏览器语义（SPA 无 app 身份）
      null → TICKET_INVALID（统一判因，P1-3——过期/已用/篡改/claimant 不符不泄露） 
  → identity(FederatedIdentity) → 委托 IFederatedLoginOrchestrator.LoginAsync(identity)
      （channel_id 可选参——多通道消歧；orchestrator 收到 identity 后优先 identity.ChannelId 消歧）

IFederatedLoginOrchestrator.LoginAsync(identity)                    # P1-1 fallback 编排
  → identity.UId 非空 → GetByUIdAsync(identity.UId)                    # 优先直读（免二次映射）
      命中 → 校验 IsEnabled/IsFrozen → 复用
      未命中 → fallthrough 到映射
  → Map.GetByChannelAsync(identity.ChannelId, identity.ExternalUserId) # UId 空/未命中 fallback
      命中 → 复用
      无 → 建号（AuthLevel.Federated，Phone 可空）+ LinkAsync（UX 冲突 catch 重查幂等）
  → 回读账号（IsEnabled/IsFrozen 守卫——ACCOUNT_FROZEN）
  → ITokenService.IssueTokenAsync(uid, AuthTypes.Federated, account.AuthLevel, ChannelType: identity.ChannelType)
      （identity.ChannelType null → 不写 channel_type claim——P2-3，既有 ITokenService 支持）
  → LoginResult / TokenResponse
```

- **`ExpectedClaimant` 语义（P1-2 显式约束）**：本端点仅消费事件链签发时 `ExpectedClaimant=null` 的票（任意核销人可兑，SPA 匿名浏览器语义）。事件链 `EventReplyHandlerBase` 把 `ExpectedClaimant` 决定权交给子类（`payload.ExpectedClaimant`）——若子类签了带 claimant 的票（绑定特定 app_id），本端点 `RedeemAsync(context: null)` CAS 恒败 → `TICKET_INVALID`（**安全正确 fail**，非隐蔽失效；README 明示约束，测试覆盖）。带 claimant 的票由对应 handler 自行提供专属兑现面（子应用通道不变）；未来若需 claimant 透传，body 增可选 `claimant` 字段（开放项记录）。
- **一致性（P2-5 fail-closed 边缘）**：ticket 消费（`RedeemAsync` 线程安全 CAS）先于建号/签发——**票消费与建号非同一事务**（对齐 `ExternalIdpLoginService` 现状：认证与建号分离）；若 `RedeemAsync` 后建号失败 → 票已消费但无会话（**fail-closed**）。**运维补偿流程（文档化）**：服务端 `ILogger.LogError` 记录"票消费成功但建号失败"（含 ticket hash + ChannelId + ExternalUserId）；客户端重试同票仍 `TICKET_INVALID` → 提示重新触发事件取新票；运维经日志反查（external_user_id → 既有映射若已落库可手动签发兜底）。建号幂等靠 `PlatformAccountMap` UX 冲突 catch 重查（对齐既有 `LinkAsync` 硬化）。

### 5.3 契约（冻结面）

| 项 | 值 |
|----|-----|
| 端点 | `POST {prefix}/login/ticket`（`RoutePrefix` 默认 `/api/auth`） |
| 请求体 | `{ ticket: string, channel_id?: string }` |
| 响应 | 复用 `TokenResponse`（AccessToken/RefreshToken/TokenType/ExpiresIn） |
| token | 与既有 token1 同契约（RS256 + kid + aud 可选 + `authType=federated` + `channel_type`=identity.ChannelType（可空）） |
| 匿名 | `[AllowAnonymous]`（游客帧） |
| SDK | `redeemTicket(ticket, channelId?)`（独立 API，不复用 `loginByExternal`——P2-1 配套） |

## 六、安全边界

- **信任根**：不新增——事件入站验签（`WeChatEventCrypto` 一票否决）→ 签 SealedTicket（高熵 + 短 TTL + 单次 CAS）→ 本端点兑现；**中间无新信任面**。
- **防枚举/防重放**：票 32B 高熵（对齐 test 端点注记）；单次 CAS（`RedeemAsync` 原子）；短 TTL（`SealedTicketExpirationSeconds`，对齐 TrustCenter 默认）；过期/已用/篡改/claimant 不符统一 null → `TICKET_INVALID`（不泄露判因，P1-3）。
- **频控（P2-4 强制）**：票兑换 ctor 注入 `IRateLimitCheck`（Initializer fallback `MemoryRateLimitCheck`，对齐 V0.9.0 密码登录先例）key `ext:ticket:{ip}`——强度阈值归领域配置 `LoginProtectionOptions.TicketRedeemPerMinutePerIp`（默认 10，配置分层 AGENTS §8）；未装配 `IRateLimitCheck` → fallback 兜底"始终在"（fail-closed）。
- **claimant 约束（P1-2）**：本端点仅消费 `ExpectedClaimant=null` 的票——带 claimant 票 CAS 恒败 `TICKET_INVALID`（安全正确 fail）；README 明示业务 handler 约束。
- **账号态**：复用 `IsFrozen`/`IsEnabled`/`TokenVersion` 既有守卫（`ACCOUNT_FROZEN`）；`TokenVersion++` 后存量 token 短 TTL 自然失效（对齐 Oracle C2 处置）。
- **配置分层**：端点开关归 `TKWF:AuthCenter:Web`（暴露面）；频控阈值归 `TKWF:AuthCenter`（领域决策）——`Web` 层无领域安全开关。
- **fail-closed 边缘（P2-5）**："票消费→建号失败"运维补偿流程文档化（§5.2——日志记录 + 客户端重取票 + 运维反查兜底）。
