## 一、背景与问题

### 1.1 现状：四种凭据形态、三套词表、零统一抽象

| 形态 | 载体 | 例子 | 问题 |
|---|---|---|---|
| A 内联凭据列 | `AuthAccountEntity` | `Phone`（兼身份锚 + 短信凭据）、`PasswordHash`、`FederationAnchorOpenId`、`AuthLevel` | 同一实体混装「身份」「凭据」「派生状态」；加一种认证方式 = 加一列 |
| B 1:1 档案 | `UserProfileEntity` | `Email`（非登录凭据，fail-closed） | 邮箱无法作为认证方式复用 |
| C 1:N 因素行集合 | `PlatformAccountMapEntity` | `(ChannelId, ExternalUserId) → UId` | 认证映射与业务 id 映射混装同一表（`LinkAsync` 把 channelId 塞进 `BusinessAppId`） |
| D 1:N 因素行集合 | `MfaSecretEntity` | `(UserId, Method)` | 第二因素自成体系，与主因素零共享 |

- 全仓 `CredentialType|AuthFactorType|AuthMethodType` **零命中**——无统一因素抽象
- 三套互不共享词表：`AuthTypes`（主因素）/ MFA `Method`（第二因素）/ `PasswordResetCode.Channel`（找回通道）
- **后果**：无法回答「该账号可用哪些方式登录」、无法按因素风控/禁用、绑定/解绑无统一落点

### 1.2 冻结：单槽 + 双向缺陷

`IsFrozen` + `FreezeEnd` 仅一组，`FreezeAsync`/`UnfreezeAsync` 均整实体读改写：不可多原因、解冻无条件清空、无原因留痕、无部分解除。**后果**：恢复关注时把风控冻结一起解除。

### 1.3 绑定/解绑：只有「绑」没有「解」

`PlatformAccountMapEntityDataService` 明确「无删除路径（T7 定稿）」`hasSoftDelete:false`，`LinkAsync` 为 upsert，`ISsoChannelMapService` 无 `UnlinkAsync`；唯一索引 `TKWFIX_PlatformAccountMap_Channel` → 保留行则无法重绑。解绑后无 `TokenVersion++` → 旧 refresh 仍可续。

### 1.4 审计：绑定关系无领域事实源

SecurityLog 仅覆盖 Freeze/Unfreeze；绑定/解绑无领域事件。

### 1.5 建号：V0.10.0 已解决（本方案只加策略开关）

## 四、目标模型

### 4.1 概念分层（核心判据）

```
身份（Identity）      AuthAccount         UId / IsEnabled / TokenVersion
凭据（Credential）    AuthFactor          Password / Sms / Email / Federated（预留 Totp/Passkey）
冻结（Policy）        AuthAccountFreeze   多原因 / 范围 / 到期 / 解除
事实（History）       AuthFactorEvent     绑/解/验证/重置（追加写）
订阅（Relationship）  → 不在 AuthCenter（Iteration 2 / Federation）
```

**判据**：*凭据*回答「凭什么证明」，其 `Identifier` 即身份锚（手机号、邮箱、openid）；unionid/联盟锚点 = **特殊通道的联邦因素**（`channelId` 命名空间表达），不是独立实体概念；*订阅*归渠道域。四者正交。

### 4.2 决策 D1：删除全部投影列（Oracle P0 #1/#2/#4 采纳）

| 列 | 处理 | 替代 |
|---|---|---|
| `Phone` | **删除** | 查 `AuthFactor(Sms, Identifier=E164)`；`GetPrimaryPhoneAsync(uid)` = 最早 `BoundAt` 的 Active Sms 因素 |
| `FederationAnchorOpenId` | **删除**（含唯一索引） | 特殊通道联邦因素（联盟服务号 = channelId，见 D2b） |
| `AuthLevel` | **删除** | `GetAuthLevelAsync(uid)` 运行时推导（任一 Federated Active → 2，否则 1） |
| `IsFrozen` / `FreezeEnd` / `IsFrozenEffective` | **删除** | `IFreezeStateProvider.IsFrozenAsync(uid)` |
| `PasswordHash` / `MustChangePassword` | 迁移 | `AuthFactor(Password).SecretHash / MustChange` |

**为何不保留投影**：`Phone` 有 2 处写入点（`SmsAuthenticationProvider.cs:64`、`FederatedLoginOrchestrator.cs:76`），`AuthLevel` 有 2 处（`:65`、`:77`）。「唯一写者」不变量要求把所有写入路径逐一改写 + 解绑时重选投影 + 写等价性测试——成本高于删列，且留下「每加一条写路径都要记得同步」的长期负担。用户裁定：前瞻最优优先，无兼容包袱。`FederationAnchorOpenId` 无任何生产写者/读者（D2b 已核实零调用），直接删列不产生迁移成本。

### 4.3 `AuthFactorEntity`（表 `TKWF_AuthFactor`）

| 列 | 类型 | 说明 |
|---|---|---|
| `Id` | long | 自增 |
| `UId` | string(32) | 所属账户 |
| `FactorType` | int | `1=Password / 2=Sms / 3=Email / 4=Federated / 5=Totp(预留) / 6=Passkey(预留)` |
| `Identifier` | **string(256)** | 规范化标识（§6.1）；256 覆盖 `channelId(64)+"|"+externalUserId(128)=193` + 余量（Oracle P1 #7） |
| `SecretHash` | string(512)? | Password 的 PBKDF2 blob（原 `AuthAccount.PasswordHash`） |
| `SecretUpdatedAt` | DateTime? | 密钥变更时间 |
| `State` | int | `0=Active / 1=Unverified`（解绑 = 物理删，不留 Revoked 态） |
| `MustChange` | bool | 原 `MustChangePassword` |
| `BoundAt` / `VerifiedAt` / `LastUsedAt` | DateTime? | 生命周期（UTC） |
| `Metadata` | string(1024)? | 扩展 JSON（**不参与查询**；承载平台附加属性） |
| `CreateTime` / `UpdateTime` | DateTime | UTC；SQLite 存 ticks（对齐既有 `AuthAccount.CreateTime` 模式） |

索引：`TKWFIX_AuthFactor_Type_Identifier` UNIQUE `(FactorType, Identifier)`；`TKWFIX_AuthFactor_UId` `(UId, FactorType)`。
实现：`partial class` + `[Table(Name="TKWF_AuthFactor")]` + `[DomainGenerateCode(UserType=nameof(AuthCenterUserInfo))]`；不手写 `IDomainEntity`/`IsFromPersistentSource`。

### 4.5 决策 D2b：**消除锚点概念**（Oracle P0 #4 延伸，2026-10-20 核实后裁定）

| 依据（已核实） | 结论 |
|---|---|
| `FederationAnchorOpenId` 生产调用点 **0 处**（仅实体定义 + 唯一索引 + `AuthAccountQueryService` 自查） | 不存在需要保留锚列的读取方 |
| `SetFederationAnchorAsync` / `GetByFederationAnchorAsync` 生产调用 **0 处**（仅 `IAuthAccountQueryService` 自身实现，无外部消费者） | `ISsoAccountLinkService` 为**空转契约**，可直接退役 |
| `SsoAccountAnchor.Create()` 仅测试引用（`SsoAccountAnchorTests.cs`） | 生成器属未兑现能力 |
| `WeChatOauthChannel.cs:17`：`scope=snsapi_base 且 ChannelId=联盟服务号时，openid = 联盟锚点（写 FederationAnchorOpenId 归装配层）` | 「锚点」本质 = **特殊通道（联盟服务号）的联邦身份**，且按配置分层裁定写归属装配层——不是独立实体概念 |

**决策：不建 `AuthIdentityAnchorEntity` 表，删除 `FederationAnchorOpenId` 列与 `ISsoAccountLinkService` 契约；「平台无关直认」改由特殊通道绑定表达**：

- 联盟服务号（或未来任何「平台无关」通道）照常走 `AuthFactor(Federated, channelId=<联盟服务号>, identifier=<openid>)`——**锚点 = 特殊通道的联邦因素**，无特殊结构
- **联盟服务号通道常量（oracle6 C7）**：`AuthCenterChannelIds`（现有 `WechatMp`/`WechatWeb`，`IAuthAccountQueryService.cs:77-78`）增常量——联盟服务号由装配层 Options 提供（配置分层：领域提供因素能力，装配层决定具体通道 + ChannelId 值），故不硬编码常量，由 `AuthCenterOptions.ExternalIdentity.AllianceChannelId`（可空，默认 null）承载；`GetByExternalIdAsync(配置的联盟服务号ChannelId, openid)` 由装配层调用
- `GetByFederationAnchorAsync(anchor)`（若有装配层需要）→ `IExternalIdentityService.GetByExternalIdAsync(联盟服务号ChannelId, openid)`，零新增表/列
- 配置分层照旧：锚点写入属装配层决策（Web 层），领域层只提供映射能力
- **UnionId 同样不建表**：`GetByUnionIdAsync` 删除，改 `AuthFactor(Federated, channelId=<union 虚拟通道>, identifier=<unionid>)`（若未来有跨渠道自然人识别需求，按 I2 覆盖；本期零消费方）

### 4.6 决策 D3：多原因冻结 + `IFreezeStateProvider`

`AuthAccountFreezeEntity`（表 `TKWF_AuthAccountFreeze`）：`Id / UId / Reason / Scope / Source / FreezeEnd? / ReleasedAt? / ReleasedBy? / CreatedAt / CreatedBy / Note?`。

- **Reason**：机器可读键（`manual / wechat_unfollow / risk_control / arrears / violation`，业务可自定义字符串）
- **Scope**：`0=Account（全站登录）/ 1=Login / 2=Feature`——**V0.11.0 恒为 0**，其余为预留位；实体注释固化此不变量（Oracle P2 #12）
- 活跃判据：`ReleasedAt == null && (FreezeEnd == null || FreezeEnd > DateTime.UtcNow)`
- 幂等：同 `(UId, Reason, Scope)` 的活跃行不重复建

`IFreezeStateProvider`（AuthCenter 内部契约，Scoped，帧内缓存）：

```
Task<bool> IsFrozenAsync(string uid, ct)          // 短路 + 缓存
Task<FreezeSnapshot> GetAsync(string uid, ct)     // IsFrozen / Reasons[] / NextExpiry
Task InvalidateAsync(string uid)                  // 冻结/解冻后主动失效
```

- **无投影列**：`IsFrozen` 真值只在冻结行；每帧最多一次查询
- 9 处 `IsFrozenEffective` 读取点改为 `await freezeState.IsFrozenAsync(account.UId, ct)`（§6.5）

### 4.7 决策 D4：绑定/解绑

`IAuthFactorService`（域门面，`DomainServiceBase` + `AddConstructibleService`）：

```
Task<AuthFactorDto> BindAsync(uid, factorType, identifier, secretHash?, mustChange, source, ct)
Task UnbindAsync(uid, factorId, operatorName, ct)
Task<IReadOnlyList<AuthFactorDto>> ListAsync(uid, ct)
Task<bool> HasAnyActiveAsync(uid, ct)
Task<string?> GetPrimaryPhoneAsync(uid, ct)              // 最早 BoundAt 的 Active Sms
Task<int> GetAuthLevelAsync(uid, ct)                     // Federated→2，否则 1
Task<bool> IsBoundToChannelAsync(uid, channelPrefix, ct) // wechat_mp| / wechat_web|
```

**UnbindAsync 六步**：

1. 归属校验（`factor.UId == uid`）
2. **最后因素守卫**：解绑后 Active 因素数 == 0 → `LAST_FACTOR_CANNOT_UNBIND`
3. 追加 `AuthFactorEvent(Unbind)`
4. 物理删除因素行（唯一索引释放 → 可重绑）
5. `TokenVersion++`（CAS `WHERE UId=@uid AND TokenVersion=@old`）
6. SecurityLog `Unbind`

- 3~5 在同一 `ITransactionManager.Begin()`（`Propagation.Required`）内：`FreeSqlEntityDAC` 经 `uowManager.Current?.GetOrBeginTransaction()` 绑定环境 UoW（证据：`_Domain.Infrastructure\FreeSql\FreeSqlEntityDAC.cs:11-13`、`FreeSqlTransactionManager.cs:20-21`）→ 两表共享同一事务（Oracle P1 #9）
- 因投影列已删除，解绑**无需重选任何投影**（Oracle P1 #5 自然消解）
- 冲突：同 `Identifier` 绑不同 UId → catch 唯一约束 → `FACTOR_ALREADY_BOUND`（复用 `PlatformAccountMapService.IsUniqueConstraintViolation` 多方言模式，Oracle P1 #8）；同 UId 同 Identifier 并发 → 幂等返回既有行

| 派生值 | 规则 | 调用点 |
|---|---|---|
| 主手机号 | 最早 `BoundAt` 的 Active `Sms` 因素 → `Identifier` | `AuthenticationUserHelperBase` / `TokenService` / `OAuthTicketService` / `PasswordResetService` / `AuthCenterWebExtension` |
| `AuthLevel` | 任一 Active `Federated` → 2；否则 1 | `TokenService` 签发；`VerifyResponse` |

### 4.9 决策 D5：建号策略（不破 F7）

`FederatedProvisioningOptions { AutoProvision = true }`（`AuthCenterOptions.FederatedProvisioning`，领域节 `TKWF:AuthCenter`）。

- `false` → 未映射身份兑现返回 `ACCOUNT_NOT_PROVISIONED`（fail-closed）
- 建号路径：建 `AuthAccount`（**不写 Phone/AuthLevel**）→ `BindAsync(Federated, {channelId}|{externalUserId})` → `GetAuthLevelAsync` 自然返回 2（Oracle P0 #1/#2 修正）
- 短信首登建号同理：建账户 → `BindAsync(Sms, E164)`（`SmsAuthenticationProvider.cs:61-67` 改造）

### 4.10 决策 D6：**合并映射契约为单一 `IExternalIdentityService`**（2026-10-20 用户确认）

`ISsoChannelMapService` + `ISsoAccountLinkService` **合并**为 `IExternalIdentityService`（`AuthCenter.Abstractions`）；两个旧契约**退役**：

```
Task<ExternalIdentityDto> LinkAsync(uid, channelId, externalUserId, operatorName, ct)     // upsert + 委托 BindAsync（D4 六步，写 Bind 事件）
Task UnlinkAsync(uid, channelId, externalUserId, operatorName, ct)                        // 跨域解绑形态：编码反查 factorId → 委托 UnbindAsync（D4 六步）
Task<ExternalIdentityDto?> GetByExternalIdAsync(channelId, externalUserId, ct)            // 查 uid（不含 secret 字段；经因素查询）
Task<IReadOnlyList<ExternalIdentityDto>> GetByAccountAsync(uid, ct)                       // 委托 ListAsync(uid) 过滤 Federated 投影
```

- `SsoChannelMapDto` → `ExternalIdentityDto(UId, ChannelId, ExternalUserId, LinkedAt)`；**不承载任何凭据字段**（`SecretHash`/`MustChange` 绝不出契约）
- **实现路径（oracle6 复审 C1/C3/C4 明确）**：`PlatformAccountMapService`（实际为 `AuthFactorService` 跨域适配面）实现 `IExternalIdentityService`——
  - `LinkAsync` = **委托** `IAuthFactorService.BindAsync(Federated, identifier={channelId}|{externalUserId}, ...)`：upsert 语义 + 写 `AuthFactorEvent(Bind)` + 唯一冲突幂等（复用现有重查模式）
  - `UnlinkAsync` = **委托** `IAuthFactorService.UnbindAsync`：按 `{channelId}|{externalUserId}` 反查 `AuthFactorEntity.Id` → 委托六步（归属校验/最后因素守卫/事件/物理删/TokenVersion++/SecurityLog）。**守卫仍在域内**（若 Federation 解绑唯一登录因素，账号变无凭据——守卫正确触发；「领域安全决策在领域层」AGENTS §8 红线 2）
  - `GetByExternalIdAsync`/`GetByAccountAsync` = 经 `AuthFactor` 查询/`ListAsync(uid).Where(Federated)` 投影
  - `operatorName` 显式参数（C2）——跨域调用方可能不在 AOP 帧内，不能依赖 `CurrentAopUser` 推断
- `ISsoAccountLinkService` 的 `SetFederationAnchorAsync`/`GetByFederationAnchorAsync` **删除**（锚点消除，D2b）；若装配层未来需要「联盟服务号直认」，走 `LinkAsync(联盟服务号, openid)` + `GetByExternalIdAsync`——契约天然覆盖，零新增方法
- **为何不退役全部映射契约、让 Federation 直接用 `IAuthFactorService`**：跨域契约按消费者意图命名；若 Federation 感知 `FactorType` 枚举与 `{channelId}|{externalUserId}` 编码规则 = 领域泄漏（编码变更将静默破坏跨包调用）；且 `IAuthFactorService` 是**凭据**服务（签名含 `secretHash`/`MustChange`），整体暴露给消费方违背最小面。门面是**接缝**（seam）——承载标识编码，不是 DTO 整形冗余层
- **实现类**：`PlatformAccountMapService` 改实现 `IExternalIdentityService`（内部经 `User.Use<IAuthFactorService>()` 委托，红线合规——不新开 Store）；`AuthCenterExtensionInitializer` 注册一对（`ISsoChannelMapService`/`ISsoAccountLinkService` 两行替换为 `IExternalIdentityService` 一行）
- 契约包 `AuthCenter.Abstractions` → **0.2.0**（破坏：`ISsoChannelMapService`/`ISsoAccountLinkService`/`SsoChannelMapDto`/`SsoAccountAnchor`/`SsoAccountDto.FederationAnchorOpenId` 删除；`IExternalIdentityService`/`ExternalIdentityDto` 新增）；Federation 侧 `EventOrchestrator`/`FederatedLoginOrchestrator` 改引 + **`FederationExtensionInitializer.cs:29` `MinVersion` 0.1.0 → 0.2.0**（oracle6 C5）+ `Federation.csproj` Abstractions 0.2.0

## 六、技术方案

### 6.1 因素标识规范化（门面单点）

| FactorType | 规则 | 示例 |
|---|---|---|
| Password | 恒为 `UId`（一账号一密码） | `u-1730000000000-ab12` |
| Sms | E.164（`+86`，去空格/横线） | `+8613800138000` |
| Email | `Trim().ToLowerInvariant()` | `a@b.com` |
| Federated | `{channelId}\|{externalUserId}`（两段 trim） | `ch_wechat_mp\|oABC123` |

- `Identifier` 上限 256；超长 → 拒绝 `IDENTIFIER_TOO_LONG`（**不做 hash 降级**——避免查询路径分叉，Oracle P1 #7）

### 6.2 解绑原子性

- `ITransactionManager.Begin()`（`Required`，加入既有 UoW）包裹：事件写入 → 删因素 → `TokenVersion++`（`EntityUpdateWhereAsync` CAS）
- 禁止裸 ORM；禁止跨帧「先删后补」
- `TokenVersion++` 失败 → 整体回滚（无「解绑成功但旧 token 有效」窗口）
