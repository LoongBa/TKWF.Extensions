# AuthCenter V0.14.0：业务兑票端点 `/login/ticket/redeem` 开发方案

> **状态**：待 Oracle 评审
> **日期**：2026-11-11
> **来源**：DMP-Lite v0.10.7 待反馈清单 E1（🔴 阻塞 DMP 真机免登闭环）——`v0.10.7-待反馈清单-框架组与扩展组.md` §一 E1 + 配套转达 `v0.10.7-兑票端点契约缺口-转达扩展组.md`（P0）
> **关联契约**：ADR05 方案 B（DMP 侧冻结）——`POST {authCenterBase}/login/ticket/redeem` `{ticket} → 200 FederatedTicketPayload（11 字段）`，`400 TICKET_INVALID / 403 ACCOUNT_FROZEN|ACCOUNT_DISABLED / 429 TICKET_RATE_LIMITED / 503 TICKET_SERVICE_NOT_CONFIGURED`

## 1. 背景与需求

### 1.1 DMP 诉求（转达原文浓缩）

DMP-Lite 公众号图文一键登录（v0.10.7）按 **ADR05 方案 B** 冻结了**业务侧兑票契约**：DMP Merchant 后端经 `AuthCenterTicketClient`（真实 HTTP 实现已就绪，`Platform:TicketRedeemEndpoint` 配置即切换、服务零改动）调 AuthCenter **兑票拿到 payload 明文**（11 字段），由 DMP 侧自行建会员会话/register 分流/领卡——**不要求 AuthCenter 建会话、不发 token**。

遗留 #1 自 2026-10-30 起两次登记「不变」未闭合，扩展侧至今未交付该端点。

### 1.2 现状核对（2026-11-11 本仓实证）

| 项 | 现状 | 差异 |
|---|---|---|
| 已交付 | `POST /login/ticket`（`ExternalTicketLoginService.LoginAsync`，`TicketLoginEndpointEnabled=true` 已启用） | **登录语义**：验票 → `FederatedLoginOrchestrator.LoginAsync`（回读/建号/守卫）→ `TokenResponse` |
| 响应 | `TokenResponse`（access/refresh/token_type/expires_in） | ≠ `FederatedTicketPayload`（11 字段） |
| 副作用 | 兑票即建 AuthCenter 会话 + 消费票 + 发 token | DMP 兑换不需要 AuthCenter 会话（Member 会话自建） |

**结论**：即使 DMP 配置指向 `/login/ticket`，200 响应体无法反序列化 `FederatedTicketPayload` → 判 null → TICKET_INVALID；且真实票据被消费 + 孤儿 token——方向性错误。需扩展侧交付**纯兑票端点**。

### 1.3 契约基线（DMP 冻结，本方案对齐）

```
POST {authCenterBase}/login/ticket/redeem   body: { "ticket": "..." }
→ 200 FederatedTicketPayload（11 字段 JSON 明文）
→ 400 TICKET_INVALID
→ 403 ACCOUNT_FROZEN | ACCOUNT_DISABLED     ← ⚠️ 本方案 R1 裁决点（见 §4.1）
→ 429 TICKET_RATE_LIMITED
→ 503 TICKET_SERVICE_NOT_CONFIGURED
```

## 2. 设计

### 2.1 门面形态（新增独立门面，不复用 `IExternalTicketLoginService`）

新增 **`IExternalTicketRedeemService`**（`TKWF.Ext.AuthCenter`，`: IDomainService`——接口方法标注 `[AllowAnonymousFlag]`）与实现 **`ExternalTicketRedeemService : DomainServiceBase`**（**`public sealed`** + `[DiContractIgnore]` + `[GenerateController]`——形态逐一对齐镜像源 `ExternalTicketLoginService` L31-32，SG1b 生成控制器可激活）。

**裁决理由**：

| # | 理由 |
|---|---|
| 1 | **语义独立**：登录（验票→编排→签 token）与兑票（验票→payload，终止于票）是不同业务语义，同一门面两方法形成"一个门面两条命运"的暧昧面 |
| 2 | **MapGenerated 门面级门控（硬约束）**（B3a/B3b Oracle 裁定语义）：`MapGenerated<TFacade>` 挂载门面**全部** `[ApiExpose]` 方法、开关塌缩为门面级（实证：`ISmsVerificationService` 双开关 OR / `ITokenService` 三开关 OR 合并先例）——若 `RedeemAsync` 挂进既有门面，`TicketLoginEndpointEnabled` 与 `TicketRedeemEndpointEnabled` 无法独立关断（挂载即双端点齐出）。独立门面才能独立开关 |
| 3 | **接口契约单一**：`IExternalTicketLoginService.LoginAsync → TokenResponse` 是 SPA 兑换面契约（DMP 不消费）；兑票契约（→ `FederatedTicketPayload` 明文）挂独立接口，返回类型异构不混面 |
| 4 | **对称命名族**：`IExternalTicketLoginService`（登录）/ `IExternalTicketRedeemService`（兑票）并列，未来 `login/ticket/*` 路由族扩展按此模式 |

**实现类名**：`ExternalTicketRedeemService`。注册：`AddConstructibleService<IExternalTicketRedeemService, ExternalTicketRedeemService>()`（Initializer + 测试宿主同步，对齐既有 24→25 门面清单注记）。

### 2.2 端点声明与装配

```csharp
// IExternalTicketRedeemService（接口方法——对齐镜像源形态：接口面 [AllowAnonymousFlag] + [ApiExpose]）
[AllowAnonymousFlag]
[ApiExpose(RestRoute = "/login/ticket/redeem", RestMethod = "POST", AllowAnonymous = true)]
Task<FederatedTicketPayload> RedeemAsync(ExternalTicketRedeemRequest request, CancellationToken ct = default);
```

- **请求 DTO**：`ExternalTicketRedeemRequest`（EndpointContracts.cs 迁入主包侧——`record ExternalTicketRedeemRequest(string Ticket)`；对齐 `ExternalTicketLoginRequest` 形态；body 绑定 + DTO 首参 B3a 语义）。
- **响应**：直接返回 `FederatedTicketPayload`（Federation.Abstractions 契约 record，11 字段 camelCase 序列化与 DMP 契约键逐字吻合——见 §2.6 字段对照）。
- **WebExtension 挂载**（`AuthCenterWebExtension.DeclareEndpoints`）：

```csharp
if (endpointOptions.TicketLoginEndpointEnabled)
    registry.MapGenerated<IExternalTicketLoginService>();    // 既有，不动
if (endpointOptions.TicketRedeemEndpointEnabled)            // 新增开关
    registry.MapGenerated<IExternalTicketRedeemService>();  // POST /login/ticket/redeem
```

- **开关**：`AuthCenterEndpointOptions.TicketRedeemEndpointEnabled`（`TKWF:AuthCenter:Web`，默认 `true`）——纯暴露面开关，配置分层合规（对齐 `TicketLoginEndpointEnabled` 语义；领域安全策略不进 Web 节）。

### 2.3 兑票流程（镜像 `ExternalTicketLoginService` 但终止于验票）

```
① 入参校验——request.Ticket 空白 → DomainException(TICKET_INVALID)（显式校验，勿走 RedeemAsync 隐性 null——
   对齐既有 Fake/生产语义分裂教训：新端点生产与测试 Fake 恒同码）
② 频控（P2-4 强制）——key ext:ticket-redeem:{ip}（R2 裁决独立桶，见 §4.2）——
   阈值 LoginProtectionOptions.TicketRedeemServicePerMinutePerIp（默认 60/min/IP，服务间调用容量——P0-2 定案）
   → RateLimitedException(retryAfterSeconds, key) { ErrorCode = "TICKET_RATE_LIMITED" }（真实构造：retryAfterSeconds
   首参 + ErrorCode 覆写；>0 时中间件自动写 Retry-After 头——DMP 重试可受益）
③ 验票——ISealedTicketService<FederatedTicketPayload>.RedeemAsync(ticket, context: null)（P1-3 统一判因：
   失败/过期/已用/篡改/claimant 不符恒 null → 400 TICKET_INVALID；P1-2：仅消费 null-claimant 票，
   带 claimant 票 CAS 恒败 → TICKET_INVALID 安全正确 fail）
④ payload.ChannelId 空白（事件链签发契约异常场景）→ fail-closed：LogWarning（观测，对齐镜像源 L102-104
   先例）+ DomainException(TICKET_INVALID)——防「无法定位通道的 payload 透传给 DMP」register 分流链断裂
⑤ L2 账号状态检查（R3，见 §2.4）——冻结/禁用 → ACCOUNT_FROZEN/ACCOUNT_DISABLED（R1 状态码裁决见 §4.1）
⑥ 返回 payload 明文 JSON（11 字段 + extensions 键，见 §2.6）——不建会话、不发 token、不触 FederatedLoginOrchestrator
⑦ fail-hard：ISealedTicketService 未装配（User.Use<ISealedTicketService<T>>() 守卫异常）→
   ServiceNotConfiguredException(503, TICKET_SERVICE_NOT_CONFIGURED)；L2 检查依赖（IAuthAccountQueryService /
   IExternalIdentityService / IFreezeStateProvider）守卫异常同 catch 同码（AuthCenter 内部门面必然注册，纯防御；
   继承镜像源 L129「框架守卫文案变更致 503→500 退化」已知风险注记）
```

**⚠️ 边缘语义注记**（P2-5 吸收）：冻结/禁用拒绝发生在验票 CAS 核销**之后**——票已消费，重试需事件链新票（`ISealedTicketService` 无 Peek 原语下唯一可行顺序，与登录面 P2-5 同型；事件链自动重签代价小）。拒绝分支 `LogWarning`（业务预期拒绝，非异常补偿级 LogError）。成功兑票 `LogDebug`/`LogInformation`（兑票流量可观测性）。

**守卫工厂与懒加载**（DI004 铁律）：`_ticketService ??= User.Use<ISealedTicketService<FederatedTicketPayload>>()`；`_accountQuery ??= User.Use<IAuthAccountQueryService>()`；`_externalIdentity ??= User.Use<IExternalIdentityService>()`；`_freezeState ??= User.Use<IFreezeStateProvider>()`。ctor 仅注入 `IDomainUser / IOptions<AuthCenterOptions> / IRateLimitCheck / IHttpContextAccessor? / ILogger`（与 `ExternalTicketLoginService` 同形态）。**不依赖** `IFederatedLoginOrchestrator`（兑票不编排）。

### 2.4 L2 账号状态检查（R3 设计）

按 payload 定位账号并检查状态（**只读查询，不建号不改写**）：

| 阶段 | 路径 | 说明 |
|---|---|---|
| 定位 | `payload.PlatformUid` 非空 → `IAuthAccountQueryService.GetByUIdAsync(PlatformUid)` | L1 直读（D03 A11 事件预置已分配） |
| 定位 | PlatformUid 空 → `IExternalIdentityService.GetByExternalIdAsync(channelId, externalUserId)`（AuthFactor 反查，V0.11.0 合并契约）→ `ExternalIdentityDto.UId` → **二跳** `GetByUIdAsync(uid)` 取账号行 | 映射复用路径（未绑定 → null） |
| 定位 | PlatformUid 非空但直读 miss（弱身份清理物理删除等数据漂移）→ **fallthrough 反查**（channelId/externalUserId 恒可从 payload 取得——对齐 `FederatedLoginOrchestrator` L77 fallthrough 语义） | 数据漂移容错 |
| 状态 | 账号行存在且 `IsEnabled == false` → `ACCOUNT_DISABLED` | 对齐 `FederatedLoginOrchestrator` 守卫 (f)；顺序先于冻结（L70-73 实证同序） |
| 状态 | 账号行存在且 `IFreezeStateProvider.IsFrozenAsync(uid)` → `ACCOUNT_FROZEN` | 对齐守卫 (e)；帧内快照缓存复用 |
| 无账号 | 两路均未命中 → **放行**（返回 payload） | **不建号**（§2.5 AutoProvision 语义） |

**判据单一真相**：冻结活跃判据经 `IFreezeStateProvider`（其内部委托 `IFreezeService` 单点）——零重复实现（对齐 V0.11.0 定责）。

### 2.5 AutoProvision 语义（回执 DMP 附带事项 1）

**兑票端点不建号、不做 AutoProvision 判断**——保持"只兑票"语义：

- D03 设计：**事件阶段预置**（事件链 `ProvisionAsync`）+ **登录编排兜底**（`FederatedLoginOrchestrator` fallback 建号）；业务兑票端点是"读票面"，不是"建号面"。
- DMP 验收「新粉丝（无账号）兑票 → register 分流 → 领卡建档」的建号动作由 **DMP 侧 register 流程**触发（`AuthAccountService.CreateAsync` / 登录编排），兑票端点只负责回答"这张票是谁的（payload）"。
- 徒增建号会导致：票端点与登录面双建号竞态、无账号判定与 AutoProvision 配置耦联、违反"兑票零副作用"契约。
- **⚠️ AutoProvision=false 组合文档化**（P2-3）：兑票放行 ≠ 建号可行——兑换到的 payload（PlatformUid=null）仅为无账号事实，DMP register 若经 `ProvisionAsync`/登录编排建号仍受 `TKWF:AuthCenter:FederatedProvisioning`（默认 true）门控，false 时返回 `ACCOUNT_NOT_PROVISIONED`——使用指南明示该组合，防 DMP 假设「兑票成功 = 建号闭环可通」。

### 2.6 `FederatedTicketPayload` 11 字段与 DMP 契约对照（逐字核实）

| # | DMP 契约键 | `FederatedTicketPayload` 属性 | 类型 | 备注 |
|---|---|---|---|---|
| 1 | provider | `Provider` | string | 开放注册表 |
| 2 | channelType | `ChannelType` | string | 通道形态（mp_subscription/mp_service/...） |
| 3 | channelId | `ChannelId` | string | 不变键 gh_xxx |
| 4 | channelAlias | `ChannelAlias` | string? | 可空 |
| 5 | externalUserId | `ExternalUserId` | string | openid |
| 6 | unionId | `UnionId` | string? | 可空 |
| 7 | platformUid | `PlatformUid` | string? | 可空（未分配 → DMP register 分流） |
| 8 | assurance | `Assurance` | string | event/base/userinfo |
| 9 | iat | `Iat` | long | Unix 秒 |
| 10 | exp | `Exp` | long | Unix 秒 |
| 11 | jti | `Jti` | string | 单次标识 |

系统默认 STJ 序列化 record 属性名恒为 camelCase——与 DMP 契约键**逐字吻合**，零别名配置。

**⚠️ 实际为 12 键**（P1-3）：record 除 11 个 positional 字段外还有 `Extensions` init 属性（`FederatedTicketPayload.cs` L55，无 `[JsonIgnore]`）——STJ 序列化 200 响应体含第 12 键 `"extensions":{...}`（`protocol_type`/`is_test` 元数据随票透传，Federation 契约原样）。**DMP 反序列化须容忍多余键**（默认 STJ 忽略未知键即可；严格模式需确认——并入 P0-1 回执清单）。

| HTTP | errorCode | 异常类型 | 触发 |
|---|---|---|---|
| 200 | — | — | 兑票成功（payload 明文 12 键） |
| 400 | `TICKET_INVALID` | `DomainException` | 请求体缺/空白 ticket（**生产显式校验，与 Fake 同码**）；RedeemAsync null（票无效/过期/已用/篡改/claimant 不符）；payload.ChannelId 空白（签发契约异常） |

## 3. 验收标准（对齐 DMP 侧 §5）

1. DMP 配置 `Platform:TicketRedeemEndpoint=https://wx.loongba.cn/login/ticket/redeem` → 真实票据兑票返回 11 字段 payload（键名 camelCase 逐字吻合）；
2. 新粉丝（无账号）兑票 → payload.PlatformUid=null 放行 → DMP register 分流 → 领卡建档闭环（扩展侧仅保证"放行不建号"）；
3. 已有会员二次进入 → 兑票成功 → DMP 免登建会话 → open_vip；
4. 错误面：伪造票 400 TICKET_INVALID / 冻结账号 400 ACCOUNT_FROZEN（R1 契约偏差点）/ 禁用 400 ACCOUNT_DISABLED / 频控 429 透传（真实链路复测）；
5. `/login/ticket` 回归不受影响（既有端点 + 既有 198 用例零回归）；
6. slnx 构建 0 错误；AuthCenter 测试全绿（预计 +12~15 用例）。

## 4. 评审请求点

### R1：403 契约 vs 框架中间件映射缺口 —— 本方案裁决：**400 折中 + 转达框架组**

**冲突**：DMP 冻结契约要求 `403 ACCOUNT_FROZEN|ACCOUNT_DISABLED`；框架 `WebExceptionMiddleware`（v4.10.86/ADR111）现状：

| 异常 | HTTP | errorCode |
|---|---|---|
| `DomainException`（默认分支） | 400 | `domainEx.ErrorCode` 透传 ✅ |
| `UnauthorizedAccessException` | **403** | **固定 `FORBIDDEN`**（无自定义透传）❌ |
| `RateLimitedException` / `ServiceNotConfiguredException` | 429 / 503 | ErrorCode 透传 ✅ |

**无**「403 + 自定义 ErrorCode」通道。

**本方案裁决（推荐 A）**：抛 `DomainException`（`ErrorCode = ACCOUNT_FROZEN / ACCOUNT_DISABLED`）→ **HTTP 400 + errorCode 细分**。

理由：
- 与既有 `FederatedLoginOrchestrator` 守卫（e/f）和 `/login/ticket` 完全一致——扩展侧单一语义（冻结/禁用 = 400 业务拒绝），不引入双状态码双语义；
- errorCode 细分保留（DMP 校验链按 errorCode 判断则**零影响**）；
- 零框架依赖，本迭代可交付，不阻塞 DMP 真机闭环。

**P0-1 闭环记录（2026-11-11 Oracle 评审确认）**：400 折中的成立前提 = DMP 消费侧按 `errorCode` 分支而非硬校验 403 状态码。本方案**合理默认**：DMP 契约文档逐码列出 errorCode（TICKET_INVALID/ACCOUNT_FROZEN/...）即以其为消费判据，且 `AuthCenterTicketClient` 系 2026-11-10 新就绪实现——按 errorCode 分支的默认成立概率高；**该默认与 extensions 第 12 键容忍性（P1-3）一并作为回执确认项**（迭代完成回复 DMP 时书面确认；若 DMP 硬校验 403 状态码，则 R1 升格等待框架通道，消费方侧错误处理需适配）。

代价（显式）：与 DMP 冻结契约的 403 状态码偏差——**需 DMP 侧确认**：按 errorCode 判断即可接受（HTTP 状态码仅粗分失败面）；若 DMP 硬校验 403 则需等待框架（见下）。

**并行转达框架组（不阻塞）**：建议框架增 403 + ErrorCode 透传通道，**两选项并陈**（P2-6）：① `ForbiddenException : DomainException`（新类型，语义显式）；② `DomainException.StatusCode` 覆写通道（对既有抛点零迁移更通用，含 `/login/ticket` 等存量 400 抛点受益）。框架落地后本端点 403 升格（400→403 属失败面内变化，errorCode 不变；**若 DMP 按状态码分组处理则需版本协调适配验证**——升格通知时点一并转达 DMP）。

### R2：频控桶独立 vs 共享 —— 本方案裁决：**独立桶 `ext:ticket-redeem:{ip}` + 独立阈值键（P0-2 定案）**

- 共享桶（`ext:ticket:{ip}`）问题：兑票（轻操作，DMP 高频业务面）与登录（重操作，编排+签发）互相挤占配额——一端被刷暴力试探，另一端业务受损；
- 独立桶：各自独立配额，防一端拖死另一端；IP 维度纵深防御语义不变；
- 代价：整体防刷力度拆分为两桶（暴力试探面扩大一倍）——32B 高熵票不可枚举，纵深已足够，接受。

**P0-2 闭环记录（2026-11-11 Oracle 评审确认）——关键语义变化：服务间调用 IP 集中**：

- 既有 `ext:ticket:{ip}` 面向 SPA 浏览器直连（IP 分散 = 终端粉丝 IP，10/min/IP 合理）；新端点消费方是 **DMP Merchant 后端服务间调用**，频控 IP = DMP 服务器出口 IP（集中）——复用 `TicketRedeemPerMinutePerIp`（10/min）会把「每用户配额」退化为「每 DMP 后端实例配额」，营销图文推送后点击洪峰易 429 误伤正常粉丝（与 E1 目标冲突）。
- **定案**：新增独立领域阈值键 **`LoginProtectionOptions.TicketRedeemServicePerMinutePerIp`**（默认 **60/min/IP**——登录桶的 6 倍，服务间调用纵深防重试风暴语义；`TKWF:AuthCenter:LoginProtection` 节，运维可独立调优，不联动登录桶）。容量假设标注于使用指南：**DMP 单出口 IP 兑票峰值 < 60/min**，超出按配置键调优。
- 若 DMP 确认其峰值远低于 60/min/IP，维持默认即可；频控真实意义 = 防 DMP 侧故障重试风暴 + DoS 纵深，非业务限流（DMP 业务侧自有限流）。

### R3：L2 状态检查路径 —— 本方案裁决：PlatformUid 直读 → 反查 fallback（含 miss fallthrough + 二跳链）→ 无账号放行

- ① **无账号放行**（Oracle 确认成立）：兑票 = 「读票面」，票本身（验签 + CAS 单次 + null-claimant 约束）即身份断言；账号态检查是**增值守卫**（仅「有账号」时拒绝冻结/禁用，防冻结用户借免登通道继续交互），建号归 DMP register/编排面——不建号、零副作用成立；
- ② **检查顺序**（Oracle 确认成立）：先 IsEnabled → ACCOUNT_DISABLED，后 IsFrozenAsync → ACCOUNT_FROZEN，与 `FederatedLoginOrchestrator` L70-73/L125-126 实证同序；
- ③ **反查签名**（Oracle 逐签核实）：`IExternalIdentityService.GetByExternalIdAsync(string channelId, string externalUserId, ct)` → `ExternalIdentityDto?`（含 UId）；底层 `IAuthFactorService` 同签名（Federated 因素 Identifier = `{channelId}|{externalUserId}`）；`GetByUIdAsync` → `AuthAccountEntity?`；`IFreezeStateProvider.IsFrozenAsync(uid, scope?, ct)`——全部可用；
- ④ **实现澄清（P2-1 吸收，§2.4 已写）**：直读 miss → fallthrough 反查；反查命中 → 二跳 `GetByUIdAsync` 取账号行（`ExternalIdentityDto.UId`）——测试②断言完整链。
