# v0.3.0 — AuthCenter.Abstractions 契约包门面提取开发方案（v0.2，评审条件已闭环）

> 状态：**方案评审 PASS WITH CONDITIONS（Oracle2，2026-11-20）——9 条缺陷（3 高）已逐条闭环并修订**；按 AGENTS §3 步骤 3，修订稿即实施输入。
> 来源：EduPlatform 反馈 B1/B2 核实裁定（Oracle7）`docs/转告/2026-11-20-B1B2三方处置转告.md`；Oracle2 评审裁定见 §九。
> 关联：`ADR-AuthCenter-身份域数据模型与密码能力边界`（既有）、`G17A §7.6/7.8`（契约型按需创建）、`G17B §10.2`（按形态引用）。

## 一、目的与目标

把 EduPlatform 实际消费的 AuthCenter 登录/票据门面从主包提取进**已存在的** `TKWF.Ext.AuthCenter.Abstractions`（V0.2.0 → V0.3.0 minor），使消费方可以按"契约型成对引用"通过 `User.Use<I门面>()` 消费契约，不再被"契约在主包"结构性阻塞，为消费方删除进程内 stand-in（AuthRelayRegistry / AuthTicketLoginService）提供结构前提。三句话目标态：

1. 契约包含 EduPlatform 12 处 F-06 TODO 中 **AuthCenter 侧 3 处**调用点（AuthRelayRegistry.cs:5 / AuthTicketLoginService.cs:7 / EduPlatformUserHelper.cs:33）对应的票据/密码登录门面与 wire DTO；其余 9 处为 AuthSurface 侧（自包含型，A6 禁止建包，不在本方案）；EduPlatformUserHelper 的明文凭据校验需求由后续专项方案承接（见 §四.2 决策 2），本迭代不关闭该 TODO；
2. 主包实现不变、namespace 不变（`TKWF.Ext.AuthCenter`），消费方引用形态随其边界口径决议（两条合法路径均兼容，见 §三 场景 1）；
3. 门面契约语义明确"先认证后断言"（B2 安全节），fail-closed 不削弱。

## 二、问题

- **债务实证**：EduPlatform 11 处 `F-06 缺 Abstractions` 字面 TODO + 1 处变体（RedeemVoucherService.cs:66），其中 AuthCenter 侧集中在 AuthRelayRegistry / AuthTicketLoginService / EduPlatformUserHelper（AdminUserDetailService 为 AuthSurface 侧，不在 AuthCenter 范围）；3 组进程内 stand-in 之一（AuthRelayRegistry）即认证中转全状态桩。
- **现有方案不足**：`AuthCenter.Abstractions` 已发布 V0.2.0（**5 契约**：IExternalIdentityService / IExternalIdpAuthenticator / IExternalIdentityProvisioningService / ISsoAccountQueryService / IWeakIdentityCleanupService + DTO），**不含**登录门面；`IPasswordLoginService.cs:20`、`IExternalTicketLoginService.cs:27` 仍在主包，消费方按 A6 契约型"成对引用"时无法只依赖契约包消费登录能力。
- **安全背景**：P1-1 前的 fail-open 形态（匿名 `/api/auth/login` + 按 UId 映射授角色 = 任意密码提权）虽已由消费方个案修复，但根因（凭据校验与身份断言解耦）靠自觉——契约语义与机械断言需随本次提取固化（B2）。

## 三、使用场景

| 场景 | 口径 |
|---|---|
| 消费方（EduPlatform）经契约包调用登录/票据门面 | `User.Use<IExternalTicketLoginService>()` 等；引用形态随消费方边界口径决议（路径 a：Domain 只引契约包〔修订 ExtensionBoundaryTests/ADR03〕；路径 b：Web/装配层成对引用 + Domain 本地端口）——本方案只提供结构前提，不预设路径 |
| 消费方 UserHelper 需要"凭据校验"而非完整登录编排 | **不在本方案**：明文凭据校验契约（EduPlatformUserHelper OnLoginByPasswordAsync 调用点）另立专项方案设计（须自带频控/尝试记录/防枚举/fail-closed 语义，经独立安全评审）；本方案只迁移既有门面 + wire DTO，零新 API |
| AuthCenter 主包端点生成（`MapGenerated` / `[ApiExpose]`） | 接口移入契约程序集后须仍被主包编译期拾取；AuthCenter 全量用例 + 端点冒烟锁定（见 §六） |
| **不适用** | AuthSurface 门面（已裁定自包含型，禁止建 Abstractions——见 G17A §7.8 / ADR03:42）；本方案只处理 AuthCenter 既有契约包内容演进，不触发形态升格 |

## 四、决策（评审闭环后定案）

1. **载体**：既有 `TKWF.Ext.AuthCenter.Abstractions` V0.2.0 → **V0.3.0**（MinVerTagPrefix `AuthCenter.Abstractions/v`，独立 tag，须用户同意；本方案不自行打 tag）。
2. **提取候选（评审定案）**：
   - `IExternalTicketLoginService`（票据换登录，验票→编排）——EduPlatform AuthTicketLoginService 调用点对应；
   - `IPasswordLoginService`（密码登录全编排）——EduPlatform PasswordLoginService 调用点对应；明文凭据校验钩子另立专项（见场景 2）；
   - `IExternalTicketRedeemService`：**默认排除**（无点名消费调用点——EduPlatform 12 处 TODO 无一对应业务兑票；DMP-Lite 经 REST 端点消费不经契约包；按 G17A §7.8 判据反推 YAGNI + 匿名面最小化）；若盘点找到具体调用点（点名文件:行号）则保留并在 ADR 记录依据；
   - wire DTO 随迁：`PasswordLoginRequest`（EndpointContracts.cs:42）/ `ExternalTicketLoginRequest`（:62）/ `TokenResponse`（:16）；若 IExternalTicketRedeemService 经上条保留则同步迁 `ExternalTicketRedeemRequest`（:79）；Federated 系列（`FederatedTicketPayload` 已在 Federation.Abstractions，契约包已依赖，零新增依赖）；
   - **范围裁定（评审定案）**：v0.3.0 = 纯迁移（门面按上述清单 + 对应 wire DTO，主包实现与行为零改动）；若 EduPlatform 盘点后确需凭据校验专用契约，另立 v0.4.0 专项方案，不并入本迭代。
3. **零破坏约束与引用接线**：namespace 保持 `TKWF.Ext.AuthCenter`（先例 Federation/SecurityLog/WeChatChannels.Abstractions）。属性来源更正：`[AllowAnonymousFlag]` 来自 TKWF.Domain（`TKW.Framework.Domain.Interception.Filters`，契约包现有依赖承载）；`[ApiExpose]` 来自 **`TKWF.CodeGeneration.Abstractions`** 包（命名空间 `TKW.Framework.CodeGeneration`）——契约包 csproj 须新增条件引用（NuGet 模式 `<PackageReference Include="TKWF.CodeGeneration.Abstractions" Condition="'$(UseLocalFw)' != 'true'"/>` + DLL 模式 `<Reference Include="TKWF.CodeGeneration.Abstractions" HintPath="$(_LocalFwRefsDir)TKWF.CodeGeneration.Abstractions.dll" .../>`，版本随 CPM lockstep 纪律，对齐主包 csproj 先例；不引 `TKWF.CodeGeneration` 纯 Analyzer 包、不引 AspNetCore）。接口 XML doc 中指向主包内部类型的 cref（PasswordAuthenticationProvider/AuthTypes/IFederatedLoginOrchestrator/LoginProtectionOptions 等）改为纯文字描述（防 CS1574 未解析 cref 告警）。须验证 MapGenerated 跨程序集拾取契约包接口不回归（见 §六 端点冒烟）。
4. **ADR**：契约包内容/接口签名变更属 ADR 场景（`docs/AuthCenter/ADR/ADR-AuthCenter-契约包门面提取.md`，三问必填），与方案同迭代交付。
5. **安全节（B2）**：门面契约必须"先认证后断言"——登录门面内既有编排顺序（认证 Provider → 取账号 → 签发）不因迁移改变；凭据校验类契约 = 校验失败 false/异常、绝不成功返回；主包实现零改动，安全语义由文档 + 测试锁定（不引入匿名端点一刀切角色守卫——见转告单一）。
6. **不在本方案**：AuthSurface 契约包（A6 禁止）；凭据校验专用契约（另立专项，独立安全评审）；`IExternalTicketRedeemService` 迁移（待点名调用点）；`ISmsLoginService`/`SmsLoginRequest` 纳入与否（EduPlatform SmsLoginService 无 F-06 TODO，短信登录暂留本地/走 AuthCenter REST 端点，默认排除）；消费方 stand-in 删除与会话架构切换（消费方组）；框架侧钩子契约文档化（转告框架组）；CPM lockstep（仓库级例行，本方案 L0 前置——已于 2026-11-20 跟至 4.10.132/4.10.132-local）。

## 五、备选方案

| 方案 | 放弃原因 |
|---|---|
| 新建 `AuthCenter.Abstractions.V2` 独立包 | 契约型已成立且已有活跃消费方（Federation）；存量包内 minor 演进零 using 迁移，新包徒增版本面 |
| 消费方 Domain 直接引主包 | 违反 ADR03/ExtensionBoundaryTests（Domain 零 `TKWF.Ext.*` 引用为骨架期回归契约；测试实断言含 `.Abstractions`，已核验） |
| 为 AuthSurface 也建 Abstractions | 违反 A6 裁定（终端应用不算跨扩展消费方；空包=禁止的第三形态） |

## 六、验证与交付（评审修正版）

- **L0（编译门）**：slnx 构建 0 错误（DLL 模式；前置：CPM 与 local-feed 版本对齐可 restore——已跟至 4.10.132/4.10.132-local）；NuGet 模式（`-p:UseLocalFw=false`）待框架 CPM 锁定版本上架 nuget.org 后复验。
- **L1（受影响面定向）**：
  1. AuthCenter 全量用例全绿（含 `AnonymousSurfaceTests` E1 匿名面正/负锁、`AuthCenterInitializerTests` 门面注册断言；计数以运行结果为准，不硬编码）；
  2. Federation 全量用例全绿（活跃契约消费方——受影响面矩阵"契约包变更"）；
  3. **端点冒烟（MapGenerated 跨程序集拾取）**：`AuthCenterWebExtensionTests` 既有 `POST /login/ticket`（V0.10.0 段）与 `POST /login/ticket/redeem`（V0.14.0 段）保持绿；**随本迭代新增 `POST /login/password` 端点冒烟 1 条**（成功 200 + 失败 400 断言，补齐当前仅服务级测试的缺口）；迁移前先跑基线，迁移后同断言全绿。
- **L2（契约包变更触发）**：48 测试项目全量回归（slnx 实测 48，发布/tag 前完成）。
- **机械验收**：① 契约包 nuspec 含迁移门面与 wire DTO（按 §四.2 裁定清单），主包 `EndpointContracts.cs` 对应类型删除、残留引用清零；② 消费方视角仅改 csproj 引用（namespace 不变、using 零改动）——以主包/测试项目引用契约包编译实证；③ 契约包依赖变化白名单：仅新增 `TKWF.CodeGeneration.Abstractions` 条件引用（版本随 CPM lockstep 纪律），TFM 不变 net10.0，此外零新增框架/第三方依赖；④ wire JSON 键名不回归：`TokenResponse_SerializesDocumentedSnakeCaseKeys` 及双收绑定用例保持绿；⑤ `grep -rn "ToEntity not implemented"` 类债务仅基线记录（与本方案正交）。
- **消费方联动验收（非本仓，前置决议）**：EduPlatform 边界口径决议落档 → 切真门面 → 删 stand-in → BR-1-11-01（AuthLoginServiceTests.cs:112-135）保持绿。
- **交付收尾**：按 AGENTS §3 步骤 5-7 交付 ADR（三问必填）、code-reviewer 审核、更新主框架总览与跟踪。

## 七、风险与回滚

| 风险 | 处置 |
|---|---|
| 接口移至契约包后 SG1b/SG2a 端点生成失效 | AuthCenter 全量用例 + 端点冒烟（含新增 `/login/password`）在 L1 锁定；失败则回退该接口迁移（保留在主包），其余独立提交 |
| wire DTO 跨程序集序列化字段名变化 | namespace 不变 + 请求/响应类型整体迁移（非拆分），以 `TokenResponse_SerializesDocumentedSnakeCaseKeys` 等端点契约用例锁定 |
| 契约包依赖膨胀 | 仅新增 `TKWF.CodeGeneration.Abstractions` 条件引用（§四.3 白名单）；其他新增依赖须方案修订后重审 |
| 消费方边界测试与契约包引用冲突 | 消费方先决议边界口径（转告单 §二.1）；决议前不删 stand-in |
| NuGet 模式 restore/CI 与契约包在线发布依赖框架上架 | 框架 4.10.122~132 已 tag 未上架；本地仅 DLL 模式验证，NuGet 模式（`-p:UseLocalFw=false`）与在线发布（须用户同意 tag + workflow_dispatch）待框架上架通知后执行（AGENTS §6 铁律） |
| local-feed/CPM 版本错位（feed 曾仅存新 -local，CPM 未跟） | L0 前置：确认 restore 可解析；本批已跟至 4.10.132/4.10.132-local，后续框架部署时同步跟进 |

**回滚**：契约包 minor 发布独立提交；单接口迁移回退不影响其他接口；tag 未打前可任意回退包内容。
