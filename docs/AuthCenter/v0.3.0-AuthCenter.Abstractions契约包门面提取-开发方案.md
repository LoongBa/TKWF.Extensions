# v0.3.0 — AuthCenter.Abstractions 契约包门面提取开发方案（v0.3，实施阻断后机制修订——契约基接口模式，重审通过并已实施）

> 状态：**v0.2 评审 PASS WITH CONDITIONS 9 条已闭环；v0.3 实施首轮命中阻断（MapGenerated 程序集不变量）→ 机制改为契约基接口模式（Oracle5 裁定）→ 重审通过 + 2026-11-20 实施闭环 + code-reviewer PASS WITH CONDITIONS（P1×3 已闭环）**。
> 来源：EduPlatform 反馈 B1/B2 核实裁定（Oracle7）`docs/转告/2026-11-20-B1B2三方处置转告.md`；Oracle2 评审裁定见 §九。
> 关联：`ADR-AuthCenter-身份域数据模型与密码能力边界`（既有）、`G17A §7.6/7.8`（契约型按需创建）、`G17B §10.2`（按形态引用）。

## 一、目的与目标

为 EduPlatform 实际消费的 AuthCenter 登录/票据能力**提供契约基接口**（业务签名 + wire DTO）进**已存在的** `TKWF.Ext.AuthCenter.Abstractions`（V0.2.0 → V0.3.0 minor）；端点承载门面**仍留主包**（MapGenerated 程序集不变量——见 §二），使消费方可经 `User.Use<I门面Contract>()` 只依赖契约包消费，不再被"契约在主包"结构性阻塞，为消费方删除进程内 stand-in（AuthRelayRegistry / AuthTicketLoginService）提供结构前提。三句话目标态：

1. 契约包含 EduPlatform 12 处 F-06 TODO 中 **AuthCenter 侧 3 处**调用点（AuthRelayRegistry.cs:5 / AuthTicketLoginService.cs:7 / EduPlatformUserHelper.cs:33）对应的**票据/密码登录契约基接口**（`IExternalTicketLoginServiceContract` / `IPasswordLoginServiceContract`）与 wire DTO；其余 9 处为 AuthSurface 侧（自包含型，A6 禁止建包，不在本方案）；EduPlatformUserHelper 的明文凭据校验需求由后续专项方案承接（见 §四.2 决策 2），本迭代不关闭该 TODO；
2. 主包实现不变、namespace 不变（`TKWF.Ext.AuthCenter`），消费方引用形态随其边界口径决议（两条合法路径均兼容，见 §三 场景 1）；
3. 门面契约语义明确"先认证后断言"（B2 安全节），fail-closed 不削弱。

## 二、问题

- **债务实证**：EduPlatform 11 处 `F-06 缺 Abstractions` 字面 TODO + 1 处变体（RedeemVoucherService.cs:66），其中 AuthCenter 侧集中在 AuthRelayRegistry / AuthTicketLoginService / EduPlatformUserHelper（AdminUserDetailService 为 AuthSurface 侧，不在 AuthCenter 范围）；3 组进程内 stand-in 之一（AuthRelayRegistry）即认证中转全状态桩。
- **现有方案不足**：`AuthCenter.Abstractions` 已发布 V0.2.0（**5 契约**：IExternalIdentityService / IExternalIdpAuthenticator / IExternalIdentityProvisioningService / ISsoAccountQueryService / IWeakIdentityCleanupService + DTO），**不含**登录门面；`IPasswordLoginService.cs:20`、`IExternalTicketLoginService.cs:27` 仍在主包，消费方按 A6 契约型"成对引用"时无法只依赖契约包消费登录能力。
- **安全背景**：P1-1 前的 fail-open 形态（匿名 `/api/auth/login` + 按 UId 映射授角色 = 任意密码提权）虽已由消费方个案修复，但根因（凭据校验与身份断言解耦）靠自觉——契约语义与机械断言需随本次提取固化（B2）。

## 三、使用场景

| 场景 | 口径 |
|---|---|
| 消费方（EduPlatform）经契约包调用登录/票据门面 | `User.Use<IExternalTicketLoginServiceContract>()` 等；引用形态随消费方边界口径决议（路径 a：Domain 只引契约包〔修订 ExtensionBoundaryTests/ADR03〕；路径 b：Web/装配层成对引用 + Domain 本地端口）——本方案只提供结构前提，不预设路径 |
| 消费方 UserHelper 需要"凭据校验"而非完整登录编排 | **不在本方案**：明文凭据校验契约（EduPlatformUserHelper OnLoginByPasswordAsync 调用点）另立专项方案设计（须自带频控/尝试记录/防枚举/fail-closed 语义，经独立安全评审）；本方案只迁移既有门面 + wire DTO，零新 API |
| AuthCenter 主包端点生成（`MapGenerated` / `[ApiExpose]`） | 主包门面继承契约基接口后，SG1b 端点生成仍拾取主包门面（`[ApiExpose]` 留主包）；AuthCenter 全量用例 + 端点冒烟锁定（见 §六） |
| **不适用** | AuthSurface 门面（已裁定自包含型，禁止建 Abstractions——见 G17A §7.8 / ADR03:42）；本方案只处理 AuthCenter 既有契约包内容演进，不触发形态升格 |

## 四、决策（评审闭环后定案）

1. **载体**：既有 `TKWF.Ext.AuthCenter.Abstractions` V0.2.0 → **V0.3.0**（MinVerTagPrefix `AuthCenter.Abstractions/v`，独立 tag，须用户同意；本方案不自行打 tag）。
2. **提取候选（评审定案）**：
   - `IExternalTicketLoginServiceContract`（票据换登录业务签名）——主包 `IExternalTicketLoginService` 继承之并 `new` 重声明带 `[ApiExpose]` 的端点方法（签名与标记原文照抄（含 `ct = default`））；
   - `IPasswordLoginServiceContract`（密码登录业务签名）——主包 `IPasswordLoginService` 继承之并 `new` 重声明端点方法；明文凭据校验钩子另立专项（见场景 2）；
   - `IExternalTicketRedeemService`：**默认排除**（无点名消费调用点——EduPlatform 12 处 TODO 无一对应业务兑票；DMP-Lite 经 REST 端点消费不经契约包；按 G17A §7.8 判据反推 YAGNI + 匿名面最小化）；若盘点找到具体调用点（点名文件:行号）则保留并在 ADR 记录依据；
   - wire DTO 随迁：`PasswordLoginRequest`（EndpointContracts.cs:42）/ `ExternalTicketLoginRequest`（:62）/ `TokenResponse`（:16）；若 IExternalTicketRedeemService 经上条保留则同步迁 `ExternalTicketRedeemRequest`（:79）；Federated 系列（`FederatedTicketPayload` 已在 Federation.Abstractions，契约包已依赖，零新增依赖）；
   - **范围裁定（v0.3 修订）**：v0.3.0 = 契约基接口 + wire DTO 增量（**门面端点面留主包**，主包实现/端点行为零改动）；Initializer 增 2 行 `AddConstructibleService<I*Contract, *Service>()`（对齐 AuthCenterExtensionInitializer.cs:115/171 既有先例）；若 EduPlatform 盘点后确需凭据校验专用契约，另立 v0.4.0 专项方案，不并入本迭代。
3. **零破坏约束（v0.3 修订）**：namespace 保持 `TKWF.Ext.AuthCenter`；契约基接口继承 `IDomainService`（既有 5 契约同形态，`User.Use` 帧内解析准入）并只承载业务签名（返回 wire DTO）+ `[AllowAnonymousFlag]`（TKWF.Domain 既有依赖承载），**不带 `[ApiExpose]`**——`[ApiExpose]`/`[AllowAnonymousFlag]` 端点标记留在主包门面的 `new` 重声明方法上（SG1b `CollectInterfaceMethodApiExpose` 只读门面自有成员，主包门面不被迁移）。**契约包依赖零变化**（D3 原 `TKWF.CodeGeneration.Abstractions` 条件引用随机制修订删除）。接口 XML doc 中指向主包内部类型的 cref 改为纯文字（防 CS1574）。端点路径/组前缀零变化（`facadeType.Assembly` 仍为主包，含 `[ExtensionModule]`）。
4. **ADR**：契约包内容/接口签名变更属 ADR 场景（`docs/AuthCenter/ADR/ADR-AuthCenter-契约包门面提取.md`，三问必填），与方案同迭代交付。
5. **安全节（B2）**：门面契约必须"先认证后断言"——登录门面内既有编排顺序（认证 Provider → 取账号 → 签发）不因迁移改变；凭据校验类契约 = 校验失败 false/异常、绝不成功返回；主包实现零改动，安全语义由文档 + 测试锁定（不引入匿名端点一刀切角色守卫——见转告单一）。
6. **不在本方案**：AuthSurface 契约包（A6 禁止）；凭据校验专用契约（另立专项，独立安全评审）；`IExternalTicketRedeemService` 迁移（待点名调用点）；整接口（带 [ApiExpose]）迁契约包（MapGenerated 三处程序集身份链阻断——见 §十，已转告框架组）；`ISmsLoginService`/`SmsLoginRequest` 纳入与否（EduPlatform SmsLoginService 无 F-06 TODO，短信登录暂留本地/走 AuthCenter REST 端点，默认排除）；消费方 stand-in 删除与会话架构切换（消费方组）；框架侧钩子契约文档化（转告框架组）；CPM lockstep（仓库级例行，本方案 L0 前置——已于 2026-11-20 跟至 4.10.132/4.10.132-local）。

## 十、实施阻断实证与机制修订（v0.3，Oracle5 裁定）

**阻断现象（2026-11-20 实施首轮）**：按 v0.2 把带 `[ApiExpose]` 的门面整体迁入契约包后，slnx 构建 0 错误，但 AuthCenter 端点测试全部启动失败：
`扩展程序集 [TKWF.Ext.AuthCenter.Abstractions] 未声明 [ExtensionEndpointRegistrations] 程序集特性，无法为门面 [TKWF.Ext.AuthCenter.IPasswordLoginService] 映射端点`。

**根因（框架机制不变量，非 bug）**：`DefaultExtensionEndpointRegistry.cs:167` `var assembly = facadeType.Assembly;` → `:238-243` ResolveMap 在该程序集找 SG1b 发射的 `[ExtensionEndpointRegistrations]`（缺失即 fail-closed）；该特性由含 `[GenerateController]` 实现类的编译产出（`ControllerGenerator.cs:1432/:1440-1477`），纯契约包按 G17A §7.8 永不产出。更深的地雷：路由组与模块前缀同样按门面程序集取键（`:80/:189-198/:220-231`，主包有 `[assembly: ExtensionModule("AuthCenter","auth")]`，契约包没有）——只修 ResolveMap 会导致路由静默从 `/api/auth/*` 漂移为 `/api/*`。WeChatChannels v0.9.0 曾撞同型墙（code-reviewer BLOCKER，以"非 Web 形态"绕开）。
