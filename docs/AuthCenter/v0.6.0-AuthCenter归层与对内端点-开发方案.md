## 一、背景与目标

### 问题

1. **名分两包**：配置节已命名 `TKWF:AuthCenter`、类名已是 `AuthCenterExtensionInitializer`/`AuthCenterOptions`——但**包名/命名空间/目录/MinVerTagPrefix 仍是 Authentication**（102 个 .cs 全量 `namespace TKWF.Ext.Authentication`），契约包 `Authentication.Abstractions` 命名空间刻意保持旧名（README 明载）——归层模型落地不完整。
2. **对内端点缺失**：认证中心 = 对内认证中心，但认证协议端点（登录/refresh/logout/票据换令牌/验证码）**零内建**——`JwtAuthenticationWebExtension` 只挂中间件（无 `ConfigureEndpoints`），REST 端点由消费方自写控制器（EduPlatform 先例）——**职责分工违背**（Federation 有 `/sso/*` 对外端点，AuthCenter 无对内端点，不对称）。
3. **路径不可配置**：`JwtAuthenticationOptions` 仅 `RejectInvalidToken`（无 `[Options]`、无配置节）——"认证中心对内路径可配置"无承载对象（AGENTS §8 配置分层倒查待办正命中此处）。
4. **不一致点**：`[TKWFExtension("Authentication")]` + `Name => "Authentication"` 仍用旧名（类名已 AuthCenter）。

### 目标

1. **全面归层（零折中）**：`TKWF.Ext.Authentication` → `TKWF.Ext.AuthCenter`（包名/命名空间/目录/MinVerTagPrefix/测试项目/xCodeGen/IVT/docs）+ 契约包统一归层 `AuthCenter.Abstractions`（命名空间同步）+ Federation 消费方同步——**不做 TypeForwardedTo/deprecated**。
2. **内建标准对内端点**：`AuthCenterWebExtension`（`JwtAuthenticationWebExtension` 归层更名）`ConfigureEndpoints` 内建认证协议端点（短信验证码/短信登录/微信登录/refresh/logout/票据换令牌），**路径可配置**（`AuthCenterEndpointOptions` `TKWF:AuthCenter:Web`：`RoutePrefix` + 端点开关）。
3. **配置分层落地**：领域决策（能力开关/安全策略/生命周期）留在 `AuthCenterOptions`（`TKWF:AuthCenter`，**不动**）；表现层暴露面（路由前缀/端点映射开关）进 `AuthCenterEndpointOptions`（`TKWF:AuthCenter:Web`，POCO 不镜像领域配置）；中间件行为独立 `AuthCenterMiddlewareOptions`（`RejectInvalidToken`）——领域安全行为 Web 层不可关闭。
4. **表现层零编排（Oracle P0-1 修订）**：登录门面升级——`ISmsLoginService`/`IWechatLoginService` 返回 `LoginResult`（门面内完成 认证→取账号→签发 全编排），端点只调一个门面，不串多门面。

### 5.2 配置分层（AGENTS §8 落地 + Oracle P0-2/P1-4 修订）

```
领域决策（TKWF:AuthCenter —— AuthCenterOptions，不动）
├── 能力开关：EnabledAuthTypes（sms/wechat）——fail-closed（默认 ["sms"]）
├── 安全策略：LoginProtection 7 阈值 / RedirectUriWhitelist / 密钥路径
├── 令牌生命周期：Access 2h / Long-lived 7d / Refresh 30d / Ticket 5min
└── fail-fast 门：Issuer / SigningKeyPath / IsProduction

中间件行为（AuthCenterMiddlewareOptions —— 独立 POCO，归层更名）
└── RejectInvalidToken（无效令牌短路 401 vs 放行后续认证）——中间件管线行为，
    非领域安全策略、非暴露面——不进 Web Options（防双源/混淆）

表现层暴露面（TKWF:AuthCenter:Web —— AuthCenterEndpointOptions，新增）
├── RoutePrefix（默认 /api/auth）
├── 端点开关：SmsSendCodeEndpoint / SmsLoginEndpoint / WechatLoginEndpoint /
   RefreshEndpoint / LogoutEndpoint / TicketExchangeEndpoint（默认 true，Endpoint 后缀明确是暴露面开关）
└── 中间件锚点（继承 IWebExtension 默认 BeforeAuthentication）
```

**安全红线**：
1. Web Options **不存在** `EnabledAuthTypes` 对应开关（防"Web 层关掉短信频控/口令校验"绕过）；`RejectInvalidToken` 不进 Web Options（中间件行为独立承载）
2. 端点开关只控 **HTTP 暴露面**——关闭端点不改变领域能力（领域服务仍可被消费方自写端点/门面直调）
3. **端点暴露 vs 领域未启用的交互语义（P1-4 明确）**：端点开关默认 true = 暴露面默认开放；若领域 `EnabledAuthTypes` 未启用对应 Provider（如 wechat 未列入）→ 端点暴露但调用时**领域层 fail-closed 拒绝**（安全由领域控制，不依赖表现层开关）——这是分层的正确语义：表现层可暴露端点，领域不工作即失败，**非不一致状态**；指南标注此预期
4. 两类配置解耦可测：领域配置变更影响行为（Domain 层测试锁定）；Web 配置变更只影响路由/暴露面（Web 冒烟锁定——"领域服务仍可用"经 `TestServer.Services.GetRequiredService<ISmsLoginService>()` 直调门面正向断言）

### 5.3 登录门面升级（T3——Oracle P0-1 修订，表现层零编排）

**新契约**（破坏性变更——无外部消费方零折中）：

```csharp
public sealed record LoginResult(
    bool Success,
    TokenIssueResult? Token,        // Success=true 时含完整签发结果
    string? FailReason);             // Success=false 时透传 ProviderAuthenticateResult.FailReason

public interface ISmsLoginService : IDomainService {
    [AllowAnonymousFlag] Task<LoginResult> LoginAsync(string phone, string code, CancellationToken ct = default);
}
public interface IWechatLoginService : IDomainService {
    [AllowAnonymousFlag] Task<LoginResult> LoginAsync(string wechatCode, string wechatScope, CancellationToken ct = default);
}
```

**门面内编排**（`SmsLoginService`/`WechatLoginService` 升级）：
1. `Provider.AuthenticateAsync`（现有——注入 `IEnumerable<IAuthenticationProvider>` 帧内选区）
2. 成功 → `IAuthAccountQueryService.GetByUIdAsync(result.UserId)`（取 `TeacherVerified`/`AuthLevel`——ctor 注入，守卫工厂帧内解析）
3. `ITokenService.IssueTokenAsync(new TokenIssueRequest(userId, AuthTypes.Sms, (int)authLevel, teacherVerified))`（ctor 注入）
4. 失败 → `LoginResult(false, null, FailReason)` 透传

**端点只调一个门面**：`guest.Use<ISmsLoginService>().LoginAsync(phone, code)` → `LoginResult` 转 `TokenResponse`/错误——**不再端点内串多门面**（V0.5.0 零编排原则保持）。

### 5.4 `AuthCenterWebExtension<TUserInfo>` 端点设计（T4）

**类形态**（`JwtAuthenticationWebExtension` 更名 + 扩展职责）：

```csharp
public sealed class AuthCenterWebExtension<TUserInfo> : IWebExtension
    where TUserInfo : class, IUserInfo, new()
{
    public Func<HttpContext, TokenValidationResult, Task<DomainUser<TUserInfo>>>? RestoreUser { get; set; }
        // 既有委托，传给 JwtAuthenticationMiddleware（中间件不变）
    public Action<AuthCenterEndpointOptions>? ConfigureOptions { get; set; }
        // 编程式配置（后于配置节 TKWF:AuthCenter:Web 应用）
    public Action<AuthCenterMiddlewareOptions>? ConfigureMiddlewareOptions { get; set; }
        // 中间件行为 Options（归层更名后，RejectInvalidToken）

    ConfigureServices: AddOptions<AuthCenterMiddlewareOptions>() + Configure(ConfigureMiddlewareOptions)
                     + AddOptions<AuthCenterEndpointOptions>() + Configure(ConfigureOptions)
    ConfigureMiddleware: UseMiddleware<JwtAuthenticationMiddleware<TUserInfo>>(RestoreUser)  // 锚点不变
    ConfigureEndpoints: ResolveOptions(endpoints.ServiceProvider)（三段兜底）→ RoutePrefix + 端点开关 → 映射 minimal API
}
```

**端点明细**（`{prefix}` = `RoutePrefix`，默认 `/api/auth`）：

| 端点 | 方法/路径 | 请求 | 响应 | 领域调用（AOP 帧内，**单门面**） | 错误映射 |
|------|----------|------|------|---------------------|---------|
| 短信验证码 | `POST {prefix}/sms/send-code` | `{ phone, scene }`（scene 白名单：Login/Register/Bind/Reset——P2-3 校验） | `204` | `guest.Use<ISmsVerificationService>().SendCodeAsync(phone, scene)` | 400（参数/scene 非法）· 429（频控）· 503（无 ISmsSender） |
| 短信登录 | `POST {prefix}/login/sms` | `{ phone, code }` | `TokenResponse` | `guest.Use<ISmsLoginService>().LoginAsync(phone, code)`（门面内全编排） | 400（错码/FailReason）· 429（频控） |
| 微信登录 | `POST {prefix}/login/wechat` | `{ code, scope }` | `TokenResponse` | `guest.Use<IWechatLoginService>().LoginAsync(code, scope)` | 400（code 无效）· 401 |
| 刷新 | `POST {prefix}/refresh` | `{ refresh_token }` | `TokenResponse` | `guest.Use<ITokenService>().RefreshTokenAsync(refreshToken)` | 400（invalid/revoked） |
| 登出 | `POST {prefix}/logout` | Bearer + `{}` | `204` | `user.Use<ITokenService>().RevokeTokenAsync(jti, "logout")`（已认证帧；jti 从中间件写入 Items 的 `TokenValidationResult` 取——见下） | 401 |
| 票据换令牌 | `POST {prefix}/ticket/exchange` | `{ ticket, code_verifier, app_id, state }` | `TokenResponse`（`OAuthTicketExchangeResult` 字段转换） | `guest.Use<IOAuthTicketService>().ExchangeAsync(...)` | 400（TICKET_EXPIRED/CONSUMED/STATE_MISMATCH） |

**TokenResponse DTO**（新建，Web 层语义）：`{ access_token, refresh_token, token_type = "Bearer", expires_in }`——转换源：`TokenIssueResult` / `TokenRefreshResult` / **`OAuthTicketExchangeResult`（P1-3 补）**（三者形状一致：AccessToken + RefreshToken + ExpiresIn）。

**匿名帧设计**（复用 V0.5.2 游客帧模式——装配约束延伸）：
- 登录/验证码/刷新/票据 = 匿名端点（`.AllowAnonymous()`）；handler 内经 **游客帧** 调用守卫工厂门面：`var guest = (DomainUser<TUserInfo>)httpContext.Items["DomainUser"]; await guest.Use<ISmsLoginService>()...`
- **⚠️ 装配约束（V0.5.2 延伸）**：`AuthCenterWebExtension` 须与 `UseWebSession` 同装配（ContextExtraction 阶段 2 写游客 DomainUser）——未装配 → handler 内抛守卫 = 正确 fail（README/指南标注）
- **登出 = 已认证端点**（不 AllowAnonymous）：中间件 `JwtAuthenticationMiddleware` 验签后 RestoreUser 返回已认证 `DomainUser<TUserInfo>`（替换 `Items["DomainUser"]`）——**同时将验签 `TokenValidationResult` 写入 `Items["AuthCenter.TokenValidationResult"]`**（中间件小改，T4 实施）；handler 内经 `user.Use<ITokenService>().RevokeTokenAsync(jti, "logout")`（jti = `TokenValidationResult.Jti`）

**免认证落地**：`ConfigureEndpoints` 内对 5 个匿名端点 `.AllowAnonymous()`（更内聚）；登出不加。

### 5.5 端点 Options 解析（HealthCheck 先例照搬）

```csharp
private static AuthCenterEndpointOptions ResolveOptions(IServiceProvider services)
{
    var options = services.GetService<IOptions<AuthCenterEndpointOptions>>()?.Value;   // ① IOptions
    if (options is not null) return options;
    var fallback = new AuthCenterEndpointOptions();                                    // ② IConfiguration 直读
    services.GetService<IConfiguration>()?.GetSection("TKWF:AuthCenter:Web").Bind(fallback);
    return fallback;                                                                    // ③ 默认值
}
```
