## 一、背景与目标

### 问题

`AuthAccountEntity` 是"四关切合一"的神实体（ADR 问题现象 1）：身份锚（UId/Phone）＋凭据（PasswordHash/联邦 Id）＋档案（Nickname/Avatar/TeacherVerified/AuthLevel）＋安全态（TokenVersion/IsEnabled）混居一表。四项直接后果：

| # | 后果 | 现状实证 |
|---|------|---------|
| 1 | 档案变更触碰认证关键表（锁竞争/审计噪音/迁移风险） | Nickname/Avatar 写入经 Provider 建号（`WeChatAuthenticationProvider.cs:84` 死赋值 `Nickname=null`） |
| 2 | 密码能力归属未定 | `PasswordHash` 列预留（`AuthAccountEntity.cs:39-42`）但无 Provider（`AuthTypes.Password` 扩展点未实现）、无 SetPassword/修改/找回；`IAuthLoginAttemptService.IsRateLimitedAsync` 无 `AuthTypes.Password` 分支（fail-open） |
| 3 | 双凭据存储危害（oracle8） | AuthAccount.PasswordHash vs IdentityUser.PasswordHash 两套，无桥接无迁移 |
| 4 | 业务内容漏出认证域 | `TeacherVerified` 被消费方映射业务角色（IdentityAdapterTests L114）；`AuthLevel` 枚举 3=教师核实混入认证强度；`teacher_verified` claim 随 JWT 携带 |

### 目标

1. **凭据/档案表级分离**：`AuthAccount`（凭据核心）+ `UserProfile`（基础档案 1:1，SG1 新表）——消除神实体；
2. **密码生命周期域内闭环**：`PasswordAuthenticationProvider`（验证）+ `SetPasswordAsync`（修改，TokenVersion++）+ 找回多通道（SMS/Email/扫码）；
3. **联邦 Id 归一化**：删 AuthAccount 冗余 3 列，Wechat Provider 迁 PlatformAccountMap（ChannelId+ExternalUserId）；
4. **UserCenter 退役**：V0.9.0 `[Obsolete]` + 保留实现，V1.0.0 移除。
5. **A.3-A.4**：AuthLevel 泛化（剔 3=教师核实）+ TeacherVerified 迁出（令牌不再携带）。

### 5.4 联邦迁移（T4——最复杂）

WeChat 登录流程改造（`WeChatAuthenticationProvider.cs` 重写查号/建号）：

```
现状：     code → (openId, scope) → AuthAccount.WechatMpOpenId/WechatWebOpenId 唯一查号 → 建号写列
改造后：   code → (openId, scope) → channelId = "wechat_mp"|"wechat_web" → ISsoChannelMapService.GetByChannelAsync(channelId, openId)
                                            → uid? 有槽:
                                                    │ 无 → 建号 + LinkAsync(uid, channelId, openId)
                                                    └ 并发冲突 (UX_TKWFIX_PlatformAccountMap_Channel) catch → 重查 → 现有 uid
```

- **并发兜底迁移（P1-3 修订）**：原"openid 列唯一冲突 catch → 重查"（AuthAccount L90-98）——**硬化 `PlatformAccountMapService.LinkAsync` 自身**（首选，单一职责，所有调用方受益）：catch `EntityCreateAsync` 的 UX 冲突 → 重查返回既有；**catch 须兜双索引冲突源**（`UX_PlatformAccountMap` on BusinessAppId+BusinessLocalId **AND** `UX_PlatformAccountMap_Channel` on ChannelId+ExternalUserId——LinkAsync L105-115 同时写两套列，任一 UX 冲突都须 catch）；WeChat Provider **不再自包 catch**（职责归 LinkAsync）。
- `AuthAccountEntityDataService` 删 `GetByWechatMp/WebOpenIdAsync`（L25-31）+ 生成条件 `ByUXAuthAccountWechatMp/WebOpenId`（Conditions.g.cs 重生成自然消失）。
- `IAuthAccountQueryService` 删 `GetByWechatMp/WebOpenIdAsync`（L15-16 + 实现 L43-46）。
- ⚠️ 双索引重叠决策：SSO `LinkAsync` 继续写 `BusinessAppId=channelId`/`BusinessLocalId=externalUserId`（现状保留，开发期可再裁定独立列语义）——`UX_PlatformAccountMap` 与 `UX_PlatformAccountMap_Channel` 并存（本批不动，非 AuthCenter 必须）。

### 5.6 密码 Provider + 登录门面（T6)

**`PasswordAuthenticationProvider`**（`internal sealed : DomainServiceBase, IAuthenticationProvider`，镜像 SmsAuthenticationProvider）：```csharp
public string AuthType => AuthTypes.Password;

public async Task<ProviderAuthenticateResult> AuthenticateAsync(ProviderAuthenticateContext context, ct)
{
    if (string.IsNullOrWhiteSpace(context.Identifier) || string.IsNullOrWhiteSpace(context.Password))
        return new(false, null, "PASSWORD_REQUIRED");
    var account = await DataService.GetByIdentifierAsync(context.Identifier, ct);   // UId 或 Phone（凭据角色）
    if (account is null) return new(false, null, "ACCOUNT_NOT_FOUND");
    if (!account.IsEnabled) return new(false, null, "ACCOUNT_DISABLED");
    var ok = PasswordHasher.VerifyPassword(context.Password, account.PasswordHash ?? "");
    return ok ? new(true, account.UId, null, AuthLevel.Phone)
              : new(false, null, "PASSWORD_MISMATCH");
}
```

- **Registration**：`TryAddEnumerableConstructible<IAuthenticationProvider, PasswordAuthenticationProvider>`（Initializer L135-136 追加）；`EnabledAuthTypes` 配置控启（现有 no-op 缺口——V0.9.0 一并补上过滤语义，见 §五.10）。
- **`IPasswordLoginService`**（镜像 SmsLoginService）：`LoginAsync(string identifier, string password, ...)` → 选 Password Provider → 认证 → 取账号 → 签发（TokenIssueRequest 不再含 TeacherVerified）→ `LoginResult`。
- `ProviderAuthenticateContext` 增 `string? Identifier = null`（现无——凭据标识；Phone 复用亦可但更通用）。**P2-5 确认**：record 末位增可选默认参，既有调用（`(Phone: ..., Code: ...)`/`(WechatCode: ..., WechatScope: ...)` 命名参数）不受影响（已核对 SmsLoginService L57 / WeChat Provider L49）。
- **P2-7 确认**：`PasswordHasher.HashPassword(string)`/`VerifyPassword(string,string)` 为 **static 方法**（`TKW.Framework.Utility.Cryptography`）——直接调用，无需 DI 注入，PasswordAuthenticationProvider ctor 不加依赖。
- `IAuthLoginAttemptService.IsRateLimitedAsync` 补 `AuthTypes.Password =>` 分支（现 `_ => false` fail-open）——阈值走 `LoginProtectionOptions` 新字段。

### 5.7 SetPasswordAsync（T7)

**DataService 字段级写**（ADR 89 `UpdateWhereAsync` CAS——只更新 PasswordHash + TokenVersion 原子递增，替代整实体 UpdateAsync）：

```csharp
// AuthAccountEntityDataService 增
public async Task<bool> SetPasswordHashAsync(string uid, string? passwordHash, CancellationToken ct = default)
    => await EntityUpdateWhereAsync(
        a => a.UId == uid,
        a => new AuthAccountEntity { PasswordHash = passwordHash, TokenVersion = a.TokenVersion + 1, UpdateTime = DateTime.UtcNow },
        ct);
```

- **`IAuthAccountService.SetPasswordAsync`**（门面）：
  - `SetPasswordAsync(uid, newPassword)` —— 直接设（管理员/找回流程用）；`PasswordHasher.HashPassword(newPassword)` 落列 + TokenVersion++。
  - `ChangePasswordAsync(uid, oldPassword, newPassword)` —— 验旧（`VerifyPassword` 旧 hash）+ 新 hash + TokenVersion++；验旧失败抛 `PASSWORD_MISMATCH`。
- **P1-4：顺带迁移 `IncrementTokenVersionAsync` 到 CAS**——现状（L62-68）read-modify-write（TOCTOU），与 T7 的 `SetPasswordHashAsync` 同字段（TokenVersion）两套写法不一致。改：`EntityUpdateWhereAsync(a => a.UId == uid, a => new AuthAccountEntity { TokenVersion = a.TokenVersion + 1, UpdateTime = DateTime.UtcNow }, ct)`——消除竞态。
- TokenVersion++ 联动：旧 refresh token 失效（`RefreshTokenAsync` L217 REFRESH_STALE），2h 内旧 access 有效属预期（ADR B.9 业界主流）。
