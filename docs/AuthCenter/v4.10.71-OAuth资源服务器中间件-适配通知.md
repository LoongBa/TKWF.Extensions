## ⚡ 一句话摘要

**框架 v4.10.71 新增 OAuth 资源服务器中间件三件套**（`OAuthResourceServerWebExtension`/`IDomainUserRestorer`/`IdTokenDecoder`+`JwksManager`）——独立服务可统一经框架中间件验证 AuthCenter token（token1 RS256）/Federation token2（ES256+JWKS），免 PEM 密钥分发。**扩展侧 A1 已实施**（AuthCenter token 补 aud——随 V0.9.x）。

## 一、变更总览

| 对象 | 变更前 | 变更后 |
|------|--------|--------|
| 框架（v4.10.71） | 无 OAuth 资源服务器中间件 | **`OAuthResourceServerWebExtension<TUserInfo>`**（一步装配）+ `IDomainUserRestorer<TUserInfo>`（显式注册）+ 验签引擎（aud/iss/exp 强校验 + JWKS ES256 P-256 白名单）——`TKW.Framework.Domain.Web.OAuth` |
| **AuthCenter（本扩展，A1）** | token 契约无 aud | **`AuthCenterOptions.Audience`**（`TKWF:AuthCenter:Audience`）非空时签发写 **`aud`** claim（空不写，向后兼容）——框架中间件强校验 aud 缺失 `missing_aud` 拒 |
| Federation（A3） | token2 验签需 PEM 分发 | **零代码改动**——token2 可经框架中间件 `JwksUri` 指向 `/sso/jwks` 直接验签（ES256 P-256 白名单双重强制） |

## 二、逐项适配指引

### A1·AuthCenter token 补 aud（扩展侧已实施）

```jsonc
"TKWF": { "AuthCenter": { "Audience": "dmp-api", ... } }   // 框架中间件场景必配——签发写 aud claim
```
- 配置 `TKWF:AuthCenter:Audience` 后新签发的 token 含 `aud`；**空配置不写**（既有消费方零破坏）。
- **框架中间件验证 AuthCenter token 时**：中间件 `Audiences` 须含同值。

### A2·装配序契约（特定验签器先 → 通用后）——**硬契约，顺序不可逆**

```csharp
.UseWebExtensions<MyUserInfo>(e =>
{
    e.Add<AuthCenterWebExtension<MyUserInfo>>(x => { x.RestoreUser = ...; });          // ① 特定（AuthCenter）先注册
    e.Add<OAuthResourceServerWebExtension<MyUserInfo>>(x => { x.ConfigureOptions = ...; }); // ② 通用（框架）后注册
})
```
> ⚠️ **错误序 + `RejectInvalidToken=true`（默认）** → 框架中间件先见 AuthCenter token 抛 `missing_aud` → **401 短路吞掉 AuthCenter 机会（不可逆）**。两扩展部署形态天然解耦：AuthCenter 须 `UseWebSession`；独立服务用 `UseNoSessionManager` + 仅框架中间件。

### A3·Federation token2 经框架中间件 JWKS 路径验签（零代码改动）

```csharp
x.ConfigureOptions = o => { o.Issuer = "<TrustCenter Issuer>"; o.Audiences = new[] { "<子应用 app_id>" };
    o.JwksUri = "https://<platform>/sso/jwks"; };   // Federation GET /sso/jwks——免 PEM 分发
```
- ES256 P-256 白名单双重强制（拉取侧 crv 过滤 + 验签侧 OID 单判）；ES384/EdDSA/HS256-over-JWKS 不支持。

### A4·一步装配 + IDomainUserRestorer 显式注册

```csharp
.UseWebExtensions<MyUserInfo>(e => e.Add<OAuthResourceServerWebExtension<MyUserInfo>>(x => { x.ConfigureOptions = ...; }));
builder.Services.AddScoped<IDomainUserRestorer<MyUserInfo>, MyUserRestorer>();   // ⚠️ 显式——启动期 fail-fast 校验（缺失拒绝启动）
```
- `RestoreAsync(ctx, claims, ct)` **非空返回**（不可解析必须抛——不静默匿名）；实现内**禁调 `User.Use<T>()`**（G18 §3 领域自治）。
- 配置节 `TKWF:OAuthResourceServer`：Issuer/Audiences 必填；JwksUri⊕VerificationKeyPem 二选一（或 AutoDiscoverJwksUri=true）。

### A5·WWW-Authenticate Bearer error（RFC 6750 §3）

401 响应头 `WWW-Authenticate: Bearer error="<引擎 ErrorCode>"`——客户端程序化判定：`missing_aud`/`token_expired`/`signature_verification_failed`/`invalid_curve`/`missing_kid` 等（清单见框架 `IdTokenDecoder`）。

### S2·Emailing 独立服务（框架前置已就绪）

S2 独立服务接入依赖本中间件——框架侧前置全部就绪（转达 §三 S2）；Emailing 侧按 S2 转告文档实施（独立迭代）。

## 三、破坏性变更汇总

| # | 变更 | 级别 | 适配动作 |
|---|------|------|---------|
| 1 | AuthCenter token 增 `aud`（`AuthCenterOptions.Audience` 非空时） | **非破坏**（新增 claim，空配置不写） | 框架中间件场景配 `TKWF:AuthCenter:Audience` + 中间件 `Audiences` 同值 |
| 2 | 框架中间件强校验 aud/iss/exp（缺失拒） | 框架侧（消费方按中间件文档配置） | `OAuthResourceServerOptions` 必填项满足 |
| 3 | 装配序契约（A2） | 文档契约 | 特定验签器先注册、通用后注册（不可逆） |
| 4 | 提交/发版节奏 | — | **CPM lockstep 4.10.71 正式升级后统一联动**（勿提前提交） |

**结论**：**扩展侧零强制迁移**（A1 空配置向后兼容；A2-A5 为消费方装配指引）。消费方接入框架中间件 = 新能力选用（非迁移）。
