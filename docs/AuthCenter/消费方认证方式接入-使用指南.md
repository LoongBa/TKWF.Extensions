## 一、认证方式全景与选型决策

### 1.1 主认证（第一因素——证明"你知道什么 / 你拥有什么"）

| 方式 | 归属扩展 | 端点/门面 | 适用场景 | 接入复杂度 | 详细指南 |
|------|---------|----------|---------|:---:|---------|
| 密码登录（SecurePassword 协议） | AuthCenter | `POST {prefix}/login/password`（`IPasswordLoginService`）——body `{identifier, clientHash, salt}` | 全场景通用；**服务端零明文**（客户端 PBKDF2 600k） | 中（客户端算哈希） | 认证中心指南 §V0.9.0 |
| 短信验证码（平台形态） | AuthCenter | `POST {prefix}/sms/send-code`（`{phone, scene}` 白名单）→ `POST {prefix}/login/sms`（`{phone, code}`）；独立校验 `POST {prefix}/sms/verify` | 手机号持有验证；平台内建端点开箱即用 | 低 | 认证中心指南 §核心用法 5 |
| **短信+CAPTCHA 门禁流**（2026-11 新交付） | **SmsCode + Captcha** | 消费方装配三端点：`POST /m/{mid}/api/auth/sms/chaptcha`（取题）→ `send-code`（带 chaptcha 凭据）→ `login` | 商户域（DMP 会员）短信登录；**防接口滥用门禁** | 中（消费方手写端点 + SPI） | SMS验证码扩展-使用指南 + DMP接入说明 |
| 外部 IdP（微信/QQ/支付宝/OIDC） | AuthCenter + Federation + 平台库 | `POST {prefix}/login/external/{channelType}`——body 参数字典原样透传 `{code, channel_id}` | 第三方授权登录/静默授权 | 中（平台 SDK 拉起） | 认证中心指南 §6（T5 桥接） |
| 事件取 OpenId 票据 SPA 兑现 | AuthCenter + Federation + TrustCenter | `POST {prefix}/login/ticket`（`{ticket, channel_id?}`）→ TokenResponse | 微信事件（关注/扫码/菜单）免登落地页 | 中 | 认证中心指南 §6-c |
| 票据换令牌（OAuthTicket + PKCE） | AuthCenter | `POST {prefix}/ticket/exchange`（`{ticket, code_verifier, app_id, state}`） | URL 回调 + 纯前端静态站 | 中（PKCE 生命周期） | 认证中心指南 §核心用法 4 |
| 业务兑票（**服务端到服务端**） | AuthCenter | `POST {prefix}/login/ticket/redeem`（`{ticket}`）→ `FederatedTicketPayload` 明文 | 业务后端持票兑 payload 自建会员会话（**不建会话不发 token**） | 低 | 认证中心指南 §6-e |

### 1.2 第二因素（MFA——证明"你持有已登记的验证器"）

| 方式 | 归属扩展 | 门面 | 要点 | 详细指南 |
|------|---------|------|------|---------|
| TOTP（RFC 6238 自研零第三方） | MFA | `IMfaService.Enroll/Confirm/RequestChallenge/VerifyChallenge` | otpauth:// URI 转 QR；30s 步/6 位/±1 窗/同窗重放拒绝（V0.3.0）；**不签发 token——编排归消费方** | MFA 指南 §3.1 |
| SMS 方法 | MFA | 同上（`method:"sms"`） | 经消费方 `IMfaSmsSender` 发码（TryAdd 必装配） | MFA 指南 §3.3 |
| 恢复码 | MFA | `VerifyRecoveryCodeAsync` → `DisableAsync` | 绑定确认时一次性返明文 **8 枚 × 8 位字母数字**（去易混淆字符）；SHA256 单次消费；**丢失设备唯一逃生口** | MFA 指南 §3.4 |

### 1.3 人机验证（防滥用——叠加在主认证前）

| 方式 | 归属扩展 | 端点 | 要点 | 详细指南 |
|------|---------|------|------|---------|
| 图形码（SVG 零第三方依赖） | Captcha | 取题经 `ICaptchaService.IssueAsync`（消费方手写端点挂接）；**校验随 send-code 门禁内联**（消费方不直接调校验面） | 挑战态 in-memory；TTL 5min/答错 3 次/单次消费；`Enabled=false` + 场景要求门禁 = 守卫异常（m7 fail-closed） | SMS验证码扩展-使用指南 §六；`docs/SmsCode/ADR/ADR-Captcha-人机验证SPI与子模式裁定.md` |

### 1.4 选型决策矩阵

| 场景 | 推荐组合 | 理由 |
|------|---------|------|
| 新消费方默认 | 密码 + 短信验证码（平台形态） | 覆盖 Web/手机双端；AuthCenter 内建零额外装配 |
| 商户域（DMP 形态） | 密码 + **短信+CAPTCHA 门禁流** + 外部 IdP | CAPTCHA 防短信接口滥用（2026-11 模块已交付）；商户会员域独立装配 |
| 低摩擦获客 | 外部 IdP + 事件票免登 | 微信一键登录/关注免登；`AuthLevel.Federated=2` |
| 高安全场景 | 任一主认证 + **MFA（TOTP 优先）** | MFA 第二因素隔离凭据泄露；管理端/资金操作推荐 |
| 纯前端静态站 | 密码 + 票据换令牌 PKCE | URL 回调承载铁律：只带一次性票据 + redirect_uri，PKCE 防拦截 |

> **二因素体系关系 / 边界（重要）**：MFA（`TKWF.Ext.MFA`）与 AuthCenter V0.11.0 `AuthFactor` 因素是**两套并存体系**——MFA = 登录后的独立第二因素挑战流（ChallengeId 句柄、不签发 token）；`AuthFactor` = AuthCenter 内部的凭据登记表（密码/手机/联邦绑定 + TokenVersion 管理）。通常消费方二选一：用 AuthFactor 管凭据 + TokenVersion（推荐平台直连），或独立 MFA 扩展做高安全叠加。二者不互斥但职责不同，勿混淆。

## 二、接入前置（所有方式共用）

### 2.1 引用包 + 白名单组合规则

| 方式组合 | 需引用包 | 白名单声明 |
|---------|---------|-----------|
| 密码 + 短信（平台） | `TKWF.Ext.AuthCenter`（+ `AuthCenter.Abstractions` 若用 SSO 契约） | `[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]` |
| 短信+CAPTCHA（SmsCode） | `TKWF.Ext.SmsCode` + `TKWF.Ext.Captcha.Abstractions` + `TKWF.Ext.Captcha` | `SmsCodeExtensionInitializer<>` **+** `CaptchaExtensionInitializer<>`（双白名单——门禁依赖必须同启） |
| 外部 IdP（code 通道） | AuthCenter + `TKWF.Ext.Federation` + `TKWF.Federation.{平台库}` | `AuthCenter` + `Federation`（+ 平台库通道注册 `AddXxxFederationChannels()`） |
| 事件票（`/login/ticket` + `/login/ticket/redeem`） | AuthCenter + **TrustCenter** + Federation + 平台库 | 同上（TrustCenter **必装**——`ISealedTicketService` 未装配 → 503 `TICKET_SERVICE_NOT_CONFIGURED` 守卫 fail-hard） |
| MFA | `TKWF.Ext.MFA` | `MFAExtensionInitializer<>` |

### 2.2 Web 装配与路由前缀（平台端点挂接前提）

> ⚠️ **白名单声明只接 Domain 三钩子**（DI/过滤器/初始化）——平台端点（`{prefix}/login/*` / `sms/*` / `ticket/*` 等）与 Bearer 认证的**可见前提是 Web 装配**：

- **`AuthCenterWebExtension<TUserInfo>`**：`app.UseWebExtensions(e => e.Add<...>(x => x.RestoreUser = ...))`（RestoreUser 委托直传 + BeforeAuthentication 锚点 + 内建端点声明）；`UseWebSession` 游客帧同装配（匿名端点必须）
- **`{prefix}` 默认 `/api/auth`**（`TKWF:Api:RestBasePath` 全局前缀 + AuthCenter 模块前缀 `auth` 合成）；改前缀入口 `TKWF:Api:Modules:AuthCenter:Prefix`
- 端点 HTTP 开关/路由在 **Web 节 `TKWF:AuthCenter:Web`**——仅控制暴露面（`SmsLoginEndpointEnabled` / `TestTicketEndpointEnabled` 等），**不改变领域能力**（配置分层，Web 层不可关闭领域安全行为）
- 完整装配样板（RestoreUser / UseWebSession / 匿名端点清单）见 [认证中心-使用指南](./认证中心-使用指南.md) §装配

### 2.3 消费方必须/可选实现的 SPI

| SPI | 必须? | 说明 |
|-----|:---:|------|
| `AuthenticationUserHelperBase<TUserInfo>`（AuthCenter） | 必须（Bearer 身份适配） | 继承并实现两工厂方法：`CreateUserInfoFromAccount(account, roles)` / `CreateUserInfoFromToken(token, roles)` |
| `IAuthorizationMapper<TUserInfo>`（AuthCenter） | 路径 B 角色映射 | `MapRolesAsync(sub, token, ct)`（TryAddScoped 注册） |
| `ISmsSender`（SmsCode） | **生产必装** | 腾讯云/阿里云渠道；未装配 → 503 `sms_sender_unavailable`；开发 dev mock 日志输出码 |
| `ISmsCodeScopeResolver`（SmsCode） | 建议（租户场景必装） | **Scoped**，返回 `merchant:{MerchantUId}`（读路由值 mid）；null = 租户缺失 → `invalid_merchant`；无租户用默认空串实现 |
| `IMfaSmsSender`（MFA SMS 方法） | MFA-SMS 时必须 | 挑战码发送渠道（`TKWF.Ext.MFA` 消费方实现） |
| `ISmsSender`（AuthCenter 平台内建） | 平台短信时**生产必装**（未装配 → 503） | AuthCenter 自身短信发送渠道（EM 中 `{prefix}/sms/send-code`） |

### 2.4 配置概览（领域节——Web 层不可关闭）

| 配置节 | 关键项 | 说明 |
|--------|-------|------|
| `TKWF:AuthCenter` | `EnabledAuthTypes`（fail-closed）/ `LoginProtection`（频控：密码 5次/10min、短信 60s/小时/天/IP、票据 10/min）/ `FederatedProvisioning.AutoProvision` / `PasswordPolicy` | 默认 `["sms","password","federated"]`——集合外 Provider 不接线 |
| `TKWF:SmsCode` | `Scenes:login:RequiresCaptcha`（默认 **true**）/ 频控：60s 重发、日 10、时 5、IP 20 / `CodeTtlMinutes` 5 / `IsProduction` | M1 冻结默认值（比 AuthCenter 收紧） |
| `TKWF:Captcha` | `Enabled`（默认 true，fail-closed）/ `EnabledProviderType`（默认 image）/ `ChallengeTtlSeconds` 300 / `AttemptsPerChallenge` 3 / `IssuePerMinutePerIp` 10（取题频控） | 与场景要求门禁冲突 = 守卫异常 |
| `TKWF:Mfa` | `ChallengeTtl` / 频控（5 次/5min/用户×方法）/ `Sms` 相关 | ⚠️ SMS 方法频控为**进程内内存滑动窗口**——多实例部署须按 N×5 条/时预算或外部限流器（见 MFA 指南 §6）；见 MFA 指南 §2.2 |

### 2.5 匿名端点底线（所有登录面共用）

- **游客帧**：认证族匿名端点（send-code / sms / password / external / ticket / exchange / refresh / verify 等平台 `AllowAnonymous` 面）必须 `guest.Use<门面>()` + `UseWebSession` 同装配（无游客 → 守卫 fail，非静默降级）
- **登录编排红线**：表现层经 `User.Use<门面>()` 帧内编排（AOP 帧）；**禁止** `[FromServices] IEnumerable<IAuthenticationProvider>` 预绑定（帧外枚举抛守卫）
- 反代部署必须 `ForwardedHeaders`（否则频控全退化为代理 IP 单桶，fail-closed 非静默）

## 三、主认证接入

### 3.1 密码登录（SecurePassword 协议——V0.9.0）

**接入步骤**：
1. `TKWF:AuthCenter:EnabledAuthTypes` 含 `"password"`（默认含）
2. 客户端（前端/服务端 SDK）算哈希——**服务端永不接收明文**：
   - `clientHash = PBKDF2(password, salt, 600_000)`（SHA256、32 字节随机盐、32 字节哈希 hex 小写）
   - `@tkwf/tsclient` 已内置 SecurePassword 协议便捷封装（**前端零手写密码学**；方法名/用法以 tsclient 文档为准——本指南描述协议本身；盐由**客户端** `RandomNumberGenerator` 自生成，服务端不参与盐分发生成，无"取盐挑战"环节）
   - 复杂度校验客户端承担（MinLength 8 / MinCategories 2）
3. `POST {prefix}/login/password` body `{identifier, clientHash, salt}` → `TokenResponse`

**关键契约**：
- 返回 `MustChangePassword` 信号（初始密码强制改密流）
- 改密：`ChangePasswordAsync`（验旧 clientHash+salt → TokenVersion++ → 旧 refresh 立即失效）
- 找回三通道：`IPasswordResetService` 门面级（SMS `InitiateSmsResetAsync` / Email `InitiateEmailResetAsync`（需 Emailing 装配）/ 扫码 OAuthTicket 链路）——**无内建端点，消费方自建**
- 错误码：`PASSWORD_MISMATCH` / `PASSWORD_NOT_SET` / `PASSWORD_RATE_LIMITED`(429) / `ACCOUNT_NOT_FOUND` / `ACCOUNT_FROZEN`
- 频控：`pwd:login:{identifier}` 5 次/10min + `login-ip:{ip}` 20/h

**fail-closed**：未启用 `password` → 登录门面拒绝；冻结/禁用账号 → 400（`ACCOUNT_FROZEN`/`ACCOUNT_DISABLED`——按 errorCode 分支非状态码）。

> 详见 [认证中心-使用指南](./认证中心-使用指南.md) §V0.9.0（协议/策略/找回）。

### 3.2 短信验证码（平台形态——scene 白名单）

**接入步骤**（AuthCenter 内建端点，两步）：
1. `POST {prefix}/sms/send-code` body `{phone, scene}`（scene ∈ Login/Register/Bind/Reset）
2. `POST {prefix}/login/sms` body `{phone, code}` → `TokenResponse`（`authType="sms"`，`auth_level=1`）

**要点**：
- 频控三键：60s 重发间隔 / 小时上限 / 日上限 + IP 桶（send+login **共桶** `sms-ip:{ip}` 20/h——单向打通即双向封口）
- 单次消费 CAS（成功码不可重放）；SHA256 落库（`FixedTimeEquals` 比对）；生产未装配 ISmsSender → 503
- 独立校验（绑定/找回场景）：`POST {prefix}/sms/verify` `{phone, code, scene}` → `200 {verified}`
- 防枚举：已注册/未注册统一响应

> 详见 [认证中心-使用指南](./认证中心-使用指南.md) §核心用法 5。

### 3.3 短信 + CAPTCHA 门禁流（SmsCode/Captcha——2026-11-15 交付 v0.1.0）

**形态**：扩展**零端点**——三端点由消费方（DMP Merchant.WebApi）手写 MapPost 挂接 + 游客帧；两端点集注意区分：

| 步骤 | 端点 | Body | 响应 |
|------|------|------|------|
| ① 取 CAPTCHA 题 | `POST /m/{mid}/api/auth/sms/chaptcha` | `{}` | `200 {challengeId, payload(SVG), ttlSeconds}`；取题频控命中 → 429 `rate_limited` |
| ② 发短信码 | `POST /m/{mid}/api/auth/sms/send-code` | `{mobile, chaptcha: "{challengeId}:{answer}"}` | `200 {sent:true, retryAfterSeconds:60}` / 400 `chaptcha_failed` / 429 / 503 |
| ③ 登录 | `POST /m/{mid}/api/auth/sms/login` | `{mobile, code}` | `200 IdentitySession`（assurance="sms"/channelType="sms"/nextAction=open_vip）/ 400/403/429/500 |

**关键契约（冻结）**：
- **captchaToken 格式**：`"{challengeId}:{answer}"`（challengeId=32hex、answer 无歧义字母表——均不含 `:`，前端直接拼装；**wire 键是 `chaptcha` 非 `captcha`**）
- **门禁序（Q6）**：CAPTCHA 校验 → 频控 → 生成码 → 落库 → 发送（门禁通过才消耗短信预算）
- **门禁 fail-closed（m7）**：场景要求门禁但 Captcha 未装配 / `Captcha.Enabled=false` → **守卫异常**（禁静默跳过——防误关导致短信预算裸奔）
- SmsCode 门面额外频控：60s 重发 / 日 10 / 时 5 / IP 20；活跃码上限 5；同码连败 5 次作废；重发使旧码失效
- **错误码 delta（前端映射表更新）**：`sms_rate_limited` → **`rate_limited`**（统一）；send-code 频控 **400 → 429**（含 `retryAfterSeconds` 驱动倒计时）；新增 `chaptcha_failed`(400)/`sms_sender_unavailable`(503)/`invalid_scene`(400)
- 消费方 SPI：`ISmsSender`（生产必装）+ `ISmsCodeScopeResolver`（Scoped `merchant:{MerchantUId}`）

> ⚠️ 前端注意：接入流程为**三步**（先 chaptcha 取题 → send-code 携带 chaptcha 凭据 → login），wire 键为 `chaptcha`（非 `captcha`）；**@tkwf/tsclient v1.1.0 已内置 `issueChaptcha()` / `sendSmsCode(mobile, challengeId, answer)` / `loginBySmsCode<T>()` 三方法**（组串内化 + wire 键单点保证，urlMap 覆盖 DMP 路径，仅 REST 通道）——前端无需手写 fetch/拼装凭据；DMP 侧对接细节与模拟层接入点见 [DMP接入说明](../SmsCode/DMP接入说明.md)。
> 详见 [SMS验证码扩展-使用指南](../SmsCode/SMS验证码扩展-使用指南.md) + [DMP接入说明](../SmsCode/DMP接入说明.md)。

### 3.4 外部 IdP 登录（微信/QQ/支付宝/OIDC）

**接入步骤**：
1. 装配：AuthCenter + Federation + 平台库（`TKWF.Federation.WeChat` 等）→ `AddWeChatFederationChannels()` 注册通道
2. 前端：平台 SDK 拉起授权 → 回调收 `code`（建议自维护 `state` 防 CSRF——通道不感知 state）
3. `POST {prefix}/login/external/{channelType}` body `{code, channel_id, ...}`（参数字典原样透传）→ `TokenResponse`

**关键契约**：
- token：`authType="federated"` + `channel_type` claim（如 `wechat_oauth`/`qq_oauth`）
- 账号映射链：UId 直读 → `(channel_id, external_user_id)` 映射 → `AutoProvision` 门控建号（`TKWF:AuthCenter:FederatedProvisioning` 默认 true；false 时未映射 → `ACCOUNT_NOT_PROVISIONED` 不建号）
- fail-hard：Federation 未装配 → 503 `EXTERNAL_IDP_NOT_CONFIGURED`（禁静默降级）
- 微信双源已删——**统一经外部 IdP 桥接**，无专用 wechat 端点

> 详见 [认证中心-使用指南](./认证中心-使用指南.md) §6（T5 桥接）+ [联邦互联-使用指南](../Federation/联邦互联-使用指南.md)。

### 3.5 票据/兑票（分组说明）

| 端点 | 定位 | Body | 响应 | 关键语义 |
|------|------|------|------|---------|
| `POST {prefix}/ticket/exchange` | 票据换令牌（PKCE） | `{ticket, code_verifier, app_id, state}` | TokenResponse | TTL 5min 单次；**PKCE 校验矩阵：签发时存 verifier hash——换取时必填比对**（服务端/trust 签发 hash 为 null，换取可省传 verifier）；state 防重放；**冻结/禁用 400 拦截且票不消耗**（解冻后同票可换） |
| `POST {prefix}/login/ticket` | 事件取 OpenId 票 SPA 兑现 | `{ticket, channel_id?}` | TokenResponse | 仅 null-claimant 票可兑；`TICKET_INVALID` 统一判因（**无** EXPIRED/USED 细分——防泄露）；400 亦含 `ACCOUNT_FROZEN`/`ACCOUNT_DISABLED`/`INVALID_ARGUMENT`；429 `TICKET_RATE_LIMITED`(10/min/IP)；503 `TICKET_SERVICE_NOT_CONFIGURED` |
| `POST {prefix}/login/ticket/redeem` | **业务兑票（服务端到服务端）** | `{ticket}` | `FederatedTicketPayload` 明文 11 键 + extensions | **不建会话不发 token**——业务后端持票兑 payload 自建会员会话；**冻结/禁用 400 非 403**（按 errorCode 分支）；**票已消费边缘语义：拒绝时票已消费，重试恒 TICKET_INVALID**（须重签票）；频控独立桶 `ext:ticket-redeem:{ip}` 60/min/IP |

**PKCE 接入要点（静态站）**：`code_verifier` 在**签发侧**生成并自持（RFC 7636 unreserved 43-128 字符），换取时回传——SDK 侧按显式参数传递（`exchangeTicket` 不内部生成，见 tsclient v1.1.0 方案）。

> 详见 [认证中心-使用指南](./认证中心-使用指南.md) §核心用法 4 / §6-c / §6-e。

### 3.6 会话管理（主认证后共用）

| 操作 | 端点 | 要点 |
|------|------|------|
| Refresh（rotation） | `POST {prefix}/refresh` `{refresh_token}`（双收键） | 30d rotation + TokenVersion 门控；**重用已撤销 refresh → 判定泄露全撤**（`REFRESH_REUSED`/`REFRESH_STALE`） |
| Logout | `POST {prefix}/logout`（Bearer 必需） | jti 落黑名单（TTL=token 自然过期）；**200**（V0.12.0 起 204→200） |
| 验证内省 | `GET {prefix}/verify`（Bearer） | 已认证内省：`200 {valid, userId, authType, auth_level, exp, jti}`；无效/缺失 Bearer → **401 显式拒绝**（非 RFC 7662 `200{active:false}`）——SDK 按 401 引导重登 |
| 应用授权状态 | `GET {prefix}/grants?appId=`（**camelCase 查询键**） | `{grants:[{appId, scopes[], validUntil, source, status}]}`（validUntil=应用授权有效期非会话期） |

> 详见 [认证中心-使用指南](./认证中心-使用指南.md) §核心用法 2/3 + V0.8.0。

## 四、MFA 接入（叠加在主认证之上）

### 4.1 绑定流

```csharp
// TOTP 绑定——ProvisioningUri 转 QR（otpauth:// 协议）
var enroll = await mfa.EnrollAsync(userId, "totp", new MfaEnrollContext(Issuer: "MyApp", DisplayName: "alice"));
var recoveryCodes = await mfa.ConfirmEnrollAsync(userId, "totp", enroll.EnrollToken, totpCode);
//  ⚠️ 绑定确认成功后**一次性**返回恢复码明文——前端必须展示并提示用户保存（仅此一次）

// SMS 方法绑定（自动发码到手机）
var enroll = await mfa.EnrollAsync(userId, "sms", new MfaEnrollContext(Phone: phone));
var codes = await mfa.ConfirmEnrollAsync(userId, "sms", enroll.EnrollToken, smsCode);
```

### 4.2 登录编排（主认证成功 → MFA 挑战 → 消费方签发）

```csharp
// 主认证成功后（消费方编排——MFA 不签发 token）
if (await mfa.IsMfaEnabledAsync(userId))
{
    var challenge = await mfa.RequestChallengeAsync(userId, "totp");   // 或 "sms"
    bool verified = await mfa.VerifyChallengeAsync(userId, "totp", challenge.ChallengeId, totpCode);
    if (!verified) { /* 统一失败提示（防枚举——不区分判因） */ }
}
// verified == true → 消费方随后自行签发会话令牌
```

### 4.3 恢复码 / 解绑

- 恢复码：**8 枚 × 8 位字母数字**（去易混淆字符）、SHA256 落库、单次消费、纳入频控；**设备丢失唯一逃生口**（建议引导用户绑定后立即保存）
- 解绑：`VerifyRecoveryCodeAsync` 验证 → `DisableAsync(userId, method)` **按方法**级联——仅删该方法绑定 + 未消费挑战 + 恢复码（恢复码随任一方法解绑清空；**另一方法不受影响**；**谨慎操作**，须先确认恢复码）

### 4.4 与 AuthCenter 关系模型边界

- MFA = **登录后第二因素挑战**（ChallengeId 句柄、挑战不落 AuthFactor 表）
- AuthFactor（V0.11.0）= AuthCenter 内部凭据登记（Password/Sms/Federated 因素 + TokenVersion 管理）
- 实践建议：**平台直连模式**凭据管理统一走 AuthFactor（TokenVersion 闭环天然衔接）；MFA 扩展用于**高安全叠加**（管理端/资金操作）或独立认证域

> 详见 [MFA多因素认证-使用指南](../MFA/MFA多因素认证-使用指南.md)（绑定/挑战/恢复码/解绑全流程 + 生产注意事项）。

## 五、组合建议与参考模式

### 5.1 场景组合矩阵

| 场景 | 主认证 | 门禁 | MFA | 说明 |
|------|-------|------|-----|------|

### 5.2 两种装配模式（平台直连 vs 接入主体域中转）

| 模式 | 说明 | 适用 | 指向 |
|------|------|------|------|
| **平台直连** | 消费方前端直接调用 AuthCenter 标准端点（`{prefix}/login/*`）、按平台会话契约消费 | 独立接入方 | [认证中心-使用指南](./认证中心-使用指南.md) |

## 六、安全底线（消费方必读）

1. **防枚举**：已注册/未注册统一响应文案（send-code、login、外部 IdP 失败统一判因）；判断用户存在性走业务侧专用查询
2. **fail-closed**：能力未装配 → 503/守卫异常（`EXTERNAL_IDP_NOT_CONFIGURED`/`TICKET_SERVICE_NOT_CONFIGURED`/`sms_sender_unavailable`/MFA mock 异常）；**场景要求门禁但 Captcha 关 = 守卫异常**（禁静默放行）
3. **凭据不落日志**：验证码/CAPTCHA 凭据/密码哈希（明文更不可）不入日志——dev mock 明文码仅 `IsProduction=false` 时日志输出（开发边界）
4. **频控双层**：领域层 `IRateLimitCheck`（pwd:login 5次/10min、sms 60s/日/时/IP、ext:ticket 10/min、redeem 60/min）+ Web 层 `RateLimiting` 扩展（`RequireRateLimiting`）——双保险
5. **登录编排红线**：`User.Use<门面>()` AOP 帧内编排；禁 `[FromServices] IEnumerable<IAuthenticationProvider>`；匿名端点游客帧 + `UseWebSession` 同装配
6. **反代**：必须 `ForwardedHeaders`（否则频控退化为代理 IP 单桶）
7. **票据/兑票**：`TICKET_INVALID` 统一判因不泄露；redeem 冻结/禁用按 errorCode 分支（400 非 403）；票消费后重试恒无效——UI 引导重新取票；**事件链免登落地页须自配 `LinkTemplate`（不配则回退内置测试兑票端点 `{prefix}/{platformId}/test/{channelId}/{ticket}`——仅联调用，生产必须关闭 `TKWF:AuthCenter:Web:TestTicketEndpointEnabled`）**
8. **PKCE**：静态站 code_verifier 必生成自持（签发侧确定），换取必比对；URL 回调只带一次性票据 + redirect_uri

> 完整安全底线与踩坑清单（参考实现实证）见 [H5应用登录对接-使用指南](./H5应用登录对接-使用指南.md) E/F 节。

## 七、故障排查速查

### 7.1 错误信封双轨（先分清端点类型）

| 端点类型 | 错误信封 | 语义码位置 | 示例 |
|---------|---------|-----------|------|
| 平台生成端点（AuthCenter/Federation） | **RFC 9457 ProblemDetails** `{type,title,status,detail,instance,errorCode,translationKey,messageArgs}` | 扩展字段 `errorCode`（`code` 字段不存在） | `TICKET_INVALID`/`ACCOUNT_FROZEN` |
| DMP 参考实现端点（/m/{mid}/api/auth/*） | **简信封** `{error, message}` | `error` 字段 | `chaptcha_failed`/`rate_limited` |

> SDK 侧：**v1.1.0 起 errorCode 通用透传已闭环**——`toErrorCode` 对 ProblemDetails `body.errorCode` 开放透传（400 硬编码两个保持优先；`errorCode` 键优先于 `error` 键），票据族错误码（`TICKET_INVALID`/`ACCOUNT_FROZEN`/`ACCOUNT_DISABLED`）**不再落 UNKNOWN**；429 分支读 body `retryAfterSeconds` / `Retry-After` 头挂 `err.retryAfterSeconds`；v1.0.15 起 `body.error` 透传（DMP 简信封，H5 指南 §A.2）。

### 7.2 常见症状 → 处置

| 症状（HTTP/SDK 码） | 可能原因 | 处置 |
|--------------------|---------|------|
| 401 `AUTH_EXPIRED`/`AUTH_REQUIRED` | 会话过期/无 session | 引导重登（onUnauthorized 集中处理） |
| 403 `FORBIDDEN` | 无权访问 | 检查角色/权限映射 |
| 429 `RATE_LIMITED`/`rate_limited` | 频控命中 | DMP 端点读 body `retryAfterSeconds` 倒计时；平台端点读 **`Retry-After` 响应头**；检查 ForwardedHeaders |
| 503 | 能力未装配 | 检查白名单/SPI（ISmsSender/IMfaSmsSender/Federation 装配） |
| 400 但无业务码（UNKNOWN） | 平台 ProblemDetails errorCode 透传缺失（旧 SDK 已知边界） | **升级 @tkwf/tsclient v1.1.0+**（errorCode 通用透传已闭环）；仍 UNKNOWN 从响应 detail 排查 |
| 冻结/禁用（400 `ACCOUNT_FROZEN`/`ACCOUNT_DISABLED`） | 账号状态 | **按 errorCode 分支（非状态码！）**——redeem 场景为 400 非 403 |
| `TICKET_INVALID` 重试恒失败 | 票已消费/过期 | 重新触发取票流程（不可重试旧票） |
