## 一、这是什么

认证中心解决"**一个平台、多种认证方式、一套令牌体系**"的问题——DMP-Lite AuthCenter 抽取的通用认证组件，多业务线独立装配部署复用。

| 你要解决的 | 用认证中心 |
|-----------|-----------|
| 短信验证码登录 + 自动注册 | `ISmsVerificationService` + `SmsAuthenticationProvider` |
| 微信网页授权/扫码登录 | `WeChatAuthenticationProvider` + `WeChatApiClient` |
| API 无状态认证（Bearer JWT） | `AuthCenterWebExtension<TUserInfo>`（UseWebExtensions 装配，路径 B，v4.10.45 收敛迁移） |
| 业务系统自己触发登录 | `AuthenticationUserHelperBase`（路径 A，AuthorityFilter 零改动） |
| 令牌签发/验证/刷新/撤销 | `ITokenService`（RS256 + Refresh rotation + 黑名单） |
| 平台账号 ↔ 业务系统账号映射 | `IPlatformAccountMapService` |
| 微信/抖音等平台凭证安全管理 | `IPlatformCredentialService`（AES-GCM 加密） |
| 登录限流防暴力 | `IAuthLoginAttemptService` + `ISmsVerificationService` 频控 |

**不包含**：用户中心（档案面）→ **独立立项 `TKWF.Ext.UserCenter`**（认证中心 v0.2.0 起实现其 `IUserProfileSource` 读取契约——档案**读取**契约归 UserCenter，数据属主为认证中心）；口令兑换体系/教师审核流/家庭码 → 教育线特有扩展点；密码 Provider/抖音 Provider → 扩展点；短信渠道（腾讯云等）→ 消费方实现 `ISmsSender`。

## 二、快速开始（3 步）

### 第 1 步：引用 + 白名单启用

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——公共内容不在此重复。

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\Authentication\TKWF.Ext.AuthCenter.csproj" />
```

```csharp
using TKWF.Ext.AuthCenter;

[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

### 第 2 步：配置 `TKWF:AuthCenter`

```jsonc
{
  "TKWF": {
    "AuthCenter": {
      "Issuer": "auth-instance-1",
      "SigningKeyPath": "C:\\keys\\rsa-private.pem",
      "CurrentKid": "rsa-key-1",
      "SigningKeys": [{ "Kid": "rsa-key-1", "PrivateKeyPath": "C:\\keys\\rsa-private.pem" }],
      "EnabledAuthTypes": ["sms", "wechat"],
      "RedirectUriWhitelist": ["https://app.example.com/callback"],
      "SecretEncryptionKeyPath": "C:\\keys\\credential-aes.key",
      "IsProduction": true
    }
  }
}
```

**生成 RSA 私钥 PEM**（生产）：
```bash
openssl genpkey -algorithm RSA -pkeyopt rsa_keygen_bits:2048 -out rsa-private.pem
```

> ⚠️ **生产 fail-fast**：`IsProduction=true` 时缺 `Issuer` / `SigningKeyPath` / `SecretEncryptionKeyPath` → 启动拒绝（InitializeAsync 预检）。密钥文件权限 chmod 600，不进代码库。
> 开发模式（`IsProduction=false`）缺密钥自动生成临时 RSA + Warning（重启即变，仅限开发联调）。

### 第 3 步：接登录（二选一或并用）

**路径 A · 业务系统自己触发登录**（短信/微信登录按钮 → 消费方 UserHelper）：

```csharp
public class MyUserHelper : AuthenticationUserHelperBase<MyUserInfo>
{
    protected override MyUserInfo CreateUserInfoFromAccount(AuthAccountEntity account, IReadOnlyList<string> roles)
        => new MyUserInfo(account.UId, account.Phone ?? account.UId) { Roles = roles.ToList() };

    protected override MyUserInfo CreateUserInfoFromToken(TokenValidationResult token, IReadOnlyList<string> roles)
        => new MyUserInfo(token.UserId, token.UserId) { Roles = roles.ToList() };
}
```
预实现钩子：`OnLoginBySmsCodeAsync`（短信校验 → 查/建账号）、`OnLoginByWeChatScanAsync` / `OnLoginByWeChatAppletAsync` / `OnLoginByOAuthAsync`（JWT 验签恢复身份）——消费方**仅实现两个工厂**，样板大减。

**路径 C · 登录编排门面（V0.5.0 推荐，ADR92/T3 闭环）**——表现层零编排终态：

```csharp
// ⚠️ V0.5.0 起禁止 [FromServices] IEnumerable<IAuthenticationProvider> 直注（帧外枚举抛守卫——EduPlatform 3 端点 500 根因）。
// 控制器经登录编排门面消费（门面 ctor 帧内枚举 Provider 集合，守卫工厂经 CurrentAopUser 供给）：

public class AuthController(DomainUser<MyUserInfo> user)   // 经 UserHelper.CreateUserInstance 注入（或 HttpContext 会话恢复）
{
    // 短信登录（验证码校验 → 有账号登录 / 无账号建账号）——返回 ProviderAuthenticateResult（UId/FailReason/AuthLevel）
    [AllowAnonymous]
    public async Task<IActionResult> SmsLogin(string phone, string code)
    {
        var result = await user.Use<ISmsLoginService>().LoginAsync(phone, code);
        return result.Success ? Ok(result) : BadRequest(new { reason = result.FailReason });
    }

    // 微信登录（snsapi_base 网页 / snsapi_login 扫码——scope 透传）
    [AllowAnonymous]
    public async Task<IActionResult> WechatLogin(string code, string scope)
    {
        var result = await user.Use<IWechatLoginService>().LoginAsync(code, scope);
        return result.Success ? Ok(result) : BadRequest(new { reason = result.FailReason });
    }
}
```

> **V0.5.0 破坏性消费约束（评审 P1）**：`EnabledAuthTypes` 集合外 Provider 不接线 → 门面返回 `SMS_PROVIDER_NOT_ENABLED` / `WECHAT_PROVIDER_NOT_ENABLED`（FailReason 透传）；原"控制器 `[FromServices] IEnumerable<IAuthenticationProvider>` 直注集合编排"形态**作废**（帧外枚举抛守卫，禁止形态）——改经 `User.Use<ISmsLoginService>()` / `User.Use<IWechatLoginService>()` 编排（EduPlatform `sms/login` + `wechat mp/web callback` 3 端点修复路径）。

**路径 B · API Bearer JWT 消费**（主框架无内置 Bearer handler——认证中心补齐）：

```csharp
// 装配（v4.10.45 收敛迁移——旧 AddJwtAuthentication + UseTkfwJwtAuthentication 静态方法已删除，破坏性变更；
// Web 装配钩子一次声明：AuthCenterWebExtension 锚点默认 BeforeAuthentication——UseWebSession 之后 / 框架认证判定之前）
builder.ConfigWebAppDomain<MyUserInfo, MyDomainInitializer, DomainWebOptions>(...)
    .UseWebSession()                                // SessionKey 会话恢复（主框架）
    .UseWebExtensions(e => e.Add<AuthCenterWebExtension<MyUserInfo>>(x =>
    {
        x.RestoreUser = RestoreUserFromToken;       // 认证中心中间件（恢复委托直传，不经 Options）
    }))
    .BeforeRouting(...)
    .AfterRouting(...)
    .Build(...);
// ITokenVerifier 等业务服务由 Domain 钩子 AuthCenterExtensionInitializer 注册（领域自治）
```

```csharp
// 恢复委托（在 UserHelper 子类内提供——CreateUserInstance 需 Host 上下文）
private Task<DomainUser<MyUserInfo>> RestoreUserFromToken(HttpContext ctx, TokenValidationResult token)
{
    var user = CreateUserInstance();                        // protected internal（UserHelper 内）
    user.LoginAsUserAsync(new MyUserInfo(token.UserId, token.UserId)
    {
        Roles = (await _mapper.MapRolesAsync(token.UserId, token)).ToList()
    }, EnumLoginFrom.OAuth);
    return Task.FromResult(user);
}
```

**管线顺序（Oracle C5 + v4.10.45 锚点分桶 P0-1）**：`UseWebSession`（SessionKey 恢复先到短路）→ **BeforeAuthentication 桶**（`AuthCenterWebExtension`——无 SessionKey 时走 Bearer）→ `UseHttpAuthentication`（读已认证 DomainUser 标记通过）→ AuthorityFilter（跳过重复检查）。两路径**互斥不叠加**——带 SessionKey 的浏览器请求 SessionKey 优先，带 Bearer 的 API 请求 JWT 优先。冒烟锁定：`JwtAuthenticationWebHookIntegrationTests`（黑盒哨兵断言顺序串 ContextExtraction → JwtAuth 验签 → HttpAuthentication）。

## 三、核心用法

### 1. 签发令牌（登录成功后）

```csharp
public class LoginService(ITokenService tokenService)
{
    public async Task<TokenIssueResult> LoginAsync(string userId, string authType)
    {
        // 认证成功（短信/微信/其他）后签发
        return await tokenService.IssueTokenAsync(new TokenIssueRequest(
            UserId: userId, AuthType: authType, AuthLevel: (int)AuthLevel.Phone, TeacherVerified: false));
    }
}
```

### 2. 令牌验证 / 撤销

```csharp
// 验证（验签 + exp + kid + iss + 黑名单——失败抛 AuthenticationException，消息含机器可读原因码）
var result = await tokenService.ValidateTokenAsync(accessToken);

// 撤销（登出/安全事件）
await tokenService.RevokeTokenAsync(result.Jti, "logout");
```

### 3. Refresh 续期（rotation）

```csharp
// 旧 refresh 置 revoked + 新对签发；TokenVersion 不匹配拒绝；重用已撤销 → 全撤销 + Warning
var refreshed = await tokenService.RefreshTokenAsync(refreshToken);
```

### 4. 票据换令牌（URL 回调 + PKCE——纯前端静态站）

```csharp
// 签发方（服务端/trust 或静态站）
var ticket = await ticketService.IssueAsync(new OAuthTicketIssueRequest(
    AppId: "app-1", RedirectUri: "https://app.example.com/callback",
    State: "csrf-state", CodeVerifier: codeVerifier /* 静态站必传 */));

// 换取方（/oauth/exchange 端点——装配层实现）
var exchanged = await ticketService.ExchangeAsync(new OAuthTicketExchangeRequest(
    Ticket: ticket, CodeVerifier: codeVerifier, AppId: "app-1", State: "csrf-state"));
```

> **PKCE 校验矩阵（Oracle C4）**：签发时存 verifier hash——换取时 verifier 必填比对（缺 verifier 拒绝）；服务端/trust 签发（hash null）换取可不传（依赖 AppId 白名单 + 内网信任）。

### 5. 短信验证码

```csharp
// 发送（频控 60s/小时/天 + 生产未装配 ISmsSender → 503 语义）
await smsVerification.SendCodeAsync("13800138000", SmsScenes.Login);
// 校验（单次消费 + 5 次/小时 + SHA256 比对）
var ok = await smsVerification.VerifyCodeAsync("13800138000", "123456", SmsScenes.Login);
```

**装配 ISmsSender**（消费方实现——参考 Emailing `IEmailSender` 模式）：

```csharp
public class TencentSmsSender : ISmsSender
{
    public async Task SendAsync(SmsMessage message, CancellationToken ct = default)
    {
        // 调腾讯云 SMS API（零第三方依赖在 Ext——渠道实现归装配层）
        await _tencentSdk.SendAsync(message.Phone, message.Content, ct);
    }
}
// 注册（TryAdd 语义——消费方实现优先）
builder.Services.TryAddScoped<ISmsSender, TencentSmsSender>();
```

### 6. 微信 OAuth（网页授权 + 扫码）

`WeChatAuthenticationProvider` 经 `EnabledAuthTypes: ["wechat"]` 启用后，装配层实现回调端点：
- 网页授权（`snsapi_base`）：`/oauth/wechat/mp/callback?code=...` → Provider.AuthenticateAsync（WechatScope="snsapi_base"）→ 签发一次性票据回应用
- 扫码（`snsapi_login`）：`/oauth/wechat/web/callback?code=...`（WechatScope="snsapi_login"）→ 同理

**绑定流程**（登录 vs 绑定隔离——Oracle I6 防绑定劫持）：绑定用 `bind_token`/`state` 独立流程，不复用登录票据；微信 openid 绑定已有手机号账号后，`AuthAccount.TokenVersion++` 使旧 refresh 失效。

### 7. 跨系统映射（DMP 会员/管理员对接）

```csharp
// 平台内部 id ↔ 业务 app + 业务本地 id（upsert）
await mapService.LinkAsync("u-100", "edu-app", "student-42", "union-xyz");
// 业务侧 → 平台侧（登录恢复）
var map = await mapService.GetByBusinessAsync("edu-app", "student-42");
// UnionId 跨应用串联
var links = await mapService.GetByUnionIdAsync("union-xyz");
```

### 8. 业务角色映射（IAuthorizationMapper——消费方实现）

```csharp
public class MyAuthorizationMapper : IAuthorizationMapper<MyUserInfo>
{
    public async Task<IReadOnlyList<string>> MapRolesAsync(string sub, TokenValidationResult token, CancellationToken ct = default)
    {
        // 令牌不含业务角色——此处本地映射（查 PlatformAdmin 表 / 业务角色表）
        // teacher_verified 仅身份声明——如需教师角色在此映射
        return ["Member"];  // 示例
    }
}
builder.Services.TryAddScoped<IAuthorizationMapper<MyUserInfo>, MyAuthorizationMapper>();
```

## V0.2.0 新增：账号查询契约 + UserCenter 档案承接

### 1. 账号查询契约（`IAuthAccountQueryService`）

认证中心对外只读查询契约——用于 UserCenter 桥接 / 装配实例 / 端内复用，返回完整 `AuthAccountEntity`：

```csharp
public class SomeService(IAuthAccountQueryService accounts)
{
    // 4 只读方法（委托 AuthAccountEntityDataService，红线合规）
    Task<AuthAccountEntity?> a = accounts.GetByUIdAsync("u_123");                    // 按平台内部 id
    Task<AuthAccountEntity?> b = accounts.GetByPhoneAsync("13800138000");            // 按手机号
    Task<AuthAccountEntity?> c = accounts.GetByWechatMpOpenIdAsync("mp_openid");     // 按公众号 openid
    Task<AuthAccountEntity?> d = accounts.GetByWechatWebOpenIdAsync("web_openid");   // 按扫码 openid
}
```

> **只读契约**——写路径（Create/Update/失效）走 `IAuthAccountService`（见 3），查询接口不携带写方法。

### 2. UserCenter 档案承接（`AuthAccountUserProfileSource`）

消费方**同时白名单声明认证中心 + UserCenter** 后，`IUserCenterQueryService.GetProfileAsync` 自动获得真实档案——**无需再写桥接类**：

```csharp
using TKWF.Ext.AuthCenter;
using TKWF.Ext.UserCenter;

[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]
[TKWFEnabledExtension(typeof(UserCenterExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

- `AuthAccountUserProfileSource` 实现 `IUserProfileSource`（public sealed，`AuthCenterExtensionInitializer` TryAddScoped 注册）——新装配实例**零桥接**；已按 UserCenter v0.1.0 写过 `AuthAccountProfileSource` 桥接类的装配实例**可删除**（零代码变更 = UserCenter 门面注入契约不变）。
- **Phone 脱敏**：`UserProfileDto.Phone` 从源返回**原始值**，由 UserCenter 门面统一脱敏（`138****5678`）——实现方**不得自行 Mask**。

### 3. 账号写契约（`IAuthAccountService`——DMP 渐进替换影子账号）

对外写契约——**迁移/装配场景**维护 AuthAccount 生命周期（ADR-Authentication-账号写契约）：`TokenService.RefreshTokenAsync` 强依赖 AuthAccount 记录（不存在/禁用 → `ACCOUNT_NOT_FOUND`；TokenVersion 不匹配 → `REFRESH_STALE`），DMP 平台管理员（本地 `PlatformAdmin` 表 + `IAuthorizationMapper` 本地映射角色）须有影子 AuthAccount 才能切扩展令牌体系：

```csharp
public class AdminLoginService(IAuthAccountService accounts)
{
    // upsert 影子账号（UId = PlatformAdmin.UId，Phone 可空——唯一索引 NULL 放行）
    public async Task EnsureShadowAccountAsync(string adminUId)
    {
        if (await accounts.GetByUIdAsync(adminUId) is null)
            await accounts.CreateAsync(new AuthAccountEntity { UId = adminUId, IsEnabled = true });
    }

    // 平台管理员改密 → bump TokenVersion → 旧 refresh 失效（REFRESH_STALE）
    public Task OnAdminPasswordChangedAsync(string adminUId)
        => accounts.IncrementTokenVersionAsync(adminUId);

    // 停用/回用（禁用后刷新报 ACCOUNT_NOT_FOUND）
    public async Task SetEnabledAsync(string adminUId, bool enabled)
    {
        var a = await accounts.GetByUIdAsync(adminUId);
        if (a is not null) { a.IsEnabled = enabled; await accounts.UpdateAsync(a); }
    }
}
```

> **边界**：`AdminDeleteAsync` 不暴露（破坏性，管理 API 迭代）；影子账号**不填 PasswordHash**（DMP 登录验证走本地 `PlatformAdmin`，AuthAccount 仅作令牌刷新锚点）；写契约面向迁移/装配场景，业务主写路径仍归扩展内部。

## V0.6.0 新增：归层 + 内建标准对内端点（2026-10-06）

> **归层迁移（破坏性——无外部消费方零折中）**：包名 `TKWF.Ext.Authentication` → **`TKWF.Ext.AuthCenter`**（命名空间/目录/MinVerTagPrefix/契约包 `AuthCenter.Abstractions` 统一；`JwtAuthenticationWebExtension` → **`AuthCenterWebExtension`**、`JwtAuthenticationOptions` → **`AuthCenterMiddlewareOptions`**）。**消费方引用/using 更新**：`using TKWF.Ext.Authentication` → `using TKWF.Ext.AuthCenter`；Federation 已同步。

### 1. 内建标准对内端点（`AuthCenterWebExtension`——登录/refresh/logout/票据/验证码）

**装配**（`UseWebExtensions` 一次声明——原 JwtAuthenticationWebExtension 用法不变，类名/命名空间更新）：

```csharp
.UseWebExtensions(e => e.Add<AuthCenterWebExtension<MyUserInfo>>(x =>
{
    x.RestoreUser = (httpContext, tokenResult) => Task.FromResult(/* 已认证 DomainUser */);
    x.ConfigureOptions = o => o.RoutePrefix = "/api/auth";   // 可选编程式覆盖（后于配置节）
}))
```

**端点表**（`{prefix}` 默认 `/api/auth`——路径/开关经 `TKWF:AuthCenter:Web` 配置）：

| 端点 | 方法 | 请求 | 响应 | 说明 |
|------|------|------|------|------|
| `{prefix}/sms/send-code` | POST | `{ phone, scene }`（scene 白名单 Login/Register/Bind/Reset） | `204` | 短信验证码发送（频控 429 / 无 ISmsSender 503） |
| `{prefix}/login/sms` | POST | `{ phone, code }` | `TokenResponse` | 短信登录——门面内认证→取账号→签发全编排（单门面） |
| `{prefix}/login/wechat` | POST | `{ code, scope }` | `TokenResponse` | 微信登录（snsapi_base/snsapi_login） |
| `{prefix}/refresh` | POST | `{ refresh_token }` | `TokenResponse` | Refresh rotation |
| `{prefix}/logout` | POST | Bearer | `204` | 撤销（jti 经中间件取——需已认证） |
| `{prefix}/ticket/exchange` | POST | `{ ticket, code_verifier, app_id, state }` | `TokenResponse` | 票据换令牌（PKCE） |

**`TokenResponse`**：`{ access_token, refresh_token, token_type: "Bearer", expires_in }`；**`ErrorResponse`**：`{ code, message }`（失败码如 `SMS_CODE_MISMATCH`/`INVALID_SCENE`/`RATE_LIMITED` 频控 429）。

**⚠️ 装配约束（V0.5.2 延伸）**：`AuthCenterWebExtension` 须与 `UseWebSession` 同装配（匿名端点 handler 经游客帧 `guest.Use<门面>()`——ContextExtraction 写游客 DomainUser；未装配 → 抛守卫 = 正确 fail）。

### 2. 配置分层（AGENTS §8——领域/表现层解耦）

| 配置节 | 承载 | 说明 |
|--------|------|------|
| `TKWF:AuthCenter`（`AuthCenterOptions`，领域） | `EnabledAuthTypes`（fail-closed）/`LoginProtection`/令牌生命周期/密钥路径 | **领域决策——Web 层不存在对应开关**（防"表现层关掉频控/口令校验"绕过） |
| `TKWF:AuthCenter:Web`（`AuthCenterEndpointOptions`，表现层） | `RoutePrefix`（默认 `/api/auth`）+ 端点开关（`SmsSendCodeEndpointEnabled`/`SmsLoginEndpointEnabled`/`WechatLoginEndpointEnabled`/`RefreshEndpointEnabled`/`LogoutEndpointEnabled`/`TicketExchangeEndpointEnabled`） | **仅 HTTP 暴露面**——关闭端点不改变领域能力（领域服务仍可经 `User.Use<门面>()` 直调） |
| `AuthCenterMiddlewareOptions`（中间件行为） | `RejectInvalidToken` | 中间件管线行为（独立 POCO，非 Web Options） |

> **端点暴露 vs 领域未启用语义**：端点开关默认 true = 暴露面默认开放；若领域 `EnabledAuthTypes` 未启用对应 Provider（如 wechat 未列入）→ 端点暴露但调用时**领域层 fail-closed 拒绝**（安全由领域控制，非不一致状态）。

### 3. 登录门面升级（V0.6.0——`LoginResult`）

`ISmsLoginService.LoginAsync`/`IWechatLoginService.LoginAsync` 返回 **`LoginResult(Success, UserId, Token, FailReason)`**（原 `ProviderAuthenticateResult`）——门面内完成 认证→取账号（TeacherVerified/AuthLevel）→签发 全编排；**消费方控制器只调一个门面**（表现层零编排保持）：

```csharp
var login = await user.Use<ISmsLoginService>().LoginAsync(phone, code);
if (login.Success) { /* login.Token.AccessToken / login.UserId */ }
else { /* login.FailReason → HTTP 400/429 映射 */ }
```

## 四、安全说明（必读）

| 主题 | 说明 |
|------|------|
| **密钥管理** | RSA 私钥 PEM + AES-GCM 密钥文件（前 32 字节）——chmod 600、不进代码库、生产预置；kid 轮换（SigningKeys 多密钥，旧钥可验证直到过期）；紧急换钥 = 换 CurrentKid + 旧 access 2h 内失效 |
| **密码修改处置** | `AuthAccount.TokenVersion++` 后，存量 2h access token 靠**短 TTL 自然失效**（业界主流——Access 验签无状态，Refresh 是收权点）；密码修改后 2h 内旧 access 仍有效属预期；高安全场景可后续加按 UserId 批量撤销（v0.2.0） |
| **Refresh 重用检测** | 已撤销 refresh 再次出现 → 判定泄露 → 撤销该用户全部 refresh + Warning（业界 BCP） |
| **回调承载铁律** | URL 只带一次性票据 + redirect_uri，**绝不带敏感信息**；纯前端静态站走公网 `/oauth/exchange` + PKCE code_verifier |
| **黑名单缓存** | 验签黑名单查询经 IMemoryCache 45s 前置过滤（避免每请求 1 次 DB）；高流量场景 v0.2.0 可配 Redis 分布式缓存 |
| **生产 Mock 语义** | 未装配 ISmsSender 时生产拒绝发送（503）——防 dev_code 泄露 |
| **手机号唯一 + 并发** | `UX_AuthAccount_Phone` 唯一约束兜底并发注册（同手机号两单）；微信便捷账号 Phone 可空（唯一索引 NULL 放行），短信绑定后回填 |
| **token 不落库明文** | Refresh Token 仅存 SHA256 hex；验证码仅存 SHA256 hex；AppSecret 仅存 AES-GCM 密文 |
| **认证入口匿名面** | 认证前置方法在**接口级**标 `[AllowAnonymousFlag]`（对齐 `IAuthController`/`IdentityAuthService` 先例，`AuthorityFilter.CanWeGo` 豁免）：`ISmsVerificationService.SendCodeAsync/VerifyCodeAsync`、`IAuthenticationProvider.AuthenticateAsync`、`ITokenService.IssueTokenAsync/RefreshTokenAsync/RevokeTokenAsync`、`IOAuthTicketService.IssueAsync/ExchangeAsync`、`IPlatformCredentialService.GetByAppIdAsync`（9 声明）。**非匿名面零声明**：`ValidateTokenAsync`（Bearer 校验在认证/中间件上下文）、`ISmsSender.SendAsync`（服务端通道）、`IPlatformCredentialService` 管理写方法（鉴权必须） |

## 五、与既有扩展划界

| 扩展 | 划界 |
|------|------|
| **Identity（用户/角色管理）** | 认证中心**不复用**其 UserEntity/RoleEntity——AuthAccount 手机号主键 + OAuth 绑定模型根本不同；两者可共存（Identity 管本地用户/角色，Authentication 管令牌/认证） |
| **Account（锁定/重置）** | 认证中心登录保护 = `AuthLoginAttemptEntity` 独立实现（含 authType 维度）——语义互补；装配实例可按需叠加启用 |
| **SecurityLog（安全事件）** | AuthLoginAttempt 是认证中心实例自身库的登录尝试计数；SecurityLog 是安全事件日志——互补不重叠 |
| **RateLimiting（Web 限流）** | RateLimiting 是 Web 层中间件（IP/用户分区 429）；认证中心登录保护是 Domain 层窗口计数——双层互补 |

## 六、DMP-Lite 迁移指引（本扩展完成后 DMP 改用本扩展）

| DMP 组件 | 处置 |
|---------|------|
| `ITokenService/TokenService`（内存密钥/黑名单） | 替换为 Ext `TokenService`（持久化密钥/黑名单 + DataService 委托） |
| `ISessionExchangeService`（仅接口） | 替换为 `ITokenVerifier` + `JwtDomainUserParser` |
| `GlobalUserMap` | 替换为 `PlatformAccountMap`（统一映射表承载；会员外键迁入） |
| `PlatformCredential` + `WeChatApiClient` | 替换为 Ext（SG1 化 + AES-GCM + DataService 委托） |
| `PlatformAdmin` | 本地映射（`IAuthorizationMapper.MapRoles` 映射 SuperAdmin/Operator——Ext 不感知管理员角色） |
| `AuthEndpoints/UserEndpoints` | 装配层重写为消费 Ext Service |

> ⚠️ **迁移破坏性影响（Oracle C7 声明）**：
> 1. **密钥交接不可行 → 全部存量 access token 失效**（DMP 密钥内存生成无 PEM 可导出）——选低峰窗口迁移 + 提前公告重登；refresh 可保留（SHA256 hash 迁移 + TokenVersion 初始化对齐则可续）。
> 2. `PlatformAdmin` 表保留为 DMP 本地表（AuthAccount 只承载"你是谁"）。
> 3. 会员外键拆除（`MemberUser.UId ↔ MemberInfo.MemberUId` JOIN 改经 `PlatformAccountMap` 查询）——列出受影响查询清单 + 改造量评估后再动。
> 4. **TokenVersion 初始化对齐**：DMP `PlatformAdmin.TokenVersion` 从未自增——迁移时 `AuthAccount.TokenVersion = 0` + `AuthRefreshToken.TokenVersion = 0` 对齐，否则迁移后所有 refresh 立即失效。

## 七、故障排查

| 症状 | 原因 | 处置 |
|------|------|------|
| 启动抛 `Issuer 未配置` / `SigningKeyPath 未配置` | 生产 fail-fast 门 | 配置 `TKWF:AuthCenter` 的 Issuer + 密钥路径 |
| `ITokenVerifier 未注册——JWT 恢复路径跳过` | 未启用认证中心扩展（Domain 钩子注册缺失） | 白名单声明 `[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]` |
| Bearer 请求 401 | 令牌无效/过期/黑名单 | 检查令牌；重新登录签发 |
| `SMS_SENDER_NOT_CONFIGURED` | 生产未装配 ISmsSender | 实现并注册 ISmsSender |
| `SMS_RESEND_TOO_FREQUENT` | 60s 重发间隔 | 等待或调大 `SmsResendIntervalSeconds` |
| `REFRESH_REUSED` | 旧 refresh 重用（或泄露） | 重新登录；检查日志 Warning（泄露告警） |
| `REFRESH_STALE` | TokenVersion 不匹配（密码/绑定变更） | 重新登录签发 |
| `TICKET_STATE_MISMATCH` | PKCE verifier / state / app_id 不匹配 | 核对换取参数（静态站必传 verifier） |
| `KID_UNKNOWN` | 验签密钥不在 SigningKeys | 检查 kid 配置（多实例密钥同步） |
