# Authentication v0.3.2 —— 扩展手写门面接口补 IDomainService 契约（开发方案）

> **扩展**：`TKWF.Ext.Authentication`（主）｜**版本**：v0.3.2（契约补齐，单行变更）
> **触发**：EduPlatform 转告（`转告-认证扩展门面补IDomainService契约-框架扩展模块组.md`，2026-10-02）
> **范围裁定**：用户指示「综合多想想，将类似情况一并处理」——**跨扩展全量**（所有构造注入 DataService 的手写门面接口一律补 `: IDomainService`，不留 CS0311 隐患）

---

## 一、本版目标

- 为 3 个认证扩展门面接口（`ISmsVerificationService` / `IOAuthTicketService` / `IPlatformCredentialService`）补 `: IDomainService` 空标记继承——使其成为 `DomainUser.Use<TService>() where TService : IDomainService` 的合法 `T`，解除消费方编译期 CS0311 阻塞。
- 完成定义（DoD）：3 接口各增 `: IDomainService` + `using TKW.Framework.Domain.Interfaces`；slnx 构建 0 错误；Authentication 测试全绿 + 全量回归零破坏；消费方（DLL refs）编译兼容。

## 二、范围

### 包含

- 3 接口空标记继承补齐（每接口一行 `: IDomainService` + using 补充）。
- 消费方 `user.Use<ISmsVerificationService>()` 等编译通过。

### 不包含

- `IAuthenticationProvider`（短信/微信 Provider）：`IEnumerable` 注入，不受 `Use<T>` 约束——**无需改**（转告 §四 边界确认）。
- 框架层改动：`IDomainService` 为框架空标记接口，**框架不替扩展声明谁继承它**（ADR47 扩展自描述——契约责任在接口定义方）。
- 表现层薄化（`UseRestApiService` 统一端点挂载）：转告 §五「后续架构迭代（可选）」，另行评估。

**跨扩展同类接口（用户裁定「一并处理」——全量消纳 CS0311 隐患）**：

> 判据（Oracle 评审）：**手写门面接口 + 构造注入 DataService** → 消费方经 `DomainUser.Use<T>()` 域通道解析必然 CS0311。空标记零副作用（只「允许走域通道」不强制），全标彻底消纳。
> 不标（Oracle 边界）：`IAuthenticationProvider`（IEnumerable 注入不受约束）、`IAuthorizationMapper<TUserInfo>`（消费方实现+泛型+TryAdd）、`IWeChatApiClient`（基础设施 HTTP 客户端）、`ISmsSender`（消费方实现渠道）、贡献者/Provider/Sender 回调类接口。
