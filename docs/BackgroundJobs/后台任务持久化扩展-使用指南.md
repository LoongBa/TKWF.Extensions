# 后台任务持久化扩展使用指南

## 概述

`TKWF.Ext.BackgroundJobs` 为 TKWF 后台任务提供**执行历史审计**和**业务结果追踪**能力，补齐主框架三实现（内置/ Hangfire / Quartz）的持久化缺口。

### 核心能力

- **自动落库**：每次作业执行完成后，`JobExecutionRecorder` 自动记录执行历史（耗时/重试/异常归档）
- **业务结果记录**：作业内通过 `IJobResultRecorder` 显式记录业务产出（JSON + 摘要）
- **SQL 级聚合统计**：执行历史统计（成功/失败/取消计数 + 平均/最大耗时）在数据库层完成
- **分页过滤查询**：支持按 JobId/JobType/Provider/IsSuccess/IsCancelled/TenantId/时间范围过滤

## 快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\BackgroundJobs\TKWF.Ext.BackgroundJobs.csproj" />
```

### 2. 启用扩展

```csharp
using TKWF.Ext.BackgroundJobs;

[TKWFEnabledExtension(typeof(BackgroundJobsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后，以下服务自动注册：
- `IBackgroundJobExecutionListener` → `JobExecutionRecorder`（自动落库）
- `IJobResultRecorder` → `JobResultRecorder`（作业内记录）
- `IJobExecutionQueryService` → `JobExecutionQueryService`（查询）
- `IJobResultQueryService` → `JobResultQueryService`（结果查询）
- `IJobHistoryCleanupService` → `JobHistoryCleanupService`（历史清理，v0.2.0）

### 3. 记录业务结果（可选）

在作业执行过程中，通过 `IJobResultRecorder` 记录业务产出：

```csharp
public class DataSyncJob : IBackgroundJob
{
    private readonly IJobResultRecorder _recorder;

    public DataSyncJob(IJobResultRecorder recorder) => _recorder = recorder;

    public async Task ExecuteAsync(IDictionary<string, string> args, CancellationToken ct)
    {
        // ... 业务逻辑 ...
        var result = new { SyncedCount = 100, FailedCount = 2 };

        // 记录业务产出（JobId 从 BackgroundJobContext.Current 自动读取）
        await _recorder.RecordAsync(
            "success",
            JsonSerializer.Serialize(result),
            $"同步完成: {result.SyncedCount} 条",
            ct);
    }
}
```

> **注意**：`IJobResultRecorder.RecordAsync` 必须在后台作业执行上下文内调用（即 `BackgroundJobContext.Enter` 之后），否则抛出 `InvalidOperationException`。

### 4. 查询执行历史

```csharp
public class ExecutionMonitorService
{
    private readonly IJobExecutionQueryService _queryService;

    public ExecutionMonitorService(IJobExecutionQueryService queryService)
        => _queryService = queryService;

    /// <summary>获取最近 24 小时统计</summary>
    public async Task<JobExecutionStats> GetDailyStatsAsync()
        => await _queryService.GetStatsAsync(TimeSpan.FromHours(24));

    /// <summary>按 Provider 过滤查询</summary>
    public async Task<JobExecutionPagedResult> SearchByProviderAsync(string provider, int skip = 0, int take = 50)
        => await _queryService.GetListAsync(new JobExecutionQueryInput(
            Provider: provider, Skip: skip, Take: take));

    /// <summary>查询失败执行详情（含错误信息）</summary>
    public async Task<JobExecutionDetailDto?> GetFailureDetailAsync(long id)
        => await _queryService.GetDetailAsync(id);
}
```

### 5. 查询业务结果

```csharp
public class ResultQueryService
{
    private readonly IJobResultQueryService _resultQuery;

    public ResultQueryService(IJobResultQueryService resultQuery)
        => _resultQuery = resultQuery;

    /// <summary>按 JobId 查最新结果</summary>
    public async Task<JobResultListItemDto?> GetLatestResultAsync(string jobId)
        => await _resultQuery.GetLatestAsync(jobId);

    /// <summary>按结果类型分页查询</summary>
    public async Task<JobResultPagedResult> SearchByTypeAsync(string resultType)
        => await _resultQuery.GetListAsync(new JobResultQueryInput(ResultType: resultType));
}
```

## 配置

```json
{
  "TKWF": {
    "BackgroundJobs": {
      "RetentionDays": 180,
      "CleanupBatchSize": 500
    }
  }
}
```

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| RetentionDays | 180 | 执行历史保留天数（v0.2.0 起由 `IJobHistoryCleanupService` 消费，超过则物理删除） |
| CleanupBatchSize | 500 | 历史清理分批大小（v0.2.0——每轮每表最多删除条数，防大表一次性删爆事务） |

### 历史清理（v0.2.0）

扩展**不内建调度器**——`IJobHistoryCleanupService` 由消费方定时调用（BackgroundJob/Quartz/Hangfire 均可）。清理逻辑：按 `RetentionDays` 计算 `cutoff = UtcNow - RetentionDays`，分表（JobExecution 锚点 `StartedAtUtc` / JobResult 锚点 `CreateTime`）分批循环物理删除直至清空；单表失败 LogWarning 静默，不阻断另一表。

```csharp
// 注入服务后由定时任务调用
public class HistoryCleanupTask : IBackgroundJob
{
    private readonly IJobHistoryCleanupService _cleanupService;

    public HistoryCleanupTask(IJobHistoryCleanupService cleanupService) => _cleanupService = cleanupService;

    public async Task ExecuteAsync(IDictionary<string, string> args, CancellationToken ct)
        => await _cleanupService.CleanupAsync(ct);
}
```

接线到调度器：

```csharp
// 内置 BackgroundJobWorker：把清理任务注册为定时作业（用法对齐主框架 AddBackgroundJob 约定）
builder.Services.AddBackgroundJobs<MyUserInfo>();
// 扩展初始化器已 TryAddScoped 注册 IJobHistoryCleanupService，消费方直接注入到作业即可

// Hangfire：RecurringJob 定时调用
RecurringJob.AddOrUpdate<IJobHistoryCleanupService>("history-cleanup",
    svc => svc.CleanupAsync(CancellationToken.None), Cron.Daily(3)); // 每日 03:00

// Quartz：IJob 实现 + CronTrigger（作业内注入 IJobHistoryCleanupService）
// var trigger = TriggerBuilder.Create().WithCronSchedule("0 0 3 * * ?").Build();
// await scheduler.ScheduleJob(job, trigger);
```

> **建议**：清理作业与业务作业分开注册；`CleanupBatchSize` 按表规模调整（默认 500 已是分批保护，无需显式改动）。

## 三实现接线示例

### 内置 BackgroundJobWorker

```csharp
// Program.cs
builder.Services.AddBackgroundJobs<MyUserInfo>();
// BackgroundJobsExtensionInitializer 通过 [TKWFEnabledExtension] 白名单启用
// 内置 Worker 执行后自动触发 IBackgroundJobExecutionListener → JobExecutionRecorder 落库
```

### Hangfire

```csharp
// Program.cs
builder.Services.AddHangfireBackgroundJobs<MyUserInfo>(config =>
{
    config.UseSqlServerStorage(connStr);
});
// Hangfire 桥执行后自动触发 IBackgroundJobExecutionListener → JobExecutionRecorder 落库
```

### Quartz

```csharp
// Program.cs
builder.Services.AddQuartzBackgroundJobs<MyUserInfo>(null, q =>
{
    q.UseTkfwAdoJobStore(o =>
    {
        o.DbProvider = "sqlserver";
        o.ConnectionString = connStr;
    });
});
// Quartz 桥执行后自动触发 IBackgroundJobExecutionListener → JobExecutionRecorder 落库
```

## 注意事项

1. **JobId 格式因 Provider 而异**：内置=`JobRecord.JobId`（Guid N）/ Hangfire=`PerformContext.BackgroundJob.Id`（数字字符串）/ Quartz=`JobKey.Name`（Guid N）。跨 Provider 查询按 `Provider` 字段区分。

2. **列表 DTO 不含 ErrorText**：安全决策（对齐 AuditLogging 先例），详情通过 `GetDetailAsync(id)` 按 Id 取全量。

3. **统计 SQL 级聚合**：`GetStatsAsync` 在数据库层完成（`Dac.CountAsync` SQL COUNT 分区计数 + FreeSql ISelect 原生 `AVG/MAX` 下推——ADR15 聚合 API 分层，IQueryable 桥接不支持 GroupBy 翻译），不拉取全表到内存。

4. **异常静默**：`JobExecutionRecorder` 和 `JobResultRecorder` 的异常不会阻断作业执行，仅记录 ILogger.Warning。

5. **多监听器叠加**：`TryAddEnumerable` 注册，消费方可添加自定义 `IBackgroundJobExecutionListener` 实现。

## 生产部署建议

- `RetentionDays` v0.2.0 已启用——配合 `IJobHistoryCleanupService` 定时清理，避免历史表无限增长
- `IX_JobResult_CreateTime` 索引 v0.2.0 补齐——清理 JobResult 走时间锚点
- 建议配合数据库索引（IX_JobExecution_StartedAt）优化时间范围查询
- 大规模部署建议按时间分区（按月/按季度）管理 JobExecution 表
- 生产环境首次启用前，建议先小批量（调低 `CleanupBatchSize`）验证清理行为
