# 数据字典扩展使用指南

> **扩展**: `TKWF.Ext.DataDictionary` | **版本**: V0.2.0 | **框架**: .NET 10

本指南帮助消费方集成数据字典扩展，集中管理枚举/下拉/参考数据（性别、状态、类型、国家地区等），并支持**按 Code 内存缓存**与**树形分组**（多级字典项）。

---

## 一、能力概览

| 能力 | 说明 |
|------|------|
| 字典定义 | 编码/名称/描述/启用——`DictionaryDefinitionEntity` |
| 字典项 | 归属定义的选项（编码/显示名/值/排序/启用）——`DictionaryItemEntity` |
| 按编码查询 | `GetDefinitionWithItemsAsync(code)` 一次返回定义 + 排序后的项 |
| 内存缓存（V0.2.0） | 按 Code 缓存聚合（key=`DD:{Code}`），高频读取命中缓存，写入后按 Code 失效 |
| 树形分组（V0.2.0） | `GetItemsTreeAsync(code)` 从平铺列表递归组装嵌套树（省市区/组织架构/分类目录） |
| Upsert 幂等 | 定义按 Code、项按 DefinitionId+Code——重复提交更新而非报错 |

---

## 二、安装

### 2.1 引用扩展项目

```xml
<!-- 消费方 .csproj -->
<ItemGroup>
  <ProjectReference Include="..\..\_Framework\DataDictionary\TKWF.Ext.DataDictionary.csproj" />
</ItemGroup>
```

### 2.2 启用扩展（v4.9.85+ 必需）

> **V4.9.85 (ADR47) 起**：扩展不再"发现即启用"。消费方需在领域初始化器上显式声明 `[TKWFEnabledExtension]`，扩展才进入白名单（三钩子执行）。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.DataDictionary;

[TKWFEnabledExtension(typeof(DataDictionaryExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

自动注册：`IDictionaryStore`（默认 `FreeSqlDictionaryStore`）+ `IDictionaryManager`（默认 `DictionaryManager`）+ `IMemoryCache`（TryAddSingleton，消费方已注册则不覆盖）+ `DataDictionaryOptions`。

## 三、使用

### 3.1 读取字典（业务侧）

```csharp
// 注入 IDictionaryManager
public class OrderFormService(IDictionaryManager dictionaryManager)
{
    // 一次返回完整字典（定义 + 排序后的项）
    public async Task<DictionaryDefinitionWithItems?> GetGenderOptionsAsync()
        => await dictionaryManager.GetDefinitionWithItemsAsync("Gender");

    // 仅取项列表（按 Order 排序，不含禁用项）
    public async Task<IReadOnlyList<DictionaryItemEntity>> GetStatusItemsAsync()
        => await dictionaryManager.GetItemsAsync("OrderStatus");
}
```

### 3.2 树形查询（V0.2.0，需 `EnableTreeMode=true`）

```csharp
// 读取树形字典（返回嵌套树，根节点 = ParentCode 为 null 的项）
public async Task<IReadOnlyList<DictionaryTreeNode>> GetRegionTreeAsync()
    => await dictionaryManager.GetItemsTreeAsync("Region");
```

`DictionaryTreeNode` 结构：`Code` / `DisplayName` / `Value` / `Order` / `IsEnabled` / `Children`（叶子节点 Children 为空列表）。

**树形字段约定**（写入字典项时维护）：

| 字段 | 说明 | 根节点 |
|------|------|--------|
| `ParentCode` | 父项的业务编码（非 Id） | null |
| `Level` | 层级深度 | 0 |
| `Path` | 物化路径，形如 `/root/child/grandchild` | `/{Code}` |

> 树形在 Manager 内存递归组装（复用平铺列表，Store 无递归 SQL），**ParentCode 为空或指向不存在父项的字典项自动归根**（作为根节点，不丢失）。

**`EnableTreeMode=false` 降级行为（D7）**：`GetItemsTreeAsync` 返回平铺列表——每项转为 `DictionaryTreeNode` 且 `Children` 为空列表；与 `GetItemsAsync` 内容一致但类型不同。V0.1.0 消费方迁移无需改动 `GetItemsAsync`（平铺行为不变）。

### 3.3 维护字典（管理侧）

```csharp
// 新增/更新字典定义（按 Code 幂等）
await dictionaryManager.UpsertDefinitionAsync(new DictionaryDefinitionEntity
{
    Code = "Gender",
    DisplayName = "性别",
    Description = "用户性别选项"
});

// 新增/更新字典项（按 DefinitionId + Code 幂等）
await dictionaryManager.UpsertItemAsync(new DictionaryItemEntity
{
    DefinitionId = genderDef.Id,
    Code = "Male",
    DisplayName = "男",
    Order = 1
});

// 删除（V0.2.0 起 Manager 提供删除门面，删除后自动失效缓存）
await dictionaryManager.DeleteItemAsync(itemId);
await dictionaryManager.DeleteDefinitionAsync(defId); // 级联清理其项
```

> 写入方法（Upsert/Delete）执行后自动按 Code 失效缓存——任一项变更即刷新该定义下所有缓存；`DeleteItem` 先反查所属定义再失效，反查失败时由缓存过期兜底（默认 300s）。

### 3.4 配置选项（V0.2.0）

扩展注册 `DataDictionaryOptions` 默认值；消费方在自身 `ConfigureServices` 中绑定 `appsettings.json`：

```csharp
services.Configure<DataDictionaryOptions>(configuration.GetSection("TKWF:DataDictionary"));
```

```json
{
  "TKWF": {
    "DataDictionary": {
      "IsEnabled": true,
      "EnableCache": true,
      "CacheExpirationSeconds": 300,
      "EnableTreeMode": false
    }
  }
}
```

| 配置项 | 默认值 | 说明 |
|--------|--------|------|
| `IsEnabled` | `true` | 是否启用数据字典 |
| `EnableCache` | `true` | 是否启用按 Code 内存缓存；关闭后每次查库（调试/测试场景） |
| `CacheExpirationSeconds` | `300` | 缓存过期时间（秒），仅 `EnableCache=true` 时生效 |
| `EnableTreeMode` | `false` | 是否启用树形模式；`false` 时 `GetItemsTreeAsync` 降级为平铺列表 |

### 3.5 自定义 IDictionaryStore / IDictionaryManager / IMemoryCache

TryAdd 语义确保消费方实现优先：

```csharp
services.AddScoped<IDictionaryStore, MyRedisDictionaryStore>();     // 覆盖默认 FreeSql 存储
services.AddScoped<IDictionaryManager, MyDictionaryManager>();      // 覆盖默认 Manager
services.AddSingleton<IMemoryCache, MyDistributedCacheAdapter>();   // 覆盖默认内存缓存（先于扩展注册）
```

## 四、实体表结构

| 表 | 说明 | 关键列 |
|----|------|--------|
| `DictionaryDefinition` | 字典定义 | Code（唯一）/ DisplayName / Description / IsEnabled |
| `DictionaryItem` | 字典项 | DefinitionId（索引）/ Code / DisplayName / Value? / Order / IsEnabled / **ParentCode? / Level / Path**（V0.2.0 树形字段） |

两表经 SG1 + `FreeSqlTableStructureSynchronizer` 自动建表；V0.2.0 三列可空或带默认值，对已存在表自动 ALTER 加列，**不影响现有数据**。

---

## 五、安全语义

- **异常静默**：存储/管理操作失败记录 Warning 日志，不阻塞业务
- **TryAdd 语义**：消费方自定义 `IDictionaryStore`/`IDictionaryManager`/`IMemoryCache` 优先
- **Scoped 生命周期**：`IDictionaryStore`/`IDictionaryManager` Scoped；`IMemoryCache` Singleton
- **Upsert 幂等**：重复提交更新而非报错
- **缓存一致性**：读取命中 `DD:{Code}` 缓存；Upsert/Delete 后按 Code 失效；反查失败靠过期兜底

## 六、常见问题

**Q: 下拉选项如何保证排序稳定？**
A: 字典项 `Order` 字段控制排序（小值在前）；`GetItemsAsync`/`GetDefinitionWithItemsAsync` 自动按 Order 返回。

**Q: 禁用字典项会怎样？**
A: 已禁用项从查询结果排除（`IsEnabled=false`），但仍保留在库中供恢复。

**Q: 能自定义字典存储吗？**
A: 可以实现自定义 `IDictionaryStore`（如 Redis 缓存后端）经 TryAdd 注册——扩展默认 FreeSql 实现不覆盖消费方。

**Q: 缓存如何失效？**
A: 读取按 Code 聚合缓存（key=`DD:{Code}`）；`UpsertDefinitionAsync`/`UpsertItemAsync`/`DeleteDefinitionAsync`/`DeleteItemAsync` 后按 Code 移除缓存。`DeleteItem` 需反查所属定义 Code（两次查询），失败时由过期兜底（默认 300s）。

**Q: 需要树形字典但不想开全局树形模式？**
A: 当前 `EnableTreeMode` 为全局配置；关闭时 `GetItemsTreeAsync` 降级返回平铺列表（每项 Children 为空）。若仅个别字典需要树形，可开启全局模式后对平级字典照常用 `GetItemsAsync`（互不影响）。
