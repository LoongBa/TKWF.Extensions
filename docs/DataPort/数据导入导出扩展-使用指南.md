## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\DataPort\TKWF.Ext.DataPort.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```csharp
using TKWF.Ext.DataPort;

[TKWFEnabledExtension(typeof(DataPortExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册（**V0.1.4 二态形态，V4.10.53 ADR90 领域自治根治**）：
- `IImportService`（Scoped）——导入服务（批次切分+类型转换+错误收集）；**接线型 `TryAddScoped`**（消费方可覆盖）
- `IExportService`（Scoped）——导出服务；**接线型 `TryAddScoped`**
- `IImportProvider`（Singleton）——MiniExcel 读取引擎；**接线型 `TryAddSingleton`**
- `IExportProvider`（Singleton）——MiniExcel 写入引擎；**接线型 `TryAddSingleton`**
- `IDataImportTaskService`——导入任务（批次记录+幂等+状态跟踪）：**`AddConstructibleService` 守卫工厂 + 实现 throw-factory**（域作用域外解析抛）——消费方经 **`User.Use<IDataImportTaskService>()` 解析（AOP 路径）**，禁构造注入（DI004）
- `DataPortOptions` 绑定 `TKWF:DataPort` 配置节

### 3. 实现导入适配器

消费方派生 `ImportAdapterBase<T>` 实现导入——不同业务各一派生类，便于管理与维护：

```csharp
using TKW.Framework.Utility.DataPort;

// 1. 定义目标实体
public sealed class PaymentLog
{
    public string OrderNo { get; set; } = "";
    public decimal TotalAmount { get; set; }
    public DateTime PayTime { get; set; }
}

// 2. 派生适配器——实现列映射+验证+批次写库
public sealed class PaymentImportAdapter : ImportAdapterBase<PaymentLog>
{
    private readonly IFreeSql _db;

    public PaymentImportAdapter(IFreeSql db) => _db = db;

    public override string DataSourceName => "美团支付";

    public override IReadOnlyDictionary<string, string> ColumnMapping { get; } =
        new Dictionary<string, string>
        {
            ["订单号"] = nameof(PaymentLog.OrderNo),
            ["金额"] = nameof(PaymentLog.TotalAmount),
            ["支付时间"] = nameof(PaymentLog.PayTime)
        };

    protected override ImportRowAction OnValidate(
        int rowIndex,
        IReadOnlyDictionary<string, object?> row,
        PaymentLog entity)
        => entity.TotalAmount > 0 ? ImportRowAction.Keep : ImportRowAction.Skip;

    public override Task OnBatchWrite(
        IReadOnlyList<PaymentLog> batch,
        CancellationToken ct)
        => _db.Insert(batch).ExecuteAffrowsAsync(ct);   // 消费方自管持久化
}
```

### 4. 执行导入

```csharp
// ⚠️ 禁构造注入 IDataImportTaskService——守卫工厂，域作用域外解析必抛（DI004）
// 正确形态：DomainServiceBase 派生 + 内部经 User.Use<IDataImportTaskService>() 解析
public class PaymentImporter : DomainServiceBase
{
    public PaymentImporter(IDomainUser user) : base(user) { }

    public async Task<DataImportTaskResult> ImportAsync(string filePath)
    {
        var result = await User.Use<IDataImportTaskService>()
            .ImportAsync(filePath, new PaymentImportAdapter(_db));

        // result.RecordId   — 批次记录 ID
        // result.BatchNo    — 批次号（回滚入口）
        // result.ImportResult.SuccessCount  — 验证通过行数
        // result.ImportResult.Failures      — 行级失败列表
        // result.ImportResult.BatchFailures — 批次级失败列表
        return result;
    }
}
```

## 二、核心概念

### 三层架构

| 层 | 项目 | 职责 | 依赖 |
|----|------|------|------|
| **核心运行库** | `TKWF.Utility.DataPort` | 批次切分算法+类型转换+三态验证+错误收集 | **零第三方依赖** |
| **MiniExcel Provider** | `TKWF.Utility.DataPort.Providers.MiniExcel` | Excel/CSV 读写引擎 | 核心 + MiniExcel |
| **扩展模块** | `TKWF.Ext.DataPort` | 批次记录持久化+FileHash 幂等+状态跟踪 | 核心 + Provider + FreeSql + SG1 |

### 模板方法模式（ImportAdapterBase\<T\>）

消费方派生 `ImportAdapterBase<T>` 实现 4 个钩子：

| 钩子 | 类型 | 说明 |
|------|------|------|
| `DataSourceName` | `string` 属性 | 数据源名称（如"美团支付"） |
| `ColumnMapping` | `IReadOnlyDictionary<string, string>` | Excel 列名 → 实体属性名映射 |
| `OnValidate` | `Func<int, IReadOnlyDictionary, T, ImportRowAction>` | 行验证：Keep（保留）/ Skip（跳过）/ Terminate（终止） |
| `OnBatchWrite` | `Func<IReadOnlyList<T>, CancellationToken, Task>` | 批次写库——消费方自管持久化 |

### 幂等检查

- **FileHash**（SHA256）唯一索引 `TKWFIX_Dir_Filehash`
- 同文件二次导入 → 返回已有批次（拒绝重复：Succeeded/Processing 拒绝不变）
- **V0.1.5 起 PartiallySucceeded 重导语义**：从"全量重导"改为**失败批次重放（批次级幂等）**——仅重放"失败 ∪ 未尝试尾部"批次，已成功批次消费方**零重复写**；Failed 保持全量重导
- 并发竞态 → re-query by FileHash 优雅降级

**重导流转示例**（V0.1.5）：

```csharp
using var taskService = User.Use<IDataImportTaskService>();

// 首次导入：BatchSize=2，批0 写库抛错 → PartiallySucceeded
var first = await taskService.ImportAsync(filePath, adapter,
    new ImportBatchOptions(BatchSize: 2, StopOnBatchFailure: false));
// 记录落库三新列：FailedBatchIndexes="[0]" / BatchSize=2 / MaxAttemptedBatchIndex=1

// 二次导入同文件（BatchSize 必须与首跑一致）→ 仅重放批0（批1 跳过）→ Succeeded
var second = await taskService.ImportAsync(filePath, adapter,
    new ImportBatchOptions(BatchSize: 2, StopOnBatchFailure: false));
```

**重放判据**（统一覆盖 continue / 早停(StopOnBatchFailure) / Terminate 一切中断源）：

```
replay(batchIndex) = batchIndex ∈ FailedBatchIndexes        // 失败批次重放
                  || batchIndex ≥ MaxAttemptedBatchIndex + 1 // 未尝试尾部纳集（早停不丢数据）
```

- 三新列：`FailedBatchIndexes`（JSON 数字数组，如 `"[0,2]"`）、`BatchSize`（首跑批次大小，重放一致性校验）、`MaxAttemptedBatchIndex`（首跑已尝试最大批次索引）
- **BatchSize 一致性约束**：重放时若传不同 BatchSize → 抛 `DataImportException`（防索引错位写错行），记录保持 PartiallySucceeded 可再尝试
- **兼容**：三新列均 null 的旧记录 → 全量重导（等效现状，升级零破坏）；`FailedBatchIndexes` 脏数据（解析失败）→ LogWarning + 降级全量重导
- **重放边界**：仅对同内容文件（FileHash 相同）+ 同 BatchSize + 同验证逻辑有效；消费方变更 `OnValidate`/`OnConvert` 行为或改文件 → 应改文件/换 BatchNo 全量重导

### 状态流转

```
Processing → Succeeded（全部成功，落 MaxAttemptedBatchIndex）
           → Failed（核心异常，三新列均 null）
           → PartiallySucceeded（批次回调异常，BatchFailures > 0，落 FailedBatchIndexes/MaxAttemptedBatchIndex）
           →(V0.1.5 超时回收)→ Failed（启动/周期扫描：Processing 超 60 分钟，ErrorSummary 含 "stale recovery"）
```

## 三、进阶用法

### 1. 定义回调模式（不派生适配器）

不需要派生适配器时，可直接使用 `IImportService` 的定义回调入口：

```csharp
public class SimpleImporter(IImportService importService)
{
    public async Task<ImportResult> ImportAsync(string filePath)
    {
        var definition = new ImportDefinition<PaymentLog>(
            new Dictionary<string, string>
            {
                ["订单号"] = nameof(PaymentLog.OrderNo),
                ["金额"] = nameof(PaymentLog.TotalAmount)
            },
            validate: (idx, vals, entity) =>
                entity.TotalAmount > 0 ? ImportRowAction.Keep : ImportRowAction.Skip);

        return await importService.ImportAsync(filePath, definition,
            (batchIndex, startRowIndex, batch, ct) =>
            {
                // 批次写库逻辑
                return Task.CompletedTask;
            },
            new ImportBatchOptions(BatchSize: 500));
    }
}
```

### 2. 导出

```csharp
public class PaymentExporter(IExportService exportService)
{
    public async Task ExportAsync(Stream output, IReadOnlyList<PaymentLog> rows)
    {
        var definition = new ExportDefinition<PaymentLog>(
            new Dictionary<string, string>
            {
                ["OrderNo"] = "订单号",
                ["TotalAmount"] = "金额"
            });

        await exportService.ExportAsync(output, "payments.xlsx", rows, definition);
    }
}
```

> ⚠️ **导出公式注入边界（安全）**：导出单元格以 `=` 开头的内容可能被 Excel 解释执行（CSV/公式注入）——**数据源自用户输入时注意消毒**（如首字符 `=`/`+`/`-`/`@` 前置 `'` 或空格）。

### 3. 批次控制

```csharp
// ImportBatchOptions 三参：BatchSize / StopOnBatchFailure / SkipValidationErrors
var options = new ImportBatchOptions(
    BatchSize: 500,               // 每批处理行数
    StopOnBatchFailure: false,    // 批次回调异常时是否终止
    SkipValidationErrors: true    // true=Skip 行收集 failure 继续（默认）；false=首个 Skip 行终止导入
);

// ⚠️ DataPortOptions 无 SkipValidationErrors 配置项——经 ImportBatchOptions 显式传
var result = await User.Use<IDataImportTaskService>().ImportAsync(filePath, adapter, options);
```

### 4. 回滚（按批次号）

```csharp
var record = await User.Use<IDataImportTaskService>().GetRecordByBatchNoAsync(batchNo);
// 消费方按 BatchNo 删自己业务表数据 → 更新/删除批次记录
```

### 5. 配置选项

通过 `appsettings.json` 配置（`TKWF:DataPort` 节）：

```json
{
  "TKWF": {
    "DataPort": {
      "DefaultBatchSize": 500,
      "StopOnBatchFailure": false,
      "ProcessingTimeoutMinutes": 60,
      "HeartbeatIntervalMinutes": 1
    }
  }
}
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `DefaultBatchSize` | 500 | 默认批次大小（每批处理行数，≥1） |
| `StopOnBatchFailure` | false | 批次回调异常时是否终止 |
| `ProcessingTimeoutMinutes` | 60 | Processing 超时（分钟）——启动/周期扫描时超时记录重置为 Failed（0 = 禁用恢复扫描） |
| `HeartbeatIntervalMinutes` | 1 | 导入心跳间隔（分钟）——导入执行中每批检查刷新 UpdateTime（0 = 禁用心跳） |

### 6. 超时治理（V0.1.5 DP-05）

进程崩溃 → 导入记录冻结在 Processing → 同文件永远无法再导入（旧版无解锁路径）。V0.1.5 引入三层治理：

- **恢复门面** `IStaleImportRecoveryService`：`RecoverStaleImportsAsync()` 重置超时 Processing → Failed（错误摘要含 "stale recovery" + EndTime）。**CAS 条件更新**（WHERE Status='Processing' AND UpdateTime < 阈值）——活跃任务/并发终态不会被覆写，影响行数判竞态。消费方经 `User.Use<IStaleImportRecoveryService>()` 解析（AddConstructibleService）。
- **导入心跳**：导入执行中 onBatch 内周期条件刷新 `UpdateTime`（仅 Processing 态，默认 1 分钟）——健康进行的导入恒新、恢复扫描天然跳过（避免超长合法导入被误清；无法接受误清的消费方可调大超时阈值或置 0 禁用恢复扫描）。
- **启动扫描**：Initializer `InitializeAsync` 在消费方白名单启用后执行一次恢复（SystemUser + 异常静默 LogWarning，绝不阻断宿主启动）——进程崩溃 → 下次启动即治愈。**⚠️ 周期兜底需消费方自行调度**（扩展不内建调度器，对齐 BackgroundJobs `IJobHistoryCleanupService` 先例）：

```csharp
public class StaleImportRecoveryTask : DomainServiceBase   // 消费方定时任务（BackgroundJob/Quartz/Hangfire）
{
    public StaleImportRecoveryTask(IDomainUser user) : base(user) { }

    public async Task RecoverAsync(CancellationToken ct)
        => await User.Use<IStaleImportRecoveryService>().RecoverStaleImportsAsync(ct);
}
```

### 7. 恢复与重导（P1-4 双写警示）

> ⚠️ **恢复后全量重导双写**：Processing 超时被恢复扫描标记为 Failed（`ErrorSummary` 含 **"stale recovery"** 标记 = 崩溃前可能已有部分批次写入）→ 再导入同文件 = **全量重导**（Failed 语义）→ 对崩溃前已写批次**重复写**。**非幂等 `OnBatchWrite`（如直接 Insert）消费方须先按 `BatchNo` 回滚（删除已落数据）再重导**；`ErrorSummary` 的 "stale recovery" 标记指示部分进度；幂等消费方（OnBatchWrite 天然去重）可直接重导。

## 四、与 ExcelTools 的关系

| 项目 | ExcelTools | DataPort |
|------|-----------|----------|
| 定位 | 只读工具类（静态方法） | 读写框架（批次+持久化+幂等） |
| 引擎 | ExcelDataReader | MiniExcel |
| 批次 | 无 | 支持（BatchSize 切分） |
| 持久化 | 无 | 扩展模块（SG1 实体+状态跟踪） |
| 幂等 | 无 | FileHash 唯一索引 |
| 集成模式 | 直接调用 | 模板方法派生适配器 |

**迁移建议**：现有 ExcelTools 代码**保持不动**，新业务优先使用 DataPort；存量代码按需逐步迁移。

## 五、常见问题

### Q: 为什么 OnBatchWrite 是 public virtual 而不是 protected virtual？

ImportService 通过委托 `(_, _, batch, ct) => adapter.OnBatchWrite(batch, ct)` 调用，需要 public 可见性。这是设计选择——消费方可直接调用（不推荐），但主要用途是 ImportService 内部调度。

### Q: MiniExcel Provider 是流式的吗？

MiniExcel 的 `QueryAsync` 返回 `Task<IEnumerable>`（库内部缓冲）。DataPort Provider 直接 yield 结果，不额外缓冲。核心 `ImportService` 逐行处理（真正流式）。对于超大文件，内存占用取决于 MiniExcel 库本身的缓冲策略。

### Q: 并发导入同一文件会怎样？

唯一索引保证只有一条记录。第二个导入会 re-query 返回已有批次（幂等），不会抛异常。

### Q: 导入失败抛什么异常？

核心导入失败统一抛 **`DataImportException`**（核心运行库导出的导入异常类型——含批量失败明细）；消费方可捕获该异常并据 `BatchNo` 回滚（§三.4）。而批次级持久化失败不抛异常——收集为 `ImportResult.BatchFailures`，状态置 PartiallySucceeded（`StopOnBatchFailure` 控制终止/继续）。
