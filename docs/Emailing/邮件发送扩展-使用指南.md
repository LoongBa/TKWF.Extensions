# 邮件发送扩展使用指南

> **扩展**: `TKWF.Ext.Emailing` | **版本**: V0.3.0 | **框架**: .NET 10

本指南帮助消费方快速集成邮件发送扩展，实现 SMTP 邮件发送与记录持久化。

---

## 一、安装

### 1.1 引用扩展项目

```xml
<!-- 消费方 .csproj -->
<ItemGroup>
  <ProjectReference Include="..\..\_Framework\Emailing\TKWF.Ext.Emailing.csproj" />
</ItemGroup>
```

### 1.2 引用扩展包

> 📌 **公共接线机制**见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二。

白名单声明 + `registry.Enable("Emailing")` 后自动注册：`IEmailSender` → `SmtpEmailSender`（TryAddScoped）。邮件记录（`EmailRecord`）经 SG1 生成的 `EmailRecordEntityDataService` 读写（`User.Use<EmailRecordEntityDataService>()`）——**`IEmailRecordStore`/`EmailRecordStore` 已删除**（A5 Store-debt cleanup），不再对外暴露该契约。

### 1.3 启用扩展（v4.9.85+ 必需）

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.Emailing;

[TKWFEnabledExtension(typeof(EmailingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

## 二、配置

### 2.1 appsettings.json

```json
{
  "TKWF": {
    "Emailing": {
      "SmtpHost": "smtp.example.com",
      "SmtpPort": 587,
      "SmtpUser": "user@example.com",
      "SmtpPassword": "your-password",
      "DefaultFrom": "noreply@example.com",
      "UseSsl": false,
      "IsEnabled": true
    }
  }
}
```

### 2.2 配置选项说明

| 配置项 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| SmtpHost | string | "" | SMTP 服务器主机名 |
| SmtpPort | int | 587 | SMTP 服务器端口 |
| SmtpUser | string | "" | SMTP 认证用户名 |
| SmtpPassword | string | "" | SMTP 认证密码 |
| DefaultFrom | string | "" | 默认发件人地址 |
| UseSsl | bool | false | SSL 连接模式（V0.1.1 起）：true = `SslOnConnect`（465 端口隐式 SSL），false = `StartTls`（587 标准） |
| IsEnabled | bool | true | 是否启用邮件发送 |
| RetryCount | int | 0 | 失败后额外重试次数（0 = 不重试，V0.1.x 默认行为）。总发送尝试次数 = RetryCount + 1 |
| RetryBaseDelayMilliseconds | int | 1000 | 指数退避基数（毫秒）：第 i 次重试前等待 `RetryBaseDelayMilliseconds * 2^(i-1)` 毫秒（如 1000 → 重试序列 1s、2s、4s…）。测试或低延迟场景可设 0/1 跳过等待 |

## 三、发送邮件

### 3.1 基本发送

```csharp
public class NotificationService(IEmailSender emailSender)
{
    public async Task SendWelcomeEmailAsync(string userEmail)
    {
        await emailSender.SendAsync(new EmailMessage
        {
            To = userEmail,
            Subject = "Welcome!",
            Body = "<h1>Welcome to our platform!</h1>",
            IsHtml = true
        });
    }
}
```

### 3.2 纯文本邮件

```csharp
await emailSender.SendAsync(new EmailMessage
{
    To = "user@example.com",
    Subject = "Password Reset",
    Body = "Your password reset code is: 123456",
    IsHtml = false
});
```

### 3.3 自定义发件人

```csharp
await emailSender.SendAsync(new EmailMessage
{
    To = "user@example.com",
    From = "custom@example.com",  // 覆盖 DefaultFrom
    Subject = "Custom Sender",
    Body = "Hello!"
});
```

### 3.4 多收件人

```csharp
await emailSender.SendAsync(new EmailMessage
{
    To = "user1@example.com,user2@example.com,user3@example.com",
    Subject = "Broadcast",
    Body = "Hello everyone!"
});
```

## 四、邮件记录查询

记录经 SG1 生成的 `EmailRecordEntityDataService` 读取（**无 Store 契约**，`IEmailRecordStore` 已删除）。在领域服务（`DomainServiceBase`）内懒加载：

```csharp
internal sealed class EmailHistoryService : DomainServiceBase
{
    private EmailRecordEntityDataService? _records;
    private EmailRecordEntityDataService Records => _records ??= User.Use<EmailRecordEntityDataService>();

    public EmailHistoryService(IDomainUser user) : base(user) { }

    // 全部（上限 1000 条）
    public Task<List<EmailRecordEntity>> GetAllRecordsAsync(CancellationToken ct = default)
        => Records.GetListByStatusAsync(null, ct);

    // 按状态过滤（"Failed"/"Sent" 等；上限 1000 条）
    public Task<List<EmailRecordEntity>> GetByStatusAsync(string status, CancellationToken ct = default)
        => Records.GetListByStatusAsync(status, ct);

    // 按 ID 查询
    public Task<EmailRecordEntity?> GetAsync(long recordId, CancellationToken ct = default)
        => Records.GetEntityByIdAsync(recordId, ct);
}
```

> 需由消费方注册 `IEntityDAC<EmailRecordEntity>`（`UseFreeSqlEntityDAC()`）。

## 五、自定义实现

### 5.1 自定义 IEmailSender

若需替换 SMTP 发送（如 SendGrid、Amazon SES）：

```csharp
// 消费方 ConfigureServices 中
services.AddScoped<IEmailSender, SendGridEmailSender>();
```

TryAdd 语义确保消费方实现优先。

### 5.2 自定义元数据存储

`IEmailRecordStore`/`EmailRecordStore` 已删除（A5 Store-debt cleanup），**不存在可替换的 Store 契约**。需要自定义记录持久化时，在消费方实现自己的实体 + SG1 DataService（tkwf-entity / tkwf-service），由业务服务经 `User.Use<TDataService>()` 组合；扩展侧不提供该扩展点。

## 六、异常处理

扩展采用**异常静默**模式：

- 邮件发送失败时记录 Warning 日志，**不抛出异常**
- 邮件记录保存失败时记录 Warning 日志，**不抛出异常**
- 业务调用不会因邮件发送失败而中断

**发送重试语义（V0.2.0）**：

- 配置 `RetryCount > 0` 时，发送失败按 `RetryBaseDelayMilliseconds` 指数退避自动重试（总尝试 = `RetryCount + 1`），期间 `record.RetryCount` 递增记录实际失败次数
- 中途成功 → 落库 `Sent` + `SendTime`；重试耗尽仍失败 → 落库 `Failed` + `ErrorMessage` + Warning（仍不抛给调用方）
- 传入的 `CancellationToken` 取消时**不再重试**——走最终失败分支静默保存 `Failed`（终态保存不依赖取消令牌，保证记录落库）
