# 功能管理扩展使用指南

> `TKWF.Ext.FeatureManagement`——特性开关：编译期 Contributor 定义声明 + 分层值（Global/Tenant/Role/User）+ `[RequireFeature]` 过滤器接入 + 管理 API。
> 版本 v0.1.0｜设计依据 [ADR-FeatureManagement-范围裁定与设计](../../../_TKWF/docs/03_扩展模块/FeatureManagement/ADR/ADR-FeatureManagement-范围裁定与设计.md)

---

## 1. 快速开始

### 1.1 引用

```xml
<ProjectReference Include="..\..\_Framework\FeatureManagement\TKWF.Ext.FeatureManagement.csproj" />
```

### 1.2 启用（v4.9.85+ 白名单声明）

```csharp
using TKWF.Ext.FeatureManagement;

[TKWFEnabledExtension(typeof(FeatureManagementExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后自动接线：Feature 定义收集 + `IFeatureManager`/`IFeatureChecker` 注册 + `AddFeatureCheck` 过滤器（消费方 `[RequireFeature]` 零改动接入）。

### 1.3 声明 Feature 定义

```csharp
[FeatureContributor]   // SG1 编译期收集（主框架 V4.9.114）
public class OrderFeatureContributor : IFeatureDefinitionContributor
{
    public void Define(FeatureDefinitionContext context)
    {
        context.Add(new FeatureDefinition
        {
            Name = "Order.NewCheckout",
            DisplayName = "新结算流程",
            Group = "Order",
            ValueType = FeatureValueType.Boolean,
            DefaultValue = "false"          // 默认关闭——fail-closed
        });
    }
}
```

### 1.4 使用

```csharp
// 方法级拦截（未启用 → FeatureDisabledException）
[RequireFeature("Order.NewCheckout")]
public Task CheckoutAsync() { ... }

// 编程式检查
public class MyService(IFeatureManager manager, IDomainUser user)
{
    public async Task<bool> IsBetaEnabled() => await manager.IsEnabledAsync("Beta.Preview", user);
    public async Task<string> GetTheme() => await manager.GetValueAsync("App.Theme", user, "light");
}
```

## 2. 分层值语义（Global → Tenant → Role → User）

| 层 | 说明 | ProviderKey |
|----|------|-------------|
| Global | 全局默认覆盖 | null |
| Tenant | 租户级（仅 `TenantId.HasValue` 时查询） | TenantId |
| Role | 角色级（多角色**遍历顺序**首个命中） | 角色名 |
| User | 用户级（最优先） | UserId |

**解析顺序（最优先）**：`User → Role → Tenant → Global → 默认值`。
**默认值**：显式 `defaultValue` 参数优先 → `FeatureDefinition.DefaultValue` → 空字符串。
**匿名用户**（`!IsAuthenticated`）：跳过 User/Role/Tenant 直查 Global。

```csharp
await manager.SetValueAsync("Order.NewCheckout", "true", FeatureProviders.Global, null);    // 全站开启
await manager.SetValueAsync("Order.NewCheckout", "false", FeatureProviders.User, "u-100");  // 指定用户关闭
await manager.SetValueAsync("Order.NewCheckout", "true", FeatureProviders.Role, "vip");     // 角色开启
var (value, provider) = await manager.GetEffectiveValueAsync("Order.NewCheckout", user);    // 命中层返回（管理显示）
```

## 3. 检查语义（fail-closed 铁律）

| 场景 | `IsEnabledAsync` 结果 |
|------|----------------------|
| 值 "true" | true |
| 值 "false" | false |
| 值存在但非布尔（如 "abc"） | **false（不跨层回退）** |
| 未定义 / 空名 | false（不抛异常） |
| 无 `FailClosedOnUndefined` 开关 | 恒 fail-closed（框架 `IFeatureChecker` 契约） |

> 无开关可翻转"未定义→true"——拼错的 Feature 名永远关闭（fail-closed 安全）。

## 6. 生产注意事项

- **多实例缓存边界（C5）**：值缓存为进程内 `IMemoryCache`——`SetValueAsync` 仅失效本实例缓存，其余实例至多 `CacheExpirationSeconds`（默认 300s）TTL 收敛。特性开关常作运营急停——即时全局生效建议临时缩短 TTL 或等待 v0.2.0 Feature 变更事件。
- **Role 层优先级**：多角色按 `IDomainUser.UserInfo.Roles` 遍历顺序命中——角色列表顺序即优先级（角色间无业务优先级语义）。
- **Global 层唯一性（C4）**：`UX_FeatureValue_Name_Provider` 唯一约束对 `ProviderKey=null`（Global）在 SQLite/PostgreSQL 下 NULL 互不相同——`SetValueAsync` 在事务内二次校验保证 Global 单行。
- **管理写路径**：仅 `IFeatureManager` 为写入口（缓存失效 + 唯一性）；`FeatureValueEntityDataService` 直写绕过缓存——设计上禁止直通控制器。
- **建表**：`FeatureValue` 单表由框架 `SyncTables` 统一托管，无手工 DDL 前置。
- **多租户**：Tenant 层仅在 `IDomainUser.TenantId.HasValue` 时参与解析——无租户部署自然跳过。

## 7. 边界与语义速查

| 场景 | 行为 |
|------|------|
| 重复 Feature 定义 Name | `InvalidOperationException`（定义收集） |
| 空定义 Name | `ArgumentException` |
| `[RequireFeature]` 未启用 | `FeatureDisabledException`（fail-closed） |
| 未定义 Feature | `IsEnabledAsync` false；`GetValueAsync` 默认值 |
| 布尔值解析失败（命中层） | false（不跨层回退） |
| 匿名用户 | 直查 Global |
| 多角色 | 遍历序首个命中 |
| Global 层重复 Set | 事务内二次校验（更新语义） |
| 非 Global 层重复 Set（同 Key） | 唯一约束冲突 → 业务异常 |

## 8. v0.2.0：Provider 扩展点与变更事件

### 8.1 自定义 Provider（新增分层）

```csharp
// 1. 实现 IFeatureValueProvider（Provider 自行注入 IDomainUser 等上下文提取 key）
public class EditionFeatureValueProvider(IFeatureValueStore store) : IFeatureValueProvider
{
    public string Name => "Edition";
    public async Task<string?> GetOrNullAsync(string name, string providerKey, CancellationToken ct = default)
        => (await store.GetAsync(name, "Edition", "pro", ct))?.Value;   // 自取 key（此处固定 "pro" 演示）
}

// 2. DI 注册（多实现追加——扩展内置四层用 TryAddEnumerable，消费方用 AddScoped）
services.AddScoped<IFeatureValueProvider, EditionFeatureValueProvider>();

// 3. ProviderOrder 配置顺序（插入 Tenant 与 Global 之间）
"TKWF": { "FeatureManagement": { "ProviderOrder": ["User", "Role", "Tenant", "Edition", "Global"] } }
```

- 未列入 `ProviderOrder` 的自定义 Provider → 追加末尾；空列表 = 注册顺序。
- Provider Name 冲突（重复）→ 首次解析抛 `InvalidOperationException`。
- `FeatureDefinition.AllowedProviders` 非空时仅查询列入层。

### 8.2 变更事件（跨实例联动/审计）

```csharp
[DomainEventHandler]
public class FeatureChangedAuditHandler : ILocalEventHandler<FeatureValueChangedEvent>
{
    public Task HandleEventAsync(FeatureValueChangedEvent e)
        => /* 审计记录 / 接自有总线（Redis pub/sub 等）实现跨实例失效 */;
}
```

- 写路径（Set/Delete）Commit 后发布 `FeatureValueChangedEvent`（Name/ProviderName/ProviderKey/OldValue/NewValue）。
- **进程内缓存失效不依赖事件**——v0.2.0 版本号方案：写后全层即时失效（无需订阅清缓存）。
- 跨实例失效：消费方订阅事件后接自有总线（本扩展零外部依赖）。
- handler 异常由事件总线隔离（永不重抛——不影响写方法返回）。

### 8.3 缓存即时性改进（v0.2.0 缺陷修复）

v0.1.0 的 User/Role/Tenant 层缓存（动态 ProviderKey）写后仅 TTL 收敛（最长 300s 陈旧）——v0.2.0 版本号 key：写后 `version++` 全层立即失效（测试验证跨层即时性）。
