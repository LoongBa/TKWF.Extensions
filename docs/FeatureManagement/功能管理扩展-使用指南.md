## 1. 快速开始

### 1.1 引用

```xml
<ProjectReference Include="..\..\_Framework\FeatureManagement\TKWF.Ext.FeatureManagement.csproj" />
```

### 1.2 启用（v4.9.85+ 白名单声明）

```csharp
using TKWF.Ext.FeatureManagement;

[TKWFEnabledExtension(typeof(FeatureManagementExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后自动接线：Feature 定义收集 + `IFeatureManager`/`IFeatureChecker` 注册 + `AddFeatureCheck` 过滤器（消费方 `[RequireFeature]` 零改动接入）。

### 1.3 声明 Feature 定义

```csharp
[FeatureContributor]   // SG1 编译期收集（主框架 V4.9.114）
public class OrderFeatureContributor : IFeatureDefinitionContributor
{
    public void Define(FeatureDefinitionContext context)
    {
        context.Add(new FeatureDefinition
        {
            Name = "Order.NewCheckout",
            DisplayName = "新结算流程",
            Group = "Order",
            ValueType = FeatureValueType.Boolean,
            DefaultValue = "false"          // 默认关闭——fail-closed
        });
        // v0.3.0 复杂 ValueType（Decimal/DateTime/Json）：
        context.Add(new FeatureDefinition { Name = "App.Rate", ValueType = FeatureValueType.Decimal, DefaultValue = "1.5" });
        context.Add(new FeatureDefinition { Name = "App.MaintenanceWindow", ValueType = FeatureValueType.DateTime, DefaultValue = "2026-10-01T00:00:00Z" });
        context.Add(new FeatureDefinition { Name = "App.GrayConfig", ValueType = FeatureValueType.Json, DefaultValue = """{"percent":20}""" });
    }
}
```

> **ValueType 支持**（v0.3.0）：`Boolean` / `String` / `Int` / `Decimal` / `DateTime`（ISO8601） / `Json`（复杂对象/数组）。默认值与存储值均为字符串表示，类型语义在 `IFeatureManager` 层（序列化/校验/反序列化）。

### 1.4 使用

```csharp
// 方法级拦截（未启用 → FeatureDisabledException）
[RequireFeature("Order.NewCheckout")]
public Task CheckoutAsync() { ... }

// 编程式检查
public class MyService(IFeatureManager manager, IDomainUser user)
{
    public async Task<bool> IsBetaEnabled() => await manager.IsEnabledAsync("Beta.Preview", user);
    public async Task<string> GetTheme() => await manager.GetValueAsync("App.Theme", user, "light");

    // v0.3.0 类型化读写
    public async Task<decimal> GetRate() => await manager.GetValueAsync<decimal>("App.Rate", user);
    public async Task<GrayConfig> GetGrayConfig() => await manager.GetValueAsync<GrayConfig>("App.GrayConfig", user, new());
    public async Task SetRate(decimal rate) => await manager.SetValueAsync("App.Rate", rate, FeatureProviders.Global, null);
}
```

## 2. 分层值语义（Global → Tenant → Role → User）

| 层 | 说明 | ProviderKey |
|----|------|-------------|
| Global | 全局默认覆盖 | null |
| Tenant | 租户级（仅 `TenantId.HasValue` 时查询） | TenantId |
| Role | 角色级（多角色**遍历顺序**首个命中） | 角色名 |
| User | 用户级（最优先） | UserId |

**解析顺序（最优先）**：`User → Role → Tenant → Global → 默认值`。
**默认值**：显式 `defaultValue` 参数优先 → `FeatureDefinition.DefaultValue` → 空字符串。
**匿名用户**（`!IsAuthenticated`）：跳过 User/Role/Tenant 直查 Global。

```csharp
await manager.SetValueAsync("Order.NewCheckout", "true", FeatureProviders.Global, null);    // 全站开启
await manager.SetValueAsync("Order.NewCheckout", "false", FeatureProviders.User, "u-100");  // 指定用户关闭
await manager.SetValueAsync("Order.NewCheckout", "true", FeatureProviders.Role, "vip");     // 角色开启
var (value, provider) = await manager.GetEffectiveValueAsync("Order.NewCheckout", user);    // 命中层返回（管理显示）
```

## 3. 检查语义（fail-closed 铁律）

| 场景 | `IsEnabledAsync` 结果 |
|------|----------------------|
| 值 "true" | true |
| 值 "false" | false |
| 值存在但非布尔（如 "abc"） | **false（不跨层回退）** |
| 未定义 / 空名 | false（不抛异常） |
| 无 `FailClosedOnUndefined` 开关 | 恒 fail-closed（框架 `IFeatureChecker` 契约） |

> 无开关可翻转"未定义→true"——拼错的 Feature 名永远关闭（fail-closed 安全）。

## 6. 生产注意事项

- **多实例缓存边界**：值缓存为进程内 `IMemoryCache`。**v0.3.0 起内建跨实例失效**——`FeatureValueChangedEvent` 标 `[DistributedEvent]`，多实例部署且注册分布式总线（如主框架 RabbitMQ）时，任一实例改值 → 分布式广播 → 各实例内建 handler bump 版本表 → **全实例即时生效**。未接分布式总线（单实例/默认 LocalDistributedEventBus）时跨实例仍靠 TTL（默认 300s）收敛。
- **RabbitMQ 模式本地 handler 语义**：接入真实分布式总线（RabbitMQ）后，Outbox 提交前导出并摘除分布式事件——**本实例 `ILocalEventHandler` 收不到变更事件**（本实例失效由 version++ 已即时，不依赖事件）；`IDistributedEventHandler` 可收到（含本实例经 RabbitMQ 回环）。默认模式（LocalDistributedEventBus）下本地 + 分布式 handler 均收到。
- **写时校验（v0.3.0 行为变更）**：向已定义 Feature 写值违反其 `ValueType` → `ArgumentException`（如向 Boolean Feature 写 "abc"）——v0.2.0 静默成功，v0.3.0 立即拒绝。**未定义 Feature 写值不校验**（向后兼容）。
- **`Value` 列加宽（v0.3.0）**：`Value` 列 `VARCHAR(512)` → 无界（SQLite=text/Pg=text/SqlServer=nvarchar(max)）——新装库 SyncTables 幂等建表；**存量库** SyncTables 自动 ALTER（SQLite 实测加宽）——若目标库未自动加宽需 DBA 手动变更。
- **Role 层优先级**：多角色按 `IDomainUser.UserInfo.Roles` 遍历顺序命中——角色列表顺序即优先级（角色间无业务优先级语义）。
- **Global 层唯一性（C4）**：`UX_FeatureValue_Name_Provider` 唯一约束对 `ProviderKey=null`（Global）在 SQLite/PostgreSQL 下 NULL 互不相同——`SetValueAsync` 在事务内二次校验保证 Global 单行。
- **管理写路径**：仅 `IFeatureManager` 为写入口（缓存失效 + 唯一性 + 写时校验）；`FeatureValueEntityDataService` 直写绕过缓存与校验——设计上禁止直通控制器。
- **建表**：`FeatureValue` 单表由框架 `SyncTables` 统一托管，无手工 DDL 前置。
- **多租户**：Tenant 层仅在 `IDomainUser.TenantId.HasValue` 时参与解析——无租户部署自然跳过。

## 7. 边界与语义速查

| 场景 | 行为 |
|------|------|
| 重复 Feature 定义 Name | `InvalidOperationException`（定义收集） |
| 空定义 Name | `ArgumentException` |
| `[RequireFeature]` 未启用 | `FeatureDisabledException`（fail-closed） |
| 未定义 Feature | `IsEnabledAsync` false；`GetValueAsync` 默认值 |
| 布尔值解析失败（命中层） | false（不跨层回退） |
| 匿名用户 | 直查 Global |
| 多角色 | 遍历序首个命中 |
| Global 层重复 Set | 事务内二次校验（更新语义） |
| 非 Global 层重复 Set（同 Key） | 唯一约束冲突 → 业务异常 |

## 8. v0.2.0：Provider 扩展点与变更事件

### 8.1 自定义 Provider（新增分层）

```csharp
// 1. 实现 IFeatureValueProvider（Provider 自行注入 IDomainUser 等上下文提取 key）
public class EditionFeatureValueProvider(IFeatureValueStore store) : IFeatureValueProvider
{
    public string Name => "Edition";
    public async Task<string?> GetOrNullAsync(string name, string providerKey, CancellationToken ct = default)
        => (await store.GetAsync(name, "Edition", "pro", ct))?.Value;   // 自取 key（此处固定 "pro" 演示）
}

// 2. DI 注册（多实现追加——扩展内置四层用 TryAddEnumerable，消费方用 AddScoped）
services.AddScoped<IFeatureValueProvider, EditionFeatureValueProvider>();

// 3. ProviderOrder 配置顺序（插入 Tenant 与 Global 之间）
"TKWF": { "FeatureManagement": { "ProviderOrder": ["User", "Role", "Tenant", "Edition", "Global"] } }
```

- 未列入 `ProviderOrder` 的自定义 Provider → 追加末尾；空列表 = 注册顺序。
- Provider Name 冲突（重复）→ 首次解析抛 `InvalidOperationException`。
- `FeatureDefinition.AllowedProviders` 非空时仅查询列入层。

### 8.2 变更事件（跨实例联动/审计——v0.3.0 起支持分布式订阅）

```csharp
// 进程内订阅（默认模式 + 未接 RabbitMQ 时均可收到）
[DomainEventHandler]
public class FeatureChangedAuditHandler : ILocalEventHandler<FeatureValueChangedEvent>
{
    public Task HandleEventAsync(FeatureValueChangedEvent e)
        => /* 审计记录 / 业务联动 */;
}

// v0.3.0：分布式订阅（多实例/微服务——经 IDistributedEventBus 广播，事件标 [DistributedEvent]）
[DomainEventHandler]
public class FeatureChangedDistributedHandler : IDistributedEventHandler<FeatureValueChangedEvent>
{
    public Task HandleEventAsync(FeatureValueChangedEvent e)
        => /* 跨实例联动：切换行为 / 通知前端刷新 */;
}
```

- 写路径（Set/Delete）Commit 后发布 `FeatureValueChangedEvent`（Name/ProviderName/ProviderKey/OldValue/NewValue）——**v0.3.0 起标 `[DistributedEvent]`**，AOP 路径经框架 `EventDispatchFilter` 自动路由：注册真实分布式总线（RabbitMQ）→ 分布式广播；默认（LocalDistributedEventBus）→ 进程内。
- **进程内缓存失效不依赖事件**——v0.2.0 版本号方案：写后全层即时失效（无需订阅清缓存）。
- **跨实例缓存失效（v0.3.0 内建）**：扩展自带 `DistributedFeatureChangedHandler`（`IDistributedEventHandler`）——收到远程事件 bump 本地版本表 → 全实例即时生效。**消费方无需自接总线**（v0.2.0 需自行桥接，v0.3.0 已内建）。
- handler 异常由事件总线隔离（永不重抛——不影响写方法返回）。

### 8.3 缓存即时性改进（v0.2.0 缺陷修复）

v0.1.0 的 User/Role/Tenant 层缓存（动态 ProviderKey）写后仅 TTL 收敛（最长 300s 陈旧）——v0.2.0 版本号 key：写后 `version++` 全层立即失效（测试验证跨层即时性）。

### 8.4 v0.3.0：复杂 ValueType（类型化读写 + 写时校验）

**类型化读取**（`GetValueAsync<T>`）——按 T 反序列化（对齐 Settings `GetAsync<T>` 先例）：

| T | 存储表示 | 解析失败 |
|---|---------|---------|
| `bool` | `"true"`/`"false"`（规范小写） | 返回 `defaultValue` |
| `int`/`long`/`decimal`/`double` | InvariantCulture 字符串 | 返回 `defaultValue` |
| `DateTime` | ISO8601（`"O"`，可往返） | 返回 `defaultValue` |
| `string` | 原样 | 原样 |
| 其他（Json 对象/数组/record） | `JsonSerializer` | **返回 `defaultValue`（引用类型默认 null——P2：消费方应传 `defaultValue` 或处理 null）** |

**回退链**：存储值 → 定义 `DefaultValue` → `defaultValue` 参数（无存储值且定义无默认时）。注：类型化入口为**定义默认优先**（与字符串入口参数优先不同——`default!` 区分不了 `default(T)` 与显式默认）。

**类型化写入**（`SetValueAsync<T>`）——序列化为规范字符串后走字符串入口（含写时校验）：

```csharp
await manager.SetValueAsync("App.Rate", 1.5m, FeatureProviders.Global, null);          // → 存 "1.5"
await manager.SetValueAsync("App.GrayConfig", new GrayConfig { Percent = 20 }, ...);    // → 存规范化 JSON
await manager.SetValueAsync("App.MaintenanceWindow", new DateTime(2026,10,1,0,0,0,DateTimeKind.Utc), ...); // → 存 ISO8601
```

**写时校验**（v0.3.0 新增）——`SetValueAsync` 按定义 `ValueType` 校验，违反 → `ArgumentException`：

| ValueType | 校验规则 |
|-----------|---------|
| `Boolean` | `bool.TryParse`（true/false，大小写不敏感） |
| `Int` | `int.TryParse`（InvariantCulture） |
| `Decimal` | `decimal.TryParse`（InvariantCulture） |
| `DateTime` | `DateTime.TryParse`（RoundtripKind——ISO8601 可往返） |
| `Json` | `JsonDocument.TryParse`（合法 JSON 文档） |
| `String` | 恒通过 |

> **未定义 Feature 写值跳过校验**（向后兼容——v0.2.0 无定义可写语义保留）。**行为变更**：向已定义 Boolean Feature 写 "abc" v0.2.0 静默成功 → v0.3.0 抛 `ArgumentException`（写错类型立即暴露，不再延迟到读时）。
