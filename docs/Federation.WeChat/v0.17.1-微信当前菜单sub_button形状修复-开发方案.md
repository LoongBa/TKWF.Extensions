## 一、背景与根因

DMP-Lite AdminUI `MenuManage` 页面加载当前菜单 500（SG3 递归选择集缺陷修复后暴露）：

```
System.Text.Json.JsonException: The JSON value could not be converted to
TKWF.Federation.WeChat.WeChatMenuButton[]. Path: $.selfmenu_info.button[0].sub_button
  at TKWF.Federation.WeChat.WeChatApiClient.GetCurrentSelfMenuInfoAsync(...)  // WeChatApiClient.cs:229
  at TKWF.Ext.WeChatOperations.MenuService.GetCurrentAsync(...)               // MenuService.cs:101-105
```

**根因**：`WeChatMenuPoco.cs:34` `[property: JsonPropertyName("sub_button")] WeChatMenuButton[]? SubButton` 建模为**数组**，但微信 `cgi-bin/get_current_selfmenu_info`（查询自定义菜单**配置**）官方返回 `sub_button` 为**对象** `{"list":[...]}`：

```json
{ "name": "菜单", "sub_button": { "list": [ {"type":"view","name":"搜索","url":"..."} ] } }
```

（官方文档 Querying_Custom_Menus + silenceper/wechat 第三方库 `SubButton struct { List []SelfMenuButton }` 一致；对比另一接口 `cgi-bin/menu/get` 的 sub_button 才是数组。）

**触发条件**：当前菜单存在二级子菜单时必现（无子菜单不报错——测试 stub 天然绕过，缺陷长期未暴露）。

### 影响面（核实确认）

| 位置 | 影响 |
|------|------|
| `MenuService.GetCurrentAsync`（MenuService.cs:101-105） | 含子菜单即 500（DMP 页面直接阻塞） |
| `MenuService.PublishAsync`（MenuService.cs:125-165） | **半成功副作用（最严重）**：L134 `CreateMenuAsync` 微信侧真实生效 → L135 确认拉取抛异常（在 L138 事务开启**之前**）→ 微信已变、本地快照/版本/审计未落、用户见"发布失败" |
| `MenuService.RollbackAsync`（MenuService.cs:181-191） | 复用 PublishAsync 同副作用链 |
| 本地 `MenuSnapshot` 基准 | 发布链失败 → 快照长期不更新 → click key 收集失真 |

## 二、评审结论（Oracle PASS WITH CONDITIONS）

### 方案选型：A（反序列化边界形状归一）——否决 B（真值建模）

| 维度 | 判定 |
|------|------|
| 破坏面 | B 需 Federation.WeChat → WeChatOperations → DMP AdminUI → SG3 DtoStubs → ts-client → mock 全 lockstep——与"反序列化适配层"问题性质不成比例 |
| 微信两接口形状并存 | `get_current_selfmenu_info`=对象 / `menu/get`=数组——converter 双形状兼容是**前向兼容**正确做法 |
| 递归 | converter 挂 `SubButton` 属性（`WeChatMenuButton[]?`）→ STJ 属性级 converter **自动递归**（深层 `{"list":[{...sub_button:{"list":[...]}}]}` 自动处理） |
| 覆盖面 | 属性级自动覆盖所有 `Deserialize<WeChatSelfMenuInfoResult>` 路径（API 拉取 L229 + 本地快照 `GetClickKeysAsync` L232） |
| 写方向 | 保持数组序列化（快照存储方向不变，`UpsertSnapshotAsync` 无影响） |
| 先例 | WeChatUserInfo 响应裁剪同属"反序列化适配层" |

### 归一规则（converter Read 方向）

| 入口 token | 归一 |
|-----------|------|
| `StartArray` `[...]` | `JsonSerializer.Deserialize<WeChatMenuButton[]>(ref reader, options)`（元素 STJ fast path 含嵌套 converter 递归） |
| `StartObject` `{"list":[...]}` | 读 `list` → 递归反序列化数组；Skip 未识别属性（如 `count`） |
| `StartObject` `{"list": null}` | `null` |
| `StartObject` `{}` / 无 `list` 属性 | `null`（归一"无子菜单"） |
| `Null` | `null` |
| `string`/`number`/`true`（数据错误） | **抛 `JsonException`**（不吞——非"空"语义） |

### P1 附带裁定

| 项 | 裁定 |
|----|------|
| `Type` `string` → `string?` | **本轮改**（官方父按钮无 type；非破坏——positional record arity 不变、消费方零改动；防未来 `RespectNullableAnnotations` 硬失败） |
| 半成功副作用 | **本轮一并修（P1）**——converter 只解除形状缺陷确定性失败，网络/限流等非确定性失败仍触发半成功；L135 确认拉取 try/catch + 失败时仍落本地（best-effort 确认语义，后续 `GetCurrentAsync` 自愈）；**语义变更需写 ADR** |
| `value` / `news_info` 建模 | **本轮不纳入**（P2 后续迭代——DMP 不阻塞，最小修复原则） |
