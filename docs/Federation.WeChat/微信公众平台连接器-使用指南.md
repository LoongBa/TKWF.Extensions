# 微信公众平台连接器-使用指南

> **库**: `TKWF.Federation.WeChat`（微信公众平台连接器——平台网关库/大使馆）| **版本**: V0.4.0（2026-10-17——事件回复 Handler 三件套） | **框架**: .NET 10
> **定位**: 认证中心**对外（上游）**接微信 IdP 的双向网关——OAuth 网页授权（身份获取）+ 事件推送（入站验签）；作为 **RP/OAuth Client** 消费微信，把 `(channel_id, openid) → uid` 归一认证中心 Federation token2。**SSO 是认证中心对下游的能力，不是本库的协议**（归层命名说明见 §六）
> **关联文档**: 技术规范见 `_Framework/Federation.WeChat/README.md`；归层实施开发方案 `docs/AuthCenter/v0.1.0-AuthCenter归层实施-开发方案.md`；微信适配历史方案 `docs/SSO/v0.1.0-SSO.WeChat-微信公众平台适配-开发方案.md`（归层修订注记）

> ✅ **实施进度（2026-10-05）**：V0.1.0 全部落地（T3-T6）——`WeChatApiClient` 出站客户端 + `WeChatOauthChannel`（wechat_oauth）/ `WeChatEventChannel` + `WeChatEventCrypto`（wechat_event 信任根一票否决）/ `AddWeChatFederationChannels()` 注册方法 + 测试 18 用例全绿。

> ✅ **实施进度（2026-10-17）**：V0.4.0 全部落地——**事件回复 Handler 三件套**（`WechatEventReplyHandlerBase` 平台基类 / `WechatTemplateEventReplyHandler` 模板驱动 / `WechatProbeEventReplyHandler` 探针）+ `WeChatEventChannel` 编排放权（返回 null + `__decrypted_xml` 富化）+ `TKWF:Federation:WeChat:EventReply` 节；测试 WeChat.Tests 86 用例全绿。本文档 §3 为本次新增小节。

### 1. OAuth 网页授权流程（`wechat_oauth`——形态 A/认证服务号）

```
用户 在目标 H5 应用 点击"微信登录"
  → 应用跳 /sso/login?target_app_id=X
  → Federation 按 channel 路由 wechat_oauth → 302 微信 authorize
       (appid + redirect_uri + scope=snsapi_base + state 绑定会话防 CSRF，回调域名 = SSO 域名)
  → 微信授权页（静默）→ 回调 /sso/oauth/wechat/callback?code=&state=
  → 验 state → WeChatApiClient.GetOpenIdAsync(appId, code) → openid
  → (channel_id=公众号id, openid) → uid → Federation 签 token2 → 302 注册 origin #t=
```

- **scope 降级**：应用注册 scope 含 `profile:basic+` 时授权后补拉用户信息（`GetUserInfoAsync`——需用户确认，`snsapi_base` 场景返回 null 降级）。
- **联盟锚点**：`snsapi_base` 联盟服务号场景 → 写 `FederationAnchorOpenId`（经 Abstractions `ISsoAccountLinkService.SetFederationAnchorAsync`）；商户 openid2 → `ISsoChannelMapService.LinkAsync` → `PlatformAccountMap`；后续任一 openid 直认（反查经既有契约）。

### 2. 事件推送接收流程（`wechat_event`——形态 B/未认证号）

```
用户 发消息/点 CLICK 菜单
  → 微信推送事件 → 接收端点（Federation/装配层映射，本库只做验签逻辑类）
  → WeChatEventCrypto 验 msg_signature = SHA1(sort(token, timestamp, nonce, msg_encrypt)) + AES 解密
  → FromUserName = openid；富化 Parameters + 存 __decrypted_xml（明文 XML——V0.4.0，Oracle P1-4）
  → WeChatEventChannel.HandleEventAsync 返回 null（"无平台回复"——编排放权编排器 EventOrchestrator）
  → 编排器 handler 双桶迭代（W3 绑定桶优先 → ChannelType 桶回退；微信可达 G4/G5）
  → handler（WechatEventReplyHandlerBase 派生）组装被动回复 XML 信封（text/news 多图文）
  → 无 handler 回复 → 端点 200 空回复兜底（5 秒超时）；异常 → 空哨兵（不触发 handler 双桶，Oracle P2-3）
```

- **各号后端**（独立公众号后端）：自实现部署（独立密钥）——本库提供微信侧接收验签 + Issue 对接的**服务端再分发**骨架。
- **不开放 HTTP `/sso/issue`**：本库内部通道不走 HMAC 自签 HTTP 备选路径（该路径是给**独立公众号后端**的，Oracle 评审点 4 P1-2 裁定）。

### 3. 事件回复 Handler（三件套）——被动回复归 handler/编排器（V0.4.0，2026-10-17）

> 方案 `docs/Federation/Wechat事件回复Handler基类与二级分发-开发方案.md`（Oracle PASS WITH CONDITIONS）+ ADR `docs/Federation/ADR/ADR-Federation-平台特定事件回复Handler基类与二级分发.md`。本库角色收敛：**通道只做"验签 + 解密 + 富化 + 返回 null"**（无平台回复），被动回复 XML 信封由平台基类 handler 组装；handler 迭代唯一归口 Federation 编排器 `EventOrchestrator`（双桶）。

**（1）平台基类继承方式**——业务 handler 继承 `WechatEventReplyHandlerBase`（`DomainServiceBase, IEventReplyHandler`，`ChannelType="wechat_event"`；**不继承** 主包 `EventReplyHandlerBase`——两基类并列，Oracle P1-1，方案 §3.1），覆盖关心的**二级分发虚方法分支**（未覆盖 → `OnDefaultAsync` 兜底 null 不回复）：

| 类别 | 虚方法（覆盖即可分流） | 强类型参数（`WechatEventContext` 类型化） |
|------|------|------|
| 事件 | `OnSubscribeAsync` / `OnUnsubscribeAsync` | EventKey（带参扫码 `qrscene_` 前缀）/ 基础字段 |
| 事件 | `OnScanAsync` / `OnLocationEventAsync` | 场景值 `scene_id`（去前缀）/ 经纬度 `Latitude`/`Longitude`/`Precision` |
| 事件 | `OnClickAsync` / `OnViewAsync` / `OnViewMiniProgramAsync` | 菜单 key（EventKey）/ 菜单 URL / 小程序参数 |
| 事件 | `OnMassSendJobFinishAsync` | 群发统计（Status/TotalCount/FilterCount/SentCount/ErrorCount） |
| 消息 | `OnTextAsync` / `OnImageAsync` / `OnVoiceAsync` / `OnVideoAsync` / `OnShortVideoAsync` | Content / MediaId+PicUrl / MediaId+Format / MediaId+ThumbMediaId / MediaId+ThumbMediaId |
| 消息 | `OnLocationAsync` / `OnLinkAsync` | 经纬度+Scale+Label / Title+Description+Url |
| 兜底 | `OnDefaultAsync` | 原始 `msg_type`/`event`（**默认 null**——不回复） |

> **协议门控内置**（回复组装层强制 null）：unsubscribe / MASSSENDJOBFINISH / TEMPLATESENDJOBFINISH 禁回复（微信平台规则）——任何 handler（含 Template/Probe/业务）无法回复；业务副作用（记录取关等）仍可经虚方法执行（方案 §3.2、ADR D2）。

**（2）业务 handler 示例**（消费方注册）：

```csharp
// 继承平台基类，只覆盖关心的分支（DI004——签票经 User.Use<ISealedTicketService<FederatedIdentity>>() 懒加载）
public sealed class MyBizHandler : WechatEventReplyHandlerBase
{
    protected override Task<WechatReplyPayload?> OnSubscribeAsync(WechatEventContext ctx, CancellationToken ct)
        => Task.FromResult<WechatReplyPayload?>(new(Content: "欢迎关注！"));

    protected override Task<WechatReplyPayload?> OnClickAsync(WechatEventContext ctx, CancellationToken ct)
        => Task.FromResult<WechatReplyPayload?>(new(News: [new EventReplyNewsArticle("菜单入口", "...", "https://app.example.com/landing")]));
    // 其余分支不覆盖 → OnDefaultAsync → null（不回复）
}
// 消费方显式注册（ADR92 集合版守卫工厂）
services.TryAddEnumerableConstructible<IEventReplyHandler, MyBizHandler>();
```

**（3）Template 模板驱动**——`WechatTemplateEventReplyHandler`（继承平台基类，覆盖 `OnDefaultAsync` 读 `Channel.Extra["news_reply"]` 模板——占位符 `{uid}/{openid}/{channel_id}/...`，**纯图文**零签票耦合）；**消费方显式注册**（平台库不默认注册——Oracle P0-1，方案 §3.3）；模板缺失/损坏/`enabled=false` → 返回 null（不回复不干预——Oracle P0-2）。模板 JSON 键为 snake_case（`title/description/link/pic_url/ttl_seconds/enabled`，经 `[JsonPropertyName]` 显式映射——ADR D8）。

**（4）Probe 探针**——`WechatProbeEventReplyHandler`（继承平台基类，覆盖全部分支），`AddWeChatFederationChannels()` **无条件注册** + `IOptions<WechatEventReplyOptions>` 惰性判断 `ProbeEventReplyHandlerEnabled`（`TKWF:Federation:WeChat:EventReply` 节，默认 **false**——Oracle P1-3，方案 §3.5）；开关开 → 可回复分支 `PROBE:branch=...` 可区分回复 / 门控分支基类强制 null + ILogger；**与业务 handler 互斥**（Oracle P2-5）。开发期对接验证无需先写业务 handler——开探针开关即可验证"微信 → 验签 → 二级分发 → 各分支"全链路。

**（5）通道编排放权**——`WeChatEventChannel.HandleEventAsync` 正常路径返回 null（"无平台回复"→ 编排器迭代）；异常（解密失败/格式非法）返回空哨兵 `EventReplyResult("", "text/xml")`（与"无回复"区分，避免 handler 收到不完整 context——Oracle P2-3，方案 §3.4、ADR D4）。主包 `TestEventReplyHandler` 已删除（Federation v0.9.0 破坏性——能力迁本层 Template/Probe，ADR D7）。

## 三、信任根安全说明（一票否决）

事件推送验签是**信任根**——`msg_signature` + AES 解密，**漏验 = 可伪造任意 openid = 体系崩溃**（设计文档 §8.1）：

| 规则 | 说明 |
|------|------|
| **验签失败即拒** | 无降级无旁路——签名校验一票否决；篡改/重放样本一律 400 + Warning |
| **恒定时间比对** | `CryptographicOperations.FixedTimeEquals` 防时序攻击 |
| **EncodingAESKey 派生** | 43 字符 + `=` → Base64Decode → 32 字节 AESKey（微信规范） |
| **各号后端为信任边界** | 自实现部署须独立安全加固（书面声明）——本库不代管各号密钥 |

信任根自动化测试（T5 验收）：合法 `msg_signature` + AES 密文通过（正向）+ 篡改样本拒（负向）——落地后经 `WeChatEventCrypto` 测试辅助生成合法样本。

## 四、事件推送接收端点归装配层（库只做验签逻辑类）

**本库不引 AspNetCore（Oracle 评审点 5）**——入站端点归 Federation 扩展/消费方**装配层**：

| 端点 | 方法 | 功能 | 归属 |
|------|------|------|------|
| `/sso/login?target_app_id=X` | GET | OAuth 代理入口（按 channel 路由：wechat_oauth → 302 微信 / wechat_event → 引导页） | Federation 装配映射 |
| `/sso/oauth/wechat/callback` | GET | 微信 OAuth 回调（验 state → code → channel.AuthenticateAsync → uid → 签 token2 → 302 `#t=`） | Federation/消费方装配 |
| `/sso/wechat/event/{channelId}` | POST | 事件推送接收（调 `WeChatEventCrypto` 验签 + AES 解密 + 富化 `__decrypted_xml` → `HandleEventAsync` 返回 null → 编排器 handler 双桶——**被动回复归 handler**，V0.2.0） | Federation/消费方装配 |
| `/sso/auth?code=`（既有） | GET | 消费 accesscode → 302 fragment | Federation（既有） |

库侧仅提供**验签逻辑类**（`WeChatEventCrypto`，已实现）——验签逻辑收 `byte[]`/`Stream`，端点映射在外（minimal API 或手写控制器，非 `[GenerateController]`，Oracle P2-5）。

## 五、故障排查

| 症状 | 原因 | 处置 |
|------|------|------|
| 事件推送接收全部 400 | `Token`/`EncodingAESKey` 与微信公众平台后台不一致 → `msg_signature` 验签失败（信任根） | 核对配置节 `TKWF:Federation:WeChat` Channels 项 Token/EncodingAESKey（注意：每个公众号一组，按 ChannelId 对应）；后台"消息加解密方式"须选兼容模式并同步 EncodingAESKey |
| `微信凭证未配置：TKWF:Federation:WeChat 节 Channels 为空` | `WeChatOptions.Channels` 未配置/空列表 | 补 Channels 列表；`[Options]` 自动绑定后重启宿主 |
| `微信凭证未配置：appId=xxx（Channels 无匹配项）` | 出站调用传入的 appId 与 Channels 任一项 AppId 不精确匹配 | 核对 AppId 精确值（Ordinal 匹配）；多公众号确认调用了对的 ChannelId |
| `微信授权 code 换取 openid 失败` / `微信 access_token 获取失败` | AppSecret 错误 / code 过期 / AppId 与 code 不绑定 | 核对 AppSecret（生产为 AES-GCM 密文，解密后值须正确）；code 一次性且 5 分钟内使用；code 须由同一 AppId 授权产生 |
| `sns/userinfo` 返回 null 降级 | 授权 scope 为 `snsapi_base`（无用户信息） | 属预期——静默授权只有 openid；需用户信息须 `snsapi_userinfo` scope |
| access_token 过期调用失败 | L1 缓存提前 5 分钟刷新策略未覆盖微信端强制过期（罕见） | 出站调用失败重试一次（自动刷新后重放）；多实例部署共享缓存语义靠微信端兜底 |

## 六、归层命名说明（SSO → Federation → Federation.WeChat）

认证体系四层归层模型（ADR-AuthCenter-归层与命名，Oracle PASS WITH CONDITIONS）：

| 层 | 包 | 形态 | 职责 |
|----|----|------|------|
| 联盟核心/认证中心 | `TKWF.Ext.AuthCenter`（规划名） | 扩展（对内，持久化+装配） | 账号/令牌/登录保护/票据 |
| 外交部/对外身份接口 | `TKWF.Ext.Federation`（**联邦互联**） | 扩展（配置装配、自含实体） | token2/accesscode/JWKS + `ISsoChannel` 窄适配 |
| 大使馆/平台网关库 | **`TKWF.Federation.WeChat`**（本库） | **纯库**（无 Initializer 无 `[TKWFExtension]` 无持久化） | 微信双向网关（OAuth + 事件推送验签） |
| 引擎/协议 | `TKWF.Utility.OAuthClient` | 库（BCL，归主框架） | authorize 构造/code 交换/令牌解析 |

**演变路径**：`TKWF.Ext.SSO`（联邦互联层独立模块，ADR-SSO 选项 A）→ `TKWF.Ext.Federation`（SSO 命名废弃——SSO 是体验词，Federation 是结构词，中文名「**联邦互联**」定案 2026-10-05；归层代码零移动）→ `TKWF.Federation.{平台}`（平台适配从"含 Initializer 的卫星扩展"降级为"纯库"，本库即首个落地先例）。

**`无 Ext` = 纯库判据**（AGENTS §8）：

| 前缀 | 形态 | 判据 |
|------|------|------|
| `TKWF.Ext.*` | 扩展 | 有装配（Initializer/白名单）或有持久化（实体/Store 归 SG1 DataService） |
| `TKWF.*`（无 Ext） | 库 | 纯逻辑/无状态——无 Initializer 无 `[TKWFExtension]` 无持久化 |

微信平台网关**无持久化、纯协议逻辑** → 应为库非扩展（每平台一个扩展 = 包泛滥）；`TKWF.Federation.{平台}` 单库多命名空间收敛。本库 `WeChatApiClient` 纯内存态 access_token 缓存 = **零持久化零 Store**（tkwf-extension 铁律落地实证——不创建 `IWeChatStore` 等 DataService 薄包装伪层，出站 API 能力直接内聚于客户端类）。

## 七、与既有 `WeChatAuthenticationProvider` 边界

| 资产 | 归属 | 定位 |
|------|------|------|
| `WeChatAuthenticationProvider` / `IWeChatApiClient` | Authentication 主包 | 认证中心**内部认证方式**（短信/微信 → token1 签发）——供单应用登录 |
| `WeChatOauthChannel` / `WeChatEventChannel` + 轻量 `WeChatApiClient` | **本库** | **联邦 IdP 适配**（外部身份源 → token2 联邦流） |

- **两会话永不交叉**：装配实例按需选装（认证中心实例用联邦流；单应用业务系统用内部 Provider）——凭证各自持有、流程各自走、产物不同（token1 vs token2）。
- **命名区分**：内部 Provider vs 联邦 Channel——Provider 在认证内核，Channel 在联邦库。
- 微信场景双轨并存是**边界声明**，非重复建设（Oracle P2-3 已裁定）。
