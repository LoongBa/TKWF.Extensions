# M3 钉钉平台网关库 开发方案（TKWF.Federation.DingTalk）

> **立项来源**: 平台网关立项依据（近中远）M3（P1 中期）｜ **类型**: L1 平台库（国内 B 端）
> **版本**: v0.1.0 ｜ **日期**: 2026-10-06 ｜ **状态**: 📋 提议（待 Oracle 评审）
> **关联**: 国内总规划（钉钉行 + §三模板 + 信任根分档）｜ 检索事实（钉钉开放平台官方文档——新 OAuth2 协议）｜ N1 模板｜ N2 锚点策略
> **关键约束**: 纯库（无 Initializer 无 `[TKWFExtension]` 零持久化零 Store）；**完整形态**（钉钉有入站事件回调——组件 3/4 齐备）；**新 OAuth2 协议**（旧 qrconnect/snsapi_login 不接入）；事件回调信任根 = AES-CBC + `sha1(sort)`（1200ms URL 校验 + 2500ms 事件双阈值——按最严 1200ms，落库即返 success + 异步业务）

## 一、背景与目标

### 现状

钉钉（dingtalk.com，阿里）是国内 To B **企业员工登录标配**——即使 B 端组织/教育线企业场景（企业员工用钉钉账号登录第三方网站）。联邦互联已落地微信（`wechat_oauth`/`wechat_event`）双通道，QQ/支付宝（近期 N3/N4）已规划——**钉钉是中期 B 端身份源代表**（与新 OAuth2 协议已推出对冲旧 qrconnect 协议淡出）。

### 目标

1. **`TKWF.Federation.DingTalk` 纯库**——OAuth 通道（`dingtalk_oauth`）+ 事件通道（`dingtalk_event`）；
2. **新 OAuth2 协议**（`login.dingtalk.com/oauth2/auth` + `userAccessToken`）——DTFrameLogin iframe 扫码内嵌 + 跳转；
3. **unionid→userid**（企业级 token 换——B 端组织身份增强）；
4. 事件回调信任根（AES-CBC + sha1——**1200ms URL 校验 / 2500ms 事件双阈值**，按最严实现）；
5. 按 N1 模板 + N2 锚点策略（钉钉 unionid 封闭于开发者账号——须 TKWF 侧自建映射）。

空 → 不存在

### 不包含

| # | 内容 | 去向 |
|---|------|------|
| 1 | **旧协议**（`oapi.dingtalk.com/connect/qrconnect` + `snsapi_login` scope） | 法律旧码——文档 2021-12-21 迁历史，存量可用"暂不下线"，但不建议新接入（国内总规划复核）——本方案**不含**，仅注记 |
| 2 | **Stream Mode**（官方建议新应用替代 Webhook 的事件接收方式） | 注记于 §五——**不实现**（Stream 需要长连接消费端 + 独立 SDK 语义，与"纯库不引 AspNetCore"约束冲突，归装配层评估）；Webhook 回调验签逻辑（AES+sha1）与 Stream 解密共用同一 crypto 基元，Stream 落地时复用 |
| 3 | exclusiveLogin（专属组织二维码） | 扫码登录增强形态——归装配层调用（库侧提供 authorize URL 构造能力即可），本方案不含专属参数编排 |

## 二、协议事实（官方文档核实——国内总规划 §五矩阵）

| 项 | 事实 |
|----|------|
| 授权形态 | 跳转 + **iframe 扫码**（`DTFrameLogin` 内嵌二维码——嵌入页须与 redirect_uri **同源**）；专属组织二维码 `exclusiveLogin`（B 端配置场景） |
| Authorize（**新协议**） | `https://login.dingtalk.com/oauth2/auth`——`client_id`=AppKey/SuiteKey + `response_type=code` + `redirect_uri` + `scope`=`openid`\|`openid corpid` + `prompt=consent` **必填** + `state` |
| Token（**新协议**） | `POST https://api.dingtalk.com/v1.0/oauth2/userAccessToken`——`clientId`+`clientSecret`+`code`+`grantType`；**accessToken 7200s** + refreshToken 30 天 + 返回 `corpId` |
| 用户标识 | **openId**（新协议 scope=openid 时返回——应用维度）+ **unionId**（开发者企业账号范围内唯一——非跨开发者联盟 ID）+ 需额外经 `topapi/user/getbyunionid`（**企业级 token**）换 **userid**（企业维度，`contact_type` 0=内部/1=外部） |
| 用户信息 API | `GET https://api.dingtalk.com/v1.0/contact/users/{unionId}`（Header `x-acs-dingtalk-access-token`，`unionId=me` 当前授权人）——nick/avatarUrl/mobile/email；**三方手机号脱敏**，完整号须申请权限 |
| 验签/安全 | OAuth 回调**无签名**（仅 state 防 CSRF；token 换取需 clientSecret，对称）；**事件订阅回调 AES-CBC + `sha1(sort(token,timestamp,nonce,msg_encrypt))`**（EncodingAESKey 43 字符）；**解密明文布局 = `random(16) + msg_len(4 BE) + msg(JSON) + receiveid(corpId)`（与微信同构布局，msg 体为 JSON 非 XML——Oracle 评审 P1-6）**；**receiveid = corpId 须校验**（P1-1：forged org-change event 可授予企业访问权，敏感度高于微信） |
| 事件回调超时 | **SyncHTTP 两值均真实**：**1200ms = URL 校验握手** / **2500ms = 日常事件响应**（官方两文档各写一值）——按最严 1200ms 实现；须"**落库即返 success + 异步业务**"（钉钉原文要求）。**边界（Oracle 评审 P1-2）**：库 `AuthenticateAsync` = 验签 + 解密 + 返回 `SsoChannelAuthResult`（CPU-only，<50ms）；**1200ms 预算覆盖装配层全链**（接收回调 → 调 AuthenticateAsync → Federation 编排落库 → 返回 success）——落库是装配层职责（库零持久化） |
| scope | 新 `openid` / `openid corpid`；旧 `snsapi_login`（不接入） |
| 用户标识唯一性 | openId 应用维度 / unionId 开发者账号维度——**均封闭于钉钉体系**——锚点须 TKWF 侧自建映射（N2） |

**设计要点（从事实导出）**：
- **完整形态**：钉钉有事件订阅回调 → 组件 1/2/3/4/5/6/7/8（对齐微信双通道）；
- **新协议强制**：旧 qrconnect 不接入（协议陈旧 + 文档迁历史）；
- **unionid→userid 为企业维度增强**：B 端员工组织身份（员工 ID）——经 `getbyunionid`（企业级 token）换，非 external_uid 主键（对齐"external_uid 恒 = 稳定全局标识"语义——QQ 先例 openid）；**getbyunionid 走旧版 `oapi.dingtalk.com/topapi/user/getbyunionid`（钉钉新协议未提供替代端点——新旧 API 混用为平台限制，Oracle 评审 P2-4）**；
- **信任根双阈值**：事件校验按最严 1200ms——验签 + 解密 + 落库即返 success（异步业务不阻塞回调响应）；**落库归装配层（库零持久化——P1-2）**；
- **Stream Mode 注记**：官方建议新应用用 Stream 替代 Webhook——但库不实现（长连接 + 装配层职责），Webhook 验签 crypto 基元与 Stream 解密共用（复用底座），Stream 独立立项时引用（**可见性：Webhook crypto 基元若为 internal 则装配层无法跨程序集复用——推荐 `InternalsVisibleTo("TKWF.Federation.DingTalk.Stream")`，Oracle 评审 P2-2**）。

├── DingTalkOptions.cs                        # [Options("TKWF:Federation:DingTalk")]——Channels 列表（DingTalkChannelConfig）
├── DingTalkChannelConfig.cs                  # ChannelId + **CorpId** + AppKey + AppSecret + Token + EncodingAESKey（凭证自持——Oracle P2-4；CorpId 用于事件回调 receiveid 校验 P1-1 + getbyunionid 企业上下文）
├── DingTalkApiClient.cs                      # 出站：userAccessToken（code→token 7200s 一次性不缓存——用户级，**不缓存 rationale 对齐 N3 QQ P1-5：用户级 authorization_code grant，联邦认证面一次性消费；refresh_token 续票归 L7 YAGNI——Oracle 评审 P2-8**）+ getbyunionid（unionId→userid，**经 channel 的 AppKey/AppSecret 换企业 token（钉钉新模式复用 OAuth 凭证，无独立 enterprise secret——P1-5）**——企业级 token L1 缓存 + 并发锁 + 提前刷新；**供装配层调用，非 channel AuthenticateAsync 路径——P1-4**）+ /contact/users/{unionId} 用户信息裁剪
├── DingTalkOauthChannel.cs                   # ISsoChannel（ChannelType="dingtalk_oauth"）——回调 code→openId/unionId（AuthenticateAsync 内 userAccessToken 换）；AuthLevel=2（对齐微信便捷语义）
├── DingTalkEventChannel.cs                   # ISsoChannel（ChannelType="dingtalk_event"）——扫码/事件订阅回调验签 + 解密 + unionId→external_uid；**信任根一票否决**
├── DingTalkEventCrypto.cs                    # 验签逻辑类（AES-CBC 解密 + sha1(sort(token,timestamp,nonce,msg_encrypt)) + `CryptographicOperations.FixedTimeEquals` 恒定时间比对 + **receiveid 提取与 corpId 校验（Oracle 评审 P1-1/P1-6）——`DecryptMsg(encodingAESKey, msgEncrypt, expectedReceiveId)` 返回 msg，解密后提取明文尾部 receiveid 与 expectedReceiveId 恒定时间比对，不符抛 CryptographicException；msg 为 JSON 用 `JsonDocument.Parse` 提取 FromUserId——对齐 WeChatEventCrypto 模式 + 钉钉增量）
├── DingTalkUserInfo.cs                       # 响应裁剪 record（OpenId/UnionId/Userid/Nick/Avatar/Mobile（脱敏）——B 端员工组织字段）；**两步填充（Oracle 评审 P1-4/P2-5）：`/contact/users/{unionId}` → nick/avatar/mobile + `topapi/user/getbyunionid` → userid**
├── DingTalkFederationServiceCollectionExtensions.cs  # AddDingTalkFederationChannels()——AddOptions().Configure + AddHttpClient<DingTalkApiClient> + TryAddEnumerableConstructible<ISsoChannel, DingTalkOauthChannel/DingTalkEventChannel>

### 3.1 DingTalkOauthChannel 流程（新 OAuth2）

```
装配层构造 authorize URL（login.dingtalk.com/oauth2/auth？client_id+redirect_uri+scope=openid+prompt=consent+state——DTFrameLogin iframe 二维码内嵌或 302 跳转）
→ 钉钉授权 → 回调 ?code=&state=
→ 验 state（CSRF）→ DingTalkApiClient.UserAccessTokenAsync(code) → accessToken 7200s（用户级——一次性交换不缓存）
→ 解析响应含 openId/unionId（scope=openid corpid 时含 corpId）
→ SsoChannelAuthResult(Success, ExternalUserId=openId, AuthLevel=2)   // external_uid 恒 = openId（应用维度稳定标识）；userid 增强由装配层按需调 GetUserIdAsync（P1-4）
→ (channel_id=dingtalk_oauth, openId) → uid（Federation 编排层，N2 锚点策略——unionId 写联盟锚点辅助）
```

### 3.2 DingTalkEventChannel 流程（事件订阅回调）

```
钉钉事件订阅推送（扫码成功 / 组织变更等）→ 接收端点（装配层映射）
→ DingTalkEventCrypto.Verify（msg_signature = sha1(sort(token, timestamp, nonce, msg_encrypt)) + AES-CBC 解密——EncodingAESKey 43 字符 Base64Decode 派生 32 字节 AESKey）
→ 验签失败即拒（**信任根一票否决**——漏验 = 可伪造任意 unionId/openId = 体系崩溃）
→ **receiveid 校验（Oracle 评审 P1-1——第二道闸门）**：解密后提取明文尾部 receiveid 与 `DingTalkChannelConfig.CorpId` 恒定时间比对，不符拒（forged org-change event 可授予企业访问权）
→ 解密后事件体（JSON——`JsonDocument.Parse` 提取 FromUserId（= openId，应用维度）作为 external_uid 来源——P1-6）→ 进程内调 Federation 门面（IssueAsync/映射——帧内 AOP，零自签）
→ 落库即返 success（**1200ms 阈值——装配层全链职责，库 AuthenticateAsync CPU-only <50ms——P1-2**；异步业务不阻塞回调响应）
```

### 3.3 external_uid 语义（对齐 N3 QQ 先例 + N2 定案）

- **external_uid 恒 = openId**（应用维度稳定映射键——钉钉 openId 应用维度唯一，跨应用隔离依赖映射表 join uid）；
- **unionId 写联盟锚点辅助**——开启 `EnableUnionId` 时经 `ISsoAccountLinkService.SetFederationAnchorAsync` 写 `FederationAnchorOpenId`（N2 §3.1 选项 B：anchor 列存 TKWF 自生成平台无关锚点值，unionid 是辅助写入——兼容）；
- **userid（企业维度）为 DTO 增强字段**——B 端需要组织身份时经 `getbyunionid` 换取，**非 external_uid**（userid 依赖企业内成员关系，随组织变动不稳定——不参与联邦映射键）。**两步流（Oracle 评审 P1-4/P1-5）**：`OauthChannel.AuthenticateAsync` 只返回 `SsoChannelAuthResult(ExternalUserId=openId)`（`SsoChannelAuthResult` 契约无 userid 承载字段）；userid 增强由**装配层**按需调 `DingTalkApiClient.GetUserIdAsync(unionId, corpId)`（**经 channel 的 AppKey/AppSecret 换企业 token——钉钉新模式复用 OAuth 凭证，无独立 enterprise secret**）经 `DingTalkUserInfo` record 承载，不进 `SsoChannelAuthResult`。

### 3.4 信任根（事件回调——对齐微信先例 + 钉钉双阈值特化）

- **对齐微信**：`sha1(sort(token,timestamp,nonce,msg_encrypt))` + AES-CBC（EncodingAESKey 43 字符）+ `CryptographicOperations.FixedTimeEquals`（Oracle 评审 P2-7）——同构算法，`DingTalkEventCrypto` 复刻 `WeChatEventCrypto` 逻辑（**独立实现避免跨库依赖——P2-1：措辞"防漂移"改为"避免跨库依赖"；若第 3 个同构平台（M4 企业微信）落地后评估提取共享 internal helper**）；
- **receiveid 校验（Oracle 评审 P1-1——第二道闸门）**：解密明文布局 = `random(16) + msg_len(4 BE) + msg(JSON) + receiveid(corpId)`——解密后提取 `plain[20+msgLen..]` 与 `DingTalkChannelConfig.CorpId` 恒定时间比对，不符抛 `CryptographicException`（钉钉事件含组织变更——比微信消息事件敏感度高，须完整三道闸门：验签 + 解密 + receiveid 校验）；
- **1200ms 硬约束**（最严）——**库 `AuthenticateAsync` = 验签 + 解密 + receiveid 校验 + 返回 `SsoChannelAuthResult`（CPU-only，<50ms——P1-2）**；落库即返 success 是**装配层/编排层职责**（persist-then-ack 模式——防异步业务失败丢事件；推荐 `IHostedService` / `Channel<T>` 队列供装配层实施参考）；2500ms 为日常事件响应超时，实现按 1200ms 计（更严覆盖 2500ms 场景）；
- **URL 校验握手**：钉钉回调配置校验流程（get 请求 challenge 回显）——装配层处理，库提供验签原语。

## 六、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 事件回调 1200ms 响应超时（钉钉 SyncHTTP 淘汰） | 高 | 异步业务（落库即返 success）——验签 + 解密 + **落库归阻塞路径（装配层 persist-then-ack 模式，推荐 IHostedService/Channel<T> 队列），业务异步；库 AuthenticateAsync CPU-only <50ms（P1-2）**；按最严 1200ms 实现 |
| userid 依赖企业组织（不稳定）被误用为映射键 | 中 | external_uid 恒 = openId；userid 仅 DTO 展示——语义断言测试（F5） |
| 旧协议（qrconnect）被误认新应用可用 | 中 | 方案显式不接入 + 注记（§不包含）；新协议端点唯一出口 |
| Stream Mode 与 Webhook 加密基元双实现 | 中 | 本方案只实现 Webhook 验签；crypto 基元独立（可复用与 Stream 解密）——Stream 归装配层另立项（**可见性推荐 `InternalsVisibleTo`——P2-2**） |
| unionid 封闭于开发者账号（不可跨开发者） | 中 | N2 锚点自建映射（anchor 值平台无关）——unionid 仅辅助，不依赖其跨开发者对齐 |
