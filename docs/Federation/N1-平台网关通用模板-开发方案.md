# N1 平台网关通用模板 开发方案

> **立项来源**: 平台网关立项依据（近中远）N1（P0 近期）｜ **类型**: L0 基建
> **版本**: v0.1.0 ｜ **日期**: 2026-10-05 ｜ **状态**: 📋 提议（待 Oracle 评审）
> **关联**: 国内总规划 §三（8 组件模板）｜ WeChat 先例 `_Framework/Federation.WeChat/`（模板事实源）｜ 国外总规划 §五（OIDC 基座独立）｜ 立项依据 N1
> **关键约束**: 模板固化为**可复制脚手架**（复制起点），非运行时组件；不改变 WeChat 先例已落地形态

---

## 一、背景与目标

### 问题

- **每平台从零设计**：QQ/支付宝/钉钉/企业微信等新平台若直接开工，各自复制 WeChat 先例的组件清单/双通道/出站客户端/信任根/注册扩展形态——重复劳动 + 一致性风险（每个平台实现细节漂移）；
- **模式未固化**：国内总规划 §三 已定义 8 组件模板（表格形式），但**未落地为可复制脚手架**——无模板文档、无项目骨架、无测试宿主模板。

### 目标

1. **模板文档化**：8 组件模板 + 出站-only 精简形态 → 权威模板文档（新平台开发的第一参考）；
2. **项目脚手架**：`_Framework/Federation.{平台}/` 目录骨架 + csproj 模板 + Options/Client/Channel/注册扩展/测试宿主模板文件（复制即改）；
3. **首个验证**：以 N3（QQ，出站-only 形态）为试点验证模板——QQ 骨架按模板复制，验证模板可用性（30min 起步目标）。

### 不包含

| # | 内容 | 去向 |
|---|------|------|
| 1 | 通用 OIDC 基座 `TKWF.Federation.Oidc` | N1 不做——OIDC 平台走基座（M1 中期立项），N1 模板覆盖 WeChat 式（授权码/设备授权/事件推送）通道形态 |
| 2 | 具体平台实现（QQ/支付宝等） | N3/N4 等平台立项——N1 只产出模板 + 骨架 |
| 3 | 联盟锚点映射策略 | N2 立项——模板仅引用锚点配合接口 |

## 二、模板设计（8 组件 + 出站-only 精简形态）

### 2.1 完整形态（有入站回调平台——微信/钉钉/企业微信）

```
_Framework/Federation.{平台}/
├── TKWF.Federation.{平台}.csproj
├── {平台}Options.cs              # 组件 5：配置（[Options("TKWF:Federation:{平台}")] + Channels 列表 + 凭证自持）
├── {平台}ChannelConfig.cs        # 组件 5：通道配置 record（ChannelId + 平台凭证字段）
├── {平台}ApiClient.cs            # 组件 1：出站客户端（typed client：HttpClient + IOptions + ILogger；token L1 缓存 + 并发锁 + 提前过期刷新；code→uid 一次性；用户信息裁剪）
├── {平台}OauthChannel.cs         # 组件 2：OAuth 通道（ISsoChannel：ChannelType="{platform}_oauth"；authorize 构造（装配层）+ 回调 code→external_uid；AuthLevel=2）
├── {平台}EventChannel.cs         # 组件 3：事件/回调通道（ISsoChannel：ChannelType="{platform}_event"；入站验签 + 解密 + FromUserName→external_uid）
├── {平台}EventCrypto.cs          # 组件 4：验签逻辑类（收 byte[]/Stream + 恒定时间比对；信任根一票否决）
├── {平台}UserInfo.cs             # 组件 6：用户信息 DTO（响应裁剪 record）
├── {平台}FederationServiceCollectionExtensions.cs  # 组件 7：Add{平台}FederationChannels()（TryAddEnumerableConstructible<ISsoChannel>）
└── (无 Initializer 无 [TKWFExtension]——纯库判据)
```

### 2.2 出站-only 精简形态（无入站回调平台——QQ/支付宝/B站/小红书/国外 OIDC）

```
= 完整形态减去 组件 3（EventChannel）+ 组件 4（EventCrypto）
  保留：组件 1/2/5/6/7/8（出站客户端 + OAuth 通道 + 配置 + 用户信息 DTO + 注册扩展 + 测试）
  信任根降级：出站 code 一次性 + state CSRF + client_secret/私钥换取 + id_token JWKS 验签（若适用）
```

### 2.3 依赖接线（固定，对齐 WeChat 先例——Oracle 评审 P1-2 补 CodeGeneration.Abstractions）

```xml
<!-- TKWF.Federation.{平台}.csproj -->
<ProjectReference Include="..\Federation\TKWF.Ext.Federation.csproj" />   <!-- 实现 ISsoChannel（Oracle P1-1） -->
<ProjectReference Include="..\Authentication.Abstractions\TKWF.Ext.Authentication.Abstractions.csproj" /> <!-- 消费面契约（按需——Federation 通道一般不直接消费，保留模板位） -->
<PackageReference Include="TKWF.Domain" Condition="'$(UseLocalFw)' != 'true'" />
<!-- ⚠️ CodeGeneration.Abstractions：DiContractIgnore 特性所在程序集（通道手写注册豁免 DI001 误报）——对齐 WeChat csproj 实际引用，双模式接线 -->
<PackageReference Include="TKWF.CodeGeneration.Abstractions" Condition="'$(UseLocalFw)' != 'true'" />
<Reference Include="TKWF.CodeGeneration.Abstractions" Condition="'$(UseLocalFw)' == 'true'" />
<PackageReference Include="Microsoft.Extensions.Http" />                  <!-- typed client -->
<!-- ⚠️ 不引 AspNetCore（P6）——入站端点归装配层 -->
```

### 2.4 注册扩展模板（组件 7 固定形态）

```csharp
public static class {Platform}FederationServiceCollectionExtensions
{
    public static IServiceCollection Add{Platform}FederationChannels(
        this IServiceCollection services, Action<{Platform}Options>? configure = null)
    {
        // ✅ Oracle 评审 P1-1 修正：对齐 WeChat 先例实际代码（WeChatFederationServiceCollectionExtensions.cs:37）
        //    使用 AddOptions().Configure 延迟应用配置——禁止 BuildServiceProvider 提前解析（临时根容器 + Scoped 捕获异常 + 性能问题）
        services.AddOptions<{Platform}Options>().Configure(o => configure?.Invoke(o));
        services.AddHttpClient<{Platform}ApiClient>(); // typed client（ctor HttpClient 注入——修 DefaultTypedHttpClientFactory 循环）
        services.TryAddEnumerableConstructible<ISsoChannel, {Platform}OauthChannel>(); // ADR92 集合版守卫工厂
        // 有入站回调平台追加：
        // services.TryAddEnumerableConstructible<ISsoChannel, {Platform}EventChannel>();
        return services;
    }
}
```

## 三、任务拆解

| 任务 | 描述 | 产出 | 工作量 |
|------|------|------|--------|
| T1 | **模板文档**——8 组件模板 + 出站-only 精简形态 + 依赖接线 + 注册扩展形态 固化为一节权威模板章节（可放国内总规划 §三或独立模板文档） | `docs/Federation/平台网关模板-开发指南.md`（新） | 低 |
| T2 | **项目脚手架**——`Federation.{平台}` csproj 模板 + 目录骨架 + 各组件文件模板（`{平台}` 占位符） | `_Framework/Federation.Template/`（含 README 说明复制用法）或 `.xCodeGen/` 旁模板目录 | 中 |
| T3 | **测试宿主模板**——`{平台}TestHost` 模板 + OAuth 正负 + 信任根正负 + 探针门面模板 | 测试模板文件 | 中 |
| T4 | **N3（QQ）试点验证**——按模板复制 QQ 骨架（出站-only 形态），验证模板可用性；模板缺陷回填 | N3 骨架（完整实现归 N3 立项）。**骨架边界界定（Oracle 评审 P1-3）**：T4 产出 = `TKWF.Federation.QQ.csproj` + 空 `QqOptions`/`QqChannelConfig`/`QqApiClient`/`QqOauthChannel` 类签名（仅骨架不含协议实现）+ `AddQqFederationChannels()` 壳 + `QqTestHost` 壳——**N3 在其上填充协议实现**（T1 csproj 接线 / T2 ApiClient 逻辑 / T3 OauthChannel 逻辑），避免与 N3 任务重叠 | 中 |

> **注**：T4 与 N3 有协作——N1 产出模板 + QQ 骨架，N3 立项在骨架上完成协议实现；两立项边界在"骨架（N1）vs 协议实现（N3）"。

## 五、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 模板过度抽象（为未定平台设计通用性） | 中 | YAGNI——模板只固化已实证形态（WeChat 先例），未验证形态（设备授权流/Apple 变体）标注"待对应平台立项时回填" |
| 模板与 WeChat 先例漂移 | 中 | WeChat 为权威事实源，模板提炼不重构；模板变更须对照先例审查 |
| 注册扩展模板 BuildServiceProvider 提前解析隐患 | 高 | 模板注记明确规避（对齐 WeChat 实际实现）；测试覆盖 |
