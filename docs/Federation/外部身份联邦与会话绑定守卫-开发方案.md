## 一、目的与目标

解决"**外部身份（微信/企微/支付宝/未来任意 IdP）如何安全地成为框架会话身份**"的统一问题。目标状态：

1. **框架级会话身份绑定守卫**——任何"外部身份→会话绑定"路径都必须经过 `uid` 一致性校验（修复框架现存安全缺口：`SessionInfo.BindUser`/`LoginAsUserAsync(TUserInfo)`/`UpdateAndActiveSessionAsync` 无条件替换，无绑定守卫；对比 tenant/OAuth-id_token/System 均已有守卫，唯 session 身份缺失）。
2. **框架级"已可信外部身份"语义**——`EnumLoginAuthType.Federated` 表达"外部方已担保、直接绑定"（区别于既有 `OAuth`=AuthCenter JWT 恢复；**仅经 `LoginAsFederatedAsync` 可达**，不进 switch 分派——评审 C1/C2），供**未来所有认证类外部联邦**（微信/企微/支付宝/QQ/Google/LDAP/OIDC/SAML）统一走同一钩子。
3. **框架级密封票据原语**——`ISealedTicketService<T>` 统一"签发→兑换→防重放→TTL"形态，后端可插拔（HMAC 无状态 / AES-GCM 密封 / 内存 / DB）；**Phase 0 只建接口 + 内存后端**，不强制迁移既有 4 票据。
4. **消费方单操作接入**——`DomainUser.LoginAsFederatedAsync(ticket, identity, loginFrom)` 合并"兑换票据→UserHelper 钩子映射→会话守卫→绑定"为一步，消费方不散调三扩展。

## 二、问题

### 2.1 现状问题（代码实证）

| # | 问题 | 实证 |
|---|------|------|
| P1 | **会话身份无绑定守卫**——`SessionInfo.BindUser`（`_TKWF/_Framework/Domain/Session/SessionInfo.cs` L48/L102）无条件替换 session.User；`DomainUser.LoginAsUserAsync(TUserInfo, EnumLoginFrom)`（`DomainUser.cs` L451）调用方塞任意 TUserInfo 绑定到任意 SessionKey；`UpdateAndActiveSessionAsync`（L503）`session.BindUser(this)` 无校验。（注 m2：`GetOrRestoreUserAsync`（DomainHost.cs L139）是**恢复路径**非绑定路径——返回既有 session.User，不调 BindUser，D1 守卫不适用；sessionKey 伪造属另一威胁，不属本方案） | 对比先例：tenant 身份有守卫（跨租户写拒绝）、OAuth id_token 有守卫（iss/azp 强制等值）、System 作用域有守卫（Human→System 硬抛）——**唯 session 身份无守卫** |
| P2 | **外部身份源无框架级语义**——`EnumLoginAuthType` 仅 {Password/SmsCode/WeChatScan/WeChatApplet/OAuth/SecurePassword}；`EnumLoginFrom` 是**终端渠道**非认证源；`ActorKind` {None/Human/System} 无 External | 已可信外部身份在枚举里无处安放 |
| P3 | **票据机制四处平行**——AuthCenter OAuthTicket（DB+PKCE+5min）、TrustCenter AccessCode（DB+SHA256+AES-GCM+120s+Claimant CAS）、AuthSurface RedemptionCode（DB+CodeHash+AES-GCM）、MFA challenge（内存单次）——同形态（签发 payload+TTL→字符串票据→兑换 payload→防重放）各自实现 | 框架已有 `ChallengeTokenService`（HMAC 自签名+内存反重放，零基础设施）但未泛化 |
| P4 | **消费方接入散裂**——落地页需手动串联 TrustCenter Redeem + AuthCenter 会话 + DomainUser 绑定三步；且步骤间有 TOCTOU 窗口 | 场景要求"在扩展验证框架内合并" |
| P5 | **现有 OAuth 钩子名不副实**——`OnLoginByOAuthAsync` 在 AuthCenter 实现为 `RestoreFromTokenAsync`（验证 AuthCenter JWT 的票据换令牌），非真正"IdP 担保→直绑" | 新语义需独立钩子，不破坏既有消费方 |

### 2.2 触发场景

- **微信未认证号**：事件推送（FromUserName=openid）→ Federation 验签 → 签密封票据进图文链接 → 用户点击 → 落地页兑换 → 建 session（**AccessCode 是唯一身份载体**——平台无静默 OAuth）
- **微信认证服务号**：静默 snsapi_base → OAuth 回调 code → 外部认证（现 `ExternalIdpLoginService` 链）
- **企微事件 / 支付宝通知 / 未来消息平台**：同一 `Federated` 钩子 + 同一密封票据原语
- **会话 uid 不一致**：已登录用户点击他人图文链接（AccessCode 绑定 uid A，当前会话 uid B）→ 框架守卫拒绝而非消费方手判

### 2.3 现有方案不足

- 初版 Oracle 评审（F2：POCO 落 AuthCenter.Abstractions / F3：用既有 LoginAsUserAsync(TUserInfo)）——经终审**推翻**：横切框架身份概念应归 Core/Domain（AuthContext 先例），UserHelper 钩子系列化（枚举+switch+虚钩子）是框架既定模式
- 扩展侧各自实现票据 → 无法复用离线验证/内存票据，未来 IdP 继续重造

## 三、使用场景

| 场景 | 适用 | 不适用 |
|------|------|--------|
| 事件推送身份（微信未认证号/企微/未来消息平台）→ 图文链接 AccessCode → 落地建 session | ✅ `Federated` 钩子 + 密封票据 | 平台提供静默 OAuth 且可接受的场景（可用 OAuth 恢复，无 AccessCode 需求） |
| 认证服务号静默授权 → 外部认证建 session | ✅ 现 `ExternalIdpLoginService`（扩展适配 Phase 1 后可并入 Federated 钩子） | 单应用内部密码/短信登录（不涉外部身份） |
| 未来外部 IdP（LDAP/OIDC/SAML/自定义）接入 | ✅ 同一 `FederatedIdentity` POCO + `OnLoginByFederatedAsync` 钩子 + 密封票据 | 已 AuthCenter 自签 JWT 的既有恢复流（OAuth=5 兼容保留） |
| 已登录会话点开他人票据链接（uid 不一致） | ✅ D1 会话绑定守卫框架层拒绝 | — |
| 票据持久化需求（审计/跨实例） | ✅ DB 后端（Phase 2 适配 AccessCode） | 一次性/短 TTL 场景（内存/无状态后端足够） |

## 四、设计（框架 Core/Domain——自上而下）

### D1：会话身份绑定守卫（修复框架级安全缺口）

**位置**：`_TKWF/_Framework/Domain/Session/SessionInfo.cs` + `_TKWF/_Framework/Domain/DomainUser.cs`

**拆分实现**（Oracle N1——BindUser 是无作用域上下文的 record，守卫不能全放这里）：

```csharp
// ① SessionInfo<TUserInfo> 增属性（M1：显式声明，init，默认 false——C# record init 天然参与相等性，控制位随实例走）
public sealed record SessionInfo<TUserInfo>(string Key, DomainUser<TUserInfo>? User) : SessionInfo(Key, User)
{
    public bool AllowReplaceIdentity { get; init; } = false;   // D1 显式替换信号（默认 false）

    public SessionInfo<TUserInfo> BindUser(DomainUser<TUserInfo> user)
    {
        // D1 守卫（record 内——uid + 认证状态检查）：
        // 会话已有【已认证】用户 && 传入【已认证】用户 && uid 不同 && 未显式允许替换 → 拒绝
        if (User?.IsAuthenticated == true && user.IsAuthenticated
            && !string.Equals(User.UserInfo.UserIdString, user.UserInfo.UserIdString, StringComparison.Ordinal)
            && !AllowReplaceIdentity)
        {
            throw new SessionIdentityConflictException(
                $"会话身份冲突：会话用户 {User.UserInfo.UserIdString} ≠ 绑定用户 {user.UserInfo.UserIdString}");
        }
        user.SessionKey = Key ?? throw new InvalidOperationException("会话 Key 不能为空");
        return new SessionInfo<TUserInfo>(Key, user) { TimeCreated = TimeCreated, TimeLastActivated = DateTime.UtcNow };
    }
}
// ② DomainUser.UpdateAndActiveSessionAsync（调用方——可访问 Host；两路径覆盖 m3）
public async Task<SessionInfo<TUserInfo>> UpdateAndActiveSessionAsync()
{
    var session = await Host.TypedSessionManager.TryGetAndActiveSessionAsync(SessionKey);
    if (session == null)
    {
        // 路径 1：新会话（User=null → 守卫短路通过——null-User 恒满足）
        var fresh = await Host.TypedSessionManager.NewSessionAsync();
        return (fresh with { AllowReplaceIdentity = IsSystemScope() }).BindUser(this);
    }
    // 路径 2：既有会话重绑——System 作用域允许替换；否则守卫在 BindUser 内生效
    return (session with { AllowReplaceIdentity = IsSystemScope() }).BindUser(this);
}
private bool IsSystemScope() => DomainUser<TUserInfo>.CurrentActorKind == ActorKind.System;   // M2 明确
// ③ Logout（DomainUser.cs L475-501）：传入用户是 guest（IsAuthenticated=false）→ 守卫自动允许
// ④ CreateNewGuestSessionAsync 绕过修复（评审 N2）：DomainUserHelperBase L85 直接构造
//    new SessionInfo<T> → 改经 BindUser 路由（修 SessionKey 赋值根因，V4.9.84 变通方案妥善修复）
```

**兼容性**（评审 Q1）：**默认开启**（安全守卫 opt-in 无意义）+ `AllowReplaceIdentity` 显式信号为合法逃生门（System 作用域自动允许）。`Logout`（传入 guest）与 `System` 自动允许，无需配置。

**守卫矩阵**：

| 流程 | 会话既有用户 | 传入用户 | 守卫动作 |
|------|-------------|----------|---------|
| 新登录（guest→认证） | guest（IsAuthenticated=false） | 认证 | ✅ 允许（guest 短路） |
| 注销（认证→guest） | 认证 | guest（false） | ✅ 允许（传入非认证） |
| System 操作绑定 | 任意 | 任意 | ✅ 允许（CurrentActorKind==System） |
| 同 uid 重绑 | 认证 A | 认证 A | ✅ 允许（uid 相等） |
| **跨 uid 劫持** | 认证 A | 认证 B | ❌ 拒绝（SESSION_IDENTITY_CONFLICT） |
| 显式替换 | 认证 A | 认证 B | ✅ 允许（AllowReplaceIdentity=true——系统级操作显式声明） |

**新异常**：`SessionIdentityConflictException`（领域异常，机器可读 `SESSION_IDENTITY_CONFLICT`）。

### D2：`EnumLoginAuthType.Federated`（框架身份语义）

**位置**：`_TKWF/_Framework/Core/EnumLoginAuthType.cs` + `_TKWF/_Framework/Domain/DomainUserHelperBase.cs`

```csharp
// EnumLoginAuthType 增（评审 N4：Federated 不用 External——对齐 AuthLevel.Federated/token authType）
public enum EnumLoginAuthType { ... OAuth=5, SecurePassword=6, Federated=7 }
```
**⚠️ 修订（评审 C1/C2——signature 一致）**：`Federated=7` **仅经 `LoginAsFederatedAsync` 可达**，**不加入 `OnUserLoginAsync` switch 分支**——switch 的 `_` 默认分支抛 `NotSupportedException`（"联邦身份登录请使用 LoginAsFederatedAsync"）。理由：switch 路径（`LoginAsUserAsync(userName, credential, AuthContext{AuthType=Federated})`）无法从 `userName/credential/authInfo` 构造 `FederatedIdentity` POCO；D5 是唯一入口，避免死代码/签名矛盾。

**与 `OAuth=5` 区别**（设计角度）：OAuth=5 = AuthCenter JWT 恢复（既有兼容，`OnLoginByOAuthAsync`→`RestoreFromTokenAsync`）；Federated=7 = 外部担保直绑（新语义，`OnLoginByFederatedAsync`）。二者并存不并入——信任模型不同，OAuth 钩子既有消费方零迁移红线。

### D3：`ISealedTicketService<T>` 密封票据原语（Phase 0 最小：接口 + 内存后端）

**位置**：`_TKWF/_Framework/Domain/Ticket/ISealedTicketService.cs` + `_TKWF/_Framework/Domain/Ticket/InMemorySealedTicketService.cs`

```csharp
public interface ISealedTicketService<T> : IDomainService where T : class
{
    Task<SealedTicketResult> IssueAsync(T payload, TimeSpan ttl, SealedTicketOptions? options = null, CancellationToken ct = default);
    Task<T?> RedeemAsync(string ticket, CancellationToken ct = default);   // 原子单次消费（评审 C3：非泛型——T 来自接口；无 context 参数）
    Task<int> CleanupExpiredAsync(CancellationToken ct = default);   // 周期清理（内存后端惰性；DB 后端按 retention）
}
public sealed record SealedTicketOptions(
    string? ExpectedClaimant = null,        // 可核销人（Phase 2 CAS 接线时生效——M4 TicketRedeemContext 延后）
    string? TicketType = null,
    IReadOnlyDictionary<string, string?>? Extensions = null);
public sealed record SealedTicketResult(string Ticket, int ExpiresIn);
```

**⚠️ Phase 0 范围澄清（评审 M6）**：`SealedTicketOptions` 是 **Phase 0 最小形态**（Claimant 预留 + TicketType + Extensions 字典），**不声称泛化全部 4 个既有实现**——PKCE（OAuthTicket/AccessCode 有）、加密模式选择（AES-GCM 密钥引用）、尝试限流（MFA）均**延后 Phase 2** 经 `Extensions` 字典按实现扩展。Phase 2 迁移非 1:1，按各信任模型适配。`TicketRedeemContext` 不在 Phase 0（评审 C3/M4——CAS 完整接线时引入）。

**后端可插拔**（Phase 0 只做 1）：
- `InMemorySealedTicketService<T>`：**Singleton 注册 + 实例内 `ConcurrentDictionary`**（评审 M3——`ISealedTicketService<T> : IDomainService` 隐含 Scoped，若用实例级字典则跨作用域不可兑换；必须 Singleton，对齐 `ChallengeTokenService._usedTokens` 先例）+ TTL 惰性清理 + `TryAdd` 原子单次（TOCTOU 消除）
- Phase 2：无状态 HMAC 后端（`ChallengeTokenService` 形态上提）、AES-GCM 密封（`ISymmetricKeyProvider`+`AeadEncryptionUtil` keyed DI）、ES256 JWT（Token2Service 模式）、DB CAS（适配现有表）、`ICacheProvider` 分布式反重放（接口已有，impl net-new）

**DI 注册（评审 M3 明确）**：

```csharp
// 框架默认（或消费方 DomainHostInitializer.OnRegisterDomainServices 注册）：
services.AddSingleton<ISealedTicketService<FederatedIdentity>, InMemorySealedTicketService<FederatedIdentity>>();
// E2 覆盖：TrustCenter 注册 AccessCodeService 实现（DB 后端）——TryAdd 语义（先注册者生效）或显式 keyed
// fail-hard（评审 m4a）：未注册时 user.Use<ISealedTicketService<FederatedIdentity>>() 抛 DI004 守卫——fail-closed 不静默降级
```

**不强制迁移**（评审 N3）：现有 OAuthTicket/AccessCode/RedemptionCode/MFA 保留——Phase 2 按需适配，不强制。

### D5：`DomainUser.LoginAsFederatedAsync` 单操作合并

**位置**：`_TKWF/_Framework/Domain/DomainUser.cs`

```csharp
/// <summary>联邦身份登录（D5——兑换票据+钩子映射+会话守卫+绑定 单操作；步骤 2/3 合并，无 TOCTOU）</summary>
public async Task LoginAsFederatedAsync(string ticket, FederatedIdentity expectedIdentity, EnumLoginFrom loginFrom, CancellationToken ct = default)
{
    // ① 兑换密封票据（Oracle N5：帧内 user.Use<T>() 解析——DI004；未注册抛守卫 = fail-hard）
    var service = Use<ISealedTicketService<FederatedIdentity>>();
    var identity = await service.RedeemAsync(ticket, ct);   // 原子单次 CAS；非泛型调用（C3 定案——T 来自接口）
    if (identity is null) throw new AuthenticationException("TICKET_EXPIRED_OR_CONSUMED");
    // ② 票据身份 vs 期望身份一致性（防票据替换）
    if (!string.Equals(identity.UId, expectedIdentity.UId, StringComparison.Ordinal))
        throw new AuthenticationException("FEDERATED_IDENTITY_MISMATCH");
    // ③ UserHelper 钩子映射（外部担保 → TUserInfo）
    var userInfo = await Host.UserHelper.OnLoginByFederatedAsync(this, identity, loginFrom);
    // ④ D1 守卫绑定
    UserInfo = userInfo; UserInfo.LoginFrom = loginFrom; IsAuthenticated = true;
    await UpdateAndActiveSessionAsync();   // BindUser 内守卫生效
}
```

**与 `LoginAsUserAsync(TUserInfo, loginFrom)` 关系**（Oracle Q5）：互补不冲突——前者是裸逃生舱（低层），后者是完整管线（高层）。不合并（重载会混淆抽象级别）。
