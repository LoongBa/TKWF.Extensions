## 一、目的与目标

消费方（DMP-Lite 三站：Platform/AdminUI/UserH5 + 独立子应用：XiaoShuTong/EduPlatform）接入认证体系的**标准协议**。两种模式：

| 模式 | 语义 | 账户体系 | 适用 |
|------|------|---------|------|
| **直接接入**（默认能力） | 各应用被视为 Platform 的子系统/子应用 | 账号统一 Platform AuthCenter | AdminUI/UserH5/新应用 |
| **仅共享 Federation**（重点） | 各应用保持独立账户体系，仅共用 Federation 多通道能力（外部 IdP 认证委托） | 各应用本地 AuthCenter（XiaoShuTong/EduPlatform 保留） | 既有子应用 |

目标状态：**Federation 多通道能力（平台凭证/协议单点）只在 Platform 部署**；子应用零平台库、零凭证、零 Federation 扩展装配；统一票据协议（accesscode 安全投递）覆盖两种模式。

## 二、问题

现状缺口（探索实证 + Oracle 评审）：

1. **`SsoLogin` 为纯通道认证**（`CreateAsync` 选区 + `AuthenticateAsync` → `SsoChannelAuthResult.ExternalUserId`）——无建号/发码/签 token2。子应用委托需外部认证的**编排面**（验 state → 认证 → 签票据）。
2. **`ISsoClientService`（origin 白名单/credential 校验）在 TrustCenter 主包**，Federation 若引主包违反 L2 门控（TKWF0022 Error）——校验面须契约化入 Abstractions。
3. **`ISsoChannel` 契约无 `BuildAuthorizeUrl`**——现有 5/8 平台库显式声明"authorize 构造归装配层"（QQ N3 P1-3 / WeChat / WeCom / Google / DingTalk），FederationWebExtension 注释明示"不臆造契约"。但"通知各方适配"需要**统一协议的 authorize/start 端点**——授权 URL 构造须收敛于通道实现（ADR 裁定，见关联文档）。
4. 无面向子应用的 server-to-server 委托换取端点。

## 三、设计决策（Oracle 6 条件已吸收）

### 决策 1：统一票据协议 = TrustCenter `accesscode` 安全数据投递

两种模式统一以 accesscode 为交接票据（`IAccessCodeService` 重载 ②）——Platform 装配面签发、子应用兑现。**选型依据**：120s 短 TTL · 原子 CAS 单次 · `expectedClaimant` 原子核销 · Payload AES-GCM 密文 · 容量 4068 字节。复用成熟安全基座，零新增加密原语。（Oracle ✅）

### 决策 2：`ISsoChannel` 增可选 `BuildAuthorizeUrlAsync`（DIM 默认 null 非破坏）【ADR 记录反转】

```csharp
// TrustCenter.Abstractions
public interface ISsoChannel : IDomainService
{
    string ChannelType { get; }
    string ChannelId { get; }
    Task<SsoChannelAuthResult> AuthenticateAsync(SsoChannelAuthContext context, CancellationToken ct = default);

    /// <summary>构造授权 URL（authorize/start 端点用）。默认 null = 不支持（端点返回 AUTHORIZE_NOT_SUPPORTED）。</summary>
    Task<SsoChannelAuthorizeResult?> BuildAuthorizeUrlAsync(SsoChannelAuthorizeContext context, CancellationToken ct = default) => Task.FromResult<SsoChannelAuthorizeResult?>(null);
}
/// <summary>授权 URL 构造输入（RedirectUri 必须入参——8 库零 redirect 配置字段；State 可空 = 引擎/通道自行生成）。</summary>
public sealed record SsoChannelAuthorizeContext(string RedirectUri, string? State, string? Scope, IReadOnlyDictionary<string, string?> Parameters);
/// <summary>授权 URL 构造输出（字段形态对齐引擎 OAuthAuthorizeResult，零转译）。</summary>
public sealed record SsoChannelAuthorizeResult(string Url, string? State, string? PkceVerifier, string? PkceChallenge);
```

- **设计反转声明（Oracle 条件 2）**：既有"不臆造契约，authorize 归装配层"决策被**有意推翻**（ADR-Federation-子应用委托授权URL构造契约化）——理由：多子应用统一协议的 authorize/start 端点需要授权 URL 构造收敛于通道实现；DIM 默认 null 对既有/未来库**非破坏**；各库内部已有构造逻辑可收敛（Alipay `BuildAuthorizeUrl` / OIDC `OidcChannelFlow` / WeChat 可复用引擎 OAuthClient 微信方言 / WeCom `WeComAuthorizeUrlBuilder` 双流合并）。
- **State 方向（探索约束 1）**：OIDC 引擎 `BuildAuthorizeUrl()` 自生成 state（无入参）——`SsoChannelAuthorizeContext.State` 可空（null = 引擎/通道生成），生成值经 `SsoChannelAuthorizeResult.State` 回传（Platform 侧组装 state 票据）。
- **PKCE（探索约束 2）**：仅 OIDC 系启用——`PkceVerifier/PkceChallenge` 可空承载，回调侧须能以 `Parameters["code_verifier"]` 键衔接（探索约束 6）。
- **WeCom 双流（探索约束 3）**：Webview/扫码两端点——经 `Parameters` 字典承载 `flow`/`login_type` 选择器，单 URL 返回。
- **模板实例（探索约束 5）**：通道 `channel=null` 集合模板实例 → `BuildAuthorizeUrlAsync` 返回 null（不可认证语义对齐）。

### 决策 3：TrustCenter.Abstractions 增只读校验契约 + `SsoClientInfo` 迁移（Oracle 条件 6）

```csharp
// ⚠️ SsoClientInfo 从 TrustCenter 主包【迁移】至 Abstractions（非新增——Oracle 条件 6）
// TrustCenter.Abstractions 新增（命名空间 TKWF.Ext.TrustCenter）
public sealed record SsoClientInfo(string AppId, IReadOnlyList<string> OriginWhitelist, IReadOnlyList<string> Scopes, bool IsEnabled);
public interface ISsoClientQueryService : IDomainService
{
    Task<SsoClientInfo?> GetInfoAsync(string appId, CancellationToken ct = default);
    Task<bool> IsOriginAllowedAsync(string appId, string origin, CancellationToken ct = default);
    Task<bool> ValidateClientCredentialAsync(string appId, string clientSecret, CancellationToken ct = default);
}
// TrustCenter 主包：ISsoClientService : ISsoClientQueryService（现有成员实现复用，非破坏）
```

- **理由**：Federation 端点编排需要校验面——契约化入 Abstractions 使 Federation 经 L2 间接层消费（合法）；`SsoClientInfo` 随接口迁移（TrustCenter V0.1.0 未发布，零下游影响）；新增接口非破坏（ISsoClientService 继承补实现）。

### 决策 4：编排门面 `ISsoSubAppBridge`（Federation 主包）+ state 票据用 Federation 密钥（Oracle 条件 3）

```csharp
public interface ISsoSubAppBridge : IDomainService
{
    Task<AuthorizeStartResult> StartAsync(AuthorizeStartRequest req, CancellationToken ct = default);
    Task<OAuthCallbackResult> CompleteOAuthAsync(string channelId, IReadOnlyDictionary<string, string?> parameters, CancellationToken ct = default);
    Task<TrustIssueResult> IssueForPlatformUserAsync(TrustIssueRequest req, string platformUid, CancellationToken ct = default);
    Task<IdentityClaimResult> ClaimAsync(IdentityClaimRequest req, CancellationToken ct = default);
}
```

**state 票据**：`state = base64url(app_id | redirect | sub_state) + HMAC`——**keyed `ISymmetricKeyProvider`，`SymmetricKeyProviderKeys.Federation`**（Federation 自有密钥，Initializer 已注册——Oracle 条件 3：跨域复用 TrustCenter 密钥违反密钥隔离，Federation 键零新增配置且域内自洽）。

### 决策 5（Oracle 条件 4/5）：防枚举 + 限流

- **claim 端点**：未知 app_id 与 credential 错误**统一 401 `AUTHENTICATION_FAILED`**（不区分 `APP_NOT_FOUND`/`INVALID_CREDENTIAL`——防 app_id 枚举）。
- **authorize/start 端点**：匿名 + **RateLimiting**（IP 分区，消费方装配 RateLimitingWebExtension 或端点内前置检查）——防滥用/DoS；app_id 不存在统一 400 通用错误。

## 四、端点协议（FederationWebExtension 增 4 端点）

前缀复用 `FederationEndpointOptions.RoutePrefix`（默认 `/feberation`）。Options 增 4 开关（默认 true，`TKWF:Federation:Web`——仅暴露面）。**平台段**（V0.7.0）：`oauth/callback` 属**平台集成面**（含 `{platformId}` 平台段 = `ChannelConfig.PlatformType`，Ordinal 校验不一致 404 `CHANNEL_NOT_FOUND`；多活跃通道省略通道段 → 400 `CHANNEL_REQUIRED`，单活跃通道降级）；`authorize/start`·`trust/issue`·`identity/claim` 属**信任/委托面**（跨平台根级，不挂平台段，仅换前缀）。

| # | 端点 | 鉴权 | 请求 | 响应/行为 |
|---|------|------|------|----------|
| 1 | `POST {prefix}/authorize/start`（匿名 + 限流） | redirect ∈ app_id origin 白名单 | `{app_id, mode: federated\|direct, channel_id?, state, redirect, scope?}` | 200 `{authorize_url, state}`（federated：通道 `BuildAuthorizeUrlAsync`；direct：Platform 登录跳转 URL） |
| 2 | **`GET`** `{prefix}/{platformId}/oauth/{channelId}/callback`（匿名）【Oracle 条件 1】 | 平台 OAuth 自身（state 票据验签） | **GET query** 原样（code/state 等） | `ISsoLogin.LoginAsync` → 签 accesscode（payload=`{mode:"federated", channel_id, external_user_id}`，expectedClaimant=app_id）→ **302** redirect?code=xxx&state=sub_state；失败映射 FailReason（省略通道段变体 `{prefix}/{platformId}/oauth/callback`：单活跃通道降级 / 多活跃通道 400 `CHANNEL_REQUIRED`） |
| 3 | `POST {prefix}/trust/issue`（**已认证** Bearer token1） | AuthCenter 中间件验签（与 AuthCenterWebExtension 同装配） | `{app_id, redirect, state}` | 验白名单 → 签 accesscode（payload=`{mode:"direct", platform_uid}`，expectedClaimant=app_id）→ **302** redirect?code=xxx&state=yyy |
| 4 | `POST {prefix}/identity/claim`（匿名 + 子应用 credential） | `ValidateClientCredentialAsync`（AES-GCM + FixedTimeEquals） | `{app_id, client_secret, code}` | `RedeemAsync(code, claimant=app_id)` → 200 `{mode, channel_id?, external_user_id?, platform_uid?}`；判因映射（见下） |

**⚠️ callback 为 GET（Oracle 条件 1 修正）**：OAuth IdP（微信/QQ/支付宝）以 **302 GET 重定向**带 code+state 回调——POST 端点必 405。`MapGet` + 处理流程（验 state → 认证 → 签票据 → 302 跳回子应用）。与既有 `POST {prefix}/{platformId}/login/{channelId}`（消费方后端 POST code → JSON）**流程互补不重叠**：前者 IdP 发起、后者消费方发起。

**错误码映射**（防枚举统一化——Oracle 条件 4）：

| 码 | HTTP | 场景 |
|----|------|------|
| `AUTHENTICATION_FAILED` | **401** | claim：app_id 未知 **或** credential 错误（统一，防枚举） |
| `ORIGIN_NOT_ALLOWED` | 400 | redirect 不在 origin 白名单（防开放重定向） |
| `CHANNEL_NOT_FOUND` | 404 | channel_id 不存在，或路由平台段与通道 `PlatformType` 不匹配（Ordinal 校验） |
| `CHANNEL_REQUIRED` | 400 | 多活跃通道下省略通道段（B 守卫——`{prefix}/{platformId}/oauth/callback` 仅单活跃通道降级） |
| `AUTHORIZE_NOT_SUPPORTED` | 400 | 通道未实现 `BuildAuthorizeUrlAsync`（DIM null） |
| `STATE_INVALID` | 400 | state 票据验签失败/过期 |
| `RATE_LIMITED` | 429 | authorize/start 超频 |
| `CHANNEL_REGISTRY_UNAVAILABLE` | 503 | 门面未拦截异常兜底 |
| `ACCESS_CODE_NOT_FOUND` / `TICKET_EXPIRED` / `TICKET_CONSUMED` / `CLAIMANT_MISMATCH` | 400 | RedeemAsync 判因透传 |

## 五、流程

### 模式 A：仅共享 Federation（XiaoShuTong/EduPlatform——账户本地保留）

```
① 子应用前端点"微信登录" → 子应用后端 → POST {prefix}/authorize/start {app_id, mode:federated, channel_id, state:子应用sub_state, redirect}
        → Platform 验 redirect ∈ 白名单 → 通道 BuildAuthorizeUrlAsync(redirect_uri={prefix}/{platformId}/oauth/{channelId}/callback, state=Platform签名票据) → 返回 authorize_url
② 前端跳微信 → 微信 302 GET 回调 Platform {prefix}/{platformId}/oauth/{channelId}/callback?code=xxx&state=yyy
③ Platform(GET): 验 state 票据（解 app_id/redirect）→ ISsoLogin.LoginAsync(channelId, context(code)) → external_user_id
        → IAccessCodeService.IssueAsync(payload:{mode:"federated",channel_id,external_user_id}, ttl:120s, expectedClaimant:app_id)
        → 302 重定向 redirect?code=xxx&state=sub_state
④ 子应用后端 → POST {prefix}/identity/claim {app_id, client_secret, code}
        → ValidateClientCredentialAsync → RedeemAsync(code, claimant=app_id) → {channel_id, external_user_id}
⑤ 子应用本地：PlatformAccountMap (channel_id, external_user_id) → 查/建本地 uid → 签本地 token1 → 登录成功
```

**关键语义**：`ISsoLogin` 纯通道认证（无建号副作用）→ 外部身份**不在 Platform 建号**——账户 100% 留在子应用本地，**单 uid 空间**。

### 模式 B：直接接入（AdminUI/UserH5/新应用——账号统一 Platform）

```
① 用户已登录 Platform（Bearer token1）
② 子应用前端 → POST {prefix}/trust/issue {app_id, redirect}（已认证）→ 验白名单 → 签 accesscode(payload:{mode:"direct", platform_uid}, expectedClaimant:app_id)
        → 302 重定向 redirect?code=xxx
③ 子应用后端 → POST {prefix}/identity/claim → 取 platform_uid → 本地业务 uid = platform_uid（不建 AuthAccount）→ 本地会话
```

## 六、安全边界

| 威胁 | 防护 | 承载 |
|------|------|------|
| accesscode 窃取/重放 | 120s TTL + 原子 CAS + SHA256 存储 | TrustCenter 既有 |
| 他应用冒领 | `expectedClaimant` 原子核销（claimant=app_id 不匹配 → `CLAIMANT_MISMATCH`） | TrustCenter 既有 |
| 开放重定向 | `redirect` ∈ SsoClient origin 白名单（Ordinal 精确）+ state 票据内 app_id 绑定 | `IsOriginAllowedAsync` + state 票据 |
| state 伪造/CSRF | Platform 签名 state 票据（HMAC，**Federation 密钥**）+ 回调验签 | 决策 4（Oracle 条件 3） |
| app_id 枚举 | claim 统一 401 `AUTHENTICATION_FAILED`；authorize/start 统一 400 通用错误 | 决策 5（Oracle 条件 4） |
| authorize/start 滥用/DoS | RateLimiting（IP 分区，429） | 决策 5（Oracle 条件 5） |
| claim 爆破 | credential 鉴权（FixedTimeEquals）+ 可选 RateLimiting | SsoClient 既有 + 装配层 |
| 明文落库 | payload AES-GCM 密文 | TrustCenter 既有 |
| 回调伪造（事件） | 平台库通道验签一票否决 | Federation 既有（event 端点不变） |
| 回调重放 | IdP code 单次 + accesscode 原子 CAS 双保险 | 平台协议 + TrustCenter |

**零新增安全基座**——全部复用三层扩展已验证机制。
