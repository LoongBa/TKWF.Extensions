# 对外路由命名空间——消费方适配通知（V0.7.0 破坏性路由变更）

> **发出方**: TKWF 扩展模块组｜**日期**: 2026-10-11｜**状态**: ✅ 已实施 + Oracle 复查 PASS（提交 `9deeabe`，tag Federation/v0.7.0 待推）
> **收件方**: 三方消费方——**XiaoShuTong / EduPlatform** + **DMP-Lite 三站（Platform/AdminUI/UserH5）** + 已对接平台 IdP 后台（微信/钉钉/企微/QQ/支付宝）
> **关联**: 开发方案 `docs/Federation/对外路由命名空间-开发方案.md` · ADR `docs/Federation/ADR/ADR-Federation-对外路由命名空间.md`

---

## ⚡ 一句话摘要

**Federation 对外端点路由改名：`/sso/*` → `/feberation/*`，平台集成面端点插入二级平台段 `{platformId}`。** 代码/契约/配置零破坏（`RoutePrefix` 可配可回退），**唯一适配动作 = 更新外部 URL 引用**（平台 IdP 后台回调/服务器配置 + 消费方 `JwksUri`）。

## 一、路由对照（唯一实质变更）

| 端点 | 变更前（0.6.0） | 变更后（0.7.0） |
|------|----------------|-----------------|
| 登录编排 | `POST /sso/login` / `/sso/login/{channelId}` | `POST /feberation/{platformId}/login` / `/login/{channelId}` |
| 事件推送 | `POST /sso/event/{channelId}` | `POST /feberation/{platformId}/event[/{channelId}]` |
| OAuth 回调 | `GET /sso/oauth/{channelId}/callback` | `GET /feberation/{platformId}/oauth[/{channelId}]/callback` |
| JWKS 分发 | `GET /sso/jwks` | `GET /feberation/jwks`（不变仅前缀） |
| 子应用委托 | `POST /sso/authorize/start`·`/trust/issue`·`/identity/claim` | `POST /feberation/authorize/start`·`/trust/issue`·`/identity/claim`（不变仅前缀） |

> `{platformId}` = 平台族（`wechat`/`qq`/`dingtalk`/`wecom`/`alipay`/`oidc`/`google`/`microsoft`——`ChannelConfig.PlatformType`，Ordinal 校验，错配统一 404）。
> 信任/委托面端点（jwks/authorize/start/trust/issue/identity/claim）**不挂平台段**——跨平台语义。

## 二、消费方适配动作（三处 URL，其余零改动）

| # | 位置 | 动作 |
|---|------|------|
| 1 | **平台 IdP 后台**（微信公众平台「服务器配置 URL」/ 钉钉/企微事件回调 / OAuth `redirect_uri`） | 完整 URL 重填：`.../sso/...` → `.../feberation/{platformId}/...`（逐通道） |
| 2 | **AuthCenter 资源服务器 `JwksUri`**（框架 `OAuthResourceServerWebExtension` 配置） | `.../sso/jwks` → `.../feberation/jwks` |
| 3 | **消费方代理/文档/客户端入参** | `/sso/...` → `/feberation/...`（含平台段） |

**可回退**：`TKWF:Federation:Web:RoutePrefix` 配回 `/sso` 即恢复旧前缀（但平台段仍存在——平台集成面端点必须带 `{platformId}`）。

## 三、行为变更（非 URL，注意）

1. **多通道 + 省略通道段 → 400 `CHANNEL_REQUIRED`**（B 守卫）：此前多通道省略 channelId 静默选默认通道（IsDefault→首项，非确定）；现多活跃通道下必须显式通道段。单通道部署不受影响（降级无歧义）。
2. **event 端点可用**（缺陷修复）：此前 `{prefix}/event/{channelId}` 的 channelType 推导缺陷致事件通道不可达；现按平台段推导 `{PlatformType}_event`——微信/钉钉/企微事件推送从不可用变为可用。
3. **错误码新增**：`CHANNEL_REQUIRED`（400）；`CHANNEL_DISABLED` 修正为 403（此前落入默认 400）。

## 四、适配工作量

**合计：3 处 URL 更新 + 若干后台配置重填——代码零改动、配置零新增。** 子应用委托 4 端点（authorize/start 等）0.6.0 刚发布无既有消费方，迁移成本最低。
