# 联邦互联平台网关立项依据（近中远）

> **用途**: 联邦互联（Federation）平台网关方向的**后续开发工作立项依据**——按**层级**（基座层/平台层/能力层）、**优先级**（P0/P1/P2）、**时间窗**（近/中/远）组织；每项给出立项内容、前置依赖、验收要点、价值与风险。作为后续迭代排期与立项的单一依据。
> **版本**: v0.1.0 ｜ **日期**: 2026-10-05 ｜ **状态**: ✅ 依据三份规划（均已 Oracle 评审——国内/国外 PASS WITH CONDITIONS、非认证 PASS，无 P0）编制
> **关联规划**: [国内平台总规划](./平台网关总体规划-开发方案.md) ｜ [国外平台总规划](./平台网关总体规划-国外平台-开发方案.md) ｜ [非认证能力平台调研](./非认证能力平台调研.md) ｜ ADR-AuthCenter-归层与命名（§五.8 协议面扩展余地）

## 一、立项分层框架

> 所有平台网关统一遵循：**平台网关 = 纯库**（无 Initializer 无 `[TKWFExtension]` 无持久化零 Store）、ISsoChannel 窄适配、凭证自持、信任根一票否决、不引 AspNetCore、库 → Federation 扩展单向依赖（设计原则 P1-P14 详见各规划）。

```
层级 L0（基座层）——跨平台共享基础设施，先行
├── L0.1 平台网关通用模板（WeChat 先例模板化 → 文档 + 脚手架）——已规划 §三
├── L0.2 通用 OIDC 通道基座 TKWF.Federation.Oidc（Discovery/JWKS/id_token 验签/配置驱动）——国外前置
└── L0.3 联盟锚点跨平台映射策略（P1-1 待设计项——实施前置）

层级 L1（平台层）——具体平台网关库（国内/国外），依赖 L0
├── 国内：QQ / 支付宝 / 钉钉 / 企业微信（第一批）→ B站 / 小红书（第二批）
└── 国外：Google / Microsoft / Apple（第一批）→ GitHub / LinkedIn（第二批）→ Slack / Facebook / Amazon（第三批）

层级 L2（能力层）——非认证能力面（消息/支付/电商核销/内容）——YAGNI 待业务驱动
└── 当前不立项（Oracle PASS 确认）；信任根机制与认证面同构可复用
```

## 三、依赖关系与排期建议

```
近期（P0）         中期（P1）              远期（P2，按需）
N1 通用模板 ──┐
N2 锚点策略 ──┤→ N3 QQ + N4 支付宝       L1 B站 / L2 小红书
              │                          L3 Apple / L4 GitHub / L5 LinkedIn / L6 第三批
              └→ M1 OIDC 基座 → M2 Google/Microsoft → M3 钉钉 / M4 企业微信
                                                     L7 非认证能力面（YAGNI 待业务驱动）
                                                     L8 Utility.OAuthClient（转达框架组）
```

**排期要点**：
1. **N1/N2 是全部 L1 平台的前置**——模板 + 锚点策略先行（无依赖，可立即启动）；
2. **国内第一批（N3/N4）与国外 OIDC 基座（M1）可并行**——国内走 WeChat 式模板（N1），国外走 OIDC 基座（M1），互不阻塞（协议阵营不同）；
3. **M3/M4（钉钉/企业微信）与 M2 并行**——国内 B 端（模板路线）与国外 OIDC（基座路线）独立演进；
4. **每平台独立包独立版本**（MinVerTagPrefix `Federation.{平台}/v`）——互不影响，可并行开发；
5. **远期平台（L1-L6）按场景价值驱动启动**——模板/基座就绪后，每平台 = 复制 + 协议差异实现，成本显著下降；
6. **L7 非认证面不主动立项**（YAGNI，Oracle PASS 确认）——真实业务需求触发时按 AGENTS"独立需求独立立项"模式启动；
7. **L8 引擎归属主框架**——本仓库不实施，转达框架组（OIDC 上下行共享协议资产的最终载体）。
