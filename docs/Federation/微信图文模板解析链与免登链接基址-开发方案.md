## 一、本版目标

- **核心交付**：微信图文回复链路**最小配置冒烟**——新消费方装配后**零 seed、零管理端、零业务派生类**即可验证「收消息 → 图文回复（含 ticket 链接）→ 点击落地 → 解票」闭环。同时在设计上理顺两条链：
  1. **模板归属 4 级解析链**（`WechatTemplateEventReplyHandler.OnDefaultAsync`）：per-channel（配置：静态投影 / DB 动态权威层）→ 全局默认 → 内置测试卡片（开发期开关）→ 纯文本模式；原"模板缺失 → null"语义（Oracle P0-2）被扩展为"①②③全空才 null"。
  2. **免登链接基址三级链**（`LoginEntryService.BuildTicketUrlAsync`）：`ChannelBaseUrls[channelId]` → `TestTicketEndpointBaseUrl` → 请求 Host 推导（`requestBaseUrl`）——**`TestTicketEndpointBaseUrl` 不再是必配**（本站点落地零配置直觉；微信图文 link 必须是完整 URL → 实际链路恒有第③级）。
- **完成定义（DoD）**：
  - 模板解析链 4 级 + 基址三级链 + per-channel 静态模板三项改动全部落地（38037ab）；
  - Federation.Abstractions v0.4.0 / Federation v0.13.0 / Federation.WeChat v0.8.0 三个包编译 0 错误（全 slnx）；
  - 测试全绿：Federation 122、Federation.WeChat 123（+4：全局默认兜底 / 内置开启 / 内置关闭 fail-safe / BaseUrl 透传）、WeChatOperations 143；
  - 内置测试卡片**生产 fail-safe**：`EnableBuiltInTestTemplate` 默认 false，联调配置仅放 `appsettings.Development.json`，未显式开启绝不发"链路测试"卡片给真实用户。

**Oracle 评审 2026-10-26 共识**：
- 「模板归属」在"per-channel 配置 / 全局默认 / 内置兜底"之间分级——配置归配置（Options 静态 + DB 动态），数据归数据（业务派生类），内置卡片仅作为**开发期冒烟设施**且必须显式开关；
- 「基址解析」复用既有 `TestTicketEndpointBaseUrl` 单一事实源，不新增重复配置项；请求 Host 推导为第三级、只作兜底，"反代/多域名显式配置覆盖"；
- 失败语义：模板配置损坏 → 回退下级不拦截（延续 P0-2）；基址全空 → 相对路径兜底而非 fail-closed null（本站点同源场景可落地）。

### 核心流程

**模板解析链（4 级）——`WechatTemplateEventReplyHandler.OnDefaultAsync`**

```
OnDefaultAsync(ctx)
  ├─ ① Channel.Extra["news_reply"]        ← per-channel：静态投影 WeChatChannelConfig.NewsReplyTemplate
  │     （WeChatChannelSource.GetChannels() → Extra） / DB 动态权威层 SsoChannelRegistry.ExtraJsonEncrypted
  │     缺失 / JSON 损坏(JsonException) → null（Oracle P0-2：不拦截业务 handler，不回退内置）
  ├─ ② Options.DefaultNewsReplyTemplate    ← 全局默认（TKWF:Federation:WeChat:EventReply:DefaultNewsReplyTemplate，
  │     NewsReplyTemplateV2 snake_case：enabled/articles/title/description/link/pic_url/ttl_seconds）
  ├─ ③ EnableBuiltInTestTemplate == true ? BuiltInTestTemplate : null
  │     ← 内置"链路测试"卡片（标题"链路测试"/link 含 {ticket}/pic_url 空=图片不存在；开发期零 seed 冒烟）
  └─ ④ null → 纯文本模式（图文不回复，WeChatOperations 落 Options.DefaultReplyText）

  模板为 null 或 Enabled != true → 返回 null（不回复不拦截）
  → RequireUidForTicket == true 且 ctx.UId 空 → null（登录卡只发已绑定用户）
  → ResolveTicketAsync(ctx, ct, template.TtlSeconds)   ← 签免登票据（基址三级链，见下）
  → BuildArticles(template, ctx, ticketUrl)             ← articles 数组优先（Take(8)）/ 单图文兼容回退
  → WechatReplyPayload(News: articles)
```

**免登链接基址三级链——`LoginEntryService.BuildTicketUrlAsync`（含透传链）**

```
                              结构                          透传链（TextTicketEndpoint 免配）
基址 = ① FederationLoginEntryOptions.ChannelBaseUrls[channelId]（按 ChannelId 覆盖）
       ② FederationEventReplyOptions.TestTicketEndpointBaseUrl（单一事实源）
       ③ requestBaseUrl（装配层请求 Host 推导）
    三级均空 → CombineUrl 相对路径兜底 /{RoutePrefix}/{TicketPath}?ticket=（不再 fail-closed null）

  请求 → FederationWebExtension.HandleEvent：parameters["base_url"] = "{Scheme}://{Host}"（服务端可信填充）
       → WeChatEventChannel：Attributes["wechat.base_url"] = Parameters["base_url"]
       → WechatEventContext.BaseUrl（record 新字段，Parse 读 base_url / FromChannelEvent 映射 wechat.base_url）
       → Handler.ResolveTicketAsync(ctx) 透传 → 第③级基址

  效果：TestTicketEndpointBaseUrl 不再是必配——本站点落地零配置直觉；
       微信图文 link 必须是完整 URL → 实际链路恒有第③级。
  仍 fail-closed：Enabled=false → null；IssueAsync 抛异常 → null（不阻断回复）。
```

### 主框架引用

- 本仓库 2026-09-16 **双模式 DLL 定案**（`Directory.Build.props`）：`UseLocalFw=true`（本地联调默认）→ 集中 DLL 引用 `$(_LocalFwRefsDir)`（`TKWFDeployPath\build\refs`）零跨仓库源码耦合；`UseLocalFw=false`（CI/发布）→ `PackageReference`。
- `TKWFSourceRoot` 定义于仓库根 `Directory.Build.props`（指向同级 `_TKWF\`，对齐 DMP-Lite 跨仓库引用模式）——本迭代涉及项目为纯 DLL 模式。
- `TKWF.Federation.WeChat.csproj`：`ProjectReference` 引 `Federation.Abstractions`（ISsoChannel 契约来源，单向依赖无循环）+ `TKWF.Domain` 条件引用（双模式）+ `TKWF.CodeGeneration.Abstractions`（`DiContractIgnore` 所在）。
- ⚠️ 不引 AspNetCore（Oracle 评审点 5）：库纯逻辑 + HttpClient；入站端点归 Federation 扩展/消费方装配层。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 内置测试卡片生产泄漏（`EnableBuiltInTestTemplate` 误配 true → 真实用户收到"链路测试"卡片） | 生产事故/体验事故 | 默认 false fail-safe；联调配置仅随 `appsettings.Development.json` 提交（生产 appsettings.json 不配）；Options XML 注释 + 使用指南双重红线声明 |
| 基址语义变化（原三级均空 fail-closed null → 相对路径兜底） | 内部/同源调用可落地，跨域场景相对链接不可用 | 微信图文 link 恒有第③级（完整 URL）——最重场景天然规避；相对兜底仅覆盖站内直调；接口注释声明"反代/多域名显式配置覆盖" |
| 配置错误（`DefaultNewsReplyTemplate` JSON 损坏 / `enabled=false`） | 该级模板失效、回复落空 | 损坏 → null 回退下级（延续 Oracle P0-2 不拦截）；全空 → ④ 纯文本模式（WeChatOperations 落 `DefaultReplyText`），不抛、不重复回复 |
| 旧语义兼容（既有消费方依赖"模板缺失 → 不回复"） | 加入全局默认/内置配置后行为变化 | ②③未配置时仍 ④ null（等价旧语义）；解析链逐级回退仅在显式配置时生效，文档化说明 |
