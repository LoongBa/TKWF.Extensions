# 联邦互联扩展-使用指南

> **扩展**: `TKWF.Ext.Federation`（**联邦互联**——认证中心对外身份接口/外交部）｜**版本**: V0.2.0｜**框架**: .NET 10
> **定位**: 认证体系四层归层模型（ADR-AuthCenter-归层与命名）中的**对外身份接口层**——消费方应用不再各自对接微信/QQ/Google/Apple/微软等 IdP，而是统一对接联邦互联层，获取**跨应用统一登录态**（Federated SSO）。中文名「**联邦互联**」定案 2026-10-05——落脚点"互联"宽于"认证"（Federation 层职责含应用注册/信任建立/身份映射/令牌协议/多 IdP 连接，非仅认证流程），与"认证中心"（AuthCenter）对仗——内部中心 + 外部互联。
> **关联文档**: 技术规范见 `_Framework/Federation/README.md`；归层 ADR `docs/AuthCenter/ADR/ADR-AuthCenter-归层与命名.md`；平台网关库指南 `docs/Federation.WeChat/微信公众平台连接器-使用指南.md`；认证中心（Authentication）指南 `docs/Authentication/认证中心-使用指南.md`

## 一、这是什么

`TKWF.Ext.Federation` 解决"**一个认证中心、多个应用、统一登录态**"的问题——消费方应用对认证渠道（微信/QQ/Google/Apple/微软）零感知，统一消费 token2（ES256 自包含 JWT + JWKS 公钥离线验签）。

| 你要解决的 | 用联邦互联 |
|-----------|-----------|
| 多应用统一登录态（H5 免登） | 授权码 accesscode（120s 原子 CAS + SHA256 存储 + PKCE 可选）→ token2 |
| 应用端离线验证登录态 | token2 验签（ES256 + JWKS 公钥，aud 须 == 自身 app_id） |
| 应用注册与信任管理 | `ISsoClientService`（origin 白名单防开放重定向 + scope + client credential AES-GCM + per-channel HMAC） |
| server-to-server 用户信息 | `ISsoProfileService`（scope 强制 + 审计，永不返回 openid/channel_id/phone） |
| 接入外部 IdP（微信/QQ/Google…） | `ISsoChannel` 窄适配 + 平台网关库（`TKWF.Federation.{平台}`） |

**不包含**：认证内核（账号/短信/微信 Provider/token1 签发 → `TKWF.Ext.Authentication`，组合式消费）；具体平台适配（→ `TKWF.Federation.{平台}` 库，如 `TKWF.Federation.WeChat`）；`/sso/*` 端点映射（装配层职责——Federation 提供 Service 层）；我方多实例互通（默认不做，iss 域隔离）。

### 组合矩阵（按需装配）

| 消费方装配 | 获得能力 | 适用 |
|-----------|---------|------|
| 只引 `TKWF.Ext.Authentication` | 内部认证（单应用登录 + 短信/微信 Provider） | 单应用、最小化 |
| Authentication + Federation | **认证中心实例**（内部认证 + 多应用联邦互联 SSO） | 多应用统一登录态（乐学/乐教、DMP 多商户） |
| Federation + 平台网关库 | 纯外部联邦登录（BYO IdP——V5 国外客户主力形态，经 `Authentication.Abstractions` 引契约零全量传递） | 对外开放、自有 IdP |
| Authentication + Federation + 平台网关库 | 完整认证中心实例（内部认证 + 对外联邦 + 平台接入） | 认证中心完整形态 |

> **"不是所有 AuthCenter 都需要 Federation"**（用户裁定）：单应用认证中心只装 Authentication；需要对外统一身份接口时才加装 Federation——分开合理。

### 不适用边界

- **档案面（UserCenter 已退役 2026-10-08）**：档案查询经 AuthCenter `IAuthAccountQueryService.GetProfileByUIdAsync`（`UserProfile` 1:1 表）或业务扩展 VEntity——档案面与联邦互联解耦，不属本扩展。
- **密钥体系隔离**：Authentication RS256（内部令牌）与 Federation ES256（token2）**独立密钥域**——密钥管理抽象（E4，框架 `DevKeyCache<TKey>` 泛型缓存 + `ISymmetricKeyProvider` keyed 注册）下 AuthCenter/Federation 各自独立实例，密钥域仍隔离。
- **通用支付网关**（纯转发型）：`TKWF.Federation.{平台}` 的网关是"平台身份适配（双向）"；若出现纯转发型网关另行评估 `TKWF.Gateways`。

## 二、快速开始（3 步）

### 第 1 步：引用 + 白名单启用

> 📌 公共接线机制（发现≠启用 / 三钩子 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——公共内容不在此重复。

```xml
<!-- 消费方 .csproj（组合式：认证中心实例 = Authentication + Federation） -->
<ProjectReference Include="..\..\_Framework\Federation\TKWF.Ext.Federation.csproj" />
<ProjectReference Include="..\..\_Framework\Authentication\TKWF.Ext.Authentication.csproj" />
<!-- 纯外部联邦场景（BYO IdP）可只引 Federation + Authentication.Abstractions 契约包 -->
```

```csharp
using TKWF.Ext.Federation;

[TKWFEnabledExtension(typeof(FederationExtensionInitializer<>))]
[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]   // 组合式：认证中心实例
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

### 第 2 步：配置 `TKWF:Federation`

```jsonc
{
  "TKWF": {
    "Federation": {
      "Issuer": "https://api.example.com",          // 必填（生产 fail-fast）——token2 iss（SSO 实例标识）
      "SigningKeyPath": "C:\\keys\\sso-ec-private.pem", // EC P-256 私钥 PKCS#8（生产 fail-fast）
      "CurrentKid": "sso-key-1",                     // 当前签发密钥 kid（SigningKeys 中匹配）
      "SigningKeys": [{ "Kid": "sso-key-1", "PrivateKeyPath": "C:\\keys\\sso-ec-private.pem" }],
      "Token2ExpirationSeconds": 300,                // token2 有效期（秒，默认 300）
      "ClockSkewSeconds": 30,                        // 验签 leeway（秒，默认 30）
      "AccessCodeExpirationSeconds": 120,            // accesscode TTL（秒，默认 120）
      "SecretEncryptionKeyPath": "C:\\keys\\sso-aes.key",  // client credential/HMAC AES-GCM（前 32 字节，生产必填）
      "IsProduction": true                           // true = fail-fast 门（缺密钥拒绝启动）
    }
  }
}
```

**生成 EC 私钥 PEM**（生产，PKCS#8）：
```bash
openssl ecparam -name prime256v1 -genkey -noout -out sso-ec-private.pem   # PKCS#8 EC 私钥
openssl ec -in sso-ec-private.pem -pubout -out sso-ec-public.pem
```

> ⚠️ **生产 fail-fast**：`IsProduction=true` 时缺 `Issuer` / `SigningKeyPath` / `SecretEncryptionKeyPath` → 启动拒绝（`InitializeAsync` 预检经系统作用域 `Use<IToken2Service>()` 触发密钥懒加载）。密钥文件 chmod 600、不进代码库。
> 开发模式（`IsProduction=false`）缺密钥自动生成临时 EC 密钥 + Warning（`DevKeyCache<Token2Service.EcKeySet>` 进程内缓存——框架 Utility.Caching，重启即变，仅限开发联调；V0.1.1 修复跨实例不一致缺陷，V0.2.0 起收编框架 `DevKeyCache`）。

### 第 3 步：接入平台网关库（可选——需要对外接 IdP 时）

```csharp
// Program.cs（Web 装配层）——装配 TKWF.Federation.WeChat 平台网关库
//    库侧 AddWeChatFederationChannels() 内部 TryAddEnumerableConstructible<ISsoChannel, X>（ADR92 集合版守卫工厂）
builder.Services.AddWeChatFederationChannels();
//    通道配置经 TKWF:Federation:WeChat 配置节绑定（SG1 [Options] 自动），或编程覆盖：
builder.Services.Configure<WeChatOptions>(o => { /* 按 AppId 选区 Channels */ });
```

- **依赖方向**：`TKWF.Federation.{平台}` 库 → `TKWF.Ext.Federation` 扩展 → `Authentication.Abstractions` + 主框架（Oracle P1-1，**单向无循环**）。
- **未装配库 = 空集合**：Federation 初始器零 `ISsoChannel` 元素注册——未引用任何平台网关库时 `IEnumerable<ISsoChannel>` 帧内解析为空数组，"未注册通道自然跳过"。
- **注册责任归属**：库无 Initializer（纯库判据）——由库侧 `AddWeChatFederationChannels()` 扩展方法注册（`Microsoft.Extensions.DependencyInjection` 命名空间）；Federation 扩展不强制引库保持核心轻量。

> 详细平台网关接入（微信 OAuth/事件推送双通道）见 [`docs/Federation.WeChat/微信公众平台连接器-使用指南.md`](../Federation.WeChat/微信公众平台连接器-使用指南.md)。

### 第 3.5 步：多通道联邦（可选——每商户一个公众号/多渠道并存，v0.3.0）

> **多通道联邦（Multi-Channel Federation，副名联邦多租户）**：单实例联邦互联持有多个 IdP 通道实例（每商户/每应用一个 `ChannelId`）。通道实例 = 凭证 + openid 映射（`UX_PlatformAccountMap_Channel`）+ accesscode（`ChannelId` 列）的隔离单元。**身份层多租户**，管理门户不在扩展模块范围。设计详见 [`多通道联邦-开发方案.md`](./多通道联邦-开发方案.md)。

```csharp
// Program.cs——装配多平台库（每库可配 N 个通道，Channels 列表）
builder.Services.AddWeChatFederationChannels();   // 通道配置经 TKWF:Federation:WeChat 节（Channels[] 每项一个公众号）
builder.Services.AddQqFederationChannels();        // 或其它平台库，各行其是

// 多通道配置示例（appsettings.json——每商户一个公众号 = Channels 两条记录）
{
  "TKWF": {
    "Federation": {
      "WeChat": {
        "Channels": [
          { "ChannelId": "merchant-a", "AppId": "wx_a", "AppSecret": "...", "Token": "t_a", "EncodingAESKey": "k_a" },
          { "ChannelId": "merchant-b", "AppId": "wx_b", "AppSecret": "...", "Token": "t_b", "EncodingAESKey": "k_b" }
        ]
      }
    }
  }
}
```

- **选区门面**：`IChannelRegistry`（`GetAsync(channelId)`/`GetDefaultAsync()`——组合语义：**DB 命中优先 → 静态回退**，Phase 2 已注入 Db；Phase 1 仅静态）+ `ISsoChannelFactory`（按 channelId 构造通道实例）+ `ISsoLogin`（编排登录）。全部经 `User.Use<T>()` 帧内解析。
- **路由定形（方案 §3.5）**：`/sso/oauth/callback` → 默认通道（无前缀降级，单实例存量零破坏）；`/sso/oauth/{channelId}/callback` → 指定通道（内部键精确选区）；`/sso/oauth/{channelAlias}/callback` → 指定通道（对外别名，§3.5c——装配层经 registry 解析为内部键）；`/sso/event/{channelId}/callback` → Event 入站回调。**authorize 构造 + state 校验仍归装配层**（通道不感知 state）。
- **错误码**：`CHANNEL_NOT_FOUND`（404，channelId 不存在）/ `CHANNEL_DISABLED`（403，IsEnabled=false）/ `CHANNEL_REGISTRY_UNAVAILABLE`（503，registry 故障）/ 平台码（400，缺 code 等）——均 `FailReason` 机器可读 + 装配层 HTTP 映射。
- **代理示例（装配层端点）**：
  ```csharp
  // 路由 /sso/oauth/{channelId}/callback → code
  var result = await user.Use<ISsoLogin>().LoginAsync(channelId, TheSsoChannelAuthContext(code));
  // 无前缀 /sso/oauth/callback → 默认通道降级
  var result2 = await user.Use<ISsoLogin>().LoginDefaultAsync(TheSsoChannelAuthContext(code));
  // 按 result.Success / result.ExternalUserId / result.FailReason 处理；失败映射错误码
  ```
- **凭证模型**：公共列（ChannelId/PlatformType/AppId/AppSecret）+ `Extra` 扩展字典（平台特有 Token/EncodingAESKey/CorpId/EnableUnionId 等）——支付宝等未来平台零 DDL 接入。平台凭证仍归各平台库自持（Oracle P2-4）。
- **协调注意**：A 平台库的通道按 `IChannelSource` 注入静态 registry（`Add{平台}FederationChannels()` 内自动注册）；Federation 主包门面（`IChannelRegistry`/`ISsoChannelFactory`/`ISsoLogin`）由 `FederationExtensionInitializer` 注册（消费方白名单启用后自动接线）。

### 第 3.5b 步：DB 动态权威（可选——生产动态接入通道，v0.3.x Phase 2）

> **DB 动态权威（Phase 2，方案 §3.3）**：通道配置的**生产权威层**——静态 Options（各平台库 `Channels`）为种子/回退，DB registry（`SsoChannelRegistryEntity`）为动态权威。**组合语义单点**：`IChannelRegistry`（Composite）DB 命中优先 → 静态回退（Oracle M3——跨实现解耦归组合单点，Phase 1 仅静态、Phase 2 注入 Db 零返工）。适用于**多商户动态开通**（每商户一个 `ChannelId`，运营侧写入 DB 即生效，免重启免改配置）。

```csharp
// 消费方（装配层/运营侧）——经 SsoChannelRegistryService 门面写入 DB（管理端点不建，服务层方法保留）
await user.Use<ISsoChannelRegistryService>().RegisterAsync(new ChannelConfig
{
    ChannelId = "merchant-c",                    // 选区键（精确匹配，一字不差）
    PlatformType = "wechat",                     // 平台族（与平台库 IChannelSource.PlatformType 一致）
    AppId = "wx_c",
    AppSecret = "secret",                        // 公共列（DB 层全程密文——AppSecretEncrypted AES-GCM 落库）
    Extra = new Dictionary<string, string?>      // 平台特有扩展（Token/EncodingAESKey/CorpId/EnableUnionId...）
    {
        ["Token"] = "t_c",
        ["EncodingAESKey"] = "k_c",
    },
    IsEnabled = true,
}, CancellationToken.None);

// 更新（重写 IsEnabled/凭证）/ 注销（删除行）
await user.Use<ISsoChannelRegistryService>().UpdateAsync("merchant-c", cfg => cfg.IsEnabled = false, CancellationToken.None);
await user.Use<ISsoChannelRegistryService>().UnregisterAsync("merchant-c", CancellationToken.None);

// 读侧零改动——Composite 自动 DB 优先：注册过的 channelId 从 DB 取（密文解密映射），未注册回退静态 Options
var cfg = await user.Use<IChannelRegistry>().GetAsync("merchant-c", CancellationToken.None);
```

- **实体**：`SsoChannelRegistryEntity`（`TKWF_SsoChannelRegistry` 表）——`ChannelId` 唯一 UX 索引 + 公共列（ChannelId/PlatformType/AppId）+ **`AppSecretEncrypted`(512)/`ExtraJsonEncrypted`(4000) AES-GCM 密文列**（Oracle M6 容量定案——RSA-2048 PEM + OIDC TokenIssuers 组合容量核验；明文不落库）+ IsDefault/IsEnabled + CreateTime/UpdateTime。
- **加解密**：服务层经 keyed `ISymmetricKeyProvider`（`SymmetricKeyProviderKeys.Federation`——`FederationOptions.SecretEncryptionKeyPath` 密钥，对齐 `SsoClientService` 模式）；`DbChannelRegistry` 读行解密映射 `ChannelConfig`（空串/解密失败降级 null/空字典——对齐 UserCenter 降级矩阵）。
- **组合降级**：DB 不可用（未建表/未注册 DAC/密钥缺失）→ Composite catch 回退静态（零破坏——平台库测试宿主零 Db 形态）；`CHANNEL_REGISTRY_UNAVAILABLE`（503）标识 registry 故障。
- **种子语义**：静态→DB 迁移 = 经 `RegisterAsync` 逐通道写入（服务层加密）；生产动态接入 = 运营侧/消费方自建管理面调用本门面（管理端点不在本扩展模块——管理门户裁定不在范围）。
- **冲突语义**：`RegisterAsync` 对已存在 ChannelId 抛 `DomainException(Conflict)`（fail-closed——防误覆盖；变更走 UpdateAsync）。

### 第 3.5c 步：ChannelAlias 对外别名（可选——内部键保护 + 直观名，方案 §3.7）

> **双键选区（2026-10-08 用户裁定）**：通道有**两个对外可用的键**——内部 `ChannelId`（持久化选区键，静态配置/DB 行/accesscode/映射列全部不变）+ 对外 `ChannelAlias`（直观名/URL 段，可选）。**默认（不配 alias）= 只用 ChannelId，存量零迁移**；配了 alias 后外部 URL/客户端入参可用别名，内部机制仍走 ChannelId。

```jsonc
// 配置示例（静态 Options——平台库 ChannelConfig 增 Alias 字段，可选）
{
  "TKWF": { "Federation": { "WeChat": { "Channels": [
    { "ChannelId": "channel-1001", "Alias": "merchant-a", "AppId": "wx_a", ... },   // 对外叫 merchant-a，内部键 channel-1001
    { "ChannelId": "channel-1002", "Alias": "edu-course", "AppId": "wx_b", ... }
  ] } } }
}
// DB 动态权威同理——SsoChannelRegistryEntity 增 ChannelAlias 列（非唯一索引，注册门面写入）
```

- **解析**：registry 统一入口 `GetByAliasOrIdAsync(key)`——先 alias 精确匹配 → 再 ChannelId 匹配 → 未中 `CHANNEL_NOT_FOUND`；装配层路由段（`/sso/oauth/{key}/callback`）经此解析后归一内部键，通道/accesscode/映射**一律 ChannelId**。
- **微信平台侧配置**：公众号后台「网页授权域名」= 域名级共享（多公众号可同域名）；「服务器配置 URL」= **每公众号独立完整 URL**（含各自 alias/channelId 段）——域名共享、路径区分。
- **安全**：alias 非敏感（凭证在服务端）；alias 保护内部键（不暴露持久化编号）；同 alias 二次注册 fail-closed（冲突语义对齐 ChannelId）。
- **✅ 已实施（v0.3.x Phase 3，6c5355e）**：`ChannelConfig.Alias`（string? 可空，缺省 null = 用 ChannelId 对外——存量零迁移）+ `IChannelRegistry.GetByAliasOrIdAsync` 三实现（Static/Db/Composite——DB 优先 → 静态回退）+ `SsoChannelRegistryEntity.ChannelAlias` 列（非唯一，兼容 alias=ChannelId 同名）+ `SsoChannelRegistryService` 注册/更新支持 Alias（同 alias 冲突 fail-closed，Update 含清空语义）+ 8 平台库 `Options.Channels[].Alias` 可选字段（ChannelSource 投影）——持久化全经自动生成 DataService。

### 第 3.5d 步：客户端 SDK 拉起微信（边界说明——非增强选配，方案 §3.8 讨论记录）

> **边界（2026-10-08 讨论记录）**：客户端 SDK 拉起微信（PC/iOS/Android/鸿蒙）——**SDK 集成层不经过联邦互联**（appid + 回调 scheme 等参数**保存在客户端**，微信 SDK 标准集成）；**身份换取必须经服务端**：客户端拿 code → 上抛服务端 → `ISsoLogin.LoginAsync(channelId/alias, context(code))` 换取 user_id/签发 token2——**现状门面已满足，无需额外参数/新增端口**（凭证在服务端，客户端永不自持密钥）。

```
客户端 SDK（SendAuth/ap.getAuthCode）→ 客户端拿 code（SDK 回调，纯客户端协议）
  → 上抛消费方服务端换取端点（自建 minimal API，薄包装 ISsoLogin）
  → 换取 user_id → 签发 token2 → 返回客户端
```

- **客户端 SDK 参数（appid/scheme/universal link）**：存客户端（微信 SDK 要求）——联邦互联不介入 SDK 集成。
- **授权发起（authorize URL 构造）+ state 校验**：归装配层/客户端（现状一致，通道不感知 state）。
- **仅当未来需"换取前验证额外身份参数"（如设备指纹）时**：再评估装配层 `POST /sso/oauth/exchange` 端点约定（届时归装配层 minimal API，Federation 不引 AspNetCore）——**当前不裁定不实现**。

## 三、核心能力

> 所有 Federation 门面接口均 `: IDomainService`——消费方经 `DomainUser.Use<T>()` 域通道帧内解析（`AddConstructibleService` 守卫工厂）。**禁止 `[FromServices]` 预绑定门面接口**（帧外抛守卫）。

### 1. 应用注册与信任管理（`ISsoClientService`）

```csharp
public class ClientAdminService(DomainUser<MyUserInfo> user)
{
    // 注册应用（生成 app_id + client secret + HMAC secret——均 AES-GCM 落库）
    public async Task RegisterAppAsync(IReadOnlyList<string> origins, IReadOnlyList<string> scopes)
    {
        var info = await user.Use<ISsoClientService>().RegisterAsync(origins, scopes);
        // info.AppId / info.OriginWhitelist / info.Scopes / info.IsEnabled
    }

    // 校验重定向 origin（防开放重定向——target_app_id → 注册精确 origin，Ordinal 匹配）
    public async Task<bool> CheckOriginAsync(string appId, string origin)
        => await user.Use<ISsoClientService>().IsOriginAllowedAsync(appId, origin);

    // 校验客户端凭据（server-to-server profile API 鉴权——AES-GCM 解密 + FixedTimeEquals 防时序攻击）
    public async Task<bool> CheckCredentialAsync(string appId, string secret)
        => await user.Use<ISsoClientService>().ValidateClientCredentialAsync(appId, secret);
}
```

- **`SsoClientEntity`**：app_id（唯一）+ origin 白名单 JSON（scheme+host 精确集合）+ scope JSON + `ClientSecretEncrypted`/`HmacSecretEncrypted`（AES-GCM 密文）+ IsEnabled。
- **防开放重定向**：**不接受自由 `redirect_uri` 参数**——`target_app_id → 注册精确 origin` 白名单（`IsOriginAllowedAsync`，Ordinal 精确匹配）。
- **per-channel HMAC**：`/sso/issue` 验签密钥来源（Oracle P1-4——不复用 `PlatformCredentialEntity`）；`GetHmacSecretAsync` 返回明文（AES-GCM 解密于 DataService 边界）。

### 2. 授权码 accesscode（`ISsoAccessCodeService`——通道 B 票据）

| 字段 | 规格 |
|---|---|
| 生成 | CSPRNG 32 字节 `base64url` |
| TTL | 120 秒（`FederationOptions.AccessCodeExpirationSeconds`） |
| 单次 | **原子 CAS**（`EntityUpdateWhereAsync(Id && used=false, set used=true)`——ADR89 引擎级条件 UPDATE），重放即拒 + Warning |
| 存储 | 只存 `SHA256(code)` 索引，不存原文（防库泄露后 code 盗用） |
| PKCE | 可选（签发时存 code_verifier SHA256 hash；消费必传比对，恒定时间——defense in depth，非强制） |
| 关联字段 | `channel_id, uid, target_app_id, scope, exp, used, ip, code_verifier_hash` |

```csharp
// 签发（channel 后端 → /sso/issue 内部调）
var issue = await user.Use<ISsoAccessCodeService>().IssueAsync(new SsoAccessCodeIssueRequest(
    ChannelId: "wx-mp-001", UId: "u_100", TargetAppId: "app-1", Scope: "profile:basic",
    OpenId: "mp_openid", /* 审计——不出 token2/URL */
    CodeVerifier: codeVerifier /* 可选 PKCE */));
// issue.Code / issue.ExpiresIn（120）

// 消费（用户点击图文链接 → /sso/auth）
var consume = await user.Use<ISsoAccessCodeService>().ConsumeAsync(code, codeVerifier);
// consume.UId / consume.TargetAppId / consume.Scope → 签 token2
```

**错误码**：`ACCESS_CODE_NOT_FOUND` / `TICKET_EXPIRED` / `TICKET_CONSUMED`（重放）/ `TICKET_STATE_MISMATCH`（PKCE）。

> **与既有 `IOAuthTicketService` 边界**（并列不迁移）：既有 = 单应用票据（login/bind + PKCE + TTL 5min，服务认证中心内部"票据换令牌"）；Federation accesscode = 联邦授权码（channel_id + target_app_id + scope，服务跨应用联邦流）——语义不同，各自独立（ADR-SSO 3.3 并存路径）。

### 3. token2 令牌（`IToken2Service`——ES256，独立密钥域）

```json
{ "alg": "ES256", "kid": "sso-key-2026-10", "typ": "JWT",
  "iss": "https://api.example.com", "sub": "<uid>", "aud": "<target_app_id>",
  "iat": 1722240000, "exp": 1722240300, "jti": "<32B base64url>", "scope": "profile:basic" }
```

- **明确不放**：openid / phone / channel_id（隐私最小化 + 解耦应用与渠道）。
- **签名**：手写 ES256（BCL `ECDsa`，曲线强制 P-256）；验签加固——alg 强制 / `FixedTimeEquals` / kid 白名单 / iss 校验 / exp·iat leeway（默认 30s）/ Base64Url 边界。
- **独立密钥域**：与 Authentication RS256 完全独立（算法/iss/消费方不同，不复用既有 `TokenService`）；kid 轮换（`SigningKeys` 遍历验证，旧密钥可验到过期）。
- **JWKS**：`GetJwksJson()` 序列化（RFC 7517：kid + x/y 坐标）；`/.well-known/jwks.json` 端点装配层映射。
- **吊销**：短 TTL 为主（默认 300s）；用户封禁/解绑 → jti 吊销列表（profile API 在线校验），app session 周期性 re-check。

```csharp
// 签发（accesscode 消费成功后）
var issued = await user.Use<IToken2Service>().IssueToken2Async(new Token2IssueRequest(
    UId: "u_100", TargetAppId: "app-1", Scope: "profile:basic"));
// issued.Token（ES256 JWT）/ issued.ExpiresIn（300）

// 验签（应用端离线验证：ES256 + JWKS 公钥；aud 须 == 自身 app_id）
Token2ValidationResult result = await user.Use<IToken2Service>().ValidateToken2Async(token2);
// result.UId / result.TargetAppId / result.Jti / result.ExpiresAtUtc / result.Claims

// JWKS 分发（公开端点 /.well-known/jwks.json）
string jwks = user.Use<IToken2Service>().GetJwksJson();
```

### 4. profile API（`ISsoProfileService`——server-to-server）

```csharp
// profile 拉取（Bearer app client credential + X-App-Id；scope 强制 + 审计）
SsoProfileDto? profile = await user.Use<ISsoProfileService>().GetProfileAsync(
    appId: "app-1", uid: "u_100",
    scopes: ["profile:basic"], ipAddress: remoteIp);
// profile.UId / profile.Nickname / profile.AvatarUrl / profile.AuthLevel
// 未授权 scope / 账号不存在 → null
```

- **scope 强制**：只返回 scope 允许字段（`profile:basic` → nickname/avatar 子集）；**永不返回 openid/channel_id/phone**。
- **审计**：ILogger 结构化日志（app_id/uid/scopes/ip/ts）；`SsoProfileAuditEntity` 归后续迭代（复用 SecurityLog 或自建表另议）。
- **数据源**：经 Abstractions 契约 `ISsoAccountQueryService` 读 `SsoAccountDto`（敏感字段不出契约包，Oracle P1-2）；独立于用户中心聚合层（已退役）。

### 5. channel 契约（`ISsoChannel`——IdP 适配器）

`ISsoChannel` 定义在 Federation 扩展（Oracle P1-1），供 `TKWF.Federation.{平台}` 平台网关库实现：

```csharp
// 平台网关库侧实现（如 TKWF.Federation.WeChat.WeChatOauthChannel）
public sealed class WeChatOauthChannel : ISsoChannel
{
    public string ChannelType => "wechat_oauth";   // channel 类型（决定 /sso/login 路由）
    public string ChannelId => "wx-mp-001";        // channel 实例 id（微信 = 公众号 id）

    public async Task<SsoChannelAuthResult> AuthenticateAsync(SsoChannelAuthContext context, CancellationToken ct = default)
    {
        // context.Parameters["code"] → code→openid（WeChatApiClient.GetOpenIdAsync）
        // → (channel_id, openid) → uid（经 Abstractions ISsoChannelMapService.LinkAsync）
        return new SsoChannelAuthResult(Success: true, ExternalUserId: openid, FailReason: null, AuthLevel: 2);
    }
}
```

- **可扩展键值上下文**：`SsoChannelAuthContext(IReadOnlyDictionary<string,string?> Parameters)`——私有 OAuth（微信/QQ）与标准 OIDC（Google/Apple/微软）均经 channel 形态承载（**协议差异收敛于 channel 实现**）。
- **与既有 `IAuthenticationProvider` 边界**（Oracle P2-3）：Provider = 认证中心内部认证方式（服务 token1 签发）；Channel = 联邦 IdP 适配（外部身份源，服务 token2 联邦流）——两套并存，两会话永不交叉。
- **注册**：`TryAddEnumerableConstructible<ISsoChannel, X>`（集合版守卫工厂，对齐 ADR92）；平台网关库 Initializer 追加实现，未注册通道自然跳过。channel 的 IdP 凭证（如微信 AppId/AppSecret）归平台网关库自持（Oracle P2-4）。

| 接口 | 方法 | 说明 |
|------|------|------|
| `IToken2Service` | `IssueToken2Async`/`ValidateToken2Async`/`GetJwksJson` | token2 签发/验签/JWKS |
| `ISsoAccessCodeService` | `IssueAsync`/`ConsumeAsync` | 授权码签发（通道 B）/消费 |

| `ISsoChannel` | `ChannelType`/`ChannelId`/`AuthenticateAsync` | IdP 适配器契约（平台网关库实现） |

## 四、协议面扩展余地（预留方向，不实现）

> **裁定 2026-10-05（用户）**：协议面扩展的**目的不是现在实现，而是流出可扩展的余地**——后续按需实现而不必修改既有设计。详见 ADR-AuthCenter-归层与命名 §五.8。

认证体系协议面按**两正交维度**分层，各层**预留扩展点**：

```
认证体系协议面（两正交维度）：
├─ 身份源适配（上游消费）：ISsoChannel + 平台网关库（TKWF.Federation.{平台}）——✅ 已落地
│    ├─ 私有 OAuth：微信/QQ（channel 键值上下文承载协议差异）
│    └─ 标准 OIDC：Google/Apple/微软（未来 channel——channel 形态不变，仅实现协议差异）
├─ 对外协议面（下游提供）：Federation 端点薄层——v0.2.0 收敛方向
│    ├─ 自研 token2（V0.1.0 已落地，私有扩展面）
│    └─ 标准 OAuth 2.0/OIDC 收敛（v0.2.0：/authorize /token /userinfo /.well-known/openid-configuration）
├─ 特殊协议（按需立项，不预留接口）：SAML 2.0——YAGNI，需要时独立库（TKWF.Federation.Saml）
└─ 引擎：TKWF.Utility.OAuthClient（BCL 协议引擎，OAuth/OIDC 通用）——归属转达框架组
```

| 协议 | 判断 | 依据 |
|------|------|------|
| **OIDC** | **v0.2.0 收敛为默认标准面**（"收敛"非"新增"） | token2 已是 OIDC 的 **80% 形态**（ES256 JWT + JWKS + accesscode PKCE 授权码 + profile API），缺的仅是标准 claims（`nonce`/`auth_time`/`at_hash` 等）+ discovery 文档 + userinfo 对齐——收敛成本低、收益高（异构客户端 `oidc-client-ts`/`openid-client` 直接对接）；自研 token2 **保留为私有扩展面**，OIDC **平行提供**（不废弃 token2——既有消费方零迁移） |
| **SAML 2.0** | **不内置，按需立项**（YAGNI） | XML 断言 + XMLDSig + 多种 binding，技术栈与 JWT 完全不同；现代 IdP（Google/M365）均支持 OIDC，SAML 仅"对接老牌企业 ADFS"场景——有需求时独立立项，**不预留接口**（避免为未定需求设计） |
| **OAuth 2.1** | 已在轨道上 | accesscode 已实现 PKCE（OAuth 2.1 强制项）+ 精确 origin 白名单，天然对齐 |

**预留原则**：协议差异**收敛于端点薄层（对外）/ channel 实现（上游）**——核心 Federation 逻辑（accesscode/token2/应用注册）**不感知协议类型**；新增协议 = 新增薄层/channel，**零核心改动**。此原则保证"后续按需实现而不必修改既有设计"。

## 五、安全边界

- **数据访问红线合规**：全部实体 SG1 + `*EntityDataService` 委托（零 IFreeSql / 零 IEntityDAC 直注入）；Federation 经 Abstractions 契约消费认证内核（`ISsoAccountQueryService`/`ISsoChannelMapService` 返回不可变 DTO，敏感字段不出契约包）。
- **密钥安全**：EC 私钥 PEM（PKCS#8，chmod 600）/ AES-GCM 密钥文件（前 32 字节）不进代码库；生产缺密钥 fail-fast；kid 轮换支持紧急换钥。
- **防开放重定向**：`target_app_id → 注册精确 origin（scheme+host）` 白名单（`IsOriginAllowedAsync`，Ordinal 精确匹配）；不接受自由 `redirect_uri` 参数。
- **client credential 校验**：AES-GCM 解密 + `CryptographicOperations.FixedTimeEquals`（防时序攻击）。
- **accesscode 只增语义**：`SsoAccessCode` 无 Update/Delete 公开业务方法（对齐 SecurityLog 先例）。
- **profile 审计**：ILogger 结构化日志（app_id/uid/scopes/ip/ts）——`SsoProfileAuditEntry`；`SsoProfileAuditEntity` 归后续迭代（复用 SecurityLog 或自建表另议）。

| 扩展 | 划界 |

## 七、故障排查

| 症状 | 原因 | 处置 |
|------|------|------|
| 启动拒绝（生产 fail-fast） | 缺 `Issuer` / `SigningKeyPath` / `SecretEncryptionKeyPath` | 补全 `TKWF:Federation` 配置；密钥文件 chmod 600 不进代码库 |
| Development 模式启动崩溃（V0.1.1 已修复） | V0.1.0 `InitializeAsync` 传 root SP 不建子 scope，`ValidateScopes=true` 下 Scoped 守卫工厂从根解析必崩 | 升级至 V0.1.1+（`BeginSystemScopeAsync()` 不传参，框架内部建子 scope） |
| token2 验签 `INVALID_SIGNATURE` | 应用端未用 JWKS 公钥 / aud 不匹配自身 app_id / 密钥轮换后旧钥未验到过期 | 核对 `/.well-known/jwks.json` 拉取公钥；aud 须 == 应用注册 app_id；kid 轮换期新旧密钥并存 |
| token2 `KID_UNKNOWN` | 验签密钥 kid 不在 SigningKeys | 检查 kid 配置（多实例密钥同步） |
| `ALG_NOT_ALLOWED` | header alg 非 ES256（防 alg=none/HS256 伪造） | 拒绝为预期行为——token2 强制 ES256 |
| accesscode 消费 `TICKET_CONSUMED` | 重复消费（重放） | accesscode 单次有效（原子 CAS）——重放即拒为预期行为；确认应用端幂等处理 |
| `ACCESS_CODE_NOT_FOUND` | code 过期（120s）/ 伪造 | 授权码 TTL 内使用；code 由 `/sso/login` 正规流程签发 |
| `TICKET_STATE_MISMATCH` | PKCE verifier 不匹配 | 核对 code_verifier（签发时存的 hash 比对） |
| `IEnumerable<ISsoChannel>` 为空 | 未装配任何平台网关库 | 属预期（未注册通道自然跳过）——需接 IdP 时装配 `TKWF.Federation.{平台}` 并调库侧注册方法 |
| 回调返回 `CHANNEL_NOT_FOUND`（404） | channelId/channelAlias 不存在——`/sso/oauth/{key}/callback` 段的键未在任一平台库 `Channels`/DB registry 注册 | 核对 `TKWF:Federation:{平台}` 节 Channels 的 ChannelId/Alias（多通道精确选区必须与配置一字不差）；alias 未配置时外部须用 ChannelId（缺省 = ChannelId，无 alias 可解析）；未装配对应平台库 / 配置段渠道 |
| 回调返回 `CHANNEL_DISABLED`（403） | channel 存在但 `IsEnabled=false` | 如非有意停用（维护/条件启用），置 `IsEnabled=true`；多通道下按需启用单渠道 |
| 回调返回 `CHANNEL_REGISTRY_UNAVAILABLE`（503） | registry 故障（DB 层未就绪 / 初始化异常） | 检查 Federation 门面注册（v0.3.0：`IChannelRegistry`/`ISsoChannelFactory`/`ISsoLogin` 由 `FederationExtensionInitializer` 注册——白名单须声明）；Phase 2 含 DB 层——未建表（`TKWF_SsoChannelRegistry` 需 SyncStructure）/ 未注册 `SsoChannelRegistryEntity` DAC 时 Composite 自动回退静态（503 仅在 registry 整体不可用时） |
| DB registry 写入抛 `DomainException(Conflict)` | `RegisterAsync` 的 ChannelId 已存在（fail-closed 防误覆盖） | 核对 ChannelId 是否已注册（重复开通）——变更走 `UpdateAsync` 重写，勿重复 Register |
| DB 通道读回凭证为空/null | `AppSecretEncrypted`/`ExtraJsonEncrypted` 解密失败（密钥轮换后旧密文） | 检查 `SecretEncryptionKeyPath` 密钥一致性（密文用旧密钥加密则解密失败——降级 null/空字典，Warning 日志定位）；`IsDefault`/`IsEnabled` 未置时默认语义 |
| 多通道选区错配（登录进错商户） | 装配层路由未按「无前缀=默认 / 带前缀=精确」约定；或默认通道非预期商户 | 单实例场景用 `/sso/oauth/callback`（降级 Channels 首项）；多实例必须带 channelId 段——默认通道语义仅为向后兼容，**不承诺多公众号下业务合理默认**（显式决策 channelId） |
| 帧外解析门面抛守卫 | 控制器 `[FromServices]` 预绑定 / 无 AOP 帧调用 | 改经 `user.Use<门面>()` 帧内解析（`AddConstructibleService` 守卫工厂）——禁止预绑定 |

## 八、归层命名说明（SSO → Federation → 联邦互联）

认证体系四层归层模型（ADR-AuthCenter-归层与命名，Oracle PASS WITH CONDITIONS + skill 复核）：

| 层 | 包 | 中文名 | 形态 | 职责 |
|----|----|--------|------|------|
| 联盟核心/认证中心 | `TKWF.Ext.AuthCenter`（规划名，现 Authentication） | 认证中心 | 扩展（对内，持久化+装配） | 账号/令牌/登录保护/票据 |
| 外交部/对外身份接口 | `TKWF.Ext.Federation` | **联邦互联** | 扩展（配置装配、自含实体） | token2/accesscode/JWKS + `ISsoChannel` 窄适配 |
| 大使馆/平台网关库 | `TKWF.Federation.{平台}` | 平台网关库 | 纯库（无 Initializer 无持久化） | 微信/QQ/Google 双向网关 |
| 引擎/协议 | `TKWF.Utility.OAuthClient` | 引擎 | 库（BCL，归主框架） | authorize 构造/code 交换/令牌解析 |

**演变路径**：`TKWF.Ext.SSO`（联邦层独立模块，ADR-SSO 选项 A）→ `TKWF.Ext.Federation`（SSO 命名废弃——SSO 是体验词、Federation 是结构词；2026-10-05 归层代码零移动）→ 中文名「**联邦互联**」定案（2026-10-05——"联邦认证"偏窄，落脚点"互联"宽于认证：含应用注册/信任建立/身份映射/多 IdP 连接）。

**`无 Ext` = 纯库判据**（AGENTS §8）：`TKWF.Ext.*` = 扩展（有装配/持久化）；`TKWF.*`（无 Ext）= 库（纯逻辑/无状态）。Federation 自含实体（`SsoClientEntity`/`SsoAccessCodeEntity`——协议编排核心状态）+ 有装配（Initializer）→ 扩展形态；`TKWF.Federation.WeChat` 等无持久化纯协议 → 库形态。
