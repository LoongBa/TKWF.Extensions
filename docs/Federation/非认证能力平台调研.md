# 联邦互联非认证能力平台调研（消息 / 支付 / 电商核销 / 内容面）

> **定位**: 联邦互联 = **平台能力联邦**（用户洞察 2026-10-05）——不仅是身份认证（认证面/`ISsoChannel`，国内/国外总规划已覆盖），还有**消息收发、支付、电商/核销、内容搜索等能力面**。本文档调研非认证面的平台能力，为后续契约定型/立项提供事实基础。
> **状态**: 📋 调研（非开发方案）——各能力面**无代码基础**，契约形态待定型（评审后定）；认证面总规划见 [《平台网关总体规划（国内）》](./平台网关总体规划-开发方案.md) + [《（国外）》](./平台网关总体规划-国外平台-开发方案.md)
> **版本**: v0.1.0 ｜ **日期**: 2026-10-05

## 一、能力面框架（联邦互联全景）

> **核心洞察（用户 2026-10-05）**：联邦互联不是单一的"身份认证"模块——而是连接各平台**多类能力**的联邦层。认证（登录）只是能力面之一；生活服务/电商平台（美团/知乎/小红书等）的侧重点可能是**营销、电商、核销、内容**，未必是身份认证。

```
联邦互联能力面（5 维度）：
├─ 认证面（Auth）       —— 用户身份联合登录 → token2           ✅ ISsoChannel 已落地（微信）＋ 总规划（国内/国外）
├─ 消息面（Messaging）  —— B2C 主动触达：机器人/模板消息/通知     ⬜ 调研（无代码）
├─ 支付面（Payment）    —— 交易收款/退款/对账                    ⬜ 调研（无代码）
├─ 电商/核销面（Commerce）—— 订单/团购核销/优惠券/门店            ⬜ 调研（无代码）
└─ 内容面（Content）    —— 内容搜索/聚合/发布（知乎类）           ⬜ 调研（无代码）
```

**关键判据**（区分"认证"与"业务能力"）：平台是否提供**面向第三方网站的"用账号登录"网页 OAuth**（→ 认证面）；还是仅提供**业务数据 API/场景绑定授权**（营销/订单/核销/内容）——后者是业务能力面，与"身份联合登录"目标不同，即使存在 OAuth 形态端点也**不归认证面**（美团实证）。

## 二、各能力面平台调研

### 2.1 消息面（Messaging）——B2C 主动触达

| 平台 | 能力形态 | 说明 | 认证面交集 |
|------|---------|------|-----------|
| **企业微信**（WeCom） | 应用消息（成员触达）、群机器人 | 企业内员工触达；OAuth 已认证（第一批） | ✅ 同一平台双面 |
| **钉钉** | 工作通知、群机器人、Stream Mode | 企业内员工触达；OAuth 已认证（第一批） | ✅ 同一平台双面 |
| **微信公众号** | 模板消息（订阅通知）、客服消息 | C 端触达；OAuth 已落地（wechat_oauth/wechat_event） | ✅ 同一平台双面 |
| **飞书** | 机器人、消息卡片 | B 端（第二批） | 🟡 |
| **企业微信/钉钉 回调事件** | 消息接收（入站） | 事件推送验签（msg_signature + AES）——**信任根机制与认证面共享** | ✅ |

**关键事实**：消息面与认证面**共享同一平台接入 + 同一入站事件验签信任根**（企业微信/钉钉的 AES+sha1 回调机制 = 认证面 wechat_event 同型）——消息面可复用认证面已建的"事件接收 + 验签"基础设施，**增量成本低**。

### 2.2 支付面（Payment）——交易收款/退款/对账

| 平台 | 能力形态 | 说明 |
|------|---------|------|
| **支付宝** | 交易 API（当面付/APP/手机网站/WAP）+ 异步通知验签 | 电商/交易；OAuth 认证已入第一批；**支付通知 RSA2 验签 = 信任根** |
| **微信支付** | 交易 API + 回调通知（APIv3 证书体系） | 与微信认证面同平台；支付回调验签（平台证书）+ 敏感信息加密 |
| **银联云闪付** | 支付 API | 可选（视业务） |

**关键事实**：支付面是**独立能力域**（与身份认证完全不同的 API 面）——但**信任根模式同构**（回调验签 = 认证面事件验签同型）；值得注意：支付回调验签是**交易正确性**的信任根，比认证面的身份信任根更敏感（金额/订单伪造 = 资金损失）。

### 2.3 电商/核销面（Commerce）——订单/核销/门店

| 平台 | 能力形态 | 说明 |
|------|---------|------|
| **美团** | 团购自助核销、外卖订单、门店授权（ISV/OAuth 业务授权模型） | **用户洞察实证**：美团 OAuth = **业务数据授权**（商家/门店/核销），非"美团账号登录你的网站"——子域名按业务划分（waimai/到店/团购），businessId 15~91 各业务独立授权；C 端核销走微信小程序中转 |
| **小红书** | 千帆商家平台（`open.xiaohongshu.com`，商家/店铺 API） | 与账号登录平台（`openaccount.xiaohongshu.com`）**不同平台**——千帆 = 商家经营（订单/商品/营销） |
| **抖音** | 电商开放平台（抖店/POI 核销） | 短视频电商核销场景（第二批待定） |

**关键事实**：电商/核销面**几乎必然依赖微信小程序/支付宝小程序生态**（美团核销 = 微信小程序跳转）——**不是标准 Web OAuth 能力**；其契约形态（若有）与身份联合登录完全不同（业务授权 + 场景绑定）。

### 2.4 内容面（Content）——内容搜索/聚合/发布

| 平台 | 能力形态 | 说明 |
|------|---------|------|
| **知乎** | 内容/圈子 API（`developer.zhihu.com` 直答/搜索 API——HMAC/静态密钥鉴权；`openapi.zhihu.com` 内容运营 API） | **用户洞察实证**：知乎开放能力 = **内容 API**（创作者工具/内容聚合），**非账号登录**——无面向第三方网站的账号 OAuth，未公开申请渠道 |
| **B站** | 内容 API（视频/UP 主） | B站 OAuth 认证已入第二批；内容 API 另议 |
| **小红书** | 笔记/内容 API（营销场景） | 内容 + 营销（种草） |
| **微博** | 内容/广场 API | 社交内容衰退，价值低 |

**关键事实**：内容面鉴权形态 = **API Key/HMAC 静态密钥**（非用户 OAuth）——完全不同的鉴权模型：认证面是"用户身份换取 token2"，内容面是"应用凭证换取内容数据"；且内容 API 鉴权一般无用户维度（B 端应用级）。

## 三、与认证面的关系（架构含义）

| 维度 | 认证面（ISsoChannel 已落地） | 非认证面（消息/支付/电商/内容） |
|------|---------------------------|-------------------------------|
| **语义** | 身份换取（external_uid → uid → token2） | 凭证换取业务能力（订单/核销/消息/内容） |
| **契约形态** | `ISsoChannel`（窄适配，身份获取） | **待定型**——非"身份获取"语义，若塞入 ISsoChannel 破坏契约纯度 |
| **入站** | 事件推送验签（wechat_event/dingtalk/work_wechat） | 支付回调验签 / 消息接收——**信任根同构可复用** |
| **凭证** | AppSecret/私钥（OAuth） | 服务商授权 token / API Key / 商户证书 |
| **用户维度** | 有（用户身份） | 消息面有（触达对象）、支付/电商/内容面多数为应用级（B 端） |
| **代码现状** | ✅ 微信双通道已落地 | ⬜ 无代码 |

**架构建议（待评审）**：
1. **认证面保持 `ISsoChannel` 纯度**——非认证面**不塞入 ISsoChannel**（语义不符 + 破坏 IDomainService 契约）；
2. **非认证面独立立项时**：消息面可复用认证面"事件接收 + 验签"基础设施（信任根同构）；支付面/电商面/内容面按"平台服务商 API"形态独立评估（可能归 `TKWF.Utility.*` 引擎 + 扩展门面，非 ISsoChannel）；
3. **本调研不立项**——各面无代码基础，待真实业务需求驱动（YAGNI + 独立需求独立立项，AGENTS 模式）。

## 四、调研结论速查

| 平台 | 认证面（可接入） | 非认证能力面 | 关键性质 |
|------|:---:|-------------|---------|
| 微信 | ✅（已落地） | 公众号模板消息 / 微信支付 | 多面型（认证+消息+支付） |
| 企业微信 | ✅（第一批） | 应用消息/通讯录/回调事件 | 多面型 |
| 钉钉 | ✅（第一批） | 工作通知/机器人/Stream | 多面型 |
| 支付宝 | ✅（第一批） | 支付 API/异步通知 | 多面型（认证+支付） |
| QQ | ✅（第一批） | 无显著业务能力 | 认证型 |
| B站 | ✅（第二批） | 内容 API | 认证+内容 |
| 小红书 | ✅（第二批，设备授权） | 千帆商家/笔记内容 | 认证+内容+电商 |
| **美团** | ⛔（**无账号登录**） | **团购核销/外卖订单/门店授权** | **纯业务能力型**（用户洞察实证） |
| **知乎** | ⛔（**无账号登录**） | **内容搜索/聚合 API** | **纯业务能力型**（用户洞察实证） |
| 微博 | ⚪ 不建议 | 内容 API | 内容型（衰退） |
| Google/Microsoft/Apple | ✅（国外第一批） | 极少业务能力 | 认证型 |
| GitHub | ✅（国外第二批） | 代码/仓库 API | 认证+内容型（开发者） |
