# v0.3.0 — FileManagement 用户级配额 开发方案

> **扩展**: `TKWF.Ext.FileManagement` | **版本**: v0.3.0 | **依赖**: 主框架 v4.10.26+（ADR78 签名）+ 既有 v0.2.0 版本化/配额
> **日期**: 2026-09-16 | **状态**: 📋 提议（待 Oracle 评审）
> **关联**: 跟踪 §五 #5（ADR 明示"留后续"，现仅目录/全局配额）；README v0.3.0+ 候选（`OwnerId` 列 + `IDomainUser` 注入）；Settings/FeatureManagement `IDomainUser` 注入先例

---

## 一、目的与目标

为 FileManagement 增加**用户级配额**——每用户文件数/容量独立限制，超越现有目录级（`MaxFilesPerFolder`/`MaxFolderSizeBytes`）与全局级（`MaxTotalSizeBytes`）配额。上传时经 `IDomainUser` 解析当前用户，按 `OwnerId` 维度检查用户配额，超限拒绝。

目标状态（3 句内）：①`ManagedFileEntity` 增加 `OwnerId` 列（可空——兼容 v0.2.0 存量数据，匿名/无用户上下文场景为空）；②新增 `MaxUserFilesCount`/`MaxUserSizeBytes` 配置键，`FileManager.EnforceQuotaAsync` 增加用户维度检查（经 `IDomainUser` 解析 owner）；③`OwnerId` 写入上传链（`UploadFileAsync`），存量文件不回填（`OwnerId` null = 未归属，不计入用户配额）。

---

## 二、问题

### 问题现象

1. **多用户场景配额缺失**：现配额只有目录维度（`MaxFilesPerFolder`/`MaxFolderSizeBytes`）和全局维度（`MaxTotalSizeBytes`）——同一用户可无限制上传至全局上限（如 10GB），SaaS/多租户场景无法按用户限流（"每人 1GB"）。
2. **无归属维度**：`ManagedFileEntity` 无 `OwnerId` 列——文件无法归属到上传用户，用户维度统计/配额无从谈起。
3. **README 明示缺口**：v0.3.0+ 候选明确列出"用户级配额（`OwnerId` 列 + `IDomainUser` 注入）"——跟踪 §五 #5 记录"ADR 明示留后续，现仅目录/全局配额"。

### 触发场景

- 消费方多用户文件管理（如网盘/文档中心）——每位用户独立容量上限。
- 目录级配额不适用时（用户文件散落多目录，需跨目录按用户汇总）。
- 匿名上传（无用户上下文）——`OwnerId` null，用户配额不生效（保持全局配额兜底）。

### 现有方案不足

- 目录配额（`MaxFolderSizeBytes`）按 `FolderId` 聚合——用户可创建多目录分散文件绕过。
- 全局配额（`MaxTotalSizeBytes`）无用户维度——无法区分"谁占用了容量"。
- 两者均不回答"某用户已用多少、还剩多少"——用户级配额是**归属维度**的新增，非现有键的扩展。

---

## 三、使用场景

1. **多用户网盘**（常态）：消费方启用 `[TKWFEnabledExtension(FileManagement)]`，配置 `MaxUserSizeBytes: 1073741824`（每人 1GB）——用户 A 上传至 1GB 后超限拒绝，用户 B 独立计算不受影响。
2. **匿名/系统场景**：`IDomainUser` 未认证（`IsAuthenticated=false`）或上传不在域作用域 → `OwnerId` 写 null → 用户配额跳过，全局配额兜底（与现状一致）。
3. **不适用**：单用户应用（无用户配额需求，保持目录/全局配额即可，配置缺省行为不变）；`OwnerId` 不回填存量数据（历史文件不计入用户配额——设计决策，见【后果】）。

## 四、决策

### 核心机制（对齐 Settings/FeatureManagement `IDomainUser` 注入先例）

```
上传链（UploadFileAsync）
  ├─ IDomainUser 解析 owner（构造注入 + Initializer 工厂）
  │    ├─ IsAuthenticated + UserId 非空 → OwnerId = UserId（long?）
  │    └─ 否则 → null（匿名，跳过用户配额）
  ├─ EnforceQuotaAsync 增加用户维度检查（MaxUserFilesCount / MaxUserSizeBytes）
  │    └─ CountByOwnerAsync / SumSizeByOwnerAsync（DataService 聚合，对齐 SumSizeByFolderIdAsync 先例）
  └─ 元数据落库 → ManagedFileEntity.OwnerId
```

### 1. 实体：`ManagedFileEntity` 增加 `OwnerId` 列

- **列定义**（`ManagedFileEntity.g.cs` 重新生成，实体声明在 `.biz.cs` partial 属性）：
  ```csharp
  /// <summary>归属用户 ID（V0.3.0 用户级配额；null = 匿名/未归属，不计入用户配额）。</summary>
  [Column(Name = "owner_id", Position = 5, CanUpdate = true)]
  public long? OwnerId { get; set; }
  ```
- **索引**：新增 `IX_ManagedFile_Owner`（`OwnerId`）——用户配额聚合查询（`WHERE owner_id = @id`）走索引；对齐 `IX_ManagedFile_Sha256` 先例。
- **兼容**：`OwnerId` 可空 → 建表迁移对存量表自动加列（FreeSql SyncTables 增量）；存量行 null（不回填，见【后果】）。
- **⚠️ 生成物纪律**：实体变更后重跑 `pwsh .xCodeGen/run-xcodegen.ps1 -Ext FileManagement` 更新 `.g.cs`（AGENTS §8 重生成纪律）——`OwnerId` 属性将进入 DTO/DataService 映射。

### 2. Options：新增用户配额键

`FileManagementOptions` 增加（对齐 V0.2.0 三键可空语义）：

```csharp
/// <summary>用户文件数上限（null = 不限制；OwnerId 归属文件计数；超限上传 → InvalidOperationException）。</summary>
public int? MaxUserFilesCount { get; set; }

/// <summary>用户容量上限（字节；null = 不限制；OwnerId 归属文件大小求和；超限上传 → InvalidOperationException）。</summary>
public long? MaxUserSizeBytes { get; set; }
```

### 3. Store/DataService：用户维度聚合

- `ManagedFileEntityDataService` 增加 2 个聚合方法（对齐 `CountByFolderIdAsync`/`SumSizeByFolderIdAsync` 先例——SQL 下推）：
  ```csharp
  public Task<long> CountByOwnerAsync(long ownerId, CancellationToken ct)      // COUNT WHERE owner_id = @id
  public Task<long> SumSizeByOwnerAsync(long ownerId, CancellationToken ct)    // SUM(size) WHERE owner_id = @id
  ```
- `IManagedFileStore` 增加对应委托方法（internal Store → DataService 转发）。

### 4. FileManager：IDomainUser 注入 + 用户配额检查

- **构造注入** `IDomainUser`（对齐 FeatureManagement FeatureManager 先例——`private readonly IDomainUser _domainUser`）。
- **Initializer 工厂**改为传入 `sp.GetRequiredService<IDomainUser>()`（对齐 FeatureManagementExtensionInitializer L81 先例）。
- `UploadFileAsync` 内 `EnforceQuotaAsync` 增加用户维度：
  ```csharp
  // 用户配额（OwnerId 归属维度；未认证/无用户 → 跳过，全局兜底）
  long? ownerId = _domainUser.IsAuthenticated
      ? long.TryParse(_domainUser.UserId, out var uid) ? uid : null
      : null;
  if (ownerId.HasValue)
  {
      if (_options.MaxUserFilesCount.HasValue)
      {
          long count = await _fileStore.CountByOwnerAsync(ownerId.Value, ct);
          if (count >= _options.MaxUserFilesCount.Value)
              throw new InvalidOperationException($"用户文件数配额超限：当前 {count} / 上限 {_options.MaxUserFilesCount.Value}");
      }
      if (_options.MaxUserSizeBytes.HasValue)
      {
          long current = await _fileStore.SumSizeByOwnerAsync(ownerId.Value, ct);
          if (current + contentLength > _options.MaxUserSizeBytes.Value)
              throw new InvalidOperationException($"用户容量配额超限：当前 {current} 字节 + 本次 {contentLength} 字节 > 上限 {_options.MaxUserSizeBytes.Value} 字节");
      }
  }
  ```
- **元数据写入**：上传创建/版本化 Upsert 时 `OwnerId = ownerId`（与 `UploaderName` 并列为归属字段——`UploaderName` 现为 null，v0.3.0 可一并填写用户显示名？——**不**：保持最小变更，仅 `OwnerId`，`UploaderName` 留待后续）。

### 5. 破坏性声明

- **实体加列**：`ManagedFileEntity` 增 `OwnerId`（可空）→ 建表增量迁移（FreeSql SyncTables）；存量行 null。
- **DTO 变化**：`ManagedFileEntityDto` 增 `OwnerId`（SG1 重新生成）——消费方读侧零破坏（加性）；写侧 DTO 增字段不影响既有调用。
- **构造注入变化**：`FileManager` 构造函数增 `IDomainUser` 参数——**internal 构造**（仅 Initializer 工厂调用），消费方自定义 `IFileManager` 不受影响；`FileManagementExtensionInitializer` 工厂内部改动。
- **行为变化**：匿名上传（无用户上下文）→ `OwnerId` null → 用户配额不生效（全局兜底）——与现状一致，零破坏。

## 五、测试计划

| 层 | 测试 | 断言 |
|----|------|------|
| DataService | `CountByOwnerAsync`/`SumSizeByOwnerAsync` SQL 聚合（SQLite 内存） | 按 OwnerId 过滤正确；无归属（null）不计入 |
| FileManager | 用户文件数配额（`MaxUserFilesCount`） | 达上限后上传 → `InvalidOperationException`（含配额信息） |
| FileManager | 用户容量配额（`MaxUserSizeBytes`） | 当前用量 + 本次 > 上限 → 拒绝；等值边界（= 允许） |
| FileManager | 匿名上传（`IDomainUser` 未认证） | `OwnerId` null → 用户配额跳过，全局配额仍生效 |
| FileManager | 多用户隔离 | 用户 A 达配额不影响用户 B 上传 |
| 实体 | `OwnerId` 列持久化 | 上传后 `OwnerId` 正确落库；存量数据 null 兼容 |
| 回归 | 既有 v0.2.0 配额（目录/全局） | 用户级新键缺省（null）时行为不变 |

## 六、风险与缓解

| 风险 | 缓解 |
|------|------|
| `IDomainUser.UserId` 解析（string → long）失败 | `long.TryParse` 失败 → null → 跳过用户配额（全局兜底）；文档化 |
| 并发"先到先得"（读-比-写非原子） | 对齐 v0.2.0 配额语义（显式声明，超限最终一致可接受） |
| 存量文件不计入用户配额 | 设计决策（不回填）——文档化：启用用户配额前已有文件不占额度，新上传开始计入 |
| 实体加列生成物陈旧 | 重跑 `run-xcodegen.ps1 -Ext FileManagement` 提交 `.g.cs`（AGENTS §8 纪律） |
| `IDomainUser` 注入破坏测试 Host | 测试 Host 补注册 `IDomainUser` 桩（对齐 Settings/FeatureManagement 测试先例） |
