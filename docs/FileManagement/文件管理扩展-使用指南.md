# 文件管理扩展使用指南

> `TKWF.Ext.FileManagement`——目录树 + 文件元数据（SHA256/去重）+ **文件版本化 + 配额（V0.2.0）** + 上传/下载/删除/重命名/移动门面。
> 版本 v0.2.0｜设计依据 [ADR-FileManagement-范围划界与文件管理设计](../../../_TKWF/docs/03_扩展模块/FileManagement/ADR/ADR-FileManagement-范围划界与文件管理设计.md) + [ADR-FileManagement-v0.2.0-版本化与配额](../../../_TKWF/docs/03_扩展模块/FileManagement/ADR/ADR-FileManagement-v0.2.0-版本化与配额.md)

## 1. 快速开始

### 1.1 引用

```xml
<!-- 消费方 .csproj：FileManagement + BlobStoring（物理存储提供方） -->
<ProjectReference Include="..\..\_Framework\FileManagement\TKWF.Ext.FileManagement.csproj" />
<ProjectReference Include="..\..\_Framework\BlobStoring\TKWF.Ext.BlobStoring.csproj" />
```

> FileManagement 只引用 `BlobStoring.Abstractions` 契约（ADR50 L2 门控）——`IBlobStorageService` 由**消费方启用的 BlobStoring 扩展**（或自定义实现）提供。

### 1.2 启用（v4.9.85+ 白名单声明）

```csharp
using TKWF.Ext.FileManagement;
using TKWF.Ext.BlobStoring;

[TKWFEnabledExtension(typeof(FileManagementExtensionInitializer<>))]
[TKWFEnabledExtension(typeof(BlobStoringExtensionInitializer<>))]   // 提供 IBlobStorageService
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

### 1.3 注入使用

```csharp
public class UploadService(IFileManager fileManager)
{
    public async Task UploadAsync(long folderId, string fileName, Stream content)
        => await fileManager.UploadFileAsync(folderId, fileName, content);
}
```

## 2. 目录管理

```csharp
// 创建（Code 白名单 [A-Za-z0-9_.-] + 防穿越；Path 由 Code 构建：根=/code/，子=父Path+Code+/）
var root = await fileManager.CreateFolderAsync("CONTRACTS", "合同");
var q3 = await fileManager.CreateFolderAsync("Q3", "2026 Q3", parentId: root.Id);
// 更新（只改 Name/SortOrder——Code 不可改，Path 不重算，C3 裁定）
await fileManager.UpdateFolderAsync(q3.Id, name: "2026 Q3（改名）");
await fileManager.RenameFolderAsync(q3.Id, "2026 Q3 最终");
// 删除保护：有子目录或文件 → InvalidOperationException（请先清空）
await fileManager.DeleteFolderAsync(q3.Id);
// 查询
var tree = await fileManager.GetFolderTreeAsync();          // 全树（SortOrder 升序；孤儿节点抛异常）
var subs = await fileManager.GetSubFoldersAsync(root.Id);   // 直接子目录（null = 根）
```

## 3. 文件上传 / 下载 / 管理

### 3.1 上传（10 步安全校验链）

```csharp
await fileManager.UploadFileAsync(folderId, "report.pdf", stream);
await fileManager.UploadFileAsync(null, "root.txt", stream);        // folderId=null → 根级文件
```

上传自动执行的安全校验链：

| # | 校验 | 失败行为 |
|---|------|---------|
| 1 | 文件名空/空白 | `ArgumentException` |
| 2 | 防穿越（`. / ..` 段 / 分隔符 `/ \` / 盘符 `:`） | `ArgumentException` |
| 3 | 扩展名白名单（小写归一，`.JPG` == `.jpg`） | `ArgumentException` |
| 4 | 大小限制（seekable 先 Length；非 seekable 边复制边计数） | `ArgumentException`（含实际/限制值） |
| 5 | SHA256 去重（同内容同目录同名 → 幂等返回既有） | 返回既有文件 |
| 6 | ContentType **服务端推导**（扩展名 → MIME 映射，不信任客户端） | 未知 → `application/octet-stream` |
| 7 | 目录存在守卫 + 根级同名预检 | `InvalidOperationException` |
| 8 | Blob 落盘 → 元数据落库（事务 + 唯一约束转业务异常） | 失败 → 补偿清理 Blob + 异常传播 |

### 3.2 下载

```csharp
var (stream, file) = (await fileManager.DownloadFileAsync(fileId))!.Value;
// 不存在 → InvalidOperationException；Blob 缺失 → FileNotFoundException
```

### 3.3 删除 / 重命名 / 移动

```csharp
await fileManager.DeleteFileAsync(fileId);          // 元数据 + Blob 同删（Blob 删失败 → 日志警告，孤儿容忍）
await fileManager.RenameFileAsync(fileId, "new.pdf"); // 跨扩展名重命名 → Extension/ContentType 自动重算 + 白名单校验
await fileManager.MoveFileAsync(fileId, newFolderId);  // 目标目录守卫 + 重名检查（null = 移到根级）
```

### 3.4 查询

```csharp
var file = await fileManager.GetFileAsync(fileId);                 // 不存在返回 null
var files = await fileManager.GetFilesAsync(folderId, skip: 0);    // 按目录分页（null = 根级文件）
var hits = await fileManager.SearchFilesAsync("报告", skip: 0);    // 文件名关键字模糊
```

## 4. 配置（`TKWF:FileManagement`）

```jsonc
{
  "TKWF": {
    "FileManagement": {
      "MaxFileSizeBytes": 52428800,          // 默认 10MB
      "AllowedExtensions": [".pdf", ".png", ".jpg", ".jpeg", ".docx", ".xlsx"],
      "AllowAnyExtension": false,            // true = 跳过白名单（不推荐）
      "Deduplicate": true,                   // SHA256 去重（仅关预查优化——目录内同名唯一约束始终生效）
      "DefaultPageSize": 50,
      "MaxFilesPerFolder": 100,              // V0.2.0 目录文件数上限（null = 不限制）
      "MaxFolderSizeBytes": 1073741824,      // V0.2.0 目录容量上限（null = 不限制）
      "MaxTotalSizeBytes": 10737418240       // V0.2.0 全局总容量上限（null = 不限制）
    },
    "BlobStoring": {                         // 物理存储（BlobStoring 扩展，v0.1.1 修复 Options 绑定后生效）
      "RootPath": "./blobs",
      "IsEnabled": true
    }
  }
}
```

| 配额键（V0.2.0） | 默认 | 行为 |
|------|------|------|
| `MaxFilesPerFolder` | `null` | 目录文件数超限上传 → `InvalidOperationException`（含配额信息） |
| `MaxFolderSizeBytes` | `null` | 目录容量超限（当前累计 + 本次增量）→ `InvalidOperationException` |
| `MaxTotalSizeBytes` | `null` | 全局容量超限 → `InvalidOperationException` |

> **配额检查时机**：上传链 Blob 落盘**之前**（预检前移）——超限上传不产生物理 Blob/补偿；**并发竞态"先到先得"**（读-比-写非原子，超限最终一致可接受）。

## 4.1 文件版本化（V0.2.0）

**语义**：上传同名不同内容 → 生成新版本（`ManagedFileVersionEntity` 版本行，`UX_mfv_file_version` FileId+Version 唯一）；版本行存 Blob 路径指针（不复制字节，旧版本 Blob 天然保留）；SHA256 去重是内容级（同内容幂等返回不产生版本）。

```csharp
// ① 上传新版本（同目录同名不同内容 → 自动生成新版本）
var v1 = await fileManager.UploadFileAsync(folderId, "report.pdf", stream1);
var v2 = await fileManager.UploadFileAsync(folderId, "report.pdf", stream2);   // 同 Id，新版本

// ② 版本列表 / 详情（Version 升序；上限 1000）
var versions = await fileManager.GetFileVersionsAsync(v2.Id);                  // [Version 1, Version 2]
var v1Detail = await fileManager.GetFileVersionAsync(v2.Id, 1);                // 精确命中；不存在 → null

// ③ 回滚（主表指针切目标版本 + 新版本行 Version=max+1；目标版本不存在 → InvalidOperationException）
var rolledBack = await fileManager.RollbackFileAsync(v2.Id, 1);                // 回滚到 v1 内容
```

**删除语义**：`DeleteFileAsync` 清理主表 + **全部版本行 + Distinct 去重删全部版本 Blob**（回滚共享 StoredPath 不重复删）。

**回滚 Extension/ContentType 不回填**（Oracle P2-3）：二者由文件名派生，回滚不改文件名——避免 Name↔Extension 断裂。

## 5. 生产注意事项

- **建表**：`FileFolder` / `ManagedFile` / `ManagedFileVersion`（V0.2.0）三表由框架 `SyncTables` 统一托管（ADR49），**无手工 DDL 前置**。
- **同名上传语义（V0.2.0 变更）**：上传同名不同内容 → **生成新版本**（不再抛"已存在同名文件"）；同名同内容 → 幂等返回既有（Deduplicate=true/false 均幂等）。原 v0.1.0 根级同名应用层预检（C2）已移除——根级同名走版本化路径。
- **UTC 时间语义**：文件/目录/版本时间列 `DateTime`（UTC）显式声明；FreeSql SQLite 存本地墙钟、读出 `Unspecified`（+8 偏移）——文件元数据时间仅记录用途（无范围计算），如需严格 UTC 请自行归一。
- **物理存储依赖**：文件字节经 `IBlobStorageService` 契约委托 BlobStoring——消费方必须同时启用 BlobStoring（或提供自定义实现）；BlobStoring 异常静默模式（上传失败返回 null → 本扩展 fail-fast `InvalidOperationException`）与取消令牌穿透已修复（v0.1.1 修复集）。
- **目录树并发边界**：低频写（百级）——并发 Create 基于过期父快照可能产生 Level/Path 偏差，依赖 `UX_FileFolder_Code` 唯一约束 + 最后写入者生效，不做读-改-写原子。
- **版本并发上传**：两并发上传不同内容 → 版本号冲突由 `UX_mfv_file_version` 唯一约束兜底（败者补偿删 Blob + 报错）——对齐目录内同名并发语义。
- **安全红线**：物理文件不落消费方代码路径（全经 BlobStoring 委托）；防穿越/白名单/大小限制/ContentType 推导在门面层统一拦截。

## 6. 边界与语义速查

| 场景 | 行为 |
|------|------|
| 重复 Code 创建目录 | 库级唯一约束拒绝 |
| 目录含子目录/文件删除 | `InvalidOperationException`（删除保护） |
| 目录重命名 | 只改 Name（Path 由 Code 构建，Code 不可变，子树不重算） |
| 上传白名单外扩展名 / 超限 / 非法文件名 | `ArgumentException` |
| 上传同内容同目录同名 | 幂等返回既有文件（Deduplicate=true 预查 + false 事务内幂等，均不产生版本） |
| 上传同名不同内容（V0.2.0） | **生成新版本**（主表指针更新 + 版本行 max+1）——不再抛"已存在同名文件" |
| 回滚到不存在版本 | `InvalidOperationException` |
| 配额超限（文件数/目录容量/全局容量） | `InvalidOperationException`（含配额信息；Blob 落盘前拒绝） |
| 下载不存在文件 / Blob 缺失 | `InvalidOperationException` / `FileNotFoundException` |
| 重命名到白名单外扩展名 | `ArgumentException`（跨扩展名重命名自动重算 ContentType） |
| 移动文件到不存在的目录 / 重名目录 | `InvalidOperationException` |
| 无扩展名文件（如 "README"） | 默认被白名单拒绝（白名单不含空扩展名） |
