# HealthCheck 健康检查扩展-使用指南

> 扩展：`TKWF.Ext.HealthCheck`（v0.2.0）——系统健康探测接线（net10 内置 HealthChecks 聚合 + `/health` 端点映射 + **内置 DB 连通性探针**）。
> 本指南公开；迭代开发方案见主框架私有 `_TKWF/docs/03_扩展模块/HealthCheck/`。

---

## 1. 本扩展解决什么

主框架无健康检查接线。本扩展一键提供：
- **健康检查服务**（net10 内置 `Microsoft.Extensions.Diagnostics.HealthChecks`，零第三方依赖）；
- **`/health` 端点映射**（D04 框架生命线已对 `/health`/`/healthz` 做认证豁免——健康探测无需登录）；
- **自定义探针扩展点**（消费方按 ASP.NET Core 标准注册 `IHealthCheck`，扩展聚合全部检查项返回整体状态）；
- **`TKWF:HealthCheck` 配置节**（路径/开关/详情级别/匿名）。

**接线型扩展**：v0.1.0 不内置具体组件探针（DB/Redis 连通性）——数据访问红线规避；消费方注册自己的探针（标准 `AddCheck<T>`）。

## 3. 启用 + 接线

```csharp
// ① 白名单启用（v4.9.85+：发现不自动启用）
[TKWFEnabledExtension(typeof(HealthCheckExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }

// ② ServiceCollection：注册健康检查服务（默认 /health）
builder.Services.AddTkfwHealthChecks();

// ③ 自定义探针（标准 ASP.NET Core 方式）
builder.Services.AddHealthChecks().AddCheck<MyDbHealthCheck>("db");

// ④ 端点映射
app.MapTkfwHealthChecks();   // GET /health → {"status":"Healthy"}
```

## 4. 配置（`TKWF:HealthCheck`）

```jsonc
{
  "TKWF": {
    "HealthCheck": {
      "Path": "/health",          // 健康检查端点路径
      "Enabled": true,            // false = 不映射端点
      "Detailed": false,          // true = 输出组件级诊断 JSON（生产建议 false）
      "AllowAnonymous": true      // 端点匿名可访问（与 D04 豁免一致）
    }
  }
}
```

## 5. 自定义探针示例

```csharp
public sealed class MyDbHealthCheck(IEntityReadOnlyDAC<MyEntity> dac) : IHealthCheck
{
    public async Task<HealthCheckResult> CheckHealthAsync(
        HealthCheckContext context, CancellationToken ct = default)
    {
        try
        {
            // 经 ORM 无关只读 DAC 轻量探活（红线合规路径）
            await dac.ToListAsync(dac.Query.Take(1), ct);
            return HealthCheckResult.Healthy();
        }
        catch (Exception ex)
        {
            return HealthCheckResult.Unhealthy("数据库不可达", ex);
        }
    }
}
```

> 探针实现走 **DataService/只读 DAC**（红线：扩展与消费方均不得在探针中注入裸 `IFreeSql` 直接查询；探活属只读探测，经 `IEntityReadOnlyDAC<T>` 轻量路径）。

## 5.1 内置 DB 探针（V0.2.0，推荐）

v0.2.0 内置 `AddDatabaseHealthCheck<TEntity>`——免手写探针 + 红线合规路径（经 `IEntityReadOnlyDAC<T>` 只读接口）：

```csharp
// TEntity = 消费方任一 SG1 声明实体（[DomainGenerateCode] 自动实现 IDomainEntity）
services.AddTkfwHealthChecks()                       // V0.2.0 返回 IHealthChecksBuilder，支持链式
    .AddDatabaseHealthCheck<OrderEntity>("db")                     // 默认超时 5s
    .AddDatabaseHealthCheck<ProductEntity>("db-products", timeout: TimeSpan.FromSeconds(10));
```

**探针语义**：`SELECT COUNT(*) FROM {Entity 表}`——连接串有效 + DB 可达 + 表存在 + 查询可执行（**表级连通性检查**，非数据库级 "SELECT 1"）。DB 宕机/连接串错误/表缺失 → 查询异常 → Unhealthy（503）。

| 参数 | 默认 | 说明 |
|------|------|------|
| `name` | 必填 | 探针名称（出现在 Detailed 响应 entries） |
| `failureStatus` | `null` | 探针异常时的报告状态（默认 → Unhealthy） |
| `timeout` | `5s` | 探针超时（防 DB 连接 hang 致 /health 无限等待） |

> **红线合规边界**：此 `IEntityReadOnlyDAC<T>` 探针合规路径**仅限接线型扩展的基础设施连通性探测**（COUNT(*) 表级探活），**不作为业务扩展数据访问的先例**——业务扩展仍须走 SG1 DataService。

## 6. 响应语义

| 状态 | HTTP | 说明 |
|------|:----:|------|
| `Healthy` | 200 | 全部检查项通过 |
| `Degraded` | 200 | 部分检查项降级（如缓存不可用但核心可用） |
| `Unhealthy` | 503 | 关键检查项失败（内置 `ResultStatusCodes` 默认语义） |
| `Detailed=true` | 200/503 | 响应含组件级 `entries` 明细（名称/状态/耗时/异常类型） |

> LB/编排探活注意：`Degraded` 返回 200 是 ASP.NET Core 内置默认语义；若需 Degraded→503 可在 `MapTkfwHealthChecks` 显式覆盖 `ResultStatusCodes`。

## 7. 边界与已知限制

- **不内置组件探针**（DB/Redis/存储）——v0.2.0 候选（DB 探活经 `IEntityReadOnlyDAC<T>` 轻量探测，红线合规路径评估中）。
- **不持久化健康状态/历史/告警**——v0.2.0 候选。
- **无第三方依赖**：全部基于 net10 内置 `HealthChecks` + `Microsoft.AspNetCore.App` 共享框架。
