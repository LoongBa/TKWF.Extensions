## 一、背景与目标

### 问题

1. **5 份复制**：族系 A `DevRsaKeyCache`（AuthCenter 57 行）+ `DevEcKeyCache`（Federation 49 行）逐行一致（仅类型参数不同）；族系 B `PlatformCredentialKeyStore`（104）+ `FederationSecretKeyStore`（107）+ `MfaSecretKeyStore`（98）`Initialize` 主体逐行同构（仅错误消息前缀不同），`Encrypt`/`Decrypt` 三份完全一致——**且三份均内联 `new AesGcm(key, 16)` 重实现，未复用框架 `TKW.Framework.Utility.Cryptography.AeadEncryptionUtil` 既有资产**（转达 §四.1「原语复用」仅为建议，现状零复用）。
2. **生命周期纪律分裂**（转达 §三 实证的真实缺陷）：
   - `ResetForTests` 覆盖不均——AuthCenter 2/5 有且被测试调用；Federation 2/5 **定义但零调用（死钩子）**；MFA 1/5 **完全缺失**（`MfaSecretKeyStore` 无 Reset 方法，测试被迫用反射 `GetField("_key")` 复位）；
   - AuthCenter 测试项目因 `DevRsaKeyCache` 进程静态缓存冲突**禁用测试并行**（`AssemblyInfo.cs` `DisableTestParallelization`）——静态单例的实测代价。
3. **格式分裂**：扩展三段点分 `base64(iv).base64(tag).base64(cipher)` vs 框架规范单段 `base64(nonce‖cipher‖tag)`（`AeadEncryptionUtil` + `AesGcmCredentialProtector` 两处一致）——扩展是离群者，且与框架资产不可互通。
4. **DI 绕行**：扩展侧 `internal static` + 服务 ctor 副作用 `Initialize` 形态——唯一机械原因是 SG1 DataService 分部构造器固定 `(IDomainUser, IEntityDAC)` 两参无法注入 Options（`PlatformCredentialKeyStore.cs:9-12` 自认）。但消费拓扑实证（bg_73aafcd3）：**仅 1/3 族系 B（AuthCenter PlatformCredential）真正触碰 DataService 边界**；Federation 全在 `SsoClientService` 服务层、MFA 全在 `TotpMfaMethod` 方法层——服务层 DI 零阻塞。
5. **陈旧误导注释**：`MfaSecretEntityDataService.cs:17-18` 声称「secret AES-GCM 加解密在 DataService 边界（对齐 PlatformCredentialEntityDataService 先例）」——**实际加解密全在 `TotpMfaMethod`**，该注释虚假（复制链注释漂移实证，重构时一并修正）。

### 目标

1. **收敛 5 份 → 框架共享抽象**：族系 B → `ISymmetricKeyProvider`（文件路径驱动 + 生产 fail-fast + 开发随机 + 单段格式 AES-GCM）；族系 A → `DevKeyCache<TKey>` 泛型 DCL 缓存（`where TKey : IDisposable`）。
2. **复用框架既有资产**：加解密委托 `AeadEncryptionUtil`（补 `byte[] key` 重载）——消除 3 份内联 `new AesGcm` 与格式分裂。
3. **DI 化（消灭静态单例）**：密钥提供者/缓存注册为 DI 单例（keyed services 区分三扩展），服务层经构造注入消费——移除 `ResetForTests` 分裂、移除 `DisableTestParallelization`、移除 MFA 反射复位。
4. **加密边界统一到服务/方法层**：AuthCenter PlatformCredential 加密从 DataService 边界**上移到服务层**（对齐 Federation/MFA 拓扑），消除唯一 ctor 阻塞点——DataService 回归纯持久化。
5. **框架惯例对齐**：Null 标记/开发临时密钥/生产 fail-fast 三态语义对齐 `RegisterAuthServices`（`ICredentialProtector` 先例）。

## 五、技术方案

### 5.1 框架侧新增 API（T0——契约定稿，框架组实施）

**落点裁定**（推翻转达 §四.3「不上主框架」）：密钥管理抽象**上提 `TKW.Framework.Domain`**，理由：
- 框架**已有有状态密钥持有者先例**——`Domain/AuthController/AesGcmCredentialProtector`（DI 单例持有 `byte[] key`）+ `ICredentialProtector` + `NullCredentialProtector` 标记实现——「容量对象生命周期应留在扩展域」的转达裁定与既有代码事实矛盾（Domain 已承载）；
- `TKW.Framework.Utility.Cryptography` **无状态静态铁律**（组件指南 §2.2：无 Factory/无 OOP 实例化/无 DI）——有状态实例服务**不应**进 Utility；
- OAuthClient 归层判据（纯协议引擎→Utility）**不适用于**密钥持有者（有状态容量对象）——与 Utility.Cryptography 判据一致。

```csharp
// ===== TKW.Framework（接口落 Core / 实现落 Domain——对齐 ICredentialProtector 文件分层先例，P2-1 修订）=====
// 命名空间建议 TKW.Framework.Domain.KeyManagement（框架组可微调，语义不变）

/// <summary>对称密钥提供者（AES-GCM）——统一密钥材料加载 + 加解密。</summary>
public interface ISymmetricKeyProvider
{
    /// <summary>取密钥（前 32 字节）。</summary>
    byte[] GetKey();

    /// <summary>AES-GCM 加密：单段 base64(nonce[12]‖cipher‖tag[16])（规范格式，对齐 AeadEncryptionUtil）。</summary>
    string Encrypt(string plaintext);

    /// <summary>AES-GCM 解密：格式非法/认证失败抛 CryptographicException。</summary>
    string Decrypt(string ciphertext);
    // ⚠️ 无 ResetForTests——测试钩子 internal（P1-1 修订：公开接口不含测试关注）
}

/// <summary>
/// 文件路径驱动的对称密钥提供者——生产（IsProduction=true）缺密钥 fail-fast（InvalidOperationException）；
/// 开发分支保留两分支语义（P1-3 修订）：path 未配置 → 随机 32 字节 + Warning（不落盘）；path 配置但文件缺失
/// → 随机 32 字节 + **写入文件** + Warning（dev 跨重启密文可读——对齐扩展既有行为）；
/// 路径存在取前 32 字节（&lt;32 抛）。
/// 加解密委托 <see cref="AeadEncryptionUtil"/>（补 byte[] 重载）——单段规范格式。
/// </summary>
public sealed class FileSymmetricKeyProvider : ISymmetricKeyProvider
{
    public FileSymmetricKeyProvider(string? keyPath, bool isProduction, ILogger? logger = null);
    // 构造即加载（单例工厂内触发）——生产缺失抛；开发按两分支
    internal void ResetForTests();  // P1-1：internal + InternalsVisibleTo（对齐 DevRsaKeyCache 既有模式）；Array.Clear(_key) + 置 null
}

// ===== TKW.Framework.Utility.Caching（P2-2：非 Utility.Cryptography——避开无状态铁律命名空间；泛型 DCL 缓存）=====

/// <summary>开发模式临时密钥缓存（双重校验锁 + 泛型 IDisposable 契约）。</summary>
public sealed class DevKeyCache<TKey> where TKey : IDisposable
{
    public TKey GetOrCreate(Func<TKey> factory);   // DCL——工厂仅首次执行
    internal void ResetForTests();                  // P1-1：internal；Dispose 已缓存实例 + 置 null
}

// ===== key 字符串常量化（P2-4：防 typo 静默解析错 key）=====
public static class SymmetricKeyProviderKeys
{
    public const string AuthCenter = "AuthCenter";
    public const string Federation = "Federation";
    public const string Mfa = "MFA";
}

// ===== AeadEncryptionUtil 增强（Utility.Cryptography，加 byte[] key 重载，格式不变）=====
public static string Encrypt(string plainText, byte[] key);   // 新增
public static string Decrypt(string cipherText, byte[] key);  // 新增
```

**DI 注册形态**（关键设计——keyed services 解决多扩展同容器冲突）：

```csharp
// 各扩展 Initializer.ConfigureServices（示例 AuthCenter——key 用常量类，P2-4）
services.AddKeyedSingleton<ISymmetricKeyProvider, FileSymmetricKeyProvider>(
    SymmetricKeyProviderKeys.AuthCenter, (sp, _) =>
    {
        var opts = sp.GetRequiredService<IOptions<AuthCenterOptions>>().Value;
        return new FileSymmetricKeyProvider(
            opts.SecretEncryptionKeyPath, opts.IsProduction,
            sp.GetService<ILogger<FileSymmetricKeyProvider>>());
    });
services.AddSingleton(new DevKeyCache<TokenService.RsaKeySet>());  // 族系 A 单例（类型化）
```

> **为何 keyed**：消费方容器组装 AuthCenter + Federation + MFA 三扩展于同一容器——若三扩展均 `AddSingleton<ISymmetricKeyProvider>` 则 last-wins 冲突（后注册覆盖先注册，错误密钥风险）。`AddKeyedSingleton<...>(serviceKey)` 按 key 隔离（.NET 8+ 原生），消费方 ctor 用 `[FromKeyedServices(...)] ISymmetricKeyProvider` 注入——`ActivatorUtilities` 构造守卫工厂对 `[FromKeyedServices]` 参数原生支持（`IKeyedServiceProvider` 由默认 `ServiceProvider` 实现，.NET 8+ 已验证）。**⚠️ 该假设验证提前至 T1 首转换冒烟（P1-4）**——MFA `TotpMfaMethod` 最简（3 处调用），经 `User.Use<IMfaMethod>()` 全 AOP 路径断言 key 注入成功后再扩至其余；若失败早退至薄派生类型 fallback（§九 #1 裁定）。

### 5.2 AuthCenter 改造（T1）

| 现状 | 目标 |
|------|------|
| `DevRsaKeyCache`（internal static，进程静态缓存） | `DevKeyCache<TokenService.RsaKeySet>` DI 单例——`TokenService` ctor 注入，`LoadKeysCore` dev 分支 `_devKeys.GetOrCreate(() => CreateDevKeySet(...))`（生产分支 PEM 天然跨实例一致，恒不走缓存——语义不变）；**`TokenService.RsaKeySet` 实现 `IDisposable`（Dispose SigningKey + VerifyKeys 全量——P1-2 前置条件，现 ResetForTests 的 Dispose 行为移入类型自身）** |

| **`PlatformCredentialEntityDataService`（唯一 DataService 边界消费——L39/43/47 GetKey/Encrypt/Decrypt 私有包装）** | **加密边界上移服务层 + 方法面显式规约（P1-6 修订）**：DataService 回归纯持久化——保留 `GetEnabledByPlatformAsync`/`GetByAppAsync`/`SetEnabledAsync`；`GetSecretByAppIdAsync`（解密）拆为 `GetByAppIdAsync`（entity 返回，不解密）；`CreateEncryptedAsync(cred, plainSecret)`（加密）→ `CreateAsync(cred)`（已加密）；`UpdateEncryptedAsync` → `UpdateAsync(cred)`；删 `GetSecretByAppAsync`（服务层经 `GetByAppAsync` + `_keys.Decrypt` 取明文）。`PlatformCredentialService` 增 `_keys.Encrypt/Decrypt` 私有包装；`WeChatApiClient` 等直接 DataService 消费方改经门面（§九 #2 穷举） |

### 5.5 格式统一

- 规范格式 = **单段 `base64(nonce[12]‖cipher‖tag[16])`**（框架既有两处一致 + 组件指南规范）——扩展三段点分废弃，**零兼容层**（用户裁定）；
- **存量密文影响（闭环确认，非设计约束）**：AuthCenter V0.6.0 / Federation V0.1.1 / MFA V0.1.3 均 2026-10-05/06 新发，DMP-Lite 尚未迁移（README 明载）——**大概率无生产存量三段密文**；切换后既有 `PlatformCredential.AppSecretEncrypted`/`SsoClient` secrets/`MfaSecret.SecretEncrypted` 三段格式不可读——**一次性数据迁移**（旧 key 解密 → 新格式重加密）或接受重注册/重绑定；MFA secret 因属 TOTP seed 建议迁移脚本保重绑定成本（§6 迁移工具）。
