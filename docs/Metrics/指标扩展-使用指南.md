# 指标扩展-使用指南

**扩展**：`TKWF.Ext.Metrics`（业务指标计算引擎）· **版本**：v0.2.0（指标结果持久化契约）
> **概念名**：业务指标计算引擎（Metrics Engine）——规格文档驱动的复合业务指标计算，纯计算内核（无取数/无 ETL）+ 指标结果持久化契约（v0.2.0）
> **技术规范**：见 [_Framework/Metrics/README.md](../../_Framework/Metrics/README.md)

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\Metrics\TKWF.Ext.Metrics.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

扩展不再"发现即启用"——消费方须在领域初始化器上显式声明白名单，三钩子才接线：

```csharp
using TKWF.Ext.Metrics;

[TKWFEnabledExtension(typeof(MetricsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册：`IMetricsEngine`（Singleton，静态注册表零反射）+ `IMetricCalculatorFactory`（Singleton）+ `MetricsSpecFileProvider`（规格存取）+ `MetricsOptions` 绑定。

### 3. 注入 + 计算

```csharp
public class SalesAnalysisService(IMetricsEngine metricsEngine, MetricsSpecFileProvider specProvider)
{
    public async Task<IReadOnlyList<MetricResult>> CalculateAsync<T>(
        IReadOnlyList<T> data, string domain, string specKey, CancellationToken ct = default)
        where T : class
    {
        // 1. 加载规格（结构校验）
        var definitions = specProvider.Load(domain, specKey);
        // 2. 按规格计算（顺序执行；定义校验一次 + 访问器缓存）
        return await metricsEngine.CalculateAsync(data, definitions, ct);
    }
}
```

## 二、规格文件 (Spec Files)

### 目录与命名

```
{SpecRoot}/{Domain}/{specKey}/metric-definitions.json
```

- **SpecRoot**：配置 `TKWF:Metrics:SpecRoot`（默认 `docs/analytics-specs`，相对消费方仓库根；git-tracked，对齐 D20 spec 目录）
- **Domain**：业务域（如 `merchant`）
- **specKey**：`{VEntityName}--{intent}`（如 `PaymentLogStatView--daily-sales-trend`）

### 格式示例

```json
{
  "$schema": "tkwf-metrics-definitions/v1",
  "specKey": "PaymentLogStatView--daily-sales-trend",
  "metrics": [
    { "name": "repurchase-rate-30d", "calculator": "repurchase-rate",
      "parameters": { "userIdField": "MemberId", "orderTimeField": "BizDate", "windowDays": "30" },
      "description": "30 日复购率" },
    { "name": "aov-cny", "calculator": "ratio",
      "parameters": { "numeratorField": "TotalAmount", "numeratorAggregate": "sum",
                      "denominatorField": "PaidCount", "denominatorAggregate": "count" },
      "description": "客单价（元）" },
    { "name": "sales-daily", "calculator": "time-bucket",
      "parameters": { "timeField": "BizDate", "bucket": "day",
                      "valueField": "TotalAmount", "aggregate": "sum" },
      "description": "每日销售趋势" }
  ]
}
```

### 编写要点

- **扁平键参数**：`parameters` 为 `string → string` 字典，**禁止嵌套对象**（如 Ratio 用 `numeratorField`/`numeratorAggregate` 扁平键，非 `numerator: { field, aggregate }`）
- **字段引用**：`*Field` 参数值须匹配数据行（DTO）的属性名（如 `MemberId`、`BizDate`）
- **聚合值**：`*Aggregate` ∈ {`sum`, `count`, `avg`}
- **唯一性**：同一规格内 `name` 不重复
- **逗号限制**：`steps`/`retentionOffsets` 值 v0.1.0 不得含逗号

### 校验

| 校验项 | 时机 | 失败行为 |
|--------|------|---------|
| 计算器名存在 | 加载后执行前 | `MissingCalculatorBehavior`（默认 Throw → `MetricDefinitionException`；Warn → 该指标结果省略） |
| 字段名引用 | 执行前 | `MissingFieldBehavior`（默认 Throw；Null → 计算器按 null 处理） |
| JSON 合法 + `$schema` | 加载时 | Throw `MetricDefinitionException` |
| 指标名唯一 | 加载时 | Throw |
| 聚合值合法 | 计算器运行时 | Throw |

> D20 manifest 状态校验（specKey 存在 + status != stale）为 **v0.2.0 占位**，v0.1.0 不校验。

## 三、消费方集成模式（导入后更新）

DMP-Lite 场景：基于支付数据 + tag 数据计算经营指标，**数据导入后重算更新**。

```
导入流程（消费方）
  ① tkwf-service 查询已物化数据 → IReadOnlyList<T>
  ② 加载规格：specProvider.Load(domain, specKey) → IReadOnlyList<MetricDefinition>
  ③ engine.CalculateAsync(data, definitions, ct) → IReadOnlyList<MetricResult>
  ④ 结果落库（v0.2.0 标准路径：IMetricResultStore 契约，见「八、指标结果持久化」；v0.1.0 自落库路径继续可用）
  ⑤ 查询展示（D20 渲染管线 / 消费方 API）
```

- **幂等重算**：`MetricsEngine` 无状态（Singleton）——每次导入后重算即"更新"，天然幂等
- **as-of-date 注意**：`retention` 计算器锚定数据集**首日**——若导入更早数据，锚点移动、该指标跨重算波次不可直接对比（其余指标幂等可比）；消费方需按 as-of-date 标注
- **Value 可空**：`MetricResult.Value` 为 `object?`——`null` 表示"无值"（Ratio 分母 0、TimeBucket avg 全 null 桶、Funnel 无人进入、空数据）；展示前需判空
- **D20 消费**：结果可序列化为 D20 `data.values` 行格式；`AlignToD20DataValues` v0.1.0 为保留标志（no-op），行映射由消费方负责

### 结果消费示例

```csharp
// 计算 → 落库 / 返回前端
var results = await metricsEngine.CalculateAsync(data, definitions, ct);

// 单值指标（复购率/客单价）：直接取值
var aov = results.First(r => r.Name == "aov-cny");
decimal? aovValue = aov.Value as decimal?;   // null → 分母 0，前端显示"—"

// 多切片指标（销售趋势/同期群留存）：每行一个 D20 data.values
var salesByDay = results.Where(r => r.Name == "sales-daily");
foreach (var row in salesByDay)
{
    var bucket = row.Dimensions!["bucket"];       // "2026-08-01"
    var amount = row.Value;                        // 250m
    // → 写入消费方指标结果表 { metric: "sales-daily", bucket, value: amount }
}
```

## 四、内置计算器速查

### 单值输出

| 计算器 | 参数 | 算法 |
|--------|------|------|
| **`repurchase-rate`** | `userIdField`、`orderTimeField`(窗口必需)、`windowDays`(可选) | 分母 = ≥1 单用户；分子 = 首购后 `windowDays` 内复购用户；缺省 `windowDays` = 全量（≥2 单 / ≥1 单） |
| **`retention`** | `userIdField`、`dateField`、`retentionDays` | 锚定数据集首日 D：初始 ∩ (D+retentionDays) 仍活跃 / 初始；单周期 |
| **`ratio`** | `numeratorField`/`numeratorAggregate`、`denominatorField`/`denominatorAggregate` | 两聚合之比；分母 0 → `Value = null` |

### 多切片输出（引擎展开为多个 `MetricResult`，每切片带 `Dimensions`）

| 计算器 | 参数 | 输出 |
|--------|------|------|
| **`cohort-retention`** | `userIdField`、`dateField`、`cohortUnit`(day/week/month)、`retentionOffsets`(逗号分隔 int[]) | 每切片 Dimensions = `{ cohort: "2026-08", offset: 30 }`，Value = 留存率 |
| **`funnel`** | `userIdField`、`stepField`、`steps`(逗号分隔有序步骤)、`timeField`(可选) | 每切片 Dimensions = `{ step: "cart" }`，Value = 转化率（进入 0 → null） |
| **`time-bucket`** | `timeField`、`bucket`(hour/day/week/month)、`valueField`、`aggregate`、`groupField`(可选) | 每切片 Dimensions = `{ bucket: "2026-08", [groupField] }`，Value = 聚合值 |

**行为约定**：
- 事件/行序：`funnel` 有 `timeField` 按时间升序，缺省按数据行原始顺序
- 桶截断：`week` = ISO 8601（周一为一周起始）；`month` = 日历月；`hour` = 时钟小时
- 空数据：引擎跳过计算器调用，返回空列表（不抛）

## 五、异常处理

| 场景 | 异常 | 说明 |
|------|------|------|
| 计算器未注册 / 字段缺失 / 规格损坏 / 指标名重复 | `MetricDefinitionException` | 含 `specKey` + 指标名 + 原因，便于定位到具体规格行 |
| 计算超时（顺序 CPU 协作式） | `TimeoutException` | `CalculateTimeout` 默认 30s，定义间检查 |
| 规格文件缺失 | `MetricDefinitionException` | 经 `MetricsSpecFileProvider.Load` |

> **严格失败优于静默错数**：默认 `Throw`——规格引用错误显式暴露（对齐 TKWF 编译期错误哲学），勿轻易改 `Warn`/`Null`。

## 七、常见问题（FAQ）

| 问题 | 说明 |
|------|------|
| **字段名匹配** | `*Field` 参数值须与数据行（DTO）**属性名完全一致**（区分大小写）；不匹配 → `MissingFieldBehavior`（默认 Throw `MetricDefinitionException`，可改 Null 让计算器按 null 处理） |
| **`count` 聚合返回类型** | TimeBucket 的 `count` 返回 `int`；Ratio 的 `count` 中间值为 `decimal`（除法需要）。判型时注意（`r.Value as int` vs `as decimal`） |
| **`funnel` 时间缺失** | 提供 `timeField` 但某行时间 null/不可解析 → 该事件按 .NET 稳定排序**置前**，可能影响有序子序列匹配（属数据质量问题；v0.2.0 评估排除或报错） |
| **`retention` 锚点漂移** | 锚定数据集首日——导入更早数据会移动锚点，该指标跨波次不可直接对比（按 as-of-date 标注） |
| **空数据** | 引擎跳过计算器调用返回空列表（不抛）；调用方自行展示"暂无数据" |
| **值类型转换** | `MetricRow.Get<T>` 为简单强转——字段类型与请求类型不一致会抛 `InvalidCastException`（如字段是 `decimal` 却 `Get<int>`）；按字段实际类型用 `Get<decimal?>` 等 |
| **自定义计算器** | 实现 `IMetricCalculator` 后，包装/替换 `CalculatorFactory` 并在消费方 DI 覆盖 `IMetricCalculatorFactory`（TryAdd 语义——消费方注册优先，扩展默认不覆盖）：`services.AddSingleton<IMetricCalculatorFactory, MyCalculatorFactory>()`。**无必要勿增 SG**——此能力已有 DI 覆盖方案，不构成引入 SG 的必要性 |
| **规格热更新** | v0.1.0 规格文件改动后**重启生效**（加载时校验 + 引擎内缓存）；无运行期热重载 |

## 八、指标结果持久化（V0.2.0）

### 8.1 契约

| 组件 | 说明 |
|------|------|
| **`IMetricResultStore`** | 持久化契约——`SaveAsync(rows)` / `QueryAsync(query)` / `CountAsync(query)` / `CleanupExpiredAsync(retentionDays, batchSize=500)` |
| **`MetricResultRow`** | 标准化行——`SpecKey`/`Name`/`Value`/`Unit`/`DimensionsJson`/`CalculatedAtUtc` |
| **`MetricResultQuery`** | 查询条件——`SpecKey`/`Name`/`FromUtc`/`ToUtc`/`DimensionFilter`/`Skip`/`Take` |
| **`MetricResultMapper`** | 静态映射器——`ToRows(results, specKey?, calculatedAtUtc?)` 1:1 展开 + Dimensions JSON 序列化 |

**关键语义**：
- **Mapper 不做切片展开（C1）**：`MetricsEngine.AddResult` 已把 `MetricSlice[]` 展开为多个 `MetricResult`——`ToRows` 只做 1:1 投影，消费方无需/无义务处理切片。
- **`Value` 后引擎不变量（P3）**：经引擎计算 + Mapper 投影后为**标量**（decimal/double/string/null）——落库时标量 `ToString()` 或 JSON 化即可；复杂值（自定义计算器/直连 calculator）由消费方 Store 按需 JSON 化。
- **`DimensionsJson` 序列化约定（P5）**：`Dimensions == null` → `null`；空字典 → `"{}"`；null 维度值省略（`{"bucket":"2026-08","segment":null}` → `{"bucket":"2026-08"}`）。`MetricResultMapper.JsonOptions` 暴露复用（`WhenWritingNull` + 紧凑）。
- **Take 钳制（P4）**：`MetricResultQuery.Take` 默认 50，**消费方 Store MUST 钳制到 [1,200]**——超界静默钳制、`Take<0` 视为 0。
- **`DimensionFilter` 可选（P1）**：按需实现（SQL JSON 函数或内存过滤）；未实现返回未按维度过滤结果（兼容降级）。

### 8.2 消费方接线三步

> 实体由消费方提供（`[DomainGenerateCode]` 接线 SG1 自动生成 DataService/DTO/API）——扩展不注册默认 Store 实现、不做建表 CRUD（ADR 决策 1）。

```csharp
// ① 定义实体
[Table("SalesMetricResult")]
[DomainGenerateCode(DefaultPageSize = 50)]
public partial class SalesMetricResultEntity
{
    [FreeSql.DataAnnotations.Column(IsPrimary = true, IsIdentity = true, Position = 1)] public long Id { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 2)] [MaxLength(128)] public string? SpecKey { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 3)] [MaxLength(128)] public string Name { get; set; } = "";
    [FreeSql.DataAnnotations.Column(Position = 4)] public string? ValueText { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 5)] [MaxLength(64)] public string? Unit { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 6)] [MaxLength(2000)] public string? DimensionsJson { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 7, CanUpdate = false)] public DateTime CalculatedAtUtc { get; set; }
    [FreeSql.DataAnnotations.Column(Position = 8, CanUpdate = false)] public DateTime CreateTime { get; set; } = DateTime.UtcNow;
}

// ② DataService 分部写 public 委托方法（xCodeGen 生成的转发方法为 internal——跨程序集须 public 包装，防御性约定）
partial class SalesMetricResultEntityDataService(IDomainUser user, IEntityDAC<SalesMetricResultEntity> dac)
    : DomainDataServiceBase<SalesMetricResultEntity, SalesMetricResultEntityDto>(user, dac, hasSoftDelete: false)
{
    public async Task CreateBatchAsync(IReadOnlyList<SalesMetricResultEntity> entities, CancellationToken ct = default)
        => await EntityCreateBatchAsync(entities, ct);

    public async Task<List<SalesMetricResultEntity>> QueryByMetricAsync(
        string? specKey, string? name, DateTime? fromUtc, DateTime? toUtc,
        int skip, int take, CancellationToken ct = default)
        => await EntitySelectAsync(BuildPredicate(specKey, name, fromUtc, toUtc), skip, take,
            q => q.OrderByDescending(e => e.CalculatedAtUtc), ct);

    public async Task<int> DeleteBeforeAsync(DateTime cutoffUtc, int batchSize, CancellationToken ct = default)
    {
        var total = 0;
        while (true)   // C3：循环分批清完——best-effort，竞态由下次调用补删
        {
            var rows = await EntitySelectAsync(e => e.CalculatedAtUtc < cutoffUtc, 0, batchSize, ct: ct);
            if (rows.Count == 0) break;
            total += await EntityDeleteBatchAsync(rows.Select(r => r.Id), ct);
        }
        return total;
    }
}

// ③ 实现 IMetricResultStore（行→实体映射 + 委托 DataService public 方法——红线合规）
public sealed class SalesMetricResultStore : IMetricResultStore
{
    private readonly SalesMetricResultEntityDataService _ds;
    public SalesMetricResultStore(SalesMetricResultEntityDataService ds) => _ds = ds;

    public async Task<int> SaveAsync(IReadOnlyList<MetricResultRow> rows, CancellationToken ct = default)
    {
        var entities = rows.Select(r => new SalesMetricResultEntity
        {
            SpecKey = r.SpecKey, Name = r.Name,
            ValueText = r.Value switch
            {
                null => null, string s => s,
                _ => System.Text.Json.JsonSerializer.Serialize(r.Value, MetricResultMapper.JsonOptions)
            },
            Unit = r.Unit, DimensionsJson = r.DimensionsJson, CalculatedAtUtc = r.CalculatedAtUtc
        }).ToList();
        await _ds.CreateBatchAsync(entities, ct);
        return entities.Count;
    }

    public async Task<IReadOnlyList<MetricResultRow>> QueryAsync(MetricResultQuery query, CancellationToken ct = default)
    {
        var (skip, take) = NormalizePage(query.Skip, query.Take);   // Take 钳制 [1,200] 静默
        var entities = await _ds.QueryByMetricAsync(query.SpecKey, query.Name, query.FromUtc, query.ToUtc, skip, take, ct);
        return entities.Select(e => new MetricResultRow(e.SpecKey, e.Name, e.ValueText, e.Unit, e.DimensionsJson, e.CalculatedAtUtc)).ToList();
    }

    public Task<long> CountAsync(MetricResultQuery query, CancellationToken ct = default)
        => _ds.CountAsync(/* 同 QueryAsync 谓词 */ ...);

    public Task<int> CleanupExpiredAsync(int retentionDays, int batchSize = 500, CancellationToken ct = default)
        => _ds.DeleteBeforeAsync(DateTime.UtcNow.AddDays(-retentionDays), batchSize, ct);
}

// ④ DI 注册（扩展不注册默认实现——消费方自行注册）
services.TryAddScoped<IMetricResultStore, SalesMetricResultStore>();
```

### 8.3 业务使用（计算 → 落库）

```csharp
public class BusinessService(IMetricsEngine engine, IMetricResultStore store)
{
    public async Task RunAsync(IReadOnlyList<T> data, IReadOnlyList<MetricDefinition> definitions,
        string specKey, CancellationToken ct = default)
    {
        var results = await engine.CalculateAsync(data, definitions, ct);
        var rows = MetricResultMapper.ToRows(results, specKey: specKey);   // 标准化展开（扩展执行）
        await store.SaveAsync(rows, ct);                                    // 落库（消费方 Store）
    }
}
```

### 8.4 红线合规（数据访问红线 2026-09-07 裁定）

- ✅ **Store 绝不注入 `IFreeSql`/`IEntityDAC`**——只经 DataService public 委托方法（上例 `_ds.CreateBatchAsync`/`QueryByMetricAsync`/`DeleteBeforeAsync`）。
- ✅ **实体数据访问走 SG1 生成 DataService**（`DomainDataServiceBase` 派生）——不是裸 ORM 直接写查询。
- ❌ 反例（禁止）：`EntityDACPermissionStore` 式直接 `IEntityDAC<T>` 手写数据访问（待整改，不构成示范）。

### 8.5 清理调度

`CleanupExpiredAsync(retentionDays, batchSize=500)` **best-effort 一次调用清完当前过期集**（循环分批，不清完不返回；竞态容忍——select→delete 之间并发可致漏删，下次调用补删）。扩展不内建调度器——消费方经 **BackgroundJobs/Quartz 每日定时触发**：

```csharp
// 消费方 BackgroundJob（示意）
await metricResultStore.CleanupExpiredAsync(retentionDays: 90, batchSize: 500, ct);
```

### 8.6 兼容与迁移

- **v0.1.0 自落库路径继续可用**：消费方已实现的"遍历结果 → 映射 → 写自有表"样板无需改写；`IMetricResultStore` 是**可选**的标准路径，不强制迁移。
- **扩展零负担**：`TKWF.Ext.Metrics` **不新增任何依赖**（保持仅 TKWF.Domain + TKWF.Utility）；`MetricsExtensionInitializer` 不注册 Store 默认实现——未实现 `IMetricResultStore` 的消费方无感知。
