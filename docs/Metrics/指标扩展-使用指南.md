# 指标扩展-使用指南

> **扩展**：`TKWF.Ext.Metrics`（业务指标计算引擎）· **版本**：v0.1.0
> **概念名**：业务指标计算引擎（Metrics Engine）——规格文档驱动的复合业务指标计算，纯计算内核（无取数/无 ETL）
> **技术规范**：见 [_Framework/Metrics/README.md](../../_Framework/Metrics/README.md)

---

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\Metrics\TKWF.Ext.Metrics.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

扩展不再"发现即启用"——消费方须在领域初始化器上显式声明白名单，三钩子才接线：

```csharp
using TKWF.Ext.Metrics;

[TKWFEnabledExtension(typeof(MetricsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册：`IMetricsEngine`（Singleton，静态注册表零反射）+ `IMetricCalculatorFactory`（Singleton）+ `MetricsSpecFileProvider`（规格存取）+ `MetricsOptions` 绑定。

### 3. 注入 + 计算

```csharp
public class SalesAnalysisService(IMetricsEngine metricsEngine, MetricsSpecFileProvider specProvider)
{
    public async Task<IReadOnlyList<MetricResult>> CalculateAsync<T>(
        IReadOnlyList<T> data, string domain, string specKey, CancellationToken ct = default)
        where T : class
    {
        // 1. 加载规格（结构校验）
        var definitions = specProvider.Load(domain, specKey);
        // 2. 按规格计算（顺序执行；定义校验一次 + 访问器缓存）
        return await metricsEngine.CalculateAsync(data, definitions, ct);
    }
}
```

## 二、规格文件 (Spec Files)

### 目录与命名

```
{SpecRoot}/{Domain}/{specKey}/metric-definitions.json
```

- **SpecRoot**：配置 `TKWF:Metrics:SpecRoot`（默认 `docs/analytics-specs`，相对消费方仓库根；git-tracked，对齐 D20 spec 目录）
- **Domain**：业务域（如 `merchant`）
- **specKey**：`{VEntityName}--{intent}`（如 `PaymentLogStatView--daily-sales-trend`）

### 格式示例

```json
{
  "$schema": "tkwf-metrics-definitions/v1",
  "specKey": "PaymentLogStatView--daily-sales-trend",
  "metrics": [
    { "name": "repurchase-rate-30d", "calculator": "repurchase-rate",
      "parameters": { "userIdField": "MemberId", "orderTimeField": "BizDate", "windowDays": "30" },
      "description": "30 日复购率" },
    { "name": "aov-cny", "calculator": "ratio",
      "parameters": { "numeratorField": "TotalAmount", "numeratorAggregate": "sum",
                      "denominatorField": "PaidCount", "denominatorAggregate": "count" },
      "description": "客单价（元）" },
    { "name": "sales-daily", "calculator": "time-bucket",
      "parameters": { "timeField": "BizDate", "bucket": "day",
                      "valueField": "TotalAmount", "aggregate": "sum" },
      "description": "每日销售趋势" }
  ]
}
```

### 编写要点

- **扁平键参数**：`parameters` 为 `string → string` 字典，**禁止嵌套对象**（如 Ratio 用 `numeratorField`/`numeratorAggregate` 扁平键，非 `numerator: { field, aggregate }`）
- **字段引用**：`*Field` 参数值须匹配数据行（DTO）的属性名（如 `MemberId`、`BizDate`）
- **聚合值**：`*Aggregate` ∈ {`sum`, `count`, `avg`}
- **唯一性**：同一规格内 `name` 不重复
- **逗号限制**：`steps`/`retentionOffsets` 值 v0.1.0 不得含逗号

### 校验

| 校验项 | 时机 | 失败行为 |
|--------|------|---------|
| 计算器名存在 | 加载后执行前 | `MissingCalculatorBehavior`（默认 Throw → `MetricDefinitionException`；Warn → 该指标结果省略） |
| 字段名引用 | 执行前 | `MissingFieldBehavior`（默认 Throw；Null → 计算器按 null 处理） |
| JSON 合法 + `$schema` | 加载时 | Throw `MetricDefinitionException` |
| 指标名唯一 | 加载时 | Throw |
| 聚合值合法 | 计算器运行时 | Throw |

> D20 manifest 状态校验（specKey 存在 + status != stale）为 **v0.2.0 占位**，v0.1.0 不校验。

## 三、消费方集成模式（导入后更新）

DMP-Lite 场景：基于支付数据 + tag 数据计算经营指标，**数据导入后重算更新**。

```
导入流程（消费方）
  ① tkwf-service 查询已物化数据 → IReadOnlyList<T>
  ② 加载规格：specProvider.Load(domain, specKey) → IReadOnlyList<MetricDefinition>
  ③ engine.CalculateAsync(data, definitions, ct) → IReadOnlyList<MetricResult>
  ④ 结果落库（消费方自有表/存储——Metrics v0.1.0 不提供结果持久化）
  ⑤ 查询展示（D20 渲染管线 / 消费方 API）
```

- **幂等重算**：`MetricsEngine` 无状态（Singleton）——每次导入后重算即"更新"，天然幂等
- **as-of-date 注意**：`retention` 计算器锚定数据集**首日**——若导入更早数据，锚点移动、该指标跨重算波次不可直接对比（其余指标幂等可比）；消费方需按 as-of-date 标注
- **Value 可空**：`MetricResult.Value` 为 `object?`——`null` 表示"无值"（Ratio 分母 0、TimeBucket avg 全 null 桶、Funnel 无人进入、空数据）；展示前需判空
- **D20 消费**：结果可序列化为 D20 `data.values` 行格式；`AlignToD20DataValues` v0.1.0 为保留标志（no-op），行映射由消费方负责

### 结果消费示例

```csharp
// 计算 → 落库 / 返回前端
var results = await metricsEngine.CalculateAsync(data, definitions, ct);

// 单值指标（复购率/客单价）：直接取值
var aov = results.First(r => r.Name == "aov-cny");
decimal? aovValue = aov.Value as decimal?;   // null → 分母 0，前端显示"—"

// 多切片指标（销售趋势/同期群留存）：每行一个 D20 data.values
var salesByDay = results.Where(r => r.Name == "sales-daily");
foreach (var row in salesByDay)
{
    var bucket = row.Dimensions!["bucket"];       // "2026-08-01"
    var amount = row.Value;                        // 250m
    // → 写入消费方指标结果表 { metric: "sales-daily", bucket, value: amount }
}
```

## 四、内置计算器速查

### 单值输出

| 计算器 | 参数 | 算法 |
|--------|------|------|
| **`repurchase-rate`** | `userIdField`、`orderTimeField`(窗口必需)、`windowDays`(可选) | 分母 = ≥1 单用户；分子 = 首购后 `windowDays` 内复购用户；缺省 `windowDays` = 全量（≥2 单 / ≥1 单） |
| **`retention`** | `userIdField`、`dateField`、`retentionDays` | 锚定数据集首日 D：初始 ∩ (D+retentionDays) 仍活跃 / 初始；单周期 |
| **`ratio`** | `numeratorField`/`numeratorAggregate`、`denominatorField`/`denominatorAggregate` | 两聚合之比；分母 0 → `Value = null` |

### 多切片输出（引擎展开为多个 `MetricResult`，每切片带 `Dimensions`）

| 计算器 | 参数 | 输出 |
|--------|------|------|
| **`cohort-retention`** | `userIdField`、`dateField`、`cohortUnit`(day/week/month)、`retentionOffsets`(逗号分隔 int[]) | 每切片 Dimensions = `{ cohort: "2026-08", offset: 30 }`，Value = 留存率 |
| **`funnel`** | `userIdField`、`stepField`、`steps`(逗号分隔有序步骤)、`timeField`(可选) | 每切片 Dimensions = `{ step: "cart" }`，Value = 转化率（进入 0 → null） |
| **`time-bucket`** | `timeField`、`bucket`(hour/day/week/month)、`valueField`、`aggregate`、`groupField`(可选) | 每切片 Dimensions = `{ bucket: "2026-08", [groupField] }`，Value = 聚合值 |

**行为约定**：
- 事件/行序：`funnel` 有 `timeField` 按时间升序，缺省按数据行原始顺序
- 桶截断：`week` = ISO 8601（周一为一周起始）；`month` = 日历月；`hour` = 时钟小时
- 空数据：引擎跳过计算器调用，返回空列表（不抛）

## 五、异常处理

| 场景 | 异常 | 说明 |
|------|------|------|
| 计算器未注册 / 字段缺失 / 规格损坏 / 指标名重复 | `MetricDefinitionException` | 含 `specKey` + 指标名 + 原因，便于定位到具体规格行 |
| 计算超时（顺序 CPU 协作式） | `TimeoutException` | `CalculateTimeout` 默认 30s，定义间检查 |
| 规格文件缺失 | `MetricDefinitionException` | 经 `MetricsSpecFileProvider.Load` |

> **严格失败优于静默错数**：默认 `Throw`——规格引用错误显式暴露（对齐 TKWF 编译期错误哲学），勿轻易改 `Warn`/`Null`。

## 七、常见问题（FAQ）

| 问题 | 说明 |
|------|------|
| **字段名匹配** | `*Field` 参数值须与数据行（DTO）**属性名完全一致**（区分大小写）；不匹配 → `MissingFieldBehavior`（默认 Throw `MetricDefinitionException`，可改 Null 让计算器按 null 处理） |
| **`count` 聚合返回类型** | TimeBucket 的 `count` 返回 `int`；Ratio 的 `count` 中间值为 `decimal`（除法需要）。判型时注意（`r.Value as int` vs `as decimal`） |
| **`funnel` 时间缺失** | 提供 `timeField` 但某行时间 null/不可解析 → 该事件按 .NET 稳定排序**置前**，可能影响有序子序列匹配（属数据质量问题；v0.2.0 评估排除或报错） |
| **`retention` 锚点漂移** | 锚定数据集首日——导入更早数据会移动锚点，该指标跨波次不可直接对比（按 as-of-date 标注） |
| **空数据** | 引擎跳过计算器调用返回空列表（不抛）；调用方自行展示"暂无数据" |
| **值类型转换** | `MetricRow.Get<T>` 为简单强转——字段类型与请求类型不一致会抛 `InvalidCastException`（如字段是 `decimal` 却 `Get<int>`）；按字段实际类型用 `Get<decimal?>` 等 |
| **自定义计算器** | 实现 `IMetricCalculator` 后，包装/替换 `CalculatorFactory` 并在消费方 DI 覆盖 `IMetricCalculatorFactory`（TryAdd 语义——消费方注册优先，扩展默认不覆盖）：`services.AddSingleton<IMetricCalculatorFactory, MyCalculatorFactory>()`。**零 SG 接线** |
| **规格热更新** | v0.1.0 规格文件改动后**重启生效**（加载时校验 + 引擎内缓存）；无运行期热重载 |
