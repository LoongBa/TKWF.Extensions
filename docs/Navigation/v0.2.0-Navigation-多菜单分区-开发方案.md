# v0.2.0 — Navigation 多菜单分区 开发方案

> **扩展**: `TKWF.Ext.Navigation` | **版本**: v0.2.0 | **依赖**: 无新增（纯扩展侧，不依赖框架组）
> **日期**: 2026-09-16 | **状态**: 📋 提议（修订 1——Oracle 评审 PASS WITH CONDITIONS 4 条件已吸收，待实施）
> **关联**: 跟踪 §五 #4（前瞻扩展点）；README V0.2.0 规划（多菜单组分区）；`IMenuManager.GetMenuAsync(string)` 接口已就绪（前瞻设计）

---

## 一、目的与目标

为 Navigation 增加**多菜单分区**能力——单应用承载多套菜单（Main 主菜单 / Admin 管理菜单 / Mobile 移动菜单），贡献者经 `MenuName` 声明菜单归属，`GetMenuAsync(menuName)` 按名精确返回，替代当前"单一定义集、所有菜单混在一起"的模型。

目标状态（3 句内）：①`MenuItemDefinition` 增 `MenuName` 属性（默认 `"Main"`——既有贡献者零迁移）；②`MenuManager.GetMenuAsync(menuName)` 按 `MenuName` 过滤（替代当前全部返回）；③`NavigationOptions.DefaultMenuName` 驱动便捷入口 `GetMainMenuAsync()`（取配置值而非硬编码 "Main"）——Admin/Mobile 多菜单开箱即用。

---

## 二、问题

### 问题现象

- `IMenuManager.GetMenuAsync(string menuName)` 接口**存在但不生效**——`MenuManager.cs` L40 `_repository.GetAll()` 返回全部项，L38-39 注释明示"单一菜单定义集，未按 menuName 分区；menuName 为前瞻扩展点"。
- `MenuItemDefinition` **无 `MenuName` 属性**——所有菜单项（无论归属主菜单/管理菜单/移动菜单）混入同一集合。
- `GetMainMenuAsync()` 硬编码 `"Main"`（L33），忽略 `NavigationOptions.DefaultMenuName`（消费方配置 `DefaultMenuName` 不生效）。

### 触发场景

- 企业后台同时需要**主菜单**（业务功能）+ **管理菜单**（系统管理/权限/审计）——当前无法分区，贡献者只能把管理项混进主菜单。
- 移动端/多租户需要不同菜单集。
- 消费方配置 `TKWF:Navigation:DefaultMenuName = "Admin"` 期望 `GetMainMenuAsync()` 返回 Admin 菜单——当前忽略配置。

### 现有方案不足

- **单集合扁平模型**：`IMenuDefinitionRepository.GetAll()` 无菜单名维度——多菜单需调用方自过滤（无契约支持）。
- **硬编码 "Main"**：`GetMainMenuAsync` 与 `NavigationOptions.DefaultMenuName`（`[Required]` 配置锚点）脱节——配置形同虚设。
- **前瞻接口空转**：`GetMenuAsync(menuName)` 参数被忽略——设计意图（多菜单组）未落地。

---

## 三、使用场景

1. **主菜单 + 管理菜单**（常态）：消费方贡献 `AdminMenuContributor`（`MenuName = "Admin"`）+ 既有 `MainMenuContributor`（默认 "Main"）——`GetMenuAsync("Admin")` 只返回管理菜单项，`GetMainMenuAsync()` 返回主菜单。
2. **移动端菜单**：`MobileMenuContributor`（`MenuName = "Mobile"`）——APP 端调 `GetMenuAsync("Mobile")`。
3. **配置驱动主菜单名**：消费方设 `DefaultMenuName = "Admin"` → `GetMainMenuAsync()` 返回 Admin 菜单。
4. **不适用**：单菜单应用（默认 "Main" 零迁移，行为不变）；菜单持久化（FreeSql 存储——README 规划项，但本方案**不做**，保持纯内存，避免与 ADR61 数据访问红线/新增 SG1 实体牵扯）。

---

## 四、决策

### 核心机制（最小变更——接口已就绪，仅补模型 + 过滤）

```
① MenuItemDefinition.MenuName（默认 "Main"）── 贡献者声明菜单归属
        │ 向后兼容：未设置 = "Main"（既有贡献者零迁移）
        ▼
② MenuManager.GetMenuAsync(menuName) ── 按 MenuName 过滤（替代全部返回）
        │ + GetMainMenuAsync 读 DefaultMenuName（替代硬编码 "Main"）
        ▼
③ 多菜单开箱即用（Admin/Mobile/Main 分区）✓
```

### 1. `MenuItemDefinition` 增 `MenuName` 属性

```csharp
/// <summary>
/// 所属菜单名（V0.2.0 多菜单分区；默认 "Main"——对齐 NavigationOptions.DefaultMenuName）。
/// <para>贡献者不设置 = 归入默认菜单（向后兼容既有贡献者零迁移）；
/// 设置 "Admin"/"Mobile" 等 = 归入对应菜单组。
/// ⚠️ 不可为 null/空白（Oracle 条件 2：MenuConfigurationContext.Add 校验，对齐 Name 校验）。</para>
/// </summary>
public string MenuName { get; init; } = "Main";   // Oracle NICE：init 对齐 Name 不可变语义
```

- **向后兼容**：默认 `"Main"`——既有贡献者（`MainMenuContributor` 未设 MenuName）零迁移，行为不变。
- **大小写**：按字符串精确匹配（`StringComparer.Ordinal`——菜单名是稳定标识符，对齐 `Name` 语义）。
- **不可变（Oracle NICE 吸收）**：`init` ——分区键一经设置不可变，对齐 `Name` 身份属性语义。

### 1.5 `MenuConfigurationContext.Add` 校验 MenuName（Oracle 条件 2）

`MenuConfigurationContext.Add(MenuItemDefinition)` 增 MenuName 校验（对齐既有 `Name` 校验——`Name` null/空白抛异常先例）：

```csharp
if (string.IsNullOrWhiteSpace(menuItem.MenuName))
    throw new ArgumentException("菜单项 MenuName 不能为空", nameof(menuItem));
```

- **fail-fast**：贡献期暴露 null MenuName（而非运行时静默从所有菜单消失）。
- 归一化方案否决（Oracle 推荐前者）——显式抛异常优于静默改默认值。

### 2. `MenuManager.GetMenuAsync` 按 MenuName 过滤

```csharp
public async Task<MenuItemDefinition[]> GetMenuAsync(string menuName)
{
    // V0.2.0：按 menuName 分区（替代单一集合全部返回）
    // Oracle 条件 3：跨菜单 Parent 引用——scoped 过滤后 byName 不含跨菜单项 → 视为顶层（depth 0），不抛异常
    var all = _repository.GetAll();
    var scoped = all
        .Where(i => string.Equals(i.MenuName, menuName, StringComparison.Ordinal))
        .ToList();
    if (scoped.Count == 0) return Array.Empty<MenuItemDefinition>();
    // ... 权限过滤 + 循环检测 + 排序（逻辑不变，操作 scoped）
}
```

- **权限过滤/循环检测/排序**逻辑不变——仅过滤源从 `all` 换为 `scoped`。
- **空菜单**：`GetMenuAsync("Admin")` 无 Admin 贡献者 → 空数组（消费方渲染空菜单）。
- **参数校验（Oracle NICE 吸收）**：`GetMenuAsync(null)`/`GetMenuAsync("")` → `ArgumentException`。
- **过滤位置（Oracle NICE）**：Manager 层内存过滤适合纯内存仓库；数据库仓库场景（v0.3.0+ 规划）需演进 `IMenuDefinitionRepository` 接口（新增按名查询）——本版不引入。

### 3. `GetMainMenuAsync` 读 DefaultMenuName

```csharp
public Task<MenuItemDefinition[]> GetMainMenuAsync()
    => GetMenuAsync(_options?.DefaultMenuName ?? "Main");
```

- **依赖注入**：`MenuManager` 构造增 `IOptions<NavigationOptions>`（对齐 Settings/FeatureManagement 先例）——从配置读 `DefaultMenuName`。
- **⚠️ Initializer 补 `AddOptions<NavigationOptions>()`（Oracle 条件 1，BLOCKER 级）**：
  ```csharp
  services.AddOptions<NavigationOptions>();   // 对齐 Settings L41 先例——确保 IOptions 在所有宿主可解析
  ```
  当前 `NavigationExtensionInitializer.ConfigureServices` **未注册 Options**（此前 MenuManager 无 IOptions 依赖）。新增构造参数后须补此注册，否则非 SG1 宿主/测试 DI 解析失败。
- **注册方式（Oracle 条件 1 修正）**：保持类型注册 `services.TryAddSingleton<IMenuManager, MenuManager<TUserInfo>>()`（DI 自动解析构造参数）——**无需改工厂委托**（修正初稿"Initializer 工厂注册"不准确表述）。
- **兼容**：未配置 = 默认 "Main"（行为不变）；配置 = 生效（修复当前"配置形同虚设"缺陷）。

### 4. 破坏性声明

- **加性变更**：`MenuItemDefinition` 增属性（默认值 + init，构造函数/初始化器不破坏）；`MenuConfigurationContext.Add` 增 MenuName 校验（仅拦截显式 null/空白——既有贡献者默认 "Main" 不受影响）。
- **构造变化**：`MenuManager` 构造增 `IOptions<NavigationOptions>`——**public 构造**；DI 类型注册自动解析（消费方自定义 `IMenuManager` 经 TryAdd 优先不受影响）。
- **行为修复**：`GetMainMenuAsync` 现在真正读 `DefaultMenuName`（原被忽略，属缺陷修复非破坏）。
- **⚠️ 测试基建影响（Oracle 条件 4）**：
  - `MenuManagerTests.CreateManager()` helper 须更新——增 `IOptions<NavigationOptions>` 构造参数（`Options.Create(new NavigationOptions())`）；
  - `NavigationExtensionInitializerTests` DI 容器须注册 `AddOptions<NavigationOptions>()`（或 `Configure<NavigationOptions>`）使 `IMenuManager` 可解析；
  - 既有 20 测试"适配构造变更后保持绿"（非"零改动保持绿"——初稿表述修正）。

## 六、风险与缓解
