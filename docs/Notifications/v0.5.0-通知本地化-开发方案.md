# Notifications - 开发方案（v0.5.0-通知本地化）

## 一、本版目标

- **核心交付**：对接主框架 ADR31 i18n 基础设施（v4.10.33 落地），本地化 `NotificationDefinition.DisplayName` 与严重级别文案——兑现 v0.1.0 承诺（指南 L457-459，拖 v0.2.0/v0.3.0/v0.4.0 顺延，跟踪 §五 #3；触发条件 = ADR31 实施，已于 2026-09-22 满足）。
- **完成定义（DoD）**：
  1. `NotificationDefinition` 支持 `DisplayNameKey`（加性，未设置零行为变化）；
  2. `NotificationPublisher` 发布时经 `IFrameworkLocalizer?` 解析本地化显示名快照（未注册/未命中回退原始文本，零破坏）；
  3. `NotificationSeverity` 本地化显示名扩展方法（`GetDisplayName`，未注册回退英文枚举名）；
  4. 专项测试（`CultureSwitcher` 作用域夹具）覆盖中英两文化 + InvariantCulture 默认；全量回归绿。

## 二、范围

### 包含

- `NotificationDefinition` 增加 `DisplayNameKey` 属性 + 构造重载（加性，不破坏现有 `(name, displayName, severity)` 构造）；
- `NotificationPublisher.PublishAsync` 显示名快照本地化解析（构造可空注入 `IFrameworkLocalizer?`，`IServiceProvider` 延迟可空解析——对齐 `IPermissionChecker` 先例，不增加构造参数依赖）；
- `NotificationSeverity` 扩展方法 `GetDisplayName(IFrameworkLocalizer?)`——key 约定 `Notifications/Severity_{Value}`（如 `Notifications/Severity_Warning`）；
- 专项 i18n 测试基线（`InvariantCulture` 默认 + zh-CN 专项）。

### 不包含

- `NotificationEntity` 存储模型变更（DisplayName 保持发布快照文本，不存 key——收件人 culture 差异化解析记录为远期候选，见 §五 D5）；
- 显示名参数化（`DisplayNameKey` + args，如"订单 {orderNo} 已发货"）——`NotificationData` 键值对 payload 已可承载参数，显示名参数化记录远期候选；
- 消费方/UI 层本地化（扩展不接管业务 UI 渲染——对齐 ADR31 不适用边界"业务文本业务自建"）；
- `ILocalizableString` 值对象引入（主框架无此类型，ADR31 走 IFrameworkLocalizer key 模式，不复制 ABP 类型）。

## 五、技术方案

### 设计决策（D1-D6，评审焦点）

#### D1：DisplayName 本地化路径——`DisplayNameKey` 加性属性（推荐）

不引入 `ILocalizableString` 值对象（主框架无此类型；ADR31 决策 3 明确走 `IFrameworkLocalizer` key 模式）。`NotificationDefinition` 增加加性 `DisplayNameKey`（可空 string）：

```csharp
public sealed class NotificationDefinition
{
    // 既有构造不变（零破坏）
    public NotificationDefinition(string name, string displayName,
        NotificationSeverity severity = NotificationSeverity.Info) { ... }

    // 新增构造（加性）——本地化 key 挂接
    public NotificationDefinition(string name, string displayName, string? displayNameKey,
        NotificationSeverity severity = NotificationSeverity.Info) { ... }

    /// <summary>本地化显示名 key（null = 原样使用 DisplayName 文本，零变化）。</summary>
    public string? DisplayNameKey { get; }
}
```

**key 命名约定（Oracle C3）**：`DisplayNameKey` 约定为 `Notifications/Definition_{Name}`（如 `Notifications/Definition_OrderShipped`）——与 D4 的 `Notifications/Severity_{Value}` 风格一致，命名空间化防冲突；**必须在使用指南文档化**（消费方贡献者须知道 key 约定才能贡献译文，文档缺失 = 本地化不可用）。

**理由**：公示的 `DisplayName`（string）与 `DisplayNameKey`（可空）并存——消费方设置 key 即获本地化，未设置完全等价现状（加性哲学对齐 ADR31 决策 4"加性 MessageKey"先例）。否决"直接把 DisplayName 当 key"替代（消费方未启用本地化时 DB 落库 key 字符串而非可读文本；展示文本撞名风险；既有注册代码语义突变需全量迁移）。

#### D2：解析时机——发布时快照（快照模型不变）

`NotificationEntity.DisplayName` 现状是**发布时快照**（DB 列）。本迭代保持快照模型：`Publisher.PublishAsync` 在构造实体时解析——发布方/服务器当前 culture 下的本地化文本落快照。

- 消费方未启用本地化（未调 `AddFrameworkLocalization()`）→ `IFrameworkLocalizer` 不可解析 → 回退 `definition.DisplayName` 原文（**零行为变化**）；
- 消费方启用且贡献了 key → 发布时按当前请求 culture 解析快照。

**权衡记录**：站内通知"收件人各按自己 culture 读取"需存 key 而非文本（DB 结构变更 + 破坏历史快照 + DTO 改造），收益低于风险，**记录为远期候选**（ABP 亦发布时解析）。

#### D3：IFrameworkLocalizer 解析方式——延迟可空解析（不增加构造参数依赖）

`NotificationPublisher` 构造参数**不新增** `IFrameworkLocalizer`（避免消费方不装 i18n 时构造断裂——对齐 `IPermissionChecker`/`IPermissionBatchChecker` 经 `IServiceProvider.GetService` 延迟解析先例）：

```csharp
// PublishAsync 内部
var resolvedDisplayName = ResolveLocalizedDisplayName(definition);
// → _serviceProvider.GetService<IFrameworkLocalizer>() 查询：
//    null → definition.DisplayName（零变化）
//    非 null → localizer[definition.DisplayNameKey] 命中 → 返回值；未命中（=key 本身）→ definition.DisplayName
```

**关键语义（Oracle C1 修订）**：`IFrameworkLocalizer` 未命中返回 **key 本身**——必须显式判断才回退原文，否则 key 会误作显示名落库。判断须含**空串防御**（贡献者/resx 配空值或占位符未填时，空串 ≠ key 会被误判"命中"落库空串）：

```csharp
var resolved = localizer?[displayNameKey];
var snapshot = string.IsNullOrWhiteSpace(resolved) || resolved == displayNameKey
    ? definition.DisplayName
    : resolved;
```

#### D4：严重级别文案——`GetDisplayName` 扩展方法 + key 约定

`NotificationSeverity` 是纯枚举（扩展不建 resx——避免与框架 FrameworkResources 重复；ACR31 不适用边界"业务文本业务自建"，但严重级别显示名消费方前端已有 enum→文案映射惯例）。提供静态扩展方法：

```csharp
public static class NotificationSeverityExtensions
{
    /// <summary>本地化显示名：localizer 命中返回译文；null/未命中/空串回退英文枚举名（Info/Success/Warning/Error）。</summary>
    public static string GetDisplayName(this NotificationSeverity severity, IFrameworkLocalizer? localizer)
    {
        if (localizer == null) return severity.ToString();
        var key = $"Notifications/Severity_{severity}";
        var resolved = localizer[key];
        return string.IsNullOrWhiteSpace(resolved) || resolved == key ? severity.ToString() : resolved;
    }
}
```

**理由**：
- key 前缀 `Notifications/` 命名空间化，避免与框架 `Enum_*`/`Validation_*` key 冲突（**Oracle C3：key 约定必须在使用指南文档化**，消费方贡献者才可配置译文）；
- 消费方如需中文：`AddFrameworkLocalization(o => o.Contributors.Add(业务贡献者))` 贡献 `Notifications/Severity_Warning → "警告"`；
- 未启用本地化/未贡献 → 英文枚举名（既有行为，客户端 enum→文案映射约定不变）；
- **resx 演进路径（Oracle S2）**：本迭代不自建 resx（Severity 仅 4 值，枚举名即英文，收益低）；扩展未来若有枚举名无法覆盖的复杂文案（通知模板默认内容等）→ 引入 `NotificationsResources.resx`（en + zh-CN 卫星，对齐框架 FrameworkResources 先例）——记录于使用指南。

#### D5：收件人 culture 差异——本迭代不做（记录远期）

发布时快照按发布方 culture（服务器当前请求 culture）。收件人各自语言读取需存 key + 读取路径解析（DB 结构变更），列为远期候选。**本迭代明确边界**：通知内容/显示名为发布时语言快照——与邮件发送（发布时语言）语义一致。

**远期演进路径（Oracle S1 记录）**：存 key + 收件人 culture 读取 = `NotificationEntity` 增 `DisplayNameKey` 列（nullable）+ 读取路径（QueryService/DTO 投影）经 `IFrameworkLocalizer` 按读者 culture 动态解析。触发场景：多语言租户/后台 job 批量发布后收件人语言差异成为实际痛点时再审。**注意**：后台 job 发布（非 HTTP 上下文）时 `CultureAccessor` 取 default culture——快照为默认语言，需在使用指南明确标注此行为（Oracle 风险补充 1）。

#### D6：测试基线——CultureSwitcher 作用域（对齐主框架先例）

- 现有测试默认 `InvariantCulture`（英文）——零断言依赖文化，无 flaky；
- 专项本地化测试用 `CultureSwitcher` 作用域夹具（对齐主框架 `_Tests/Domain.Core.Tests/EnumHelperLocalizationTests.cs` 先例）；
- 测试宿主注册**模拟 `IFrameworkLocalizer`**（内存字典，命中返回译文；未命中返回 key 本身——模拟 ADR31 契约）——覆盖**四条路径**（Oracle C2）：
  1. **命中**：字典含 key → 返回译文；
  2. **未命中**：字典无 key → 返回 key 本身 → 回退原始 DisplayName；
  3. **null**：localizer 未注册（Host 无模拟）→ 零行为变化；
  4. **空串**（C1 修订回归）：字典返回空串 → `IsNullOrWhiteSpace` 防御生效 → 回退原始 DisplayName（**Oracle C2 必须补充**）；
  5. **非 HTTP 上下文**（Oracle S3 建议）：模拟后台 job 发布（无请求 culture，Culture=default）→ 快照回退行为验证。

### 核心流程

```
PublishAsync(notificationName, ...)
  → definition = _definitionManager.Get(name)
  → resolvedDisplayName = localizer(可选)?[definition.DisplayNameKey]（命中）: definition.DisplayName
  → NotificationEntity { DisplayName = resolvedDisplayName, ... }   ← 快照语义不变
```

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| `IFrameworkLocalizer` 未注册时 Publisher 解析裂缝（构造依赖） | 消费方零 i18n 环境构造崩 | 延迟可空解析（`IServiceProvider.GetService`），未注册回退零变化 |
| localizer 未命中返回 key 本身误落库 | 显示名变 key 脏数据 | 显式判 `resolved == key` 才回退（§五 D3，专项测试 R3 锁） |
| **C1** localizer 返回空串误判命中 | 显示名空串落库 | `string.IsNullOrWhiteSpace(resolved)` 防御（§五 D3，测试 R3.1 锁） |
| **风险1** 后台 job 发布 culture 漂移 | 快照落默认语言，消费方困惑 | 使用指南明确标注"发布时快照 = 发布上下文 culture；后台 job = 默认语言" |
| 测试文化敏感 flaky | 全量回归不稳 | 默认 InvariantCulture 断言 + CultureSwitcher 作用域隔离（对齐主框架先例） |
| 扩展传递引用 Abstractions 在 NuGet 模式失效 | 编译断裂 | 已确认 TKWF.Domain→Abstractions 引用链；slnx 构建 + NuGet 模式验证双覆盖 |
