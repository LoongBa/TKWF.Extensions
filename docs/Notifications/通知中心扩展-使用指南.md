# 通知中心扩展-使用指南

> **扩展**：`TKWF.Ext.Notifications`（通知中心）· **版本**：v0.3.0
> **概念名**：通知中心（Notifications）——站内通知收件箱 + 订阅 + 事件驱动通知 + 多通道路由（V0.2.0 UseChannels/Email）+ **用户偏好路由 + 逐用户权限门控（V0.3.0）**
> **技术规范**：见 [_Framework/Notifications/README.md](../../_Framework/Notifications/README.md)

---

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\Notifications\TKWF.Ext.Notifications.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

```csharp
using TKWF.Ext.Notifications;

[TKWFEnabledExtension(typeof(NotificationsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册（TryAdd 语义，消费方可覆盖）：
- `INotificationPublisher`（Scoped）——发布通知（显式收件人/订阅者派发）
- `INotificationStore`（Scoped）——收件箱查询 + 已读管理
- `INotificationDefinitionManager`（Singleton）——通知定义注册/校验
- `INotificationNotifier`（可选——多实例收集，V0.2.0）——通道投递（Inbox + Email）
- `INotificationPreferenceManager`（Scoped，V0.3.0）——用户通道偏好管理（Get/Set/Clear/批量预取）
- `IUserEmailProvider`（**不注册**，消费方实现/注册）——Email 通道收件地址来源

> **V0.3.0 权限门控前置**：定义 `RequirePermission(...)` 启用**逐用户权限门控**时，消费方须启用 **Permissions v0.9.0+**（注册 `IPermissionBatchChecker`）；未注册 → 门控跳过 + 日志 Warning（降级为仅发布方门控 C1）。

### 3. 注册通知定义

```csharp
// 通知定义贡献者——集中注册业务通知
public class MyNotificationDefinitions : INotificationDefinitionProvider
{
    public void Define(INotificationDefinitionContext context)
    {
context.Add(new NotificationDefinition(
            "OrderShipped",                     // 稳定唯一名
            "订单已发货",                        // 显示名
            Severity: NotificationSeverity.Info)
            .RequirePermission("App.Orders.View")   // 可选：权限门控
            .UseChannels("Inbox", "Email"));        // 可选：多通道路由（v0.2.0；默认 ["Inbox"]，按顺序去重）
    }
}
```

### 4. 发布通知

```csharp
public class OrderService(INotificationPublisher publisher)
{
    public async Task ShipAsync(long orderId)
    {
        // 业务逻辑...

        // 显式收件人（null = 按订阅者派发）
        await publisher.PublishAsync(
            "OrderShipped",
            data: new NotificationData(new Dictionary<string, object?>
            {
                ["OrderId"] = orderId,
                ["TrackingNo"] = "SF1234567890"
            }),
            severity: NotificationSeverity.Info,
            userIds: new long[] { buyerId });   // null=订阅者 / []=空操作 / [x,y]=显式
    }
}
```

### 5. 查询收件箱

```csharp
public class NotificationController(INotificationStore store)
{
    // 未读通知
    public async Task<IReadOnlyList<UserNotificationEntity>> Unread(long userId)
        => await store.GetUnreadAsync(userId);

    // 全部通知（分页）
    public async Task<IReadOnlyList<UserNotificationEntity>> List(long userId, int page, int pageSize)
        => await store.GetListAsync(userId, page, pageSize);

    // 标记已读
    public async Task MarkRead(long userId, long notificationId)
        => await store.MarkReadAsync(userId, notificationId);

    // 全部已读
    public async Task MarkAllRead(long userId)
        => await store.MarkAllReadAsync(userId);
}
```

## 二、核心概念

### 数据模型三层

| 实体 | 表名 | 职责 |
|------|------|------|
| `NotificationEntity` | `Notification` | 发布态——通知内容/严重级别/实体关联（一份通知一次写入） |
| `UserNotificationEntity` | `UserNotification` | 收件箱行——每收件人一行（UserId + NotificationId + 已读状态） |
| `NotificationSubscriptionEntity` | `NotificationSubscription` | 订阅关系——用户按通知名订阅（可选实体级） |

### 派发语义（PublishAsync）

```
userIds = null   → 从订阅者解析收件人（NotificationSubscription）
userIds = []     → 空操作（直接返回）
userIds = [x,y]  → 显式指定收件人
```

- 重复 ID 自动去重
- 每个收件人写一行 `UserNotificationEntity`（inbox 行）
- 收件人受通知定义权限门控（不满足则跳过）

### 事件驱动通知（v0.1.0）

通知扩展是**事件总线的高层组合**（D15 §5.7）——业务代码发布领域事件，通知扩展消费并生成通知：

```csharp
// 业务侧：定义领域事件（可跨进程 → [DistributedEvent]）
[DistributedEvent]
public record OrderCreatedEvent(long OrderId, long BuyerId, string OrderNo);

// 通知扩展侧：消费事件 → 生成通知
[DomainEventHandler]
public class OrderNotificationHandler(INotificationPublisher publisher)
    : ILocalEventHandler<OrderCreatedEvent>   // 本地（同进程）用 ILocalEventHandler
{
    public async Task HandleEventAsync(OrderCreatedEvent eventData)
    {
        await publisher.PublishAsync("OrderCreated", ...);
    }
}
```

> **注意**：通知涉及外部 I/O（发邮件/推送）时，事件应标记 `[DistributedEvent]` 走 Outbox 异步持久化，handler 实现 `IDistributedEventHandler<T>`。v0.1.0 的 inbox-only 通道无外部 I/O，用 `ILocalEventHandler<T>` 即可。

### 通道抽象与多通道路由（INotificationNotifier，v0.2.0）

```csharp
public interface INotificationNotifier
{
    string Name { get; }   // 通道名（"Inbox"/"Email"/"SignalR"）
    Task DeliverAsync(NotificationDeliveryRequest request, CancellationToken ct = default);
}
```

- **多通道路由**：通知定义 `UseChannels(...)` 声明通道，发布时逐通道匹配 `notifier.Name == channel` 投递（未声明通道自然跳过）
- **内置通知器**：`InboxNotifier`（写收件箱，参与发布事务）+ `EmailNotifier`（Email 通道，best-effort）
- **外部通道 best-effort**：Email 投递失败不重抛、阻塞发布流程；Inbox 仍保证 C4 原子性
- 通道可独立实现、按需注册，核心不感知具体通道

#### Email 通道接线（v0.2.0 先例）

```csharp
// ① 消费方实现 IUserEmailProvider（从用户存储查邮箱）并注册
public class MyUserEmailProvider(IUserManager users) : IUserEmailProvider
{
    public async Task<string?> GetEmailAsync(long userId, CancellationToken ct = default)
        => (await users.FindByIdAsync(userId))?.Email;   // 无邮箱返回 null → Email 通道跳过
}

// ② 启用 Emailing 扩展（注册 IEmailSender）——消费方 DomainHostInitializer 白名单追加：
[TKWFEnabledExtension(typeof(EmailingExtensionInitializer<>))]   // 前提：启用 Emailing 扩展注入 IEmailSender
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }

// ③ 通知定义声明 Email 通道（见上文 .UseChannels("Inbox", "Email")）
```

> **IUserEmailProvider 扩展不注册**——须消费方注册（TryAdd 语义，扩展内不覆盖）。
> **任一前置缺失**（Emailing 未启用 / IUserEmailProvider 未实现 / 用户无邮箱）→ `EmailNotifier` LogWarning 跳过，不影响收件箱投递。

### 用户偏好路由（INotificationPreferenceManager，v0.3.0）

用户可为特定通知选择接收通道（**覆盖定义级 `UseChannels`**）：

| 偏好 | 发布时行为 |
|------|-----------|
| 无偏好（无记录） | 回退定义级 `UseChannels`（零迁移） |
| `["Email"]` | 仅投递 Email（排除 Inbox——用户主动降噪，不产生收件箱行） |
| `[]`（空列表） | **不接收该通知**（显式退出——订阅者也不在收件箱出现） |
| 损坏 JSON | 回退定义级（容错） |

```csharp
public class PreferenceService(INotificationPreferenceManager prefManager)
{
    // 设置偏好：订单通知只收 Email
    public async Task SetOrderPref(long userId)
        => await prefManager.SetAsync(userId, "OrderShipped", new[] { "Email" });

    // 查询偏好（无偏好返回 null）
    public async Task<IReadOnlyList<string>?> Get(long userId, string name)
        => await prefManager.GetChannelsAsync(userId, name);

    // 清除偏好（回退定义级）
    public async Task Clear(long userId, string name)
        => await prefManager.ClearAsync(userId, name);
}
```

> **批量预取**（Oracle P2-1）：发布时收件人解析后、事务前一次 `GetChannelsBatchAsync` 预取全部收件人偏好，避免事务内 N 次往返。

### 逐用户权限门控（v0.3.0，委托 Permissions）

通知定义 `RequirePermission(...)` 升级为**收件人级权限过滤**——发布时仅向有权限查看该通知的收件人投递：

```csharp
context.Add(new NotificationDefinition("OrderShipped", "订单已发货")
    .RequirePermission("App.Orders.View")      // 发布方门控（C1）+ 收件人级过滤（V0.3.0）
    .UseChannels("Inbox", "Email"));
```

- **门控逻辑完全委托 Permissions v0.9.0 `IPermissionBatchChecker`**——Admin.All 放行 / fail-closed / 用户→角色回退由 Permissions `PermissionChecker` 内部统一处理，Notifications 零权限实现（安全逻辑单一真相源）。
- **顺序**：先权限过滤（无权限用户不发，无论偏好）→ 再偏好覆盖（有权限用户按偏好收）。
- **依赖**：`TKWF.Ext.Permissions.Abstractions`（ADR48 D7，不引实现项目）；消费方启用 Permissions 扩展后自动生效。
- **降级**：`IPermissionBatchChecker` 未注册（Permissions 未启用）→ 跳过收件人门控 + Warning（降级为仅发布方门控 C1）。

## 三、进阶用法

### 1. 订阅/退订

```csharp
public class PreferenceService(INotificationSubscriptionManager subManager)
{
    // 订阅通知（定义级：关注所有该通知）
    public async Task Subscribe(long userId, string notificationName)
        => await subManager.SubscribeAsync(userId, notificationName);

    // 订阅实体级（只关注某个具体实体）
    public async Task SubscribeEntity(long userId, string notificationName, string entityType, string entityId)
        => await subManager.SubscribeAsync(userId, notificationName, entityType, entityId);

    // 退订
    public async Task Unsubscribe(long userId, string notificationName)
        => await subManager.UnsubscribeAsync(userId, notificationName);
}
```

```csharp
var unreadCount = await store.GetUnreadCountAsync(userId);
```

## 四、与 Emailing 的关系（v0.2.0 Email 通道）

| 项 | Emailing | Notifications（v0.2.0 Email 通道） |
|----|----------|-----------------------------------|
| 职责 | 邮件发送引擎（SMTP/MailKit + 记录） | 通知编排（收件箱 + 订阅 + 通道路由） |
| 依赖 | 无 | 经 `TKWF.Ext.Emailing.Abstractions` 引用 `IEmailSender`（ADR48 D7）；`IUserEmailProvider` 消费方实现 |
| 模板 | V0.2.0 规划（TextTemplates） | 复用 Emailing 能力，不重复实现 |

**依赖倒置**：Notifications 不直接引用 Emailing 实现项目，通过 `TKWF.Ext.Emailing.Abstractions`（抽取的接口契约）依赖倒置，符合 ADR48 D7 + L2 门控（TKWF0022）。

**Email 通道启用前提**：① 消费方实现并注册 `IUserEmailProvider`；② 启用 Emailing 扩展（注册 `IEmailSender`）。两者齐备且定义 `UseChannels` 含 `"Email"` 才实际发送；任一缺失 → LogWarning 跳过（best-effort，不阻塞收件箱写入）。

## 五、配置选项

通过 `appsettings.json` 配置（`TKWF:Notifications` 节）：

```json
{
  "TKWF": {
    "Notifications": {
      "DirectDistributionUserThreshold": 50,
      "RecipientBatchSize": 256
    }
  }
}
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `DirectDistributionUserThreshold` | 50 | 显式收件人 ≤ 此值内联分发，超过转后台批量 |
| `RecipientBatchSize` | 256 | 订阅者派发批处理大小 |

## 六、常见问题

### Q: 通知和领域事件是什么关系？

通知是**事件总线的高层组合**（D15 §5.7）——业务代码发布领域事件（如 `OrderCreated`），通知扩展通过 `[DomainEventHandler]` 消费事件并生成通知。业务侧零耦合，不需要感知通知机制。

### Q: 为什么 v0.1.0 只有 Inbox 通道？

v0.1.0 聚焦站内通知核心（发布/收件箱/订阅/事件驱动）。Email 通道依赖 Emailing.Abstractions 拆分，于 **v0.2.0 已实施**（`EmailNotifier` + `UseChannels`）；SignalR 通道需要 AspNetCore.SignalR 依赖评估，仍在远期规划。

### Q: 如何启用 Email 通道？

三步：① 消费方实现 `IUserEmailProvider`（查邮箱）并注册；② 启用 Emailing 扩展（`IEmailSender` 注册）；③ 通知定义 `.UseChannels("Inbox", "Email")`。任一前置缺失会 LogWarning 跳过发送，不影响收件箱写入。

### Q: 如何给特定用户发通知而不需要他订阅？

用 `PublishAsync(name, data, severity, userIds: new[] { userId })` 显式指定收件人，跳过订阅解析。

### Q: 用户如何只收 Email 不收收件箱（降噪）？

v0.3.0 起用 `INotificationPreferenceManager.SetAsync(userId, notificationName, ["Email"])` 设置偏好——发布时该用户的通道被偏好覆盖（排除 Inbox，不产生收件箱行）。空列表 `[]` = 完全不接收该通知；`ClearAsync` 回退定义级。

### Q: 通知定义 `RequirePermission` 后收件人都会校验权限吗？

是（v0.3.0 起）。发布方（C1）+ 逐收件人（V0.3.0）都校验：仅向有权限收件人投递。校验完全委托 Permissions v0.9.0 `IPermissionBatchChecker`（Admin.All/角色回退/fail-closed 归 Permissions）。若消费方未启用 Permissions（batch checker 未注册）→ 门控跳过 + Warning（降级仅发布方门控）。

### Q: 通知内容支持多语言吗？

v0.1.0 通知名称是稳定标识符，Data 是键值对 payload。显示文本的本地化（`ILocalizableString`）规划到 v0.2.0，与主框架本地化（D16/ADR31）对接。

## 七、V0.2.0 生产部署要求：DBA 建视图

V0.2.0 起，`GetListAsync(name)`（按通知名过滤收件箱）改用 **VEntity**（`vw_UserNotificationView`，JOIN `UserNotification` → `Notification` 单查询下推 DB）。

- **开发环境**：框架 `SyncViewsAsync` 自动执行 ViewSql 建视图（仅 IsDevelopment）
- **生产环境**：**框架不自动建视图**——需 **DBA 手动执行以下 ViewSql**（按目标库方言调整）：

```sql
-- PostgreSQL
CREATE OR REPLACE VIEW "vw_UserNotificationView" AS
SELECT un."Id", un."UserId", un."NotificationId", un."State", un."ReadTime", un."CreateTime",
       n."Name", n."Severity", n."DisplayName"
FROM "UserNotification" un
INNER JOIN "Notification" n ON un."NotificationId" = n."Id";
```

> SQL Server / MySQL / Oracle 生产库需按对应方言书写（或扩展补 `ViewSqlSqlServer` 等变体后由开发环境 SyncViewsAsync 生成参考 DDL）。
