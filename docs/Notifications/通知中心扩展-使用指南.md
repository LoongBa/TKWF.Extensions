# 通知中心扩展-使用指南

> **扩展**：`TKWF.Ext.Notifications`（通知中心）· **版本**：v0.1.0
> **概念名**：通知中心（Notifications）——站内通知收件箱 + 订阅 + 事件驱动通知 + 多通道抽象
> **技术规范**：见 [_Framework/Notifications/README.md](../../_Framework/Notifications/README.md)

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\Notifications\TKWF.Ext.Notifications.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

```csharp
using TKWF.Ext.Notifications;

[TKWFEnabledExtension(typeof(NotificationsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册（TryAdd 语义，消费方可覆盖）：
- `INotificationPublisher`（Scoped）——发布通知（显式收件人/订阅者派发）
- `INotificationStore`（Scoped）——收件箱查询 + 已读管理
- `INotificationDefinitionManager`（Singleton）——通知定义注册/校验
- `INotificationNotifier`（可选）——通道投递（v0.1.0 仅 inbox-only）

### 3. 注册通知定义

```csharp
// 通知定义贡献者——集中注册业务通知
public class MyNotificationDefinitions : INotificationDefinitionProvider
{
    public void Define(INotificationDefinitionContext context)
    {
        context.Add(new NotificationDefinition(
            "OrderShipped",                     // 稳定唯一名
            "订单已发货",                        // 显示名
            Severity: NotificationSeverity.Info)
            .RequirePermission("App.Orders.View")   // 可选：权限门控
            .UseChannels("Inbox"));                  // 可选：通道（v0.1.0 仅 Inbox）
    }
}
```

### 4. 发布通知

```csharp
public class OrderService(INotificationPublisher publisher)
{
    public async Task ShipAsync(long orderId)
    {
        // 业务逻辑...

        // 显式收件人（null = 按订阅者派发）
        await publisher.PublishAsync(
            "OrderShipped",
            data: new NotificationData(new Dictionary<string, object?>
            {
                ["OrderId"] = orderId,
                ["TrackingNo"] = "SF1234567890"
            }),
            severity: NotificationSeverity.Info,
            userIds: new long[] { buyerId });   // null=订阅者 / []=空操作 / [x,y]=显式
    }
}
```

### 5. 查询收件箱

```csharp
public class NotificationController(INotificationStore store)
{
    // 未读通知
    public async Task<IReadOnlyList<UserNotificationEntity>> Unread(long userId)
        => await store.GetUnreadAsync(userId);

    // 全部通知（分页）
    public async Task<IReadOnlyList<UserNotificationEntity>> List(long userId, int page, int pageSize)
        => await store.GetListAsync(userId, page, pageSize);

    // 标记已读
    public async Task MarkRead(long userId, long notificationId)
        => await store.MarkReadAsync(userId, notificationId);

    // 全部已读
    public async Task MarkAllRead(long userId)
        => await store.MarkAllReadAsync(userId);
}
```

## 二、核心概念

### 数据模型三层

| 实体 | 表名 | 职责 |
|------|------|------|
| `NotificationEntity` | `Notification` | 发布态——通知内容/严重级别/实体关联（一份通知一次写入） |
| `UserNotificationEntity` | `UserNotification` | 收件箱行——每收件人一行（UserId + NotificationId + 已读状态） |
| `NotificationSubscriptionEntity` | `NotificationSubscription` | 订阅关系——用户按通知名订阅（可选实体级） |

### 派发语义（PublishAsync）

```
userIds = null   → 从订阅者解析收件人（NotificationSubscription）
userIds = []     → 空操作（直接返回）
userIds = [x,y]  → 显式指定收件人
```

- 重复 ID 自动去重
- 每个收件人写一行 `UserNotificationEntity`（inbox 行）
- 收件人受通知定义权限门控（不满足则跳过）

### 事件驱动通知（v0.1.0）

通知扩展是**事件总线的高层组合**（D15 §5.7）——业务代码发布领域事件，通知扩展消费并生成通知：

```csharp
// 业务侧：定义领域事件（可跨进程 → [DistributedEvent]）
[DistributedEvent]
public record OrderCreatedEvent(long OrderId, long BuyerId, string OrderNo);

// 通知扩展侧：消费事件 → 生成通知
[DomainEventHandler]
public class OrderNotificationHandler(INotificationPublisher publisher)
    : ILocalEventHandler<OrderCreatedEvent>   // 本地（同进程）用 ILocalEventHandler
{
    public async Task HandleEventAsync(OrderCreatedEvent eventData)
    {
        await publisher.PublishAsync("OrderCreated", ...);
    }
}
```

> **注意**：通知涉及外部 I/O（发邮件/推送）时，事件应标记 `[DistributedEvent]` 走 Outbox 异步持久化，handler 实现 `IDistributedEventHandler<T>`。v0.1.0 的 inbox-only 通道无外部 I/O，用 `ILocalEventHandler<T>` 即可。

### 通道抽象（INotificationNotifier）

```csharp
public interface INotificationNotifier
{
    string Name { get; }   // 通道名（"Inbox"/"Email"/"SignalR"）
    Task DeliverAsync(NotificationDeliveryRequest request, CancellationToken ct = default);
}
```

- v0.1.0：内置 `InboxNotifier`（仅写收件箱，无外部投递）
- v0.2.0：Email 通道（对接 `TKWF.Ext.Emailing`）+ SignalR 通道（实时推送）
- 通道可独立实现、按需注册，核心不感知具体通道

## 三、进阶用法

### 1. 订阅/退订

```csharp
public class PreferenceService(INotificationSubscriptionManager subManager)
{
    // 订阅通知（定义级：关注所有该通知）
    public async Task Subscribe(long userId, string notificationName)
        => await subManager.SubscribeAsync(userId, notificationName);

    // 订阅实体级（只关注某个具体实体）
    public async Task SubscribeEntity(long userId, string notificationName, string entityType, string entityId)
        => await subManager.SubscribeAsync(userId, notificationName, entityType, entityId);

    // 退订
    public async Task Unsubscribe(long userId, string notificationName)
        => await subManager.UnsubscribeAsync(userId, notificationName);
}
```

### 2. 未读计数

```csharp
var unreadCount = await store.GetUnreadCountAsync(userId);
```

### 3. 按通知名过滤

```csharp
var shipped = await store.GetListAsync(userId, page, pageSize, "OrderShipped");
```

## 四、与 Emailing 的关系（v0.2.0 通道）

| 项 | Emailing | Notifications（v0.2.0 Email 通道） |
|----|----------|-----------------------------------|
| 职责 | 邮件发送引擎（SMTP/MailKit + 记录） | 通知编排（收件箱 + 订阅 + 通道路由） |
| 依赖 | 无 | 经 `TKWF.Ext.Emailing.Abstractions` 引用 `IEmailSender`（ADR48 D7） |
| 模板 | V0.2.0 规划（TextTemplates） | 复用 Emailing 能力，不重复实现 |

**依赖倒置**：Notifications 不直接引用 Emailing 实现项目，通过 `TKWF.Ext.Emailing.Abstractions`（抽取的接口契约）依赖倒置，符合 ADR48 D7 + L2 门控（TKWF0022）。

## 五、配置选项

通过 `appsettings.json` 配置（`TKWF:Notifications` 节）：

```json
{
  "TKWF": {
    "Notifications": {
      "DirectDistributionUserThreshold": 50,
      "RecipientBatchSize": 256
    }
  }
}
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `DirectDistributionUserThreshold` | 50 | 显式收件人 ≤ 此值内联分发，超过转后台批量 |
| `RecipientBatchSize` | 256 | 订阅者派发批处理大小 |

## 六、常见问题

### Q: 通知和领域事件是什么关系？

通知是**事件总线的高层组合**（D15 §5.7）——业务代码发布领域事件（如 `OrderCreated`），通知扩展通过 `[DomainEventHandler]` 消费事件并生成通知。业务侧零耦合，不需要感知通知机制。

### Q: 为什么 v0.1.0 只有 Inbox 通道？

v0.1.0 聚焦站内通知核心（发布/收件箱/订阅/事件驱动）。Email 通道依赖 Emailing.Abstractions 拆分，SignalR 通道需要 AspNetCore.SignalR 依赖评估——均规划到 v0.2.0。

### Q: 如何给特定用户发通知而不需要他订阅？

用 `PublishAsync(name, data, severity, userIds: new[] { userId })` 显式指定收件人，跳过订阅解析。

### Q: 通知内容支持多语言吗？

v0.1.0 通知名称是稳定标识符，Data 是键值对 payload。显示文本的本地化（`ILocalizableString`）规划到 v0.2.0，与主框架本地化（D16/ADR31）对接。
