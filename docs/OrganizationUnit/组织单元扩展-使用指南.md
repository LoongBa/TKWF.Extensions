# 组织单元扩展使用指南

> `TKWF.Ext.OrganizationUnit`——树形部门/团队/分组定义、维护与用户归属管理（对标 ABP OrganizationUnits）。
> 版本 v0.2.0｜设计依据 [ADR-OrganizationUnit-数据模型与树形设计](../../../_TKWF/docs/03_扩展模块/OrganizationUnit/ADR/ADR-OrganizationUnit-数据模型与树形设计.md)

---

## 1. 快速开始

### 1.1 引用

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\OrganizationUnit\TKWF.Ext.OrganizationUnit.csproj" />
```

### 1.2 启用（v4.9.85+ 白名单声明）

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

扩展被引用后 SG1 即发现，但**发现 ≠ 启用**——须在自身领域初始化器上声明：

```csharp
using TKWF.Ext.OrganizationUnit;

[TKWFEnabledExtension(typeof(OrganizationUnitExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

### 1.3 注入使用

```csharp
public class OrgService(IOrganizationUnitManager orgManager)
{
    public async Task CreateCompanyAsync()
    {
        // 根组织
        var hq = await orgManager.CreateAsync("HQ", "集团总部", null);
        // 子组织
        var rd = await orgManager.CreateAsync("RND", "研发中心", hq.Id);
        await orgManager.CreateAsync("RD-BJ", "研发中心北京分部", rd.Id);
        // 分配用户（用户 Id 为 string，对齐 IUserInfo.UserIdString）
        await orgManager.AssignUserAsync(rd.Id, "user-001");
    }
}
```

## 2. 树维护

### 2.1 创建

```csharp
// 根节点：Level=0、Path="/Code/"
var root = await orgManager.CreateAsync("HQ", "集团总部", null);
// 子节点：Level=父+1、Path=父Path+Code+"/"；SortOrder 默认同级末尾
var rd = await orgManager.CreateAsync("RND", "研发中心", root.Id);
// 显式排序（同级 SortOrder 小值在前）
var x = await orgManager.CreateAsync("X", "X部门", root.Id, sortOrder: 10);
```

**Code 规则**：仅允许 `[A-Za-z0-9_.-]`（字母/数字/下划线/点/连字符），拒绝 `%`/空白（防 LIKE 通配符歧义）与纯点组合 `.`/`..`；**创建后不可修改**（Path 不变量）。Name 可含任意字符。

### 2.2 更新

```csharp
await orgManager.UpdateAsync(id, name: "新名称", isEnabled: false, sortOrder: 5);
// Code 不可改；仅更新非空字段
```

### 2.3 移动

```csharp
// 移动到指定父节点下（null = 设为根）
await orgManager.MoveAsync(id, newParentId);
await orgManager.MoveAsync(id, null);          // 设为根

// 移动特性：
// - 循环防护：移入自身或自身后代 → InvalidOperationException
// - 整棵子树 Level/Path 重算（BFS，含孙代）
// - 移动节点 SortOrder 追加到新父末尾（可随后 UpdateAsync 修正）
// - 事务原子：要么全旧要么全新，无半更新
```

### 2.4 删除

```csharp
// 删除保护：含子节点或关联用户 → InvalidOperationException（请先清空）
await orgManager.DeleteAsync(id);
```

**删除语义**：物理删除（软删字段不存在）——已删 Code 可复用；已删 OU 的引用守卫：向其建子/分配用户/查子树 → 拒绝。

### 2.5 查询

```csharp
// 全树（内存组装，同级 SortOrder 升序；孤儿节点抛异常提示数据异常）
var tree = await orgManager.GetTreeAsync();
// tree.Children 递归；TreeNode 含 Id/Code/Name/SortOrder/IsEnabled/Children

// 子树（含自身 + 全部子孙）——V0.2.0 SQL 下推（物化路径精确前缀比较，非全量拉取内存过滤）
var subTree = await orgManager.GetSubTreeAsync(rd.Id);
// 祖先链（根 → 直接父，不含自身；面包屑）——V0.2.0 SQL 下推（Code IN 单查询；缺失段抛异常）
var ancestors = await orgManager.GetAncestorsAsync(rd.Id);
```

## 3. VEntity 化/下推（V0.2.0）

V0.2.0 起，三处读路径由"全量快照 + 内存过滤"改为 **SQL 下推**（接口签名不变，消费方零迁移）：

| 读路径 | V0.1.x（内存） | V0.2.0（SQL 下推） |
|--------|---------------|-------------------|
| `GetSubTreeAsync(id)` | `GetAllAsync` + 内存 `Path.StartsWith` | 单表 `WHERE` 物化路径**精确前缀**比较（非 LIKE——P3 实证 FreeSql `StartsWith`→SQLite `instr`、PG 可能 `LIKE`，`_` 通配符失配风险统一用 `substr`/`substring` 精确比较规避） |
| `GetAncestorsAsync(id)` | `GetAllAsync` + 内存逐段 `Path == prefix` | 单表 `WHERE Code IN (分段)` 单查询；**缺失段抛异常**（数据异常不静默） |
| `GetUserIdsInOrganizationUnitAsync(id, includeDescendants: true)` | 两步（子树 Id 集合 → junction） | **`vw_UserOrganizationUnitView` 视图单查询**（JOIN `OrganizationUnitUser` → `OrganizationUnit`，`WHERE OUPath` 精确前缀）→ 内存去重 |
| `GetUserIdsInOrganizationUnitAsync(id, includeDescendants: false)` | junction 单查 | **保留 junction 单查**（不触视图）——双模式（oracle3 C-5/M2） |

- **视图语义**：`vw_UserOrganizationUnitView` 为**敏感读模型**（用户-OU 归属关系）——`ExposeGraphqlQuery = false`，无 GraphQL/REST 直连，数据访问统一经 `IOrganizationUnitManager` 门面。
- **写路径零触碰**：Create/Move/Delete 完全不动（实体回写仍走 Manager 业务逻辑）。
- **ViewSql 生产要求**：框架 `SyncViewsAsync` 仅开发环境自动建视图；**生产需 DBA 手动执行 ViewSql**（PG 默认方言见 `UserOrganizationUnitView.ViewSql`，SQLite 方言见 `ViewSqlSQLite`）。

## 4. 用户关联

```csharp
// 分配用户（重复分配 → InvalidOperationException "该用户已在此组织单元"）
await orgManager.AssignUserAsync(rd.Id, "user-001");
// 解除（幂等：不存在静默成功）
await orgManager.UnassignUserAsync(rd.Id, "user-001");

// 双向查询
var usersInRd = await orgManager.GetUserIdsInOrganizationUnitAsync(rd.Id, includeDescendants: true);
//   → 研发中心及其全部子孙 OU 下的用户 Id（去重）；false = 仅直属
//   V0.2.0 双模式：true 走 vw_UserOrganizationUnitView 视图单查询（JOIN OU→OUUser + OUPath 精确前缀，
//   替代"子树 Id 集合 → junction"两步）；false 保留 junction 单查（仅本 OU，不触视图）
var orgsOfUser = await orgManager.GetOrganizationUnitIdsForUserAsync("user-001");
//   → 该用户所属的全部 OU Id
```

## 5. 生产注意事项

- **建表**：`OrganizationUnit` / `OrganizationUnitUser` 两表由框架 `SyncTables` 统一托管（V4.9.92 ADR49），**无手工 DDL 前置**。
- **视图（V0.2.0）**：`vw_UserOrganizationUnitView`（JOIN `OrganizationUnitUser` → `OrganizationUnit`）用于 `GetUserIdsInOrganizationUnitAsync(includeDescendants: true)` 单查询下推。框架 `SyncViewsAsync` **仅开发环境自动建视图**；**生产需 DBA 手动执行 ViewSql**（PG 默认方言，见 `UserOrganizationUnitView.ViewSql`；SQLite 方言见 `ViewSqlSQLite`）。视图为敏感读模型（用户-OU 归属关系），`ExposeGraphqlQuery = false`——无 GraphQL 直连，数据访问统一经 `IOrganizationUnitManager` 门面。
- **数据量边界**：树查询 `GetTreeAsync` 采用"全量快照 + 内存组装"策略（递归组装不适用 VEntity），适用于**百级 OU**（组织架构常规规模）；`GetSubTreeAsync`/`GetAncestorsAsync`/`GetUserIdsInOrganizationUnitAsync`（V0.2.0 起）已 SQL 下推，大数据量下仍保持单查询/谓词过滤。若 OU 超万级或需实时子树分页，请评估进一步优化。
- **并发写边界**：并发创建/移动交叠可能产生基于过期父快照的 Level/Path 偏差——组织架构为低频小数据量场景，依赖库级唯一约束 + 最后写入者生效，不保证读-改-写原子。并发重复分配用户会得到明确的业务异常。
- **UserId 类型**：string（对齐 `IUserInfo.UserIdString`），与 Identity 扩展的用户 Id 直接兼容。
- **多租户隔离**：v0.1.0 不内置租户过滤，多租户场景由消费方自行隔离。

## 6. 边界与语义速查

| 场景 | 行为 |
|------|------|
| 重复 Code 创建 | 库级唯一约束拒绝 |
| 移动到自己/后代之下 | `InvalidOperationException` |
| 删除含子节点的 OU | `InvalidOperationException`（提示子节点数） |
| 删除含关联用户的 OU | `InvalidOperationException`（提示关联数） |
| 删除空 OU | 成功（事务内清 junction + 物理删） |
| 删除后同 Code 再建 | 允许（物理删除释放唯一索引） |
| 向已删 OU 建子/分配用户/查子树 | 拒绝（引用守卫） |
| 重复分配同一用户 | `InvalidOperationException`（唯一约束转换） |
| Path 超过 1024 字符 | `InvalidOperationException`（层级过深/Code 过长） |
| 树中存在孤儿节点（父不存在） | `GetTreeAsync` 抛异常（数据异常提示） |
