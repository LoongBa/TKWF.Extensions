## 一、概述

TKWF 权限扩展（`TKWF.Ext.Permissions`）提供**细粒度权限管理**——权限定义（如 `"Order.Create"`）、运行时权限检查、方法级权限门（`[RequirePermission]`），与框架核心的 `AuthorityFilter`（角色检查）并存互补。

### 1.1 与 AuthorityFilter 的分工

| 机制 | 检查内容 | 属性 | 过滤器 | 归属 |
|:--|:--|:--|:--|:--|
| **AuthorityFilter** | 角色（`[RequireRole]`） | `RequireRoleFlagAttribute` | 框架核心 | 角色级授权 |
| **PermissionFilter** | 权限（`[RequirePermission("Order.Create")]`） | `RequirePermissionAttribute` | 扩展（Tier-S） | 权限级授权 |

两者独立工作可同时使用：用户可被分配角色（AuthorityFilter 检查）和权限（PermissionFilter 检查）。

### 1.2 核心概念

| 概念 | 说明 |
|:--|:--|
| 权限定义（PermissionDefinition） | 权限声明——`Name`（如 `"Order.Create"`）+ 显示名/分组/父权限 |
| 权限贡献者（IPermissionDefinitionContributor） | 业务模块声明权限定义的类，`[PermissionContributor]` 标记 |
| 权限检查器（IPermissionChecker） | 运行时判断当前用户是否拥有权限 |
| 权限存储（IPermissionStore） | 持久化角色/用户权限值（V4.9.72 提供 NoOp 默认实现，真实持久化需消费方实现） |
| 方法级权限门（[RequirePermission]） | 标记方法/接口，无权限时抛 `DomainException(FORBIDDEN)` |

> ⚠️ **默认实现说明（V4.9.72）**：默认 `IPermissionStore` 是 NoOp（读恒拒绝）——**真实启用权限需要消费方注册自定义 `IPermissionStore`**（数据库权限存储）。`IPermissionChecker`（默认 `PermissionChecker<TUserInfo>`）已接通用户上下文 + store 链路，是逻辑层默认实现。

## 二、快速入门

### 2.1 启用权限扩展

消费方引用 `TKWF.Ext.Permissions` 包。扩展经 `[TKWFExtension("Permissions")]` 被 SG1 自动发现，三钩子自动接线（V4.9.71 机制）——**无需手动注册**：

```csharp
// 消费方 .csproj
<ProjectReference Include="..\Framework\Permissions\TKWF.Ext.Permissions.csproj" />
```

扩展自动注册：`IPermissionChecker`（默认 `PermissionChecker<TUserInfo>`）+ `IPermissionStore`（默认 NoOp）+ `IPermissionDefinitionRepository` + `PermissionFilterAttribute`（Tier-S）。

### 2.2 声明权限定义（贡献者）

业务模块用 `[PermissionContributor]` 标记一个实现 `IPermissionDefinitionContributor` 的类：

```csharp
[PermissionContributor]
public class OrderPermissions : IPermissionDefinitionContributor
{
    public void Define(PermissionDefinitionContext context)
    {
        context.Add(new PermissionDefinition
        {
            Name = "Order.Create",       // 点分层级约定
            DisplayName = "创建订单",
            Group = "Order"
        });
        context.Add(new PermissionDefinition
        {
            Name = "Order.Delete",
            DisplayName = "删除订单",
            Group = "Order"
        });
    }
}
```

SG1 扫描 `[PermissionContributor]` → 生成 `GeneratedPermissionContributors` → 启动时扩展初始化器实例化贡献者、调用 `Define()` 收集定义（ConfigureServices 阶段，编译期清单无反射）。

### 2.3 方法级权限门

在服务接口方法或控制器接口上标记 `[RequirePermission]`：

```csharp
public interface IOrderService
{
    [RequirePermission("Order.Create")]
    Task CreateOrderAsync(CreateOrderInput input);

    // 多权限 + 任一逻辑（Any）：销售或管理员任一权限即可
    [RequirePermission("Order.Delete", "Order.ForceDelete", Logic = PermissionLogic.Any)]
    Task DeleteOrderAsync(long id);
}
```

无权限时抛 `DomainException`（`ErrorCode = FORBIDDEN`），客户端收到 `FORBIDDEN` 错误码。

### 2.4 真实启用权限（注册自定义 IPermissionStore）

默认 NoOp store 恒拒绝——注册你的权限存储后权限检查才真正生效：

```csharp
// DomainInitializer / ConfigureServices 中
services.AddSingleton<IPermissionStore, MyDbPermissionStore>();
```

`MyDbPermissionStore` 实现 `IPermissionStore`：

```csharp
public sealed class MyDbPermissionStore : IPermissionStore
{
    public Task<PermissionGrantResult> GetAsync(string permissionName, string providerName, string providerKey)
    {
        // providerName = "User"（当前用户），providerKey = UserIdString
        // 查库判断用户是否被授予该权限
        var granted = /* 查数据库 */;
        return Task.FromResult(granted ? PermissionGrantResult.Granted : PermissionGrantResult.Denied);
    }

    public Task SetAsync(string permissionName, string providerName, string providerKey, bool isGranted)
    {
        // 写入/移除权限授予（权限分配管理后台用）
        return Task.CompletedTask;
    }
}
```


### 2.5 SG1 声明式实体（V0.2.0）

`PermissionGrantEntity` 采用 SG1 声明式——`partial class` + `[DomainGenerateCode]`（不指定 UserType）：

```csharp
[Table("PermissionGrant")]
[DomainGenerateCode(DefaultPageSize = 50, SubDomain = "Permissions", SubDomainRoutePrefix = "/Permissions")]
public partial class PermissionGrantEntity
{
    [FreeSql.DataAnnotations.Column(IsPrimary = true, IsIdentity = true, Position = 1)]
    public long Id { get; set; }

    [FreeSql.DataAnnotations.Column(Position = 2)]
    [MaxLength(200)]
    public string PermissionName { get; set; } = "";

    // ... ProviderName, ProviderKey, IsGranted
}
```

- **不指定 UserType**：扩展不知道消费方 UserInfo 类型（ADR42 D4），DataService 用非泛型 `DomainDataServiceBase<TEntity,TDto>`。
- **FreeSql `[Column]` 全限定**：避免与 BCL `Schema.Column` 冲突。
- **`[Table]` 保留**：`FreeSqlTableStructureSynchronizer` 依赖 BCL `[Table]` 发现实体建表。
- **xCodeGen 配置**：`.xCodeGen/permissions.xCodeGen.json` 已配置 Entity/Dto/Conditions/DataService 模板。`.cs` 骨架（业务扩展点）入库；`.g.cs`（CRUD 逻辑）不入库，Debug 构建时经 `_XCG_Run` 自动重新生成。


### 2.6 权限管理 Service（V0.3.0 / V0.4.0）

V0.3.0 新增 `PermissionGrantEntityDataService`——继承 `DomainDataServiceBase<PermissionGrantEntity, PermissionGrantEntityDto>`，提供 DataService 级 CRUD + 自定义查询。DTO/DataService 为 **xCodeGen 生成**（`.g.cs` 承载标准 CRUD，`.cs` 骨架承载业务方法）；标记 `[GenerateController(FromDataService = true)]`，消费方 SG1 自动生成 REST 管理 API（subdomain `Permissions`）。

```csharp
// 注入 DataService（自动注册，无需手动配置）
public class PermissionAdminService
{
    private readonly PermissionGrantEntityDataService _dataService;
    public PermissionAdminService(PermissionGrantEntityDataService dataService)
        => _dataService = dataService;
}

// 设置权限授予（upsert）
await _dataService.SetGrantAsync("Order.Create", "User", "u-1001", isGranted: true);

// 查询权限授予
var grant = await _dataService.GetGrantAsync("Order.Create", "User", "u-1001");

// 按权限名查询所有授予
var grants = await _dataService.GetByPermissionNameAsync("Order.Create");

// 按 provider 查询
var userGrants = await _dataService.GetByProviderAsync("User", "u-1001");

// 撤销权限
await _dataService.RevokeGrantAsync("Order.Create", "User", "u-1001");
```

> ⚠️ DataService 自动注册为 Scoped（`TryAddScoped`），消费方可自定义覆盖。需先注册 `IEntityDAC<PermissionGrantEntity>`（调用 `UseFreeSqlEntityDAC()`）。

### 2.7 配置（PermissionOptions，V0.2.0 / V0.4.0）

权限扩展配置经 `[Options("TKWF:Permissions")]` 声明，SG1 `GeneratedOptionsBindings` 自动绑定：

```json
// appsettings.json
{
  "TKWF": {
    "Permissions": {
      "DefaultPolicy": "Authenticated",
      "CacheTtlSeconds": 600,
      "SeedAdminRoleName": "admin"
    }
  }
}
```

- `SeedAdminRoleName`（V0.4.0 G3 + V0.7.0 W3）：启动时**幂等预置**该角色的 <code>Admin.All</code> 系统权限（V0.7.0 起，替代 V0.4.0 的逐权限授予——Admin.All 拥有者对全部已定义权限放行，未来新增权限自动覆盖）；空字符串 = 禁用种子。需注册 `IEntityDAC<PermissionGrantEntity>` 才生效（NoOp 模式跳过）。

亦可在 `ConfigureServices` 中代码覆盖：

```csharp
services.Configure<PermissionOptions>(o =>
{
    o.DefaultPolicy = "RequireAdmin";
    o.CacheTtlSeconds = 300;
});
```

### 2.8 角色→权限映射（V0.6.0）

权限检查支持**用户+角色双重检查**：用户级显式授予优先；未授予时回退角色级判定（任一角色授予即通过）。

- **用户权限**：`("User", UserIdString)`——`IPermissionStore.SetAsync("Order.Create", "User", userId, true)`。
- **角色权限**：`("Role", roleName)`——`("Role", "admin")` 授予即该角色所有用户拥有。
- **角色来源**：`IRoleProvider<TUserInfo>`（默认 `DefaultRoleProvider<TUserInfo>` 从 `IUserInfo.Roles` 解析）。消费方可 DI 注册自定义实现覆盖（如从角色服务/缓存/外部身份提供商解析）：

```csharp
services.AddScoped<IRoleProvider<MyUserInfo>, MyRoleProvider>();
```

### 2.9 Admin.All 系统权限（V0.7.0 W3）

`PermissionNames.AdminAll`（`"Admin.All"`）是内置系统权限——用户或任一角色拥有即对**所有已定义权限**放行。授予方式与普通权限相同：

```csharp
// 角色级：admin 角色拥有全部权限
await dataService.SetGrantAsync(PermissionNames.AdminAll, "Role", "admin", isGranted: true);
```

种子初始化默认预置 admin 角色 `Admin.All`（见 §2.7）。

### 2.10 生产建表迁移（V0.7.0 W1/W2）

`PermissionGrant` 扩展实体不在消费方 `SyncTables` 自动建表范围——V0.7.0 提供两层建表方案：

1. **开发环境（自动）**：注册了 `ITableStructureSynchronizer`（FreeSql）时，扩展 `InitializeAsync` 对扩展程序集主动 `SyncStructure`（幂等建表，创建缺失表/列）。
2. **生产环境（脚本）**：包内 `scripts\PermissionGrant.sql`（随 NuGet 发布）——含建表 + 唯一约束 + 索引，幂等（IF OBJECT_ID 守卫），DBA/CI 执行。

## 三、权限检查 API

### 3.1 IPermissionChecker（可注入）

运行时任意服务注入 `IPermissionChecker` 做代码级权限判断：

```csharp
public class MyService
{
    private readonly IPermissionChecker _checker;
    public MyService(IPermissionChecker checker) => _checker = checker;

    public async Task DoSomethingAsync()
    {
        if (await _checker.IsGrantedAsync("Order.Create"))
        {
            // 有权限
        }

        // 批量检查
        var results = await _checker.IsGrantedAsync("Order.Create", "Order.Delete");
    }
}
```

> ⚠️ 代码级检查是**软判断**（不抛异常）——只做业务分支。真正的**安全门**用 `[RequirePermission]`（fail-closed 抛异常）。

### 3.2 权限判定语义（fail-closed）

| 场景 | 结果 |
|:--|:--|
| 权限名未定义（仓库中不存在） | 拒绝（fail-closed） |
| 权限名已定义但用户未授予 | 拒绝 |
| 权限名已定义 + store 返回 Granted | 通过 |
| 未标记 `[RequirePermission]` | 不受影响 |

## 四、设计要点与边界

### 4.1 与菜单扩展的集成

菜单项 `RequiredPermissions` 经 `IMenuManager` 调用同一 `IPermissionChecker` 过滤（见 [导航扩展使用指南](../../Navigation/docs/导航扩展-使用指南.md) §3.2）。

### 4.2 已知边界（V0.2.0 SG1 化）

| 边界 | 说明 |
|:--|:--|
| 编译期权限名校验 | **未实现**（ADR38 D7）——贡献者 `Define()` 是运行时方法，SG 看不到体内字符串；运行时 fail-closed 兜底 |
| 权限分配管理 API | **已实现**（V0.4.0 G2）——DataService 标记 `[GenerateController(FromDataService = true)]`，消费方 SG1 自动生成 REST 管理 API（subdomain `Permissions`）；`EntityDACPermissionStore` 保持 `IEntityDAC` 注入 |
| 角色→权限映射 | **已内置**（V0.6.0）——`IRoleProvider<TUserInfo>` + `PermissionChecker` 用户+角色双重检查 |
| xCodeGen 生成物 | `.xCodeGen/permissions.xCodeGen.json` 已生效；`.cs` 骨架入库、`.g.cs` 不入库（Debug 构建自动重新生成） |
| 建表迁移 | `SyncTables` 只扫消费方 assembly，`PermissionGrant` 扩展实体不在主动建表范围——V0.7.0 起扩展 `InitializeAsync` 对扩展程序集自建表（幂等）；生产部署用包内 `scripts\PermissionGrant.sql`（见 §2.9 下建表说明） |

### 4.3 常见反模式

| 反模式 | 说明 | 正确做法 |
|:--|:--|:--|
| 只注册 Permissions 包不注册 store | 所有 `[RequirePermission]` 永远拒绝 | 注册自定义 `IPermissionStore` |
| 用 `IPermissionChecker.IsGrantedAsync` 当安全门 | 软判断不抛异常，可被绕过 | 用 `[RequirePermission]`（fail-closed） |
| 权限名用自由字符串散落各处 | 拼写错误运行时才发现 | 定义常量/贡献者集中声明 |

## 五、FAQ

**Q: 如何让"销售或管理员"都能访问一个方法？**
用 `[RequirePermission("Sale.Create", "Admin.All", Logic = PermissionLogic.Any)]`——任一权限授予即可通过。

**Q: 权限检查和角色检查冲突吗？**
不冲突。`AuthorityFilter`（角色）和 `PermissionFilter`（权限）独立工作，可同时标记。

**Q: 权限定义在哪声明？**
在消费方业务模块的 `[PermissionContributor]` 类里，经 `Define(context).Add(...)` 声明。SG 编译期发现（源码 + 引用程序集）。

**Q: 默认权限检查器为何恒拒绝？**
默认 `IPermissionStore` 是 NoOp（V4.9.72 简化）。`PermissionChecker<TUserInfo>` 已接通用户上下文 + store 链路——注册 store 后即真实生效。
