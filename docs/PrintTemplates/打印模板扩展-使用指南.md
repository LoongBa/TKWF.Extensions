# 打印模板扩展-使用指南

> **扩展**：`TKWF.Ext.PrintTemplates`（打印模板引擎与版本化）· **版本**：v0.1.0
> **概念名**：打印模板引擎（Print Templates）——Scriban 沙箱渲染 + Draft/Active/Archived 版本生命周期 + `{Key}@{Version}` 审计固定渲染
> **技术规范**：见 [_Framework/PrintTemplates/README.md](../../_Framework/PrintTemplates/README.md)

---

## 一、快速开始

### 1. 引用扩展

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\..\_Framework\PrintTemplates\TKWF.Ext.PrintTemplates.csproj" />
```

### 2. 白名单声明（v4.9.85+ 必需）

扩展不再"发现即启用"——消费方须在领域初始化器上显式声明白名单，三钩子才接线：

```csharp
using TKWF.Ext.PrintTemplates;

[TKWFEnabledExtension(typeof(PrintTemplatesExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

声明后自动注册（TryAdd 语义，消费方可覆盖）：
- `ITemplateStore`（Scoped，FreeSql 实现）——模板/版本 CRUD
- `ITemplateManager`（Scoped）——版本生命周期 + 渲染入口
- `ITemplateRenderer`（Singleton）——Scriban 沙箱渲染
- `PrintTemplatesOptions` 绑定 `TKWF:PrintTemplates` 配置节

### 3. 注入 + 使用

```csharp
public class InvoicePrintService(ITemplateManager templateManager)
{
    // 渲染当前激活版本：取最新 Active，失败显式抛异常
    public async Task<string> RenderInvoiceAsync(InvoiceViewModel model, CancellationToken ct = default)
        => await templateManager.RenderAsync("Invoice.Standard", BuildModel(model), ct);

    // 审计固定渲染：按打印时激活版本精确渲染历史单据
    public async Task<string> ReRenderInvoiceAsync(InvoiceViewModel model, string version, CancellationToken ct = default)
        => await templateManager.RenderAsync("Invoice.Standard", BuildModel(model), version, ct);

    private static Dictionary<string, object?> BuildModel(InvoiceViewModel m) => new()
    {
        ["InvoiceNo"] = m.InvoiceNo,
        ["Date"] = m.Date,
        ["Customer"] = new Dictionary<string, object?>
        {
            ["Name"] = m.CustomerName,
            ["Address"] = m.CustomerAddress
        },
        ["Items"] = m.Items.Select(i => new Dictionary<string, object?>   // 嵌套字典 → 模板嵌套对象
        {
            ["Name"] = i.Name, ["Qty"] = i.Qty, ["Price"] = i.Price
        }).ToList(),
        ["Discount"] = m.Discount
    };
}
```

> **数据模型规则（安全关键）**：模板只能访问经 `IDictionary`/原始类型/集合构造的数据。**禁止传入原始 .NET 业务对象**——复杂对象会被转成字符串（`ToString()`），不暴露成员（见 §五安全契约）。

## 二、模板编写（Scriban 语法速查）

模板正文为 Scriban 语法（Liquid 风格）。数据模型字典的 key 作为全局变量直接可用（`{{ Key }}`），嵌套字典用点号访问（`{{ Customer.Name }}`）。

### 1. 变量输出

```liquid
发票单号：{{ InvoiceNo }}
客户：{{ Customer.Name }}
```

- 缺失/空变量输出空字符串，不抛错
- 顶层 key 直接引用；点号访问嵌套对象；`{{ for }}` 循环变量见下

### 2. 循环（行项目）

```liquid
<table>
  {{ for item in Items }}
  <tr>
    <td>{{ for.index }}</td>
    <td>{{ item.Name }}</td>
    <td>{{ item.Qty }}</td>
    <td>{{ item.Price | string.format "0.00" }}</td>
    <td>{{ item.Qty * item.Price | math.format "0.00" }}</td>
  </tr>
  {{ end }}
</table>
```

- 循环内建变量：`for.index`（从 1 起）、`for.first`、`for.last`
- 行项目表格还可直接用 `tablerow`：`{{ tablerow item in Items cols: 3 }}...{{ end }}`
- 循环上限受 `LoopLimit`（默认 1000）约束

### 3. 条件分支

```liquid
{% if Discount > 0 %}
  优惠：{{ Discount | string.format "0.00" }}
{% else if Customer.Vip %}
  尊享客户（无折扣）
{% else %}
  无优惠
{% end %}
```

- 运算符：`==`、`!=`、`>`、`<`、`>=`、`<=`、`and`、`or`、`not`
- 多分支还可用 `{% case X %}{% when A %}{% end %}` 结构

### 4. 过滤器（金额/日期格式化）

| 用途 | 写法 | 示例输出 |
|------|------|---------|
| 金额固定两位 | `{{ amount | string.format "0.00" }}` | `1280.50` |
| 金额千分位 | `{{ amount | string.format "#,##0.00" }}` | `1,280.50` |
| 金额去尾零 | `{{ amount | math.format "0.##" }}` | `1280.5` |
| 日期格式化 | `{{ date | date.to_string "%Y-%m-%d" }}` | `2026-08-01` |
| 日期时间 | `{{ date | date.to_string "%Y/%m/%d %H:%M" }}` | `2026/08/01 14:30` |
| 货币符号 | `{{ Customer.Currency }} {{ amount | string.format "0.00" }}` | `CNY 1280.50` |
| 字符串大写 | `{{ Customer.Name | string.upcase }}` | `LOONGBA` |
| 字符串替换 | `{{ text | string.replace "old" "new" }}` | — |

> **编写建议**：金额/日期格式化到消费方**需要什么格式就写什么格式**——Scriban 内置格式化过滤器已覆盖打印布局需求（操作者经管理 UI 自助调整，无需开发者注册 C# helper）。

### 5. 注释

```liquid
{{# 这是注释，不会出现在渲染结果中 #}}
```

### 6. 完整示例（发票模板）

```liquid
{{# 发票模板 v1.0.0 #}}
<h1>发票 {{ InvoiceNo }}</h1>
<p>开票日期：{{ Date | date.to_string "%Y-%m-%d" }}</p>
<p>客户：{{ Customer.Name }}　{{ Customer.Address }}</p>

<table border="1">
  <tr><th>#</th><th>品名</th><th>数量</th><th>单价</th><th>金额</th></tr>
  {% for item in Items %}
  <tr>
    <td>{{ for.index }}</td>
    <td>{{ item.Name }}</td>
    <td>{{ item.Qty }}</td>
    <td>{{ item.Price | string.format "0.00" }}</td>
    <td>{{ item.Qty * item.Price | string.format "0.00" }}</td>
  </tr>
  {% end %}
</table>

{% if Discount > 0 %}
<p>优惠：{{ Discount | string.format "0.00" }}</p>
{% end %}
<p><b>合计：{{ Total | string.format "0.00" }}</b></p>
```

## 三、版本管理（生命周期）

### 生命周期

```
Draft（草稿）──── Publish ────→ Active（唯一）──── Archive ────→ Archived（可追溯渲染，不可再发布）
   │ 每模板仅一个（保存即覆盖）    │ 新 Active 发布时旧 Active 自动 Archived
   │ 版本号 "1.{next}.0-draft"   │ 自动 minor 递增：1.0.0 → 1.1.0 → 1.2.0 ...
```

### 1. 发布新版本（PublishAsync）

```csharp
// 发布新版本：首版自动建成 1.0.0，后续自动 minor 递增（1.1.0、1.2.0 ...）
var version = await manager.PublishAsync("Invoice.Standard", content, "增加含税列", ct);
// version.Version == "1.1.0"; version.Status == PrintTemplateVersionStatus.Active
```

- Key 不存在时**自动创建** `PrintTemplate` 行（`Name=Key`）——无需预建模板
- 旧 Active 自动转 Archived（每模板同时仅一个 Active）
- `TemplateId + Version` 唯一约束：并发发布同 Key 冲突时败者收到存储层异常

### 2. 编辑草稿（DraftAsync）

```csharp
// 存/更新草稿（每模板仅一个 Draft，保存即覆盖；不占 Active 槽位）
var draft = await manager.DraftAsync("Invoice.Standard", newContent, "改排版中", ct);
// draft.Status == PrintTemplateVersionStatus.Draft; Version == "1.2.0-draft"
// 再次 DraftAsync 覆盖同一草稿（版本号不变）
```

- 草稿**不会**出现在打印渲染中（`RenderAsync` 只取 Active/显式版本）
- `PublishAsync` 不提升 Draft —— 正式发布须另传正文（草稿内容 → 复制进 `PublishAsync`）

### 3. 归档（ArchiveAsync）

```csharp
// 归档指定版本（可追溯渲染，不可再发布）
await manager.ArchiveAsync("Invoice.Standard", "1.0.0", ct);
```

- 归档后该版本仍可按固定版本渲染（审计必需），但不会成为 Active
- **改版不删除历史版本**——全部版本留在 `PrintTemplateVersion` 表供追溯

### 4. 查询接口

```csharp
var template = await manager.GetTemplateAsync("Invoice.Standard");          // 模板定义
var active   = await manager.GetActiveVersionAsync("Invoice.Standard");     // 当前 Active 版本
var versions = await manager.ListVersionsAsync("Invoice.Standard");         // 全部版本（版本号倒序）
var v10      = await manager.GetVersionAsync("Invoice.Standard", "1.0.0");  // 精确版本
```

## 四、审计固定渲染（历史单据）

**场景**：发票已按 1.0.0 开具；后续模板升级到 1.2.0。重打该发票时**必须保持开票时外观**——按打印时激活版本固定渲染，而非最新模板。

```csharp
// 默认：最新 Active（新单据）
var latest = await manager.RenderAsync("Invoice.Standard", model, ct);

// 审计固定：按历史版本渲染（旧单据重打/审计回溯）
var historical = await manager.RenderAsync("Invoice.Standard", model, "1.0.0", ct);

// 建议消费方在单据表记录打印时版本，重打时回传
// SELECT PrintedTemplateVersion FROM Invoice WHERE InvoiceNo = 'INV-2026-0001'  -- "1.0.0"
```

**要点**：
- `version` 参数传 SemVer 字符串（如 `"1.1.0"`），也可用带后缀的草稿版本号
- 版本缺失 / 模板 Key 不存在 → 抛 `InvalidOperationException`（显式失败，不用旧模板静默兜底）
- 归档版本（Archived）同样支持固定渲染——审计链路不随时间失效

## 五、安全契约（沙箱边界）

模板运行于 Scriban 沙箱（V0.1.0 强制，不可关闭）。渲染时**只能**：
- 访问经数据模型字典传入的键（顶层/嵌套/集合元素）
- 使用循环、条件、内置过滤器、内置数学/日期/字符串函数

**不能**（沙箱逐项阻断）：
- ❌ 调用方法——`{{ obj.Method() }}`、`{{ "x".GetType() }}` 均被阻断（`MemberFilter` 仅放行公共属性）
- ❌ 访问字段/私有成员/`GetType`/`ToString`/反射逃逸路径
- ❌ `include` 子模板——扩展**不配置 `TemplateLoader`**，模板无法读盘
- ❌ 访问原始 .NET 业务对象——数据经递归转换，复杂类型只留字符串表示

**数据模型契约**：

| 传入类型 | 模板中形态 |
|---------|-----------|
| `Dictionary<string, object?>`（含嵌套） | 对象（点号访问） |
| `List`/数组（含嵌套元素） | 数组（`for` 遍历） |
| string / 数值 / bool / null | 原样 |
| 其他 .NET 类型 | `ToString()` 字符串（不暴露成员） |

**执行限制**（`TKWF:PrintTemplates` 可调，见 §六）：LoopLimit=1000、RecursiveLimit=100、LimitToString=1MB、RegexTimeOut=10s——防死循环/巨型字符串/恶意正则。

> **受信后台限定**：Scriban 沙箱**不是进程级隔离**（官方明示）。操作者可编辑模板须限定在**受信管理后台 + 权限门控**（登录操作者自助编辑），不得接收公开/不可信模板输入。

## 六、配置选项

```json
{
  "TKWF": {
    "PrintTemplates": {
      "LoopLimit": 1000,
      "RecursiveLimit": 100,
      "LimitToString": 1048576,
      "RegexTimeOut": 10000
    }
  }
}
```

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `TKWF:PrintTemplates:LoopLimit` | 1000 | 模板循环上限 |
| `TKWF:PrintTemplates:RecursiveLimit` | 100 | 模板递归上限 |
| `TKWF:PrintTemplates:LimitToString` | 1048576 | 字符串转换上限（1 MB） |
| `TKWF:PrintTemplates:RegexTimeOut` | 10000 | 正则表达式超时（毫秒） |

消费方亦可在初始化器 `ConfigureExtensions` 中 `services.Configure<PrintTemplatesOptions>(o => ...)` 程序化覆盖（扩展内 `BindConfiguration` + 默认值兜底，消费方注册优先）。

## 七、自定义渲染器 / 存储 / 门面（DI 覆盖）

扩展全部用 `TryAdd` 注册——**消费方注册的同类型实现优先，扩展默认不覆盖**。

### 自定义渲染器（DI override ITemplateRenderer）

```csharp
// 消费方：在 ConfigureServices 中注册自定义渲染器
public class MyRenderer : ITemplateRenderer
{
    public Task<string> RenderContentAsync(string content,
        IReadOnlyDictionary<string, object?> model, CancellationToken ct = default)
    {
        // 自定义渲染逻辑（如接其他模板引擎）
        ...
    }
}

// 注册（TryAddSingleton 语义：消费方优先）
services.AddSingleton<ITemplateRenderer, MyRenderer>();
```

典型场景：自定义渲染器包装 `ScribanTemplateRenderer` 增加额外过滤器/预处理器；或精确控制渲染日志（审计留痕）。自定义存储（`ITemplateStore`）需在 `MyDomainInitializer.ConfigureExtensions` 中 DI 注册替换（扩展 `TryAddScoped` 不覆盖消费方）。

## 八、异常处理

| 场景 | 异常 | 说明 |
|------|------|------|
| 模板正文含 Scriban 语法错误 | `TemplateParseException` | 含解析消息列表（定位到具体行列）；**渲染/发布时即报错**，不产出坏单据 |
| 渲染但模板无 Active 版本 | `InvalidOperationException` | 消息含模板 Key |
| 审计固定渲染但版本不存在 | `InvalidOperationException` | 消息含模板 Key + 版本号 |
| 归档/发布时模板或版本未找到 | `InvalidOperationException` | Store 层往上抛（**不静默**——模板是审计关键资产，C1） |
| 并发发布同 Key | 存储层唯一约束异常 | `TemplateId + Version` 唯一索引冲突，败者显式异常 |
| 数据模型含未知类型 | 无异常（转字符串） | 复杂对象只暴露 `ToString()`，不抛错不泄漏 |

> **严格失败优于静默**：模板是审计关键资产——渲染失败/版本缺失一律显式抛异常，禁止"找个旧模板顶替"。

## 九、常见问题（FAQ）

| 问题 | 说明 |
|------|------|
| **草稿为什么不显示** | `RenderAsync` 只取 Active 或显式版本；Draft 不占 Active 槽位，须 `PublishAsync` 才生效 |
| **怎么修改已发布模板** | 三步：`DraftAsync` 改草稿 → 确认后复制正文 `PublishAsync` → 自动出新 Active 版本（旧版本归档保留） |
| **历史单据外观会变吗** | 不会。单据表记录打印时版本，重打用 `RenderAsync(key, model, version)` 固定渲染（§四） |
| **模板里能调用 C# 方法吗** | 不能。`MemberFilter` 仅放行公共属性；需要自定义能力走 DI 覆盖 `ITemplateRenderer`（§七） |
| **金额千分位怎么格式化** | `{{ amount \| string.format "#,##0.00" }}`；日期用 `date.to_string`（§二） |
| **发布错了想回滚** | 归档版本不可直接改/再发布。回滚 = 固定渲染旧版本，或把旧正文重新 `PublishAsync` 成一个新版本 |
| **并发发布同 Key** | 唯一索引兜底，败者收到存储层异常——发布侧重试或调整后重发 |
| **模板语法报错在哪看** | `TemplateParseException.Messages` 含解析消息列表（行列定位）；渲染与发布（写入 DB 前不解析）场景下，**发布正文不做解析校验**，语法错误在首次渲染时暴露——建议发布前先用 `RenderContentAsync` 冒烟 |
| **插值输出 HTML 会转义吗** | Scriban 默认不转义插入值（原样输出）。模板渲染结果是 HTML 文本，转 PDF/输出由消费方渲染链路负责；若插入用户输入须消费方自行转义 |
| **BlobStoring/其他扩展能共用吗** | 本扩展独立；版本化模型（`{Key}@{Version}`）供未来 `TextTemplates`（邮件）复用，引擎选型独立评估 |
