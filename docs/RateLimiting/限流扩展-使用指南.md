# RateLimiting 限流扩展-使用指南

> 扩展：`TKWF.Ext.RateLimiting`（v0.2.0）——Web 层限流接线（ASP.NET Core `AddRateLimiter` 中间件）。
> 本指南公开；迭代开发方案/ADR/审核报告见主框架私有 `_TKWF/docs/03_扩展模块/RateLimiting/`。

---

## 1. 本扩展解决什么

主框架 Domain 层限流（`[RateLimit]` AOP）覆盖**服务方法级**（领域层），但 **Web 层（HTTP 端点）限流未接线**：
- `RateLimitPartitionBy.Ip` 在 Domain 层**抛异常**（IP 维度限流须在 Web 层做）；
- 端点级/全局 HTTP 限流（按 IP/路径/用户）+ 429 统一映射 + `Retry-After` 无统一配置入口；
- 消费方裸配 `AddRateLimiter` 样板重复、策略散落。

本扩展一键接线：`RateLimitingWebExtension`（UseWebExtensions Web 装配钩子，v4.10.45 收敛迁移）+ `TKWF:RateLimiting` 配置节，零第三方依赖（net10 内置）。

## 3. 启用 + 接线

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```csharp
// ① 白名单启用（v4.9.85+：发现不自动启用）
[TKWFEnabledExtension(typeof(RateLimitingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }

// ② Web 装配钩子一次声明（v4.10.45 收敛迁移——旧 AddTkfwRateLimiting + app.UseRateLimiter() 静态接线已删除，破坏性变更；
//    AddRateLimiter 展开 + Options 绑定 + 中间件挂载全部内聚进扩展，锚点默认 BeforeAuthentication——Route 前）
builder.ConfigWebAppDomain<MyUserInfo, MyDomainInitializer, DomainWebOptions>(...)
    .UseWebSession()
    .UseWebExtensions(e => e.Add<RateLimitingWebExtension>(x =>
    {
        x.ConfigureOptions = o => /* 编程式覆盖配置节（可选） */;
    }))
    .BeforeRouting(...)
    .AfterRouting(...)
    .Build(...);
```

> **标注式限流（v4.10.45 现状）**：本扩展默认锚点 `BeforeAuthentication`（Route 之前）——自动路径感知模式
> （`EndpointPolicies` 精确路径命中）无碍；**标注式 `RequireRateLimiting` 需端点 metadata（UseRouting 后）**
> ——当前仍需消费方在 `BeforeRouting` 显式 `app.UseRateLimiter()`（AfterRouting 锚点为框架机制预留，见 G18 §5）。

## 4. 配置（`TKWF:RateLimiting`）

```jsonc
{
  "TKWF": {
    "RateLimiting": {
      "Partition": "Ip",                              // Ip | User | None
      "RejectionStatusCode": 429,
      "RetryAfter": true,
      "Global": {
        "Algorithm": "FixedWindow",                   // FixedWindow | SlidingWindow | TokenBucket
        "PermitLimit": 100,                           // 窗口许可数 / 令牌桶 TokenLimit
        "WindowSeconds": 60,
        "SegmentsPerWindow": 6,                       // 滑动窗口分段
        "ReplenishmentTokensPerSecond": 1,            // 令牌桶补充速率（个/秒）
        "QueueLimit": 0                               // 默认 0 = 直接拒绝不排队
      },
      "EndpointPolicies": {
        "/api/auth/login": { "Algorithm": "FixedWindow", "PermitLimit": 5, "WindowSeconds": 60 }
      }
    }
  }
}
```

**端点策略匹配（精确，Oracle P2-2）**：`EndpointPolicies` 键为完整路径（如 `/api/auth/login`），仅整路径完全一致命中，未命中回退 `Global`；v0.1.0 不支持通配符前缀。命中端点策略的请求独立配额（与全局桶隔离）。

## 5. 典型场景

### 5.1 登录接口 IP 防暴力破解（Domain 层无法做的场景）

```csharp
// UseWebExtensions 内（v4.10.45 收敛迁移后）
e.Add<RateLimitingWebExtension>(x => x.ConfigureOptions = o =>
{
    o.Partition = RateLimitPartition.Ip;
    o.EndpointPolicies["/api/auth/login"] = new()
    {
        Algorithm = RateLimitAlgorithm.FixedWindow,
        PermitLimit = 5,          // 每分钟 5 次/IP
        WindowSeconds = 60
    };
});
```

### 5.2 已认证用户频控（配合 Domain 层双层防护）

```csharp
e.Add<RateLimitingWebExtension>(x => x.ConfigureOptions = o => o.Partition = RateLimitPartition.User);  // HttpContext.User → NameIdentifier
// 匿名 fallback IP 分区（Oracle C1）
```

## 6. 双层防护定位（与 Domain 层关系，Oracle C2）

| 层 | 入口 | 粒度 | 典型用途 |
|----|------|------|---------|
| **Web 层**（本扩展） | `RateLimitingWebExtension`（UseWebExtensions 装配，v4.10.45 收敛迁移） | IP / 端点 / 全局粗粒度 | 登录 IP 防爆、OpenAPI 文档端局限流、导出接口频控 |
| **Domain 层**（主框架） | `FilterBuilder.AddRateLimit()` + `[RateLimit("policy")]` | 用户级细粒度 AOP | 服务方法级用户频控（D10D 已完整，本扩展**不重建**） |

> 登录接口组合用法 = **Web IP 限流 + Domain 用户限流**双层。
> ⚠️ 一般**不要**在同一路径同时配置 Web 全局/端点限流与 Domain `[RateLimit]` 相同语义——两者配额独立，会叠加计数；按场景各司其职（Web 防入口爆破、Domain 防方法滥用）。

## 7. 点检查原语与三层限流分工（v0.3.0+，IRateLimitCheck）

> **版本演进（v0.3.0）**：本扩展从"纯 Web 层接线"扩展为三层限流分工中的**点检查原语 DB Provider**——新增 `SqlCountRateLimitCheck`（独立计数表 `TKWF_RateLimitCounter`，ADR89 CAS 原子递增，跨实例正确）。抽象 + 内存默认 `IRateLimitCheck`/`MemoryRateLimitCheck` 在主框架 `TKW.Framework.Utility.RateLimitChecks`（v4.10.67，ADR104）。

### 7.1 三层职责表

| 层 | 载体 | 粒度 | 用途 | 拒绝语义 |
|----|------|------|------|---------|
| **Web 层** | 本扩展 `RateLimitingWebExtension`（ASP.NET Core `AddRateLimiter` 中间件） | IP/端点粗粒度 | 登录 IP 防爆、OpenAPI 端局限流 | HTTP 429 + `Retry-After` |
| **Domain AOP** | 主框架 `FilterBuilder.AddRateLimit()` + `[RateLimit("policy")]` + 官方 `PartitionedRateLimiter` | 用户/方法级 AOP | 服务方法级用户频控 | `RateLimitException`（429） |
| **点检查原语**（v0.3.0 新增） | `IRateLimitCheck`（运行库抽象 + 内存默认）+ 本扩展 `SqlCountRateLimitCheck`（DB Provider） | 服务内任意点 | MFA 验证尝试、短信发送、改密/找回频控、聚合逻辑内检查 | `bool + RetryAfter + Remaining` 返回值（不抛异常，调用方自决） |

> **分工原则**：Web 层管"谁在打 HTTP 入口"，Domain AOP 管"方法级策略限流"，点检查原语管"服务内任意位置的窗口计数"——三层互补不重叠；同一路径**不要**叠加相同语义（配额独立会叠加计数）。

### 7.2 点检查原语（IRateLimitCheck）

```csharp
namespace TKW.Framework.Utility.RateLimitChecks;

public interface IRateLimitCheck
{
    /// 判定并计入一次尝试；窗口内已计数 ≥ maxAttempts → false（remaining=0，经 GetRetryAfter 取可重试时间）。
    /// 入参守卫：key 空/白、maxAttempts ≤ 0、window ≤ Zero → false（fail-closed）。
    bool TryAcquire(string key, int maxAttempts, TimeSpan window, out int remaining);

    /// 窗口满时下一次尝试可行的剩余等待时长；未满/键不存在 → TimeSpan.Zero。
    TimeSpan GetRetryAfter(string key, TimeSpan window);

    /// 当前剩余额度（只读不计数）；键不存在 → maxAttempts。
    int GetRemaining(string key, int maxAttempts, TimeSpan window);
}
```

- **key 规范化约定**：`{policy}:{partitionBy}:{subject}`（各段非空、不含 `:` 分隔符；如 `mfa:verify:user:u_123:sms`、`pwd:reset:user:u_123`）。key 对 Provider 为不透明字符串（不解析），仅作计数键。
- **Provider 窗口语义差异（Oracle7 RC2）**：`MemoryRateLimitCheck` = **sliding window**（时间戳队列，继承原 MFA `MfaRateLimiter`）；`SqlCountRateLimitCheck` = **fixed window**（单窗口计数器，`WindowEndUtc` 过期重置）。切换 Provider 时窗口边界突发行为可能变化（fixed 允许窗口边界双倍突发）——MFA 验证等低频场景可接受，高频场景按需评估。

### 7.3 SqlCountRateLimitCheck（DB Provider，跨实例正确）

消费方**显式注册**为确定性路径（RC1 排序裁定——MFA 与 RateLimiting 扩展无依赖约束，依赖"扩展自动注册序"不可靠；TryAdd 首注册胜出下 fallback 可能静默取 Memory）：

```csharp
// 消费方 ConfigureServices / DomainHostInitializerBase 内：
services.AddSingleton<IRateLimitCheck, SqlCountRateLimitCheck>();
```

- 独立计数表 `TKWF_RateLimitCounter`（Key 唯一 / Count / WindowStartUtc / WindowEndUtc）——**仅需限流、单次尝试无审计价值的场景**（MFA 验证、改密/找回频控）。
- **TryAcquire 原子语义**：经 ADR89 `UpdateWhereAsync` CAS（`SET Count=Count+1 WHERE Key=@key AND WindowEndUtc>=@now AND Count<@max`）——非读-改-写 TOCTOU，跨实例 DB 行锁正确。
- 惰性淘汰：过期行随下一次命中该 key 时重置（无后台清理）；⚠️ **孤儿键（不再命中的 key）无自然回收、表增长无界**——v0.1.0 已知限制（清理任务 v0.2.0），消费方应限制键空间为有界标识（如 userId）。
- **未显式注册时**：MFA/AuthCenter/AuthSurface 等扩展 Initializer 已 `TryAddSingleton<IRateLimitCheck, MemoryRateLimitCheck>()` fallback——频控"始终在"不降级为空（SMS 计费滥用防护保持）。

### 7.4 审计表 COUNT vs 通用计数表（Oracle7 C5 决策规则）

| 场景 | 选型 | 依据 |
|------|------|------|
| 需审计轨迹（登录尝试/短信发送——每行有独立审计价值） | **审计表 COUNT**（AuthCenter `AuthLoginAttempt`/`SmsRecord`——append-only + COUNT 下推） | 审计与计数双目的正确，不膨胀计数表 |
| 仅需限流、单次尝试无审计价值（MFA 验证、改密/找回频控） | **`RateLimitCounter`**（本扩展 SqlCount） | 泛型契约表无关、CAS 真原子 |

> 未来贡献者按此规则选型，不猜测（ADR-RateLimiting 决策点 2）。

### 7.5 三层组合示例（登录接口完整防护）

```text
Web 层（RateLimitingWebExtension）: /api/auth/login 每分钟 5 次/IP       → 入口防爆破
Domain AOP（[RateLimit("login-policy")]）: 每用户每 10 分钟 30 次         → 方法级滥用
点检查（IRateLimitCheck）: 服务内登录编排 TryAcquire(pwd:login:{uid})     → 业务逻辑级窗口计数
```

## 8. 边界与注意事项

- **进程内限流**：限流状态存进程内存，多实例部署不共享——v0.2.0 Redis 分布式限流候选；单实例语义下使用。
- **IP 解析**：经反向代理/负载均衡部署时 `RemoteIpAddress` 是代理地址——需 `app.UseForwardedHeaders()` + `ForwardedHeaders.XForwardedFor` 配置，否则限流按代理 IP 聚合。
- **429 语义**：`RejectionStatusCode` 默认 429，对齐 Domain 层 `RateLimitException`；`Retry-After` 默认写响应头（拒绝时建议重试秒数）。
- **测试说明**：扩展自带 20 项测试（TestServer 起端点，HTTP 级验证固定/滑动/令牌桶/端点覆盖/IP 隔离/用户分区/可配项/Options 绑定）。
- **不适用**：跨进程分布式限流、运行时动态改策略（均 v0.2.0 候选）。
