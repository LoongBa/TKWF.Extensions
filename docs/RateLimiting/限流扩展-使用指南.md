# RateLimiting 限流扩展-使用指南

> 扩展：`TKWF.Ext.RateLimiting`（v0.1.0）——Web 层限流接线（ASP.NET Core `AddRateLimiter` 中间件）。
> 本指南公开；迭代开发方案/ADR/审核报告见主框架私有 `_TKWF/docs/03_扩展模块/RateLimiting/`。

---

## 1. 本扩展解决什么

主框架 Domain 层限流（`[RateLimit]` AOP）覆盖**服务方法级**（领域层），但 **Web 层（HTTP 端点）限流未接线**：
- `RateLimitPartitionBy.Ip` 在 Domain 层**抛异常**（IP 维度限流须在 Web 层做）；
- 端点级/全局 HTTP 限流（按 IP/路径/用户）+ 429 统一映射 + `Retry-After` 无统一配置入口；
- 消费方裸配 `AddRateLimiter` 样板重复、策略散落。

本扩展一键接线：`AddTkfwRateLimiting` + `TKWF:RateLimiting` 配置节，零第三方依赖（net10 内置）。

## 3. 启用 + 接线

```csharp
// ① 白名单启用（v4.9.85+：发现不自动启用）
[TKWFEnabledExtension(typeof(RateLimitingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }

// ② ServiceCollection：展开 AddRateLimiter（全局 + 端点 + 分区 + 429/Retry-After + Options 绑定）
builder.Services.AddTkfwRateLimiting();   // 也可传 configure 编程式覆盖配置节

// ③ 中间件（Route 之前）
app.UseRateLimiter();
```

## 4. 配置（`TKWF:RateLimiting`）

```jsonc
{
  "TKWF": {
    "RateLimiting": {
      "Partition": "Ip",                              // Ip | User | None
      "RejectionStatusCode": 429,
      "RetryAfter": true,
      "Global": {
        "Algorithm": "FixedWindow",                   // FixedWindow | SlidingWindow | TokenBucket
        "PermitLimit": 100,                           // 窗口许可数 / 令牌桶 TokenLimit
        "WindowSeconds": 60,
        "SegmentsPerWindow": 6,                       // 滑动窗口分段
        "ReplenishmentTokensPerSecond": 1,            // 令牌桶补充速率（个/秒）
        "QueueLimit": 0                               // 默认 0 = 直接拒绝不排队
      },
      "EndpointPolicies": {
        "/api/auth/login": { "Algorithm": "FixedWindow", "PermitLimit": 5, "WindowSeconds": 60 }
      }
    }
  }
}
```

**端点策略匹配（精确，Oracle P2-2）**：`EndpointPolicies` 键为完整路径（如 `/api/auth/login`），仅整路径完全一致命中，未命中回退 `Global`；v0.1.0 不支持通配符前缀。命中端点策略的请求独立配额（与全局桶隔离）。

## 5. 典型场景

### 5.1 登录接口 IP 防暴力破解（Domain 层无法做的场景）

```csharp
services.AddTkfwRateLimiting(o =>
{
    o.Partition = RateLimitPartition.Ip;
    o.EndpointPolicies["/api/auth/login"] = new()
    {
        Algorithm = RateLimitAlgorithm.FixedWindow,
        PermitLimit = 5,          // 每分钟 5 次/IP
        WindowSeconds = 60
    };
});
```

### 5.2 已认证用户频控（配合 Domain 层双层防护）

```csharp
services.AddTkfwRateLimiting(o => o.Partition = RateLimitPartition.User);  // HttpContext.User → NameIdentifier
// 匿名 fallback IP 分区（Oracle C1）
```

## 6. 双层防护定位（与 Domain 层关系，Oracle C2）

| 层 | 入口 | 粒度 | 典型用途 |
|----|------|------|---------|
| **Web 层**（本扩展） | `AddTkfwRateLimiting` + `app.UseRateLimiter()` | IP / 端点 / 全局粗粒度 | 登录 IP 防爆、OpenAPI 文档端局限流、导出接口频控 |
| **Domain 层**（主框架） | `FilterBuilder.AddRateLimit()` + `[RateLimit("policy")]` | 用户级细粒度 AOP | 服务方法级用户频控（D10D 已完整，本扩展**不重建**） |

> 登录接口组合用法 = **Web IP 限流 + Domain 用户限流**双层。
> ⚠️ 一般**不要**在同一路径同时配置 Web 全局/端点限流与 Domain `[RateLimit]` 相同语义——两者配额独立，会叠加计数；按场景各司其职（Web 防入口爆破、Domain 防方法滥用）。

## 7. 边界与注意事项

- **进程内限流**：限流状态存进程内存，多实例部署不共享——v0.2.0 Redis 分布式限流候选；单实例语义下使用。
- **IP 解析**：经反向代理/负载均衡部署时 `RemoteIpAddress` 是代理地址——需 `app.UseForwardedHeaders()` + `ForwardedHeaders.XForwardedFor` 配置，否则限流按代理 IP 聚合。
- **429 语义**：`RejectionStatusCode` 默认 429，对齐 Domain 层 `RateLimitException`；`Retry-After` 默认写响应头（拒绝时建议重试秒数）。
- **测试说明**：扩展自带 20 项测试（TestServer 起端点，HTTP 级验证固定/滑动/令牌桶/端点覆盖/IP 隔离/用户分区/可配项/Options 绑定）。
- **不适用**：跨进程分布式限流、运行时动态改策略（均 v0.2.0 候选）。
