## 二、代码复查结论（对照 tkwf-extension skill 逐项核对）

| # | skill 要求（§4/§5） | SSO V0.1.0 现状 | 判定 |

## 三、Oracle 评审结论归档

### 3.1 归层实施开发方案评审（bg_06ff4b27，2026-10-05）

**结论**: PASS WITH CONDITIONS

**最优解判定**: ✅ **"代码零移动 + 纯命名归层"是最优解**（对比"代码大重构"与"现状不动"两极端——SSO 现状已合规，无技术债驱动重构；SSO 未发布为命名归层成本最低窗口期；类名 `Sso*Entity` 保留 = DB 表名同步，重命名得不偿失）。

**P1 四项修订（已在归层实施开发方案落实）**:

| # | 修订项 | 落点 |
|---|--------|------|
| P1-1 | **ISsoChannel 契约归属**——保留在 Federation 扩展内（现状不移）；`TKWF.Federation.WeChat` 库**引 Federation 扩展**实现 ISsoChannel（单向依赖无循环）；ADR §五.3 修订"库不引扩展"措辞 | ADR §五.3 + 方案 §5.4/§5.5 |
| P1-2 | **内部类改名遗漏**——补 `SsoOptions→FederationOptions`（含配置节 `TKWF:SSO→TKWF:Federation`）/ `SsoSigningKeyConfig→FederationSigningKeyConfig` / `SsoSecretKeyStore→FederationSecretKeyStore` / 测试项目目录改名 | 方案 §5.1 |
| P1-3 | **xCodeGen 重生成纪律**——命名归层后重跑 `run-xcodegen.ps1 -Ext Federation`（.g.cs 命名空间随包迁移重生成入库）+ 配置文件名改名 | 方案 §5.1 |
| P1-4 | **消费方白名单影响确认**——`[TKWFEnabledExtension(typeof(SsoExtensionInitializer<>))]` 改名同步（SSO 未发布应无外部消费方，实施前 grep 确认） | 方案 §5.1 + 风险表 |

**P2 四项**: 库不引 AspNetCore（验签逻辑收 byte[]/Stream，端点归装配层）/ 测试宿主措辞修正（保留分层单测不重写）/ ISsoChannel 注册责任（库提供 `AddWeChatFederationChannels()` 扩展方法）/ 风险表补 ISsoChannel 归属。
