## 一、本版目标

- **核心交付**：`TKWF.Ext.SSO.WeChat` v0.1.0——微信公众平台适配扩展，覆盖：
  1. **`WeChatOauthChannel`**（channel_type=`wechat_oauth`，形态 A/认证服务号）：认证中心代理微信网页授权（`snsapi_base` 静默 / `snsapi_userinfo`）→ code → openid
  2. **`WeChatEventChannel`**（channel_type=`wechat_event`，形态 B/未认证号）：公众号事件推送接入（验微信签名 + AES 解密）→ openid → 调 SSO Issue API 签 accesscode
  3. **轻量微信 API 客户端**（自建，对齐 Authentication.WeChatApiClient 模式）：access_token L1 缓存 + 并发锁 + 提前 5 分钟过期刷新 + 凭证自持
  4. **凭证自持 `WeChatOptions`**（`TKWF:SSO:WeChat` 节：AppId/AppSecret——AES-GCM 或装配注入；**不复用** Authentication `PlatformCredentialService`，Oracle P2-4）
  5. **联盟锚点配合**：`snsapi_base` 授权通道支持"联盟服务号"场景（openid → `FederationAnchorOpenId`）+ 商户 openid2 场景（→ `PlatformAccountMap`）
  6. **Issue API HMAC 验签**（复用 SSO `SsoClientService.GetHmacSecretAsync`——per-channel HMAC，设计文档 §5.1）
- **完成定义（DoD）**：2 channel 实现 + 轻量客户端 + 端点装配（TestServer 黑盒冒烟：OAuth 回调 + 事件推送验签）+ 测试（双通道时序 + 签名负路径）+ README + 使用指南 + slnx 接线 + 全量回归不破坏。

## 五、技术方案

### 5.1 术语界定（用户 2026-10-05 对齐）——本扩展"对外、OAuth"非"SSO"

```
下游应用视角：认证中心 = IdP → SSO 断言（token2）          【对内】
认证中心视角：微信 = IdP → OAuth 授权码（wechat_oauth）/ 事件推送（wechat_event）  【对外】
本扩展定位：认证中心作为 RP 接入微信的适配层（对外、OAuth/事件、非 SSO）
```

- **SSO 是认证中心对下游的整体体验**（token2 统一断言），不是本扩展的协议；
- **微信扩展用 OAuth/"事件推送"从上游"进货"身份**，认证中心用 SSO 对外"出货"；
- 文档/命名/讨论严格区分：本扩展 = FedSSO **上侧接入器**（IdP Adapter），非 FedSSO 本身。

**多 channel 实例 DI 注册形态（Oracle 评审点 4 P1-3 声明）**：`ISsoChannel.ChannelId` 为实例属性，多公众号 = 多 channel 实例。注册方向——`SsoWeChatExtensionInitializer` 加载 `WeChatOptions.Channels` 配置列表，对每个 channel 配置经 **factory 注册 `TryAddEnumerableConstructible<ISsoChannel, WeChatOauthChannel>`**（守卫工厂语义：帧内 CurrentAopUser 供给 ctor IDomainUser；channel 业务参数 ChannelId/凭证经 Options 注入，不占 ctor IDomainUser 槽——与 ADR92 兼容）。实现期按此方向落 factory；若配置驱动 factory 与守卫工厂冲突，退化为"每 channel 类型注册 + Options 按 ChannelId 选区"（使用指南声明）。

```csharp
{

    public Task<SsoChannelAuthResult> AuthenticateAsync(SsoChannelAuthContext context, CancellationToken ct)
    {
        // context.Parameters["code"]（微信回调 code）
        // 1. GetOpenIdAsync(appId, code) → openid
        // 2. 返回 SsoChannelAuthResult(Success=true, ExternalUserId=openid, AuthLevel=2)
        // 联盟锚点配合（T5）：scope=snsapi_base 且 ChannelId=联盟服务号 → 写 FederationAnchorOpenId

```

- **`/sso/login` 代理流程**：SSO 装配层按 `target_app_id` 关联的 channel 路由——`wechat_oauth` → 302 微信 `authorize?appid&redirect_uri&scope=snsapi_base&state`（state 绑定会话防 CSRF，回调域名 = SSO 域名，设计文档 §5.4）。
- **降级 `snsapi_userinfo`**：应用注册 scope 含 `profile:basic+` 时授权后补拉用户信息（`GetUserInfoAsync`——形态 A 专属能力，需用户确认，设计文档 §5.4）。

### 5.4 `WeChatEventChannel`（形态 B，未认证号——事件推送）

```
用户 发消息/点 CLICK 菜单
  → 微信推送事件 → 本扩展接收端点（验 msg_signature + AES 解密；FromUserName = openid）
  → 进程内调 SSO 主包 ISsoAccessCodeService.IssueAsync（帧内 AOP，零 HMAC 自签——Oracle 评审点 4 裁定）
  → 得 accesscode → 被动回复图文链接 https://api.<域>/sso/auth?code=<code>
```

- **信任根（一票否决）**：验微信事件签名（`msg_signature` = SHA1(sort(token, timestamp, nonce, msg_encrypt)) + AES 解密），漏验 = 可伪造任意 openid = 体系崩溃（设计文档 §8.1）。
- **Issue 路径裁定（Oracle 评审点 4，P1）**：SSO.WeChat 是认证中心实例的**内部组件**（同进程装配）——`WeChatEventChannel` 验签后**进程内调 `ISsoAccessCodeService.IssueAsync`**（`User.Use<ISsoAccessCodeService>()` 帧内 AOP，零 HMAC 自签自验）。设计文档 §5.1 `/sso/issue` HTTP 端点是给**独立公众号后端**（非 SSO.WeChat 渠道）的备选路径，SSO.WeChat 内部不走它。
- **ChannelId 语境**：事件推送的 openid 是"该公众号下"的——`(channel_id=公众号id, openid) → uid`，经 `ISsoChannelMapService.LinkAsync`（Abstractions，upsert 已有契约）查/建映射。
- **各号后端**：自实现部署（独立密钥）；本扩展提供接收验签 + Issue 对接的**服务端再分发**骨架（设计文档 §3.2/§9）。

### 5.5 轻量 `WeChatApiClient`（模式参考，不引主包）

- 对齐 Authentication `WeChatApiClient`：`access_token` L1 缓存（`ConcurrentDictionary<string, (string Token, DateTime Expiry)>` + `SemaphoreSlim` 并发锁 + 提前 5 分钟过期刷新）；
- 凭证从**本扩展 `WeChatOptions`**（AppId/AppSecret）解析——**不经** Authentication `IPlatformCredentialService`（Oracle P2-4：channel 凭证归适配扩展自持；零主包依赖）；
- `GetOpenIdAsync(appId, code)` → `sns/oauth2/access_token`；`GetUserInfoAsync(accessToken, openid)` → `sns/userinfo`（响应裁剪，对齐 `WeChatUserInfo` record 语义）。

**凭证承载形态（Oracle 评审点 4 P2 补充）**：开发——明文 `appsettings.json` 配置；生产——**AES-GCM 密文**（复用 SSO 主包 `SecretEncryptionKeyPath` 派生密钥加解密，或装配注入 K8s secret mount）；**AppSecret 永不明文进配置库**。与 SSO 主包 `SsoSecretKeyStore` **独立**（channel 凭证归适配扩展，P2-4 已裁定）。

### 5.6 边界（与既有微信资产，Oracle P2-3）

| 资产 | 归属 | 定位 |
|---|---|---|
| `WeChatAuthenticationProvider` / `IWeChatApiClient` | Authentication **主包** | 认证中心**内部认证方式**（短信/微信 → token1 签发）——供单应用登录 |
| `WeChatOauthChannel` / `WeChatEventChannel` + 轻量 `WeChatApiClient` | **SSO.WeChat** | **联邦 IdP 适配**（外部身份源 → token2 联邦流） |

- 两会话**永不交叉**：装配实例按需选装（乐学认证中心实例用 SSO 联邦流；单应用业务系统用内部 Provider）；
- 微信场景双轨并存（内部 Provider + 联邦 channel）——**避免重复建设**的边界声明：凭证各自持有、流程各自走、产物不同（token1 vs token2）。

### 5.7 端点契约（装配层扩展 + TestServer 黑盒冒烟）

| 端点 | 方法 | 功能 | 归属 |
|---|---|---|---|
| `/sso/login?target_app_id=X` | GET | OAuth 代理入口（按 channel 路由：wechat_oauth → 302 微信 / wechat_event → 引导页） | SSO 装配映射 |
| `/sso/oauth/wechat/callback` | GET | 微信 OAuth 回调（验 state → code → channel.AuthenticateAsync → uid → 签 token2 → 302 `#t=`） | SSO.WeChat 装配 |
| `/sso/wechat/event/{channelId}` | POST | 事件推送接收（验签 + AES 解密 + 进程内 IssueAsync 对接） | SSO.WeChat 装配 |
| `/sso/issue`（既有） | POST | **独立公众号后端备选路径**（HMAC 验签 + 签 accesscode）——SSO.WeChat 内部不走此 HTTP（Oracle 评审点 4 P1-2 裁定） | SSO（既有） |
| `/sso/auth?code=`（既有） | GET | 消费 accesscode → 302 fragment | SSO（既有） |

**端点实现形态（Oracle 评审点 4 P2 补充）**：`/sso/*` 非 RESTful（302/OAuth 回调/事件推送），**minimal API 或手写控制器**（推荐 minimal API——轻量对齐 SSO 主包；非 `[GenerateController]`，Oracle P2-5）。

**TestServer 黑盒冒烟**（T6，对齐 JwtAuthenticationWebHookIntegrationTests 模式）：OAuth 回调全链 + 事件推送签名正负路径 + 防开放重定向（篡改 target 参数只落注册 origin）。

**测试宿主 mock 策略（Oracle 评审点 4 P2 补充）**：`WeChatApiClient` HTTP 调用（微信 authorize/callback/token/userinfo）**不真打微信**——`HttpMessageHandler` 桩注入（TestServer 内 mock 微信响应）或 `IHttpClientFactory` 替换；事件签名用 `WeChatEventCrypto` 测试辅助生成合法 `msg_signature`/AES 密文（正向）+ 篡改样本（负向）。

### 5.8 联盟锚点配合（T5，设计文档 §7）

- **联盟服务号场景**（认证中心自持联盟认证服务号）：`snsapi_base` 取 openid = **联盟 openid（锚点）** → 经 **Abstractions 写契约 `ISsoAccountLinkService.SetFederationAnchorAsync(uid, anchorOpenId)`** 写 `AuthAccount.FederationAnchorOpenId`（Oracle 评审点 4 P1-1 已补全契约——实现归 Authentication 主包 `AuthAccountQueryService`，委托既有 DataService，红线合规）；
- **商户 openid2 场景**（成员有自己公众号）：openid2 → **`ISsoChannelMapService.LinkAsync(uid, channelId, openid2)`（Abstractions 已有 upsert 契约）** → `PlatformAccountMap`（`(channel_id, openid2) ↔ uid`）；
- **反查直认**（设计文档 §7 时序③"后续任一 openid 直认"）：联盟 openid → `ISsoAccountLinkService.GetByFederationAnchorAsync(openid)`（反查 uid）；商户 openid2 → `ISsoChannelMapService.GetByChannelAsync(channelId, openid2)`（反查 uid）；
- **首次两步时序**（设计文档 §7）：① 认证中心经联盟服务号取联盟 openid（锚点）→ ② 转向商户取 openid2 → 关联 → 后续任一 openid 直认。
