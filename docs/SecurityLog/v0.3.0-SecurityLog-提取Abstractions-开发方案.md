### 5.2 契约迁移要点

- **命名空间政策**：保持 `TKWF.Ext.SecurityLog`（**不追加 .Abstractions 后缀**）——对齐 Account.Abstractions / Emailing.Abstractions 先例。既有消费方 `using TKWF.Ext.SecurityLog;`（含 Account `LoginHistoryService.cs` L8 与 `ILoginHistoryService.cs`/`LoginHistoryDtos.cs` 的 `<see cref>`）**零改动**。
- **csproj 关键属性**（照抄 Account.Abstractions 模板）：`TargetFramework=net10.0`、`RootNamespace=TKWF.Ext.SecurityLog`（无后缀）、`MinVerTagPrefix=SecurityLog.Abstractions/v`（有后缀，独立演进）、`PackageId=TKWF.Ext.SecurityLog.Abstractions`、`IsPackable=true`。
- **主框架依赖判定**：`SecurityLoggingOptions` 使用 `TKW.Framework.Domain` 的 `[Options("TKWF:SecurityLog")]` 特性（编译期 attribute）——**契约包需引 `TKWF.Domain`**（双模式条件化，对齐 Permissions.Abstractions 先例）。其余 10 个契约类型纯 BCL。
- **SG1 Options 绑定连续性实证**（对照生成器源码 `EntityMetadataGenerator.Generation.cs` `CollectOptionsBindings` L1447-1471）：`compilation.GetTypeByMetadataName` + **`compilation.SourceModule.ReferencedAssemblySymbols`** 遍历——SG1 收集 `[Options]` 类型覆盖**引用程序集**。SecurityLoggingOptions 迁入 Abstractions 后，本体经 ProjectReference 引用，本体/消费方的 SG1 仍能收集并生成 `GeneratedOptionsBindings.g.cs`（含 `typeof(global::TKWF.Ext.SecurityLog.SecurityLoggingOptions)` 编译期引用）——**绑定注册（`services.Configure<SecurityLoggingOptions>(GetSection("TKWF:SecurityLog"))`）不失效**。无需本体手动补充注册。

### 5.3 cref 断裂点处理（6 处——契约引本体类型）

迁移后 Abstractions 项目无法解析指向本体类型的 `<see cref>`（本体类型不在 Abstractions 编译单元；反向循环引用也不允许）。**全部改 `<c>` 纯文本**（仓库未启 `TreatWarningsAsErrors`，CS1574 仅警告，但按先例求干净）：

| 文件 | 原 cref | 处理 |
|------|---------|------|
| SecurityLogEntry.cs L7-8 | `SecurityLogFilterAttribute{TUserInfo}` / `SecurityLogEntity` | → `<c>` 纯文本 |
| SecurityLogListItemDto.cs L6 | `SecurityLogEntity` | → `<c>` |
| SecurityLogFailureStat.cs L5-6 | `SecurityLogEntityDataService.GetTopFailedByUserAsync/GetTopFailedByIpAsync` | → `<c>` |
| SecurityLogEventTypes.cs L5 | `SecurityLogFilterAttribute{TUserInfo}` | → `<c>` |
| ISecurityLogAnalyticsService.cs L10 | `SecurityLogEntityDataService` | → `<c>` |
| SecurityLoggingOptions.cs L26/L35 | `SecurityLogAnalyticsService.CleanupExpiredAsync` / `SecurityLogEntityDataService.DeleteExpiredAsync` | → `<c>` |

> 同批迁移类型之间的 cref（如 ISecurityLogQueryService → SecurityLogListItemDto/GetDetailAsync、PagedResult → ListItemDto、Analytics → FailureStat/Options）**保留**——同程序集可解析。

### 5.4 Account 侧改造

<!-- 改造后（注释同步更新） -->

- **删除 L66-81 整块**（13 行架构决策注释 + `<PropertyGroup><NoWarn>...`）——该注释即债的决策记录，落地后删除属债务清偿闭环；豁免机制不再需要（已走标准 Abstractions 路径）。

- `Extension.Account.Tests.csproj` **零改动**——测试项目引用 Account 本体即传递获取 Abstractions 契约；L41 对 SecurityLog 本体的 ProjectReference 是集成测试建真表用（非门控对象，测试项目不在 L2 检查范围），保留。

## 七、风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| SG1 `[Options]` 绑定迁出后失配 | SecurityLoggingOptions 配置节不绑定（高影响） | **已实证消除**：SG1 收集覆盖 `ReferencedAssemblySymbols`（生成器 L1447-1471）；验收 D7 构建后核验 `GeneratedOptionsBindings.g.cs` |
| 契约包意外依赖主框架 | "零依赖"描述失真 | `SecurityLoggingOptions` 需 `TKW.Framework.Domain` 的 `[Options]`——**对齐 Permissions.Abstractions 先例**（其同样引 TKWF.Domain）；其余 10 类型纯 BCL，README 标注实际依赖面 |
| cref 断裂（CS1574） | 警告噪音 | 6 处改 `<c>` 纯文本（§5.3 清单）；仓库未启 TreatWarningsAsErrors |
| 契约迁出遗漏实现类内部引用的契约文件 | 编译错误 | 前置盘点完成：11 契约文件 1:1 全量迁移，实现类 internal 留本体 |
| 外部消费方编译期引用迁移接口（二进制移动） | 消费方需补引 Abstractions 包 | **与 Emailing.Abstractions 先例同构**（评估记录见 §七注）——扩展迭代审核报告核引用面 |
| 测试项目引用 SecurityLog 本体（D9 场景） | 误删导致集成测试失联 | 保留 `Extension.Account.Tests.csproj` L41 本体引用（建真表用），仅 Account 生产项目切换 Abstractions |

> **注（兼容性评估，非阻塞）**：接口迁入新程序集后，SecurityLog 的公开查询接口（`ISecurityLogQueryService` 等）属**二进制移动**——编译期引用这些接口的消费方需补引 `TKWF.Ext.SecurityLog.Abstractions` 包。本仓库内除 Account 外无其他扩展编译期引用（前置盘点：`using TKWF.Ext.SecurityLog` 仅 LoginHistoryService.cs 一处）；该影响在扩展迭代审核报告中核一遍引用面即可，与 Emailing.Abstractions 迁移先例（ADR48 D7 既定路径）同构。
