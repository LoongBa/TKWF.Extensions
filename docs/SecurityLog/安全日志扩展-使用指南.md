# SecurityLog 安全日志扩展-使用指南

> 扩展：`TKWF.Ext.SecurityLog`（v0.1.0）——认证/授权安全事件记录与查询（登录成败/登出/改密/重置/锁定/注册/挑战 + IP/UA/结果/详情）。
> 本指南公开；迭代开发方案/ADR/审核报告见主框架私有 `_TKWF/docs/03_扩展模块/SecurityLog/`。

---

## 1. 本扩展解决什么

主框架审计日志（`TKWF.Ext.AuditLogging`）记录**方法调用事件**（业务操作追踪），**无安全事件维度**（EventType/IP/UserAgent/Result）——登录失败来源 IP、暴力破解轨迹、改密操作无法从 AuditLog 回答。

本扩展提供：
- **独立安全事件实体** `SecurityLog`（SG1）：登录/登出/改密/密码重置/锁定/注册/挑战 + IP/UA/结果/详情/关联 ID；
- **自动采集**（Domain AOP 过滤器）：拦截 `AuthController` 安全方法与 `IPasswordResetFlow`，无需改主框架，消费方 opt-in；
- **查询 API**：按用户/IP/事件类型/结果/时间分页检索 + 计数。

**与相关扩展划界**：
- **AuditLogging** = 方法调用审计（业务操作追踪）；**SecurityLog** = 安全事件记录（认证/授权，含 IP/UA/结果）——两者并存、语义不同。
- **Account** V0.3.0「登录历史与异常检测」将**消费本扩展查询**（SecurityLog 为唯一数据源），Account 不重复建表。

## 3. 启用 + 接线

```csharp
// ① 白名单启用（v4.9.85+：发现不自动启用）
[TKWFEnabledExtension(typeof(SecurityLogExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ② 采集接线：全局注册安全日志过滤器（opt-in——只拦安全方法，白名单判定）
    protected override void ConfigureGlobalFilters(FilterBuilder<MyUserInfo> builder)
        => builder.AddSecurityLog();
}
```

> 过滤器经 Domain AOP 管线拦截 `AuthController` 安全方法与 `IPasswordResetFlow` 实现（CanWeGo 白名单：目标类型 `IAuthController`/`IPasswordResetFlow` + 8 个方法名）；成功/失败自动判定，异常（`AuthenticationException`）记 Failed，其他异常不拦截（保持原语义）。

## 4. 配置（`TKWF:SecurityLog`）

```jsonc
{
  "TKWF": {
    "SecurityLog": {
      "Enabled": true,                        // false = 过滤器零开销（不采集）
      "EventTypes": [                         // 启用的事件类型（默认全部）
        "Login", "Logout", "PasswordChange", "PasswordReset",
        "Lockout", "Register", "Challenge"
      ]
    }
  }
}
```

## 5. 事件类型

| EventType | 触发 | Result 判定 |
|-----------|------|------------|
| `Login` | `LoginByPasswordAsync`/`LoginByContextAsync` | 成功 = 正常返回；失败 = 捕获 `AuthenticationException` 记 Failed（含 Detail 脱敏异常消息） |
| `Logout` | `LogoutAsync` | 正常返回即 Success |
| `PasswordChange` | `ChangePasswordSecureAsync` | 成功/失败（旧密码错误等） |
| `PasswordReset` | `InitiateResetAsync`/`CompleteResetAsync`（`IPasswordResetFlow` 实现） | 成功/失败（`ResetResult.Success`） |
| `Lockout` | `LoginByContextAsync` 锁定分支 | 异常消息含「锁定」判定 Failed（v0.1.0 语义） |
| `Register` | `RegisterSecureAsync` | 成功/失败（`RegisterResult.Success`） |
| `Challenge` | `RequestChallengeAsync` | 成功/失败 |

> `EventCategory` 统一 `Authentication`（v0.1.0 仅认证类事件；`Authorization` 值预留）。
> **防枚举语义**：登录失败记录**尝试用户名**（请求输入）——安全审计需要来源，不因防枚举丢失。

## 6. 查询

```csharp
public class SecurityQueryService(ISecurityLogQueryService query)
{
    public async Task<SecurityLogPagedResult> SearchAsync(string? ip = null, string? type = null)
        => await query.GetListAsync(new SecurityLogQueryInput(
            IpAddress: ip, EventType: type, Take: 50));
}
```

- `GetListAsync(input)`：分页过滤（UserName/IpAddress/EventType/Result/时间范围；Take 默认 50 上限 200）；
- `GetDetailAsync(id)`：详情（含 Detail 全文）；
- `CountAsync(input)`：计数（异常检测/仪表盘用）。

> **安全决策**：列表 DTO **不含 Detail**（异常消息/敏感摘要不随列表拉取），详情按 Id 取——对齐 AuditLogging 不含 ArgumentsJson 先例。

## 7. 安全与边界

- **Detail 脱敏**：仅记异常消息（不含密码/令牌/完整堆栈）；SensitiveFields 对齐 AuditLog 语义。
- **只增不改**：SecurityLog 是只写流水——扩展不暴露 Update/Delete API、无更新业务方法。
- **异常静默**：落库失败仅 Warning 日志，不阻断登录/改密流程。
- **不实现**：异常检测算法/告警（v0.2.0 候选）；实时推送（v0.2.0）；保留天数清理（v0.2.0）。
