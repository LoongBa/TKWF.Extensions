# 设置管理扩展使用指南

> **扩展版本**: V0.1.0 | **框架版本**: .NET 10 | **状态**: 核心业务扩展

本指南介绍如何在消费方项目中使用 `TKWF.Ext.Settings` 扩展进行设置管理与持久化。

---

## 快速开始

### 1. 添加项目引用

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\Framework\Settings\TKWF.Ext.Settings.csproj" />
```

### 2. 启用扩展（V4.9.85+ 必需）

扩展经 `[TKWFExtension]` 被 SG1 编译期发现（生成能力清单）。**V4.9.85 起发现不自动启用**：消费方须在领域初始化器上声明白名单，三钩子才接线：

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.Settings;

[TKWFEnabledExtension(typeof(SettingsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

若不声明 `[TKWFEnabledExtension]`，扩展的三钩子（ConfigureServices / ConfigureFilters / InitializeAsync）不会执行，DI 注册不会生效。

白名单声明后自动注册：`ISettingStore`（默认 `FreeSqlSettingStore`）+ `ISettingManager`（默认 `SettingManager`）。

### 3. 读写设置

```csharp
// 注入 ISettingManager
public class MyService(ISettingManager settingManager)
{
    // 读取字符串设置
    public async Task<string> GetThemeAsync()
    {
        return await settingManager.GetAsync("Theme", "light");
    }

    // 读取强类型设置
    public async Task<int> GetMaxRetriesAsync()
    {
        return await settingManager.GetAsync("MaxRetries", 3);
    }

    // 写入设置
    public async Task SetThemeAsync(string theme)
    {
        await settingManager.SetAsync("Theme", theme);
    }

    // 写入强类型设置（自动 JSON 序列化）
    public async Task SetConfigAsync(AppConfig config)
    {
        await settingManager.SetAsync("AppConfig", config);
    }
}
```

## 配置选项

通过 `appsettings.json` 配置：

```json
{
  "TKWF": {
    "Settings": {
      "DefaultSettingValueProvider": "Global",
      "IsEnabled": true
    }
  }
}
```

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `DefaultSettingValueProvider` | "Global" | 默认设置值提供者名称 |
| `IsEnabled` | true | 是否启用设置管理 |

## 自定义实现

### 替换 ISettingStore

若需使用其他存储后端（如 Redis、文件）：

```csharp
// 消费方 ConfigureServices 中
services.AddScoped<ISettingStore, RedisSettingStore>();
```

TryAdd 语义确保消费方实现优先。

### 替换 ISettingManager

若需自定义分层逻辑：

```csharp
// 消费方 ConfigureServices 中
services.AddScoped<ISettingManager, CustomSettingManager>();
```

## 分层读取（V0.2.0 规划）

V0.1.0 仅支持 Global 层；V0.2.0 将实现完整分层：

```
读取顺序：User → Tenant → Global → 默认值
```

- **User 层**：按当前用户 ID 读取
- **Tenant 层**：按当前租户 ID 读取
- **Global 层**：全局设置（ProviderKey = null）

---

## 最佳实践

1. **命名规范**：设置名称使用 PascalCase（如 `Theme`、`MaxRetries`）
2. **默认值**：始终提供合理的默认值，确保设置缺失时系统仍可运行
3. **类型安全**：优先使用强类型 Get/Set，避免手动 JSON 序列化
4. **异常处理**：扩展内部已静默处理异常，消费方无需额外 try-catch

## 故障排查

### 设置读取失败

- 检查数据库连接是否正常
- 检查 `Setting` 表是否存在（FreeSql 自动建表）
- 查看 Warning 日志：`"设置读取失败: Name=..."`

### 设置写入失败

- 检查数据库连接是否正常
- 检查字段长度限制（Name: 256, Value: MAX, ProviderName: 128, ProviderKey: 128）
- 查看 Warning 日志：`"设置写入失败: Name=..."`
