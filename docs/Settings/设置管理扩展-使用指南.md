# 设置管理扩展使用指南

> **扩展版本**: V0.2.0 | **框架版本**: .NET 10 | **状态**: 核心业务扩展

本指南介绍如何在消费方项目中使用 `TKWF.Ext.Settings` 扩展进行设置管理与持久化。

---

## 快速开始

### 1. 添加项目引用

```xml
<!-- 消费方 .csproj -->
<ProjectReference Include="..\Framework\Settings\TKWF.Ext.Settings.csproj" />
```

### 2. 启用扩展（V4.9.85+ 必需）

扩展经 `[TKWFExtension]` 被 SG1 编译期发现（生成能力清单）。**V4.9.85 起发现不自动启用**：消费方须在领域初始化器上声明白名单，三钩子才接线：

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.Settings;

[TKWFEnabledExtension(typeof(SettingsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

若不声明 `[TKWFEnabledExtension]`，扩展的三钩子（ConfigureServices / ConfigureFilters / InitializeAsync）不会执行，DI 注册不会生效。

白名单声明后自动注册：`ISettingStore`（默认 `FreeSqlSettingStore`）+ `ISettingManager`（默认 `SettingManager`）+ `IMemoryCache`（默认 `MemoryCache`）。

### 3. 读写设置

```csharp
// 注入 ISettingManager
public class MyService(ISettingManager settingManager)
{
    // 读取字符串设置
    public async Task<string> GetThemeAsync()
    {
        return await settingManager.GetAsync("Theme", "light");
    }

    // 读取强类型设置
    public async Task<int> GetMaxRetriesAsync()
    {
        return await settingManager.GetAsync("MaxRetries", 3);
    }

    // 写入设置（已认证用户写入 User 层，匿名写入 Global 层）
    public async Task SetThemeAsync(string theme)
    {
        await settingManager.SetAsync("Theme", theme);
    }

    // 写入强类型设置（自动 JSON 序列化）
    public async Task SetConfigAsync(AppConfig config)
    {
        await settingManager.SetAsync("AppConfig", config);
    }
}
```

## 分层读取（V0.2.0）

V0.2.0 实现完整分层读写：

```
读取顺序：User → Tenant → Global → 默认值
```

- **User 层**：按当前用户 ID 读取（`ProviderName = "User"`, `ProviderKey = userId`）
- **Tenant 层**：按当前租户 ID 读取（`ProviderName = "Tenant"`, `ProviderKey = tenantId`）
- **Global 层**：全局设置（`ProviderName = "Global"`, `ProviderKey = null`）

### 匿名降级

`IsAuthenticated == false` 时跳过 User/Tenant 层，直接查 Global → 默认值。匿名用户无 UserId/TenantId，查 User/Tenant 层无意义且可能误命中其他用户数据。

### 写入层

- **已认证用户**：`SetAsync` 写入 User 层（`ProviderName = "User"`, `ProviderKey = userId`）
- **匿名用户**：`SetAsync` 写入 Global 层

## 内存缓存（V0.2.0）

V0.2.0 引入 `IMemoryCache` 读缓存，减少 Store 查询次数：

- **缓存 key**：`Setting:{ProviderName}:{ProviderKey}:{Name}`（如 `Setting:User:42:Theme`）
- **缓存过期**：`SettingsOptions.CacheExpirationSeconds` 默认 300 秒（5 分钟）
- **缓存失效**：`SetAsync` 后自动清除对应 key 的缓存
- **TryAddSingleton**：消费方可覆盖为分布式缓存等实现

## 配置选项

通过 `appsettings.json` 配置（SG1 自动绑定 `TKWF:Settings` 节，无需消费方手动调用 `Configure`）：

```json
{
  "TKWF": {
    "Settings": {
      "DefaultSettingValueProvider": "Global",
      "IsEnabled": true,
      "CacheExpirationSeconds": 300
    }
  }
}
```

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `DefaultSettingValueProvider` | "Global" | 默认设置值提供者名称 |
| `IsEnabled` | true | 是否启用设置管理 |
| `CacheExpirationSeconds` | 300 | 缓存过期时间（秒） |

> **Options 绑定（V0.2.0）**：`SettingsOptions` 标注 `[Options("TKWF:Settings")]`——SG1 在消费方生成
> `GeneratedOptionsBindings`，宿主启动期自动执行 `services.Configure<SettingsOptions>(configuration.GetSection("TKWF:Settings"))`，
> 无需消费方手动绑定（与 Navigation/Permissions 同模式）。亦可在消费方 `ConfigureExtensions` 中
> `services.Configure<SettingsOptions>(o => ...)` 覆盖。

## 自定义实现

### 替换 ISettingStore

若需使用其他存储后端（如 Redis、文件）：

```csharp
// 消费方 ConfigureServices 中
services.AddScoped<ISettingStore, RedisSettingStore>();
```

TryAdd 语义确保消费方实现优先。

### 替换 ISettingManager

若需自定义分层逻辑：

```csharp
// 消费方 ConfigureServices 中
services.AddScoped<ISettingManager, CustomSettingManager>();
```

### 替换 IMemoryCache

若需使用分布式缓存：

```csharp
// 消费方 ConfigureServices 中
services.TryAddSingleton<IMemoryCache, DistributedMemoryCache>();
```

## 最佳实践

1. **命名规范**：设置名称使用 PascalCase（如 `Theme`、`MaxRetries`）
2. **默认值**：始终提供合理的默认值，确保设置缺失时系统仍可运行
3. **类型安全**：优先使用强类型 Get/Set，避免手动 JSON 序列化
4. **异常处理**：扩展内部已静默处理异常，消费方无需额外 try-catch
5. **缓存调优**：根据业务场景调整 `CacheExpirationSeconds`（配置类数据建议 300s，高频变更数据建议更短）

## 故障排查

### 设置读取失败

- 检查数据库连接是否正常
- 检查 `Setting` 表是否存在（FreeSql 自动建表）
- 查看 Warning 日志：`"设置读取失败: Name=..."`

### 设置写入失败

- 检查数据库连接是否正常
- 检查字段长度限制（Name: 256, Value: MAX, ProviderName: 128, ProviderKey: 128）
- 查看 Warning 日志：`"设置写入失败: Name=..."`

### 缓存不生效

- 确认 `IMemoryCache` 已注册（扩展自动注册，或消费方自行注册）
- 确认 `SetAsync` 后缓存已失效（扩展自动清除）
- 调整 `CacheExpirationSeconds` 以匹配业务需求
