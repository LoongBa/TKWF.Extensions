# 设置管理扩展使用指南

> **扩展版本**: v0.3.1 | **框架版本**: .NET 10 | **状态**: 核心业务扩展

本指南介绍如何在消费方项目中使用 `TKWF.Ext.Settings` 扩展进行设置管理与持久化。

---

## 快速开始

### 1. 添加项目引用

```xml
<!-- 消费方 .csproj：NuGet 包模式（推荐，已发布 TKWF.Ext.Settings） -->
<PackageReference Include="TKWF.Ext.Settings" Version="0.3.1" />

<!-- 源码模式（本仓库联调） -->
<ProjectReference Include="..\..\_Framework\Settings\TKWF.Ext.Settings.csproj" />
```

### 2. 启用扩展（V4.9.85+ 必需）

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.Settings;

[TKWFEnabledExtension(typeof(SettingsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

白名单声明后自动注册：`ISettingManager`（默认 `SettingManager`，`AddConstructibleService` 接口守卫工厂）+ `IMemoryCache`（默认 `MemoryCache`）。

### 3. 读写设置（V0.3.0 起：领域服务门面经 `User.Use<T>()`）

```csharp
// V0.3.0：ISettingManager 是领域服务（禁构造注入——DI004 零豁免）——经 User.Use<ISettingManager>() 解析
public class MyService : DomainServiceBase
{
    public MyService(IDomainUser user) : base(user) { }

    // 读取字符串设置
    public async Task<string> GetThemeAsync()
    {
        var settingManager = User.Use<ISettingManager>();
        return await settingManager.GetAsync("Theme", "light");
    }

    // 读取强类型设置
    public async Task<int> GetMaxRetriesAsync()
    {
        var settingManager = User.Use<ISettingManager>();
        return await settingManager.GetAsync("MaxRetries", 3);
    }

    // 写入设置（已认证用户写入 User 层，匿名写入 Global 层）
    public async Task SetThemeAsync(string theme)
    {
        var settingManager = User.Use<ISettingManager>();
        await settingManager.SetAsync("Theme", theme);
    }

    // 写入强类型设置（自动 JSON 序列化）
    public async Task SetConfigAsync(AppConfig config)
    {
        var settingManager = User.Use<ISettingManager>();
        await settingManager.SetAsync("AppConfig", config);
    }
}
```

## 分层读取（V0.2.0）

V0.2.0 实现完整分层读写：

```
读取顺序：User → Tenant → Global → 默认值
```

- **User 层**：按当前用户 ID 读取（`ProviderName = "User"`, `ProviderKey = userId`）
- **Tenant 层**：按当前租户 ID 读取（`ProviderName = "Tenant"`, `ProviderKey = tenantId`）
- **Global 层**：全局设置（`ProviderName = "Global"`, `ProviderKey = null`）

### 匿名降级

`IsAuthenticated == false` 时跳过 User/Tenant 层，直接查 Global → 默认值。匿名用户无 UserId/TenantId，查 User/Tenant 层无意义且可能误命中其他用户数据。

### 写入层

- **已认证用户**：`SetAsync` 写入 User 层（`ProviderName = "User"`, `ProviderKey = userId`）
- **匿名用户**：`SetAsync` 写入 Global 层

## 内存缓存（V0.2.0）

V0.2.0 引入 `IMemoryCache` 读缓存，减少 Store 查询次数：

- **缓存 key**：`Setting:{ProviderName}:{ProviderKey}:{Name}`（如 `Setting:User:42:Theme`）
- **缓存过期**：`SettingsOptions.CacheExpirationSeconds` 默认 300 秒（5 分钟）
- **缓存失效**：`SetAsync` 后自动清除对应 key 的缓存
- **TryAddSingleton**：消费方可覆盖为分布式缓存等实现

## 配置选项

通过 `appsettings.json` 配置（SG1 自动绑定 `TKWF:Settings` 节，无需消费方手动调用 `Configure`）：

```json
{
  "TKWF": {
    "Settings": {
      "CacheExpirationSeconds": 300
    }
  }
}
```

| 选项 | 默认值 | 说明 |
|------|--------|------|
| `CacheExpirationSeconds` | 300 | 缓存过期时间（秒） |
| `DefaultSettingValueProvider` | "Global" | ⚠️ **预留未消费**（全仓零消费，配置不改变任何行为，勿依赖） |

> **Options 绑定（V0.2.0）**：`SettingsOptions` 标注 `[Options("TKWF:Settings")]`——SG1 在消费方生成
> `GeneratedOptionsBindings`，宿主启动期自动执行 `services.Configure<SettingsOptions>(configuration.GetSection("TKWF:Settings"))`，
> 无需消费方手动绑定（与 Navigation/Permissions 同模式）。亦可在消费方 `ConfigureExtensions` 中
> `services.Configure<SettingsOptions>(o => ...)` 覆盖。

## 自定义实现（V0.3.0 起——正确路线）

### 自定义 ISettingManager（领域服务定制）

**V0.3.0（ADR90）：`ISettingStore`/`FreeSqlSettingStore` 已删除**（伪 Store 层）。若需自定义分层逻辑——实现为领域服务（继承 `DomainServiceBase` + 接口标 `IDomainService`）：

```csharp
public sealed class CustomSettingManager : DomainServiceBase, ISettingManager
{
    private SettingEntityDataService? _ds;
    private SettingEntityDataService Ds => _ds ??= User.Use<SettingEntityDataService>();
    public CustomSettingManager(IDomainUser user) : base(user) { }
    // 实现 ISettingManager 四方法——委托 Ds（GetByKeyAsync/UpsertByKeyAsync 等）
}

// 消费方 ConfigureServices 中
services.AddConstructibleService<ISettingManager, CustomSettingManager>();
```

### 替换 IMemoryCache

若需用分布式缓存替换默认的内存实现，注意两点：① `IMemoryCache` 是内存缓存抽象——分布式缓存（Redis 等）实现 `IDistributedCache` 而非 `IMemoryCache`，需用 `Microsoft.Extensions.Caching.Memory` 的 `MemoryDistributedCache` 适配（实现 `IDistributedCache`，内部可选包装 `IMemoryCache` 作 L1），或改用 `SettingsOptions.CacheExpirationSeconds` 之外自行接入分布式缓存层；② `TryAddSingleton` **不覆盖已注册**实现（扩展已 `TryAddSingleton<IMemoryCache, MemoryCache>` 注册，消费方 TryAdd 会被跳过——须用 `AddSingleton`/`RemoveAll` 显式替换）：

```csharp
// 消费方 ConfigureServices 中——显式替换（TryAddSingleton 不覆盖已注册，须 Add 系方法）
services.RemoveAll<IMemoryCache>();                                   // 先移除扩展默认
services.AddSingleton<IMemoryCache>(sp => new MemoryCache(new MemoryCacheOptions()));  // 或替换为自定义实现
```

> ⚠️ 扩展缓存语义基于 `IMemoryCache`（进程内）；Redis 等多实例共享缓存需自行接入（`IDistributedCache` 不是 `IMemoryCache` 的子类型，不可直接替换注册）。

## 最佳实践

1. **命名规范**：设置名称使用 PascalCase（如 `Theme`、`MaxRetries`）
2. **默认值**：始终提供合理的默认值，确保设置缺失时系统仍可运行
3. **类型安全**：优先使用强类型 Get/Set，避免手动 JSON 序列化
4. **异常处理**：扩展内部已静默处理异常，消费方无需额外 try-catch
5. **缓存调优**：根据业务场景调整 `CacheExpirationSeconds`（配置类数据建议 300s，高频变更数据建议更短）

## 故障排查

### 设置读取失败

- 检查数据库连接是否正常
- 检查 `TKWF_Setting` 表是否存在（FreeSql 自动建表）
- 查看 Warning 日志：`"设置读取失败: Name=..."`

### 设置写入失败

- 检查数据库连接是否正常
- 检查字段长度限制（Name: 256, Value: MAX, ProviderName: 128, ProviderKey: 128）
- 查看 Warning 日志：`"设置写入失败: Name=..."`

### 缓存不生效

- 确认 `IMemoryCache` 已注册（扩展自动注册，或消费方自行注册）
- 确认 `SetAsync` 后缓存已失效（扩展自动清除）
- 调整 `CacheExpirationSeconds` 以匹配业务需求
