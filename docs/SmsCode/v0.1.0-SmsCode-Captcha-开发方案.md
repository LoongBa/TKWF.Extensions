## 1. 需求与背景

DMP-Lite（P1）：手机号验证码登录（发送/校验/登录适配）+ CHAPTCHA 人机验证（防短信接口滥用）。UserH5 前端已按预留端点完成对接，等待服务端契约落地。

框架侧（本方案依托的架构裁定链，详见设计梳理文档）：
- **C1**：独立立项（不并入 AuthCenter——商户会员域 vs 全局账号域）；模块名 `TKWF.Ext.SmsCode`（不含登录编排）
- **b+ 共识**：引擎按"未来统一核心的胚胎"写（场景注册表驱动、零 DMP 逻辑、Subject 不透明键控——X' 冻结项 1）
- **Captcha 即日拆分**：独立模块 + Abstractions（第二消费者设计期即出现：AuthCenter 注册/找回匿名面）
- **X' 收敛裁定**：MFA/AuthCenter 本期不迁移；六项 ADR 冻结保未来廉价收敛（本方案 §4/§5 落实）

## 2. 模块范围与边界

| 模块 | 做（v1 冻结） | 不做（边界） |
|---|---|---|
| **TKWF.Ext.SmsCode** | 短信验证码引擎（手机号持有权验证）：发送/校验/频控/落库/场景注册表/CAPTCHA 门禁内联 | 登录编排（归消费方：DMP MemberLoginService 形态）；AuthCenter/MFA 引擎迁移（X' 触发器驱动）；语音/邮件/TOTP 通道（谱系 LATER）；外部验证服务型引擎（Twilio Verify 形态） |
| **TKWF.Ext.Captcha（+Abstractions）** | `ICaptchaProvider` SPI + 本地图形 Provider v1 + 挑战门面（Issue/Verify）+ 挑战态存储（v1 in-memory）+ 契约包 | 第三方 Provider 适配器（腾讯/极验/阿里——DMP 选型后纯增量）；评分型/滑块/行为/音频（谱系 LATER）；场景归属（"哪些场景要门禁"归消费方场景注册表） |
| 主框架 | 零新 API 依赖（IRateLimitCheck/SG1/DomainServiceBase 均既有） | 不提取、不改动 |

## 4. TKWF.Ext.SmsCode 设计

### 4.1 实体（SmsCodeRecordEntity，SG1）——M2 闭环（评审）：xCodeGen 配置与 .g.cs 入库

```csharp
[Table("TKWF_SmsCode")]
[FreeSql.DataAnnotations.Index("TKWFIX_SmsCode_SubjectSceneTime", nameof(Subject) + "," + nameof(Scene) + "," + nameof(CreateTime))]
[FreeSql.DataAnnotations.Index("TKWFIX_SmsCode_IpTime", nameof(IpAddress) + "," + nameof(CreateTime))]
[DomainGenerateCode(DefaultPageSize = 50)]
public partial class SmsCodeRecordEntity
{
    long Id;                        // 自增主键
    string Subject;                 // ⚠️ X' 冻结项 1：不透明主体键（v1 恒=手机号，[MaxLength(20)]），列名 Subject 不叫 Phone
    string? DeliveryTarget;         // 投递目标（v1 恒=手机号，与 Subject 分离——MFA 未来 subject=user×method 而投递=绑定号），[MaxLength(20)]
    string Scene;                   // 场景（SmsScenes 白名单），[MaxLength(20)] fail-closed
    string CodeHash;                // SHA256 hex（明文不落库），[MaxLength(64)]
    bool IsVerified;                // 单次消费
    string? IpAddress;              // 请求 IP（频控维度），[MaxLength(45)]
    DateTime ExpireAt;              // TTL（UTC）
    long? FailedAttempts;           // 同码连续失败计数（M3 闭环——FailedVerifyInvalidateThreshold 作废机制落点；null=0 语义）
    DateTime CreateTime;            // UTC；索引 (Subject,Scene,CreateTime)/(IpAddress,CreateTime)
}
```

- 只增语义（无 Update/Delete 公开业务方法，对齐 SmsRecord 先例）；`FailedAttempts` 为可更新列（CAS `WHERE IsVerified=false` 下自增）
- **重发作废旧码机制（M3 闭环）**：send 通过频控后 CAS `EntityUpdateWhereAsync` 将本 (Subject,Scene) 全部未消费未过期记录的 `ExpireAt` 置 now（`WHERE IsVerified=false AND ExpireAt>now`）——旧码即时失效，`MaxActiveCodesPerSubject` 只统计未失效记录；**不是** verify-latest-only（后者导致活跃计数膨胀）
- **xCodeGen 配置**：`\.xCodeGen\extensions\smscode.xCodeGen.json`（已建，TargetProject/OutputRoot 指向 `_Framework\SmsCode\`，OutputDir 相对 OutputRoot 的 `..\Entities`/`..\DataServices` 风格）；实体变更后运行 `pwsh .xCodeGen/run-xcodegen.ps1 -Ext smscode`，**.g.cs 随代码一并提交**（仓库法 checklist 1-5，禁只改实体不提交生成物）
- ⚠️ 模板/内容列红线：本实体无内容列（验证码散列定长 64）；后续如有模板列须显式 `[MaxLength(-1)]`

### 4.2 引擎（VerificationCodeEngine，internal）

- 码生成：`RandomNumberGenerator.GetInt32(1_000_000).ToString("D6")`（加密安全，禁 System.Random）
- 散列：SHA256 hex（小写，统一 MFA 先例——X' 裁定实证漂移修复方向）
- 单次消费：CAS `WHERE Id=? AND IsVerified=false`（ADR89 EntityUpdateWhereAsync）
- 比对：`CryptographicOperations.FixedTimeEquals`（统一 MFA 先例——ǫ知 AuthCenter 用 string.Equals 为漂移实证，新引擎直接采用正确形态）
- TTL：Options 配置（默认 5min）
- 场景注册表驱动：scene → 策略（码长/TTL/频控/RequiresCaptcha），零 DMP 逻辑

### 4.3 门面（ISmsCodeService）

```csharp
public interface ISmsCodeService : IDomainService
{
    Task<SmsCodeSendResult> SendCodeAsync(string scene, string subject, string deliveryTarget,
        string? captchaToken, CancellationToken ct = default);
    Task<SmsCodeVerifyResult> VerifyCodeAsync(string scene, string subject, string code,
        CancellationToken ct = default);
}
```

- 注册：`AddConstructibleService<ISmsCodeService, SmsCodeService>`；实现继承 `DomainServiceBase`
- **门禁内联（Q6 裁定）**：`scene.RequiresCaptcha=true` → 先经 `Captcha.Abstractions` 门面验 captchaToken（缺失/无效 → fail-closed 错误码）；**场景要求门禁但 Captcha 未装配 → 守卫异常（禁静默跳过）**；captchaToken 格式冻结：`{challengeId}:{answer}`（challengeId=32hex、answer 无歧义字母表均不含 ':'，分隔安全）
- 门禁序：CAPTCHA 校验 → 频控检查 → 生成码 → 落库 → 发送（Casdoor 保预算先例）
- 发送失败：发送器异常向上传播（调用方 503 语义）；记录不标记 verified（自然过期作废）

### 4.4 类型化结果 + 错误契约分层（X' 冻结项 2）

```csharp
// 引擎层：类型化结果（错误码映射住 DMP 门面/端点层——MFA 未来委托不继承 DMP 错误契约）
public sealed record SmsCodeSendResult(bool Sent, SmsCodeSendFailure? Failure, int? RetryAfterSeconds);
public enum SmsCodeSendFailure { None, CaptchaFailed, RateLimited, SenderUnavailable, UnknownScene, ScopeMissing }
public sealed record SmsCodeVerifyResult(bool Verified, SmsCodeFailure? Failure);
public enum SmsCodeFailure { None, NotFound, Expired, Mismatch, RateLimited, UnknownScene, ScopeMissing }
```

- **M1 闭环（评审）**：SendResult 带 `SmsCodeSendFailure` 判别——DMP 端点据此映射 `chaptcha_failed`(400)/`rate_limited`(429)/`sms_sender_unavailable`(503) 等，无歧义
- 发送器异常：`SenderUnavailable` 类型化返回（调用方 503 语义），不落异常日志明文
- DMP 侧端点映射（snake_case，与既有通道同表）：`chaptcha_failed`/`rate_limited`/`invalid_mobile`/`invalid_scene`（400——未知场景）/`sms_sender_unavailable`（503——发送器不可用）/`invalid_code`/`code_expired`/`invalid_merchant`/`member_disabled`/`session_create_failed`/`internal_error`（oracle2 冻结全表，见 §6）

### 4.5 投递与租户 SPI

```csharp
public interface ISmsSender   // send-only（发送即服务形态；生产未装配 → 503 fail，对齐 ISmsSender 先例）
```

- 注册：TryAdd（smt sender 无默认；ScopeResolver 默认空串单例，消费方 TryAdd 覆盖）

- **m2 闭环（评审）——IP 获取路径**：`SmsCodeService` ctor 可选注入 `IHttpContextAccessor`，`RemoteIpAddress` 取 IP；空白/未注册 → `unknown` 桶（fail-closed，AuthCenter AC-02 同款）
- 频控键：`smscode:{scope}:{scene}:{subject}`（ScopeResolver 前缀 + Scene + Subject；**严禁复用 AuthCenter `sms-ip:` 桶**——X' 冻结项 + 塑形决策 2）

### 4.6 场景与频控（SmsScenes + Options）

```csharp
public static class SmsScenes { public const string Login = "login"; }  // v1 闭集：login（DMP 所需）；扩场景=加条目不加引擎
```

```jsonc
// TKWF:SmsCode 节（领域配置，Web 层不可关闭）
{ "SmsCode": {
    "SmsResendIntervalSeconds": 60,      // 同 subject+scene 重发间隔
    "SmsDailyLimitPerSubject": 10,       // 每主体日上限（oracle2 冻结：比 AuthCenter 20 收紧）
    "SmsHourlyLimitPerSubject": 5,       // 每主体小时上限
    "SmsHourlyLimitPerIp": 20,           // IP 桶（send+verify 共享，IRateLimitCheck 点检查）
    "MaxActiveCodesPerSubject": 5,       // 活跃未消费码上限（防轰炸发送）
    "VerifyAttemptsPerWindow": 5,        // 校验尝试上限（15min 窗，计数 verify 调用而非活跃记录——修正 AuthCenter 缺陷）
    "FailedVerifyInvalidateThreshold": 5,// 同码连续失败 N 次作废该码
    "CodeTtlMinutes": 5,
    "CodeLength": 6,
    "IsProduction": false,               // fail-fast 门（生产缺 ISmsSender → 拒绝发送）
    "Scenes": { "login": { "RequiresCaptcha": true } }   // 场景注册表：门禁开关 + 未来 per-scene 覆盖
}}
```

- **M3 闭环（评审）——频控计数落点**：subject 维日/小时上限 = **实体 COUNT**（SmsCodeRecordEntity 只增窗口查询，复用 (Subject,Scene,CreateTime) 索引——对齐 AuthCenter 已验证形状）；**verify 调用计数 = `IRateLimitCheck` 键 `smscode:verify:{scope}:{scene}:{subject}`**（15min 窗，计数调用非活跃记录——修正 AuthCenter 缺陷的落点）；**作废机制 = `FailedAttempts` 列 CAS 自增**（§4.1，`FailedAttempts>=Threshold` → 该码 ExpireAt 置 now）；IP 桶 = `IRateLimitCheck` 键 `smscode:ip:{scope}:{ip}`（send+verify 共享）
- **m6 闭环（评审）——未知场景 fail-closed**：场景不在注册表 → `SmsCodeSendResult.Failure=UnknownScene` / `SmsCodeVerifyResult.Failure=UnknownScene`（DMP 端点映射 400 `invalid_scene` 或按 internal 处理——不落入任何频控键，防换场景绕限）

### 4.7 装配（SmsCodeExtensionInitializer）

- `[TKWFExtension]` + 继承 `ExtensionInitializer<TUserInfo>`；三钩子：ConfigureServices 注册门面/SPI 默认/Options；零手动 DataService 注册（SG1 自动）

## 5. TKWF.Ext.Captcha 设计

### 5.1 SPI（ICaptchaProvider）——M4 闭环（评审）：类型拼写统一 Captcha（wire 层保留 chaptcha）

```csharp
public interface ICaptchaProvider : IDomainService
{
    string Type { get; }                                        // "image" / "geetest" / "tencent" / ...
    Task<CaptchaChallenge> IssueAsync(string scene, CancellationToken ct = default);
    Task<CaptchaVerifyResult> VerifyAsync(string challengeId, string answer, CancellationToken ct = default);
}
public sealed record CaptchaChallenge(string ChallengeId, string Payload, int TtlSeconds);  // Payload=Provider 自渲染不透明串（锁形状不锁媒介）
public sealed record CaptchaVerifyResult(bool Passed, double? Score = null);                // score 可选字段现在就入形状（评分型 Provider 门面按场景阈值裁决）
```

- **拼写约定（M4）**：模块/命名空间/配置键/公开类型一律 `Captcha`（`TKWF.Ext.Captcha`/`ICaptchaProvider`/`ICaptchaService`/`CaptchaChallenge`/`CaptchaVerifyResult`/`TKWF:Captcha`）；**wire 层保留 `chaptcha`**（端点路径 `sms/chaptcha`、错误码 `chaptcha_failed`、send-code body 字段 `chaptcha`——DMP 前端已按转达文档预留接入）。Scheme：wire 契约跟随消费方既有拼写，C# 类型遵循正确拼写
- 注册：`TryAddEnumerableConstructible`（多 Provider 集合，ADR92）；Options `EnabledProviderType` 选中（type 字符串匹配，未匹配 → fail-closed 异常）
- **CAPTCHA 场景无关**（只发/验挑战；"哪些场景要门禁"归消费方场景注册表）

### 5.2 本地图形 Provider（ImageCaptchaProvider，v1 唯一内置实现）

- 挑战生成：随机 4-6 位字符 → 答案 SHA256 散列存挑战态 → 渲染图形 Payload（**答案永不进客户端载荷**）
- 挑战态存储：v1 in-memory（`IMemoryCache`，TTL 5min + 单挑战答错上限 3 + 验证成功即消费）——⚠️ **in-memory CAS 非原子：单实例内自加锁（SemaphoreSlim per-challengeId 或全局轻锁）**；多实例局限写入使用指南（第三方 Provider 无状态可水平扩展）
- **m1 闭环（评审）**：Initializer 须 `TryAddSingleton<IMemoryCache>` 兜底 + `TryAddSingleton<IRateLimitCheck, MemoryRateLimitCheck>` fallback（守卫工厂 ActivatorUtilities 解析需可解析，AuthCenter V0.4.0 同款注记）——`IRateLimitCheck` 消费方显式注册 DB 实现时静默替换（对齐 MFA V0.2.1 先例）
- 图形渲染：**零第三方依赖优先**（System.Drawing 不可跨平台 → 评估纯托管方案/SVG/ASCII 变体；若需引入 SkiaSharp/ImageSharp **另行 ADR**——风险开放项，见 §11）
- 取题频控：Issue 本身按 IP 频控（`captcha:issue:{ip}`，默认 10/min），防挑战表洪泛
- 无障碍：音频变体 LATER（载荷不透明形状不阻断）

### 5.3 门面（ICaptchaService）

```csharp
public interface ICaptchaService : IDomainService
```

## 6. 端点契约（DMP 消费侧挂接——扩展零端点，对齐 WeChatChannels 非 Web 形态）

> 扩展提供门面能力；端点由消费方（DMP Merchant.WebApi）手写 MapPost 挂接（对齐 MemberLoginEndpoints 先例）。本契约 = oracle2 冻结版，供 DMP 落位。

```
POST /m/{mid}/api/auth/sms/send-code   Body: {mobile, chaptcha}
  → 200 {sent:true, retryAfterSeconds:60}
  → 400 chaptcha_failed|invalid_mobile        （400 仅参数校验/门禁失败）
  → 429 rate_limited (+retryAfterSeconds)     （频控统一 429——修订①）
  → 503 sms_sender_unavailable
POST /m/{mid}/api/auth/sms/login       Body: {mobile, code}
  → 200 IdentitySession（assurance="sms"/channelType="sms"/channelId=null/nextAction=open_vip，与 DMP 通道同构零适配）
  → 400 invalid_code|code_expired|invalid_merchant|invalid_credentials（未注册统一文案）
  → 403 member_disabled  → 429 rate_limited  → 500 session_create_failed|internal_error
POST /m/{mid}/api/auth/sms/chaptcha     Body: {}
  → 200 {challengeId, payload, ttlSeconds}    （修订②：CHAPTCHA 取题端点——硬缺口补入）
```

- **修订③（错误码命名）**：snake_case 业务域码对齐 DMP 既有通道（前端单一 errorCode→toast 映射表复用）；引擎层类型化结果（§4.4）在 DMP 端点层映射
- retryAfterSeconds 语义 = 距最严约束重置秒数（由扩展计算，消费方不得自推）
- 防枚举：send-code 对已注册/未注册号统一响应（不区分）；login 未注册 → invalid_credentials 同文案
- 安全边界（oracle2 清单）：未注册照发短信；Disabled/Frozen 状态仅登录时查（照发不泄露）；重发使旧码失效（ExpireAt 置 now 作废——非 verify-latest-only）；手机号归一化（`^1\d{10}$`，send/login 同一口径）；(MerchantUId, Mobile) 重复行守卫移植（P1-3 兜底）；验证码/CHAPTCHA 凭据不落日志
