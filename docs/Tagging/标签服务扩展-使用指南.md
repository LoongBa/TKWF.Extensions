# 标签服务扩展使用指南

> **扩展**: `TKWF.Ext.Tagging` | **版本**: v0.4.0（AC 自动机 + Options 配置接入）| **框架**: .NET 10
>
> **架构（ADR52）**: 标签算法内核（分词/匹配/流水线）在 `TKWF.Utility`（`TKW.Framework.Utility.Tags`）——纯算法零 DI 可独立调用；`TKWF.Ext.Tagging` 是**标签存储扩展**（DI 接线 + 规则/命中持久化 + Options 配置）。V0.4.0 落地 AC 自动机批量匹配（`DictMatch`）+ `TaggingOptions` 配置接入。

本指南帮助消费方集成标签服务扩展，实现文本标签提取、匹配与格式化。

---

## 一、能力概览

| 能力 | 说明 |
|------|------|
| 标签提取 | 分词 → 匹配器家族（精确/包含/正则/前缀/后缀/全文）→ 命中结果 |
| **词典批量匹配（V0.4.0）** | `DictMatch` 模式走 **AC 自动机**（Aho-Corasick）——单次文本扫描捞取全量词库命中，规则过千性能与规则数解耦 |
| 结果后处理 | 互斥裁剪（ExclusionGroup 优先）、默认标签兜底 |
| 业务门面 | `ITagService`（加载规则 + 提取标签 + 格式化输出） |
| **配置接入（V0.4.0）** | `TaggingOptions`（`TKWF:Tagging` 节）——默认规则声明 + Store 自动加载 |
| 零分配设计 | `TokenText` 坐标流 + `ReadOnlySpan<char>`，引擎核心 AOT 兼容（详见 `TKWF.Utility` README） |

> **双面契约（ADR52 决策 1）**：
> - **算法面**：`TKW.Framework.Utility.Tags` 纯算法类型（`ITokenizer`/`ITagMatcher` 家族/`ITagBatchMatcher`/`TagExtractionPipeline`/`TagService` 等）——不启用扩展也可 `new TagService(pipeline)` 独立调用
> - **扩展面**：`TKWF.Ext.Tagging` 经 `[TKWFEnabledExtension]` 白名单接入 DI（下方 §二/三）

## 二、安装

### 2.1 引用扩展项目

```xml
<!-- 消费方 .csproj -->
<ItemGroup>
  <ProjectReference Include="..\..\_Framework\Tagging\TKWF.Ext.Tagging.csproj" />
</ItemGroup>
```

### 2.2 启用扩展（v4.9.85+ 必需）

> **V4.9.85 (ADR47) 起**：扩展不再"发现即启用"。消费方需在领域初始化器上显式声明 `[TKWFEnabledExtension]`，扩展才进入白名单（三钩子执行）。

```csharp
// 消费方领域初始化器（DomainHostInitializerBase<TUserInfo> 子类）
using TKWF.Ext.Tagging;

[TKWFEnabledExtension(typeof(TaggingExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    // ...
}
```

自动注册（全部 TryAdd*，消费方可覆盖；类型来自 `TKWF.Utility`）：
- `ITokenizer` → `DefaultTokenizer`（Singleton）
- `ITagMatcher` 家族 ×6：`TokenExactMatcher` / `ContainsMatcher` / `RegexMatcher` / `StartsWithMatcher` / `EndsWithMatcher` / `FullMatchMatcher`（V0.4.0 补齐）（Singleton）
- `ITagBatchMatcher`（V0.4.0）：`AcAutomataBatchMatcher`（`DictMatch` AC 自动机）（Singleton）
- `ITagPipelinePostProcessor` ×2：`ExclusionGroupProcessor`（互斥裁剪）/ `DefaultTagProcessor`（默认标签兜底）
- `TagExtractionPipeline` + `ITagService` → `TagService`（Singleton）
- `TaggingOptions`（V0.4.0）：`TKWF:Tagging` 配置节绑定（下方 §3.5）

> 存储扩展（V0.3.0）：`ITagRuleStore` / `ITagHitStore` / `ITagAnalysisService` 三接口持久化已实施（规则 CRUD + 命中落库 + 聚合分析）。

## 三、使用

### 3.1 业务调用

```csharp
// 注入 ITagService
public class AnalysisService(ITagService tagService)
{
    public void Process(string input)
    {
        // 极简 API，内部自动调度流水线
        var hits = tagService.GetTags(input);

        foreach (var hit in hits)
        {
            // hit 包含：维度、标签名、命中位置、原词、优先级等
            _logger.LogInformation("命中标签: {Tag} (位置: {Start})", hit.TagName, hit.StartIndex);
        }
    }
}
```

### 3.2 加载规则

```csharp
// 规则来源于 DomainOptions.TagRules 或自定义来源
tagService.LoadRules(rules); // 业务运行时加载/热更新
```

### 3.3 自定义分词器 / 匹配器

消费方自定义实现后经 DI 覆盖默认：

```csharp
// 自定义分词器（如中文 NLP）替换默认
services.AddSingleton<ITokenizer, MyChineseTokenizer>();
// 消费方注册顺序决定取用——TryAddSingleton 不覆盖已注册项，需在扩展前注册或直接 AddSingleton 覆盖
```

### 3.4 匹配模式

规则经 `TagMatchMode` 路由到对应匹配器：`TokenExact` / `Contains` / `Regex` / `StartsWith` / `EndsWith` / `FullMatch`（V0.4.0 补齐）。

**词典批量匹配（`DictMatch`，V0.4.0）**——规则过千场景的推荐模式：

```csharp
// 行业词库：成千上万条规则声明为 DictMatch，引擎自动走 AC 自动机批量路径
tagService.LoadRules([
    new TagRule { Dimension = "industry", TagName = "专有名词", MatchMode = TagMatchMode.DictMatch, Pattern = "特定词" },
    // ... 更多词库规则
]);

// 单次文本扫描捞取全部命中（O(N)，与规则数解耦）；同一 Pattern 可被多维度/多标签共享
var hits = tagService.GetTags("包含特定词的文本");
```

> **大小写**：AC 自动机逐字符 `ToLowerInvariant`（OrdinalIgnoreCase 语义，对齐 ContainsMatcher）。ASCII/CJK 与 `OrdinalIgnoreCase` 等价；个别边缘 Unicode 字符（如土耳其 ı/İ）可能有差异。
> **重叠命中**：AC 输出全部出现位置（含重叠）——`TagService.GetTags` 按 `(Dimension, TagName)` 去重，最终结果与 ContainsMatcher 等价。

### 3.5 配置接入（`TaggingOptions`，V0.4.0）

配置节：`TKWF:Tagging`。消费方 appsettings.json：

```json
{
  "TKWF": {
    "Tagging": {
      "AutoLoadRulesFromStore": true,
      "DefaultRules": [
        { "Dimension": "brand", "TagName": "华为", "MatchMode": "DictMatch", "Pattern": "华为", "Priority": 0 }
      ]
    }
  }
}
```

| 配置项 | 默认 | 说明 |
|--------|------|------|
| `AutoLoadRulesFromStore` | `false` | 启动自动从 `ITagRuleStore.GetEnabledAsync()` 加载启用规则到内存引擎（闭环规则陈旧性） |
| `DefaultRules` | 空 | 配置节默认规则（静态词库场景，无需 DB）；`TagRule` 直接绑定（`MatchMode` 支持枚举字符串） |

**配置优先级**：Store 规则 > 配置节 DefaultRules > 无（消费方显式 `LoadRules`）。两条路径均未配置时启动日志 Warning 提示（软校验，不阻断）。

> **注意**：`LoadRules` **非线程安全**（`TagService` 内存规则驻留）——消费方应避免运行时并发调用；运行中 DB 变更仍需显式重调 `LoadRules`（无热更新监听）。

## 四、核心组件清单

| **组件** | **职责** | **默认实现** |
|----------|---------|------------|
| **`ITagService`** | 业务门面（规则加载 + 提取 + 格式化） | `TagService`（本扩展） |

| **`TagExtractionPipeline`** | 引擎流水线（分词→匹配→后处理） | 内置 |
| **`TagRule`** | 规则模型（模式/维度/优先级/ExclusionGroup） | 内置 |
| **`TaggingOptions`** | 扩展配置（V0.4.0，`TKWF:Tagging` 节） | 内置，`[Options]` SG1 绑定 |
| **`TaggingExtensionInitializer`** | 扩展初始化器（三钩子） | 内置，`[TKWFExtension]` SG1 发现 |

## 五、性能与约束

- **零分配**：核心循环不产生 `Substring`/`Split`/LINQ 分配——`TokenText` 仅为 8 字节坐标（`readonly struct`）
- **Native AOT**：全部组件无反射（禁 `Reflection.Emit`），可 AOT 发布
- **接口封闭**：命中结果输出 `IReadOnlyList<TagHit>`，下游不可修改
- **批量匹配（V0.4.0）**：`DictMatch` 规则过千时建议走 AC 自动机批量路径（O(N+Z) 单次扫描）；规则量小（<100）时 `ContainsMatcher` SIMD 已足够
- **`LoadRules` 非线程安全**：避免运行时并发调用（v0.3.0 既有约束，V0.4.0 使用指南强化注明）

## 七、常见问题

**Q: 标签规则从哪来？**
A: 三种来源——① 消费方自行组装 `TagRule` 后经 `tagService.LoadRules(rules)` 加载；② 配置节声明（`TKWF:Tagging:DefaultRules`，V0.4.0）；③ 启用 `AutoLoadRulesFromStore` 后启动自动从 `ITagRuleStore` 加载（V0.4.0）。优先级：Store > 配置 > 显式。

**Q: 高并发大批量规则性能如何？**
A: 规则声明为 `DictMatch` 模式即走 **AC 自动机批量匹配**（V0.4.0）——单次扫描 O(N)，与规则数解耦；规则量小（<100）时 `ContainsMatcher` 的 SIMD 滚动扫描已足够。
