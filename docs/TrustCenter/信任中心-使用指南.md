## 一、这是什么

`TKWF.Ext.TrustCenter` 解决"**跨应用间信任**"问题——签发给下游 SP 应用的**统一身份断言**（token2，ES256 自包含 JWT + JWKS 公钥离线验签），管理下游应用注册（origin 白名单防开放重定向），提供联邦授权码 + 安全数据投递通道（accesscode）。

| 你要解决的 | 用信任中心 |
|-----------|-----------|
| 多应用统一登录态（H5 免登） | accesscode（120s 原子 CAS + SHA256 存储 + PKCE 可选）→ token2 |
| 应用端离线验证登录态 | token2 验签（ES256 + JWKS 公钥，aud 须 == 自身 app_id） |
| 应用注册与信任管理 | `ISsoClientService`（origin 白名单 + scope + client credential AES-GCM + per-channel HMAC） |
| 跨应用/跨扩展数据投递（人工核验/自动核验） | accesscode **安全数据投递**（Payload AES-GCM 密文 + ExpectedClaimant 原子核销 + Peek/Redeem） |
| server-to-server 用户信息 | Federation `ISsoProfileService`（scope 强制 + 审计——连接层职责） |
| 接入外部 IdP（微信/QQ/Google…） | **不属本扩展**——`ISsoChannel` 契约在此定义，平台连接归 Federation 连接层 |

**信任内核纯签发（zero-orchestration）**：TrustCenter **只签发不编排**——`ISsoChannelFactory`/`SsoLogin`（编排面）与多通道选区设施（`IChannelRegistry` 系列/`SsoChannelRegistryEntity`）归 Federation 连接层；TrustCenter 经 `ISsoChannel` 契约感知外部存在，**不感知具体平台实现**、不持任何平台凭证、零外部协议库引用（验收 F1）。

**三层边界**（`TrustCenter剥离与三层架构-开发方案.md` §5.1）：

```
AuthCenter（身份）── TrustCenter（信任·纯签发）   ← 内网，零外部协议依赖
        │                    │
        └────────┬───────────┘ 经 Abstractions 契约（不引主包）
                 ▼
          Federation（对外连接层）── 平台库集合 / /feberation/* 端点 / 外部 IdP 桥接
```

**不包含**：具体平台适配扩展（→ `TKWF.Federation.{平台}` 平台网关库，引目标 TrustCenter.Abstractions）；`/feberation/*` 端点映射（→ Federation `FederationWebExtension`）；认证内核（账号/令牌 token1 → `TKWF.Ext.AuthCenter`）；我方多实例互通（默认不做，iss 域隔离）。

### 第 2 步：配置 `TKWF:TrustCenter`

```jsonc
{
  "TKWF": {
    "TrustCenter": {
      "Issuer": "https://api.example.com",          // 必填（生产 fail-fast）——token2 iss（信任中心实例标识）
      "SigningKeyPath": "C:\\keys\\sso-ec-private.pem", // EC P-256 私钥 PKCS#8（生产 fail-fast）
      "CurrentKid": "sso-key-1",                     // 当前签发密钥 kid（SigningKeys 中匹配）
      "SigningKeys": [{ "Kid": "sso-key-1", "PrivateKeyPath": "C:\\keys\\sso-ec-private.pem" }],
      "Token2ExpirationSeconds": 300,                // token2 有效期（秒，默认 300）
      "ClockSkewSeconds": 30,                        // 验签 leeway（秒，默认 30）
      "AccessCodeExpirationSeconds": 120,            // accesscode TTL（秒，默认 120）
      "AccessCodeRetentionDays": 7,                  // 过期 accesscode 清理保留天数（默认 7，≤0 跳过清理）
      "SecretEncryptionKeyPath": "C:\\keys\\trustcenter-aes.key",  // 信任内核 AES-GCM（前 32 字节，生产必填）——应用注册 credential/HMAC + accesscode Payload
      "IsProduction": true                           // true = fail-fast 门（缺密钥拒绝启动）
    }
  }
}
```

**生成 EC 私钥 PEM**（生产，PKCS#8）：
```bash
openssl ecparam -name prime256v1 -genkey -noout -out sso-ec-private.pem   # PKCS#8 EC 私钥
openssl ec -in sso-ec-private.pem -pubout -out sso-ec-public.pem
```

> ⚠️ **生产 fail-fast**：`IsProduction=true` 时缺 `Issuer` / `SigningKeyPath` / `SecretEncryptionKeyPath` → 启动拒绝（`InitializeAsync` 预检经系统作用域 `Use<IToken2Service>()` 触发密钥懒加载）。开发模式（`IsProduction=false`）缺密钥自动生成临时 EC 密钥 + Warning（`DevKeyCache<Token2Service.EcKeySet>` 进程内缓存——框架 Utility.Caching，重启即变，仅限开发联调）。

### 第 3 步：消费（应用端验证 / Federation 编排面签发）

```csharp
// 门面帧内解析（AddConstructibleService 守卫工厂——禁止 [FromServices] 预绑定）
var result = await user.Use<IToken2Service>().ValidateToken2Async(token2);        // 应用端离线验证（aud 须 == 自身 app_id）
var issued = await user.Use<IToken2Service>().IssueToken2Async(                    // 签发（Federation 编排链 / 内部循环场景）
    new Token2IssueRequest(UId: "u_100", TargetAppId: "app-1", Scope: "profile:basic"));
string jwks = user.Use<IToken2Service>().GetJwksJson();                            // JWKS 分发（RFC 7517）
```

> **❌ 不需要 Federation**：仅跨应用信任（token2/accesscode/应用注册）场景**不需要**引用 Federation——TrustCenter 独立装配即"信任中枢"（内网两层，无外连端点）。只在对**外 IdP 连接**时才加装 Federation。

## 三、应用注册与信任管理（`ISsoClientService`——下游 SP 接入点）

```csharp
public class ClientAdminService(DomainUser<MyUserInfo> user)
{
    // 注册应用（生成 app_id + client secret + HMAC secret——均 AES-GCM 落库）
    public async Task RegisterAppAsync(IReadOnlyList<string> origins, IReadOnlyList<string> scopes)
    {
        var info = await user.Use<ISsoClientService>().RegisterAsync(origins, scopes);
        // info.AppId / info.OriginWhitelist / info.Scopes / info.IsEnabled
    }

    // 校验重定向 origin（防开放重定向——target_app_id → 注册精确 origin，Ordinal 匹配）
    public async Task<bool> CheckOriginAsync(string appId, string origin)
        => await user.Use<ISsoClientService>().IsOriginAllowedAsync(appId, origin);

    // 校验客户端凭据（server-to-server profile API 鉴权——AES-GCM 解密 + FixedTimeEquals 防时序攻击）
    public async Task<bool> CheckCredentialAsync(string appId, string secret)
        => await user.Use<ISsoClientService>().ValidateClientCredentialAsync(appId, secret);
}
```

- **`SsoClientEntity`（表 `TKWF_SsoClient`）**：AppId（唯一，token2 `aud`）+ origin 白名单 JSON（scheme+host 精确集合）+ scope JSON + `ClientSecretEncrypted`/`HmacSecretEncrypted`（AES-GCM 密文）+ IsEnabled。
- **防开放重定向**：**不接受自由 `redirect_uri` 参数**——`target_app_id → 注册精确 origin` 白名单（`IsOriginAllowedAsync`，Ordinal 精确匹配）。
- **per-channel HMAC**：`GetHmacSecretAsync` 返回明文（AES-GCM 解密于服务边界）——`/sso/issue` 等 server-to-server 验签密钥来源（Oracle P1-4——不复用 AuthCenter `PlatformCredentialEntity`）。

## 四、accesscode——联邦授权码（`IAccessCodeService`，通道 B 票据）

| 字段 | 规格 |
|---|---|
| 生成 | CSPRNG 32 字节 `base64url` |
| TTL | 120 秒（`TrustCenterOptions.AccessCodeExpirationSeconds`） |
| 单次 | **原子 CAS**（`EntityUpdateWhereAsync(Id && used=false, set used=true)`——ADR89 引擎级条件 UPDATE），重放即拒 + Warning |
| 存储 | 只存 `SHA256(code)` 索引，不存原文（防库泄露后 code 盗用） |
| PKCE | 可选（签发时存 code_verifier SHA256 hash；消费必传比对，恒定时间——defense in depth，非强制） |
| 关联字段 | `channel_id, uid, target_app_id, scope, exp, used, ip, code_verifier_hash` |

```csharp
// 签发（channel 后端 → 编排链发码）
var issue = await user.Use<IAccessCodeService>().IssueAsync(new AccessCodeIssueRequest(
    ChannelId: "wx-mp-001", UId: "u_100", TargetAppId: "app-1", Scope: "profile:basic",
    OpenId: "mp_openid", /* 审计——不出 token2/URL */
    CodeVerifier: codeVerifier /* 可选 PKCE */));
// issue.Code / issue.ExpiresIn（120）

// 消费（应用端跳回 → /sso/auth）
var consume = await user.Use<IAccessCodeService>().ConsumeAsync(code, codeVerifier);
// consume.UId / consume.TargetAppId / consume.Scope → 签 token2（Federation 编排链完成）
```

**错误码**：`ACCESS_CODE_NOT_FOUND` / `TICKET_EXPIRED` / `TICKET_CONSUMED`（重放）/ `TICKET_STATE_MISMATCH`（PKCE）。

**与 AuthCenter `IOAuthTicketService` 边界**（并列不迁移）：既有 = 单应用票据（login/bind + PKCE + TTL 5min，服务认证中心内部"票据换令牌"）；TrustCenter accesscode = 联邦互联授权码 + 安全数据投递（channel_id + target_app_id + scope + Payload）——语义不同，各自独立（ADR-SSO 3.3 并存路径）。

## 五、token2 令牌（`IToken2Service`——ES256，独立密钥域）

```json
{ "alg": "ES256", "kid": "sso-key-2026-10", "typ": "JWT",
  "iss": "https://api.example.com", "sub": "<uid>", "aud": "<target_app_id>",
  "iat": 1722240000, "exp": 1722240300, "jti": "<32B base64url>", "scope": "profile:basic" }
```

- **明确不放**：openid / phone / channel_id（隐私最小化 + 解耦应用与渠道，设计文档 §6.2）。
- **签名**：手写 ES256（BCL `ECDsa`，曲线强制 P-256）；验签加固——alg 强制 / `FixedTimeEquals` / kid 白名单 / iss 校验 / exp·iat leeway（默认 30s）/ Base64Url 边界。
- **独立密钥域**：与 AuthCenter RS256 完全独立（算法/iss/消费方不同，不复用既有 `TokenService`）；kid 轮换（`SigningKeys` 遍历验证，旧密钥可验到过期）。
- **JWKS**：`GetJwksJson()` 序列化（RFC 7517：kid + x/y 坐标）——公开端点由 Federation `FederationWebExtension` `GET {prefix}/jwks` 映射（装配层职责）。
- **吊销**：短 TTL 为主（默认 300s）；用户封禁/解绑 → jti 吊销列表（profile API 在线校验），app session 周期性 re-check。

## 六、accesscode——安全数据投递通道（`IAccessCodeService` 通路 B，方案 §5.5）

> **业务层选用能力**（非 SSO 专属）——跨应用/跨扩展"携带数据的单次投递"：签发时附带 JSON 数据（明文不落库）+ 指定可核销人，核销方单次原子取回即销毁。**用途由业务层决定**（人工核验/自动核验——如凭证兑换、安全链接投递），本扩展只提供能力不规定用途（开发方案 §二 不包含 #1 落档转告记录）。

```csharp
// ① 签发：附带数据 + TTL + 可核销人
var issue = await user.Use<IAccessCodeService>().IssueAsync(
    payloadJson: JsonSerializer.Serialize(new { OrderId = "o_100", Amount = 99.5m, Code = "coupon-abc" }),  // 明文 ≤ ~4068 字节，超限 PAYLOAD_TOO_LARGE
    ttl: TimeSpan.FromMinutes(5),                 // ttl ≤ 0 → 钳制为配置默认（120s）
    expectedClaimant: "store-001",                // 谁可核销；null = 可转让（任意核销人）
    ct);
// issue.Code / issue.ExpiresIn

// ② 预读（只读快照非锁定——Peek 后行可能被并发 Redeem；不可逆动作必须走 Redeem）
var preview = await user.Use<IAccessCodeService>().PeekAsync<OrderPayload>(issue.Code, ct);   // 业务层复杂规则预读

// ③ 核销取回 + 销毁（单次原子 CAS——核销人 + 并发核销联合判定恰一成功）
var payload = await user.Use<IAccessCodeService>().RedeemAsync<OrderPayload>(issue.Code, "store-001", ct);
// payload.OrderId / payload.Amount / payload.Code；行已 Used=true（销毁语义）
```

**契约与语义**：

| 方法 | 语义 |
|------|------|
| `IssueAsync(string? payloadJson, TimeSpan ttl, string? expectedClaimant, ct)` | 签发带附带信息的 accesscode——`payloadJson` 非空时 **UTF8 明文 ≤ 4068 字节**（4096 - 12 nonce - 16 tag，AES-GCM 密文列 `MaxLength(4096)`），超限抛 `PAYLOAD_TOO_LARGE`；keyed `ISymmetricKeyProvider`（`TrustCenterKeyProviderKeys.TrustCenter` 过渡常量——主框架 `SymmetricKeyProviderKeys.TrustCenter` 转正后切换）AES-GCM 加密落 `PayloadEncrypted`（**明文不落库**）；`expectedClaimant` 可空 = 可转让；`ttl ≤ 0` → 钳制配置默认 |
| `PeekAsync<T>(code)` | **只读快照非锁定**——查行 → 过期拒 → 解密 payload + 反序列化 `<T>`；**不消费不锁定**——业务层**不得基于 Peek 结果做不可逆决策**（不可逆动作一律经 `RedeemAsync` 原子 CAS 恰一成功） |
| `RedeemAsync<T>(code, claimant)` | **核销取回 + 销毁（单次原子 CAS）**——`EntityUpdateWhereAsync(WHERE CodeHash=? AND used=false AND (ExpectedClaimant IS NULL OR ExpectedClaimant=claimant), set Used=true)`：核销人 + 并发核销**联合判定无 TOCTOU**，恰一成功；影响 0 → 重查判因（`ACCESS_CODE_NOT_FOUND`/`TICKET_CONSUMED`/`CLAIMANT_MISMATCH`/`TICKET_EXPIRED`）；成功 → 解密 payload 取回 + 销毁（Used=true） |
| `CleanupExpiredAsync(retentionDays?)` | 清理过期行**含 Payload 密文**（防业务数据残留）——`ExpiresAt < UtcNow - retentionDays`（默认 `AccessCodeRetentionDays`=7；≤ 0 跳过清理 返回 0）；**消费方经 `IRecurringBackgroundJobManager` 周期调度**（对齐 Metrics 定时重算范式） |

**错误码**：`ACCESS_CODE_NOT_FOUND` / `TICKET_EXPIRED` / `TICKET_CONSUMED` / `TICKET_STATE_MISMATCH` / **`CLAIMANT_MISMATCH`**（核销人不符）/ **`PAYLOAD_TOO_LARGE`**（明文超 ~4068 字节）。

**⚠️ 并发语义（显式声明）**：`Peek` **不锁定/不消费**——Peek 后行可能被并发 Redeem（行消失/已用）；业务层须自行处理 `RedeemAsync` 失败（`TICKET_CONSUMED`/`ACCESS_CODE_NOT_FOUND` 重查判因），**不得**基于 Peek 结果做不可逆决策。

**清理任务注册示例**（BackgroundJobs `IRecurringBackgroundJobManager`，对齐 Metrics 周期调度）：
```csharp
await user.Use<IRecurringBackgroundJobManager>().EnqueueRecurringAsync(
    "trustcenter-accesscode-cleanup",
    "0 0 3 * * ?",   /* 每日 03:00 */
    () => user.Use<IAccessCodeService>().CleanupExpiredAsync(null, CancellationToken.None));
```

## 七、安全边界

- **数据访问红线合规**：全部实体 SG1 + `*EntityDataService` 委托（零 IFreeSql / 零 IEntityDAC 直注入）；TrustCenter 纯签发零编排——**零外部协议库引用**（grep 断言零 `Federation.` 平台库引用，验收 F1）。
- **密钥安全**：EC 私钥 PEM（PKCS#8，chmod 600）/ AES-GCM 密钥文件（前 32 字节）不进代码库；生产缺密钥 fail-fast；kid 轮换支持紧急换钥。**对称密钥经 keyed `ISymmetricKeyProvider`**——⚠️ **过渡常量 `TrustCenterKeyProviderKeys.TrustCenter`**（主框架 `SymmetricKeyProviderKeys` 暂缺 TrustCenter 键——已转告框架组 C11 第 5 扩展申请并入，CPM 升级后切换主框架常量，防 typo 静默解析错 key 单一事实源；对齐 AuthSurface v0.2.0 先例）。
- **防开放重定向**：`target_app_id → 注册精确 origin（scheme+host）` 白名单（`SsoClientService.IsOriginAllowedAsync`，Ordinal 精确匹配）；不接受自由 `redirect_uri` 参数。
- **client credential 校验**：AES-GCM 解密 + `CryptographicOperations.FixedTimeEquals`（防时序攻击）。
- **accesscode 只增语义**：`AccessCodeEntity` 无 Update/Delete 公开业务方法（对齐 SecurityLog 先例）。
- **Payload 密文**：附带信息 AES-GCM 密文落库（明文不落库）；`Peek`/`Redeem` 解密失败（密文被篡改/密钥不匹配）→ `CryptographicException`/`FormatException`——**fail-closed 拒信任，不静默降级**。

## 八、与既有扩展划界

| 扩展 | 边界 |
|------|------|
| `TKWF.Ext.AuthCenter`（认证中心） | **token1 vs token2 双令牌域**：AuthCenter `ITokenService` 签 RS256（内部 Bearer 中间件）；TrustCenter `IToken2Service` 签 ES256（外部应用离线验签 + JWKS）——**密钥体系完全独立**（算法/iss/消费方不同）。组合式消费：AuthCenter + TrustCenter = 认证中心实例（信任中枢） |
| `TKWF.Ext.AuthCenter` `IOAuthTicketService` | 既有 = 单应用票据（login/bind + PKCE + TTL 5min）；TrustCenter accesscode = 联邦授权码 + 安全数据投递（channel_id + target_app_id + scope + Payload）——**语义不同，并列不迁移** |
| `TKWF.Ext.Federation`（联邦互联） | **编排/连接/多通道设施归 Federation**（`ISsoChannelFactory`/`SsoLogin`/`IChannelRegistry` 系列/`SsoChannelRegistryEntity`/`/feberation/*` 端点/`ExternalIdpAuthenticator`）；Federation 经 `TrustCenter.Abstractions` 契约调签发（L2 间接层合法） |
| `TKWF.Federation.{平台}`（平台网关库） | 实现 `ISsoChannel`（契约在 TrustCenter.Abstractions）——协议单源；引目标 TrustCenter.Abstractions（L2 门控） |
| `TKWF.Ext.AuthSurface`（兑换码） | AuthSurface 兑换码 = 独立扩展（RedemptionCode Payload 加密增强 v0.2.0）；TrustCenter accesscode 安全数据投递 = **通用数据投递通道**（不规定用途）——两者均可供业务层选用，语义平行（开发方案 §二 不包含 #1：AuthSurface 兑换码增强落档转告，随业务需求立项） |
