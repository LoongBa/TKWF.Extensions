## 一、本版目标

- **核心交付**：`TKWF.Ext.UserCenter.Abstractions` + `TKWF.Ext.UserCenter` v0.1.0——用户中心**档案面内核**：
  1. **契约包（Abstractions）**：`IUserProfileSource` / `IRedemptionHistorySource` / `IUserAppsSource` + `IUserCenterQueryService` + `UserProfileDto` / `RedemptionRecordDto` / `UserAppDto`——**中立契约，实现方 = 数据源扩展 / 装配实例**

  4. **领域逻辑进扩展**：`UserCenterQueryService` 门面（组合三 Source + **门面输出强制脱敏** + 缺省降级）+ `PhoneMasker` + **过渡期模板基类** `UserProfileSourceBase`/`RedemptionHistorySourceBase`/`UserAppsSourceBase`（装配层最小适配）
  5. `UserCenterOptions`（TKWF:UserCenter 节）+ `UserCenterExtensionInitializer<TUserInfo>`（三钩子装配门面）+ 测试 + README + 使用指南 + slnx 接线
- **完成定义（DoD）**：全部组件落地 + **零扩展间依赖**（TKWF0022 零违规——契约经 Abstractions，实现方经契约引用）+ 降级行为测试覆盖 + 脱敏测试矩阵 + 模板基类装配示例 + 全量回归不破坏 + 指南含「认证中心桥接示例 / 装配实例最小适配示例」（过渡期）+「数据源扩展实现契约」终态路径（未来认证中心/授权面实现）。

## 四、命名与边界裁定（引认证中心 ADR——同步落档）

> 认证中心 ADR `ADR-Authentication-认证中心命名与边界.md` 已裁定用户中心独立立项。本扩展边界细化如下：

| # | 决策点 | 裁定 | 理由 |
|---|--------|------|------|
| 1 | **扩展命名** | `TKWF.Ext.UserCenter`（主包）+ `TKWF.Ext.UserCenter.Abstractions`（契约包），命名空间 `TKWF.Ext.UserCenter` | 用户中心（档案面）独立立项（用户裁定 2026-09-30，命名已确认）；认证中心 ADR L40/L85/L86 已引用 |
| 2 | **包形态** | **双包：Abstractions（契约）+ 主包（实现）** | 契约实现方含**其他扩展**（认证中心/授权面终态实现）——契约必须中立：实现方引 Abstractions 而非 UserCenter 主包（避免实现方背上用户中心依赖与循环风险）；对齐 Emailing/SecurityLog 拆包先例（ADR48 D7） |
| 3 | **存储边界** | **两包均不建实体/表**（SG1 零接线） | 档案数据属主 = AuthAccount（认证中心），兑换/应用数据属主 = 授权面——用户中心是**聚合读取层**，读取契约 + 门面 + 领域逻辑归本扩展，数据与持久化归数据属主（对齐 Metrics「实体归消费方」/ Dashboard「零存储」先例）；自有持久化（档案偏好类）待写需求出现再评估（YAGNI） |
| 4 | **契约实现方归属（终态）** | `IUserProfileSource` → **认证中心扩展内实现**（AuthAccount 属主）；`IRedemptionHistorySource` / `IUserAppsSource` → **授权面扩展内实现**（兑换/授权属主） | 数据属主实现读取契约（引 UserCenter.Abstractions），各经自己 Initializer 三钩子装配进消费方 DI——**装配层零桥接**，纯扩展机制接线（§5.9 装配图）——充分发挥"扩展自定义对象装配 DI"优势 |
| 5 | **过渡期（v0.1.0，认证中心/授权面未就绪）** | 装配实例经**模板基类**最小适配（`UserProfileSourceBase` 等——扩展内预实现管线，实例仅实现查询钩子）或直接实现白地契约；缺省注册 → 门面降级（null/空列表） | 不阻塞认证中心/授权面实施；消费方先行装配验证用户中心骨架；过渡代码量最小化（模板基类把领域逻辑留在扩展内） |
| 6 | **与认证中心划界** | 认证中心=令牌签发/验证 + 账号（AuthAccount）管理；本扩展=档案**读取** + 聚合展示 + 脱敏/降级领域逻辑 | 本扩展主包**零引用**认证中心（不引实体/实现/契约）；认证中心 v0.1.0 零改动不受本扩展影响；未来认证中心实现 `IUserProfileSource`（引 Abstractions）即完成自动装配 |
| 7 | **与授权面（口令兑换）划界** | 授权面=兑换/授权/管理端（未立项）；本扩展=兑换历史/我的应用**读取视图** | `IRedemptionHistorySource`/`IUserAppsSource` 是读取契约——授权面立项后扩展内实现（缺省空列表降级——消费方不受未立项阻塞） |
| 8 | **Domain/Web 拆分** | v0.1.0 两包均**纯 Domain**（零 Web 依赖，无 FrameworkReference） | 无中间件/无页面渲染（页面归装配实例）——对齐 Dashboard/Analytics 纯 Domain 先例；待扩展自带页面渲染服务需求出现再评估 Web 拆分 |
| 9 | **业务档案边界** | 任课班级/孩子/家庭码/进度/购买明细**不进本扩展** | 立项方案 §4.1 裁定：不适合集中、需特化 → 业务系统本地 |

### 5.2 契约接口（Abstractions，冻结——实现方 = 数据源扩展/装配实例）

```csharp
namespace TKWF.Ext.UserCenter;

/// <summary>公共档案源——数据属主（认证中心 v0.2.0+）或装配实例（过渡）实现。</summary>
public interface IUserProfileSource
{
    /// <summary>按平台内部 id（JWT sub / DomainUser 标识）取公共档案；不存在返回 null。</summary>
    /// <remarks>返回的 <see cref="UserProfileDto.Phone"/> 为<b>原始</b>手机号——门面输出前经 PhoneMasker 强制脱敏（实现方不需自行脱敏）。</remarks>
    Task<UserProfileDto?> GetProfileAsync(string userId, CancellationToken ct = default);
}

/// <summary>兑换历史源——授权面（口令兑换体系）或装配实例实现。</summary>
/// <remarks>与 <see cref="IUserAppsSource"/> 拆为两接口（同属授权面）：支持授权面扩展<b>分阶段实现</b>（先兑换后应用），单一接口迫使一次性实现全量（P3）。</remarks>
public interface IRedemptionHistorySource
{
    /// <summary>取用户口令兑换历史。<see cref="RedemptionRecordDto.CodeMasked"/> 由实现方保证脱敏（UserCenter 不存储明文）。</summary>
    Task<IReadOnlyList<RedemptionRecordDto>> GetRedemptionsAsync(string userId, CancellationToken ct = default);
}

/// <summary>我的应用源——授权面或装配实例实现（聚合授权 + 使用情况，<b>不含学习明细</b>——儿童数据红线，契约文档约束）。</summary>
public interface IUserAppsSource
{
    Task<IReadOnlyList<UserAppDto>> GetAppsAsync(string userId, CancellationToken ct = default);
}

/// <summary>用户中心门面——消费方注入入口（主包实现）。</summary>
public interface IUserCenterQueryService
{
    Task<UserProfileDto?> GetProfileAsync(string userId, CancellationToken ct = default);
    Task<IReadOnlyList<RedemptionRecordDto>> GetRedemptionsAsync(string userId, CancellationToken ct = default);
    Task<IReadOnlyList<UserAppDto>> GetAppsAsync(string userId, CancellationToken ct = default);
}
```

```csharp
public sealed record UserProfileDto(

    string? Phone,          // ⚠️ 原始手机号（仅源/门面内部流转）——UserCenterQueryService 输出前强制 PhoneMasker 脱敏；源/门面均不得将含 Phone 的 DTO/异常栈写日志或序列化（C1）
    bool IsWechatBound,     // 微信绑定状态（双形态任一）
    string? Nickname,
    string? AvatarUrl,      // 头像 URL string（DMP 实践——非二进制）
    bool IsTeacherVerified, // teacher_verified 认证声明（不含业务权限）

    string? TargetAppId,    // 兑换目标应用 id
    DateTime RedeemedAtUtc, // 兑换时间（UTC）
    string Status);         // 状态（redeemed/expired...——授权面域，UserCenter 透传不枚举化）

public sealed record UserAppDto(
    string AppId,           // 应用/产品 id
    string? AppName,
    bool IsAuthorized,      // 当前授权状态
    DateTime? ExpiresAtUtc, // 授权到期（可空=永久/未定义）
    string? UsageSummary);  // 使用情况聚合文本/JSON（契约约束：不含学习明细——儿童数据红线，授权面保证）
```

### 5.3 UserCenterQueryService（门面——领域逻辑进扩展）

- 组合：构造注入三 Source（`IUserProfileSource`/`IRedemptionHistorySource`/`IUserAppsSource`，可空——不注册 Source 时门面仍可构造，降级工作）。**DI 注入语义（P4）**：门面构造参数 nullable + 解析经 `IServiceProvider.GetService<T>()`（未注册返回 null），不采用必需注入（未注册会构造失败）；实施期对齐既有可空注入先例。
- **门面输出强制脱敏（领域逻辑单一真相源）**：`GetProfileAsync` 组合 `IUserProfileSource.GetProfileAsync` 返回原始 `Phone` → 内部 `PhoneMasker.Mask(profile.Phone)` → 以 `with { Phone = masked }` 输出——**实现方（含未来认证中心实现）不需要也不得自行脱敏**（防漏）；装配示例同步声明。
- **脱敏责任不对称（P1，显式对比）**：手机号脱敏归**门面**——AuthAccount 中手机号**明文存储**，Source 返回原始值，门面统一脱敏（单一真相源，防实现方漏脱敏）；兑换 code 脱敏归**源实现方**（`CodeMasked` 契约约束）——code 在授权面**已脱敏存储**（UserCenter 不存明文），Source 返回即已脱敏值，门面透传不重复脱敏。
- **降级矩阵**：

| Source 注册状态 | GetProfileAsync | GetRedemptionsAsync | GetAppsAsync |
|---|---|---|---|
| 三 Source 全注册 | 完整档案（Phone 已脱敏） | 历史列表 | 应用列表 |
| `IUserProfileSource` 缺失 | **null**（装配方自行映射 404/匿名档案） | 正常 | 正常 |
| 兑换/应用源缺失 | 正常 | **空列表** | **空列表** |
| 三 Source 全缺 | null | 空列表 | 空列表 |
| Source 抛异常 | null + `ILogger.Warning` | 空列表 + Warning | 空列表 + Warning |

- 异常静默（Warning 不冒泡）对齐仓库惯例——不阻塞用户中心页面渲染。

### 5.4 手机号脱敏（PhoneMasker——扩展内安全组件）

```csharp
public static class PhoneMasker
{
    /// <summary>脱敏：保留前 3 后 4，中间 *；长度 ≤7 → 全 *；null/空白 → null。Trim 后处理。</summary>
    public static string? Mask(string? phone);
}
```

- 规则：`13812345678` → `138****5678`；`12345`（<8 位）→ `*****`；null/空白 → null；含空格先 Trim。
- 可配性：`UserCenterOptions.PhoneMask`（保留位数/正则模板，缺省内置规则）——本期默认内置，配置项留档。

### 5.5 过渡期模板基类（装配层最小适配——扩展内预实现领域管线）

> **机制体现**：对齐 `IdentityUserHelperBase` / `AuthenticationUserHelperBase` 先例——扩展提供**对象骨架**（映射/降级/日志管线预实现），装配实例经继承只补"查数据"最短钩子，代码量几行，领域逻辑留在扩展内。

```csharp
namespace TKWF.Ext.UserCenter;

/// <summary>过渡期模板：装配实例继承此基类实现 IUserProfileSource，仅需实现查询钩子。</summary>
public abstract class UserProfileSourceBase : IUserProfileSource
{
    private readonly ILogger _logger;
    protected UserProfileSourceBase(ILogger<UserProfileSourceBase> logger) => _logger = logger;

    public async Task<UserProfileDto?> GetProfileAsync(string userId, CancellationToken ct = default)
    {
        try
        {
            var raw = await QueryRawProfileAsync(userId, ct);   // 装配实例仅实现：查 AuthAccount / 其他身份源
            return raw is null ? null : MapToProfile(userId, raw);  // 映射钩子（可覆写，默认投影）
        }
        catch (Exception ex) when (ex is not OperationCanceledException)
        {
            _logger.LogWarning(ex, "UserCenter 档案读取失败（userId={UserId}），降级为 null", userId);
            return null;
        }
    }
    /// <summary>装配实例实现——返回原始档案行（任意自有类型：AuthAccountEntity / 自定义 POCO）。</summary>
    protected abstract Task<RawProfile?> QueryRawProfileAsync(string userId, CancellationToken ct);
    /// <summary>映射钩子（可覆写）——默认投影公共档案字段 + Phone 原始值（门面负责脱敏）。</summary>
    protected virtual UserProfileDto MapToProfile(string userId, RawProfile raw) => /* 默认投影 */;
    public sealed record RawProfile(string? Phone, bool IsWechatBound, string? Nickname, string? AvatarUrl, bool IsTeacherVerified, int AuthLevel);
}
```

- 兑换历史 / 我的应用同型基类（`RedemptionHistorySourceBase` / `UserAppsSourceBase`，异常降级空列表）——**三基类对称设计（C3）**：`RedemptionHistorySourceBase.RawRedemption`（CodeMasked/ProductName/TargetAppId/RedeemedAtUtc/Status）+ `UserAppsSourceBase.RawApp`（AppId/AppName/IsAuthorized/ExpiresAtUtc/UsageSummary）——同为 sealed record「默认投影」载体；装配实例若需自定义字段可覆写 `MapToProfile`/`MapToRedemption`/`MapToApp` 从自有类型直接构造 DTO（Raw* 不是强约束，仅默认投影便利）。
- **终态说明（指南）**：认证中心 v0.2.0+ 实现 `IUserProfileSource` 时**直接实现白地接口**（AuthAccount 数据自有，无需模板钩子）并 `TryAddScoped` 注册——装配实例删除过渡桥接类即可，**消费方零代码变更**（门面注入不变）。

### 5.7 安全与防护

| # | 风险 | 对策 | 归属 |
|---|------|------|------|
| 1 | **IDOR 越权**（A 查 B 档案） | 门面**显式 `userId` 参数** + 契约文档声明「仅本人令牌可读」（需求 L385）——装配端点从 DomainUser/令牌解析 userId，不信任客户端传参 | 装配实例（端点层强制）+ UserCenter（契约文档约束） |
| 2 | **手机号泄露**（档案 API 返回原始手机号 / 内部流转日志泄漏） | **门面输出强制脱敏**（PhoneMasker，5.3 裁定——实现方不得自行处理，防漏）+ **流转约束**：源/门面均不得将含原始 Phone 的 DTO、异常消息、异常栈写日志或序列化（C1） | UserCenter（门面）+ 源实现方 |
| 3 | **兑换 code 明文泄露** | `RedemptionRecordDto.CodeMasked` 契约约束（实现方输出前脱敏）+ 指南示例脱敏提示 | Source 实现方（授权面/装配实例） |

| 5 | **Source 异常吞业务** | 降级（null/空列表）+ `ILogger.Warning`（对齐异常静默惯例） | UserCenter（门面 + 模板基类） |

### 5.8 数据访问红线合规（自查）

- **主包与契约包均零实体 / 零表 / 零 ORM / 零 IEntityDAC / 零 IFreeSql**——接线型聚合扩展（对齐 Dashboard/Analytics 零存储先例），数据读取全部经装配的 Source 接口完成（数据读写归数据属主：认证中心/授权面各自红线合规路径）——**不触碰红线范畴**（接线型不适用边界，HealthCheck 先例）。

### 5.9 扩展机制优势发挥（核心——对齐用户裁定：扩展内实现自定义数据结构/对象，装配至消费方 DI/DomainHost）

> **与传统 ABP 模块设计对比**：ABP 的 Profile 模块（AbpAccount `IProfileAppService`）是"模块自带实体 + 服务、消费方引模块即用"——能力内聚但实体/服务同包，扩展间协作靠模块引用。TKWF 扩展机制更彻底：**契约 + 实现分离、数据归属主、领域逻辑入扩展、三钩子自动装配**——消费方仅白名单编排。

**装配图（终态——充分体现机制优势）**：

```
消费方 DomainHost（唯一声明）
├── [TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]   // 认证中心：令牌 + AuthAccount + IUserProfileSource 实现（v0.2.0+）
├── [TKWFEnabledExtension(typeof(UserCenterExtensionInitializer<>))]   // 用户中心：门面（脱敏/降级/聚合领域逻辑）
└── [TKWFEnabledExtension(typeof(RedemptionExtensionInitializer<>))]   // 授权面（未来）：兑换/授权 + IRedemptionHistorySource/IUserAppsSource 实现

DI 自动装配（零桥接）：
  IUserProfileSource        ← 认证中心 Initializer（自身数据 AuthAccount）
  IRedemptionHistorySource  ← 授权面 Initializer（自身数据兑换记录）
  IUserAppsSource           ← 授权面 Initializer（自身数据授权快照）
  IUserCenterQueryService   ← 用户中心 Initializer（组合三者 + 脱敏 + 降级）
→ 消费方注入 IUserCenterQueryService 即得完整用户中心能力
```

- **扩展内自定义对象清单**：契约（Abstractions DTO/接口——跨扩展共享的数据结构）+ 门面/脱敏/模板基类（主包——装配至消费方 DI 的领域对象）。**数据实体**（AuthAccount/兑换记录）归各自数据属主扩展，SG1 建表 + DataService 自动注册——用户中心不重复建模（存储边界 §4#3）。
- **三钩子装配**：两扩展 Initializer 全部经 ConfigureServices TryAdd 注册（门面 + Source 实现），消费方白名单声明后自动接线——装配层**零手写桥接**（终态）。
- **过渡 vs 终态的演进路径**（指南附录）：

| 阶段 | IUserProfileSource 实现方 | 装配实例工作 |
|------|--------------------------|-------------|
| **v0.1.0（认证中心未就绪）** | 装配实例继承 `UserProfileSourceBase`（或白地实现） | 1 个桥接类（几行查询钩子）+ 1 行 DI 注册 |
| **认证中心 v0.2.0+（终态）** | 认证中心扩展内直接实现契约 + TryAddScoped | **删除过渡桥接类，零代码变更** |

- **机制债声明**：本扩展不要求任何主框架机制演进（三钩子/白名单/TryAdd 语义全满足）；契约包拆包为 ADR48 D7 第 6 次落地先例（Emailing/BlobStoring/Permissions/SecurityLog/Account 已 5 次）。

## 八、v0.2.0+ 终态升级路径（最优解探索结论——装配层组合视图）

> **2026-09-30 最优解探索落档**（Oracle 裁决 + 五路机制验证）：方法论总纲见 `docs/框架实战教学/01-扩展模块最优解探索-Schema级数据组合-开篇.md`。
> **v0.1.0 保持本方案**（契约层 + 门面 + 模板基类过渡——不阻塞认证中心/授权面实施）；**v0.2.0+ 依本节升级**。核心洞察：UserProfile 可变性在项目层 → 项目建表 + VEntity/View 跨表关联扩展数据 → **SQL 层自动组装，免内存拼装**（Schema 级 Open-Closed）。

### 8.1 终态架构（三层协作）

```
┌─ UserCenter（契约层，零实体零存储）───────────────┐
│  Abstractions：三 Source 契约 + DTO（不变）            │
│  主包：门面（软脱敏/降级领域逻辑）——模板基类删除        │
└───────────────┬──────────────────────────────────┘
                │ TryAdd 语义（扩展实现契约先例：Identity L47）
┌─ 属主扩展（读模型层）───────────────────────────┐
│  认证中心：vw_AuthAccountProfile VEntity + 只读 DataService   │ ← D17A 裁定 2 + ADR61 自动注册（零手写 SQL/零注册）
│  授权面：  兑换 vw_UserRedemptions + 应用授权 vw_UserApps      │ ← 契约实现直接委托只读 DataService
└───────────────┬──────────────────────────────────┘
                │ SyncViewsAsync 自动建视图（开发）/ DBA 手动（生产）
┌─ 装配实例（组合层）─────────────────────────────┐
│  vm_UserCenterProfile = JOIN 认证中心基表(AuthAccount) + 兑换 + 应用 + 项目定制表  │ ← 【首个跨扩展组合 VEntity 先例】
│  自动 DTO + REST/GraphQL 默认暴露 = 页面数据一次查询组装           │
└────────────────────────────────────────────────┘
```

> **C1 关键裁定（Oracle3 2026-09-30）**：组合视图**必须 JOIN 属主基表**（`AuthAccount` 等），**不能 JOIN 属主 VEntity**（`vw_AuthAccountProfile`）——`ViewSqlColumnValidator` 视图链禁令（VIEW002 编译期 + 运行时双门控，L107-119）硬禁止 `vw_` 嵌套。SQL 硬脱敏无传递性——组合视图脱敏须重做（见 8.4）。

### 8.2 属主扩展读模型（认证中心 v0.2.0+ / 授权面）

- **认证中心 v0.2.0+**：建 `vw_AuthAccountProfile` VEntity（投影公共档案字段，含 SQL 层硬脱敏）→ 手写只读 DataService（`DomainReadOnlyDataServiceBase` + `IEntityReadOnlyDAC`，**v4.10.8 ADR61 起自动注册**，Initializer 零手动注册）→ 实现 `IUserProfileSource` 时**直接委托该只读 DataService**（替代手写查询桥接）
- **授权面立项后**：建兑换记录/应用授权 VEntity → 实现 `IRedemptionHistorySource`/`IUserAppsSource` 同模式委托
- **机制依据**：VEntity 五件套（实体定义 ~55 行 + SG 自动 DTO/GraphQL + 只读 DataService ~30 行 + 零注册）——数据获取走框架原生路径。**注（2026-09-30 用户裁定 + C4 澄清）**：先例（Identity/Notifications）走"视图行映射回原实体（接口不变）"保守形态；UserCenter **无历史负担（内部测试）**——组合视图 `vm_UserCenterProfile` VEntity DTO **直接暴露**（GraphQL/REST 自动端点，见 8.3）；但 **`IUserProfileSource` 契约返回 `UserProfileDto`（v0.1.0 已冻结）——契约实现仍需映射 VEntity DTO → `UserProfileDto`**（"直接暴露"指组合视图路径，非契约返回类型）。

### 8.3 装配层组合视图（vm_UserCenterProfile）

- **同库前提**（D17A 裁定 3 默认 Single DB）：`ViewSql` 跨扩展 JOIN **属主基表**（`AuthAccount` + 兑换表 + 应用授权表 + 项目定制表）——**非属主 VEntity**（视图链禁令 VIEW002：`ViewSqlColumnValidator` L107-119 编译期 + 运行时硬禁止 `vw_` 嵌套，C1）
- **开发**：SyncViewsAsync 自动建（ADR49 决策 6——装配实例自有 VEntity 与扩展同构，SG 聚合清单覆盖）；**表先于视图**框架级硬保证（SyncTables → SyncViewsAsync 固定序）。**接线前提（P3）**：装配实例须导入 `TKWF.Domain.targets` 或手动跑 SyncViewsAsync 才能开发环境自动建（AGENTS §8 本仓库未导入 targets——装配实例需自行接线）
- **生产**：DBA 手动执行 ViewSql——**跨扩展 DBA 段落需新增到装配实例指南**（依赖扩展表清单 + 各扩展建表前置 + 多方言变体）
- **落地后立 ADR**：`ADR-UserCenter-跨扩展组合视图设计`（记录首个跨扩展 VEntity 先例 + 生产复杂度评估）
- **备选形态**（各属主扩展各建视图 + 消费方内存/二次组装）仅在"多页面灵活组合 / 高频缓存"场景更优——默认走组合视图

### 8.4 投影下沉（分层脱敏）

- **SQL 硬脱敏**（v0.2.0+ 读模型层）：手机号前 3 后 4 等简单规则进 ViewSql——**任何消费路径（GraphQL/REST/内部直查）自动脱敏**，消灭漏脱敏
  - **必须 AS 别名**（否则 ViewSqlColumnValidator 判"缺失列"运行期阻断）
  - 方言安全：`substr` + `||` 拼接（双方言一致），备 `ViewSqlSQLite` 变体（ADR53）；避免 `concat` 版本依赖 / `substring` 仅 PG
  - **Tier 1.5 SQLite 真实视图测试**验证（Tier 1 内存 DAC 无 VEntity 填充通道）
- **脱敏路径独立（C1 关键推论）**：SQL 硬脱敏逻辑必须在**组合视图 `vm_UserCenterProfile` 的 ViewSql 里对 `AuthAccount.Phone` 直接重做**（属主 VEntity `vw_AuthAccountProfile` 的脱敏**不传递**——组合视图 JOIN 基表含明文列）——脱敏逻辑在属主 VEntity（契约路径）与组合视图（页面路径）各做一次，是视图链禁令的**必然代价**（Oracle3 C1）
- **门面 PhoneMasker 去留（C2——防双脱敏）**：v0.2.0+ **属主 Source 路径门面不再调 PhoneMasker**（`IUserProfileSource` 返回的 DTO 已 SQL 硬脱敏，再 Mask 会破坏格式 `138****5678`→`138*****678`）；PhoneMasker 仅服务于 **v0.1.0 装配实例桥接路径**（模板基类/白地实现返回原始 Phone 时）；门面"软脱敏"职责 = 动态/角色级字段裁剪（不碰 Phone 值）
- **门面软脱敏**（保留）：动态/角色级字段裁剪（业务逻辑）

### 8.6 前提与风险

| # | 前提/风险 | 处置 |
|---|----------|------|
| 1 | **同库硬边界** | 立项前确认业务线同库；分库 → 契约 + 门面拼装（对方不浪费，契约层保留）。**P2：v0.1.0 使用指南提示装配实例"选库决定 v0.2.0 组合视图可行性"** |
| 2 | 跨扩展组合视图**首个先例**（成熟度待验证） | Tier 1.5 测试 + 落地后 ADR 记录 |
| 3 | 生产 DBA 跨扩展视图复杂度（多扩展表依赖 + 多方言变体） | 装配实例指南新增跨扩展段落（依赖表清单 + 前置条件） |
| 4 | 表名裸名冲突（`Setting`/`Notification` 等通用名） | 装配实例自建表避让扩展表名；视图引用前核对 |
| 5 | 契约自动实现（SG 检测满足自动注册） | V5 前瞻（`ReadModelProjection<T>` 显式声明，规避鸭子类型）——非本期，立 ADR 锁方向 |
| 6 | **组合视图 IDOR（C3 安全缺陷）** | 组合视图 `ExposeGraphqlQuery=true` 默认 GraphQL/REST 自动暴露，**无"仅本人"防护**（§5.7 门面防护只盖门面端点）——装配实例须补：**方案 A（推荐）** `IGlobalQueryFilter.Apply<T>` 对 `vm_UserCenterProfile` 按 `ctx.User.UserId` 过滤；**方案 B** `ExposeGraphqlQuery=false` + 经门面 Service 包装暴露（userId 从 DomainUser 解析）。选一并在 8.3/使用指南显式声明 |
| 7 | **方案 A 可行性实证（2026-09-30 增补）** | **IGlobalQueryFilter 对 VEntity 完全生效**——`DomainReadOnlyDataServiceBase<TEntity,TDto>` 泛型约束 `where TEntity : class, IDomainEntity, new()`（基类 L31），VEntity 实体满足 `IDomainEntity`；`QueryForUser()` 无条件链式应用所有已注册 `IGlobalQueryFilter`（`foreach (var filter in User.GetServices<IGlobalQueryFilter>()) q = filter.Apply(q, ctx)`，基类 L113-116）——组合视图手写只读 DataService 继承该基类即自动受全局过滤约束。**方案 A 无需 DB 级 RLS**（RLS 调研结论：PG15+ `security_invoker` 四件套 + owner 豁免陷阱，方言不可移植，SQLite 无 RLS——不作为默认；SQL Server 语义更干净但非跨方言）。实现形态：新增 `OwnerGlobalQueryFilter`（对实现 `IUserOwned`/含 `OwnerId` 字段实体按 `ctx.User.UserId` 过滤）→ 教学系列 §九 **F6 候选**；当前方案 A 落地前确保装配实例注册该过滤器 |
