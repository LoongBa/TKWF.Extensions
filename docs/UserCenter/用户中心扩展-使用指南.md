# 用户中心扩展-使用指南

> **扩展**: `TKWF.Ext.UserCenter`（用户中心）| **契约包**: `TKWF.Ext.UserCenter.Abstractions`
> **版本**: V0.1.0｜**文档**: 2026-09-30
> **定位**: 通用档案面扩展——公共 Profile API + 用户中心 API 骨架（兑换历史/我的应用经**扩展间契约协作**），多业务线装配复用

## 一、快速开始

### 1. 引用与启用

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```xml
<PackageReference Include="TKWF.Ext.UserCenter" Version="0.1.0" />
```

消费方领域初始化器声明白名单（V4.9.85+ 发现不自动启用）：

```csharp
using TKWF.Ext.UserCenter;

[TKWFEnabledExtension(typeof(UserCenterExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后自动注册：`IUserCenterQueryService`（门面）。

> ⚠️ **Source 接口不注册默认实现**——`IUserProfileSource` / `IRedemptionHistorySource` / `IUserAppsSource`
> 需由**数据属主扩展**（认证中心 v0.2.0+ / 授权面）或**装配实例**（过渡期模板基类）提供（见 §二）。

### 2. 使用（消费方注入门面）

```csharp
public class UserCenterPage(IUserCenterQueryService userCenter)
{
    // userId 从 DomainUser/令牌解析——仅本人防护（需求 L385），不信任客户端传参
    public async Task<UserProfileDto?> MeAsync(string currentUserId)
        => await userCenter.GetProfileAsync(currentUserId);

    public async Task<IReadOnlyList<RedemptionRecordDto>> RedemptionsAsync(string currentUserId)
        => await userCenter.GetRedemptionsAsync(currentUserId);

    public async Task<IReadOnlyList<UserAppDto>> AppsAsync(string currentUserId)
        => await userCenter.GetAppsAsync(currentUserId);
}
```

### 3. 端点映射（装配实例）

```
/api/edu/user/me          → IUserCenterQueryService.GetProfileAsync(userId)
/api/edu/user/redemptions → IUserCenterQueryService.GetRedemptionsAsync(userId)
/api/edu/user/apps        → IUserCenterQueryService.GetAppsAsync(userId)
```

userId 一律从 DomainUser/令牌解析（登录态 + 仅本人防护在**装配层强制**——门面显式 userId 参数，不做隐式推断）。

### 过渡期装配示例（认证中心桥接）

> （V0.2.0 起不再需要——保留仅作历史参考）

```csharp
// 继承 UserProfileSourceBase：仅实现查询钩子（映射/降级/日志管线已预实现）
public sealed class AuthAccountProfileSource : UserProfileSourceBase
{
    private readonly IAuthAccountQueryService _accounts;   // 认证中心查询服务（装配实例层可用，经认证中心门面）
    public AuthAccountProfileSource(IAuthAccountQueryService accounts, ILogger<UserProfileSourceBase> logger) : base(logger)
        => _accounts = accounts;

    protected override async Task<RawProfile?> QueryRawProfileAsync(string userId, CancellationToken ct)
    {
        var acct = await _accounts.GetByUidAsync(userId, ct);   // 查 AuthAccountEntity
        return acct is null ? null : new RawProfile(acct.Phone, acct.HasWechat, acct.Nickname, acct.Avatar, acct.TeacherVerified, acct.AuthLevel);
    }
}

// DomainHostConfigureServices：
services.AddScoped<IUserProfileSource, AuthAccountProfileSource>();
```

### 终态说明（认证中心 v0.2.0 —— ✅ 已实施）

认证中心 v0.2.0 **已实现** `IUserProfileSource`（`AuthAccountUserProfileSource`，public sealed，经 `AuthCenterExtensionInitializer` **TryAddScoped** 注册）——消费方**同时白名单声明**认证中心 + UserCenter 后，`IUserCenterQueryService.GetProfileAsync` **自动获得真实档案**（AuthAccount 数据，Phone 门面强制脱敏）：
- **新装配实例无需再写桥接类**——零桥接样板。
- **已写过 `AuthAccountProfileSource` 桥接类**的装配实例**可删除**（含 `services.AddScoped<IUserProfileSource, AuthAccountProfileSource>()` 注册行）——零代码变更指 UserCenter 门面注入契约不变，删除后门面自动解析认证中心的实现。
- 档案映射：UserId←UId / Phone←Phone（原始值，门面脱敏）/ IsWechatBound←推导（MpOpenId/WebOpenId/UnionId 任一非空）/ Nickname / AvatarUrl←Avatar / IsTeacherVerified←TeacherVerified / AuthLevel←AuthLevel

## 三、降级行为（缺省/异常不阻塞）

| Source 注册状态 | GetProfileAsync | GetRedemptionsAsync | GetAppsAsync |
|---|---|---|---|
| 三 Source 全注册 | 完整档案（Phone 已脱敏） | 历史列表 | 应用列表 |
| `IUserProfileSource` 缺失 | **null**（装配方自行映射 404/匿名档案） | 正常 | 正常 |
| 兑换/应用源缺失 | 正常 | **空列表** | **空列表** |
| 三 Source 全缺 | null | 空列表 | 空列表 |
| Source 抛异常 | null + Warning | 空列表 + Warning | 空列表 + Warning |

异常静默（Warning 不冒泡）——不阻塞用户中心页面渲染（对齐仓库惯例）。

## 四、安全约束

| 项 | 约束 | 归属 |
|----|------|------|
| **IDOR 越权**（A 查 B 档案） | 门面显式 `userId` 参数 + 契约文档声明「仅本人令牌可读」——装配端点从 DomainUser/令牌解析 userId，**不信任客户端传参** | 装配实例（端点层强制）+ UserCenter（契约文档约束） |
| **手机号泄露** | 门面输出**强制脱敏**（PhoneMasker 前 3 后 4）；源/门面不得将含原始 Phone 的 DTO/异常栈写日志或序列化 | UserCenter（门面）+ 源实现方 |
| **兑换 code 明文** | `RedemptionRecordDto.CodeMasked` 契约约束（实现方输出前脱敏；授权面已脱敏存储，UserCenter 不持有明文） | Source 实现方 |
| **儿童数据红线** | `UserAppDto.UsageSummary` 契约约束「不含学习明细」 | Source 实现方（授权面） |

## 五、与认证中心 / 授权面划界

| 模块 | 职责 | 与 UserCenter 的关系 |
|------|------|--------------------|
| **认证中心**（`TKWF.Ext.Authentication`） | 令牌签发/验证 + 账号（AuthAccount）管理 | 认证中心 v0.1.0 零改动；**v0.2.0 已实现 `IUserProfileSource`（`AuthAccountUserProfileSource`）自动装配** |
| **授权面**（口令兑换，未立项） | 兑换/授权/管理端 | UserCenter 经 `IRedemptionHistorySource`/`IUserAppsSource` **读取视图**（缺省降级，不受未立项阻塞） |
| **UserCenter**（本扩展） | 档案**读取** + 聚合展示 + 脱敏/降级领域逻辑 | 零实体零存储（聚合读取层）；数据归各属主 |

## 七、v0.2.0+ 终态路径（最优解探索——装配层组合视图）

> 方法论依据：`docs/框架实战教学/01-扩展模块最优解探索-Schema级数据组合-开篇.md`（§八 终态路径）

认证中心 v0.2.0+ 后，装配层可升级为**组合视图** `vm_UserCenterProfile`（**首个跨扩展组合 VEntity 先例**）：

- **JOIN 基表**（认证中心 `AuthAccount` 等），非 VEntity（VIEW002 视图链禁令 + 解耦）
- **SQL 硬脱敏**直接作用于 `AuthAccount.Phone`（投影下沉——确定性规则）
- **仅本人防护**：`IGlobalQueryFilter` 按 UserId 过滤（框架 F6 候选 / 方案 A，推荐）或 `ExposeGraphqlQuery=false` 经门面暴露（方案 B）
- **生产部署**：SyncViewsAsync 只跑开发环境建视图；**生产需 DBA 手动执行 ViewSql**

> **选库决定 v0.2.0 可行性（P2 提示）**：组合视图要求档案数据与业务数据**同库**——分库部署时保持 v0.1.0 契约 + 门面拼装形态（契约层保留，不浪费）。
