# 微信公众号运营扩展-使用指南

> **扩展**: `TKWF.Ext.WeChatOperations`（微信公众号运营——实体型扩展）| **版本**: V0.3.1（2026-10-18——P2 对齐迭代：状态卡聚合/匹配过程明细/统计卡聚合/超时单位统一） | **框架**: .NET 10
> **定位**: 公众号运营能力扩展——渠道配置 / 素材 / 回复规则 / 菜单 / 订阅统计 / 日志 / **消息转发网关**的数据底座与业务门面；事件回复与消息转发消费平台库 `TKWF.Federation.WeChat`（通讯走库，单向依赖）+ 运行库 `TKWF.Federation.WeChat.MessageGateway`（纯判定）
> **关联文档**: 技术规范 `_Framework/WeChatOperations/README.md`；开发方案 `docs/WeChatOperations/微信公众号运营扩展-开发方案.md`；平台库指南 `docs/Federation.WeChat/微信公众平台连接器-使用指南.md`

## 一、定位（扩展是什么）

为消费方提供微信公众号**运营全链路**能力——从渠道凭证、素材、回复规则、菜单到订阅统计、日志审计，再到**消息转发网关**（把公众号消息按规则路由转发给下游业务系统）：

| 能力 | 说明 |
|------|------|
| **公众号渠道配置** | DB 权威（凭证 AES-GCM 密文）+ Options 降级两源并存；多公众号按 ChannelId 管理 |
| **素材库** | 文本/图文素材（图文四件套 Title/Description/Url/PicUrl），全局共享规则引用；**引用反查清单**（跨回复规则聚合引用位置） |
| **回复规则** | `ReplyRuleEntity` 全消息类型回复规则（Subscribe/Keyword/Click/Image/Voice/Video/ShortVideo/Location/Link/Scan/Default）+ 网关路由规则（消息类型多选） |
| **菜单管理** | 拉取/发布/快照/版本/回滚（两阶段底层能力；Click 映射独立于菜单结构）+ **click key 收集**（自动生成映射行） |
| **订阅统计** | subscribe/unsubscribe 事件驱动按 channel 按日按来源 upsert + 趋势查询 + **区间汇总（统计卡）** |
| **日志** | 交互日志（OpenId/时间/类型/内容/触发类型/回复/耗时/**匹配过程明细**）+ 发布审计 |
| **消息转发网关** | 消息路由规则匹配 → 幂等 → 转发决策（本地/异步抄送/同步透传）→ 降级链 + 熔断 + 全链留痕 |

**三部分分层**（用户裁定——扩展 = ②领域装配，①与③边界清晰）：

| 部分 | 载体 | 职责 |
|------|------|------|
| ① 运行库 | `TKWF.Federation.WeChat.MessageGateway` | **纯判定**——路由规则匹配 / 幂等键规范化 / 转发决策与降级链 / 熔断三态状态机（零实体零持久化零 DI 零 DB） |
| ② 领域装配 | **`TKWF.Ext.WeChatOperations`（本扩展）** | 数据底座（12 实体）+ 8 门面 + 事件回复 handler + 网关编排 `RouteAsync` + Web 端点（15 个） |
| ③ GUI | **DMP-Lite 消费方自研** | 菜单编辑器 / 素材管理 / 规则配置页面（R2 路径直连 REST）——本扩展不含 GUI（阶段二实证后拆回 `.UI` 扩展） |

## 二、引用与启用

### 1. 引用（消费方 .csproj）

```xml
<ProjectReference Include="..\_TKWF.Extensions\_Framework\WeChatOperations\TKWF.Ext.WeChatOperations.csproj" />
<ProjectReference Include="..\_TKWF.Extensions\_Framework\Federation.WeChat\TKWF.Federation.WeChat.csproj" />
```

> 运行库 `TKWF.Federation.WeChat.MessageGateway` 经扩展传递引用（判定逻辑在 handler/网关编排帧内调用），消费方无需显式引用。

### 2. 启用（白名单声明）

```csharp
[TKWFEnabledExtension(typeof(WeChatOperationsExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后三钩子自动接线：8 门面（6 运营 + 2 网关）`AddConstructibleService` + handler `TryAddEnumerableConstructible` + keyed `ISymmetricKeyProvider`（`WeChatOperationsKeyProviderKeys`）+ `DbWeChatCredentialResolver`（DB 命中解密 + Options 降级两源并存）+ `DbWeChatChannelSource`（Insert(0) 前置）+ 网关装配（`DownstreamForwardClient` typed client + `WeChatMessageForwardJob` 作业注册 + 系统用户桥 + 熔断 `WeChatCircuitBreaker` 单例）。

### 3. 门面消费（`User.Use<T>()`）

运营/网关门面均为**领域服务**（`IDomainService`）——**禁构造注入**（DI004 零豁免），经 `User.Use<T>()` 帧内解析：

```csharp
// 消费方 DomainUser 帧内
var menuService = user.Use<IMenuService>();
await menuService.PublishAsync("wechat-mp-main", menuJson, ct);

var gateway = user.Use<IMessageGatewayService>();
await gateway.SaveRuleAsync(new MessageRouteRuleEntity { ChannelId = "wechat-mp-main", ... }, ct);
```

### 4. Web 装配（可选——运营管理端点，V0.2.0 起）

```csharp
app.UseWebExtensions(e => e.Add<WeChatOperationsWebExtension<MyUserInfo>>(x => x.ConfigureOptions = o => o.RoutePrefix = "/api/wechat-ops"));
```

> ⚠️ **须与 `UseWebSession` 同装配**（ContextExtraction 写 `DomainUser`——端点经已认证帧 `user.Use<门面>()` 调用守卫工厂门面；未装配 → 抛守卫 = 正确 fail）。

## 三、配置 `TKWF:WeChatOperations`

```jsonc
{
  "TKWF": {
    "WeChatOperations": {
      "DefaultReplyText": "感谢您的关注，请稍后再试。",   // 未命中关键词默认兜底文案
      "SecretEncryptionKeyPath": "<AES-GCM 密钥文件路径>", // 生产必配（缺钥 fail-fast）；开发随机兜底
      "IsProduction": true,                             // 生产 true / 开发 false
      "Gateway": {                                      // 消息路由转发网关（配置分层——领域安全/转发决策归本节，Web 层无对应开关）
        "GatewayEnabled": false,                        // 网关全局开关——默认 false（fail-closed 默认关，未启用时 handler 零回归不查库不转发）
        "IdempotencyRetentionDays": 7,                  // 幂等保留天数（覆盖微信全部重试窗口 + 对账余量；0/负数 = 不清理；仅清理终态记录）
        "PendingTimeoutMinutes": 5,                     // 幂等 Pending 超时分钟（超时后允许新请求复用键重建 Pending+转发——防陈旧 Pending 数据丢失窗口）
        "AsyncForwardRetryCount": 3,                    // 异步抄送投递重试次数（BackgroundJob 队列 MaxRetryCount；下游须幂等——IdempotencyKey 透传自去重）
        "BackoffSeconds": 2,                            // 异步抄送失败退避秒数（指数退避 2^RetryCount 秒基础值）
        "DefaultSyncTimeoutSeconds": 2                  // 同步透传默认超时秒数（上限强制 ≤3 防运维误配吞兜底窗口；端点 TimeoutSeconds 缺省回落本节）
      },
      "Web": {                                          // 表现层暴露面（配置分层）
        "RoutePrefix": "/api/wechat-ops"
      }
    }
  }
}
```

> **凭证来源（两源并存）**：① `WeChatChannelConfigEntity`（DB——AES-GCM 密文，权威）；② `WeChatOptions.Channels`（`TKWF:Federation:WeChat` 节——降级）。DB 命中解密返回，未命中回退 Options。**下游端点鉴权令牌**（`DownstreamEndpointEntity.AuthTokenCipher`）同为 AES-GCM 密文落库——明文仅出站瞬时。
>
> **配置分层（AGENTS §8）**：领域安全/转发决策（`GatewayEnabled` fail-closed、幂等保留期、超时上限）归 `:Gateway` 领域节——`WeChatOperationsEndpointOptions`（`:Web`）**不存在**关闭领域行为的对应开关（防表现层绕过）；`:Web` 仅承载 `RoutePrefix` + 端点开关（POCO 不镜像领域配置）。

## 四、基础能力使用

以下门面均在 `User.Use<T>()` 帧内调用（`ct` 为可选取消令牌）。

### 1. 渠道配置 `IChannelConfigService`

| 方法 | 说明 |
|------|------|
| `ListAsync(ct)` | 全量渠道 DTO 列表（**DTO 投影无凭证密文**——Oracle P1） |
| `GetAsync(appId, ct)` | 按 AppId 取单渠道 DTO |
| `SaveAsync(entity, appSecretPlain?, tokenPlain?, encodingAesKeyPlain?, ct)` | 新建/更新（凭证明文参数可空 = 保持既有；AES-GCM 加密落库）→ 返回 Id |
| `DeleteAsync(id, ct)` | 删除渠道 |

```csharp
var channels = user.Use<IChannelConfigService>();
await channels.SaveAsync(new WeChatChannelConfigEntity { ChannelId = "wechat-mp-main", AppId = "wx...", DisplayName = "主公众号" },
    appSecret: "xxx", token: "yyy", encodingAesKey: "zzz", ct);
```

### 2. 素材库 `IMaterialService`

| 方法 | 说明 |
|------|------|
| `ListAsync(kind?, ct)` | 素材列表（kind 可空 = 全部） |
| `SaveAsync(material, ct)` | 新建/更新素材 → 返回 Id |
| `DeleteAsync(materialId, ct)` | 删除（**被规则引用禁止删除**） |
| `GetReferencesAsync(materialId, ct)` | **引用反查**——跨回复规则聚合 `MaterialReferenceDto` 清单（SceneType 语义/规则 Id/TriggerKey——DMP-Lite 5.2 "引用 N 处"） |

```csharp
var materials = user.Use<IMaterialService>();
await materials.SaveAsync(new MaterialEntity { ChannelId = "wechat-mp-main", Kind = 1, Content = "欢迎语文本", ... }, ct);
var refs = await materials.GetReferencesAsync(materialId, ct);   // 该素材被哪些规则引用
```

### 3. 回复规则 `IReplyRuleService`

| 方法 | 说明 |
|------|------|
| `ListRulesAsync(channelId, sceneType?, ct)` | 规则列表（sceneType 可空 = 全部场景） |
| `SaveRuleAsync(rule, ct)` | 新建/更新规则（SceneType 覆盖 Subscribe/Keyword/Click/Image/Voice/Video/ShortVideo/Location/Link/Scan/Default）→ 返回 Id |

```csharp
var rules = user.Use<IReplyRuleService>();
await rules.SaveRuleAsync(new ReplyRuleEntity { ChannelId = "wechat-mp-main", SceneType = 2 /*Keyword*/, TriggerKey = "优惠", ReplyContent = "最新优惠活动：...", ... }, ct);
```

### 4. 菜单管理 `IMenuService`

| 方法 | 说明 |
|------|------|
| `GetCurrentAsync(channelId, ct)` | 当前菜单（`WeChatSelfMenuInfoResult?`） |
| `PublishAsync(channelId, menuJson, ct)` | 发布菜单（**事务：快照 + 版本 + 审计**） |
| `ListVersionsAsync(channelId, ct)` | 版本列表 |
| `RollbackAsync(versionId, ct)` | 回滚到指定版本（加载该版本 AfterJson 重新发布） |
| `GetClickKeysAsync(channelId, ct)` | **菜单树递归收集 click 类型按钮 Key**（快照空/解析失败 → 空列表——DMP-Lite 5.4 自动生成映射行） |

```csharp
var menu = user.Use<IMenuService>();
await menu.PublishAsync("wechat-mp-main", menuJson, ct);
var clickKeys = await menu.GetClickKeysAsync("wechat-mp-main", ct);   // 生成 Click 映射候选
```

### 5. 订阅统计 `ISubscriptionStatService`

| 方法 | 说明 |
|------|------|
| `RecordAsync(channelId, eventType, source?, ct)` | 记录订阅/取关计数（1=subscribe / 2=unsubscribe）——每日 upsert（(ChannelId, StatDate, Source) 唯一约束） |
| `GetTrendAsync(channelId, from, to, source?, ct)` | 按日趋势（[from, to] 闭区间；source 可空 = 仅汇总行） |
| `GetSummaryAsync(channelId, from, to, source?, ct)` | **区间汇总（统计卡聚合）**——`SubscriptionStatSummaryDto`（区间新增/取消/净增/日均/累计增长率） |

```csharp
var stats = user.Use<ISubscriptionStatService>();
await stats.RecordAsync("wechat-mp-main", 1, "search", ct);   // handler 帧内自动调用
var summary = await stats.GetSummaryAsync("wechat-mp-main", from, to, null, ct);
```

### 6. 日志查询 `ILogQueryService`

| 方法 | 说明 |
|------|------|
| `ListInteractionsAsync(channelId, openId?, from?, to?, triggerType?, ct)` | 交互日志筛选（MsgTime 降序；triggerType 值域 1..12 对齐 `WeChatReplySceneTypes`；含 `DurationMs` 耗时 + `MatchTraceJson` 匹配过程明细） |
| `ListPublishLogsAsync(channelId, ct)` | 菜单发布审计（Action=Read/Create/Delete/Test；OperateAt 降序） |

```csharp
var logs = user.Use<ILogQueryService>();
var interactions = await logs.ListInteractionsAsync("wechat-mp-main", openId: "oX...", from: today, ct);
```

### 7. 系统状态聚合 `IWeChatOperationsStatusService`（V0.3.1）

| 方法 | 说明 |
|------|------|
| `GetStatusSummaryAsync(channelId, ct)` | 四卡聚合 `WeChatOperationsStatusDto`（Connected/ConnectedDetail/TodayMessageCount/AutoReplyHitRate/ForwardSuccessRate——DMP-Lite 5.8；当日口径 UTC 自然日半开区间；**DTO 零凭证**） |

```csharp
var status = user.Use<IWeChatOperationsStatusService>();
var card = await status.GetStatusSummaryAsync("wechat-mp-main", ct);
```

## 五、消息转发网关（V0.2.0+）

网关把公众号消息按**路由规则**匹配后**转发给下游业务系统**（HTTP 出站），全程幂等 + 留痕 + 降级。

### 1. 四实体语义

| 实体 | 表 | 语义 |
|------|-----|------|
| `MessageRouteRuleEntity` | `TKWF_WeChatMessageRouteRule` | 路由规则——ChannelId + MsgType + Event + MatchMode + TriggerKey 五键匹配，同键覆盖更新；**MsgType 逗号分隔多值**（"text,image,event" 任一命中，空 = 全类型通配） |
| `DownstreamEndpointEntity` | `TKWF_WeChatDownstreamEndpoint` | 下游端点——BaseUrl + Path（可空）拼接出站目标，HttpMethod 默认 POST；AuthType 0=None / 1=Bearer / 2=Header 自定义头；`AuthTokenCipher` AES-GCM 密文落库 |
| `MessageForwardLogEntity` | `TKWF_WeChatMessageForwardLog` | 转发流水全链留痕——Status 值域 Queued=1/Success=2/Fail=3/Timeout=4/SkippedDuplicate=5/NoRule=6 |
| `WeChatMessageIdempotencyEntity` | `TKWF_WeChatMessageIdempotency` | 幂等键——LastStatus Pending=1/Forwarded=2/Skipped=3；唯一索引防并发双转发 |

### 2. 开关（fail-closed）

`GatewayEnabled` **默认 false**——未开全局开关/未配规则时 `RouteAsync` 首行判定直接返回未接管，既有 handler 零回归（不查库不转发）。**开启后**路由规则/幂等/转发全部生效。

### 3. 转发策略（三[四]策略）

运行库 `WeChatMessageForwardModes` 四策略，`RouteAsync` 编排决策：

| 策略 | 语义 |
|------|------|
| `LocalOnly` | 仅本地渲染回复，不转发 |
| `AsyncCopy` | **异步抄送**——转发日志 Queued 落库 + `IBackgroundJobManager` 入队 `WeChatMessageForwardJob`（at-least-once + 指数退避重试，幂等键透传下游自去重） |
| `SyncProxy` | **同步透传（V0.3.0）**——出站透传 `DownstreamForwardClient.SendRawXmlAsync` → 下游完整响应 XML 经 `WechatReplyPayload.RawXml` **原样接管回复**（防双重信封） |
| `PreprocessSync` | 与 SyncProxy **同语义**（透传 + 降级）；前置处理差异归后续迭代 |

### 4. 幂等机制

- `WeChatMessageIdempotencyKeyBuilder` 规范化键：`msg:`/`evt:` 前缀类型隔离 + ChannelId 入键——消息用 MsgId / 事件用 FromUserName+CreateTime 双形态。
- `RouteAsync` **幂等检查最前短路**：微信重推命中既有键 → 静默跳过（转发日志 SkippedDuplicate 留痕审计对账可见）——防止同一消息双转发/双回复。
- Pending 超时复用：`PendingTimeoutMinutes`（默认 5）超时后允许新请求复用键重建 Pending+转发，防陈旧 Pending 数据丢失窗口。
- 清理：`IdempotencyRetentionDays`（默认 7）仅清理终态（Forwarded/Skipped）记录。

### 5. 降级链

转发失败/超时/非 XML/HTTP 非 2xx → 转发日志 Timeout/Fail（ErrorMsg 脱敏）→ 运行库 `WeChatMessageForwardDecider` 降级 **LocalFallback**——降级链步进 `LocalRender → Template → DefaultReplyText`（本地回复兜底，不 500）。

### 6. BackgroundJob 前置接线

```csharp
// 消费方领域初始化器 ConfigureServices——异步抄送前置（V0.2.0 起必需）
services.AddBackgroundJobs<TUserInfo>();
```

> ⚠️ AsyncCopy 分支经 `IBackgroundJobManager` 持久化队列投递（TKWF_JobRecord 重启续投 + 重试 MaxRetryCount + SystemActor 帧自动绑定）。**缺接线时**入队失败经网关 fail-safe 降级（本地回复不受影响不 500，转发日志 Fail 行留痕可对账）。

### 7. SyncProxy RawXml 透传（V0.3.0）

`RouteSyncProxyAsync` 出站透传：`__decrypted_xml` 明文 XML 原样 POST 下游 → 下游完整响应 XML 经 `WechatReplyPayload.RawXml` **原样接管回复**（跳过 text/news 重组——防双重信封）。判定：2xx + `IsValidReplyXml` 合法 `<xml>` 结构。透传成功/失败均更新幂等表 Forwarded——键存在跳过不重复透传（幂等联动）。

### 8. 熔断（进程内存）

`WeChatCircuitBreaker` 运行库熔断状态机（关→开→半开→关）——Initializer `AddSingleton` 进程内单例接线，**每 EndpointId 独立计数**（默认阈值 3 / 开窗 60s）；开闸期 `RouteAsync` 直接 LocalFallback 不转发。⚠️ **多实例部署各自独立**（进程内存，重启即清零）——跨实例熔断聚合归后续迭代。

### 9. 超时单位（V0.3.1 统一）

- **领域秒契约**：`DownstreamEndpointEntity.TimeoutSeconds`（1..3 上限 ≤3——微信 5 秒硬时限留本地兜底窗口；端点缺省/0/负回落 `DefaultSyncTimeoutSeconds` 默认 2）。
- **前端毫秒派生**：`DownstreamEndpointDto.TimeoutMs => TimeoutSeconds * 1000`（**非存储列不落库**，positional arity 不变）——前端表单展示/提交毫秒，服务端按秒契约存储。

## 六、DMP-Lite 对齐接口（V0.2.1/V0.3.0/V0.3.1）

| 项 | 接口/字段/端点 | 满足 DMP-Lite 章节 |

## 八、安全边界

- **凭证密文落库**：AppSecret/Token/EncodingAESKey/下游 AuthToken AES-GCM 单段密文（base64(nonce‖cipher‖tag)，keyed `ISymmetricKeyProvider`）——明文不入库不进日志；解密仅出站瞬时
- **DTO 投影**：`GetAsync/ListAsync` 返回 DTO 不含凭证密文；状态聚合 DTO 只含布尔/计数/比率（Oracle P1）
- **出站日志脱敏**：access_token 经 query string 传参——出站日志脱敏；转发失败 ErrorMsg 脱敏
- **异常消息**：解密失败/凭证缺失异常消息不含明文
- **不走动态加载**：DB 不存 handler 类型名；回复 handler 全部编译期静态注册（`WeChatOperationsReplyHandler` + 通道级差异经 `IChannelSpecificEventReplyHandler` W3 绑定桶）——DB 只存规则数据
- **配置分层**：领域安全行为（`GatewayEnabled` fail-closed/凭证加密）Web 层不可关闭（`:Web` 无对应开关，防表现层绕过）
