## 一、转达 1（网关运行时开关）：契约事实修正 + 裁定 A 成立

### 1.1 事实修正（DMP 侧定性需更新一处）

DMP 表「运行时开关（enabled）：`SetGatewayEnabledAsync` —— **`IsExposed=false`（REST-only），SG3 不生成**」——**前半句属实，契约判断需修正**：

| 项 | 扩展仓实证 | 证据 |
|----|-----------|------|
| REST 端点 | **存在且已上线**——`[ApiExpose(RestRoute = "/gateway/enabled", RestMethod = "POST")]`（V0.4.0，`POST /api/wechat-ops/gateway/enabled`，`SetGatewayEnabledRequest` → [FromBody]） | `_Framework/WeChatOperations/MessageGatewayService.cs` L86-91 |
| IsExposed=false 的实际影响面 | **仅 SG3 客户端代理**——v4.10.87 ADR113 口径：`IsExposed` = 可映射 &&（GraphQL 通道 \|\| REST 通道）；本方法返回**非泛型 `Task`** → GraphQL 通道不可映射（mutation 需类型化返回字段）→ SG3 客户端不生成该代理方法 | `Directory.Packages.props` v4.10.87 注记 |
| 端点生成通道 | SG2/B4 照常生成（端点发射读 `[ApiExpose]` 声明，不依赖 ApiMetadata IsExposed）——**契约写面存在** | WeChatOperations README §三 V0.6.0 端点总表（25 端点含 `enabled`） |

**结论**：契约能力**非只读**——写面（REST `POST /gateway/enabled`）自 V0.4.0 起存在；DMP 页面只读的真实根因 = **SG3 客户端代理缺失**（非泛型 Task 返回在 GraphQL 通道不可映射，v4.10.87 ADR113 起 SG3 不再误生成）。

### 1.2 裁定（二选一 → 扩展组裁定 A + 补强说明）

- **裁定 A（采纳，零契约变更）**：关切「运行时开关」确认降级为**只读状态展示**；运行时切换归运维/admin 渠道（REST 端点契约已具——admin 侧可经标准 REST 客户端调用，非发明新 API 面）。DMP 页面现状 = 终态，转达通知审核报告可勾对。
- **补强说明（可选，不阻塞）**：若 DMP 后续要 GUI 写交互，**无需扩展组契约变更**——直接消费既有 REST 端点 `POST /api/wechat-ops/gateway/enabled`（标准通道：`AddRestApiClient` + 既有 wire DTO `SetGatewayEnabledRequest`；SG3 代理缺失期手写 REST 调用属标准契约消费，不违反边界契约 §四.8「不发明 API 面」）。扩展组**不**为该方法开放 GraphQL 面（非泛型 Task 无返回字段，语义上为命令式写操作，REST-only 是设计内状态）。
- 是否将返回类型升级为 `Task<GatewayEnabledResultDto>`（换取 SG3 代理恢复）→ 记为可选增强项，**不在本轮回执决策**（版本线/消费方影响另行评估）；DMP 无诉求则维持。

## 二、转达 2（SG2a WARN007）：归属 = ① refs/构建版本不一致（非 ADR117 已知边界）

### 2.1 扩展仓证据链（当前产物 WARN007 不会发生）

| # | 证据 | 实测结果 |
|---|------|---------|
| 1 | SG2a 契约接口生成物 | `obj/GeneratedFiles/.../ControllerGenerator/IPermissionGrantEntityDataService.ExtI.g.cs` 存在（V4.10.92/ADR118 机制——`[GenerateController]` DataService 自动产 `{扩展根Ns}.I{X} : IDomainService`），**非**「无手写门面接口」形态 |
| 2 | 权威注册真名 | `_GeneratedControllerCatalog.g.cs` `InterfaceNames = "TKWF.Ext.Permissions.IPermissionGrantEntityDataService"`（无 `.Controllers` 假名） |
| 3 | **refs DLL 实测（关键）** | `%TKWFDeployPath%\build\refs\TKWF.Ext.Permissions.dll`（2026-11-06 **19:19** 构建，0.9.6.0，源码基线 c1ee3b1 = tag `Permissions/v0.9.6`）经 ALC 反射：**接口 TypeDef 存在**（iface=True）+ `GeneratedControllerCatalog.InterfaceNames` 真名一致——**消费方 SG2a 用此 DLL 解析必然成功** |
| 4 | 扩展仓自证测试 | `_Tests/Extension.Permissions.Consumer/ConsumerIntegrationTests.cs` `Sg1b_InterfaceNames_IncludesPermissionDataService` 断言真名进 `GeneratedControllerRegistrations.InterfaceNames`（v4.10.96 ADR120 语义） |

### 2.2 判定

- **归属原因①（refs/源码 SDK 构建版本不一致）**。DMP 侧 refs（16:16 构建 0.9.6.0）为**陈旧产物**——该构建时主框架 local-feed 刚部署 `4.10.110-local`（16:03），编译服务器（VBCSCompiler 常驻）若复用旧版 `TKWF.CodeGeneration` 分析器（Roslyn 增量缓存 bug 先例），ExtI 接口未生成 → DLL 无接口 TypeDef → 消费方 SG2a `GetTypeByMetadataName` 返回 null → WARN007。
- **非原因②（ADR117 已知边界）**：ADR117 指 DataService「无手写门面接口 → 消费方无解析目标」；本 DataService 接口由 SG2a **自动产出**（ExtI.g.cs），权威注册真名（无 `.Controllers` 假名），不属该边界。
- **`[GenerateController(FromDataService=true, ExcludeMethods=...)]` 已显式收敛写面**（Create/Update/Delete 排除——越权授权面修复，2026-10-15）：DataService **应当暴露管理面**（SetGrantAsync/RevokeGrantAsync + 只读查询，`WeChatOperations` 同款范式），不需要「显式不生成」。

### 2.3 DMP 动作

1. **刷新 refs 复验**：用扩展仓 19:19 构建的 `TKWF.Ext.Permissions.dll 0.9.6.0`（与扩展仓 refs 同步；`build-ext-deployment.ps1 -Ext Permissions` 重推亦可）重编 DMP-Lite.slnx（源码模式 + DLL 模式双复验）→ 预期 WARN007 归零。
2. 若复验后 WARN007 仍现（极端情形：DMP 侧 NuGet 缓存/本机 nuget.config local-feed 未指向 `%TKWFDeployPath%\local-feed` → 旧 CodeGeneration 分析器），按 WARN007 提示原因①的「新版 SDK 重建」路径处理——扩展仓当前 SDK = `TKWF.CodeGeneration 4.10.110-local`。
3. 权限管理 UI 规划不受阻：SG2a 解析恢复后 REST/GraphQL 端点 + SG3 客户端桩即齐（SetGrantAsync/RevokeGrantAsync/GetByPermissionNameAsync 等已 `[GenerateControllerMethod]` 标注涉写方法齐全）；IPageContributor 落地另行。
