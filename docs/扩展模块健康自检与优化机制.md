# 扩展模块健康自检与优化机制

> **一句话入口（AGENTS 同款）**：触发词「自检」「优化」→ 执行 `pwsh build/build-ext-healthcheck.ps1`（只读，产出报告到 `docs/健康自检/`），并按本文件 §6 闭环。
>
> 适用：`TKWF.Extensions` 全仓库（`_Framework/` + `_Tests/` + `docs/` + 构建/发布资产）。
> 定位：**仓库级周期性体检机制**——不替代开发流程（方案评审/代码审核/测试纪律），而是补上「时间维度」的横切检查：随迭代演进产生的漂移、债务与失同步。
> 版本：v1.3（2026-11-21 立项 + 首轮实践 + Oracle 优化评审 + 复查收敛） | 状态：活跃

---

## 1. 目的与不在范围

### 1.1 目的

用一个**低摩擦、可重复、可机器执行**的巡检回路，持续回答四个问题（并留下证据）：

1. **单个扩展是否健康**——结构、命名、生成物、数据访问红线、测试覆盖。
2. **扩展之间是否健康**——依赖方向、契约包、表名/视图撞名、族内实现复用边界。
3. **文档体系是否健康**——使用指南/设计文档/README/ADR 的完备性、命名、链接、元数据、单一事实源。
4. **文档与代码/版本是否同步**——版本事实、API/配置键、关键事实断言（防止"文档教的做法已被代码废弃"；端点路径校验见 §10.5 暂缓项）。

产出：**巡检报告 + 分级整改单 + 基线（棘轮）**，并把"机制本身的改进"也纳入台账。

### 1.2 不在范围（避免与既有流程重复）

| 不做 | 归属 |
|------|------|
| 判定一个开发方案是否合理 | Oracle 方案评审（AGENTS §3 步骤 3） |
| 逐文件代码质量审核 | `code-reviewer` 迭代级审核（AGENTS §8） |
| 替代 L0/L1/L2 测试纪律 | `docs/测试纪律-受影响面定向测试.md` |
| 代替人工做发布决策 | 用户裁定 + AGENTS §5 Tag 纪律 |
| 实时 CI 门禁（每次 push 全量） | `.github/workflows/ci-publish.yml`（巡检是低频、全仓、面向漂移） |

> 巡检的定位是**发现"流程之外、时间之中"的问题**：昨天正确的文档今天过期、上周合规的依赖今天越界、上次发布的版本表今天滞后。

## 2. 问题域全景

用户已点名 4 类；机制按"健康维度"扩展为 8 类（编号用于检查项归类）：

| # | 维度 | 典型病症（本仓真实先例） |
|---|------|--------------------------|
| 1 | **单模块健康** | 项目未进 slnx；csproj 名/MinVerTagPrefix/PackageId 不一致；实体改了但 `.g.cs` 未重生成（Permissions 曾漂移 2 周）；新增实体漏 xCodeGen 配置（Approval 曾缺） |
| 2 | **模块间一致** | 跨扩展直引他扩展主包（应走 `.Abstractions`，L2 `TKWF0022`）；表名/视图/索引前缀不规范或跨扩展撞名；族内实现复用（Federation.Oidc ← 平台库）越界 |
| 3 | **文档体系**（用户点名） | 缺使用指南/README；ADR 缺"三问"；文档命名混乱；相对链接失效（文件搬迁后）；重复嵌套目录（如 `ADR/ADR`） |
| 4 | **文档↔代码同步**（用户点名） | 指南里的 `User.Use<X>()` 类型已改名；配置键 `TKWF:xxx` 已变；端点路径已迁移；文档仍教已废弃的接线方式 |
| 5 | **文档↔文档同步**（用户点名"设计文档和使用文档之间"） | 规则文档与根 AGENTS 口径冲突（如"ProjectReference 引用框架源码" vs 已迁移 PackageReference）；一次性通知/转达文档长期滞留被当作现行规范 |
| 6 | **版本与发布** | README 版本表滞后于 tag（曾漂移 21 处）；`docs/versions.json` 过期；CPM 正式号与 Analyzer `-local` 锁不同步；部署 refs 存在孤儿 DLL |
| 7 | **质量基线与安全** | 数据访问红线（裸 `IFreeSql`/`IEntityDAC`/手写 Store）存量债务无台账、缓慢增长；内容列漏 `[MaxLength(-1)]`（曾致 Pg 22001）；硬编码密钥/口令样板被复制 |
| 8 | **治理熵** | 退役扩展残留（UserCenter）、草稿/临时文件、空目录、生成物误入库、变更记录无限膨胀、检查项本身失效（长期全绿但没人看） |

> 原则：**每类病症都能追溯到至少一个本仓历史事故或转达**。没有先例的检查项不进目录（防检查表膨胀）。

## 3. 设计原则

1. **单一事实源优先**：能由 git tag / 代码 / 配置派生的，不另设手工清单；已有 `docs/versions.json`（tag 派生）、`build/gen-versions.ps1`、`build-ext-deployment.ps1` 一律复用，不重造。
2. **机器优先，人工兜底**：判据可判定的写成脚本断言（Pass/Fail），不可判定的列为人工清单（如"设计取舍是否仍成立"）。脚本只读，不修改工作区。
3. **分层执行**：L0 秒级（注册/命名/链接）→ L1 十秒级（约 10–20s；+ 版本/生成物/跨模块）→ L2 全量（+ 构建/测试/部署一致性）。按场景选层，不每次都跑最重的。
4. **分级与棘轮**：P0/P1/P2 分级；**存量债务用基线（baseline）棘轮**——记"当前已知违规"，只允许减少、不允许新增（新增即失败）。避免"一上线就 200 条红"导致机制被放弃。
5. **报告即证据**：每条发现必须能定位（文件:行/包名/链接），整改后必须能复跑证明消失。
6. **低摩擦**：一条命令跑完；报告自动落盘；不要求开发者记检查表。
7. **机制可退出**：检查项有生命周期（新增→观察→强制→退役），长期高误报项必须降级或删除（见 §9）。

## 4. 检查目录（Check Catalog）

> 编号稳定，不随执行顺序变化。**手段**：`脚本` = `build-ext-healthcheck.ps1` 自动断言；`人工` = 报告模板中的清单项；`复用` = 调用既有脚本/CI。
> **级别**：P0 阻塞（构建/发布/契约破坏）；P1 应修（一致性/消费方可见失同步）；P2 卫生（可排期）；INFO 观察。

### 4.1 单模块（A）

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|
| HK-A1 | `_Framework/*/` 项目 ↔ `TKWF.Extensions.slnx` 双向一致；csproj 名 = `TKWF.Ext.{X}` / `TKWF.Federation.{X}`；`MinVerTagPrefix` = `{X}/v`；`PackageId` 与程序集名一致（`IsPackable=false` 例外） | 脚本 | P0/P1/P2 |
| HK-A2 | 每个扩展目录有 `README.md`；每个**对外主包**有使用指南（`docs/{目录}/*-使用指南.md`；契约/附属/平台包并入族内指南，正文提及按启发式判定） | 脚本 | P1/P2 |
| HK-A3 | 含 `[DomainGenerateCode]` 的扩展 ↔ `.xCodeGen/extensions/{name}.xCodeGen.json` 1:1；配置 `TargetProject` 可解析；`OutputDir` 为相对路径（禁绝对式/翻目录） | 脚本 | P1 |
| HK-A4 | 生成物新鲜：实体**声明源**（项目根 `*.cs` 带 `[DomainGenerateCode]`；`Entities/` 下是生成物）变更时对应 `.g.cs` 必须同步变更（**含已提交变更**：比较最后提交时间，防"提交后忘记重生成"） | 脚本 | P1 |
| HK-A5 | 数据访问红线：无新增裸 `IFreeSql` 注入、无新增 `IEntityDAC<` 注入、无新增手写 `*Store`（**`*.Abstractions` 的门面契约豁免**；存量入基线；新增自动升级 P1；Store 棘轮键=扩展+类型名） | 脚本 + 基线 | P1/P2 |
| HK-A6 | 内容列 `[MaxLength(-1)]`：字段名以 `Json/Content/Body/Payload/Html/Xml/Sql/Message/Template` 结尾的 string 必须显式无界（**等价接受 `StringLength = -1`；文档注明"截断"的有界列视为有意设计**；存量走基线） | 脚本 + 基线 | P1/P2 |
| HK-A7 | 每个主包有对应测试项目（纯运行库/模板/分析器由脚本内豁免清单覆盖） | 脚本 | P2 |

### 4.2 模块间（B）

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|
| HK-B1 | 跨扩展依赖方向：引用他扩展**主包**须为同族前缀（如 `Notifications.SignalR → Notifications`、`Federation.* → Federation.Oidc`）或 `*.Abstractions`；`.Abstractions` 不得引用任何实现包 | 脚本 | P0/P1 |
| HK-B2 | 表/视图/索引前缀：表 `TKWF_`、视图 `TKWFV_`、索引 `TKWFIX_`；跨扩展规范化后同名 = 撞名（扫描**实体声明源**：项目根带 `[DomainGenerateCode]` 的手写文件） | 脚本 | P1/P2 |
| HK-B3 | 契约包成对：主包引 `X.Abstractions` 时其在 slnx、PackageId 合法；契约包独立 tag 前缀正确 | 脚本 | P1 |
| HK-B4 | 权限键命名符合 `{模块}.{动作}` 约定、无跨扩展重复定义冲突（仅扫 `[RequirePermission]`；事件名/配置节另行人工） | 脚本（弱）+ 人工 | P2 |

### 4.3 文档体系（C）

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|
| HK-C1 | Markdown 相对链接（含图片）目标存在：`README.md`、`Agents_TKWF_Ext.md`、`docs/**/*.md`、`_Framework/**/README.md` | 脚本 | P1 |
| HK-C2 | 文档命名：开发方案 `vX.Y.Z-*-开发方案.md`；使用指南 `*-使用指南.md`；ADR 文件名 `ADR-*` 且**三问必填**（目的与目标/问题/使用场景） | 脚本 | P1/P2/INFO |
| HK-C3 | **关键事实断言**（文档不变量）：`build/healthcheck-doc-invariants.json` 声明的"某文档必须/不得包含某表述"——专门锁定"文档教的做法与代码现状相反"这类事故 | 脚本（配置驱动） | P1/P2 |
| HK-C4 | `docs/AGENTS.md` 路由表与反引号路径可解析（路由目标真实存在） | 脚本 | P2 |

### 4.4 文档↔代码（D）

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|
| HK-D1 | 版本一致性：`git tag`（事实源）→ `docs/versions.json` → 根 README 版本表 → `_Framework/{X}/README.md` 版本记录，四处最新版本一致（展示层滞后即报；**README 版本记录仅对已有版本段的文件检查**——无版本段视为不适用） | 脚本 | P1/P2 |

| HK-D3 | 指南中的配置键 `TKWF:*` 与代码配置节前缀相容（**排除 `TKWF:Api:*`/框架键**；扩展自有节才校验） | 脚本 | P2 |

### 4.5 版本与发布（E）

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|
| HK-E1 | tag 规范：`{Package}/vX.Y.Z` 或无前缀 `vX.Y.Z`（仅公共内容）；无非法格式；**tag 前缀须有对应项目**（退役包白名单） | 脚本 | P1/P2 |

| HK-E3 | 部署 refs 一致性（只读）：扩展 DLL 孤儿（无对应 csproj）/缺失/跨日批次提示 | 脚本（同口径，不调用部署脚本） | P1/P2 |

| ID | 判据 | 手段 | 级别 |
|----|------|------|------|

| ID | 判据 | 手段 | 级别 |

## 5. 执行模式与时机

### 5.1 三种模式

| 模式 | 命令 | 覆盖 | 耗时 | 用途 |
|------|------|------|------|------|
| **L0 快检** | `pwsh build/build-ext-healthcheck.ps1 -Mode L0` | A1/A2/A3、C1/C2/C4、E1、G2 | 秒级 | 提交前/日常随手 |
| **L1 标准**（默认） | `pwsh build/build-ext-healthcheck.ps1` | L0 + A4–A7、B1–B4、C3、D1–D3、E2–E4、F3、G1/G3/G4 | 十秒级 | 迭代收尾、tag 前、框架 lockstep 后 |
| **L2 全量** | `pwsh build/build-ext-healthcheck.ps1 -Mode L2 -WithBuild -WithTests` | L1 + 编译 + 全量测试 + 部署一致性收口建议 | 分钟~十分钟 | 周期性体检、发布门禁前 |

> `-UpdateBaseline`：把当前存量债务写入 `build/healthcheck-baseline.json`（棘轮基线）。**仅允许全仓 L1/L2**（`-Scope`/L0 会拒绝执行，防截断基线）；若本轮有"新增存量债务"，默认拒绝写入，需先修复或 `-ForceBaseline` 显式吸收（首次建立基线除外）。基线键**不含行号**（行号漂移不产生误报）。
> `-NoWrite`：只输出控制台，不写报告（基线仍会更新，便于 CI/临时演练）。
> `-Scope <扩展名>`：只巡检指定扩展及其受影响面（迭代期高频用）；**范围化报告文件名带 `-scoped-{Ext}`**，不覆盖全量报告（审计轨迹保护）。
> 退出码：`0` 通过；`1` 棘轮出现新增；`2` 存在 P0；`3` 基线操作被拒绝（范围/模式/新增未修复）。可直接用于未来 CI 门禁。

### 5.2 触发时机（建议节奏）

| 时机 | 模式 | 说明 |
|------|------|------|
| **每次迭代收尾**（提交前） | L1（可 `-Scope`） | **硬性**（2026-11-21 首轮验证：全仓约 10–20s，具备随手可跑条件）；与"受影响面定向测试"同批执行；报告随迭代提交 |
| **打 tag / 发布前** | L1 + 测试纪律 L2 | 与 `目录结构与版本管理规则.md` §3.3 发布清单合并，不重复检查版本表 |
| **框架 CPM/DLL lockstep 后** | L1 | 重点看 E2（基线一致）+ A4（生成物）+ B1（契约方向） |
| **新增/退役扩展、目录重构后** | L1（全量） | 重点 A1/A2/A3、B2、C1、G1 |
| **每周一次（建议周五）** | L1 全量（可选） | 迭代频繁时以"每次收尾"替代；周检作为兜底抽查，不强制占用整块时间 |
| **每月一次（建议月末）** | L2 | 含编译 + 全量测试 + refs 一致性收口（`build-ext-deployment.ps1 -SkipBuild -NoCleanOrphans` 只读巡检） |
| **事件触发**（不定时） | L1 | 消费方转达缺陷、CI 连续红、reviewer 发现系统性问题、重大文档搬迁 |
| **每季度** | 机制复盘 | 检查项有效性（见 §9），更新本文件与基线 |

> 节奏原则：**高频轻量、低频全量**。L1 必须做到"随手可跑"，否则机制会死；L2 与发布绑定，避免每周都跑全量测试。

## 6. 闭环流程（发现 → 整改 → 复核 → 回写）

```
① 执行巡检（脚本/人工清单）
      ↓ 报告：docs/健康自检/健康自检报告-YYYY-MM-DD.md
② 分级与提炼整改单（Sisyphus/负责人）
   - P0 立即修（阻塞构建/发布/契约）
   - P1 本迭代内修（拆条目：文件+行号+动作+依赖）
   - P2 入待办池（按季度清理）
   - INFO 观察，不建单
      ↓
③ 分派修复（AGENTS §8 审核-修复闭环规则）
   - 无依赖条目 → 并行 deep1~8 / code-execute
   - 高影响（契约/安全/核心路径）→ 人工或指定 Go 通道
      ↓
④ 复核：修完重跑巡检（同一模式）+ 必要测试；P0/P1 需证据（命令输出/行号消失）
      ↓
⑤ 回写：报告状态列 [已修复/未修复/新问题]；基线收紧（-UpdateBaseline）
      ↓
⑥ 机制复盘（每季度/每次重大误报后）：
   新增检查项？降级/删除高误报项？调整节奏？更新本文件版本号
```

**整改单格式**（报告 §整改清单）：

| ID | 级别 | 文件:行 | 问题 | 动作 | 依赖 | 状态 |
|----|------|---------|------|------|------|------|

## 9. 机制自身的演进（防退化）

### 9.1 检查项生命周期

```
提出（有真实先例） → 观察（只报告不阻断，1 个季度）
  → 强制（进 P0/P1） → 稳定 → 退役（误报高/已被流程内化）
```

- **新增条件**：至少 1 个本仓真实事故/转达；能给出明确判据；能定位到文件；**必须自证非空转**（用已知正例验证会命中，见 §10.2 #7）。
- **降级/退役条件**：连续 2 个季度 0 命中且已被其他流程覆盖；或误报率 > 30% 且无法收敛。
- **误报处理**：个例误报优先改判据，其次加 `-Scope` 豁免，最后进基线并在报告留痕；**系统性高误报**（>30%）按生命周期降级/退役，不以基线长期掩盖。

### 9.2 棘轮（Ratchet）

- 存量债务（A5/A6/G2）首次落地时全量入基线（首轮 A5=43；Oracle R5 修正后 A5=40——Abstractions 门面契约豁免）；此后**新增即失败**（自动升级 P1）。
- 每次修复后执行 `-UpdateBaseline` 收紧；基线条目数应单调不增。
- 基线键 = `检查项|文件/类型|规则类别`（不含行号；A5 用"扩展+类型名"）；文件移动/改名会被视为"新增 + 消除"，属预期（需人工判断是否等价迁移）。
- 报告显式展示"基线 N 条 → 本次 M 条（新增 X / 消除 Y）"。

### 9.3 机制健康指标（报告摘要展示前 3 项；误报率人工登记）

| 指标 | 含义 | 目标 | 数据来源 |
|------|------|------|----------|
| P0/P1 数 | 阻断/应修数量 | 迭代收尾时为 0 | 报告摘要 |
| 新增 vs 消除 | 相对上次报告 | 收敛 | 报告棘轮行 + `healthcheck-history.jsonl` |
| 整改闭环率 | 上期 P0/P1 未决已修复占比 | ≥ 80% | 报告摘要自动计算（对比 history 上一条 `open`） |
| 误报率 | 人工判定为误报的条目占比 | < 15% | 人工登记（当前未自动采集） |

### 10.2 机制层经验（写回本文件）

1. **先跑 L0 再跑 L1**：L0 秒级暴露脚本自身缺陷（如 `$pid` 只读变量冲突），避免在 L1 的几十条输出里捞脚本错误。
2. **棘轮必须"首次即入基线"**：首轮 43 条存量若不入基线，机制会因"一片红"被放弃。基线与 `-UpdateBaseline` 是机制可用性的关键组成。
3. **基线键禁含行号**：首版用 `path:line`，任何编辑都会让键漂移→误报"新增"；改为 `检查项|文件|规则类别`。
4. **报告要能区分"存量"与"新增"**：摘要显式写"基线 43 现存 / 新增 0 / 已消除 0"，否则 P2 数量会被误读为质量退化。
5. **发现数与耗时**：L1 全仓约 10–20s（首轮 13.8s；受 git 缓存/机器影响），满足"随手可跑"；因此把"每次迭代收尾 L1（可 `-Scope`）"定为**硬性**，每周全量降为可选抽查（避免形式化）。
6. **真实问题集中在四类**：版本展示层、相对链接、历史文档口径、结构残留——恰好验证了用户列出的"文档-代码/文档-文档同步"是主战场。
7. **检查项必须"自证非空转"**：首版 A4/A6/B2 按 `Entities/` 目录扫描，而本仓实体声明在**项目根**（`Entities/` 下是 `.g.cs/.biz.cs` 生成物）→ 三项长期 0 命中（假绿）。修正扫描源后 A6 立刻暴露 10 条真实内容列风险。**新增/修改检查项必须用一个已知正例验证会命中**（如"随手挑一个 `*Entity.cs` 应被 B2/A6 统计"）。
8. **"无界"判据要给等价口**：FreeSql `StringLength = -1` 与 BCL `[MaxLength(-1)]` 等价；代码注释明确"截断 N 字符"的有界列属有意设计——否则 A6 4 条误报。

### 10.4 误报治理（判据修正记录）

| 误报 | 根因 | 修正 |
|------|------|------|
| A1：58 个测试项目"未注册 slnx" | slnx 用 `/`，脚本用 `\` 比较 | 路径统一 `/` |
| A3：HealthCheck 被误判实体型 | 命中 XML 文档注释里的 `[DomainGenerateCode]` | 注释感知（跳过 `//`/`///`/`*`） |
| B2：DTO/`.biz.cs` 表名越界 | 扫描了非实体声明文件 + 注释 | 仅扫 `Entities/*Entity.cs`（非 DTO/生成物），去注释 |
| B3：所有 Abstractions 引用"不存在" | 正则捕获到 csproj 文件名而非目录 | 取路径倒数第二段 |
| D1/E4：61 个包"不在 README" | CRLF 下 `(?m)$` 与 `[^\r\n]*` 不匹配 | 逐行 `ReadAllLines` 解析 |
| D2/D3：框架/消费方键与历史类型 | 未区分归属与迁移说明 | 排除 `TKWF:Api:*`；跳过"更名/废弃/迁移"行；框架类型经 refs XML 排除 |
| A4/A6/B2：长期 0 命中（**假绿**） | 扫描 `Entities/` 目录，而实体声明在项目根 | 改为扫描带 `[DomainGenerateCode]` 的手写根文件 |
| A6：`StringLength=-1`/截断列误报 | 只认 BCL `[MaxLength(-1)]` | 接受 FreeSql 等价写法与"截断"说明 |

> 结论：**检查项的判据必须"注释感知 + 路径归一 + 行解析 + 归属过滤 + 自证非空转"**，这五条已固化进脚本实现约定（新增检查项同此要求）。

### 10.5 Oracle 评审与采纳（2026-11-21，优化导向）

评审结论：**机制方向正确，重点是"保护棘轮不自毁、补齐提交后盲区、结果跨机可复现、节奏从荣誉制变强制"**。已采纳（v1.2）：

| # | 建议 | 落地 |
|---|------|------|
| R1 | `-UpdateBaseline` 防呆 | 全仓 L1+ 才允许；本轮"新增存量"默认拒绝，需 `-ForceBaseline`；退出码 3 |
| R2 | A4 补"已提交漂移" | 比较实体源 vs `.g.cs` 的最后提交时间（git log），mtime 降为提示 |
| R3 | 结果可复现 | E2 lockstep 组从 CPM 派生（不再硬编码 11 包）；D2 无 refs 时显式降级；报告头增加环境行（DeployPath/refs/local-feed） |
| R4 | 节奏自动化 | 新增 HK-G4（报告 >14 天或早于最新 tag → P2）；新增 `healthcheck-history.jsonl` 趋势台账；CI 定时作业列为下一步（见下） |
| R5 | A5 类别纠正 | `*.Abstractions` 内 `*Store` 视为门面契约豁免（基线 43→40）；棘轮键改为"扩展+类型名"（文件移动不误报） |

附加采纳：A1"缺 MinVerTagPrefix"（会静默继承公共 `v` tag）；E1 tag 前缀无对应项目（退役白名单）；C2 ADR 三问锚定标题；F3 降为 P1（启发式不硬阻断）；报告折叠基线内债务（信噪比）；范围化报告独立文件名；`-Scope` 不覆盖全量报告。

**暂缓/下一步**（价值高但需专门排期）：
1. 合约包 **public API 快照**（`publicapi.txt` 或 `dotnet-analyzer get_api_surface`）——当前唯一触及仓外消费者的"契约语义漂移"。
2. 指南端点路径 ↔ 代码路由交叉校验（AuthCenter V0.12 的 `?app_id→?appId`、`logout 204→200` 类破坏）。
3. 文档关键默认值断言（如频控阈值"默认 N"）进入 `healthcheck-doc-invariants.json` 正则抽取。
4. CI 定时作业（weekly `pwsh build/build-ext-healthcheck.ps1 -NoWrite`，fetch-depth 0，退出码门禁）与 `-AutoScope`（从 git diff 推导范围）。

> 结论：本轮评审未推翻任何现有结构；"不做"清单（只读、单命令、L1 秒级、检查 ID 稳定、配置驱动不变量、§9 生命周期）继续保留。
