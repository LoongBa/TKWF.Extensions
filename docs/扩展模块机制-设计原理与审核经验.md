## 0. 一页速查（审核者先看这里）

| # | 事实 | 判据/证据 | 违反后果 |
|:-:|------|-----------|---------|
| 1 | 扩展 = 业务领域（唯一区别：不初始化自己的 DomainHost） | `_Framework/<Ext>/*ExtensionInitializer.cs` 继承 `ExtensionInitializer<TUserInfo>` | 出现"Store 伪 DataService 层"/裸 ORM 即为坏味道 |

| 3 | **发现 ≠ 白名单 ≠ 启用**（三层） | 见 §1.2–§1.4 | 只写 `[TKWFEnabledExtension]` 不写 `registry.Enable` → 三钩子**不执行**（实测） |
| 4 | 消费方必须**两处声明**：`[TKWFEnabledExtension(typeof(XxxInitializer<>))]` + `ConfigureExtensions` 里 `registry.Enable("Xxx")` | 框架 `TkExtensionDescriptor.IsEnabled` 默认 false；DMP-Lite `DmpDomainInitializer` 两处并存 | 端点 404 / 服务未注册 / 过滤器不生效 |

| 7 | DataService = SG1 生成基座 + 手写业务分部；**禁手写 CRUD Store** | `_Framework/*/DataServices/*.g.cs` + 同名 `.cs` | 手写 Store 绕过租户/软删/UoW，红线 |

| 12 | 测试宿主必须走**生产路径**（真实 DI + BindScope + `Use<T>()`），不得 StubDomainUser 掩盖守卫 | D26B 心得 #8/#9；`_Tests/Extension.Testing.Shared` | 测试绿、生产红 |

## 1. 机制全景

### 1.1 四个角色（ADR137）

| 角色 | 判据（唯一实现：`ProjectRoleResolver`） | 生成物归属 |
|------|--------------------------------------|-----------|
| **Domain（领域/宿主）** | 含 `DomainHostInitializerBase<T>` 派生类 | 权威注册（`GeneratedControllerRegistrations`）、页面权威注册 `public` |
| **Extension（扩展）** | 含非抽象 `ExtensionInitializer<T>` 派生类 | 能力清单（`GeneratedControllerCatalog`/`GeneratedPageCatalog`）`internal`（防跨扩展 CS0436） |
| **Consumer（消费方/普通项目）** | 其余 | 不产扩展注册；直接引用扩展 → `TKWF0030` Error |

> 设计含义：**角色不是配置项、不是可选参数**（ADR137 明确"禁止再以可选参数传递"）。判据来自代码结构，因此"扩展项目"与"领域项目"的边界是可编译验证的。

### 1.2 发现（编译期，零反射）

- SG1a（`EntityMetadataGenerator`）扫描**本编译单元 + 所有引用程序集**的 `[TKWFExtension]` 标注类型（`CollectInNamespace`）。
- 扩展侧声明的是**开放泛型** `XxxExtensionInitializer<TUserInfo>`；宿主编译时用宿主 `DomainHostInitializerBase<TUserInfo>` 的闭合 TUser 替换泛型参数，生成 `GeneratedExtensionInitializers.CreateInstances()`（编译期 `new XxxExtensionInitializer<HostUserInfo>()` 数组）。
- 因而：
  - 扩展**永远不知道**消费方用户类型（只约束 `IUserInfo`）；
  - 扩展包必须与消费方 SDK 同代重建（旧包只产生 `WARN007`/`EXTENDPOINT001`，无新能力）；
  - **运行时无 `Activator.CreateInstance`**（ADR48 D4）。

> ⚠️ **实测边界（2026-11-28 复核）**：发现发生在 `EntityMetadataGenerator` 的完整生成路径中；若宿主项目**自身没有任何领域类型**（无实体/服务/控制器），SG1a 走"空壳 ProjectMetaContext"早退路径，`ExtensionDescriptors`/`CreateEntityInstances` 均为空——此时 `registry.Enable("Xxx")` 会抛"扩展未在清单中"。纯扩展宿主（自身零实体）需先向框架组确认（已登记 §7 未闭环项）。领域项目正常有自身实体，不受影响。

### 1.3 白名单（编译期决策）

- `[TKWFEnabledExtension(typeof(XxxExtensionInitializer<>))]` 标注在**领域宿主初始化器类**上（`AllowMultiple`）。
- SG1b 从 `InitializerType.ContainingAssembly.Name` 推导扩展程序集名，生成 `EnabledExtensions`（pipe 分隔）：
  - 聚合白名单内扩展的**能力清单**进领域权威注册（控制器接口/页面清单）；
  - 白名单外但被引用 → `TKWF0021` Warning（传递引用）/ 直接引用 → `TKWF0032` Error；
  - 白名单外使用扩展实体 → `TKWF0034` Warning（可升 Error）。
- **白名单只解决"编译期聚合"，不解决"运行时执行"**（见 §1.4）。

### 1.4 启用（运行期）——最容易误解的一层

```csharp
// 领域宿主初始化器（消费方）
[TKWFEnabledExtension(typeof(PermissionsExtensionInitializer<>))]   // ① 编译期白名单（能力清单聚合）
public sealed class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo>
{
    protected override void ConfigureExtensions(ITkExtensionRegistry registry, IServiceCollection services)
    {
        registry.Enable("Permissions");                               // ② 运行期启用（IsEnabled=true）
    }
}
```

实现事实（源码取证）：
- `TkExtensionRegistry.FromProjectMetaContext()` 从 SG 生成描述符构建注册表；`TkExtensionDescriptor.IsEnabled` **默认 false**（`TkExtensionRegistry.cs:73`）。
- `DomainHostInitializerBase.ConfigureExtensionServices/ConfigureFilters/InitializeExtensionAsync` 均只遍历 `Extensions.Where(d => d.IsEnabled)`（`EnabledDescriptors()`）。
- **没有任何代码**把 `[TKWFEnabledExtension]` 白名单自动写入 `IsEnabled`——属性与运行时启停是两条独立通道。
- 因此正确写法是**两处都声明**；DMP-Lite 生产宿主即此形态（`DmpDomainInitializer.cs`：10 个 `[TKWFEnabledExtension]` + 10 个 `registry.Enable`）。

> **文档口径修正**：本仓旧文档"`[TKWFEnabledExtension]` 是唯一启用通道 / 声明后三钩子自动接线"为**过度简化**，自本文档起统一为"白名单（编译期）+ Enable（运行期）双声明"。
> 另注：`ExtensionInitializer<T>` 的 XML 注释与 `TKWFExtensionAttribute` 注释中"标注即产生运行时行为"同样不成立（IsEnabled 默认 false），已在 §7 登记为框架侧文档漂移。

### 1.5 Domain 三钩子 + 自举后钩子（时序与边界）

```
InitializeDiContainer
  ├─ OnPreInitialize
  ├─ RegisterInfrastructureServices        ← ProjectMetaContext.Instance 就绪
  ├─ 构建 TkExtensionRegistry + SG 实例预填充
  ├─ ConfigureExtensions(registry, services)   ← 启停裁定（必须在服务注册前）
  ├─ RegisterOptionsBindings（扩展 [Options] 段）
  ├─ ConfigureExtensionServices(services)      ← 扩展 ConfigureServices
  └─ OnRegisterDomainServices
...
ConfigGlobalFilters  → ConfigureExtensionFilters(builder)
...
OnEnsureSystemReadyAsync 之后 → InitializeExtensionAsync(sp)
自举完成后（IsBootstrapCompleted=true）→ InitializeAfterBootstrapAsync(sp)   // v4.10.126
```

| 钩子 | 何时用 | 禁止 |
|------|--------|------|
| `ConfigureServices` | 注册门面（`AddConstructibleService`）、接线型服务（`TryAddScoped`）、Options | 注册 DataService（SG 自动）；注册 IDomainUser |
| `ConfigureFilters` | `FilterBuilder.Add<T>(FilterTier)` 按 S→F→O | 依赖请求期上下文 |
| `InitializeAsync(sp)` | 种子/预热（必须 `BeginSystemScopeAsync()` **不传参**） | 裸 `sp.GetService<门面>()`（帧外守卫必抛） |
| `InitializeAfterBootstrapAsync(sp)` | 需要接口服务（AOP）的种子/预热 | 吞异常（抛出即启动失败） |

### 1.6 Web 装配面（与 Domain 正交）

- 形态：`UseWebExtensions(e => e.Add<XxxWebExtension>(o => ...))`；实例由 `Activator.CreateInstance` 创建（**必须有 public 无参构造**）。
- 三阶段：`ConfigureServices`（立即，仅宿主面）→ `MiddlewareAnchor`（BeforeAuthentication/AfterRouting 分桶）→ `DeclareEndpoints` + `DeclareProtocolEndpoints`（AfterRouting 排空时执行）。
- 端点通道（F13/ADR112）：
  - `MapGenerated<TFacade>()`——生成化 REST（门面方法需 `[ApiExpose(...)]`）；
  - `MapInfrastructure(EndpointKind)`——闭枚举（HealthCheck / PageCatalog）；
  - `MapHub<THub>(path, requireAuthorization)`——SignalR；
  - `DeclareProtocolEndpoints(IProtocolEndpointBuilder)`——raw body/XML/302/同路径多方法等厚协议。
- 前缀：`[assembly: ExtensionModule("Key","default-prefix")]` + 配置覆盖 `TKWF:Api:Modules:{Key}:Prefix`；组路径 = `TKWF:Api:RestBasePath`（默认 `/api`）+ 模块前缀。
- 安全：端点级 `AllowAnonymous` 声明（`IAllowAnonymous` 元数据）是唯一免认证通道；**不要**在 Web 层给生成端点重复加 `.AllowAnonymous()`（双源）。

### 1.7 页面装配面（ADR106）

- 契约：`IPageContributor.GetPages()` 返回 `PageDescriptor`（Id/Route/Scenario/Title/Icon/Group/PageType/RequiredPermissions/ResourceDependencies）——**纯元数据**，不做授权判定、不加载数据。
- 归属：数据形状 `PageDescriptor` 在 `TKWF.CodeGeneration.Abstractions`；接口 `IPageContributor` 在扩展仓 `TKWF.Ext.UI.Abstractions`；权威注册由领域项目 `GeneratedPageRegistrations` 聚合（白名单机制复用）。
- 门控：`PAGE002`（贡献者必须 public + 无参构造）仍生效；`PAGE001` 已退役（v4.10.111，判据与收集语义矛盾）；`PAGE003/004`（路由/资源键冲突）当前无发射者（页面数据提取阶段未实现，D18A 已登记）。
- 中间件：`PageReachabilityMiddleware` 当前为 **MVP 透传**（页面可见性判定在装配点 `PageAssemblyService.LoadAsync`），文档不得宣称"中间件已做逐请求授权"。

## 2. 设计原理（12 条）

> 每条给"命题 → 推论（怎么做）→ 违反后果 → 证据锚点"。审核时以"违反后果"作判定。

### P1 编译期确定优先（零运行时反射）
- 命题：能在编译期确定的，绝不留到运行期。
- 推论：扩展发现/实例化/能力清单/端点表/页面注册全部 SG 生成；贡献者实例编译期 `new`。
- 违反后果：AOT 失效、启动期不确定性、诊断滞后。
- 证据：ADR37 决策 4；ADR48 D4；`GeneratedExtensionInitializers.CreateInstances()`。

### P2 单一权威事实源
- 命题：同一事实只能有一处声明，其余是投影。
- 推论：能力 ID 取 `[TKWFExtension(Name)]`；路由前缀取 `[assembly: ExtensionModule]`；权限键取 `[RequirePermission]`/定义贡献者；页面 Id 取 `PageDescriptor.Id`；菜单引用 PageName 不重声明路由。
- 违反后果：双源漂移（典型：表现层重复 `AllowAnonymous`、文档/代码各说各话）。
- 证据：ADR106 决策 1；ADR108；`TKWFExtensionCapabilityAttribute` 注释"CapabilityId 单一事实源"。

### P3 显式决策优于自动行为（发现 ≠ 启用）
- 命题：可被发现，但不可自动生效。
- 推论：白名单 + `registry.Enable` 双声明；`IsEnabled` 默认 false；扩展不因"被引用"而运行。
- 违反后果：死引用静默启用、权限面意外打开。
- 证据：ADR47 原则 1；`TkExtensionDescriptor.IsEnabled`；§1.4。

### P4 领域自治（IDomainUser 中心，禁构造注入）
- 命题：领域服务只能经 `User.Use<T>()` 在域作用域内构造，IDomainUser 永不注册 DI。
- 推论：门面继承 `DomainServiceBase` + `AddConstructibleService`；服务间组合用懒加载属性 `_x ??= User.Use<T>()`；接线型（实现主框架/他扩展契约、非 IDomainService）用 `ctor(IServiceProvider)` + 帧内解析。
- 违反后果：普通 DI 注入 IDomainUser → 生产解析失败（AuthController 锁定检查静默失效先例）；构造注入域服务 → `DI004` 编译阻断。
- 证据：`DomainServiceCollectionExtensions`（throw-factory + 守卫工厂）；D26B #8/#16。

### P5 依赖倒置（扩展间只走 Abstractions）
- 命题：扩展间耦合必须经公共契约程序集。
- 推论：`TKWF.Ext.X.Abstractions`；`[TKWFExtensionCapability(DependsOn=...)]` + `[TKWFExtensionDependency(DependencyType, MinVersion)]` 声明版本线。
- 违反后果：`TKWF0022` Error；版本偏移导致契约缺失。
- 证据：ADR48 D7；`DEP001/002/003`。

### P6 正交分层（Domain / Web / Page；表现层不承载领域决策）
- 命题：领域行为与暴露面分离。
- 推论：领域开关（`EnabledAuthTypes` fail-closed 等）在 Domain Options；Web Options 只承载路由/端点开关；页面 `PageDescriptor` 纯元数据。
- 违反后果：`WEBEXT_001`；"Web 层关掉频控/口令校验"类绕过。
- 证据：AGENTS §8 配置分层；ADR87；ADR106。

### P7 fail-closed + 不静默（P7 显式诊断）
- 命题：不能确定的，宁可硬失败并给出可操作诊断，不静默降级。
- 推论：非法 SemVer → `DEP001`；版本不足 → `DEP002`；旧扩展包 → `WARN007`/`EXTENDPOINT001`；端点无模块前缀 → `EXTMODULE001`（Warning 起步，迁移后 Error）。
- 违反后果：端点全 404 但编译无提示（历史 T22）；密钥解析错 key。
- 证据：D18A 诊断码总表；ADR112 决策 5。

### P8 归属原则（生成物可见性随角色）
- 命题：生成物的可见性是角色语义的一部分。
- 推论：扩展项目生成物 `internal`（防扩展间 CS0436）；宿主/领域 `public`；扩展不写全局 `ProjectMetaContextBase.Instance`。
- 违反后果：跨扩展类型冲突；消费者误用扩展内部注册。
- 证据：`BuildExtensionInitializersSource(..., isExtension)`；ADR137。

### P9 类型系统门禁（窄接口，无逃生口）
- 命题：用类型系统封死"任意路径/任意形态"的逃生口。
- 推论：`IExtensionEndpointRegistry` 无 builder 参数；`EndpointKind` 闭枚举；`IProtocolEndpointBuilder` 只暴露受控原语。
- 违反后果：前缀漂移（Federation 旧裸 `/feberation` 实证）、双挂载。
- 证据：ADR112 决策 2/4；`IExtensionEndpointRegistry` 源码。

### P10 启用双通道（白名单 + Enable）与"不迁就"
- 命题：编译期决策与运行期执行各司其职，缺一不可。
- 推论：见 §1.4；框架不为存量错误引用让步（`TKWF0032` Error）。
- 违反后果：扩展"已引用、已白名单"但三钩子不跑。
- 证据：§1.4；ADR47"框架不迁就现有代码"。

### P11 断代升级优于兼容包袱（可选原则）
- 命题：机制级破坏性变更不留 Obsolete 双通道。
- 推论：`ConfigureEndpoints` 直接删除（F13）；`[TKWFExtension]` 精简为单参数；`InitializeAsync(sp)` 带参断代。
- 违反后果：双通道分叉、文档教旧法。
- 证据：ADR112；ADR78；ADR48。

### P12 测试走生产路径（不得用桩掩盖守卫）
- 命题：测试宿主必须复现生产装配与守卫语义。
- 推论：真实 DI + FreeSql + `BindScope` + `user.Use<T>()`；分层单测可用可配置 stub 直构门面（经基类 `User`），但**不得**注册 `IDomainUser` 到 DI。
- 违反后果：StubDomainUser 掩盖 ctor 注入 IDomainUser 缺陷（D26B #8 实证）。
- 证据：D26B #8/#9；`_Tests/Extension.Testing.Shared/TestHostBase.cs`。

## 3. 标准形态（扩展骨架）

### 3.1 项目结构与 csproj

```
_Framework/{Ext}/
├── TKWF.Ext.{Ext}.csproj          # 实体型：SG1 分析器 + CodeGeneration.Abstractions（PackageReference）
├── Properties/AssemblyInfo.cs     # [assembly: ExtensionModule("{Ext}","{prefix}")]（有 [GenerateController] 时必须）
├── {Ext}ExtensionInitializer.cs   # [TKWFExtension] + [TKWFExtensionCapability]（可选）
├── Entities/                      # [DomainGenerateCode] 实体（xCodeGen 生成物入库）
├── DataServices/                  # .g.cs 基座 + 手写业务分部
├── {Ext}Options.cs                # [Options("TKWF:{Ext}")]
└── ...门面/服务
_Framework/{Ext}.Abstractions/     # 契约型扩展必需；自包含型可无
_Tests/Extension.{Ext}.Tests/      # ConsumerHostInitializer + TestHostBase
```

### 3.2 初始化器标准写法

```csharp
[TKWFExtension("{Ext}")]
[TKWFExtensionCapability(ServiceType = typeof(I{Ext}Service))]
public sealed class {Ext}ExtensionInitializer<TUserInfo> : ExtensionInitializer<TUserInfo>
    where TUserInfo : class, IUserInfo, new()
{
    public override void ConfigureServices(IServiceCollection services)
    {
        services.AddOptions<{Ext}Options>();
        services.AddConstructibleService<I{Ext}Service, {Ext}Service>();   // 门面：守卫工厂
        services.TryAddScoped<I{Ext}Port, {Ext}Adapter>();               // 接线型：普通 DI（帧内解析）
    }
    public override void ConfigureFilters(FilterBuilder<TUserInfo> builder)
        => builder.Add<{Ext}FilterAttribute>(FilterTier.F);
    public override async Task InitializeAsync(IServiceProvider sp)
    {
        var host = sp.GetRequiredService<DomainHost<TUserInfo>>();
        await using var sys = await host.BeginSystemScopeAsync();   // 不传参
        await sys.System.Use<I{Ext}Seeder>().SeedAsync();
    }
}
```

### 3.3 门面（Service）标准形态
- 继承 `DomainServiceBase`；接口标 `IDomainService`；**ctor 只允非域基础设施**（`IDomainUser` 由基类/AOP 工厂注入，业务依赖懒加载）。
- 数据访问：`User.Use<XxxEntityDataService>()`（具体类，NoAop 直建）；**不注入 `IEntityDAC<T>`/`IFreeSql`**。
- 多实现集合：`TryAddEnumerableConstructible<I契约, TImpl>()`；消费方在门面方法内 `Use<I契约>()` 枚举，控制器不得 `[FromServices] IEnumerable<T>`。

        => services.Configure<{Ext}WebOptions>(_ => { });        // 仅宿主面

        => registry.MapGenerated<I{Ext}Facade>();                 // 门面方法 [ApiExpose]
    public void DeclareProtocolEndpoints(IProtocolEndpointBuilder builder) { /* 厚协议 */ }
}

## 4. 审核清单（逐条取证）

> 用法：新扩展/迭代收尾时逐项勾选；每项都必须给出"证据位置"（文件:行 / 命令输出 / 构建日志），不允许"看起来没问题"。

### A. 身份与装配
- [ ] A1 初始化器继承 `ExtensionInitializer<TUserInfo>`，`[TKWFExtension("Name")]` 存在，类为 `public` 或 `sealed`（与既有风格一致）。
- [ ] A2 初始化器**不**是闭合泛型（必须是 `<TUserInfo>` 开放泛型）。
- [ ] A3 有 `[GenerateController]` 的程序集声明了 `[assembly: ExtensionModule(Key, Prefix)]`（否则 `EXTMODULE001`）。
- [ ] A4 扩展项目未引用其他扩展实现（`TKWF0022`）；跨扩展契约只在 `.Abstractions`。
- [ ] A5 扩展项目无 `DomainHostInitializerBase<T>`（扩展宿主门控 Gate004）。
- [ ] A6 `*.Abstractions` 存在性与分发形态匹配（契约型成对 / 自包含型单包），README 首屏声明。

### B. DI 与领域自治
- [ ] B1 门面接口继承 `IDomainService`；实现继承 `DomainServiceBase`；注册用 `AddConstructibleService`。
- [ ] B2 **零** `IDomainUser` 构造注入于普通 DI 服务；门面 ctor 的 `IDomainUser` 仅作为基类参数。
- [ ] B3 无构造注入域服务（`DI004` 零豁免）；服务间用 `_x ??= User.Use<T>()`。
- [ ] B4 多实现集合用 `TryAddEnumerableConstructible`（非 `TryAddEnumerable`）。
- [ ] B5 接线型服务（实现主框架/他扩展契约）用 `ctor(IServiceProvider)` 且解析点在 AOP 帧内。

### C. 数据访问
- [ ] C1 无手写 Store CRUD 包装（`I{X}Store` 只允许是**业务语义契约**，且实现继承 `DomainServiceBase`）。

- [ ] C4 实体变更后 `.g.cs` 已重生成并提交（`pwsh .xCodeGen/run-xcodegen.ps1 -Ext {Ext}`）。
- [ ] C5 跨表多对一用 VEntity；一对多聚合不用 VEntity（缓存/两步查询）。

### D. 端点与页面
- [ ] D1 Web 钩子无 `ConfigureEndpoints`（已删除）；用 `DeclareEndpoints`/`DeclareProtocolEndpoints`。
- [ ] D2 `[ApiExpose]` 全量标注：非端点方法 `ExposeRest=false`；匿名端点 `AllowAnonymous=true` 在契约上声明。
- [ ] D3 Web `ConfigureServices` 无领域业务类型注册（`WEBEXT_001`）。
- [ ] D4 页面贡献者 `public` + `public` 无参构造（`PAGE002`）；`PageDescriptor.Route` 全局唯一。
- [ ] D5 页面纯元数据（无授权判定/数据加载）；权限键与 `[RequirePermission]`/定义贡献者一致。

### E. 测试

- [ ] E2 集成测试走生产路径（真实 DI + `BindScope` + `Use<T>()`），无 `StubDomainUser` 掩盖。

### 6.1 文档漂移高频模式（2026-11-28 全仓文档核对实证）

> 这些不是代码缺陷，而是**文档把已删除/已变更的机制继续当现行教**——最危险，因为消费方照抄即写出运行期失败代码。复核时按此表逐项 grep。

| 漂移模式 | 典型症状 | 根因 | 复核 grep |
|---------|---------|------|----------|
| **已删 Store 仍被文档教学** | `IBlobRecordStore`/`IEmailRecordStore`/`IDictionaryStore`/`IAccountLockoutStore`/`IFeatureValueStore` 等（A5 Store-debt cleanup 已删） | 文档未随 ADR90 整改同步 | 上述类型名；命中处若未标"已删除"即缺陷 |
| **门面被教成构造注入** | `public class X(IJobResultRecorder r)` / `LoginService(ITokenService t)` | AddConstructibleService 守卫工厂 + DI004；文档停留整改前 | `AddConstructibleService` 对应接口名 + `I` 接口的 ctor 注入写法 |
| **`ConfigureEndpoints` 残留** | 端点/中间件仍描述"由 ConfigureEndpoints 完成" | F13（ADR112）删除，改 `DeclareEndpoints`/`DeclareProtocolEndpoints` | `ConfigureEndpoints` |
| **`TryAdd*` 语义错标** | 称门面"TryAdd 可覆盖"，实为 AddConstructibleService 不可普通覆盖 | 整改前后混写 | `TryAddScoped` + 域服务接口名 |
| **路由带 `/api` 硬编码** | `GET /api/identity/user-roles` | 组前缀由 `TKWF:Api:RestBasePath` + 模块前缀在消费方决定 | `"/api/` |
| **版本头滞后** | 指南头部版本 ≠ `versions.json`/tag | 发版未回写指南 | 每篇指南 `版本` 行 vs `docs/versions.json` |
| **文档领先代码（属性未实现）** | `DirectDistributionUserThreshold` 等 Options 键在代码不存在 | 方案物化时删字段未回写 | 文档 `TKWF:` 配置键 vs Options 类 |
| **旧包名/旧机制术语** | `TKWF.Ext.Authentication`、`Authentication`、`Navigation 当前在主框架内` | 归层/迁出未回写 | 旧名 grep |

> 判定口径：**文档承诺必须可在代码中定位**（类型/方法/配置键/路由/注册形态）；定位不到即缺陷，除非显式标注"已删除/历史/规划"。

## 7. 已知边界与未闭环项（复核时不要误判为违规）

1. **纯扩展宿主（自身零领域类型）**：SG1a 空壳早退 → `ExtensionDescriptors` 为空 → `registry.Enable` 抛错。**已登记**，待框架组确认是否补生成。
2. **白名单不自动置 `IsEnabled`**：`[TKWFEnabledExtension]` 只做编译期聚合；`ExtensionInitializer`/`TKWFExtensionAttribute` 的 XML 注释"标注即产生运行时行为"与实现不符（框架侧文档漂移）。本仓文档已按实现修正口径。
3. **`PAGE003/004` 无发射者**：页面数据提取阶段未实现，路由/资源键冲突暂无编译期校验（人工审 D4）。
4. **`PageReachabilityMiddleware` 为 MVP 透传**：逐请求页面可见性判定未接线。
5. **`TKWF0020`/`CTRB001`/`PAGE001` 已退役**：出现旧文档引用即为过时；不得作为判定依据。
6. **测试宿主 `TestMetaContext` 空桩**：本仓 `_Tests/Extension.Testing.Shared` 的空桩仅适用于**无业务元数据**的扩展测试宿主；依赖生成 DTO 写入的测试必须安装扩展生成的 `ProjectMetaContext`（§4 E3）。
7. **扩展项目 `internal` 生成物**：跨程序集读取扩展 Catalog 是 SG 行为，不是"缺 public"，不要误判。
8. **两条实现事实已转达框架组**（`_TKWF/docs/03_扩展模块/转达/转达-扩展启用语义与零领域类型宿主发现缺口-请框架组复核.md`）：启用双声明（T2）、零领域类型宿主发现为空（T2）、PAGE003/004 无发射者 + 页面中间件 MVP（T3 登记）。框架组回执后按结论回写本文档。

## 8. 复核路线（10 步）

1. 读扩展 README + 使用指南：确认分发形态（契约型/自包含）、初始化器名、配置节。
2. 打开 `XxxExtensionInitializer`：核对 `[TKWFExtension]`、泛型、`ConfigureServices` 注册形态（B1-B6）。
3. 抽查 2-3 个门面：`DomainServiceBase`、`IDomainService`、懒加载组合、无 ctor 域服务。
4. 抽查 DataServices：`.g.cs` + 手写分部；无 Store CRUD；无 IFreeSql。
5. 查 `[assembly: ExtensionModule]` 与 `[ApiExpose]`/`DeclareEndpoints`：端点所有权与匿名声明。
6. 查页面贡献者（如有）：`PageDescriptor` 纯元数据、权限键一致、路由唯一。
7. 查测试宿主：生产路径、白名单、`ProjectMetaContext` 安装。
8. 跑 `dotnet build TKWF.Extensions.slnx`（L0）+ 该扩展测试（L1）。
9. 扫文档：类名/方法/配置节/过时机制（F1/F2）。
10. 输出"证据表"（文件:行 + 命令输出），不含无证据结论；P0/P1 进整改清单。
