# 扩展模块表前缀迁移——消费方通知（ADR100 / c0319c4）

> 日期：2026-11-23｜状态：**待随 schema 批 tag 发布**｜影响：所有持有扩展存量库的消费方（DMP-Lite / EduPlatform 等）

## 一、为什么需要迁移

2026-10-07（`c0319c4`，ADR100）将扩展实体表统一加 `TKWF_` 前缀、VEntity 视图改 `TKWFV_`、索引改 `TKWFIX_`，解决与业务表的命名冲突。当时这批改动**晚于多数模块已发布的 tag**，因此线上 NuGet 包与仓库 HEAD 的库表结构长期不一致：

- 实测：`Approval/v0.4.0` 发布包视图名 `vw_ApprovalTaskView`，HEAD 为 `TKWFV_ApprovalTaskView`。
- 消费方升级到本批新 tag 后，代码将查询 `TKWF_*` 表；若库里仍是旧表名 → 运行期 "relation does not exist"（Pg）/ "Invalid object name"（SQL Server）。

## 二、关键纪律：`UseAutoSyncStructure` 不搬数据

框架 `UseAutoSyncStructure` 只建新表/新列，**不会 ALTER 已有表改名，也不会搬数据**。因此升级后若只同步结构，旧表数据会静默搁浅（新表为空）。消费方必须按下列映射显式执行 DDL 改名。

## 六、执行示例

PostgreSQL:

```sql
ALTER TABLE "AccountLockout" RENAME TO "TKWF_AccountLockout";
ALTER INDEX "IX_ApprovalFlow_Code" RENAME TO "TKWFIX_ApprovalFlow_Code";
-- 视图须 DROP + CREATE（ViewSql 见各扩展指南，基表名同步改为 TKWF_*）
```

SQL Server:

```sql
EXEC sp_rename 'dbo.AccountLockout', 'TKWF_AccountLockout';
EXEC sp_rename 'dbo.PermissionGrant.UK_PermissionGrant_Provider', 'TKWFIX_PermissionGrant_Provider', 'INDEX';
```

## 七、升级顺序

1. **先迁移库**（执行上述 DDL）→ 2. 部署新 DLL → 3. 回归查询/写入路径。
2. 迁移前备份；`ALTER TABLE RENAME` 在与应用停机窗口内执行。
3. 回滚：先回滚 DLL，再按映射反向 RENAME。
