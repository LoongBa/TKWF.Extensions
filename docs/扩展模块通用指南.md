# TKWF 扩展模块通用指南

> 本指南回答**消费方视角**的公共问题：如何引用、启用、接线任意 `TKWF.Ext.*` 扩展。
> 这是 28 份扩展使用指南中「启用/接线」公共内容的**单一事实源**——各扩展指南只保留特有内容，公共部分引用本文档。
> 扩展开发者视角（怎么写一个扩展）见主框架私有 `D17-TKWF扩展机制与业务模块全景-设计方案.md` §4.4；本文档不含扩展开发指引。
>
> 适用：所有启用了 TKWF 扩展的消费方领域项目（Domain 侧）+ Web 项目（装配侧）。

---

## 一、核心概念

| 概念 | 说明 |
|------|------|
| **扩展** | `TKWF.Ext.*` 独立包（权限/身份/通知/MFA 等 33+ 包），独立版本（MinVer），与主框架版本无关 |
| **发现 ≠ 启用**（V4.9.85/ADR47） | 扩展 DLL 被引用后，SG1 编译期**发现**其 `[TKWFExtension]` 初始化器（生成能力清单）；但**发现不自动启用**——须消费方白名单声明才执行三钩子 |
| **三钩子**（Domain 侧） | `ConfigureServices`（DI 注册）/ `ConfigureFilters`（AOP 过滤器）/ `InitializeAsync`（异步种子），由 DomainHost 启动流程自动调用 |
| **Web 装配钩子**（v4.10.45/ADR87） | Web 类扩展（认证/限流/健康检查/SignalR）装配宿主面（中间件/端点）走独立 `IWebExtension` 机制，与 Domain 三钩子**正交** |
| **依赖倒置**（ADR48 D7） | 扩展间依赖走 `.Abstractions` 契约包，不引用实现项目（L2 门控 `TKWF0022` Error） |

## 二、接入流程（消费方三步）

### 第 1 步：引用扩展包

**NuGet 包模式**（生产消费方推荐）：

```xml
<PackageReference Include="TKWF.Ext.Identity" Version="0.4.0" />
<!-- 扩展经 PackageReference 传递引用主框架包（TKWF.Domain 等，CPM 集中版本）；
     依赖扩展（如 Identity → Permissions.Abstractions）自动解析 -->
```

**源码模式**（扩展仓库内联调/开发）：

```xml
<ProjectReference Include="..\_TKWF.Extensions\_Framework\Identity\TKWF.Ext.Identity.csproj" />
```

### 第 2 步：白名单声明（启用）

扩展不"发现即启用"——消费方须在领域初始化器上显式声明白名单：

```csharp
using TKWF.Ext.Identity;   // 引入扩展命名空间（含初始化器类型）

[TKWFEnabledExtension(typeof(IdentityExtensionInitializer<>))]
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

- `[TKWFEnabledExtension]` 支持 `AllowMultiple`——多个扩展同一初始化器上并列声明。
- 声明后扩展三钩子自动接线（DI 注册 / 过滤器 / 种子数据初始化）。
- **未声明**：扩展被发现但**不启用**——DI 注册缺失、Filters 不生效（表现为运行时 `XxxService 未注册`，详见 §五）。

### 第 3 步：Web 装配（仅 Web 类扩展，v4.10.45+）

Web 类扩展（如 Authentication/RateLimiting/HealthCheck/Notifications.SignalR）的中间件/端点装配走 `IWebExtension`——在 WebHost 装配链上一次性声明：

```csharp
builder.ConfigWebAppDomain<MyUserInfo, MyDomainInitializer, DomainWebOptions>(...)
    .UseWebSession()                                // 会话恢复（主框架，按需）
    .UseWebExtensions(e => e.Add<HealthCheckWebExtension>(x =>
    {
        x.AddDatabaseHealthCheck<MyDbHealthCheck>("db");   // 扩展特有配置
    }))
    .BeforeRouting(...)
    .AfterRouting(...)
    .Build(...);
```

- **Domain 与 Web 正交**：业务服务 DI 由 Domain 钩子（`XxxExtensionInitializer`）注册；宿主面（中间件/端点映射）由 Web 钩子（`XxxWebExtension`）承担。二者独立声明、独立生效（`TKWF_SG1b_WEBEXT_001` 编译期门控守护边界）。
- 各扩展的 Web 钩子类型与锚点（BeforeAuthentication/BeforeRouting 等）不同——**查对应扩展指南**。

## 三、启动时序（三钩子何时执行）

```
OnServiceProviderBuilt
  ↓
OnValidateRuntimeGatesAsync     ← ADR35 统一门控验证（含扩展 SG1 生成的 GateRules）
  ↓
SyncTables / SyncViewsAsync     ← 扩展实体建表/视图
  ↓
ExtensionInitializer.InitializeAsync()   ← 种子数据 + 启动期预检（fail-fast）
```

| 钩子 | 执行时机 | 用途 |
|------|---------|------|
| `ConfigureServices` | `InitializeDiContainer`（DI 构建前） | TryAddScoped 注册业务服务 |
| `ConfigureFilters` | `ConfigGlobalFilters`（FilterBuilder 构建） | 注册 AOP 过滤器（权限/安全日志等） |
| `InitializeAsync` | `OnEnsureSystemReadyAsync` 之后 | 种子数据、密钥预检（fail-fast） |

> 三钩子锚定 **DomainHost** 且零 ASP.NET Core 依赖——Web 装配（宿主注册/中间件/端点）由 `IWebExtension` 独立承载，**不进三钩子**（v4.10.45 正交注记，ADR87）。

## 四、扩展初始化器内安全解析模式（启动期 DI 铁律）

> 背景：Authentication v0.3.1（2026-10-02）修复启动期 `Unable to resolve service`——`InitializeAsync` 中裸 `sp.GetService<ITokenService>()` 解析构造注入 DataService 的服务，在启动期无域作用域会撞守卫（数据访问红线 + 域作用域语义）。

**错误模式**（启动期裸解析）：

```csharp
// ❌ InitializeAsync / ConfigureServices 里裸 GetService 解析含 DataService 依赖的服务
var tokenService = sp.GetService<ITokenService>();   // 解析需 CurrentAopUser 域作用域 → 抛守卫异常
```

**正确模式**（系统作用域 + Use<T>）：

```csharp
public override async Task InitializeAsync(IServiceProvider sp)
{
    var host = sp.GetRequiredService<DomainHost<TUserInfo>>();
    await using var sysScope = await host.BeginSystemScopeAsync(sp);   // 进入系统作用域
    var tokenService = sysScope.System.Use<ITokenService>();           // Use<T> 内设 SystemUser 域上下文
    if (tokenService is TokenService concrete)
        concrete.EnsureKeysLoaded();                                   // fail-fast 预检
}
```

要点：
- `BeginSystemScopeAsync(sp)` 建立系统作用域（`StandaloneDomainUserAccessor` 通道）。
- `scope.System.Use<T>()` 要求 `T : IDomainService`（空标记接口准入）——`Use<T>` 内设 `CurrentAopUser=SystemUser`，DataService 在合法域作用域下构造（**自治铁律零妥协**）。
- 预检逻辑抽静态单一真相源（如 `TokenService.LoadKeysCore`），运行期 Lazy 与启动预检共用，避免双实现漂移。
- **消费方零感知**：该改动属扩展内部；消费方只需白名单声明（第二步）。

## 五、常见接线错误速查

| 症状 | 原因 | 处置 |
|------|------|------|
| `XxxService 未注册——…路径跳过` | 扩展白名单未声明（发现≠启用，DI 注册缺失） | `[TKWFEnabledExtension(typeof(XxxExtensionInitializer<>))]` 声明 |
| 启动抛 `解析需处于域作用域` 守卫 | 扩展/消费方在启动期裸 `GetService` 解析 DataService 依赖 | 见 §四 系统作用域模式 |
| 启动抛 `Issuer 未配置` / `SigningKeyPath 未配置` | 生产 fail-fast 门（缺配置） | 配置 `TKWF:{扩展名}` 对应节 |
| 旧静态方法不存在（`AddXxx`/`MapTkfwXxx` 编译失败） | v4.10.45 Web 钩子收敛——静态方法破坏性删除 | 改 `UseWebExtensions(e => e.Add<XxxWebExtension>(...))` |
| Web 中间件不生效（但 DI 注册正常） | 只声明了 Domain 白名单，未装配 Web 钩子 | WebHost 链 `UseWebExtensions` 补声明 |
| `TKWF0022` Error（L2 门控） | 扩展引用了其他扩展的实现项目而非 Abstractions | 改引 `.Abstractions` 契约包 |
