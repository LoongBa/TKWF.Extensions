# v0.1.0 — AuthSurface 授权面 开发方案

> **扩展**: `TKWF.Ext.AuthSurface`（授权面——口令兑换体系 + 我的应用聚合）｜**版本**: v0.1.0（独立起点）｜**日期**: 2026-10-07
> **状态**: 📋 已评审（**Oracle4 PASS WITH CONDITIONS**——无 P0；3 项 P1 修订闭环 + 8 项 P2 采纳，2026-10-07）
> **定位**: 横在"认证中心 vs 用户中心"之间的**第三个领域**（前置裁定 §一）——口令兑换体系（code/redemption/grant/batch + 管理端）+ 我的应用聚合 + 授权快照候选。数据属主 = 兑换/授权记录（非账号），行级身份引用一律 `AuthAccount.UId`（P4 白名单）。
> **机制核心**: 承接 UserCenter 预留 `IRedemptionHistorySource`/`IUserAppsSource` 两契约的**数据属主**，但按 P2 FREEZE **不实现**该两契约——自建 `TKWFV_UserRedemptionHistory`/`TKWFV_UserApps` 跨扩展 VEntity + 授权面自有查询门面，消费方兑换/应用查询**不经 UserCenter 门面**。
> **关联**: 前置裁定 `docs/授权面/授权面立项前置裁定.md`（P1/P2/P4 已落档、P3 非阻塞）；`ADR-AuthCenter-身份域数据模型与密码能力边界.md`（A.1/A.2 白名单、A.8 联邦归一、C.14 UserCenter 处置、C.16 前缀）；`N2-联盟锚点映射策略-开发方案.md`；UserCenter v0.1.0 开发方案 + README §七（范围来源）；AuthCenter V0.8.0（AuthGrantEntity 底座 + `AuthGrantSources.Redeem` 预留）；AGENTS §8 VEntity 先例（Identity/Notifications/DataDictionary/OrganizationUnit）。

## 一、本版目标

- **核心交付**：`TKWF.Ext.AuthSurface` v0.1.0——授权面内核（**兑换核心 + 两 VEntity**，用户裁定 2026-10-07；批次管理端留 v0.2.0）：

  1. **兑换码体系**：`RedemptionCodeEntity`（SG1 + xCodeGen——code 存 **SHA256 哈希**（`CodeHash` 唯一，对齐 SmsRecord.CodeHash 先例）+ `CodeMasked` 展示脱敏 + 状态机 Available/Redeemed/Expired + `RedeemedByUId` 行级 FK=`AuthAccount.UId`）+ **兑换写入链路**（校验 → CAS 原子兑换 → 历史可见）
  2. **我的应用聚合**：`AuthAppEntity`（应用目录——vm_UserApps 的 `AppName` 来源，**AuthGrant 底座缺应用元数据的必要支撑**，explore 实证）+ `TKWFV_UserApps` VEntity（JOIN `AuthGrant` + `AuthAccount` + `AuthApp`——跨扩展视图，P3 归授权面）
  3. **兑换历史读模型**：`TKWFV_UserRedemptionHistory` VEntity（JOIN `RedemptionCode` + `AuthAccount`）
  4. **门面**：`IRedemptionCommandService`（`CreateCodeAsync` 单码创建 / `RedeemAsync` 兑换）/ `IRedemptionQueryService`（`GetRedemptionsAsync`）/ `IUserAppsQueryService`（`GetAppsAsync`）/ `IAuthAppService`（目录管理）——`AddConstructibleService` + `DomainServiceBase` + **仅本人**（门面显式 `userId`）
  5. **兑换尝试频控**（v4.10.67 适配——框架 `IRateLimitCheck` 点检查原语，`MemoryRateLimitCheck` fallback——防无效码爆破）
  6. **P2 FREEZE 合规**：不实现 `IRedemptionHistorySource`/`IUserAppsSource`；消费方兑换/应用查询经**授权面自有门面**（DTO 复用 UserCenter.Abstractions——页面零适配）

- **完成定义（DoD）**：全部组件落地 + 兑换链路端到端（生成→兑换→历史）+ 两 VEntity **Tier 1.5 SQLite 真实视图**验证 + L2 门控零 TKWF0022 + 数据访问红线合规（零 IFreeSql/IEntityDAC 直注入）+ 仅本人防护 + 频控 + 并发双兑 CAS 单胜 + xCodeGen 配置 + `.g.cs` 入库 + README + 使用指南 + slnx 接线 + 全量回归不破坏。

## 四、命名与边界裁定

| # | 决策点 | 裁定 | 理由 |
|---|--------|------|------|
| 1 | **扩展命名** | `TKWF.Ext.AuthSurface`（主包），命名空间 `TKWF.Ext.AuthSurface`，MinVerTagPrefix `AuthSurface/v`，中文名**授权面** | 用户裁定 2026-10-07（直译全覆盖——兑换 + 我的应用 + 授权快照）；UserCenter 方案 §5.9 装配图占位 `RedemptionExtensionInitializer` **废弃**（需同步改） |
| 2 | **契约包** | v0.1.0 **不建** `AuthSurface.Abstractions`——门面契约在主包 | 零扩展间依赖（唯依赖为 UserCenter.Abstractions DTO 复用，纯 BCL）；未来其他扩展消费授权面门面时再拆（对齐 UserCenter 先例的拆包时机判断） |
| 3 | **与 UserCenter 划界** | 档案面归 UserCenter（Profile 已由认证中心 V0.2.0 承接）；**兑换/应用读取经授权面自有门面**（P2 FREEZE——不经 UserCenter 门面）；UserCenter `GetRedemptionsAsync`/`GetAppsAsync` **保持缺省降级（空列表）**；DTO 复用 `RedemptionRecordDto`/`UserAppDto`（授权面引 **UserCenter.Abstractions**——纯契约包，L2 合规） | P2 FREEZE 语义（前置裁定 §三）；DTO 复用 = 消费方页面零适配（"碰巧兼容只需记录"，AGENTS §1） |
| 4 | **与 AuthCenter 划界** | 身份锚 `AuthAccount.UId` = **行级 FK 唯一引用**（`RedeemedByUId`）；`FederationAnchorOpenId` **不作引用键**（P2/P4——行级关系一律 UId）；`AuthGrant` login 源承接（vm_UserApps 读模型）；`AuthGrantSources.Redeem` 预留 **v0.2.0** 写入 | 前置裁定 §四承接清单；N2 anchor 语义（冗余快查列）；避免 v0.1.0 跨扩展门面扩展/拆包复杂度 |
| 5 | **视图归属与命名** | `TKWFV_UserRedemptionHistory`/`TKWFV_UserApps` 归**授权面**（业务域扩展——AGENTS §8 已定）；前缀 `TKWFV_` **暂用**（前置裁定 P3 + ADR C.16——框架组前缀批次核查后视情况 rename，不影响实体/ViewSql 设计） | P3 非阻塞裁定；对齐 C.16 新标准（既有 `vw_` 先例为历史形态，前缀批次统一） |
| 6 | **兑换码存储** | 明文 **不落库**——`CodeHash`（SHA256 十六进制 64，唯一）+ `CodeMasked`（展示脱敏值）；生成时**一次性返回明文** | 防库泄露即任意兑换（对齐 SmsRecord.CodeHash 先例）；UserCenter 契约 `CodeMasked` 约束（授权面已脱敏存储） |
| 7 | **兑换授权快照** | v0.1.0 兑换**不写** AuthGrant redeem——兑换 = 记录 + 码状态变更；"兑换入我的应用" v0.2.0（评估 AuthCenter `RecordLoginGrantAsync` Source 参数化 or 授权面委托——后者需拆 `AuthCenter.Abstractions`） | 范围克制（用户裁定）；`AuthGrantSources.Redeem` 常量已预留不阻塞未来 |
| 8 | **表名** | `RedemptionCode` / `AuthApp`（无前缀）；⚠️ **AuthCenter 表名对齐 V0.9.0**（`AuthAccount` 已改 `TKWF_AuthAccount`——ADR100 表名别名批次落地；`AuthGrant` 未变）；C.16 前缀批次后续若再变随框架组同步 | 域内唯一不与既有扩展冲突；AuthCenter V0.9.0 身份域重构（2026-10-07 实施适配实证） |
| 9 | **Domain/Web 拆分** | v0.1.0 **纯 Domain**（零 Web 依赖） | 无中间件/无内建端点（查询/兑换全经门面，装配实例映射端点）；对齐 UserCenter 纯 Domain 先例；管理端 API 随 v0.2.0 批次评估 |

### 5.2 实体设计（SG1 + xCodeGen）

#### RedemptionCodeEntity（表 `RedemptionCode`——兑换码一体）

```csharp
[Table("RedemptionCode")]
[Index("UX_RedemptionCode_CodeHash", nameof(CodeHash), IsUnique = true)]
[DomainGenerateCode(DefaultPageSize = 50)]
public partial class RedemptionCodeEntity
{
    [Column(IsPrimary = true, IsIdentity = true, Position = 1)] public long Id { get; set; }
    [Column(Position = 2, StringLength = 64)] public string CodeHash { get; set; } = "";     // SHA256 十六进制；唯一（一码一兑）
    [Column(Position = 3, StringLength = 32)] public string CodeMasked { get; set; } = "";   // 展示脱敏（如 "EDU-AB12-****-CD34"）
    [Column(Position = 4, StringLength = 100)] public string ProductName { get; set; } = ""; // 商品/载体名
    [Column(Position = 5, StringLength = 100)] public string TargetAppId { get; set; } = ""; // 兑换目标应用 id（对齐 AuthApp.AppId 语义）
    [Column(Position = 6)] public int Status { get; set; }                                    // <remarks>0=Available / 1=Redeemed / 2=Expired（惰性翻转）——对齐 AuthGrantEntity.Status(int) 先例；v0.2.0 考虑 RedemptionCodeStatus 枚举</remarks>
    [Column(Position = 7, IsNullable = true)] public DateTime? ExpireAtUtc { get; set; }     // 有效期（null=永不过期）
    [Column(Position = 8, IsNullable = true, StringLength = 32)] public string? RedeemedByUId { get; set; }  // 行级 FK=AuthAccount.UId（P4）
    [Column(Position = 9, IsNullable = true)] public DateTime? RedeemedAtUtc { get; set; }   // 兑换时间 UTC
    [Column(Position = 10, CanUpdate = false)] public DateTime CreateTime { get; set; } = DateTime.UtcNow;
    [Column(Position = 11)] public DateTime UpdateTime { get; set; } = DateTime.UtcNow;
}
```

- **单实体承载生成/兑换/历史**（v0.1.0 无批次；一码一兑语义下"兑换记录 = 码被兑换态"）——不为历史单独建 `RedemptionRecordEntity`（YAGNI，避免冗余双表）；v0.2.0 批次管理端加 `BatchId` 列即可扩展。

### 5.3 VEntity 设计（跨扩展视图——P3 归授权面）

### 5.6 兑换流程（生成 → 兑换 → 历史）

> **业务前提（Oracle4 P1-1 修订——裁定 A）**：v0.1.0 兑换**必须已登录**——`RedeemAsync(userId, codeInput)` 的 `userId` 必填（已认证帧，装配层从 DomainUser/令牌解析），频控按 userId 维度。业务场景限定"已注册用户兑换码激活应用"；**未登录用户无法兑换**（先注册/登录）。匿名兑换（兑换创建账号）留 v0.2.0 评估（IP+设备指纹频控 + AuthCenter 账号写契约衔接，需拆 `AuthCenter.Abstractions`）。使用指南 §二 显式标注该前提。

**创建码**（运营侧，`IRedemptionCommandService.CreateCodeAsync`）：
1. CSPRNG 生成高熵 code（`EDU-` 前缀 + 12 位 base32 字符，去易混淆 `0O1lI`——如 `EDU-AB12-CD34-EF56`）
2. `CodeHash = SHA256(code)`（十六进制 64）；`CodeMasked = EDU-AB12-****-EF56`（保留前 6 后 4）
3. `RedemptionCodeEntityDataService.EntityCreateAsync`（Status=0, ExpireAtUtc 按 validity 算, 余空）
4. 返回**明文 code**（一次性——不落库、不日志）

**兑换**（`IRedemptionCommandService.RedeemAsync(userId, codeInput)`）：
1. `IRateLimitCheck.GetRemaining(key, max, window) <= 0` 前置拦截（只读不计数——用户维度窗口内无效尝试超限 → `REDEMPTION_TOO_MANY_ATTEMPTS`——防爆破）
2. `hash = SHA256(codeInput)` → `RedemptionCodeEntityDataService.EntitySelectAsync(predicate CodeHash==hash)` 查码
3. 不存在 → `REDEMPTION_CODE_INVALID`（频控计一次无效）
4. `Status != 0` → 已兑（`REDEMPTION_CODE_USED`）/ 过期（`REDEMPTION_CODE_EXPIRED`——`ExpireAtUtc < UtcNow` 时顺手 `EntityUpdateWhereAsync` 翻 `Status=2`）
5. **CAS 原子兑换**：`EntityUpdateWhereAsync(predicate: Id==code.Id && Status==0 && (ExpireAtUtc==null || ExpireAtUtc>UtcNow), set: Status=1, RedeemedByUId=userId, RedeemedAtUtc=UtcNow)`——**影响 0 行 = 并发双兑败者** → 重查判定（已兑/过期）→ 抛对应异常（对齐 ADR89 单语句 WHERE 谓词 + FileManagement UX 约束败者重查先例）
6. 成功 → 映射 `RedemptionRecordDto` 返回（历史即码行 Redeemed 态）

**历史查询**：`IRedemptionQueryService.GetRedemptionsAsync(userId)` → `UserRedemptionHistoryViewDataService.GetHistoryByUserIdAsync`（仅本人过滤在 predicate——IDOR 防护在数据层兜底）→ 映射 DTO。

### 5.7 兑换尝试频控（v4.10.67 适配——IRateLimitCheck 点检查原语）

- **v4.10.67 适配（2026-10-07）**：兑换尝试频控经框架 `IRateLimitCheck` 点检查原语（`TKW.Framework.Utility.RateLimitChecks`——R1 上移自 MFA MfaRateLimiter，适配通知 §一 R3 同步删 MfaRateLimiter——**新扩展不复制旧形态**）。`MemoryRateLimitCheck`（内存滑动窗口）经 `TryAddSingleton<IRateLimitCheck, MemoryRateLimitCheck>()` fallback（未启用 RateLimiting 扩展时频控不消失；R2 `SqlCountRateLimitCheck` 落地后可替换，TryAdd 语义）。
- **key 规范化**（IRateLimitCheck XML doc 约定 `{policy}:{partitionBy}:{subject}`）：`redemption:redeem:{userId}`。
- **流程**：① 前置只读拦截 `GetRemaining(key, max, window) <= 0` → 抛 `REDEMPTION_TOO_MANY_ATTEMPTS`（不计数——防有效兑换误计）；② 无效/已兑/过期路径 `TryAcquire(key, max, window, out _)` 计入失败（防批量枚举爆破）；③ 成功兑换**不计数**（不污染窗口；"成功重置"由不计数天然近似替代——窗口满时所有尝试被拒直到滑出，对齐 MFA 频控语义）。
- 窗口/上限可配：`AuthSurfaceOptions`（`TKWF:AuthSurface` 节——`RedemptionAttemptWindowMinutes` 默认 60 / `RedemptionAttemptMaxAttempts` 默认 10）。
- 分布式场景（多实例）v0.2.0 评估（SqlCountRateLimitCheck / Redis 计数器）。

### 5.8 安全与数据访问红线

| # | 项 | 设计 | 归属 |
|---|----|------|------|
| 1 | **IDOR 越权** | 门面**显式 `userId`**（对齐 UserCenter L385 先例）+ DataService predicate 按 UserId 过滤（数据层兜底）——装配端点从 DomainUser/令牌解析，不信任客户端传参 | 授权面（门面 + DataService）+ 装配实例 |
