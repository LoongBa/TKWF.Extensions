## 1. 背景与目标

EduPlatform（教育线 B-口令兑换）需「批量发券」核心需求（生成、导出 CSV、券名称/有效期、批次数量、核销统计、明细分页、吊销）。经扩展模块组**边界再评估**（oracle-pro7 全局裁定，转告 §一/§四 定稿）：批次 = 兑换码域**固有聚合根**，`CodeBatch` 头表归 AuthSurface（扩展仓三先例：DataPort 任务/记录、FileManagement 主/版本、WeChatOperations 快照/版本——「头+行」均在扩展内）；消费方零批次表，仅保留表现层（管理端点/CSV 呈现/审计）。

**目标（v0.3.0，全程加性非破坏）**：
1. 批次域：`TKWF_CodeBatch` 头表 + `ICodeBatchService` 门面族（创建/生成/删除/列表统计/明细/吊销）；
2. 码侧契约：`BatchId` 列、`Revoked(3)` 状态 + 兑换链路归类、`CreateCodeAsync(expireAt:)`、按明文哈希读码（含 batchTest/channel）、兑换历史分页、payload 解密门面；
3. AuthCenter 协作：`RecordGrantAsync(source:, validUntil:)` 泛化（写路径归属消费方编排，扩展侧仅提供门面能力）。

## 3. 实体设计（SG1）

### 3.1 `CodeBatchEntity`（新增，表 `TKWF_CodeBatch`）

```csharp
[Table("TKWF_CodeBatch")]
[DomainGenerateCode(DefaultPageSize = 20)]
public partial class CodeBatchEntity
{
    long Id;                                  // PK 自增（码行 BatchId 引用此值——C-4⑤ 类型定稿：码侧 BatchId 列 `long?` 直接存 Id，对齐 ManagedFileVersionEntity.FileId 实际形态，非 VARCHAR 字符串）
    string BatchNo;                           // 展示批次号，唯一（TKWFIX_CodeBatch_BatchNo）
                                              // 格式：B{yyyyMMdd}{4 位随机大写字母数字}（CSPRNG，无模偏差）；同日碰撞（唯一约束 23505）→ 重试再生成（有限 3 次，A-3）
    string Name;                              // 批次/券名称（≤100）
    string ProductName;                       // 产品名（≤100，码行冗余——生成时投影）
    string TargetAppId;                       // 目标应用（≤100，软引用 AuthApp.AppId；"*" 全产品语义透传）
    int? ValidityDays;                        // 兑换后授权时长模板（自然日，null=无 grant 语义）——扩展不解释，消费方编排读
    DateTime? ExpireAtUtc;                    // 批次券有效期（绝对 UTC，未兑换前作废点；null=不过期）
    string? Channel;                          // 发行渠道（≤100 软词汇——值域归消费方，仅长度校验）
    int Quantity;                             // 计划数量（1~Options.MaxBatchQuantity 默认 5000）
    int GeneratedCount;                       // 实际生成数
    int Status;                               // 0 DRAFT / 1 GENERATING / 2 GENERATED / 3 REVOKED
    bool Test;                                // 测试批次标记（拒兑策略归消费方兑换编排）
    DateTime? ExportedAtUtc;                  // 生成即导出时间（= GENERATED 落定时刻）
    string? CreatedBy;                        // 创建人（≤64，透传不做身份校验）
    DateTime CreateTime; DateTime UpdateTime;
}
```

- 状态机：`DRAFT → GENERATING（CAS 抢占）→ GENERATED`；`GENERATED → REVOKED（整批吊销动作）`；`DRAFT →（物理删除）`；失败回滚 → DRAFT。**PARTIAL_REVOKED 不落库**（派生：`Status==GENERATED && revokedCount>0` 由统计聚合直接派生，零额外查询——oracle-pro3 3c 判定优于落库；全吊销升 REVOKED 落库）。**RevokeCodeAsync 升 REVOKED 判定式**：「吊销后该批内 `status==0` 码计数==0 → 升 REVOKED」（"未兑"字面不含已翻转 status=2 的过期码——不影响终态判定，C-4 精确化）。
- **批次级 EXPIRED 惰性派生态（A-1 登记，非本版落库状态）**：B1 §4.1 有「批次 expire_at_utc 已过或全部码过期」（转告定稿 4 态未含——以转告为准，本版不落库）；消费方可从统计派生（`expiredCount==generatedCount`）；若需批次列表按"已过期"过滤 → 回执中与 EduPlatform 对齐一句（后续可增 `GetBatchesAsync` filter 派生参数），避免 B1 实施期二次转告。
- 无软删除（对齐 RedemptionCodeEntity）；`hasSoftDelete:false`。
- BatchId 引用（码侧 → 批次）：**软引用无 FK**（对齐 `ManagedFileVersionEntity.FileId` 先例：`long?` 类型 + 非唯一索引 + 代码级生命周期保证——批次仅 DRAFT 可删，DRAFT 无码；生成/吊销批次不可删）。

## 4. 门面设计

### 4.1 `ICodeBatchService : IDomainService`（新增，8 方法）

实现 `internal sealed class CodeBatchService : DomainServiceBase, ICodeBatchService`，`AddConstructibleService` 注册；DataService 经 `User.Use<CodeBatchEntityDataService>()` 懒加载（DI004 零豁免）。

```csharp
public interface ICodeBatchService : IDomainService
{
    // T-0 创建（DRAFT）；通用校验：Name/ProductName/TargetAppId 非空、Quantity∈[1,Options.MaxBatchQuantity(默认5000)]、
    // ExpireAtUtc 为空或晚于 now、Channel 长度；ValidityDays 校验>0（白名单{7,30,90,365}等业务政策归消费方）
    Task<CodeBatchDto> CreateBatchAsync(CreateCodeBatchRequest request, CancellationToken ct = default);

    // T-0 生成即导出（CAS 抢占 DRAFT→GENERATING（谓词 status==0 且 GeneratedCount==0，败者 BATCH_NOT_EDITABLE）
    // → 逐码回调（main方案：Func<string, long, CancellationToken, Task>？）+ 失败/中断整体回滚 DRAFT
    // → 全量成功 → GENERATED + GeneratedCount=Quantity + ExportedAtUtc=now
    // 定稿（C-2/oracle-pro3 3a）：**回调形态为主方案**（转告 T-0 明文允许「or 回调」）——
    //   GenerateBatchAsync(batchId, Func<string, CancellationToken, Task> onPlainCode, ct)
    //   ——回调异常/ct 取消 → 整体回滚 DRAFT；明文一次性：回调内即消费（写入 CSV 流），门面不缓存不落库不落日志；
    //   事务生命周期收敛在方法内（无跨枚举长事务/无 Dispose 悬挂风险）；内存占用恒 O(1)。
    //   IAsyncEnumerable 流式废弃（跨枚举事务 + 枚举器不 Dispose → GENERATING 悬挂死批次风险，oracle-pro3 3a 裁定）；
    //   内存物化为降级（仅在框架事务 API 不支持方法内回滚时启用——须回执 EduPlatform 声明「消费方中断不再回滚」语义弱化）。
    // 崩溃恢复语义（B1 §4.1 失败边崩溃分支，C-2 补充）：CAS 抢占与码生成同事务——进程崩溃 → DB 事务回滚 → 批次自然回 DRAFT（可重试生成）
    Task GenerateBatchAsync(long batchId, Func<string, CancellationToken, Task> onPlainCode, CancellationToken ct = default);

    // T-0 删除（仅 DRAFT 物理删——无已生成码；非 DRAFT → BATCH_NOT_EDITABLE；不存在 → BATCH_NOT_FOUND）
    Task DeleteBatchAsync(long batchId, CancellationToken ct = default);

    // T-2 批次列表+每批统计（单查询分组聚合；filter：状态/渠道/时间范围/名称模糊/Test；分页 page/pageSize）
    Task<CodeBatchPageDto> GetBatchesAsync(CodeBatchFilter filter, int page, int pageSize, CancellationToken ct = default);

    // T-2 批次详情+统计（不存在 → BATCH_NOT_FOUND）
    Task<CodeBatchDetailDto> GetBatchAsync(long batchId, CancellationToken ct = default);

    // T-2 券明细分页（掩码/状态/兑换归属/时间；状态过滤 status?；明文不出现在列表；
    //   不存在批次 → BATCH_NOT_FOUND；越界 → 空页，非异常）
    Task<CodePageDto> GetBatchCodesAsync(long batchId, int page, int pageSize, int? status, CancellationToken ct = default);

    // T-3 整批吊销：批次须 GENERATED（DRAFT 无码吊销无意义 → BATCH_NOT_EDITABLE；REVOKED 幂等返回；不存在 → BATCH_NOT_FOUND）
    //   单语句条件更新（where BatchId==? && Status==0 → set Status=3），批次状态机同事务 GENERATED→REVOKED
    Task RevokeBatchAsync(long batchId, CancellationToken ct = default);

    // T-3 单码吊销：单语句条件更新（where Id==? && Status==0 → set Status=3）；
    //   返回 bool = 是否翻成功（已兑/已吊销 → false 幂等，不抛——C-4② 定稿幂等语义）；
    //   翻成功 → 同事务判定「吊销后该批 status==0 码计数==0」→ 批次升 REVOKED
    Task<bool> RevokeCodeAsync(long codeId, CancellationToken ct = default);
}
```

**批量生成事务形态（定稿 C-2）**：门面内显式事务（`ITransactionManager`/框架 UoW 语义——扩展测试宿主先例）包裹「CAS 抢占 → 逐码回调生成 → 状态落定」；回调异常/消费方 ct 取消 → 事务回滚 → 批次回 DRAFT（B1 §4.4「生成中任一步失败 → 整体回滚 + 中断响应」语义；失败批次的 CSV 已流出明文 = 作废码，由 DRAFT 回滚 + 不可再生成保证）。**崩溃恢复**：同事务 CAS 抢占 → 进程崩溃 DB 回滚 → 批次回 DRAFT（B1 §4.1 失败边崩溃分支——CAS 抢占与生成同一事务的唯一崩溃恢复论证）。SQLite 测试用**文件模式 + 物理事务**（Noop 事务管理器不真回滚会假绿——测试约定 §C-5）；PG 生产同事务传播。

**统计口径（T-2 契约，转告 C-1 继承）**：
- `expired = status=0 && expire_at_utc ≤ now`（**时间派生，禁按 Status==2 落库计数**——惰性翻转仅发生在兑换尝试时）；
- `pending = status=0 && (expire_at_utc is null ∥ > now)`；
- `total = GeneratedCount`（A-6 明确——DRAFT 批次 GeneratedCount=0，全桶为 0）；不变式 `total = redeemed + pending + expired + revoked`；
- 列表聚合：单查询按 BatchId 分组（FreeSql 可翻译表达式——`DateTime.UtcNow` 比较已有 CAS 谓词实证可翻译；`GroupCountAsync`/`GroupByAsync` V4.10.39 原语，AuditLogging/Tagging 先例）——分组维度 = `CodeBatch.Id`（long）；**口径一律按码行 `expire_at_utc` 逐码判定**（批次码生成时继承头值；C-4⑥ 删除头口径歧义句）。

**DTO**（`Contracts/` 或 Entities/DTOs 分部）：`CodeBatchDto`（BatchNo/Name/Status/Quantity/GeneratedCount/Test/ExpireAtUtc/ValidityDays/Channel/CreatedBy/CreateTime/ExportedAtUtc + 7 统计指标）/ `CreateCodeBatchRequest` / `CodeBatchFilter` / `CodeBatchDetailDto` / `CodePageDto`（掩码行）/ `CodeBatchLookupDto`（T-5）。

## 5. 兑换链路语义（Revoked 归类闭环）

| 路径 | 现状 | v0.3.0 |
|------|------|--------|
| 前置判定 | L132 `Status==1`→Used；L137 `Status==2`或过期→Expired | + L：`Status==3` → `REDEMPTION_CODE_REVOKED`（403） |
| CAS 谓词 | `Id==id && Status==0 && 未过期` | **不变**（Status==0 天然排斥 Revoked） |
| 败者重查 | `fresh.Status==1 ? Used : Expired` | `==1→Used / ==3→Revoked / else→Expired` |
| 频控 | 无效/已兑/过期均 TryAcquire 计数 | Revoked 路径同计数（防枚举探态一致性） |
| 错误码 | 4 个 | + `REDEMPTION_CODE_REVOKED`（HTTP 403 映射归装配实例） |

## 6. AuthCenter 协作（T-7，跨扩展）

`IAuthGrantCommandService` 泛化——**新增**方法，既有 `RecordLoginGrantAsync` 保留（内部委托）：

```csharp
// 泛化：Source/ValidUntil 参数化（redeem 源写路径——T-7 契约）
Task RecordGrantAsync(string userId, string appId, string source, DateTime? validUntilUtc, CancellationToken ct = default);
```

- **upsert 语义**：复合键 (UserId+AppId+Source) 存在 → **以传入 `validUntilUtc` 覆写 + Status=0(Active) + UpdateTime**（解决现冲突路径 `RefreshActiveAsync` 不动 ValidUntil 的缺口——IAuthGrantCommandService.cs L60/L82 实证）；不存在 → 创建（ValidUntil = 传入值）。
- **覆写语义 = last-writer-wins（read-modify-write 归消费方）**：并发叠加防丢失更新（B1 §2.1 I-5c「30+30 并发只记 30」按用户串行化）**不在本门面内处理**——README/指南明示（A-4），消费方兑换编排自持（账号维度锁/条件更新）。
- **向后兼容**：`RecordLoginGrantAsync` 保持原签名/原行为（login 源 ValidUntil 恒 null——既有行恒 null 由唯一写入口保证，覆写 null 无损），内部改委托 `RecordGrantAsync(userId, appId, Sources.Login, null, ct)`。
- **跨门面事务**：CAS（AuthSurface 门面）+ grant 写（AuthCenter 门面）同一 TransactionScope 传播——**测试验证为硬性交付**（§8.2 C-3 用例：grant 写失败 → 码状态回滚可重兑；若证实不可传播 → 转告补偿登记，不阻塞本迭代其余项）。
- **写路径归属**：AuthSurface **不**直写 AuthGrant（TKWF0022 红线）；消费方兑换编排调 `User.Use<IAuthGrantCommandService>().RecordGrantAsync(..., "redeem", validUntil)`。

## 7. Options 扩展（`TKWF:AuthSurface`）

| 键 | 默认 | 说明 |
