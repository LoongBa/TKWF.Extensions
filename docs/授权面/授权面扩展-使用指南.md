# 授权面扩展-使用指南

> **扩展**: `TKWF.Ext.AuthSurface`（授权面——口令兑换体系 + 我的应用聚合）| **版本**: V0.1.0 | **框架**: .NET 10
> **文档**: 2026-10-07｜**开发方案**: [v0.1.0-AuthSurface-授权面-开发方案.md](./v0.1.0-AuthSurface-授权面-开发方案.md)
> **定位**: 横在"认证中心 vs 用户中心"之间的**第三个领域**——口令兑换体系（code/redemption/grant/batch + 管理端）+ 我的应用聚合 + 授权快照候选。行级身份引用一律 `AuthAccount.UId`（P4 白名单）。
> **关键边界（✅ UserCenter 已退役 2026-10-08）**: 原 P2 FREEZE（不实现 UserCenter `IRedemptionHistorySource`/`IUserAppsSource`）已随 UserCenter 完整删除完结——无契约可 Freeze；消费方兑换/应用查询**唯一通道 = 本扩展自有门面**；DTO（`RedemptionRecordDto`/`UserAppDto`）归本扩展主包。

## 一、快速开始

### 1. 引用与启用

> 📌 **公共接线机制**（发现≠启用 / 三钩子 / Web 钩子正交 / 启动期安全解析）见 [《扩展模块通用指南》](../扩展模块通用指南.md) §二/§四——以下仅列本扩展特有接线。

```xml
<!-- 消费方 .csproj（NuGet 模式——生产推荐） -->
<PackageReference Include="TKWF.Ext.AuthSurface" Version="0.1.0" />
```

```xml
<!-- 源码模式（扩展仓库内联调） -->
<ProjectReference Include="..\_TKWF.Extensions\_Framework\AuthSurface\TKWF.Ext.AuthSurface.csproj" />
```

消费方领域初始化器声明**白名单启用**（V4.9.85+ 发现不自动启用）——**须同时启用认证中心**（本扩展两 VEntity 视图 JOIN 依赖其 `AuthGrant`/`AuthAccount` 基表）：

```csharp
using TKWF.Ext.AuthSurface;
using TKWF.Ext.AuthCenter;

[TKWFEnabledExtension(typeof(AuthSurfaceExtensionInitializer<>))]
[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]   // 依赖：AuthAccount/AuthGrant 表 + 身份
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后自动注册：

- **门面×4**（`User.Use<接口>()` 解析——守卫工厂）：`IRedemptionCommandService`（创建码/兑换）/ `IRedemptionQueryService`（兑换历史）/ `IUserAppsQueryService`（我的应用）/ `IAuthAppService`（应用目录维护）
- **DataService**（SG1 + ADR61 自动注册，零手动）：`RedemptionCodeEntityDataService` / `AuthAppEntityDataService` / `UserRedemptionHistoryViewDataService` / `UserAppsViewDataService`
- **⚠️ 无 WebExtension**：v0.1.0 纯 Domain——兑换/查询端点映射归**装配实例**（对齐仓库纯 Domain 先例）；v0.2.0 批次管理端 API 经 `[GenerateController]` 自动生成 Controller

### 2. 配置（`TKWF:AuthSurface` 节）

```json
{
  "TKWF": {
    "AuthSurface": {
      "RedemptionAttemptWindowMinutes": 60,
      "RedemptionAttemptMaxAttempts": 10
    }
  }
}
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `RedemptionAttemptWindowMinutes` | 60 | 兑换尝试频控窗口（分钟）——用户维度无效码尝试计数窗口 |
| `RedemptionAttemptMaxAttempts` | 10 | 窗口内无效码尝试上限——超限抛 `REDEMPTION_TOO_MANY_ATTEMPTS` |

## 二、核心用法

### 1. 兑换（消费方门面——仅本人，userId 从 DomainUser/令牌解析）

> **⚠️ 兑换前提（业务约束）**：v0.1.0 兑换**必须已登录**——`RedeemAsync` 的 `userId` 必填（已认证帧，装配层从 DomainUser/令牌解析）。**未登录用户无法兑换**（先注册/登录）；匿名兑换（兑换创建账号）留 v0.2.0 评估。频控按 userId 维度。

```csharp
public class RedeemController(IUserAppsQueryService apps, IRedemptionQueryService redemptions,
                              IRedemptionCommandService redemptionCmd, IAuthAppService authApp)
{
    // POST /api/edu/user/redeem —— 兑换（userId 从 DomainUser/令牌解析，不信任客户端传参）
    public async Task<RedemptionRecordDto> RedeemAsync(string currentUserId, string code)
        => await redemptionCmd.RedeemAsync(currentUserId, code);

    // GET /api/edu/user/redemptions —— 兑换历史
    public async Task<IReadOnlyList<RedemptionRecordDto>> RedemptionsAsync(string currentUserId)
        => await redemptions.GetRedemptionsAsync(currentUserId);

    // GET /api/edu/user/apps —— 我的应用（授权聚合）
    public async Task<IReadOnlyList<UserAppDto>> AppsAsync(string currentUserId)
        => await apps.GetAppsAsync(currentUserId);
}
```

兑换失败业务异常（HTTP 映射归装配实例）：`REDEMPTION_CODE_INVALID`（无效码）/ `REDEMPTION_CODE_USED`（已兑）/ `REDEMPTION_CODE_EXPIRED`（过期）/ `REDEMPTION_TOO_MANY_ATTEMPTS`（频控）。

### 2. 创建兑换码（运营侧——单码，v0.1.0 无批次管理端）

```csharp
// 运营后台（管理员上下文）——返回明文 code 一次性（库中仅存 SHA256 哈希 + 脱敏值）
string code = await redemptionCmd.CreateCodeAsync(
    productName: "学期课程包", targetAppId: "edu-course", validity: TimeSpan.FromDays(30));
// 明文 code 仅此一次返回——分发后不留存，不得写日志
```

### 3. 应用目录维护（"我的应用" AppName 来源）

```csharp
// 运营侧：录入应用（AppId 对齐 AuthGrant.AppId / RedemptionCode.TargetAppId 语义）
await authApp.CreateAppAsync(appId: "edu-course", appName: "教育课程", icon: "https://cdn.example.com/icons/course.png");
await authApp.SetEnabledAsync("edu-course", isEnabled: true);
```

> ⚠️ **录入前置**：`AuthApp` 目录未录入的应用，`我的应用`列表 `AppName` 显示为 null（不丢行——`LEFT JOIN`）；生产装配前建议先录入目录。
> ⚠️ **软删除建议**：`AuthApp.AppId` 与 `AuthGrant.AppId`/`RedemptionCode.TargetAppId` 为**字符串软引用**（无 FK 约束）——删除前需检查引用；建议 `SetEnabledAsync(false)` 软禁用而非物理删除（防 vm_UserApps 丢 AppName / 兑换码 TargetAppId 指向已删应用）。

## 三、表结构与视图

| 实体/视图 | 表/视图名 | 说明 |
|-----------|----------|------|
| `RedemptionCodeEntity` | `RedemptionCode` | 兑换码一体（生成/兑换/历史同表）——`CodeHash`(SHA256 唯一)/`CodeMasked`/`ProductName`/`TargetAppId`/`Status`(0 Available/1 Redeemed/2 Expired)/`ExpireAtUtc`/`RedeemedByUId`(**行级 FK=AuthAccount.UId**)/`RedeemedAtUtc` |
| `AuthAppEntity` | `AuthApp` | 应用目录——`AppId`(唯一)/`AppName`/`Icon`/`IsEnabled` |
| `UserRedemptionHistoryView` | `TKWFV_UserRedemptionHistory`（VEntity） | 兑换历史读模型——JOIN `RedemptionCode` + `TKWF_AuthAccount`（取身份锚 UId——AuthCenter V0.9.0 凭据白名单列）；`ExposeGraphqlQuery=false`（经门面查询） |
| `UserAppsView` | `TKWFV_UserApps`（VEntity） | 我的应用读模型——JOIN `TKWF_AuthGrant` + `TKWF_AuthAccount` + `AuthApp`（LEFT JOIN 取 AppName）；`ExposeGraphqlQuery=false` |

> **视图前缀注记**（P3 裁定）：`TKWFV_` 前缀为**暂用**（ADR-AuthCenter C.16 前缀批次 + 框架组核查后视情况 rename——不影响实体/ViewSql 设计）。

## 四、安全约束

| 项 | 约束 | 归属 |
|----|------|------|
| **IDOR 越权** | 门面显式 `userId` 参数 + DataService predicate 按 UserId 过滤（数据层兜底）——装配端点从 DomainUser/令牌解析，**不信任客户端传参** | 授权面 + 装配实例 |
| **兑换码明文** | 明文**不落库**（SHA256 哈希）；生成时一次性返回；展示用 `CodeMasked`；明文/含码 DTO 不入日志 | 授权面 |
| **并发双兑** | CAS 原子兑换（单语句 WHERE 谓词）——败者重查判定 | 授权面 |
| **无效码爆破** | 兑换尝试频控经框架 `IRateLimitCheck` 点检查原语（v4.10.67——`MemoryRateLimitCheck` fallback，用户维度） | 授权面 |
| **敏感视图** | 两 VEntity `ExposeGraphqlQuery=false`——查询全经门面 | 授权面 |
| **儿童数据红线** | `UserAppDto.UsageSummary` v0.1.0 恒 null（"不含学习明细"契约约束） | 授权面 |
| **身份引用** | 行级 FK 一律 `AuthAccount.UId`（P4 白名单）；`FederationAnchorOpenId` 不作引用键 | 授权面 |

## 五、与认证中心 / 用户中心划界

| 模块 | 职责 | 与授权面的关系 |
|------|------|--------------|
| **认证中心**（`TKWF.Ext.AuthCenter`） | 令牌 + 账号（`AuthAccount`）+ 应用授权底座（`AuthGrant` + `GET /grants`） | 身份锚 `AuthAccount.UId` = 本扩展行级 FK；`AuthGrant`（login 源）为 `我的应用` 数据底座；**v0.1.0 本扩展不写 `Source=redeem` 授权**（`AuthGrantSources.Redeem` 已预留，v0.2.0 落地） |
| ~~**用户中心**~~（`TKWF.Ext.UserCenter`） | ~~档案面（Profile 已由认证中心承接）+ 兑换/应用读取骨架（缺省降级）~~ | **✅ 已退役（2026-10-08 完整删除）**——原 P2 FREEZE（不实现两 Source 契约 / 门面空列表降级 / DTO 复用）全部随 UserCenter 删除完结；档案经 AuthCenter 门面、兑换/应用经本扩展门面、DTO 归本扩展主包（本行为历史对照） |
| **授权面**（本扩展） | 兑换体系 + 我的应用聚合 + 授权快照（候选） | 数据属主 = 兑换/授权记录。**⚠️ v0.1.0 业务语义缺口（Oracle4 P1-3 明示）**：兑换成功后应用**不会**出现在"我的应用"列表——v0.1.0 兑换不写 `AuthGrant`（`Source=redeem` 留 v0.2.0）；兑换历史（`vm_UserRedemptionHistory`）可见。消费方页面应区分"兑换记录"与"应用授权"两栏 |

## 六、生产部署要求

- **跨扩展视图（DBA 手动执行）**：`SyncViewsAsync` 仅开发环境自动建视图；**生产需 DBA 手动执行 ViewSql**。依赖扩展表清单（**先建表后建视图**）：

| 视图 | 依赖基表 | 属主 |
|------|---------|------|
| `TKWFV_UserRedemptionHistory` | `RedemptionCode` + `TKWF_AuthAccount` | 授权面 + 认证中心 |
| `TKWFV_UserApps` | `TKWF_AuthGrant` + `TKWF_AuthAccount` + `AuthApp` | 认证中心×2 + 授权面 |

- **方言变体**：PG 用 `CREATE OR REPLACE VIEW`（开发环境自动），SQLite 用 `CREATE VIEW IF NOT EXISTS`——DBA 按部署库方言执行对应 ViewSql（见开发方案 §5.3 全文）。
- **表名快照依赖**：ViewSql 引用 `TKWF_AuthGrant`/`TKWF_AuthAccount` 表名（⚠️ `AuthAccount` 已改 `TKWF_AuthAccount`——AuthCenter V0.9.0 身份域重构 ADR100 表名别名批次落地）——后续前缀批次若再变，视图需同步 rename（P3 已登记）。

## 七、常见问题

| 症状 | 原因 | 处置 |
|------|------|------|
| `我的应用` 显示裸 AppId（AppName 为 null） | `AuthApp` 目录未录入该应用 | `IAuthAppService.CreateAppAsync` 录入（§二.3） |
| 兑换返回 `REDEMPTION_CODE_USED` | 码已被他人/自己兑换过 | 一码一兑（CodeHash 唯一 + CAS）——码不可复用 |
| 兑换报 `REDEMPTION_TOO_MANY_ATTEMPTS` | 窗口内无效码尝试超限 | 等窗口滑过（默认 60min）或调 `AuthSurfaceOptions` 上限 |
| 视图查询报"表不存在" | AuthCenter 未启用/未建表，或生产视图未建 | 白名单同时声明 AuthCenter（§一.1）；生产 DBA 执行 ViewSql（§六） |
| 消费方仍在代码里引用已删除的 `IUserCenterQueryService`/UserCenter DTO | **UserCenter 已完整删除（2026-10-08）**——编译失败属预期 | 按适配通知迁移：DTO 改 `TKWF.Ext.AuthSurface`、兑换经 `IRedemptionQueryService`、档案经 AuthCenter（`docs/UserCenter/UserCenter-退役-消费方适配通知.md`） |
| 兑换成功但"我的应用"列表无该应用 | **v0.1.0 预期行为**——兑换不写 `AuthGrant`（`Source=redeem` 留 v0.2.0）；应用授权暂不入"我的应用" | 兑换历史可见（§二.1 RedemptionsAsync）；应用授权聚合 v0.2.0（§五 明示） |
