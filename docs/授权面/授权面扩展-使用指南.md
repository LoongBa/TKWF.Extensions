> **扩展**: `TKWF.Ext.AuthSurface`（授权面——口令兑换体系 + 批次管理 + 我的应用聚合）| **版本**: V0.3.1（已发布 2026-11-17）| **框架**: .NET 10
> **文档**: 2026-11-17｜**开发方案**: [v0.1.0-AuthSurface-授权面-开发方案.md](./v0.1.0-AuthSurface-授权面-开发方案.md)

```xml

```

```xml

<!-- 源码模式（扩展仓库内联调） -->
<ProjectReference Include="..\_TKWF.Extensions\_Framework\AuthSurface\TKWF.Ext.AuthSurface.csproj" />
```

消费方领域初始化器声明**白名单启用**（V4.9.85+ 发现不自动启用）——**须同时启用认证中心**（本扩展两 VEntity 视图 JOIN 依赖其 `AuthGrant`/`AuthAccount` 基表）：

```csharp
using TKWF.Ext.AuthSurface;
using TKWF.Ext.AuthCenter;

[TKWFEnabledExtension(typeof(AuthSurfaceExtensionInitializer<>))]
[TKWFEnabledExtension(typeof(AuthCenterExtensionInitializer<>))]   // 依赖：AuthAccount/AuthGrant 表 + 身份
public class MyDomainInitializer : DomainHostInitializerBase<MyUserInfo> { ... }
```

启用后自动注册：

- **门面×5**（`User.Use<接口>()` 解析——守卫工厂）：`IRedemptionCommandService`（创建码/兑换）/ `IRedemptionQueryService`（兑换历史/读码/payload）/ `ICodeBatchService`（**V0.3.0** 批次管理）/ `IUserAppsQueryService`（我的应用）/ `IAuthAppService`（应用目录维护）
- **DataService**（SG1 + ADR61 自动注册，零手动）：`RedemptionCodeEntityDataService` / `CodeBatchEntityDataService`（**V0.3.0**）/ `AuthAppEntityDataService` / `UserRedemptionHistoryViewDataService` / `UserAppsViewDataService`
- **⚠️ 无 WebExtension**：纯 Domain 扩展——兑换/查询/批次管理**端点**均归**装配实例**；**V0.3.0 定稿**：批次管理端点由消费方经 `User.Use<ICodeBatchService>()` 编排（如 `/api/edu/admin/code-batches` 族），扩展**不生成** `[GenerateController]` 管理端点（CSV 呈现/审计归消费方表现层）

### 2. 配置（`TKWF:AuthSurface` 节）

```json
{
  "TKWF": {
    "AuthSurface": {
      "RedemptionAttemptWindowMinutes": 60,
      "RedemptionAttemptMaxAttempts": 10,
      "IsProduction": true
    }
  }
}
```

| 属性 | 默认 | 说明 |
|------|------|------|
| `RedemptionAttemptWindowMinutes` | 60 | 兑换尝试频控窗口（分钟）——用户维度无效码尝试计数窗口 |
| `RedemptionAttemptMaxAttempts` | 10 | 窗口内无效码尝试上限——超限抛 `REDEMPTION_TOO_MANY_ATTEMPTS` |
| `SecretEncryptionKeyPath` | `null` | **v0.2.0**——兑换码附加信息（核验业务信息）AES-GCM 密钥文件路径（`string?`，keyed `ISymmetricKeyProvider`，键 AuthSurface） |
| `MaxBatchQuantity` | `5000` | **V0.3.0**——单批计划数量上限（`CreateBatchAsync` 通用校验，超出抛 `BATCH_QUANTITY_EXCEEDED`；业务白名单如 {7,30,90,365} 归消费方） |
| `IsProduction` | `true` | **v0.2.0**——生产模式（`bool`）：`true`=缺密钥拒绝启动（禁 dev 随机兜底） |

> ⚠️ **密钥配置强制（v0.2.0）**：生产环境必须配置密钥文件路径（`SecretEncryptionKeyPath`）——**即使不使用 payload 功能**（兑换门面构造即加载密钥，缺密钥生产 fail-fast）；开发环境须显式设 `IsProduction=false`。

## 二、核心用法

### 1. 兑换（消费方门面——仅本人，userId 从 DomainUser/令牌解析）

> **⚠️ 兑换前提（业务约束）**：v0.1.0 兑换**必须已登录**——`RedeemAsync` 的 `userId` 必填（已认证帧，装配层从 DomainUser/令牌解析）。**未登录用户无法兑换**（先注册/登录）；匿名兑换（兑换创建账号）留 v0.2.0 评估。频控按 userId 维度。

```csharp
// ① 推荐：DomainServiceBase 派生门面形态——内部经 User.Use<接口>() 解析
public class RedeemService : DomainServiceBase
{
    public RedeemService(IDomainUser user) : base(user) { }

    // POST /api/edu/user/redeem —— 兑换（userId 从 DomainUser/令牌解析，不信任客户端传参）
    public async Task<RedemptionRecordDto> RedeemAsync(string currentUserId, string code)
        => await User.Use<IRedemptionCommandService>().RedeemAsync(currentUserId, code);

    // GET /api/edu/user/redemptions —— 兑换历史
    public async Task<IReadOnlyList<RedemptionRecordDto>> RedemptionsAsync(string currentUserId, int? page = null, int? pageSize = null)
        => await User.Use<IRedemptionQueryService>().GetRedemptionsAsync(currentUserId, page, pageSize);

    // GET /api/edu/user/apps —— 我的应用（授权聚合）
    public async Task<IReadOnlyList<UserAppDto>> AppsAsync(string currentUserId)
        => await User.Use<IUserAppsQueryService>().GetAppsAsync(currentUserId);
}
```

```csharp
// ② 备选：MVC Controller 内经 _domainUser.Use<T>() 显式解析（域作用域帧内）——
//    ⚠️ 禁构造注入 4 门面（AddConstructibleService 守卫工厂——域作用域外解析必抛）
public class RedeemController(IDomainUser domainUser)
{
    private readonly IDomainUser _domainUser = domainUser;

    public async Task<RedemptionRecordDto> RedeemAsync(string currentUserId, string code)
        => await _domainUser.Use<IRedemptionCommandService>().RedeemAsync(currentUserId, code);

    public async Task<IReadOnlyList<RedemptionRecordDto>> RedemptionsAsync(string currentUserId, int? page = null, int? pageSize = null)
        => await _domainUser.Use<IRedemptionQueryService>().GetRedemptionsAsync(currentUserId, page, pageSize);

    public async Task<IReadOnlyList<UserAppDto>> AppsAsync(string currentUserId)
        => await _domainUser.Use<IUserAppsQueryService>().GetAppsAsync(currentUserId);
}
```

兑换失败业务异常（HTTP 映射归装配实例）：`REDEMPTION_CODE_INVALID`（无效码）/ `REDEMPTION_CODE_USED`（已兑）/ `REDEMPTION_CODE_EXPIRED`（过期）/ `REDEMPTION_TOO_MANY_ATTEMPTS`（频控）。
> ⚠️ **V0.3.0 升级注意（`GetRedemptionsAsync` 签名变更）**：`ct` 参数位次由第 2 位移至第 4 位（`GetRedemptionsAsync(userId, page?, pageSize?, ct)`）。既有**位置传 ct** 的调用将**编译失败**（`CancellationToken` 无法转 `int?`——编译期暴露，非静默变化）；改具名 `ct:` 或补 page/pageSize 即可。`page/pageSize` 传 null = 全量（向后兼容）；分页=兑换时间倒序窗口。

### 2. 创建兑换码（运营侧——单码）

```csharp
// 运营后台（管理员上下文，DomainServiceBase 门面/Controller 经 _domainUser）——返回明文 code 一次性（库中仅存 SHA256 哈希 + 脱敏值）
var command = User.Use<IRedemptionCommandService>();
string code = await command.CreateCodeAsync(
    productName: "学期课程包", targetAppId: "edu-course", validity: TimeSpan.FromDays(30));
// v0.2.0：附加核验业务信息（购买人/权益明细 JSON）→ CreateCodeAsync(payload:) 加密落库，兑换时取回明文
// ⚠️ payload 容量上限 2800 字符（超限抛 ArgumentException）——密文列 VARCHAR(4000) 保障：ASCII 2800 字符加密后 base64 约 3740 ≤ 4000
// 明文 code 仅此一次返回——分发后不留存，不得写日志

// V0.3.0（T-4）：券有效期可用绝对 UTC 瞬间（日期粒度换算 +08:00 到期日最后一刻 → UTC 归消费方；
// 与 validity 互斥——同传抛 ArgumentException）
string code2 = await command.CreateCodeAsync(
    productName: "暑期30天卡", targetAppId: "peilian", expireAtUtc: new DateTime(2026, 8, 31, 15, 59, 59, DateTimeKind.Utc));
```

### 2.1 批次管理（V0.3.0——批量发券；批次域归扩展，管理端点/CSV 呈现归消费方）

```csharp
var batches = User.Use<ICodeBatchService>();

// ① 创建批次（DRAFT）——名称/目标应用/授权时长模板/券有效期/渠道/数量/test
var batch = await batches.CreateBatchAsync(new CreateCodeBatchRequest(
    Name: "暑期30天卡-peilian", ProductName: "英语陪练", TargetAppId: "peilian",
    ValidityDays: 30, ExpireAtUtc: DateTime.UtcNow.AddDays(30),
    Channel: "official", Quantity: 100, Test: false, CreatedBy: currentUId));

// ② 生成即导出（回调主方案——明文一次性；消费方在回调内写 CSV 流/HTTP 响应）
//    回调抛异常或 ct 取消 → 整体回滚 DRAFT（已流出明文作废——SHA256 单向不可事后重导）
await batches.GenerateBatchAsync(batch.Id, async (plainCode, ct) =>
{
    await csvStream.WriteLineAsync($"{plainCode},{batch.BatchNo},official", ct);   // 明文仅此一次，禁落库/日志
}, ct);

// ③ 批次列表 + 每批统计（一次查询——expired/pending 时间派生，禁按 Status==2 计数）
var page = await batches.GetBatchesAsync(new CodeBatchFilter(Status: 2, Channel: "official"), 1, 20, ct);
foreach (var b in page.Items)
    Console.WriteLine($"{b.BatchNo} 生成 {b.GeneratedCount} 兑 {b.RedeemedCount} 待 {b.PendingCount} 过期 {b.ExpiredCount} 吊销 {b.RevokedCount}");

// ④ 明细（掩码——明文不出现在列表）/ ⑤ 吊销（整批/单张；已兑不动；批次状态联动）
var codes = await batches.GetBatchCodesAsync(batch.Id, 1, 50, status: 0, ct);
await batches.RevokeBatchAsync(batch.Id, ct);                     // 整批 REVOKED（吞没过期未翻转码）
// 单张吊销（CodeMaskedRowDto 含 Id——明细行直达；false=已兑/已吊销幂等）
bool flipped = await batches.RevokeCodeAsync(codes.Items[0].Id, ct);
```

> ⚠️ **边界（重要）**：批次管理**端点**（`/api/.../code-batches` 族，API Key + app_id 隔离 + 二次确认 + 审计）与 **CSV 呈现**（UTF-8 BOM/中文表头/Content-Disposition）归**消费方表现层**；扩展只交付 `ICodeBatchService` 领域门面（不生成 `[GenerateController]` 管理端点）。批次 `Channel`/`Test` 为软词汇列（值域/白名单校验、test 生产拒兑策略归消费方）；`hasPayload` 批次列本版未建（`/import` 单码写入走 `CreateCodeAsync(payload:)` 不受影响）。
> ⚠️ **批次管理错误码**：`BATCH_NOT_FOUND`（404 语义）/ `BATCH_NOT_EDITABLE`（400 语义——已生成重复生成/状态不允许）/ `BATCH_QUANTITY_EXCEEDED`（400 语义——超 `MaxBatchQuantity`，默认 5000）；`REDEMPTION_CODE_REVOKED`（403 语义——吊销码兑付拒绝）。
> ⚠️ **T-7 消费方编排**：兑换成功后的授权写入由消费方调 AuthCenter `IAuthGrantCommandService.RecordGrantAsync(userId, appId, "redeem", validUntil, ct)`（扩展不直写 AuthGrant）；`ValidUntil` 由消费方按 `CodeBatch.ValidityDays` 计算；覆写=last-writer-wins，并发叠加（30+30）防丢失归消费方账号维度串行化。

### 2.2 按明文读码与管理端 payload（V0.3.0——T-5/T-8 只读门面）

```csharp
var query = User.Use<IRedemptionQueryService>();

// ① 按明文读码（兑换编排 CAS 前只读预检——内部 SHA256 哈希，明文不落库）
//    返回 null = 码不存在（消费方归 REDEMPTION_CODE_INVALID 防枚举）；只读预检非兑换承诺（CAS 仍唯一裁决）
var lookup = await query.GetByCodeAsync(codeInput, ct);
// lookup.Id / TargetAppId / Status / ExpireAtUtc / BatchId / BatchTest / Channel 供编排判定
// （test 拒兑 / 目标匹配 / 吊销归类归消费方兑换编排；`*` 全产品码按请求 appId 落授权）

// ② 管理端 payload 解密（可重复只读；鉴权归装配层管理端二次鉴权；明文不落日志）
var payload = await query.GetPayloadAsync(lookup!.Id, ct);   // 无 payload/码不存在 → null（消费方映射 PAYLOAD_UNAVAILABLE）
```

> ⚠️ **频控语义**：`GetByCodeAsync`/`GetPayloadAsync` 均为只读门面，**不计兑换频控**（计数仅发生在 `RedeemAsync` 无效/失败路径）——预检拒绝的消费方须**自行计数频控**（或装配层 Web 限流兜底），防预检面被用于无成本枚举探测。

### 3. 应用目录维护（"我的应用" AppName 来源）

```csharp
// 运营侧：录入应用（AppId 对齐 AuthGrant.AppId / RedemptionCode.TargetAppId 语义）
var appService = User.Use<IAuthAppService>();
await appService.CreateAppAsync(appId: "edu-course", appName: "教育课程", icon: "https://cdn.example.com/icons/course.png");
await appService.SetEnabledAsync("edu-course", isEnabled: true);
```

> ⚠️ **录入前置**：`AuthApp` 目录未录入的应用，`我的应用`列表 `AppName` 显示为 null（不丢行——`LEFT JOIN`）；生产装配前建议先录入目录。
> ⚠️ **软删除建议**：`AuthApp.AppId` 与 `AuthGrant.AppId`/`RedemptionCode.TargetAppId` 为**字符串软引用**（无 FK 约束）——删除前需检查引用；建议 `SetEnabledAsync(false)` 软禁用而非物理删除（防 TKWFV_UserApps 丢 AppName / 兑换码 TargetAppId 指向已删应用）。
> ⚠️ **软禁用效果（V0.2.1 兑现）**：`SetEnabledAsync(false)` 后应用**不出现在"我的应用"聚合**（`GetAppsAsync` 排除——目录行保留、授权不吊销）；恢复 `SetEnabledAsync(true)` 后重新出现；目录未录入的应用（无 AuthApp 行）视同启用不排除。

## 三、表结构与视图

| 实体/视图 | 表/视图名 | 说明 |
|-----------|----------|------|
| `RedemptionCodeEntity` | `TKWF_RedemptionCode` | 兑换码一体（生成/兑换/历史同表）——`CodeHash`(SHA256 唯一)/`CodeMasked`/`ProductName`/`TargetAppId`/`Status`(0 Available/1 Redeemed/2 Expired/**3 Revoked**)/`ExpireAtUtc`/`RedeemedByUId`(**行级 FK=AuthAccount.UId**)/`RedeemedAtUtc`/`PayloadEncrypted`(v0.2.0 核验信息密文)/`BatchId`(**V0.3.0 批次软引用**——BIGINT NULL，IX 非唯一，无 FK) |
| `CodeBatchEntity` | `TKWF_CodeBatch` | **V0.3.0 批次头**——`BatchNo`(唯一展示号)/`Name`/`ProductName`/`TargetAppId`/`ValidityDays`(授权时长模板)/`ExpireAtUtc`/`Channel`(软词汇)/`Quantity`/`GeneratedCount`/`Status`(0 DRAFT/1 GENERATING/2 GENERATED/3 REVOKED；PARTIAL 派生)/`Test`/`ExportedAtUtc`/`CreatedBy` |
| `AuthAppEntity` | `TKWF_AuthApp` | 应用目录——`AppId`(唯一)/`AppName`/`Icon`/`IsEnabled` |
| `UserRedemptionHistoryView` | `TKWFV_UserRedemptionHistory`（VEntity） | 兑换历史读模型——JOIN `TKWF_RedemptionCode` + `TKWF_AuthAccount`（取身份锚 UId——AuthCenter V0.9.0 凭据白名单列）；`ExposeGraphqlQuery=false`（经门面查询） |
| `UserAppsView` | `TKWFV_UserApps`（VEntity） | 我的应用读模型——JOIN `TKWF_AuthGrant` + `TKWF_AuthAccount` + `TKWF_AuthApp`（LEFT JOIN 取 AppName；**V0.2.1 追加 `a."IsEnabled"` 投影**——软禁用排除在 DataService，NULL=目录未录入视同启用）；`ExposeGraphqlQuery=false` |

> **视图前缀注记**（P3 裁定）：`TKWFV_` 前缀为**暂用**（ADR-AuthCenter C.16 前缀批次 + 框架组核查后视情况 rename——不影响实体/ViewSql 设计）。

## 四、安全约束

| 项 | 约束 | 归属 |
|----|------|------|
| **IDOR 越权** | 门面显式 `userId` 参数 + DataService predicate 按 UserId 过滤（数据层兜底）——装配端点从 DomainUser/令牌解析，**不信任客户端传参** | 授权面 + 装配实例 |
| **兑换码明文** | 明文**不落库**（SHA256 哈希）；生成时一次性返回；展示用 `CodeMasked`；明文/含码 DTO 不入日志 | 授权面 |
| **并发双兑** | CAS 原子兑换（单语句 WHERE 谓词）——败者重查判定（含 **`Status==3` 吊销归类**——V0.3.0）| 授权面 |
| **批次/吊销并发（V0.3.0）** | 生成 CAS 抢占（`Status==0 && GeneratedCount==0`）单胜；吊销单语句条件更新（`Status==0`→`3`，禁 read-then-write 盲更）；批次状态机与码行同事务联动 | 授权面 |
| **批次明文（V0.3.0）** | 批量生成明文仅经回调一次性流出（门面不缓存/不落库/不落日志）；明细列表仅 `CodeMasked`；CSV 呈现归消费方（不得落日志/临时文件） | 授权面 + 消费方 |
| **管理端 payload（V0.3.0）** | `GetPayloadAsync` 可重复只读但**明文不落日志**；鉴权归装配层（管理端二次鉴权）；PII/儿童数据最小化（历史列表不携带） | 授权面 + 装配实例 |
| **无效码爆破** | 兑换尝试频控经框架 `IRateLimitCheck` 点检查原语（v4.10.67——`MemoryRateLimitCheck` fallback，用户维度） | 授权面 |
| **敏感视图** | 两 VEntity `ExposeGraphqlQuery=false`——查询全经门面 | 授权面 |
| **儿童数据红线** | `UserAppDto.UsageSummary` v0.1.0 恒 null（"不含学习明细"契约约束） | 授权面 |
| **身份引用** | 行级 FK 一律 `AuthAccount.UId`（P4 白名单）；`FederationAnchorOpenId` 不作引用键 | 授权面 |

## 五、与认证中心 / 用户中心划界

## 六、生产部署要求

- **跨扩展视图（DBA 手动执行）**：`SyncViewsAsync` 仅开发环境自动建视图；**生产需 DBA 手动执行 ViewSql**。依赖扩展表清单（**先建表后建视图**）：

| 视图 | 依赖基表 | 属主 |
|------|---------|------|
| `TKWFV_UserRedemptionHistory` | `TKWF_RedemptionCode` + `TKWF_AuthAccount` | 授权面 + 认证中心 |
| `TKWFV_UserApps` | `TKWF_AuthGrant` + `TKWF_AuthAccount` + `TKWF_AuthApp` | 认证中心×2 + 授权面 |

- **方言变体**：PG 用 `CREATE OR REPLACE VIEW`（开发环境自动），SQLite 用 `CREATE VIEW IF NOT EXISTS`——DBA 按部署库方言执行对应 ViewSql（见开发方案 §5.3 全文）。
- ⚠️ **视图重建（V0.2.1）**：新版本 ViewSql 含 `a."IsEnabled"` 投影（SELECT 末尾追加列——PG `CREATE OR REPLACE` 原位升级零窗口，列只增不删向后兼容）——生产 DBA **先重建 `TKWFV_UserApps` 再升级 DLL**（先升级 DLL 则新 DLL SELECT 含 IsEnabled 列而视图尚无 → 查询失败）。
- **表名快照依赖**：ViewSql 引用 `TKWF_RedemptionCode`/`TKWF_AuthApp`（本扩展）+ `TKWF_AuthGrant`/`TKWF_AuthAccount` 表名（⚠️ AuthCenter V0.9.0 身份域重构 ADR100 表名别名批次落地）——后续前缀批次若再变，视图需同步 rename（P3 已登记）。

## 七、常见问题

| 症状 | 原因 | 处置 |
|------|------|------|
| `我的应用` 显示裸 AppId（AppName 为 null） | `AuthApp` 目录未录入该应用 | `IAuthAppService.CreateAppAsync` 录入（§二.3） |
| 兑换返回 `REDEMPTION_CODE_USED` | 码已被他人/自己兑换过 | 一码一兑（CodeHash 唯一 + CAS）——码不可复用 |
| 兑换报 `REDEMPTION_TOO_MANY_ATTEMPTS` | 窗口内无效码尝试超限 | 等窗口滑过（默认 60min）或调 `AuthSurfaceOptions` 上限 |
| 视图查询报"表不存在" | AuthCenter 未启用/未建表，或生产视图未建 | 白名单同时声明 AuthCenter（§一.1）；生产 DBA 执行 ViewSql（§六） |
| 消费方仍在代码里引用已删除的 `IUserCenterQueryService`/UserCenter DTO | **UserCenter 已完整删除（2026-10-08）**——编译失败属预期 | 按适配通知迁移：DTO 改 `TKWF.Ext.AuthSurface`、兑换经 `IRedemptionQueryService`、档案经 AuthCenter（`docs/UserCenter/UserCenter-退役-消费方适配通知.md`） |
| 兑换成功但"我的应用"列表无该应用 | 扩展**不直写** AuthGrant——V0.3.0 起 redeem 源授权写入须由**消费方兑换编排**调 AuthCenter `RecordGrantAsync(userId, appId, "redeem", validUntil, ct)`（T-7，§2.1）；未编排则预期不出现 | 兑换历史恒可见（§二.1）；消费方编排写入后 `TKWFV_UserApps` 聚合可见 |
