# 授权面（口令兑换体系）立项前置裁定

> **状态**：前置裁定已定案，立项未启动（待划分新会话执行）
> **日期**：2026-10-07
> **关联**：ADR-AuthCenter-身份域数据模型与密码能力边界 · ADR-Authentication-UserCenter契约承接 · oracle3 方案审视（本会话）· N2 联盟锚点映射策略 · 主框架 `_TKWF/docs/03_扩展模块/总览和跟踪.md`
> **性质**：授权面立项前的 4 项前置裁定 + 承接契约清单——防止在分裂模型上启动授权面（固化双模型债）

---

## 一、这是什么

**授权面**（口令兑换/授权体系）是横在"认证中心 vs 用户中心"之间的**第三个领域**：承接 UserCenter 预留的 `IRedemptionHistorySource`（兑换历史）/`IUserAppsSource`（我的应用）两契约的数据属主。本会话裁定：**授权面不得在分裂模型上启动**——必须先落 4 项前置裁定，否则它会同时引用 AuthAccount（身份）与 IdentityUser（角色）固化双模型债。

**范围指针**（新会话起步上下文，详见引用文档，本文件不重复展开）：
- **功能范围来源**：`_Framework/UserCenter/README.md` §七「不包含」——授权面 = 口令兑换体系（code/redemption/grant/batch + 管理端）+ 我的应用聚合 + 授权快照候选；
- **VEntity 设计依据**：AGENTS §8「跨表查询（VEntity）」——视图归消费方/业务域扩展，`DomainReadOnlyDataServiceBase` + `IEntityReadOnlyDAC<T>`，生产需 DBA 建视图；
- **候选底座**：AuthCenter V0.8.0 `AuthGrantEntity` + `IAuthGrantQueryService`/`IAuthGrantCommandService` 双门面（README L172/L199）——授权面"我的应用"承接候选。

## 二、为什么不能现在启动（背景）

- UserCenter V0.1.0 为授权面预留两 Source 契约，但**无属主实现**（当前缺省降级空列表）；
- oracle3 裁定：若授权面在认证中心/Identity 双模型未收敛时启动，将**永久固化双账号模型债务**；
- 授权面数据属主 = 兑换/授权记录（非账号），但需引用用户身份——身份锚未定则表设计无据。

## 三、立项前必须完成的 4 项前置裁定（oracle3 + 本会话）

| # | 前置裁定 | 状态 | 执行方 |
|---|---|---|---|
| **P1** | **联邦存储 ADR**（`ADR-AuthCenter-身份域数据模型与密码能力边界` A.8：PlatformAccountMap 归一化 + FederationAnchorOpenId 锚点列）——授权面引用的身份锚/联邦 Id 形态先定 | ✅ 已落档 | 扩展组 |
| **P2** | **UserCenter 处置**（C.14：聚合层退役 / IRedemptionHistorySource+IRedemptionHistorySource FREEZE / 授权面**不实现** Source 契约、自建 VEntity）——授权面知悉"禁止实现 Source 契约" | ✅ 已落档 | 扩展组 |
| **P3** | **VEntity 跨扩展视图归属**（视图归消费方/业务域扩展，非 AuthCenter；`vm_UserCenterProfile` 类视图的属主） | ⚠️ 待定（并入表名前缀批次框架组核查）；**非授权面设计阻塞项**——授权面 VEntity 设计可先行（视图归消费方扩展，AGENTS §8 已定；前缀 `TKWFV_` 暂用，框架组核查后视情况 rename，不影响实体/ViewSql 设计） | 框架组+扩展组 |
| **P4** | **AuthAccount 列冻结清单**（ADR-AuthCenter A.2：白名单 + 准入标准）——授权面新增身份引用须在清单内 | ✅ 已落档 | 扩展组 |

**P2 已含强制条款**：授权面立项时**禁止**实现 `IRedemptionHistorySource`/`IUserAppsSource`（否则重演 UserCenter 过早聚合设计）；应自建 `vm_UserRedemptionHistory` 类 VEntity（跨扩展 JOIN AuthAccount + 授权面表）。

**FREEZE 语义（oracle6 澄清，避免"dead contract"疑问）**：`IRedemptionHistorySource`/`IUserAppsSource` 契约**保留于 UserCenter.Abstractions**（已发布包，供装配层适配器向后兼容），但**授权面（canonical 未来属主）禁止实现**——`IUserCenterQueryService.GetRedemptionsAsync/GetAppsAsync` 在授权面落地后**保持缺省降级（空列表，显式降级非静默失效）**；消费方兑换/应用查询改经授权面自有 VEntity + 查询服务（不经 UserCenter 门面）。

## 四、授权面立项时应承接的契约/接口清单

| 契约 | 属主 | 授权面动作 |
|---|---|---|
| `IRedemptionHistorySource`（UserCenter.Abstractions） | **不实现**（P2 FREEZE） | 自建 VEntity `vm_UserRedemptionHistory` 替代 |
| `IUserAppsSource`（UserCenter.Abstractions） | **不实现**（P2 FREEZE） | 自建 VEntity `vm_UserApps` 替代 |
| `AuthAccount.UId`（认证中心身份锚） | AuthCenter | **行级 FK = `AuthAccount.UId`**（P4 白名单内）；`FederationAnchorOpenId`（P1 联邦锚点列）仅授权面自身消费联邦身份时相关，**不作行级引用键**（P2 单一事实源：行级关系一律 UId） |
| `AuthGrantEntity`（AuthCenter V0.8.0 应用授权底座） | AuthCenter | 授权面"我的应用"可承接此底座（`GET {prefix}/grants` 已有端点，prefix 可配置于 `TKWF:AuthCenter:Web`）——**未来候选**，立项时评估 |
| 兑换记录表（授权面自有） | 授权面 | 自建 SG1 实体 + DataService（红线合规） |

## 五、风险与后续

- **最大风险**：授权面在 P1-P4 未全定前启动 → 固化双模型债（本裁定阻止）；
- **后续**：授权面立项时开启**新会话**（本会话不承接实现），按 AGENTS §3 流程：使用指南 → 开发方案 → Oracle 评审 → 实施 → 审核报告 → 总览跟踪更新；
- 授权面完成前，UserCenter `IRedemptionHistorySource`/`IUserAppsSource` 保持缺省降级（空列表），不受未立项阻塞。
