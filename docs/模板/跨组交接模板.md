# 跨组交接模板（转达 · AE-Kit 技能写入 · 回执闭环）

> **用途**：扩展组 → 框架组（或反向）的一次跨组请求/写入，用一个模板收口，避免"内容写了但没过门禁""改了等别人提交"两类事故。
> **硬前置（2026-11-28 起，对齐框架 `docs/AE-Kit/skills/README.md` §使用约定 5）**：**任何写入 AE-Kit（`../_TKWF/docs/AE-Kit/`）的动作，落盘后立即执行**
>
> ```powershell
> pwsh ../_TKWF/scripts/verify-skills.ps1      # 只读校验；有 ERROR 先修，修完复跑
> ```
>
> **原因**：`.agents/skills/tkwf` 是指向 AE-Kit **源码目录**的 Junction——**零暂存缓冲**，落盘即对所有 agent 生效。`1b66f594`（2026-11-28）就是未过门禁直接可达的实例（38 个 verify-skills ERROR 进主线）。
> **提交归属**：**AE-Kit 的提交由框架组执行**；扩展组只负责「写入 + 自检 + 交接清单」。不得以"改完等别人提交"规避校验。

---

## A. 跨组转达（扩展组 → 框架组）

> 落位：框架仓 `docs/03_扩展模块/转达/转达-{主题}-{请框架组YYY}.md`；**状态行必填**（🔴 活跃 / ✅ 已闭环）；闭环后按框架转达纪律：结论入正式文档 → `历史归档/README.md` 登记 → `git rm` 删正文。

```markdown
# 转达-{主题}-请框架组{裁定|适配|修复}

> **状态**：🔴 活跃（{YYYY-MM-DD} 发起）｜ **发起方**：扩展模块组 ｜ **接收方**：框架组
> **阻塞级别**：T1 阻塞我的发布 / T2 非阻塞复核 / T3 请求排期
> **关联**：{框架文档/ADR/扩展仓包或提交}

## T1【级别·动作】{标题}
| 位置 | 现状 | 请改为 | 依据 |
|---|---|---|---|
| `{文件}` | {现状} | {目标} | {证据：代码行/文档/测试} |

## T2 ...

## 回执要求
- T1：{需要什么确认 → 我方据此做什么}
- T2：{复核点}
- T3：{排期/暂不}
```

**自检清单（发出前）**
- [ ] 每条都有**证据锚点**（文件+L行/提交 hash/测试名），不写"疑似/可能"
- [ ] 区分「事实纠偏」与「新增约束」——后者单独标注，便于对方只驳回约束不驳回纠偏
- [ ] 阻塞级别明确（谁被卡住）
- [ ] 已登记框架 `总览和跟踪.md`（活跃转达一行）

## B. AE-Kit 技能写入交接（扩展组 → 框架组）

> 适用：新增/修改 `skills/**/SKILL.md`、`skills/**/references/**`、`skills/README.md`。

**B1 写入前**
- [ ] 确认 canonical 路径（**不要猜**：本仓 `docs/AE-Kit` 不存在；canonical = 框架仓 `docs/AE-Kit/skills/`）
- [ ] 读 `skills/README.md` §使用约定（自包含 / 跨技能共享文件唯一例外 / 状态诚实 / 写入纪律）

**B2 写入后（立即，不得跳过）**
- [ ] `pwsh ../_TKWF/scripts/verify-skills.ps1` → **错误 0**（警告逐条判断：占位符 `{xxx}`、>300 行、缺 CONTEXT 段、description >400 字符）
- [ ] 内容变更 → **bump `version:`**（SKILL.md front-matter）
- [ ] 部署包同步由框架组执行（`build-deployment.ps1`；未同步时 verify 会报"部署包技能过期/缺文件"）

**B3 交接清单（交框架组提交）**

| 项 | 内容 |
|---|---|
| 新增/修改文件 | {相对 `docs/AE-Kit/` 的路径列表} |
| 版本变化 | `{skill}` {旧} → {新} |
| verify-skills 结果 | 错误 0 / 警告 N（逐项：接受理由或已修） |
| 内容要点 | {一句话×N} |
| 已知遗留 | {如：实测状态"未实测（首发）"待首次真实使用回写} |

---

## C. 回执闭环（收到对方回复后）

- [ ] 逐条判定：接受 / 部分接受 / 驳回（驳回须给证据）
- [ ] 结论写入**正式文档**（本仓 `docs/变更记录.md`、包 README 版本记录；框架侧 CHANGELOG/ADR/D23）
- [ ] 契约类文件（如 `page-contract.md`）的"待定项"收敛为定论，去掉"待回执"字样
- [ ] 活跃转达按纪律归档（框架侧 `git rm` + 历史归档索引）
- [ ] 若结论改变了**已发布**的内容 → 评估版本与 tag 动作（tag 须用户同意）
