# 测试纪律——受影响面定向测试

> **裁定**: 用户 2026-10-11（不每次全量 1946+ 用例——按变更类型定向测试，全量作为发布门/关键节点）｜**状态**: 生效（AGENTS.md §构建/编译操作纪律 后测试纪律节引用本文档）
> **基线**: 42 测试项目 ~1948 用例（2026-10-11：1913 → 1946 → +2 aud = 1948）；全量分批跑（避免 MSB4166）约 30 分钟

---

## 一、为什么（背景）

全量回归成本高（42 项目 ~1948 用例，分批 ~30 分钟）且**影响面可静态判定**（依赖拓扑反向图）——每次微小变更跑全量不经济。设计三级分层：常规变更跑定向（L1），发布/关键节点跑全量（L2）。

## 二、三级分层

| 级别 | 内容 | 成本 | 触发 |
|------|------|------|------|
| **L0 编译门** | slnx 构建 0 错误（`dotnet build TKWF.Extensions.slnx`） | ~3 min | **每次变更必做**（硬前提——编译错即测试无意义） |
| **L1 受影响面定向** | 按 §三 矩阵跑相关测试项目（循环 `dotnet test {项目}` 逐个） | ~2-10 min | **每次变更收尾必做** |
| **L2 全量回归** | 42 测试项目全部（分批 B1/B2/B3，`dotnet test` 逐个 + 汇总） | ~30 min | **发布/tag 前 + 契约包变更 + 主框架 lockstep + 不定期**（非每次） |

## 三、变更类型 → 必测范围

| 变更类型 | 示例 | 必测受影响面 |
|---------|------|------------|
| **契约包变更**（`*.Abstractions` 增/改成员） | TrustCenter.Abstractions 增 `ISsoClientQueryService`/`ISsoChannel.BuildAuthorizeUrlAsync` | 契约实现方（TrustCenter）+ 编排消费方（Federation）+ 契约实现库（8 平台库）——**建议 L2**（契约影响面广） |
| **主框架 CPM/DLL 升级** | v4.10.70→4.10.71 | **编译门先筛**——编译通过后：框架转达清单指出的重点面（如 Iter-6 A1-A5 → AuthCenter/Federation）+ **L2 全量**（框架是底座，影响面不可静态穷举；零破坏实证可降级 L1 + 抽查） |
| **单扩展内部**（无契约/无框架 API） | AuthCenter 内部 bug 修复 | 该扩展测试 + 直接消费方测试（若接口行为变化） |
| **扩展门面/端点/Web 装配钩子** | FederationWebExtension 增 4 端点 | 该扩展测试（Web 冒烟 + 门面） |
| **平台库**（`Federation.{平台}`） | WeChat 通道实现 | 该库测试 + Federation 主包（编排面） |
| **文档/配置/Options 默认值** | 使用指南、`TKWF:` 节 | 编译门即可（若 Options 默认值影响行为 → 该扩展测试） |

## 四、受影响面判定方法（免人工拍脑袋）

1. **扩展间依赖**：csproj ProjectReference 反向图——改了 X → 测 X + 所有引 X 的项目（`dotnet-analyzer analyze_dependencies` 或 grep `<ProjectReference`）
2. **契约消费**：grep `using TKWF.Ext.{Xxx}.Abstractions`——改了契约 → 测所有消费方
3. **框架 API 消费**：编译错误定位 + 框架组转达清单（如 Iter-6 的 A1-A5 明确指 AuthCenter/Federation——定向指引）

## 五、工具化（CI 自动化——2026-10-17 已落地）

> **CI 落地（2026-10-17）**：`ci-publish.yml` 内置受影响面推导（`changes` job `test-targets` 输出）——tag push / PR / 分支 push 均自动按变更推导测试范围，不再人工判定：

**推导规则**（对齐 §三 矩阵）：

| 变更 | 推导结果 | CI Test 动作 |
|------|---------|-------------|
| 契约包（`_Framework/*.Abstractions/`）或 `Directory.Packages.props`（CPM） | `__ALL__` | 全量 slnx test（纪律矩阵红线——影响面不可静态穷举） |
| 单扩展（`_Framework/{Ext}/`） | 反向图（该扩展测试 + ProjectReference 引用它的测试项目，csproj grep `_Framework\{Ext}\`） | 循环 `dotnet test {项目}`（列表） |
| 空 diff（tag 指向 main 已测 commit） | 空 | 跳过 Test（main 已全量测过；发布链路编译门由 Build 保证） |
| workflow_dispatch（无 diff 基准） | `__ALL__` | 全量（fallback 安全） |
| 纯 docs/`*.md`（分支 push） | docs-only → 跳过 build-test 整体 | —（既有方案 1） |

**保留设计**：
- **Build 恒全量**（slnx 编译门——L0 硬前提，发布链路必须；成本 ~3min 本地 / CI 同量级）
- Test 列表循环用 `--no-build`（复用 Build 产物，避免重复编译）
- `dotnet test` 不支持多项目参数（MSB1008 实证）→ 列表循环逐个

**本地等价**（无 CI 时人工执行）：
- `-Changed Xxx` → 自动解析依赖反向图（csproj grep）→ 只跑受影响测试项目（L1）
- `-Full` → 全量分批（L2，B1/B2/B3 循环）
- `-BuildOnly` → 仅编译门（L0）
