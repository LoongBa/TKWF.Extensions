# 目录结构与版本管理规则

> 本文档记录 `TKWF.Extensions` 仓库的目录结构约定、版本级联规则和文档生命周期管理。
> 所有人类成员和 AI Agent 均需遵守。

---

## 一、仓库定位与边界

```
_TKWF/               主框架（TKW.Framework）：领域框架、扩展机制基座、SG、Infrastructure
_TKWF.Extensions/    本仓库：TKWF 业务扩展包（TKWF.Ext.*）+ 扩展测试 + 扩展文档
```

- 本仓库**不包含**主框架核心代码；扩展包经 `$(TKWFRoot)` ProjectReference 跨仓库引用主框架源码
- 扩展包与主框架 slnx 解耦：`TKW.Framework.slnx` 不含扩展项目，扩展在 `TKWF.Extensions.slnx`
- 扩展机制基座文档（D17/ADR37-39）属主框架文档，不在本仓库

## 二、目录结构

```

│       └── **/*.cs

│   └── Extension.{扩展名}.Tests/
├── docs/
│   ├── AGENTS.md          # Agents 路由指南（默认上下文）
│   ├── 目录结构与版本管理规则.md   # 本文档
│   ├── 扩展规划和跟踪执行.md       # 扩展路线图 + 跟踪（唯一入口）
│   ├── adr/               # 扩展 ADR（ADR-{扩展名称}-{title}.md）
│   ├── 模板/               # 开发方案/审核报告/ADR 模板

└── TKWF.Extensions.slnx   # 扩展解决方案
```

## 三、版本管理（MinVer）

采用 MinVer 风格：`V{major}.{minor}.{patch}`（git tag 前缀 `v`，如 `v4.9.79`）。

- **扩展包版本独立**：与主框架 `_TKWF` 版本独立——扩展包各打各的 tag
- tag 触发 MinVer → 版本号自动推导（`v4.9.79` → 4.9.79）
- 无 tag → `0.0.0-preview.N`

### 文档命名规则

```
{扩展名}-开发方案.md          # 如 Tagging-开发方案.md
{扩展名}-审核报告.md          # 如 Tagging-审核报告.md
ADR-{扩展名}-{title}.md      # 如 ADR-Tagging-标签提取引擎迁移.md（独立于主框架 ADR01-39 序号）
```

> **扩展 ADR 命名**：不走主框架全局序号（ADR01-39 为主框架核心专用），按扩展名独立命名 `ADR-{扩展名称}-`，避免混编号。扩展 ADR 仍需满足 ADR 三问必填（目的与目标/问题/使用场景）。

## 四、Commit / Tag 纪律

| 规则 | 说明 |
|------|------|
| **避免频繁 commit/push** | 积累一定工作量后统一提交（一次迭代 1-4 个提交） |
| **tag 前置条件** | 必须有开发方案 + 审核报告均已就绪 |
| **tag 需同意** | 必须征得同意后才能打 tag，不得擅自发布版本 |
| **提交语义完整** | 同一主题的探索性/失败尝试改动合并为单条有意义的提交 |

---

## 五、每次迭代的标准流程

1. 编写 `{扩展名}-开发方案.md` → Oracle/人工评审
2. 按方案实施（代码 + 测试）
3. 架构决策 → `docs/adr/ADR-{扩展名}-{title}.md`
4. 审核代码 → 编写 `{扩展名}-审核报告.md`
5. 更新 `docs/扩展规划和跟踪执行.md`（状态勾选）
6. 推送（不自动打 tag）→ 征求同意后打 tag

## 六、每个文档的标准元数据格式

所有正式文档（非草稿）顶部 YAML frontmatter：

```yaml
---
title: 文档标题
version: v4.9.79
last_updated: 2026-08-29
status: 活跃          # 活跃 / 已归档
extension: Tags       # 关联扩展
---
```

```markdown
| 日期 | 版本 | 变更内容 | 关联ADR |
|------|------|---------|---------|
| 2026-08-29 | v4.9.79 | 初始版本 | - |
```

## 七、草稿 → 归档流程

```
草稿/  →  讨论定稿  →  拆分到正式目录  →  原稿移入 草稿/归档/
```

- 草稿阶段：存放于 `docs/草稿/`，无版本约束
- 定稿后：内容拆分到对应目录
- ADR：**不修改**，仅状态变更（活跃 → 已废弃 → 被替代），永久保留

## 八、扩展性原则

1. **扩展独立**：每个扩展 = 独立项目 + 独立测试 + 独立文档 + 独立版本，不互相耦合（除显式依赖）
2. **主框架解耦**：扩展不进入主框架 slnx；主框架升级不影响扩展构建（除 API 破坏）
3. **编译期依赖**：扩展间依赖走 ProjectReference（编译期确定），不走运行时能力发现
4. **完整追溯**：所有文档有明确版本标记，历史永不删除
