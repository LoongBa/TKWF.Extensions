# 端点契约化与路径所有权 — 开发方案

> 版本：v1.2（2026-10-24，R2 用户裁定并入：Registry 不给 builder、分析器收窄、per-endpoint 开关三级覆盖、DMP 适配通知化）
> 范围：框架（路由/生成/中间件） + 扩展模块（门面契约） + 消费方（DMP-Lite 等内测项目，**不考虑断代兼容**）
> 前置裁定：内测项目可随时破坏性调整，本方案以「框架最优 + 扩展模块最优 + 前瞻性」为唯一判据。

---

## 1. 目的与目标

1. **端点五要素**（是否存在 / 动词 / 路径 / 是否匿名 / 请求响应形状）全部由领域契约在**编译期**声明，表现层不得声明任何一项。
2. **路径前缀**为可配置项：默认值写在领域侧，表现层只能覆盖不能新增，且组合规则单一、可启动期断言。
3. 表现层退化为装配：删除全部业务 `app.Map*`、请求 DTO、手工 DI 与 `IEntityDAC` 直接注入；**不保留任何表现层匿名特例**。

## 2. 问题

### 2.1 现象

| 位置 | 手写端点 | 说明 |
|---|---|---|
| `DMP-Lite.Platform.Web/Program.cs`（412 行） | 7 个（`/auth/login/password` 84 行、`/auth/exchange`、`/auth/refresh`、`/auth/revoke`、`/auth/public-key`、`/api/admin/wechat-bind`、`/api/admin/sso-clients`） | 业务、限流、审计、响应塑形全在表现层；直注入 `IEntityDAC<PlatformAdmin>`（数据红线）；`AddControllers/MapControllers` 死代码；`AddScoped<ISessionExchangeService, InProcessSessionExchangeService>`（DI 倒置） |
| `TKWF.Ext.AuthCenter/AuthCenterWebExtension.cs` L83–104 | 11 个（`sms/send-code`、`sms/verify`、`login/sms`、`login/external/{channelType}`、`login/ticket`、`login/password`、`refresh`、`logout`、`verify`、`grants`、`ticket/exchange`） | 同一套协议面在扩展内手写，消费方开关关掉后再自己写一遍（能力双实现） |

### 2.2 触发场景

- 需要调整前缀（反代、灰度、多租户）→ 手写端点与生成端点走两套拼接逻辑。
- 需要新增一个协议端点或一个业务端点 → 必须同时改表现层与领域层。
- 需要核对"某端点是否匿名" → 契约属性与表现层 `.AllowAnonymous()` 两处都可能声明。

### 2.3 现有方案的不足

| 不足 | 实证 |
|---|---|
| 路径双源 | `[ApiExpose(RestRoute)]` 与 `UseRest(basePath)` 可互相重复 → `/api/api/wechat-ops/*`（当前被 T22「端点未聚合」掩盖，T22 一修即全表 404） |
| 契约被违反无人发现 | `MerchantVerifyService` 文档写 `/m/verify`，实际 `/api/m/verify` |
| 匿名双声明 | 契约 `AllowAnonymous` 与表现层 `.AllowAnonymous()` 并存 |
| 错误语义散落 | `429` 无中间件映射 → 端点内 `Results.Json(..., 429)`；`401` 靠字符串前缀 `IsRateLimitedCode` 判别 |
| 协议端点不可生成 | 真实约束只是"生成 handler 无 HttpContext"，却被表述为"登录类非 REST 不适合生成"（P2-5） |

## 3. 决策

### D1 路径三段模型（所有权互不重叠）

```
生效路径 = basePath（宿主，部署期） + modulePrefix（模块，领域默认 + 配置覆盖） + RestRoute（契约，编译期）
```

| 段 | 所有者 | 声明位置 | 可变性 | 典型值 |
|---|---|---|---|---|
| `basePath` | 宿主/部署 | `UseApiService(o => o.UseRest(cfg))`，键 `TKWF:Api:RestBasePath`，默认 `/api` | 部署期 | `/api` |
| `modulePrefix` | 模块（扩展/领域） | Domain Options 属性（如 `AuthCenterOptions.RoutePrefix`），默认值写在类上 | 配置覆盖 | `/auth`（AuthCenter）、`/wechat-ops`（WeChatOperations）、空（业务域） |
| `RestRoute` | 契约方法 | `[ApiExpose(RestRoute = "...")]` | 改代码=改契约 | `/login/password`、`/channels/{id}/menu` |

- **只允许简单拼接，不允许互斥回落/叠加二义**。三段各自只写自己的段，任何一段不得包含另一段。
- 守卫（启动期，fail-fast，非 404）：解析后路径若出现相邻重复段（`/api/api/`、`/auth/auth/`）或某段以另一段开头 → 抛 `InvalidOperationException`，报出「模块 / 契约 / 三段值」。
- 配置优先级：`TKWF:Api:Modules:{ModuleName}:Prefix`（宿主覆盖） > Domain Options 默认值。

**为什么必须三段（不可折叠）**：`modulePrefix` 是消费方**唯一可在部署期按模块覆盖、且不需重编译**的旋钮。折进 `RestRoute` → 扩展身份散落进 N 个契约属性，单模块改挂载点等于逐个改契约；折进 `basePath` → 失去按模块粒度（改一个动全部）。

**为什么前缀粒度取模块级而非门面级**：门面级 `[GenerateController(RoutePrefix = "...")]` 有两个结构性缺陷——① 前缀是编译期属性，消费方做不到零重编译改挂载；② 同扩展多门面共享前缀（AuthCenter 的 `ISmsLoginService`/`IPasswordLoginService`/`IExternalIdpLoginService` 同属 `/auth`）必须逐门面重复声明 → 必然漂移。模块级只声明一次。契约方法**不感知**自己的挂载前缀（那是部署/模块关注点），可读性让位于关注点分离。

### D2 匿名唯一来源 = 契约属性（不给 builder，能力移除优先）

- 唯一声明点：`[ApiExpose(AllowAnonymous = true)]`（编译期 → SG2 生成 `.AllowAnonymous()`）。
- **表现层禁止 `.AllowAnonymous()`**，删除 ADR108 中"手写协议端点可在表现层匿名"的豁免文本。
- **主守卫 = 能力移除（类型系统，非分析器）**：扩展/领域侧拿不到 `IEndpointRouteBuilder`——`IWebExtension.ConfigureEndpoints(IEndpointRouteBuilder)` **直接替换**为 `DeclareEndpoints(IExtensionEndpointRegistry)`（**不留 Obsolete 兼容层**，内测项目无包袱）：

  ```csharp
  // 唯一可用的两个方法（不给 builder，连字符串路径都不出现）
  void DeclareEndpoints(IExtensionEndpointRegistry registry)
  {
      registry.MapGenerated<IPasswordLoginService>();
      registry.MapInfrastructure(EndpointKind.SignalRHub<NotificationHub>());
  }
  ```

  - `MapGenerated<TFacade>()`：挂载 SG2 生成的该门面全部 `[ApiExpose]` 端点（内部调 F1 生成的 `Map{Facade}Endpoints` 助手）。
  - `MapInfrastructure(EndpointKind)`：仅 D3 五类非 REST 例外可走，kind 枚举写死（**不留 `Custom` 逃生口**，遇到新需求再增枚举，见 D3）。
  - 效果：扩展与表现层**无法**调用 `.AllowAnonymous()`（拿不到 `IEndpointConventionBuilder`），也**无法**书写任何路径片段（`modulePrefix` 只存在于 Options）——比分析器更强的构造性保证。
- **残余守卫（分析器，收窄）**：`Program.cs` 等宿主 top-level 代码拿得到 `app`，类型系统管不到 → `TKWF_SG_WEB001` 保留但缩为"非 `.g.cs` 源码中**注册端点**的调用 → Error"（禁 `Map{Verb}`/`MapMethods`/`MapHealthChecks`/`MapHub`/`MapControllers`/`MapRazorPages`/`MapFallback*`/`MapSwagger`；**放行 `MapGroup`**——纯分组不注册端点）。`TKWF_SG_WEB002`（`.AllowAnonymous()`）降级为**可选兜底**（registry 落地后扩展侧已不可达）。宿主自有基础设施（Swagger/StaticAssets/HealthCheck）经 **`[assembly: TKWFHostEndpoints(TKWFHostEndpointKind.Swagger | StaticAssets)]` 编译期白名单**豁免——**不做运行时（appsettings）白名单**（等于把匿名开关交回表现层）。
- **为什么不做启动期"匿名不变式断言"**：SG2 从同一 `[ApiExpose(AllowAnonymous)]` 同时产出元数据，两者同源 → 「元数据 ≡ 声明」是生成器自证，永真；而"改前缀改变匿名性"在结构上不可能（前缀只管 mount，不明 auth）。启动期断言无法捕获真实风险（人在手写端点上加 `.AllowAnonymous()`），故降级为可选的生成器自检（单测覆盖），不作为守卫。用户诉求「改前缀后仍自动允许匿名」由构造保证：匿名元数据不参与路径解析。

### D3 协议端点（JSON POST/GET）一律生成；契约模型边界显式枚举

- `login/*`、`refresh`、`logout`、`verify`、`grants`、`ticket/exchange`、`sms/*` 全部转 `[GenerateController]` + `[ApiExpose]`，删除 `AuthCenterWebExtension.ConfigureEndpoints` 的 11 个 `Map*`。
- **五要素契约模型仅适用于 REST 端点**。以下**不在** `[ApiExpose]` 契约内，各自有所有权规则（不得援引本方案要求其"契约化"）：

| 例外 | 归属 | 说明 |
|---|---|---|
| GraphQL | `[DomainGenerateCode(ExposeGraphqlQuery = true)]` + 生成 schema | 无 REST 动词/路径概念 |
| SignalR Hub | Hub 类 `[Authorize]` + `registry.MapInfrastructure(EndpointKind.SignalRHub<T>)` | 管道路由，非请求-响应语义 |
| 页面贡献（`IPageContributor`） | Razor/Blazor `@page` + 组件级授权（ADR106） | PAGE 合成令牌，非 REST |
| 健康检查 | `IWebExtension`（`HealthCheckWebExtension`） | 基础设施端点，无领域契约 |
| Swagger UI 挂载 | 宿主 | 仅 UI 路由宿主所有；文档内容由契约派生 |

- P2-5 豁免收窄为**无 Content-Length 的真流式**（SSE / WebSocket 升级 / chunked 流式上传）——物理上无法由 `MapPost/MapGet` 表达者。**带 Content-Length 的 `IFormFile` 多部分是参数，可以生成**，不在豁免内。
- 框架自带 `AuthEndpoints.LoginAsync`（`LoginAsUserAsync` 便捷通道）保留，但**不得作为协议端点的范式**（其结果对象返回是查询范式，不是命令范式）。

### D3b 端点存在性开关：集中配置为主，允许分级覆盖（用户裁定 R2-3）

「端点是否存在」与「是否匿名」分开对待：匿名永不可覆盖（D2）；**存在性**允许三级，集中配置为主、逐级特例：

| 级 | 位置 | 能力 | 示例 |
|---|---|---|---|
| ① 声明式（设计时规则） | `[ApiExpose]` / 门面契约 | 端点的**默认存在性**（存在、形状、匿名在编译期定死） | `[ApiExpose(RestRoute="/login/password", RestMethod="POST", AllowAnonymous=true)]` |
| ② 扩展初始化器（领域特例） | `ExtensionInitializer.ConfigureServices` | 按领域/环境**程序化覆盖**存在性（如开发环境临时开 `sms/verify`） | `options.SmsVerifyEndpointEnabled = true;` |
| ③ 表现层配置（暴露面） | 宿主 `appsettings` `TKWF:Api:Modules:{Module}:Endpoints` | **仅限设计时已显式声明为可配的开关**覆盖；**不允许新增开关、不允许改匿名/路径/动词/形状**（设计时规则不可破坏） | `"TKWF:AuthCenter:Web": { "PasswordLoginEndpointEnabled": false }` |

- **授权模型**：设计时（声明式）把"哪些开关允许表现层配置"定死（即三级开关清单 = 契约一部分）；表现层只能在清单内取子集，不能发明新开关。实现：`[ApiExpose(Configurable = true)]` 或门面级 `[EndpointConfigurable(nameof(...))]`——**未标注 = 表现层不可见**（配置了也不读，或读时报错）。
- **判据（用户裁定）**："合适的情况，允许表现层根据配置覆盖（设计时允许的开关），但不允许破坏设计时的规则"——即三级 < 二级 < 一级，覆盖只许"关小/换实现"，不许"改语义"。
- **AuthCenter 11 个 per-endpoint 开关归位**：`AuthCenterEndpointOptions.{Xxx}EndpointEnabled`（现 11 个）→ 语义为**三级开关清单**（已标注可配者进 `TKWF:AuthCenter:Web`，未标注者仅扩展初始化器可程序化覆盖）；表列映射到 D3b 表。

### D4 错误语义：命令用类型化异常，查询用结果对象

| 端点性质 | 失败表达 | 出口 |
|---|---|---|
| 命令/协议（login、refresh、logout、exchange、revoke） | 抛类型化异常 | `WebExceptionMiddleware` 统一映射 RFC 9457 ProblemDetails |
| 查询（`/m/verify`、内省、存在性判断） | 结果对象（`Verified=false` 是正常结果） | 直接返回 |

新增/补齐异常类型（框架），**统一派生 `DomainException`**（复用其 errorCode 管道，中间件按类型分派状态码，避免 N 个 catch 分支）：

| 类型 | 状态码 | errorCode | 附加 |
|---|---|---|---|
| `RateLimitedException` | 429 | `RATE_LIMITED` | `RetryAfterSeconds`（**整数秒**）→ 响应头 `Retry-After` |
| `InvalidCredentialsException` | 401 | `INVALID_CREDENTIALS` | 与 `AuthRequired`（无/坏令牌）严格区分 |
| `ServiceNotConfiguredException` | 503 | `SERVICE_NOT_CONFIGURED` | 替换现有 `InvalidOperationException` 字符串判定 |
| `UpstreamServiceException` | 502 | `UPSTREAM_SERVICE_ERROR` | `UpstreamChannel`（哪个 IdP）；可选 `RetryAfterSeconds`；`IsTimeout` 标记（504 折叠于此，不另立类型） |

- **`Retry-After` 一律整数秒**（不用 HTTP-date）：限流窗口天然产出"剩余秒数"，无时钟偏移问题，客户端解析可靠；HTTP-date 属 CDN/源站协同场景，此处过度设计。
- **502 的必要性**：联邦登录 `/login/external/{channelType}` 调微信/QQ/支付宝，IdP 不可达或返回错误 → 既非"凭据无效"（用户凭据可能没问题）也非"未配置"（配了但在故障），现状落到默认 500 把上游故障泄漏为自身内部错误。

### D5 审计与令牌上下文经 `IAmbientContext`

- 键规范（常量类集中）：`ClientIp`（既有）、`UserAgent`（新增内置 `UserAgentContextExtractor`）、`AuthCenter.TokenValidationResult`（`JwtAuthenticationMiddleware` 认证成功后写入）。
- 领域服务读 `User.GetService<IAmbientContext>()`；**IP/UA 永不作为方法参数**（生成端点的参数来自 route/query/body = 可伪造）。
- 机制已验证可行：`ScopedHttpContextAmbientContext` 是惰性委托，实时读 `HttpContext.Items[typeof(IAmbientContext)]` 实例，中间件后续写入立即可见 → `TokenValidationResult` 无需框架新机制，只需扩展写入。

### D6 消费方配套变更：适配通知×2（不跨仓操作）

- **交付物 = 适配通知**（分**领域层**、**表现层**两份，标注接收方 Agent/开发组，各自可独立执行）——本仓库与框架仓库**不触碰 DMP-Lite 代码**。
- 适配通知（领域层，接收 = DMP 领域 Agent/组）：
  - DMP 登录走 **SecurePassword 协议**（客户端 PBKDF2 → `clientHash` + `salt`），直接复用 `IPasswordLoginService.LoginAsync`；删除自带明文校验实现。
  - **数据迁移约束（实证）**：`AuthFactor.SecretHash` 存的是客户端 `clientHash` 本身（组装格式 `salt.iterations.b64hash`，服务端 `FixedTimeEquals` 比对），**无法从既有服务端 `PasswordHasher` 哈希反推** → 存量平台管理员口令必须重设（一次性设置令牌 / 重置流程），不能自动迁移。
  - `InProcessSessionExchangeService` 迁 Domain（DI 倒置纠正，`ISessionExchangeService` 实现落领域层）。
- 适配通知（表现层，接收 = DMP Web Agent/组）：
  - 删 7 端点 / 5 DTO / `AuthJwkHelper` / `AddControllers`/`MapControllers`；`/auth/exchange` 去匿名（Bearer 由框架恢复）；`/auth/revoke` 禁止客户端指定 jti，改读 `IAmbientContext`；`admin/*` 转生成端点；开分析器门禁。
  - 能力双实现归零：DMP 不再保留任何协议端点实现。
- 通知内**附对账清单**：旧→新端点 diff（method/path/anonymous）+ 期望行为变化（登录协议、revoke 语义），执行组照单核销。

## 4. 实施

### 4.1 批次与门禁

| 批 | 内容 | 门禁 |
|---|---|---|
| **B0** | 契约合规化：全部 `[ApiExpose(RestRoute)]` 去绝对前缀（26 处，已完成）；前缀段拆出并写入模块 Options 默认值；**路径漂移对账**：枚举 11 个旧生效路径（`{RoutePrefix}/{endpoint}`）vs 新三段路径，逐条 diff | 构建 0 错误 + 路径解析单测 + **漂移 diff 为空**（非空即 B0 修，不得留到 B5 当"前端变更"） |

| **B3b（扩展，结构）** | AuthCenter 11 端点 → `[GenerateController]` + `[ApiExpose]` + **`DeclareEndpoints(registry)`**（删除手写 `ConfigureEndpoints` 与 catch 重映射）；`JwtAuthenticationMiddleware` 写 `TokenValidationResult` 到 ambient；审计补 IP/UA；**per-endpoint 开关归位到 D3b 三级清单** | AuthCenter 全量测试 + 生成端点清单对账（旧→新 path/method/anonymous 全等）+ 开关三级覆盖用例（声明式/初始化器/表现层配置各一） |

| **B5（消费方）** | **产出适配通知×2（领域层/表现层，附对账清单）**，交 DMP Agent/开发组执行；本仓不碰 DMP 代码 | 通知评审（内容完整、旧→新 diff 全可解释、无模棱两可项） |

## 9. R3 机制裁定与实证结论（2026-10-24）

### 9.1 Oracle 对 F1 机制的裁定（Q1–Q4）

**Q1 生成物形态与解析方式 —— 采用「单程序集级注册表 + 汇编级属性定位」**

- 每扩展程序集生成**一个** `internal static class GeneratedEndpointRegistrations`：

  ```csharp
  public static void Map<TUserInfo>(Type facadeType, RouteGroupBuilder group,
      IDomainUserAccessor<TUserInfo> accessor)
      where TUserInfo : class, IUserInfo, new()
  {
      if (facadeType == typeof(IChannelConfigService))
          ChannelConfigServiceEndpointRegistration.Map<TUserInfo>(group, accessor);
      // … 每门面一分支，顺序 = 生成器枚举顺序（确定性） …
      else
          throw new InvalidOperationException($"无生成端点注册：{facadeType.FullName}");
  }
  ```

- 每门面另有 `internal static class {ShortName}EndpointRegistration`（方法体形状同 SG2 `GenerateRestEndpointSource`）。
- **定位**：生成器同时发射 `[assembly: ExtensionEndpointRegistrations(typeof(GeneratedEndpointRegistrations))]`；registry 经 `typeof(TFacade).Assembly.GetCustomAttribute<…>()` 取注册表类型，**缺属性即 fail-closed 抛**（不静默跳过）。
- **为何不用「约定名反射」/「扫接口实现」**：约定名是字符串脆耦合；扫类型 O(types) 且 trim 不友好。汇编属性能把范围收敛到「TFacade 所在程序集」这一有界集合，且缺失即失败。
- **已知代价**：`TUserInfo` 只有消费方编译期才知道 → 必须一次 `MakeGenericMethod`；**限于启动期、每门面一次、结果缓存**，绝不落在请求路径上。

**Q1 签名修订（2026-10-24，B4.3 实施期实证后）——去掉映射期 `accessor` 参数**

- **原签名**：`Map<TUserInfo>(Type facadeType, RouteGroupBuilder group, IDomainUserAccessor<TUserInfo> accessor)`。
- **实证冲突**：`WebDomainUserAccessor<TUserInfo>` 是 **Scoped**（`WebAppBuilder` L115/L212 `TryAddScoped`），其 `DomainUser` 经 `IHttpContextAccessor`（Singleton + AsyncLocal）**每次 getter 动态解析**（G13 修复注释明确说明"即使被 Singleton 捕获也能取到当前请求 user"）。因此映射期传入的 accessor **虽是安全的长寿 Scoped 捕获，但在请求链路上从不被使用**——它只会让装配期提前解析 Scoped 服务，且与框架自己的 minimal API 写法分叉。
- **框架既有形态（唯一先例）**：`_Domain.ApiService\MinimalApi\Endpoints\AuthEndpoints.cs` L20-30 —— 映射期只取 `RouteGroupBuilder group`，**handler 参数**注入 `IDomainUserAccessor<TUserInfo> accessor`（按请求解析）。
- **裁定**：采用框架既有形态。签名改为

  ```csharp
  public static void Map<TUserInfo>(Type facadeType, RouteGroupBuilder group)
      where TUserInfo : class, IUserInfo, new();
  ```

  每门面 `{ShortName}EndpointRegistration.Map<TUserInfo>(RouteGroupBuilder group)`；handler 参数末尾注入 `IDomainUserAccessor<TUserInfo> accessor`（方法含 `CancellationToken` 时再追加 `ct`）。
- **不变项**：Q1 其余结论（单程序集级注册表、汇编级属性定位、缺属性 fail-closed、显式 switch、`MakeGenericMethod` 仅启动期）与 Q2/Q3/Q4 全部维持。
- **收益**：装配期零 Scoped 解析、无长寿捕获、与 `AuthEndpoints` 同形；B1 的 `MapGenerated<T>` 也不再需要"先解析 accessor 才能装配"的时序假设。

**Q2 basePath / modulePrefix 来源 —— 否决 `TModule` marker**

- **否决 `MapGenerated<TFacade, TModule>()`**：它要求扩展在调用点传参，违背用户裁定「扩展不传 basePath/modulePrefix」；marker 类型只是把字符串换成类型，语义未变。
- **basePath**：框架配置 `TKWF:Api:RestBasePath`（默认 `/api`），registry 从 `IConfiguration` 读——全局唯一，不做 per-extension 覆盖。
- **modulePrefix**：扩展程序集上 `[assembly: ExtensionModule(Key = "WeChatOperations", DefaultPrefix = "wechat-ops")]`（**作者声明一次 = 配置，不是注册**）；registry 取属性默认值，再查 `TKWF:Api:Modules:{Key}:Prefix` 作表现层覆盖。
- **授权/路径/动词/形状不可覆盖**：生成器在编译期按 `[ApiExpose]` 定稿（`.RequireAuthorization()` / `.AllowAnonymous()` 烘焙进生成物），registry API 形状上不提供任何注入口。

**Q3 `accessor.DomainUser.Use<IFacade>()` 的正确性**

- **正确**，前提：扩展门面实现继承**非泛型** `DomainServiceBase`（`User` 可由 AOP 帧写入消费方 `IDomainUser`）。扩展已按 ADR90 门面化，满足。
- **无时序陷阱**：装配期只构造 handler 委托；`accessor` 与门面解析发生在**请求期请求作用域**内。
- **⚠️ 新增硬约束（R3 发现）**：门面**必须 Scoped**。若注册为 Singleton，`Use<T>()` 每请求覆写同一实例的 `User` → 跨请求串号。B1 须补「扩展门面注册生命周期 = Scoped」断言或单测。

**Q4 双重注册 —— SG2 侧结构性早退**

- 在 `ApiServiceGenerator.TryResolveAndAdd`（L694-717）最前加：

  ```csharp
  if (iface.ContainingAssembly.GetCustomAttribute<ExtensionEndpointRegistrationsAttribute>() is not null) continue;
  ```

- 互斥由构造保证：**有属性 → 扩展自注册，SG2 让路；无属性 → 仍被既有 `IAopContract` 判据拦住（现状）**。任一侧放宽都不会双挂。
- **不要依赖「重复路由抛错」**：ASP.NET Core 对同模板重复注册**不保证抛**，可能静默歧义匹配。

**附带风险（R3 指出）**：SG1b 不能引用 `TKWF.Domain.ApiService.SG`，故须**自含** REST 发射逻辑 → 与 SG2 存在漂移风险。对策：把 `GetHttpVerb` / `GetRestRoute` / `HttpVerbNormalization`（`ApiServiceGenerator.Resolvers.cs` L2594-2658）上移 `TKWF.CodeGeneration.Abstractions` 作唯一事实源，两侧共用。

### 9.2 F12 核查结论（实证，非推断）

- SG2 handler 生成形状（`ApiServiceGenerator.Resolvers.cs` L2829-2900）：
  `private static async Task<{method.ReturnType}> {ResolverName}<TUserInfo>({参数…}, IDomainUserAccessor<TUserInfo> accessor)` + `return await svc.{Method}({args});`
- `_Domain.SG\ApiService.SG` 全目录 `IResult|Results.|TypedResults` **零命中** → 无 `IResult` 特化分支。
- **门面返回 `Task<IResult>` 运行期可用**（ASP.NET 会执行 `IResult`），但：① `.Produces<IResult>(200)` 生成错误 OpenAPI 元数据；② `IResult` 位于 `Microsoft.AspNetCore.Http`，进领域契约破坏分层。→ **不采用**。
- **采用形态**：命令返回 DTO（`.Produces<TDto>(200)`），失败一律 typed exception 由 `WebExceptionMiddleware` 映射。
- **已知让步（须在 B6 文档登记）**：
  - `204 NoContent` → 生成端点落 **`200 + 空体`**（`SendSmsCode` / `Logout`）。
  - `HandleVerify` / `HandleGrants` 的 401 由生成端点的 `.RequireAuthorization()` **前置**返回（比手写函数内判定更严格且更正确）。
- **结论**：AuthCenter 11 端点**全部可生成**。

**⚠️ 顺带修复的存量缺陷（P0，非本方案引入）**

`WebExceptionMiddleware` 用 source-gen 上下文 `JsonContext`（仅声明 `ProblemDetails`）序列化
`[JsonExtensionData] Dictionary<string, object?>`，而 `messageArgs` 是 `object[]` → 多态序列化无元数据 →

**新公开面（Oracle 交付 API 草图，待 B1-c 扩展侧剩余部分实施时落码）**

```csharp
public interface IWebExtension
{
    // ...既有成员不变...
    void DeclareEndpoints(IExtensionEndpointRegistry registry) { }            // F13 通道（门面/基础设施）——不变
    void DeclareProtocolEndpoints(IProtocolEndpointBuilder builder) { }       // 新增：协议适配专用（默认空 = 99% 扩展忽略）
}

public interface IProtocolEndpointBuilder
{
    IProtocolRoute Map(string template, string method, bool allowAnonymous = true);
    IProtocolRoute Map(string template, params string[] methods);             // GET+POST 同路径
}
public interface IProtocolRoute
{
    IProtocolRoute RequireAuthorization();
    IProtocolRoute WithHandler(RequestDelegate handler);                      // 扩展自持厚逻辑，框架不约束 handler 内部
}

public interface IExtensionEndpointRegistry
{
    void MapGenerated<TFacade>() where TFacade : class;                        // 不变
    void MapInfrastructure(EndpointKind kind);                                 // 不变
    void MapHub<THub>(string path, bool requireAuthorization = true) where THub : class;  // 新增
}
```

**关键裁定点**

1. **生成模型不兼容确认**：GET/POST 同路径、302 Redirect、raw body 流读、text/xml 回复——均无法用 [ApiExpose] 薄门面表达；Federation 强行走 MapGenerated 是**类别错误**（category error）。
2. **闭枚举语义重释**：`EndpointKind` 闭枚举 + 无 Custom **仅适用于基础设施 kind**（HealthCheck/未来框架实现者）；协议适配是**独立声明面**（扩展自持 handler + 框架拥有挂载），不属于 infra kind——F13 原裁定的疏漏在此。
3. **SignalR 用 `MapHub<THub>`**：不进枚举（枚举无类型参数承载不了 hub 类型）；不进协议面（hub 非 handler 委托，是类型 + 框架管理连接生命周期）；独立注册表方法最干净。
4. **R2-2 完好**：`DeclareProtocolEndpoints` 带默认空实现 = **附加非破坏**（原 ConfigureEndpoints→DeclareEndpoints 硬删保留）；"不给 builder"门禁**语义保持**——扩展只见窄接口（Map/RequireAuthorization/WithHandler），永不见 `IEndpointRouteBuilder`/`RouteGroupBuilder`；路由模板是数据（扩展拥有）、前缀拼接是逻辑（框架拥有）。
5. **孤儿方法清理（前提）**：三个扩展（Federation/AuthCenter/NotificationsHub）现存 `ConfigureEndpoints(IEndpointRouteBuilder, DomainWebOptions)` 是**非接口成员的死方法**（F13 下从不被调用）——迁移时必须删除。

### 9.15 AuthCenter 迁移设计注记（2026-10-24——非机械迁移，实施前需定案）

**AuthCenter 11 端点中 9 个可机械走 MapGenerated，2 个有真实设计难点**（`/verify` + `/logout`）——§9.12 预判的 2 新门面方法（RevokeCurrentSessionAsync/GetCurrentTokenInfoAsync）命中，但**实现方式需先行裁定**。

**问题根因**：`HandleVerify`/`HandleLogout` 依赖中间件写入的 `HttpContext.Items[TokenValidationResult]`（`JwtAuthenticationMiddleware` 验签产物——jti/UserId/AuthType/AuthLevel/Exp），而 B4.3 生成端点 handler 只接收（路由/body/query 参数 + accessor + ct），无 HttpContext.Items 访问。门面方法在 AOP 帧内经 `User.Use<IFacade>()` 解析，同样没有 HttpContext。

**候选方案（需 Oracle 或用户裁定）**

| 方案 | 机制 | 优劣 |
|---|---|---|
| A. ambient 上下文（框架 Web 层） | `JwtAuthenticationMiddleware` 验签后把 TokenValidationResult 写入 Web 层 ambient（AsyncLocal/按请求上下文），门面方法经新框架读口取"当前会话令牌信息" | 与 B1 计划中"认证中间件写哨兵 → 生成端点读 IAmbientContext 的集成测试"契合；需框架新增 ambient 设施 + 扩展消费 |
| B. handler 注入 HttpContext | B4.3 生成器扩展：方法参数含 `HttpContext` 时 handler 注入（minimal API 原生支持），Web 层把 Items 值转为方法参 | 偏离 B4.3 已定稿 handler 形状；扩展仍触摸 HttpContext（R2-3 精神弱化——虽然不是 builder） |
| C. 门面入参携带 | `/verify` 的生成端点接收查询/body 参数（token 字符串），门面内部自行验签解析 | 重复验签（中间件刚验过）；GET /verify 带 token 语义改变；不推荐 |
| D. 保留 Web 层拼装 | `GetCurrentTokenInfoAsync` 返回稳定 DTO 字段定义，Web 层 handler 内读 Items → 新门面方法因为是额外路径…… | 与"表现层零编排"原则冲突 |

**推荐**：A（ambient 上下文）——与 B1 计划内 ambient 前置集成测试是一件事的两半，实施顺序：框架 Web 层加"当前验签产物"读口 → AuthCenter 2 新门面方法消费 → 生成端点走 MapGenerated。此裁定（含 ambient 设施 API 形态）升 Oracle。

**AuthCenter 迁移范围（裁定后）**：9 薄端点 → `[GenerateController]`+`[ApiExpose]` 标注现有门面；2 特殊端点 → 新门面方法；删 `AuthCenterWebExtension.ConfigureEndpoints` 孤儿方法 + 11 handler + Web DTO（TokenResponse/ErrorResponse/请求 DTO 迁门面契约或保留 Web DTO）；`RoutePrefix` 归框架 Module 前缀（`[assembly: ExtensionModule(Key="AuthCenter", DefaultPrefix="api/auth")]`——注意 DefaultPrefix 含 `/api` 段与 basePath 的关系需在裁定中确认拼接语义）。测试 181 用例适配（`/api/auth/*` 路径断言核对 Module 前缀拼接结果）。
