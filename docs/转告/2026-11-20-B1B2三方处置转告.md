# 三方转告单（B1/B2 反馈核实结论，2026-11-20）

> 来源：`EduPlatform/docs/feedback` B1/B2 反馈行 + Oracle7 核实裁定。
> 用法：可分拆转发给对应组；本仓库仅保留转告记录，不代改他仓。

## 一、给框架组（B2 契约文档化）

**主题：密码登录钩子 fail-closed 契约化（非中间件守卫）**

**证据**：`DomainUserHelperBase.cs:350-353` 默认 `OnLoginByPasswordAsync` 抛 `NotSupportedException`（框架默认已 fail-closed）；fail-open 源于消费方以"恒成功、不校验凭据"覆写钩子。框架 `/api/auth/login` 默认匿名属实（`HttpAuthenticationOptions.cs:33-58`），但框架无法观测 helper 是否真校验凭据——运行时角色守卫不可行（过宽会阻断合法管理员登录）。

**转告请求**（三处同源）：
1. `DomainUserHelperBase` 钩子族（`OnLoginByPasswordAsync` 等）XML doc 写明契约："实现必须先校验凭据；未配置真实凭据源时保持默认抛出（不覆写即 fail-closed）；禁止返回未验证 TUserInfo（无论有无角色）。"
2. G17B（使用扩展模块-使用指南）补"消费方登录钩子 fail-closed 约定"小节。
3. xCodeGen `init/UserHelper.cs:27` 模板携带同样契约注释，使生成骨架自带守卫语义。

**明确不做**：不引入"匿名端点默认不授予特权角色"的框架级中间件守卫——登录端点按设计匿名、按设计在凭据校验成功后授予角色，一刀切会破坏合法登录流或迫使授权转入更不透明旁路。

## 二、给消费方组（B1 落地 + B2 机械断言）

**主题：B1 两端分化 + B2 残余风险决议**

1. **AuthCenter 侧**：扩展组将既有 `AuthCenter.Abstractions` 增补登录门面（V0.3.0）；消费方须先决议 Domain 边界口径——当前 `ExtensionBoundaryTests.cs:13-23` 断言 Domain **一切** `TKWF.Ext.*` 引用为空（含 `*.Abstractions`，比注释宣称的"实现程序集"更严）。两条合法路径：(a) 修订测试/ADR03 允许契约包入 Domain；(b) 维持 Domain 全净 + Web/装配层消费 + 本地端口。决议前不要删 AuthRelayRegistry 等 stand-in。另：EduPlatformUserHelper.cs:33 的明文凭据校验 TODO 不在 v0.3.0 纯迁移范围，由后续"凭据校验专用契约"专项承接（须独立安全评审：频控/尝试记录/防枚举），请勿等待 v0.3.0 关闭该 TODO。
2. **AuthSurface 侧**：**不创建 AuthSurface.Abstractions**——A6（G17A §7.8）明确"只被终端应用消费"属自包含型，建包违反裁定且触发禁止的第三形态。按已同步的 ADR03:42 单包引用即可；CodeBatchRegistry/RedeemCodeRegistry 重组为"Domain 本地端口 + 装配层适配器委托 `User.Use<ICodeBatchService>()`"，或正名为长期端口。
3. **B2 残余风险须决议**：`EduPlatformUserHelper.cs:33-39` 当前任意密码可为已知 userName 换得"已认证但无角色"会话——P1-1 消除的是提权、不是认证绕过（冒充面仍在）。建议评估 stand-in 期直接不覆写钩子（回归框架默认 fail-closed 抛出），或 ADR 明示接受该残余面并记录影响。BR-1-11-01（AuthLoginServiceTests.cs:113-135）断言保持绿。
4. **两处细节随接入核对**：`RedeemVoucherService.cs:66` 期望兑换记录含 BatchNo（核对 AuthSurface `IRedemptionQueryService` DTO 是否提供）；`RedeemCodeRegistry.cs:31` 注释门面名 `IRedemptionService` 不存在（实际 `IRedemptionCommandService`/`IRedemptionQueryService`）。
