# 转告框架组（非阻塞）：跨程序集门面自注册能力缺口登记

> 状态：**登记备查，非阻塞**。本仓 AuthCenter v0.3.0 契约包提取已按 Oracle5 裁定改走"契约基接口模式"（框架零改动）自闭环；本转告只登记机制缺口，供框架组决定是否立项能力增强。

## 现象（两次独立撞墙）

1. **WeChatOperations v0.9.0（2026-11-05）**：`code-reviewer` BLOCKER #1——`WeChatChannelsWebExtension.MapGenerated<IChannelConfigService>()` 按门面程序集（Abstractions）定位 `[assembly: ExtensionEndpointRegistrations]`/`[assembly: ExtensionModule]`（两特性声于主包，契约接口在契约包）→ 装配即 fail-closed。当时以"非 Web 形态"（去 WebExtension、消费方 SG2 按 ADR47 生成控制器）绕开。
2. **AuthCenter v0.3.0 契约包提取（2026-11-20 实施首轮）**：将带 `[ApiExpose]` 的门面整体迁入 `AuthCenter.Abstractions` 后，构建 0 错误，但端点宿主启动即抛：
   `扩展程序集 [TKWF.Ext.AuthCenter.Abstractions] 未声明 [ExtensionEndpointRegistrations] 程序集特性，无法为门面 [TKWF.Ext.AuthCenter.IPasswordLoginService] 映射端点`。

## 机制分析（框架源码定位）

- **注册表查找**：`_Domain.Infrastructure/Web/Extensions/DefaultExtensionEndpointRegistry.cs:167` `var assembly = facadeType.Assembly;` → `:238-243` ResolveMap 在该程序集找 SG1b 发射的 `[ExtensionEndpointRegistrations]`（缺失即 fail-closed）。该特性由含 `[GenerateController]` 实现类的编译产出（`ControllerGenerator.cs:1432/:1440-1477`），纯契约包按 G17A §7.8 零 SG1 → 永不产出。
- **路由组/前缀同键**（比报错更隐蔽）：`:80` `GetOrCreateGroup(facadeType.Assembly)` + `:189-198`（组按程序集建）+ `:220-231`（`ResolveModulePrefix` 读该程序集的 `[ExtensionModule]`）。主包有 `[assembly: ExtensionModule("AuthCenter","auth")]`，契约包没有 → 若只补注册表查找，端点路径会**静默**从 `/api/auth/*` 变 `/api/*`。
- **SG2 让路链**：`_Domain.SG/ApiService.SG/ApiServiceGenerator.cs:763-798` 按门面所在程序集判"扩展自注册"；门面在契约包 → 特性缺失 → 落 fallback 分支并发 `Sg2ExtensionRestRegisteredFallback` 诊断（功能不坏，但语义靠巧合 + 每次消费方编译产生诊断噪音）。
- **生成侧本身是通的理由**（若立项增强）：`ControllerGenerator.cs:1685-1694` `FindFacadeInterface` 经 `serviceType.Interfaces`→`AllInterfaces` 解析（符号解析跨程序集有效），`:1702-1714` `CollectInterfaceMethodApiExpose` 读 PE 符号特性，`:1599-1608` 分发器按 `typeof` 全等匹配 + 未匹配 fail-closed——这解释了"构建 0 错误、运行时才炸"：主包的注册表其实生成了，坏的只是运行期查找**键**。

## 建议框架组评估（不要求本轮答复）

是否为"门面声明程序集 ≠ 实现/注册表程序集"提供一等支持：例如 `MapGenerated<TFacade>(Assembly? registrationAssembly = null)` 加性重载 + 组键/前缀键同步重定位 + SG2 让路判定同步；或框架级 ADR 明确该形态不支持并给出文档口径。任何方案须保持 fail-closed（缺特性/未匹配仍抛，不静默跳过；本仓红线）。

## 本仓采用的规避形态（供参考）

契约包只放**纯业务签名基接口**（`I*Contract`，无 `[ApiExpose]`），主包门面继承并 `new` 重声明带 `[AllowAnonymousFlag]`+`[ApiExpose]` 的端点方法；Initializer 对契约基接口额外 `AddConstructibleService<IContract, Impl>()`（对齐本仓既有 `AuthCenterExtensionInitializer.cs:115/171/179-180`）。框架零改动、端点路径零变化、契约包依赖零新增。若框架组未来落地跨程序集支持，本仓可在后续 minor 迁回单接口形态（消费方至多改 using，无行为变化）。
