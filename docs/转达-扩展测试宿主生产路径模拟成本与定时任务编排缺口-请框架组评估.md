# 转达 · 扩展测试宿主生产路径模拟成本（AddConstructibleService 守卫工厂镜像）与定时任务编排缺口——请框架组评估

> **转达方**：TKWF 扩展模块组（`_TKWF.Extensions`）
> **接收方**：TKW.Framework 框架组
> **日期**：2026-10-04
> **关联**：v4.10.53 ADR90 领域自治根治（正确路线）· `AddConstructibleService`/`AddService`（`DomainServiceCollectionExtensions`）· `TKW.Framework.Domain.Testing`（`ConfigTestDomainExtensions`）· `DomainUser.BindScope` · BackgroundJobs 扩展（`IBackgroundJobManager`）
> **性质**：请评估——①扩展测试宿主为走生产路径需镜像守卫工厂，模拟成本高（框架有无测试辅助可降低）；②Metrics 定时触发重算依赖框架 BackgroundJobs 补齐，请确认计划

---

## 一、要评估的问题（一句话）

① v4.10.53 门面化后（`AddConstructibleService`：接口注册为**可构造守卫工厂**（`CurrentAopUser` 守卫）+ 实现类注册为 **throw-factory**），扩展测试宿主为验证生产路径（注册形态断言 + AOP 解析）需**镜像守卫工厂语义**——框架 `_TKWF\_Framework` 无共享测试辅助，`TKW.Framework.Domain.Testing` 包未被扩展测试引用，导致 ~19 个 TestHost 全手写、StubDomainUser/TestUserInfo 大量重复。②Metrics 扩展定时触发重算的 `IBackgroundJobManager` 包装依赖框架 BackgroundJobs 补齐，Metrics 侧零改动——请确认补齐计划。

## 二、问题现象（实测成本）

### 2.1 测试宿主模拟成本（v4.10.53 全量整改收尾统计，2026-10-04）

扩展测试项目（`_Tests/`，32 个项目）为走**生产路径**（真实 DI + `DomainUser<TestUserInfo>.BindScope` + `user.Use<接口>()` AOP）验证门面化整改，全部重复以下样板：

```csharp
// 每个测试项目一份（无共享基座）
public static class TestHost
{
    public static ServiceProvider CreateProductionHost() { /* 真实 DI + 扩展 Initializer + FreeSql 基础设施 + IEntityDAC Singleton */ }
    public static IDisposable BindScope(ServiceProvider sp) => DomainUser<TestUserInfo>.BindScope(sp);
}
public class StubDomainUser { /* ~30-50 行桩 */ }   // 重复 10+ 处
public class TestUserInfo { /* 用户信息桩 */ }       // 重复 25+ 处
```

- **~19 个 TestHost/TestSupport 类**（DataPort 112 行 / FeatureManagement 342 / FileManagement 411 / MFA 346 / Notifications.Helpers 273 / OrganizationUnit 227 / Calendar 235 / Approval 182 / Identity 181 / SignalR 223 / ...），全手写 `CreateProductionHost` + `BindScope`。
- **StubDomainUser 桩重复 10+ 处**（每处 ~30-50 行）、**TestUserInfo 重复 25+ 处**。
- **注册形态断言三要素**（接口可守卫解析 / 实现类 throw-factory 直接解析必抛 / 域外解析抛）每扩展重写，无断言辅助。
- `AddConstructibleDataService` 已随 v4.10.53 删除（DataService 统一 `AddService` throw-factory）——测试宿主镜像模式无法复用旧 API。
- `TKW.Framework.Domain.Testing`（`ConfigTestDomainExtensions.ConfigTestDomainAsync`）提供了标准测试宿主（DomainHost.Initialize + TestSessionManager + MockDbEntityDAC），但扩展测试因需**真实 IEntityDAC + 扩展 Initializer 白名单 + 域作用域 BindScope** 未采用——宿主形态不匹配。

### 2.2 定时任务编排缺口（Metrics）

`docs/_Framework/Metrics/README.md` L262：

> 定时触发重算：DMP-Lite 每日指标重算可用 `IBackgroundJobManager` 包装（**框架组 BackgroundJobs 补齐后**；Metrics 侧零改动）

Metrics 的定时触发重算（指标结果持久化后的每日重算）无内建调度器（`CleanupExpiredAsync` 同理，调用方按需触发）——`IBackgroundJobManager` 包装能力依赖框架 BackgroundJobs 补齐，当前**未转达计划**。

## 三、根因分析

1. **守卫工厂/throw-factory 是内部实现语义**（`DomainServiceCollectionExtensions.AddConstructibleService` L236/L244）——测试侧无等价公开 API，只能手写镜像（真实 DI 构造接口解析路径 + 断言异常行为）。
2. **框架测试辅助包（Domain.Testing）与扩展"真实 DI + BindScope 生产路径"宿主需求之间无桥梁**——`ConfigTestDomainAsync` 面向框架自身业务领域测试，未提供"扩展 Initializer 白名单 + 门面注册断言"辅助。
3. `BindScope`（`DomainUser<TestUserInfo>.BindScope`）为框架公开 API 但无便捷封装（每测试项目重复写 scope 生命周期管理）。
4. Metrics 定时编排缺口为**框架 BackgroundJobs 能力缺口**的消费方等待（扩展侧零改动）。

## 四、建议方案（给框架组）

### 议题 1：测试宿主模拟成本

1. **A（框架，首选）**：`TKW.Framework.Domain.Testing` 提供"生产路径测试宿主辅助"：
   - `BindScope` 便捷封装（测试基类/Fixture 基类，自动 Dispose）；
   - **注册形态断言辅助**（`AssertConstructible<TInterface>(sp, user)`：帧内可解析 / 实现类直接解析抛 / 帧外解析抛——对齐 `AddConstructibleService` 守卫语义，免各扩展自写）；
   - `TestUserInfo`/`StubDomainUser` 基类（`SimpleUserInfo` 派生样例）。
2. **B（框架，轻量）**：公开等价"守卫工厂直建/断言"测试 API 少量扩展（如 `DomainUser` 测试辅助静态类），保持最小侵入。
3. **C（扩展侧，先行可实施）**：本仓库 `_Tests/` 建**共享测试宿主公共基座**（TestHostBase + 断言辅助 + TestUserInfo 复用，跨 32 项目引用），框架零改动——可立即降低模板重复；框架提供 A/B 后再迁移。

### 议题 2：Metrics 定时编排

4. 请框架组确认 `IBackgroundJobManager`（或等价定时编排能力）在 BackgroundJobs 的补齐计划与预计版本；Metrics 侧零改动，待补齐后转达使用方式。

## 五、请求

1. 请框架组评估议题 1 的 A/B（测试宿主辅助）优先级与可行性——若采纳，扩展侧 19 个手写 TestHost 可收敛为统一基座 + 断言辅助，显著降低后续扩展测试维护成本与门面化验证的重复劳动。
2. 请框架组告知议题 2（Metrics 定时编排）的补齐计划版本。
3. 扩展侧先行动作：若框架短期内无测试辅助计划，本仓库将自行建设共享测试宿主公共基座（方案 C），后续框架提供 A/B 后再对齐迁移。
